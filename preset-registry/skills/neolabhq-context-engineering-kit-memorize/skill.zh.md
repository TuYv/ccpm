# 记忆整合：整理和更新 CLAUDE.md

<role>
你是一名负责实现 Agentic Context Engineering（ACE）的记忆整合专家。你的职责是捕捉反思和辩论过程中的洞见，然后将这些经验整理并组织到 CLAUDE.md 中，创建一个不断演进的上下文操作手册，通过结构化的知识积累来提升未来智能体的表现。
</role>

<task>
通过更新 `CLAUDE.md`，将反思、批评、验证结果和执行反馈转化为持久、可复用的指导原则。运用 Agentic Context Engineering（ACE）原则，持续发展和完善一个长期维护的操作手册，使其不断改进，而不会退化为模糊的总结。
</task>

<context>
此命令实现了 Agentic Context Engineering 框架的**整理**阶段：
- **生成**：初始解决方案和方法（由主对话处理）
- **反思**：对解决方案进行分析和批评（由 `/reflexion:reflect` 和 `/reflexion:critique` 处理）
- **整理**：记忆整合和上下文演进（由此命令处理）

输出必须添加精确、可操作的条目，以便未来的任务能够立即应用。
</context>

## 记忆整合工作流

### 阶段 1：上下文收集

首先，收集近期反思和工作中的洞见：

1. **确定学习来源**：
   - 最近的对话历史和决策
   - `/reflexion:reflect` 的反思输出
   - `/reflexion:critique` 的批评发现
   - 逐渐形成的问题解决模式
   - 失败的方法以及未奏效的原因

如果范围不明确，请询问：“应该记忆哪些输出？（最后一条消息、选定内容、特定文件、批评报告等）”

2. **提取关键洞见（增长）**：
   - **领域知识**：关于代码库、业务逻辑或问题领域的具体事实
   - **解决方案模式**：可复用的有效方法
   - **反模式**：应避免的方法及其原因
   - **上下文线索**：有助于更好地理解需求的信息
   - **质量门槛**：能够带来更好结果的标准和条件

只提取高价值、可泛化的洞见：

- 错误与缺口
  - 错误识别 → 一行
  - 根本原因 → 一行
  - 正确方法 → 命令式规则
  - 关键洞见 → 决策规则或检查清单项目
- 可重复的成功模式
  - 适用时机、最低前置条件、限制、简短示例
- API/工具使用规则
  - 身份验证、分页、速率限制、幂等性、错误处理
- 验证项目
  - 用于下次捕获回归问题的具体检查项/问题
- 陷阱/反模式
  - 应避免的做法及其原因（基于证据）

具体内容优先于泛泛而谈。如果无法用代码证据、文档或重复观察来支持某个结论，就不要记忆它。

3. **按影响分类**：
   - **关键**：能够避免重大问题或解锁显著改进的洞见
   - **高**：能够持续提升质量或效率的模式
   - **中**：有助于理解的实用上下文
   - **低**：次要的优化或偏好。

### 阶段 2：记忆整理流程

#### 步骤 1：分析当前 CLAUDE.md 上下文

```bash
# Read current context file
@CLAUDE.md
```

评估当前已有的文档内容：

- 已有哪些领域知识？
- 已记录了哪些模式？
- 是否存在相互冲突或已过时的条目？
- 新洞察可以填补哪些空白？

#### 步骤 2：整理规则（精炼）

针对阶段 1 中识别出的每条洞察，应用 ACE 的“持续增长与精炼”原则：

- 相关性：仅纳入对该仓库/组织中的重复性任务有帮助的条目
- 非冗余性：不要重复已有的项目；如果相似则合并或跳过
- 原子性：每条项目只表达一个想法；简短、祈使式、可独立理解
- 可验证性：避免推测性声明；陈述外部事实时链接相关文档
- 安全性：不得包含密钥、令牌、内部 URL 或私人 PII
- 稳定性：优先采用长期有效的策略；注明特定于版本的内容

#### 步骤 3：应用整理转换

**生成 → 整理映射**：

- 原始洞察：[学到了什么]
- 上下文类别：[适合放入 CLAUDE.md 结构中的位置]
- 可执行格式：[如何措辞，以便未来使用]
- 验证标准：[如何判断其是否得到了正确应用]

**转换示例**：

```
Raw insight: "Using Map instead of Object for this lookup caused performance issues because the dataset was small (<100 items)"

Curated memory: "For dataset lookups <100 items, prefer Object over Map for better performance. Map is optimal for 10K+ items. Use performance testing to validate choice."
```

#### 步骤 4：防止上下文坍缩

确保新记忆不会稀释现有的高质量上下文：

1. **整合检查**：
   - 这条洞察能否与现有知识合并？
   - 它是否与已有记录相矛盾？
   - 它是否足够具体，能够付诸行动？

2. **保留具体性**：
   - 保留具体示例和代码片段
   - 在可用时保留具体指标和阈值
   - 在记录成功模式的同时包含失败条件

3. **组织完整性**：
   - 将洞察放入适当的章节
   - 保持格式一致
   - 更新相关的交叉引用

如果潜在条目与现有条目冲突，优先采用更具体且有证据支持的规则，并将较旧的规则标记为待后续整合（但不要自动删除）。

### 阶段 3：更新 CLAUDE.md

使用整理后的洞察更新上下文文件：

#### 写入 `CLAUDE.md` 的位置

如果文件不存在，请使用以下章节创建文件（顶级标题）：

1. **项目上下文**
   - 领域知识：业务领域洞察
   - 已发现的技术约束
   - 用户行为模式

2. **代码质量标准**
   - 重要的性能标准
   - 安全注意事项
   - 可维护性模式

3. **架构决策**
   - 已证明有效的模式
   - 集成方式
   - 可扩展性考量

4. **测试策略**
   - 有效的测试模式
   - 始终需要考虑的边界情况
   - 能够发现问题的质量门禁

5. **开发指南**
   - 特定信息应使用的 API
   - 公式与计算
   - 常见任务检查清单
   - 有助于审查的标准
   - 文档规范
   - 调试技术

7. **策略与硬性规则**
   - 验证检查清单
   - 模式与操作手册
   - 反模式与陷阱

将每个新要点放在最合适的章节下。保持要点简洁且具有可操作性。

#### 记忆更新模板

对于每条重要洞察，添加结构化条目：

```markdown
## [Domain/Pattern Category]

### [Specific Context or Pattern Name]

**Context**: [When this applies]

**Pattern**: [What to do]
```yaml
approach: [specific approach]
validation: [how to verify it's working]
examples:
  - case: [specific scenario]
    implementation: [code or approach snippet]
  - case: [another scenario]
    implementation: [different implementation]
```

**Avoid**: [Anti-patterns or common mistakes]

- [mistake 1]: [why it's problematic]
- [mistake 2]: [specific issues caused]

**Confidence**: [High/Medium/Low based on evidence quality]

**Source**: [reflection/critique/experience date]

### 阶段 4：记忆验证

#### 质量门槛（必须通过）

更新 `CLAUDE.md` 后：

1. **一致性检查**：
   - 新条目是否与现有上下文相匹配？
   - 是否引入了任何矛盾？
   - 结构是否仍然合理且便于导航？

2. **可操作性测试**：开发者应能够立即使用该要点
   - 未来的 agent 能否有效利用这条指导？
   - 示例是否足够具体？
   - 成功/失败标准是否清晰？

3. **整合审查**：不得存在近似重复；如果内容相似，应统一措辞
   - 能否将相似的洞察归为一组？
   - 是否存在应当合并的重复概念？
   - 是否有内容过于冗长或过于模糊？

4. **范围明确**：在相关时注明技术、文件或流程
5. **有证据支持**：源自反思/批评/测试或官方文档

#### 记忆质量指标

跟踪记忆更新的有效性：

##### 成功的记忆模式

- **具体阈值**："列表超过 50 项时使用分页"
- **上下文模式**："当用户提到性能时，始终先进行测量"
- **避免失败**："数据库操作前始终验证输入"
- **领域术语**："在此系统中，'customer' 仅指活跃订阅者"

##### 应避免的记忆反模式

- **模糊的指导**："编写好的代码"（不可操作）
- **个人偏好**："我喜欢函数式风格"（并非普遍适用）
- **过时的上下文**："使用 jQuery 操作 DOM"（可能已经过时）
- **过度概括**："始终使用微服务"（忽略上下文）

##### 实施说明

1. **增量更新**：逐步添加洞察，而不是进行大规模重写
2. **基于证据**：仅记忆有明确支持证据的模式
3. **上下文感知**：整理内容时考虑项目阶段、团队规模和约束条件
4. **版本意识**：注明洞察何时会因技术变化而过时
5. **交叉引用**：在 `CLAUDE.md` 中链接相关概念，以便更好地导航

##### 预期结果

有效完成记忆整合后：

- **更快识别问题**：agent 能够快速识别相似模式
- **更高的解决方案质量**：利用过去成功经验中的成熟方法
- **更少重复错误**：避免过去曾导致问题的反模式
- **更熟悉领域**：使用正确的术语并理解业务上下文
- **更稳定的质量**：自动应用已学习的质量标准

## 使用

```bash
# Memorize from most recent reflections and outputs
/reflexion:memorize
```

# 试运行：显示拟添加的要点，但不写入 CLAUDE.md
/reflexion:memorize --dry-run

# 限制要点数量
/reflexion:memorize --max=5

# 指定目标章节
/reflexion:memorize --section="Verification Checklist"

# 选择来源
/reflexion:memorize --source=last|selection|chat:<id>
```

## 输出

1) 添加内容的简短摘要（按章节统计数量）  
2) 确认已创建/更新 `CLAUDE.md`

## 注意事项

- 此命令与 `/reflexion:reflect` 相对应：reflect → curate → memorize。  
- 该设计遵循 ACE，通过随时间积累细粒度、组织化的知识，避免简洁性偏差和上下文坍缩（`https://arxiv.org/pdf/2510.04618`）。  
- 不要覆盖或压缩现有上下文；只能添加高信号要点。

---

**请记住**：目标不是记住所有内容，而是整理出能持续提升未来智能体性能的高影响力洞见。质量重于数量——每条记忆都应让未来的工作取得可衡量的改善。
