# 可逆性

核心规则：让流程深度与撤销成本相匹配。大多数决策的逆转成本比看上去更低；不可逆的决策才值得深思熟虑和分阶段投入。

## 适用场景

- 不确定某个决策值得投入多少分析（技术、流程、产品、组织）
- 想把影响范围很小的选择提交委员会讨论，或想仓促通过一个高锁定成本的选择
- 可以通过重新设计举措（试点、特性开关、抽象、时间盒）来降低撤销成本
- 行动与等待的恢复前景不对称的高风险选择

## 不适用场景

- 本次会话中已完成分类——按匹配的深度决策即可；不要永远重复归类
- 琐碎的双向决策（命名、局部重构）——直接决定比分类更省事
- 受外部强制且无可选余地的举措（硬性截止日期、合同、法规）
- 正确性关卡（安全、数据完整性）——需要的是正确答案，而非速度表演

## 操作步骤

1. **指明决策与撤销路径。** 说明将要承诺的内容，以及具体的逆转动作（回滚、迁移回去、撤销、重新招聘、重新签约）。
2. **评估可逆性。** 衡量技术工作量、时间、金钱、声誉、依赖方，以及逆转时会损失的经验积累。分类：
   - **Type 2：** 数天内可撤销，成本低 → 快速决策
   - **Type 1.5：** 数周内可撤销，成本中等 → 轻量结构 + 监控
   - **Type 1：** 需要数月或实际上无法撤销 → 深思熟虑
3. **不对称的下行风险 / 恢复前景。** 针对 Type 1 或 1.5：
   - 行动出错：下行损失、能否恢复、恢复成本
   - 不行动：哪些会永久关闭（窗口期、独占机会、路径锁定）
   - 规则：可恢复的行动下行风险 + 永久性的不作为损失 → 分阶段投入优于无限期拖延；灾难性后果或第三方损害 → 拒绝或先重新设计
4. **保留可选项的重新设计。** 优先采用试点、特性开关、接口、版本化、限时的供应商条款或绞杀者模式切片，把 Type 1 的表层转化为 Type 2 实验。只需对残余的不可逆核心进行深思熟虑。
5. **匹配流程并投入。** Type 2：选定一个合理选项，发布，监控。Type 1：记录假设，论证反方观点，若风险等级需要则呈报给负责人。分类与投入深度一经确定即停止——没有新的撤销成本证据，不要重新分析。

## 输出

```text
Decision: …
Undo path: …
Class: Type 2 | 1.5 | 1 (factors: …)
Acting downside / recovery: …
Not-acting permanent loss: …
Staging / option-preserving move: …
Process depth: decide-now | pilot | full deliberation
Commitment: …
```

## 验证

- **证伪：** 如果“我们以后总能改”没有具体的撤销路径和成本，那么在证明相反之前，应将其视为更不可逆。
- **停止：** 分类和流程深度确定之后，进一步的归类工作是浪费——直接执行匹配的流程。
- **防过度应用：** 不要用矩阵拖慢琐碎的 Type 2 工作。不要以“双向门”为由跳过对不可逆数据、安全或公开承诺的验证。
