# 林迪效应

对于不会“消亡”的想法、技术和实践，预期剩余寿命与当前的存活年限成正比。优先选择已被证明的幸存者，除非新选项能通过举证责任，或领域本身已发生漂移。

## 适用场景

- 在长期存续事关重大的场景下选择语言、框架、数据库、协议、模式或依赖项时。
- 价值取决于持续相关性的技能或架构押注。
- 在各选项年限差异显著、且选择会超出短期实验寿命的情况下进行选项排序时。

## 不适用场景

- 会消亡的目标：特定的 SaaS 厂商、硬件、时尚潮流或可能被关停的产品——无论其概念年限如何。
- 处于活跃范式断裂期的领域，此时旧范式下的年限只是弱证据。
- 长寿与否无关紧要的一次性工作——应为契合度与速度做优化。
- 把“更老”当作“对新需求最优”；存活只能预测继续存活，而非最佳契合。

## 步骤

1. **确认非消亡范围。** 概念/技术/实践仍在延续；厂商/设备 → 仅评估契合度/风险即止。
2. **记录存活年限。** 记录首次重要生产使用的时间和当前年限（若生态尚年轻，则相对该生态衡量）。
3. **形成林迪先验。** 预期剩余寿命 ≈ 当前年限；根据年限与持续活跃使用标注置信度。
4. **执行领域漂移检查。** 问题类别是否已改变？是否存在使旧假设失效的范式转移？新选项是否独一无二地填补了一个现实中存在的缺口？
5. **分配举证责任。** 默认选择足够胜任的较老选项。仅当新选项具有明确说明的必要优势、且林迪选项无法以可接受成本满足时，才接受新选项。
6. **带着残余风险做决策。** 选定主选项；注明先验有误时的影响以及任何回退方案。

**停止条件：** 已选定主选项，并附上年龄先验、漂移检查，以及新选项为何通过或未通过举证责任的说明。

## 输出

```text
Options: <name, age, Lindy prior>
Drift: stable | discontinuous — <note>
Burden: on new | waived because <gap>
Decision: <primary>
Rejected: <one line each>
If Lindy wrong: <impact + fallback>
```

## 验证

- 若在未确认非消亡范围的情况下使用了年限，或忽视了范式转移，则判定不成立。
- 若新选项虽已证明存在必要缺口、却仅因年轻而被拒绝，则判定不成立。
- 过度应用防范：在契合度与退出成本占主导时，跳过一次性原型和会消亡的厂商押注。
