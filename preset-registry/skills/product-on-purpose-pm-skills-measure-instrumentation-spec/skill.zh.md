# 埋点规范

埋点规范定义要跟踪哪些分析事件、何时触发这些事件，以及要包含哪些属性。它是产品与工程之间的契约，确保以一致的方式收集数据，从而实现准确的度量。完善的埋点规范可以避免出现“我们无法回答这个问题，因为当时没有跟踪相关数据”的情况。

## 适用场景

- 在工程团队实现新功能之前
- 为实验定义分析需求时
- 审查现有埋点是否存在遗漏或不一致时
- 接入新的分析工具时
- 上线前，确保测量机制已经就绪

## 不适用场景

- 你要规定基于这些事件构建的仪表板 -> 使用 `measure-dashboard-requirements`
- 你需要的是特定于实验的指标和变体，而不是面向整个产品的跟踪 -> 使用 `measure-experiment-design`
- 功能本身尚未完成定义（没有可供埋点的流程） -> 先使用 `deliver-prd`
- 你正在分析已经收集的数据 -> 使用 `measure-experiment-results` 或 `measure-survey-analysis`

## 指令

当被要求创建埋点规范时，请按照以下步骤操作：

1. **定义分析目标**
   从你需要回答的问题开始。你要测量什么？这些数据将为哪些决策提供依据？这样可以避免过度埋点，同时确保不会遗漏重要内容。

2. **确定要跟踪的事件**
   列出应当跟踪的每个用户操作或系统事件。遵循一致的命名约定（通常使用 `noun_verb` 或 `verb_noun` 这样的 snake_case 格式）。每个事件都应代表一个明确且有意义的操作。

3. **规定事件触发条件**
   对于每个事件，准确描述其触发时机。要具体明确：“用户点击 Submit 按钮”与“表单成功提交时”是不同的事件，其含义也不同。

4. **定义事件属性**
   列出附加到每个事件上的属性（特征）。包括属性名称、数据类型、描述和示例值。属性提供的上下文信息能让事件真正发挥作用。

5. **记录用户属性**
   确定应与所有事件关联的持久性用户级属性（例如订阅层级、账户创建日期）。这些属性支持在分析中进行分群。

6. **处理 PII 和隐私**
   标记任何包含个人身份信息的属性。记录应如何处理 PII——进行哈希、加密或排除。

   *当捕获任何模型输入、输出、检索上下文或工具调用时*，还应扩展本节以涵盖该追踪记录。触发条件是捕获，而不是内容的作者身份：无论敏感文本是由用户输入的、从租户的文档中检索的、包含在系统提示中的、传递给工具或由工具返回的、从上传的文件或批处理作业中读取的，还是由模型自身生成的，都会触发。即使功能没有直接的用户输入，也仍然可能将客户的合同文本写入追踪存储中。

跟踪记录（trace）不是事件：事件携带的是你预先选择的属性，而跟踪记录携带的是可以包含任何内容的自由文本，包括属性模式未预料到的数据。请决定并记录：

   - **捕获的数据类别。** 明确列出这些类别（用户文本、检索到的文档、系统提示词、工具参数和结果、文件内容、模型输出）。“跟踪记录”不是一个答案。
   - **在两个边界执行最小化。** 哪些内容会在跟踪记录*离开进程之前*被丢弃或脱敏，以及哪些内容会在*存储之前*被丢弃或脱敏，分别说明。仅在存储层运行的脱敏器，已经把原始文本通过网络发送出去了。
   - **访问权限。** 谁可以读取跟踪记录，以及读取操作是否会被记录。跟踪记录存储通常是某个功能所处理的最敏感数据中，治理最薄弱的副本。
   - **保留与删除。** 保留多长时间、由什么机制删除，以及当跟踪记录被复制到评估集后，删除请求如何传达到该跟踪记录。
   - **同意与选择退出。** 数据主体是否已同意，以及他们拒绝时该功能如何处理。
   - **采样。** 捕获的比例是多少，以及如何选择样本。均匀采样不适合发现罕见故障；如果记录跟踪记录是为了诊断错误输出，就应对被标记的案例进行过采样，并明确说明这一点。

7. **创建测试清单**
   定义 QA 应如何验证跟踪是否正确实现。包括验证事件是否在正确的时间触发，并携带正确属性的步骤。

## 输出格式

使用 `references/TEMPLATE.md` 中的模板来组织输出。一份完整的规格说明应填写模板中的每个部分：概览；事件清单；用户属性；PII 与隐私注意事项；实现说明；以及测试清单。

## 质量检查清单

定稿前，请验证：

- [ ] 事件名称遵循一致的命名规范
- [ ] 每个事件都有清晰、明确的触发条件
- [ ] 属性包含数据类型和示例值
- [ ] 已识别 PII，并记录其处理方式
- [ ] 事件与需要回答的分析问题相对应
- [ ] 测试清单能够支持 QA 验证
- [ ] 如果捕获了任何模型输入、输出、检索上下文或工具调用：已明确列出数据类别，在数据离开进程和存储这两个边界都已决定最小化措施，并已决定访问权限、读取日志记录、保留与删除、同意以及采样方式，而不是将这些事项推迟
