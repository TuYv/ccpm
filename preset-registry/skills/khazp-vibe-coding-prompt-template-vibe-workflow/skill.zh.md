# 应用工作流路由器

根据请求和现有项目状态选择下一项有用操作。
仅加载识别结果、约束条件和当前实现所需的上下文。已有文件并不能证明某个阶段已完成。

- **新产品：**有选择地使用调研、PRD 和技术设计技能。快速模式需要明确结果、约束条件和验收流程；对于尚未确定的集成或影响重大的决策，更深入的规划会有所帮助。
- **现有产品：**在当前架构中实现所请求的变更。若可用则使用变更技能；缺少规划文档不意味着必须重新开始探索。
- **故障行为：**复现、诊断、修复并验证该故障。若可用则使用调试技能，而不要重新进行新产品访谈。
- **仅限说明或交接：**产出所请求的制品并说明其局限；不要开始未经请求的实现或部署。

创建项目说明时使用 `vibe-agents`，进行新实现时使用 `vibe-build`，并针对相关用户流程使用可用的验证技能。仅调用目标环境中实际存在的技能。这五个阶段是有用的路径，而不是每次编辑都必须经过的五道审批关卡或必需文档集。

复用已回答的问题和交接上下文。询问缺失但影响重大的决策；否则在明确说明假设的前提下继续推进。将稳定约束保存在 `AGENTS.md` 中，将决策保存在产品文档中，并在项目使用时将当前进度保存在 `MEMORY.md` 中。除非独立工作和可用工具足以证明委派合理，否则一个构建者即可。

完成用户请求的范围，包括相关检查和修复。报告时，区分实际结果与未执行的检查，并说明任何具体阻碍。若请求的是可工作的产品，不要在首次实现后就停止；本地工作完成并不意味着应当发布。
