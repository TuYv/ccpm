# 变体

此技能接收一个已描述的 UI 部件，并构建三个有意不同的版本。它们会置于真实页面中的选择器之后，因此你可以在它们之间切换并进行选择。

这里的其他技能都负责评判。此技能负责产出候选方案，并将决定权交还。审查现有 UI 应使用 `interface-review` 和 `better-interface`，它不会选择获胜方案。

## 不同的答案，而非不同的色调

仅在强调色上有所不同的三个变体毫无意义。你在它们之间切换，看不到真正的选择，这次运行就浪费了。

因此，每个变体都应是对同一需求的不同答案，且差异应位于本集合所负责的某个维度上：

| 维度 | 负责人 | 变化内容 |
| --- | --- | --- |
| 结构 | `better-layout` | 分组、顺序、列数、哪些内容折叠 |
| 密度 | `better-layout` | 间距尺度、点击区域、可容纳的信息量 |
| 强调 | `better-colors` | 填充色的位置、哪些内容弱化 |
| 字体 | `better-typography` | 尺寸阶梯、字重对比、行长 |
| 文风 | `better-writing` | 标签、语气、文案量 |

选择**一个主要维度**，并让每个变体在该维度上处于不同位置。次要选择应由其推导，而不是自行变化。高密度变体可能需要更小的字体尺寸阶梯，这是一致性，而不是第二个维度。

同时改变每个维度会产生三个无法归因的结果。你只能知道自己喜欢哪个，而不知道是什么让它奏效，因此下一个部件又得从零开始。

## 每个变体都必须达到的底线

一个视觉上胜出却未通过升级触发条件的变体，不是候选方案。它只是一个有着漂亮表面的缺陷。

变体进入选择器前，必须通过 `better-interface` 的升级触发条件。每个控件都有可访问名称，键盘能够完成指针可完成的一切操作，焦点清晰可见，在 320px 宽度下没有内容被裁切，且不应仅依赖颜色传递含义。

这条底线在所有变体中完全一致。它不是一个维度，也绝不能与任何维度进行取舍。当某个方向只能通过破坏这条底线来实现时，应明确说明并放弃该方向。

## 1. 确定一个部件的范围

每次运行只处理一个 UI 部件。 “仪表盘”不是一个部件；指标卡才是。当需求涵盖多个部件时，指出其他部件所依附的那个部件，说明原因，并将其余部件作为后续运行提供。

用一句话重述需求：这个组件是什么、它在哪里渲染、它必须完成什么。

## 2. 了解基础环境

变体必须看起来像是明天就能发布，因此要了解它们所依托的环境：

- 样式系统、组件库，以及任何动画库。
- 设计令牌：颜色、间距、圆角、字体尺寸、缓动。
- 产品的密度与文风。高密度的专业工具会限制最大胆的变体可以走多远。
- 该部件的渲染位置：面对什么背景、位于哪些相邻元素旁边、处于哪些宽度下。

没有项目可供阅读时，使用中性灰、一种强调色和系统字体栈，并说明你是这样做的。

## 3. 在编写代码前确定维度

默认采用三个变体。仅在被要求时，或空间确实足够宽敞时，才增加到五个。超过五个，没人会比较，他们只会滚动。

先写下这组方案，每个方案各有一个名称和一个轴位置。名称要说明方向，因此用 `Quiet`、`Editorial`、`Dense`，绝不用 `Option A`。

当没有两个变体共享同一个位置，而且你能用一句短语说明每个变体所处的轴位置时，这一步就完成了。

## 4. 将其构建到真实页面中

变体单独看起来会不错，因此隔离环境恰恰不是评判它的正确场所。将变体放到实际会承载该部分的页面中，使用真实的页面框架、真实的相邻内容和逼真的数据。

使用 URL 搜索参数（`?variant=quiet`）进行选择，这样每个变体都是可以发给别人的链接。使用一个浮动控件设置它；规范在 [picker.md](picker.md) 中。

一次渲染一个变体，并以完整尺寸显示。缩略图会扭曲间距和比例，而间距通常正是你需要在不同方案之间做取舍的地方。

如果没有页面可以承载它，就构建一个独立的 HTML 文件，并保留相同的选择器。

为每个变体提供真实内容：符合产品形态的文案、可信的名称，以及该页面实际会承载的项目数量。Lorem ipsum 和三行内容会让任何结构看起来都不错。

## 5. 展示取舍并停止

先自己逐一查看每个变体。每个都能渲染，每项交互都有响应，控制台保持干净。

然后把决策交出去：

| 变体 | 轴位置 | 适合的情况 | 代价 |
| --- | --- | --- | --- |
| Quiet | 最低视觉权重 | 页面每天都会使用 | 最不容易留下印象 |
| Editorial | 最大字号、最多留白 | 此刻值得被强调 | 占用垂直空间 |

说明选择器运行在哪里、用哪个键切换，以及你是在什么宽度下评判的。在 375px 和 1440px 下，答案可能不同。

绝不要在表格中标记你偏好的方案。被直接询问时，应根据这部分内容被看到的频率和产品的个性来回答，而不是根据你更享受构建哪一个。

## 6. 推进一个，删除其余方案

选定后：按照项目自身的约定，在它应处的位置把该变体完整实现，然后删除其他变体和测试框架。

如果被要求再做一轮，则保留测试框架并再次执行第 3 步，在你倾向的方向附近选取新的位置。

在推进到生产实现之前，测试框架绝不从生产代码导入，生产代码也绝不从测试框架导入。

## 完成前

| 错误 | 修正方法 |
| --- | --- |
| 变体只在强调色或文案上不同 | 将其中一个移到主轴上的不同位置，或删除它 |
| 每个轴都同时变化 | 只变化一个；其余变化由它决定 |
| 在空白路由上评判 | 将它们放到会承载该部分的页面中 |
| Lorem ipsum、三行内容、`"Jane Doe"` | 使用真实文案，以及页面实际会承载的项目数量 |
| 最大胆的变体跳过键盘或焦点支持 | 清除障碍，或放弃这个方向 |
| 在表格中标记了偏好方案 | 说明每个变体的代价，让用户选择 |
| 使用项目的设计令牌重设选择器样式 | 保持它明显处于设计系统之外 |
| 推进后仍留下测试框架 | 除非被要求保留，否则删除它 |
