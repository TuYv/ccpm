# Figma → HyperFrames

将用户的 Figma 作品导入合成中。**按能力拆分**（设计规范 §2）：

| 阶段 | 内容                | 传输方式                     | 接口                          |
| ----- | ------------------- | ---------------------------- | ----------------------------- |
| 1     | 静态资源            | REST                         | `hyperframes figma asset`     |
| 2     | 品牌令牌/样式       | REST                         | `hyperframes figma tokens`    |
| 3     | 组件 → HTML         | REST                         | `hyperframes figma component` |
| 4     | 动效 → GSAP         | **仅 MCP**                   | 由你通过 `get_motion_context` |
| 5     | 着色器              | **仅 MCP** / 手动导出        | 由你处理                      |

只要可行就使用 REST（适合大规模使用、支持无头模式）；仅在 Figma 没有提供对应 REST 功能（动效、着色器）时才使用 MCP。每条路径都会将资源冻结到本地，从而确保渲染结果具有确定性。故事板重建会将阶段 1 的资源导出（REST）与代理驱动的时间线组装结合起来——无需 MCP。现有的冻结资源、清单记录和绑定不受路由变更影响——这种拆分只会改变下一次导入所使用的凭据。

## 身份验证——两种凭据，各有作用域

**预检——在首次调用 CLI 之前，检查令牌是否存在**：shell 环境变量（`[ -n "$FIGMA_TOKEN" ]`）**或**项目 `.env`（CLI 会自动加载它——`.env` 中存在相应条目即视为已配置）。如果两者都没有，请勿为了获取错误信息而运行命令——应先引导用户完成一次性设置，然后停止并等待：

1. figma.com/settings → **Security** → **Personal access tokens** → Generate new token。
2. 作用域——此集成只需要只读权限（它绝不会向 Figma 写入内容）：**File content: Read-only** + **File metadata: Read-only**。如果你将在非 Enterprise 套餐中运行 `tokens`，还需添加 **Library content: Read-only**——已发布样式的回退机制会访问 `/v1/files/:key/styles`，缺少此权限会返回 403（旧版设置说明遗漏了这个作用域）。如果需要品牌变量，可选择添加 **Variables: Read-only**——仅 Enterprise 可用；如果没有此权限，`tokens` 会自动降级为使用已发布样式（这是预期行为，并非错误——应明确说明）。现在，403 会指出具体缺失的作用域；429 会自动重试（受每分钟限额约束，并遵循 `Retry-After`）。
3. `export FIGMA_TOKEN="figd_…"`——并建议将其持久化保存（shell 配置文件或项目 `.env`），这样以后的会话就无需重复此步骤。

在引导设置时，还应简要说明预期行为：每次导入都会生成一个**记录了来源信息的本地冻结文件**——渲染时绝不会调用 Figma；重新运行命令时，只会重新导入 Figma 中发生变化的内容；一个令牌即可用于资源、品牌令牌和组件，并适用于其 Figma 账户有权查看的所有文件。

- **阶段 4–5（动效/着色器）：** Figma MCP 连接器（单击 OAuth），它是与令牌不同的独立凭据。如果 MCP 工具报未认证错误，请告知用户连接 Figma 连接器，然后停止。
- 明确说明失败阶段所需的具体凭据——绝不要把这种凭据拆分描述成系统故障。
- 流程中途出现 `BAD_TOKEN` (401) → 令牌已过期/被撤销；重新生成。`FORBIDDEN` (403) → 消息会指出缺少的确切作用域（例如，样式回退需要 `library_content:read`）——添加该作用域，否则说明该账户无法查看此文件。`REQUIRES_ENTERPRISE`（变量请求返回 403）→ 不算失败：样式回退已经运行。`RATE_LIMITED` (429) → 客户端已经使用退避策略重试（这适用于每一次读取——资产、令牌、样式、节点树、版本——重试逻辑位于共享请求路径中；会遵循 `Retry-After`，上限为 60 秒）；如果仍然出现此错误，请等待一分钟，或减少每次调用导入的节点数。

**速率限制注意事项（规范 §2.1）：** Starter 方案中的 MCP 限额为 6 次工具调用/**月**（截至 2026-07 的 Figma 方案矩阵——如果配额看起来不对，请重新核实）——在父节点上使用 `recursive:true` 进行批量处理，除非用户要求，否则跳过验证截图，并缓存原始 MCP 响应，确保重新推导时绝不会耗费第二次调用。REST 按分钟计限（每分钟 10 次以上，按端点分别划分配额桶）——足以支持批量操作，遇到 429 时执行退避。

## 路由

使用 `parseFigmaRef` 解析用户的 Figma 链接（URL、`fileKey:nodeId`、裸 `fileKey`）。然后根据意图进行路由：

- “使用这个图层 / 徽标 / 图像” → **资产**（CLI）
- “提取我的品牌 / 颜色 / 令牌” → **令牌**（CLI）
- “根据这个画框构建场景” → **组件**（CLI）
- “导入这个动画 / 动效” → **动效**（MCP，见下文）
- 一组场景画框构成的故事板分区 / 胶片条 → **故事板**（见下文）
- 着色器填充/效果 → **着色器**（见下文）

**向用户讲述每一个步骤**——执行每条命令前，说明即将从 Figma 提取什么；执行后，说明产物保存到了哪里（冻结路径 / sidecar / 组件目录）、合成中发生了什么变化，以及紧接着要执行的操作（预览、添加打印出来的变量、重新导入以关联绑定）。绝不能让用户还需要追问“成功了吗？”或“接下来做什么？”。

## 资产（阶段 1 — CLI）

```bash
hyperframes figma asset '<url-or-fileKey:nodeId>' [more refs…] [--format svg|png|jpg|pdf] [--scale 2] [--description "..."] [--entity "..."]
```

通过 REST 渲染，净化 SVG，将其冻结在 `.media/images/` 下，在清单中追加来源信息，重新生成 `.media/index.md`（共享媒体使用清单），并输出一个 `<img>` 代码片段。按 `fileKey:nodeId:format:scale:version` 保证幂等。矢量图/徽标优先使用 SVG（可缩放、可制作动画），需要保持光栅图像保真度时使用 PNG `--scale 2`。**始终传入 `--description "<what it is>"`**（它会成为索引行和 `<img alt>`）；对于具名品牌标识，添加 `--entity "<name>"`，这样媒体使用工具的 `resolve --entity` 之后就能找到它们（实体命中会跨图像/图标进行匹配）。

**在一次请求中批量处理多个节点**——传入同一文件中的多个引用（以空格分隔或用逗号连接）：`hyperframes figma asset 'KEY:1-2' 'KEY:3-4' 'KEY:5-6'`。所有节点都将在单次 `/v1/images` 调用中渲染，这是 Figma 自己针对每分钟速率限制给出的解决方案——提取整个画框中的资产时，优先采用这种方式，而不是执行 N 条单独命令。`--description`/`--entity` 会应用于批次中的每个节点，因此应将用途相同的节点放在同一批次中。无论如何，遇到 429 时也会自动使用退避策略重试。

## 令牌（阶段 2 — CLI）

```bash
hyperframes figma tokens <fileKey>
```

将变量导入为组合品牌变量条目，同时生成 `figma-tokens.json` 辅助文件和绑定索引记录（`.media/figma-bindings.jsonl`）。上游仅允许企业版使用变量：在其他套餐中，该命令会降级为已发布样式的元数据（其值会在组件导入时解析）。将输出的条目添加到组合的 `data-composition-variables` 中。

当同时需要令牌和组件时，**请先导入令牌，再导入组件**——这样组件颜色才能链接到品牌变量，而不是固化重复值。

**非企业版变量路径（经实测）：** REST 变量仅限企业版使用，但 Figma MCP 的 `get_variable_defs` 并非如此。当 `tokens` 报告 `REQUIRES_ENTERPRISE` 且用户拥有 MCP 连接器时，你可以自行构建索引：(1) 对场景的父节点调用 `get_variable_defs`——只调用一次，并将原始 JSON 缓存到 `.media/figma-cache/`——即可得到 `name → value`；(2) REST 节点树中的 `boundVariables` 提供每个属性对应的 `VariableID`；(3) 按节点和属性进行联接，并写入 `.media/figma-bindings.jsonl` 行（`{kind:"binding", figmaId, sourceFileKey, compositionVariableId: "figma:<name>", version}`）以及组合变量条目。所有下游功能（组件 `var()` 解析、刷新、运行时 CSS 变量）都使用已交付的机制。请向用户标明：“通过 Figma 连接器获取令牌——企业版套餐可直接通过 `hyperframes figma tokens` 获取这些令牌。”

运行时会将每个已声明的组合变量定义为 CSS 自定义属性（位于文档根节点和子组合宿主节点），因此，当变量默认值发生变化时，导入的 `var(--slug, literal)` 会自动应用重新着色——只需更新 `data-composition-variables` 中的一个值，即可为所有已导入组件更换品牌，而无须重新导入任何内容。`hyperframes render --variables '<json>'` 可在渲染时覆盖这些变量。

## 组件（阶段 3 — CLI）

```bash
hyperframes figma component '<url-or-fileKey:nodeId>'
```

将节点树转换为具有精确 Figma 几何布局的可编辑 HTML，并打包为 `compositions/components/<name>/` 下的注册表项。矢量图形/布尔运算会通过阶段 1 导出自动栅格化。绑定处理（规范 §7.1，仅限精确 ID——绝不按值匹配）：

- **静态保真度自检（首屏核心内容必须执行）**：导入后，渲染该片段并与 Figma 自身的像素结果进行比较——`figma asset <same node> --format png` 是基准真值。文本是已知的偏移来源：如果 Figma 文本框的高度小于其行高，则其边界经过了垂直裁剪（映射器会为这种情况输出 `text-box-trim`；实测表明，在 70px 字体上，如果没有它，偏移约为 6px）。如果比较结果显示存在映射器尚未覆盖的偏移，请报告该问题——不要默默地手动微调片段。
- 绑定到**已导入**令牌的填充 → `var(--slug, #literal)`——品牌刷新会自动传播。
- 绑定到**未知**令牌的填充 → 字面值 + `data-figma-unresolved` 标志。命令会告知你这种情况；请向用户建议：对源文件（或库文件）运行 `tokens`，然后重新导入组件以建立链接。对于每个未知库，只询问**一次**它对应哪个文件——绝不要猜测，也绝不要按十六进制颜色值匹配。

## 动效（阶段 4 — MCP，核心部分）

**使用信标：**MCP 阶段没有 CLI 接触点，因此请在开始和结束时触发技能信标（匿名、需经同意、绝不会导致失败）：开始时运行 `npx hyperframes events --skill=figma-motion`，完成时运行 `npx hyperframes events --skill=figma-motion --event=skill_completed --outcome=success|error`。着色器（`figma-shaders`）和故事板（`figma-storyboard`）同样如此。

不存在对应的 REST 方案。你需要操作 MCP 工具，然后将输出交给 `@hyperframes/core/figma` 中的纯辅助函数：

1. `get_motion_context(fileKey, nodeId)` — 对父级画框使用 `recursive:true`（整个场景只调用一次，而不是每个元素调用一次）。将原始 JSON 保存在项目旁的缓存目录中（`.media/figma-cache/`），这样重新转换无需额外成本。
2. 使用 `@hyperframes/core/figma` 中的 `motionContextToDocs(rawResponse, { selectorFor, repeat })` 将其规范化为 `MotionDoc` — **绝不要手动转录关键帧数值**。该辅助函数以程序化方式编码了经过实际验证的解码规则：它解析 motion.dev 代码片段（这是可靠的编码形式——CSS 代码片段会拉伸持续时间，并且可能与其不一致，因此会被忽略），移除循环回绕的尾部关键帧（时间约为 0.9999→1 的亚毫秒片段是循环的瞬时重置，而不是创作者制作的动效——回绕由 `repeat` 重新开始来实现），并原样保留贝塞尔缓动。`selectorFor` 必须返回阶段 3 组件导入时生成的 id——不要根据节点名称推导选择器。
   2b. **在宣布完成前对照真实基准进行验证——强制要求**：对同组对象的 `rootNodeId` 使用 `export_video`，可获得 Figma 自身对时间轴的渲染结果。运行 `node skills/figma/scripts/verify-motion.mjs --reference <export.mp4> --render <render.mp4> --crop WxH+X+Y`——它会比较运动能量差值（静态导入的保真度差异会相互抵消），并在最小运动 PSNR 低于 15dB 时判定失败（校准结果：忠实还原约为 20+，明显偏离约为 5）。应根据渲染结果中卡片的实际边缘测量 `--crop`，不要猜测。FAIL 表示应重新检查转换，而不是调整阈值。
3. `motionToGsap(doc)` → `emitTimelineScript(spec)` → 在 GSAP + CustomEase CDN 标签后注入为 `<script>`。时间轴应处于暂停状态、次数有限，并使用字面量键注册到 `window.__timelines`。
4. 无法转换的轨道（由着色器驱动、不受支持的属性、复杂蒙版）→ 烘焙：`export_video` → 固化为 MP4 → 嵌入为 `<video class="clip">`。例外：由着色器驱动的轨道——Figma 的导出路径会将着色器展平为基础颜色（请参阅下方的“着色器”部分），因此在此处进行烘焙会悄无声息地丢失着色器效果；请改为要求用户提供 Figma 原生导出。始终说明使用了哪种路径以及原因。映射集合之外的命名缓动将回退为线性缓动——映射表位于 `motionEase.ts`；发生回退时，应告知用户。
5. 在宣布完成前运行 `npx hyperframes check`。

## 着色器（阶段 5 — 主要依靠手动操作）

Figma 的 MCP 渲染路径不会执行着色器（它们会被展平为基础颜色），而且只有**已发布到库中**的样式才能访问着色器源代码（需要付费的 Full 席位）。默认路径：要求用户在 Figma 中以原生方式导出着色器画框（PNG 或 Motion MP4），然后将其作为阶段 1 的资源/剪辑导入。不要尝试通过 MCP 对着色器进行像素捕获——它会悄无声息地产生错误结果。

## 故事板（场景帧的一个 SECTION → 动画）

**首要原则：故事板帧是关键帧，而不是幻灯片。** 包含同一元素的两个帧描述了该元素随时间变化的状态——应在这些状态之间对该元素进行动画处理；绝不能把这些帧作为一系列静止画面播放。在连续四个帧中绘制于逐渐降低的 y 坐标上的徽标，是同一个元素经过四个关键帧向上移动。将故事板帧首尾相接地播放是典型的失败方式；你的任务是重建这些帧所隐含的元素时间线。

故事板文件遵循一种可以机械解析的语法——不要凭肉眼判断，要进行解码：

1. **场景单元**：在 SECTION 内，每个帧尺寸的节点都是一个场景——包括命名的 FRAME，_以及_ 独立的全帧 RECTANGLE（设计师会将静止画面直接粘贴到该 section 中）。应按尺寸筛选（≈ 合成画面的宽高比，例如 >1400×900），而不是按节点类型或名称筛选。
2. **顺序 = x 坐标位置**（如果场景条换行，则按行优先）。按 `absoluteBoundingBox.x` 对场景排序。
3. **对相邻帧求差异以形成元素链**——动画就存在于这里。匹配连续帧中的子节点：首先按**名称**匹配（名称相同 = 同一元素 → 在不同状态之间对其相对 x/y/w/h 进行补间），然后按**几何相似度**匹配（尺寸相近 + 中心点邻近 = 同一个逻辑元素，但其像素发生了变化 → 在对几何属性进行补间的同时，让两次导出结果在原位交叉淡化；这可以覆盖逐字输入的文本序列和形变状态）。未匹配的子节点在其所属场景的节拍点进入或退出。帧背景填充作为颜色轨道进行补间。每条元素链仅导出一个资源（只有当像素确实不同时，才为每种状态分别导出一个）——绝不要为每一帧导出一张静止画面。
4. **静止画面是后备方案，而不是默认方案**——仅用于无法拆解的帧（没有共享元素的扁平化全帧截图）；这些帧采用下文所述的动态分镜处理方式。
5. **导演注释**：场景条下方的 TEXT 节点表示运动意图，并与其 x 范围所重叠的场景配对。它们描述的是_如何_制作动画——不是要显示在画面上的文案。
6. **批量导出**（元素或静止画面）：`GET /v1/images` 接受以逗号分隔的 id，但大型场景帧在超过约 12 个 id 时会出现 "Render timeout"——每次调用分成约 4 个，并在失败时重试。（每个场景调用一次会浪费速率配额；通过单资源路径处理 26 个场景约需 52 次调用。）
7. **注释动词 → 转场**（以下为初始词汇，遇到新词时继续扩展）：

| 注释内容                       | 处理方式                                                          |
| ------------------------------- | ----------------------------------------------------------------- |
| 爆炸 / 爆发                     | 入场缩放约 1.5→1 + 淡入，`power3.out`                             |
| 滑入 / 滑向…… / 滚动           | 从指定边缘沿相应方向滑入                                          |
| 形变 / 揭示                     | 交叉淡化——如果运动发生在单个场景内部，则使用第 3 阶段导入         |
| 循环展示 / 逐个展示             | 延长停留时间——如果各项在场景内部运动，则使用第 3 阶段导入         |
| （无注释）                      | 交叉淡化 + 缓慢的 Ken Burns 漂移动画                              |

8. **静帧与组件的路由选择**：描述场景_之间_运动的注释 → 在静帧上应用转场（见上文）。描述场景_内部_运动的注释（“文本行逐行显现”、“胶囊元素以动画方式进入”）→ 该帧应在第 3 阶段导入组件（真实元素），并按照注释制作动画，而不是使用扁平 PNG。先使用静帧完成动态分镜，然后再升级注释中特别指出的场景。
9. 使用一个 `main` 时间线按顺序编排所有内容（在绝对时间点设置各场景的 opacity/x/y）——制作动态分镜不需要为每个场景创建子合成。
10. **升级处理——当所有帧描绘的是同一个产品 UI 时 → 重建应用，而不是使用元素链。** 当每一帧都是同一应用界面的连续状态（注册流程、设置面板、播放器）时，元素链无法充分呈现其效果。应将 UI 重建为实时 DOM——对会改变状态的部分执行第 3 阶段组件导入，对静态界面框架使用真实导出的像素（**对会改变状态的部分编写代码，冻结不会改变的部分**）——并将每一帧的差异视为一次**需要执行的交互**，而不是要应用的补间动画：光标进入、点击控件、状态作出响应，界面像真实导航一样推入或滑动。最终效果应像是一段运行中应用的连续屏幕录制。这是基本准则在 UI 流程中的彻底贯彻；静帧/元素链处理方式适用于并非同一个连贯应用的故事板。

## 确定性

绝不要在合成中留下 Figma URL——应先冻结。绝不要输出 `repeat: -1`。时间线必须处于暂停状态、长度有限，并使用字面量 `window.__timelines` 键。所有 Figma I/O 都应在导入时完成；渲染时只能读取本地文件。
