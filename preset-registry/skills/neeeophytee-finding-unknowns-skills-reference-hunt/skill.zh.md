# 参考实现探寻

有些需求过于复杂或过于隐晦，难以用文字明确表达，但某处已有的可运行代码已经体现了这些需求。最好的参考不是截图或描述，而是源代码。像阅读规范一样阅读它，然后重新实现其语义，而不是照搬语法。

## 步骤

1. 获取参考对象：仓库路径、项目内置目录、库名称，或可以读取底层代码的网站。询问需要从中提取的具体内容——行为、结构、视觉系统还是 API 形态——以免模仿了错误的维度。
2. 阅读参考实现，并在编写任何代码之前给出一份**语义摘要**：
   - 它实现的行为和保证（时序、顺序、错误处理、边界情况）；
   - 哪些决策看起来是有意为之，哪些只是偶然形成；
   - 任何无法直接转换到目标语言或技术栈的内容，以及建议采用的等效方案。
3. 让用户确认语义摘要。这一步能以较低成本及时发现理解偏差。
4. 在目标技术栈中重新实现：保持相同语义，采用原生惯用写法。不要逐行转写，也不要逐字复制许可证不允许复制的参考代码——如果许可证不明确，请注明这一点。
5. 完成闭环：逐一列出摘要中的每项行为以及新实现中体现该行为的位置，并说明所有有意偏离之处及其原因。

## 约束

- 参考实现定义*做什么*；目标代码库的约定定义*怎么做*。
- 如果发现参考实现本身存在缺陷或不一致，应明确指出，而不是忠实复现该缺陷。
- 尊重许可证：提取语义没有问题；复制许可证不兼容的代码则不可以。
