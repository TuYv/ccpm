# 用于上下文工程的智能体技能

本合集为通过有效的上下文工程构建生产级 AI 智能体系统提供结构化指导。

## 何时启用

在以下情况下启用这些技能：
- 从零开始构建新的智能体系统
- 优化现有智能体的性能
- 调试与上下文相关的故障
- 设计多智能体架构
- 为智能体创建或评估工具
- 实现记忆与持久化层
- 设计自主研究或评估框架

## 技能图谱

### 上下文工程基础

**理解上下文基础**
上下文不只是提示文本，而是推理时语言模型可用的完整状态，包括系统指令、工具定义、检索到的文档、消息历史记录和工具输出。有效的上下文工程意味着理解哪些信息对当前任务真正重要，并对这些信息进行筛选和组织，以实现最高的信噪比。

**识别上下文退化**
随着上下文增长，语言模型会表现出可预测的退化模式：“中间信息丢失”现象，即上下文中部的信息获得的注意力较少；优先关注开头和结尾的 U 形注意力曲线；错误不断累积时产生的上下文污染；以及无关信息淹没相关内容时产生的上下文干扰。

### 架构模式

**多智能体协调**
生产级多智能体系统逐渐趋向三种主流模式：采用集中式控制的监督者/编排器架构、支持灵活交接的点对点群体架构，以及用于复杂任务分解的层级结构。关键在于，子智能体的主要作用是隔离上下文，而不是模拟组织角色。

**长周期提示**
长时间运行的自主智能体和并行编排的成败取决于启动提示。伪形式化任务简报会明确成功判定条件、不计入成果的结果、带有审计门控返回条件的持续执行规则、最低投入要求、并行任务组合的多样性策略以及污染防护措施，从而以语言形式将形式化验证的严谨性应用于不存在机器可检查成功条件的问题。

**记忆系统设计**
记忆架构涵盖从简单暂存区到复杂时序知识图谱的多种形式。向量 RAG 可提供语义检索，但会丢失关系信息。知识图谱能够保留结构，但需要投入更多工程成本。将文件系统用作记忆的模式可以实现即时上下文加载，而无须将大量内容塞入上下文窗口。

**基于文件系统的上下文**
文件系统为存储、检索和更新近乎无限的上下文提供了统一接口。关键模式包括：使用暂存区卸载工具输出、为长周期任务持久化计划、通过共享文件实现子智能体通信，以及动态加载技能。智能体使用 `ls`、`glob`、`grep` 和 `read_file` 进行有针对性的上下文发现，在结构化查询方面通常优于语义搜索。

**托管式智能体基础设施**
后台编码智能体运行在远程沙箱环境中，而非本地计算机上。关键模式包括按固定周期刷新的预构建环境镜像、用于即时启动会话的预热沙箱池、用于保持会话持久性的文件系统快照，以及支持协作式智能体会话的多人功能。关键优化包括允许在 git 同步完成前读取文件（仅阻塞写入）、在用户开始输入时预测性预热沙箱，以及通过智能体自行派生来并行执行任务。

**工具设计原则**
工具是确定性系统与非确定性智能体之间的契约。有效的工具设计遵循整合原则（优先使用单个综合性工具，而非多个功能狭窄的工具），在错误中返回上下文信息，支持响应格式选项以提高 token 效率，并采用清晰的命名空间。

### 卓越运营

**上下文压缩**
当智能体会话耗尽内存时，压缩就成为必需措施。正确的优化目标是每项任务所需的 token 数，而不是每次请求所需的 token 数。采用明确划分文件、决策和后续步骤等部分的结构化摘要，比激进压缩能保留更多有用信息。在所有压缩方法中，制品轨迹的完整性仍是最薄弱的维度。

**上下文优化**
相关技术包括压紧（在接近上下文限制时进行摘要）、观察遮蔽（用引用替换冗长的工具输出）、前缀缓存（跨请求复用 KV 块），以及策略性上下文分区（将工作拆分给具有隔离上下文的子智能体）。

**潜在简报（KV 内存共享）**
在编排器-工作器系统中，当监督器累积了较长的执行轨迹，而工作器只能看到狭窄的文本片段时，token 消耗可能会复合增长。潜在简报使用任务引导注意力（注意力匹配式压紧）将编排器轨迹压紧到工作器模型的 KV 缓存中，从而在技术栈开放工作器 KV 状态且模型兼容的情况下，让工作器无需完整重放文本即可接收相关的潜在状态。

**评估框架**
生产环境中的智能体评估需要确定性检查和多维评分标准，涵盖事实准确性、完整性、工具效率和过程质量。仅在结构、证据和评分标准计算均有效后才使用模型评审器；评审器设计、成对比较和偏差缓解应交由高级评估处理。

**执行框架工程**
可靠的自主智能体需要围绕模型构建明确的操作循环：锁定的指标、可编辑界面、持久化日志、新颖性检查、回滚规则和人工审批边界。执行框架可防止智能体削弱评估器、在压紧过程中丢失状态，或将模糊目标转化为无法审查的更改。

**自我改进循环**
当执行框架本身成为优化目标时，需要采用另一套方法：递归式自我改进、元执行框架搜索、由失败驱动的有界自我编辑、演化式脚手架搜索，以及上下文机制演化。其控制性约束包括基于实证的双拆分验收门槛、包含原始轨迹的文件系统经验档案、在所有可编辑界面之外实施的运行时强制约束，以及用于防止坍缩的多样性保持。

### 开发方法论

**项目开发**
高效的 LLM 项目开发始于任务与模型的适配性分析：在构建自动化流程之前，先通过手动原型验证任务是否适合由 LLM 处理。生产流水线采用分阶段、幂等的架构（获取、准备、处理、解析、渲染），并通过文件系统状态管理实现调试和缓存。通过明确的格式规范来设计结构化输出，可以实现可靠的解析。应从最小化架构开始，仅在证明确有必要时才增加复杂性。

### 认知架构

**BDI 心智状态**
信念—愿望—意图建模提供了一种正式的方法，可将结构化的外部上下文转换为智能体的心智状态。它适用于理性智能体、可解释性，以及需要在信念、目标和所选行动之间建立可审计关联的系统。

## 核心概念

本合集围绕四个核心主题组织。第一，上下文基础阐明什么是上下文、注意力机制如何运作，以及为什么上下文质量比数量更重要。第二，架构模式涵盖实现高效智能体系统所需的结构和协调机制。第三，卓越运营涉及优化、评估和运行框架的可靠性。第四，开发方法论和认知架构涵盖项目执行与正式的心智状态建模。

## 实践指南

每项技能既可以单独使用，也可以组合使用。首先从基础知识入手，建立上下文管理的心智模型。然后根据系统需求转向相应的架构模式。在优化生产系统时，参考运营类技能。

这些技能与平台无关，可与 Claude Code、Cursor 或任何支持自定义指令或类技能构造的智能体框架配合使用。

## 集成

本合集中的各项内容可以相互集成——各技能会相互引用，并建立在共享概念之上。基础技能为所有其他技能提供上下文。架构类技能（多智能体、记忆、工具）可以组合起来构建复杂系统。运营类技能（优化、评估）适用于使用基础技能和架构技能构建的任何系统。
