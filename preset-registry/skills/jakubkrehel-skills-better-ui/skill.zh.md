# UI 精修

精致感来自大量彼此叠加的小细节。本技能说明哪些细节值得关注，以及它们应采用什么值。

进行评审时，放慢界面速度。以 10% 速度播放时让你觉得不对劲的地方，就是全速运行时那些细微的错误所在。

保持项目现有的组件库、设计令牌和密度，并沿用其动效语言，除非下方规则规定了精确的交互方式。

下方的每个时长、曲线、缩放值和模糊值都是具体值，而不是可近似的范围。`cubic-bezier(0.2, 0, 0, 1)` 不等于 `cubic-bezier(0.4, 0, 0.2, 1)`，`0.96` 也不等于 `0.95`。使用文中写明的值。

文本换行、字体渲染、表格数字和文本间距属于 `better-typography`。点击区域、焦点、键盘支持、ARIA 和减少动效属于 `better-accessibility`。分组、区块间距、断点和空间布局 RTL 属于 `better-layout`。

## 同心圆角

外层圆角 = 内层圆角 + 内边距。嵌套元素的圆角不匹配，是最常见的界面观感不协调原因。[surfaces.md](surfaces.md) 中提供了圆角、阴影和轮廓的配置方案。

## 光学对齐优于几何对齐

当几何居中看起来不对时，应采用光学对齐。带图标的按钮、播放三角形和不对称图标都需要手动微调。

## 用阴影表现层级，用边框表现结构

如果边框仅用于制造深度，优先使用分层的透明 `box-shadow` 值。保留那些用于传达结构或状态的边框：分隔线、分隔符，以及选中或聚焦状态。

## 可中断的动画

对于交互状态变化，使用 CSS 过渡，因为它们可以在动画进行到一半时被中断。将关键帧保留给只运行一次的分阶段序列。

## 拆分并错开入场动画

对于不常发生、且顺序能够传达层级关系的分阶段入场，应将内容拆分为语义块，并以约 100ms 的间隔依次播放。为一个容器设置动画，在相同成本下能获得的效果更少。高频交互不要使用错开动画。参见 [enter-exit.md](enter-exit.md)。

## 细微的退出动画

使用较小的固定 `translateY`，而不是完整高度。退出动画应比入场动画更柔和。两个方向都使用 `ease-out`。

## 上下文相关的图标动画

使用 `opacity`、`scale` 和 `blur` 为图标添加动画，而不是切换可见性。严格使用以下值：scale 从 `0.25` 到 `1`，opacity 从 `0` 到 `1`，blur 从 `4px` 到 `0px`。

如果使用动效库（`package.json` 中包含 `motion` 或 `framer-motion`），应匹配该软件包的导入路径；如果两者都存在，则参考附近的导入。使用 `transition: { type: "spring", duration: 0.3, bounce: 0 }`。Bounce 始终为 `0`。

如果没有动效库，则将两个图标都保留在 DOM 中，让其中一个绝对定位，并使用 `cubic-bezier(0.2, 0, 0, 1)` 进行交叉淡入淡出。这样无需依赖项即可同时实现入场和退出。两种方案都在 [icon-transitions.md](icon-transitions.md) 中提供。

## 图像轮廓

为图像添加低不透明度的 `1px` 轮廓，以保持一致的深度感。浅色模式使用纯黑（`oklch(0 0 0 / 0.1)`），深色模式使用纯白（`oklch(1 0 0 / 0.1)`）。绝不要使用类似 slate 或 zinc 的近黑色，也不要使用带色调的中性色。带色调的轮廓会吸收下方表面的颜色，在图像边缘看起来像污渍。

## 按下时缩放

点击时使用 `scale(0.96)` 可为按钮提供触觉反馈。始终使用 `0.96`；低于 `0.95` 的任何值都会显得过于夸张。在动作会造成干扰的地方，添加 `static` prop 将其关闭。参见 [CSS、Tailwind 和 Motion 的配方](animations.md#scale-on-press)。

## 跳过页面加载时的动画

在 `AnimatePresence` 上使用 `initial={false}`，以便在首次渲染时关闭进入动画。检查这不会使有意设计的页面进入效果失效。

## 主题切换时抑制过渡

主题切换会同时改变几乎每个元素的颜色、背景、边框和阴影。这些属性上的每个过渡都会同时触发，使切换变得拖沓，而不是瞬间完成。注入 `*,*::before,*::after{transition:none !important}`，强制回流，然后在下一帧将其移除。参见 [配方](animations.md#suppress-transitions-on-theme-switch)。

## 只过渡发生变化的内容

始终明确指定确切的属性：`transition-property: scale, opacity`。Tailwind 的 `transition-transform` 覆盖 `transform, translate, scale, rotate`。

## 谨慎使用 `will-change`

仅用于 `transform`、`opacity` 和 `filter`，GPU 可以对这些属性进行合成。绝不要使用 `will-change: all`。在看到首帧卡顿时再添加，而不是提前添加。参见 [performance.md](performance.md)。

## 使图标描边匹配文本字重

文本旁边的图标承载着文本的视觉重量：常规（400）文本旁使用 `1.5px` 描边，半粗（600）文本旁使用 `2px`。每套图标使用一种描边粗细，每个界面使用一个图标库。尺寸调整和 RTL 翻转请参见 [icons.md](icons.md)。

## 一个 SVG，按状态重新着色

图标使用 `currentColor`，并通过 CSS 的颜色和不透明度获取悬停、选中和禁用状态，而不是使用单独的资源。默认使用描边变体；填充表示激活状态。

## 克制动效

为高频交互提供即时反馈，或对不透明度和颜色使用 `150ms` 或更短的过渡。自定义动画会在每次触发时消耗用户的注意力成本。

每个动画状态变化也都需要一个静态提示：颜色、图标或标签。动效绝不能成为唯一的反馈渠道。

## 完成前检查

| 错误 | 修复 |
| --- | --- |
| 图标看起来不居中 | 通过内边距进行视觉微调，或修复 SVG |
| 分阶段的进入或退出效果令人突兀 | 对低频进入效果进行错峰；保持退出效果含蓄 |
| 主题切换使整个页面交叉淡化 | 为切换禁用过渡，强制回流，并在下一帧恢复 |
| 元素上使用 `transition: all` | 指定确切的属性 |
| 首帧动画卡顿 | 添加 `will-change: transform`（谨慎使用） |
| 细线图标与粗体文本并置 | 使描边宽度匹配文本字重 |

## 报告

**严重性。** `HIGH` 会破坏交互、使动效无法使用，或使状态变化只能在动画运行期间可见。`MEDIUM` 是界面、图标或动效中明显的不一致。`LOW` 是局部的润色问题。

**验证。** 不使用浏览器时：检查组件定义的每个状态，即悬停、焦点、激活、加载和空状态，以及从代码中读取的动效持续时间和缓动效果。使用浏览器时：逐一检查每个状态，并在浏览器的 Animations 面板中以 10% 的速度重放动效。将所有无法执行的检查报告为 `Not verified`。

**格式。** 按每条发现所违反的原则进行分组，并按严重程度排序；每个根本原因占一行，列出其出现的所有位置：

| 严重程度 | 位置 | 修改前 | 修改后 | 原因 |
| --- | --- | --- | --- | --- |

`Location` 的格式为 `path/to/file:line`。`Why` 需说明相关原则及其对用户的影响。

当仍有任何 `HIGH` 项时，以 `Block` 结尾；否则以 `Approve` 结尾，同时将其余内容保留在表格中作为待处理事项。切勿对未检查的覆盖范围执行 `Approve`。如果没有需要报告的内容，请写明 "No actionable UI-polish findings"，并报告验证结果。
