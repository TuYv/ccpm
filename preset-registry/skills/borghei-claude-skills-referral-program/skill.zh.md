# 推荐计划

生产级推荐与联盟营销计划框架，涵盖四阶段推荐闭环、激励设计方法、触发时机优化、分享机制、病毒系数建模、联盟营销计划架构，以及系统化优化手册。旨在构建能够产生复利增长、而非被束之高阁的计划。

## 核心能力

- **计划类型与闭环设计** — 推荐计划与联盟营销计划的选择，以及四阶段闭环（触发 → 分享 → 转化 → 奖励）
- **激励设计** — 单边与双边激励、奖励类型、分层游戏化，以及基于 LTV/CAC 的奖励经济性分析
- **触发与分享机制** — 产品内和电子邮件中的触发点、分享渠道优先级、第一人称分享文案
- **被推荐用户体验** — 推荐落地页、归因规则、计划文案集（提示语、电子邮件、仪表板）
- **增长测算** — K 因子建模、收入影响模型，以及逐项改进 K 因子的杠杆分析
- **联盟营销框架** — 佣金模式、分级体系、合作伙伴工具包、招募
- **优化** — 先诊断后优化的操作手册、指标基准、故障排查，以及三个 Python 工具

## 适用场景

- 用户要求“设计推荐计划”“启动联盟营销计划”或“提升病毒式增长”
- 需要在客户推荐计划与联盟营销计划之间做出选择
- 现有推荐计划陷入停滞（K 因子 <1、分享率低、被推荐用户转化率低）
- 需要根据 CAC、利润率或 LTV 确定奖励规模
- 需要识别触发时机（何时发出邀请、选择哪些产品内事件、选择哪些生命周期电子邮件）
- 用户表示“口碑传播不起作用”或“我们想添加好友推荐流程”

## 首先澄清

在设计推荐计划之前，请确认以下输入。如果其中任何一项未知或含糊，请提问——不要自行假设：

- [ ] **计划类型** — 客户推荐与联盟营销计划（热情活跃/社交型客户与团队采购者）（决定整个框架）
- [ ] **触发时机** — 发出邀请的产品内或生命周期节点（第一阶段失效，无法通过在第四阶段增加奖励来补救）
- [ ] **奖励经济性** — 首次付款金额、利润率和 CAC（将奖励上限设为首次付款的 <30%）
- [ ] **当前推荐率（如有）** — 决定采用单边还是双边激励，以及优先修复哪个阶段

停止规则：仅询问对输出影响最大的 2-3 项。如果用户说“直接起草即可”，则继续执行，并在交付内容顶部列出你的假设。

## 快速开始

1. **选择计划类型** — 使用“推荐与联盟营销决策”表（热情活跃/社交型客户 → 推荐计划；团队采购者 → 联盟营销计划）。
2. **按顺序构建闭环** — 触发 → 分享 → 转化 → 奖励；第一阶段失效，无法通过在第四阶段增加奖励来补救。
3. **确定激励规模** — 将奖励上限设为首次付款的 <30%；如果推荐率 <1%，则采用双边激励。
4. **建模与验证** — 运行脚本（`referral_economics_calculator.py`、`referral_funnel_analyzer.py`、`affiliate_commission_modeler.py`），以确定奖励规模、找出最薄弱的阶段，并对联盟营销分级体系进行建模。
5. **按优先级优化** — 首先解决认知度问题，然后优化分享流程，接着改善被推荐用户体验，最后调整激励。

## 范围与限制

**范围内：** 客户推荐计划设计（四阶段循环）、激励结构（单边、双边、分层）、触发时机架构、分享机制、推荐落地页规范、病毒系数建模、联盟计划框架（佣金模式、分层体系、招募），以及系统化优化手册。

**范围外：** 推荐落地页视觉设计和 CRO（使用 page-cro）、受推荐用户的注册流程优化（使用 signup-flow-cro）、受推荐用户注册后的引导（使用 onboarding-cro）、受推荐客户的流失预防（使用 churn-prevention），以及奖励与定价的一致性（使用 pricing-strategy）。脚本仅对本地数据进行操作——不与推荐平台（ReferralHero、Viral Loops、PartnerStack 等）集成。

**限制：** K 因子基准假设面向消费者或专业消费者的 SaaS；B2B 企业推荐计划具有不同的动态特征（K 因子更低，但每次推荐的价值更高）。联盟佣金基准（20-30% 的持续佣金）专用于 SaaS；市场平台和电子商务的佣金遵循不同的模式。归因窗口（30-90 天 Cookie）正日益受到浏览器隐私功能的限制（Safari ITP、Chrome 第三方 Cookie 弃用）。收入预测是基于所提供转化率得出的估算值。

## 集成点

- **pricing-strategy** -- 推荐奖励额度必须与定价利润率和 LTV 保持一致；奖励应低于首笔付款的 30%
- **signup-flow-cro** -- 受推荐用户的注册流程应预填电子邮件、显示推荐人上下文，并尽量减少阻力
- **onboarding-cro** -- 受推荐用户可能需要不同的引导路径（他们到达时已经从推荐人处获得了相关背景信息）
- **churn-prevention** -- 单独监控受推荐客户的留存情况；推荐客户的高流失率会浪费获客支出
- **page-cro** -- 推荐落地页的转化优化遵循 page-cro 方法论
- **popup-cro** -- 购买后或达成里程碑后的弹窗是自然的推荐触发点
