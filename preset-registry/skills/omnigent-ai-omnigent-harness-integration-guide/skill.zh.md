# 运行框架集成指南

此 Skill 描述了每个 Omnigent 运行框架都必须考虑的**功能矩阵**。
在规划、审查或实现新的运行框架时，请使用此 Skill。

Omnigent 有两种不同的运行框架路线，它们具有不同的架构和
功能集：

- **SDK/子进程运行框架** — 直接运行供应商模型（进程内 SDK、
  CLI 子进程或 ACP 子进程）。它们负责管理模型的生命周期。
- **原生运行框架** — 封装供应商自己的 TUI 或服务器，并将其
  输出镜像到 Omnigent。它们负责观察和中继，而非驱动。

---

## 第 1 部分 — SDK / 子进程运行框架

这些运行框架直接运行供应商模型，并将 Omnigent 工具桥接到
供应商的工具调用接口。

### 功能矩阵

| 功能 | 含义 |
|---|---|
| **连接到 Omnigent MCP** | 运行框架通过 MCP 协议公开/使用工具（进程内 SDK MCP 服务器） |
| **模型覆盖** | 用户可以通过 `--model` / 配置选择模型；某些运行框架被锁定为特定供应商（例如仅限 Claude、仅限 GPT、仅限 Gemini） |
| **身份验证** | 获取凭据的方式 — API 密钥、网关令牌、供应商 CLI 登录、OAuth 等 |
| **流式传输** | 运行框架将 token 级或 delta 级流式输出转发到 Omnigent 转发器 |
| **Omnigent 策略** | 运行框架强制执行 Omnigent 侧的工具策略 — 必须对工具调用和工具结果都支持 ALLOW、ASK 和 DENY 判定 |
| **原生征询** | 当策略判定为 ASK 时，运行框架会在 Omnigent Web UI 中显示批准请求，以便用户批准或拒绝 |
| **中断** | 用户可以在流式传输过程中取消正在运行的轮次 |
| **实时队列（并发）** | 可以将多个轮次加入队列并并发处理 |
| **工具边界引导** | Omnigent 可以在工具调用边界注入引导文本 |
| **从 Omnigent 对话记录恢复/分叉** | 从已存储的 Omnigent 对话记录重建对话（重放历史记录、使用种子提示词或供应商会话 ID） |
| **压缩** | 对长对话进行压缩；运行框架会公开 `CompactionComplete` 事件 |
| **推理** | 转发模型的推理/思考 token |
| **图像** | 转发图像内容（屏幕截图、图表）— 完整二进制数据、路径引用或文本扁平化形式 |
| **成本跟踪** | 运行框架针对每个轮次将 token 用量和成本数据报告回 Omnigent |

### MCP 连接

运行框架必须桥接 Omnigent 的内置 MCP 工具，以便模型可以调用
它们。这些工具提供会话管理、智能体编排、策略
控制和 Web 访问：

- `sys_session_get_info`, `sys_session_list`, `sys_session_get_history`
- `sys_agent_get`, `sys_agent_list`, `sys_agent_download`
- `sys_call_async`, `sys_cancel_async`, `sys_cancel_task`
- `sys_read_inbox`
- `sys_add_policy`, `sys_policy_registry`
- `load_skill`
- `list_comments`, `update_comment`
- `web_fetch`, `web_search`

### Omnigent 策略

运行框架必须在两个检查点支持 Omnigent 策略引擎的三种判定：

| 检查点 | ALLOW | ASK | DENY |
|---|---|---|---|
| **工具调用**（执行前） | 静默继续 | 向用户显示批准请求（通过征询） | 阻止调用，并向模型返回策略拒绝错误 |
| **工具结果**（执行后） | 将结果返回给模型 | 在返回前显示结果以供用户审查 | 抑制结果，并向模型返回策略拒绝错误 |

### 原生请求确认

当策略裁定为 ASK 时，执行框架必须在 Omnigent Web UI 中以审批卡片的形式展示待处理的工具调用或工具结果，然后将用户的批准/拒绝决定传回执行框架，以继续或阻止执行。

### 恢复 / 分叉策略

| 策略 | 工作方式 |
|---|---|
| 完整历史重放 | 将整个消息历史重放到新的线程/会话中 |
| 历史前缀重放 | 将历史记录的一个前缀重放到新的会话中 |
| 文本前缀重放 | 注入先前历史记录的文本摘要/前缀 |
| 提示词植入 | 在重建时将先前历史记录植入系统提示词 |
| 供应商会话 ID | 依赖供应商自身的会话持久化（Omnigent 端不进行重建） |

### 身份验证模式

| 模式 | 描述 |
|---|---|
| API 密钥 / Databricks 网关 | 直接使用 API 密钥，或通过 Databricks 网关路由 |
| 供应商 API 密钥（直连） | 供应商专用 API 密钥（例如 Cursor、Gemini） |
| 供应商 CLI 登录 / 配置文件 | 凭据存储在供应商配置文件中，或通过供应商 CLI 登录进行管理 |
| OAuth / GitHub 令牌 | OAuth 流程或平台令牌（例如 GitHub PAT） |
| 网关 + 回退 | 以网关为主要方式，并可回退到供应商原生身份验证 |

### 新 SDK/子进程执行框架检查清单

对于完整的执行框架集成，以下所有能力均为**必需**：

- [ ] 连接到 Omnigent MCP（进程内 SDK MCP 服务器或供应商专用桥接器）
- [ ] 模型覆盖有效（或记录供应商锁定限制）
- [ ] 身份验证已配置并有文档说明（`omni setup` 中的设置流程）
- [ ] 将流式输出转发到 Omnigent 转发器
- [ ] Omnigent 策略会强制执行工具使用规则
- [ ] 原生请求确认会在 Web UI 中展示工具审批请求
- [ ] 中断操作会取消正在运行的轮次
- [ ] 实时队列支持并发轮次
- [ ] 工具边界引导能够正确注入
- [ ] 恢复/分叉会根据 Omnigent 对话记录重建会话
- [ ] 压缩操作会被呈现（`CompactionComplete` 事件）
- [ ] 推理令牌会被转发
- [ ] 图像会被转发（首选完整二进制数据；路径或文本扁平化形式也可接受）
- [ ] 成本跟踪会报告每个轮次的令牌用量和成本
- [ ] 单元测试涵盖工具桥接、身份验证和模型路由
- [ ] 模拟 LLM 测试无需真实 API 调用即可覆盖正常流程

### 快捷方式：ACP CLI 执行框架只需一个目录条目

如果供应商 CLI 通过 stdio 使用 Agent Client Protocol（即 `goose acp` / `qwen --acp` 系列），请勿编写新的内部模块、注册表条目或启动环境构建器。只需在 `omnigent/acp_cli_harnesses.py` 的 `ACP_CLI_HARNESSES` 中添加一行（包括标签、二进制文件、ACP argv、别名、安装提示或 npm 包、供应商登录命令），并补充文档。有效性、模块路由、选择器标签、能力、安装规范、就绪状态、设置步骤、启动环境，以及实时端到端矩阵排除项都会从该行派生；`tests/test_acp_cli_harnesses.py` 会自动断言每一行的接线配置。这些条目通过 `omnigent/inner/acp_harness.py` 和 `AcpExecutor` 运行，自行管理身份验证和模型选择，并会预先拒绝 `/model` 覆盖。

## 第 2 部分 — 原生适配器

原生适配器封装供应商自己的 TUI 或服务器，并将输出镜像到 Omnigent。它们会将供应商侧的对话转发到 Omnigent 会话中。

### 能力矩阵

| 能力 | 含义 |
|---|---|
| **传输方式** | 原生适配器的通信方式 — tmux TUI、应用服务器、HTTP/SSE、文件注入式 TUI |
| **连接到 Omnigent MCP** | 原生适配器是否连接到 Omnigent MCP 服务器 |
| **模型覆盖** | 用户可以在启动时或每次提示时选择模型 |
| **身份验证** | 供应商登录 / 配置 / 令牌 |
| **流式传输（转发器）** | `deltas`（令牌级）与 `complete-only`（完成后返回完整响应） |
| **Omnigent 策略** | 原生适配器是否执行 Omnigent 侧的工具策略 — 必须同时针对工具调用和工具结果支持 ALLOW、ASK 和 DENY 判定 |
| **原生请求确认** | 当策略判定为 ASK 时，原生适配器会在 Omnigent Web UI 中显示审批请求，以便用户批准或拒绝 |
| **中断** | 用户可以中止正在运行的轮次 |
| **双向同步（TUI->Omni）** | 将 TUI 输出镜像到 Omnigent 对话中 |
| **适配器内会话命令同步** | 支持来自 Omnigent 的 `clear`、`fork`、`resume`、`switch` 命令 |
| **从 Omnigent 对话记录恢复/派生** | 可以根据 Omnigent 对话记录重建对话（原生重建或全新启动） |
| **压缩** | 供应商内部的压缩状态 |
| **推理** | 转发模型的推理/思考令牌 |
| **图像** | 转发图像内容 — 路径引用、完整二进制数据或文本扁平化内容 |
| **成本跟踪** | 原生适配器会将每个轮次的令牌用量和成本数据报告回 Omnigent |
| **工具输出流式传输** | 实时增量命令/工具输出（`outputDelta`）与仅最终聚合输出 |
| **工作树差异** | 显示供应商按轮次聚合的差异（而不是根据逐文件编辑重建） |
| **生成/查看的媒体** | 镜像模型生成或模型查看的图像（不同于用户提供的图像输入） |
| **供应商模式** | 将供应商特有的模式（审查模式、计划模式等）镜像为状态 |

### 新原生适配器检查清单

各项能力根据其重要程度划分为不同层级。**P0** 必须正常工作，否则适配器将无法使用。**P1** 是实现完整、同等水平集成的必要条件 — Web 界面应与供应商 TUI 中显示的内容一致。**Stretch** 项取决于供应商特有的信号，可以提升还原度；这些项目是可选的，当供应商未提供相关信号或数据存在冗余时，可以合理地按 wontfix 关闭。

**P0 — 核心（缺少这些功能将无法使用）**

- [ ] 已选择并实现传输方式（tmux TUI、应用服务器、HTTP/SSE）
- [ ] 连接到 Omnigent MCP
- [ ] 已配置身份验证（供应商登录 / 配置）
- [ ] 流式转发器正常工作（优先使用增量；仅完成后转发亦可接受）
- [ ] Omnigent 策略执行工具使用规则（在工具调用和工具结果阶段均支持 ALLOW / ASK / DENY）
- [ ] 原生请求确认功能会在 Web UI 中显示工具审批请求
- [ ] 中断操作会中止正在运行的轮次
- [ ] 双向同步会将 TUI 输出镜像到 Omnigent 对话中
- [ ] 成本跟踪会报告每个轮次的令牌用量和成本
- [ ] 单元测试覆盖转发器、身份验证和传输方式
- [ ] Mock LLM 测试无需实际 API 调用即可覆盖正常流程

**P1 — 功能对等（完整集成的必要条件）**

- [ ] 模型覆盖在启动时**以及**每次提示时均有效（否则应记录供应商锁定限制）
- [ ] 可从 Omnigent 执行会话命令（清除、分叉、恢复）
- [ ] 恢复/分叉操作会根据 Omnigent 转录记录重建会话
- [ ] 推理 token 会被转发
- [ ] 压缩状态会被呈现
- [ ] 用户提供的图像会被转发（优先使用路径；二进制或文本扁平化形式也可接受）

**扩展目标 — 取决于供应商的保真度**

- [ ] 实时流式传输工具/命令输出（`outputDelta`），而非仅提供最终聚合输出
- [ ] 呈现供应商聚合的工作树差异（如果提供）
- [ ] 镜像生成/查看的媒体（模型生成或模型查看的图像）
- [ ] 将供应商特有模式（审查模式、计划模式等）镜像为状态
