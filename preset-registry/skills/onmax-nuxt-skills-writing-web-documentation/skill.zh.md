# 编写 Web 文档

当用户希望为 Web 项目编写优秀的技术文档，而不只是“在代码周围配上一些文字”时，请使用此技能。目标是产出易于上手、易于浏览、值得信赖且易于维护的文档。

优秀的文档不是产品事实的堆砌，而是一条引导路径，帮助有特定目标的读者逐步了解和使用产品。

## 此技能的优化目标

1. **快速取得首次成功**
   新读者应当能够快速获得可正常运行的结果。

2. **根据意图清晰导航**
   学习产品的初学者和查阅某个选项的专家不应被迫在同一个页面中费力寻找所需内容。

3. **减少歧义**
   命令、文件名、版本、前置条件、预期结果和失败状态都应明确说明。

4. **易于浏览**
   忙碌的开发者通常会先浏览，再仔细阅读。标题、简介、列表、表格和代码块应让页面一目了然、便于导航。

5. **可维护性**
   文档应能从容应对时间推移，易于随代码变更而更新，并让过时信息显而易见。

## 非目标

**不要**针对以下方面进行优化：

- 炒作
- 营销语言
- 在每个页面中详尽介绍所有背景信息
- 在第一篇文档中展示所有受支持的变体
- 炫技式文风
- 缺少说明的大段代码堆砌

## 首先确定：这是什么类型的页面？

在选择页面类型之前，绝不要开始起草。不同页面类型应保持清晰区分。

### README 或文档着陆页

用于介绍和导航。

- 回答：这是什么？适合谁？我应该从哪里开始？
- 保持简短。
- 将深入的详细信息放到子页面中。

### 快速入门

用于通过最短的顺利路径获得可正常运行的结果。

- 一条路径。
- 一个主要环境。
- 尽量减少分支。
- 明确说明前置条件，并清晰展示成功状态。

### 教程

用于通过实践进行教学。

- 读者会构建有实际意义的内容。
- 包含检查点和回顾总结。
- 提供足以支持学习的说明，而不是百科全书式的全面介绍。

### 操作指南

用于解决一个具体问题。

- 假定读者已经掌握基础知识。
- 关注结果，而不是背景理论。

### 参考文档

用于回答精确的事实性问题。

- 语法、选项、默认值、参数、返回值、事件、错误、限制、兼容性。
- 客观、完整、易于浏览。

### 说明 / 概念页面

用于建立心智模型。

- 系统为什么以这种方式工作。
- 架构、权衡、不变量、决策规则。
- 链接到相关的任务文档和参考文档。

### 故障排除页面

用于根据症状诊断问题。

- 症状 -> 可能的原因 -> 修复方法 -> 验证 -> 预防措施。

### 迁移指南

用于版本、API 或架构发生变化时。

- 明确指出破坏性变更。
- 展示变更前后的对比。
- 提供安全的操作顺序。
- 在适用时包含回滚指南。

## 默认工作流

除非用户提出范围更窄的要求，否则请遵循此工作流。

### 1) 确定读者和任务

推断或明确说明：

- 读者类型：初学者、资深用户、维护者、集成者、API 使用者、平台工程师
- 任务：学习、设置、集成、自定义、调试、迁移、部署、贡献
- 环境：框架、运行时、包管理器、操作系统、浏览器、托管目标
- 成功状态：读者完成阅读后应能够做什么

如果缺少任何重要事实，**不要**一直停滞不前。做出范围最小的合理假设，并清楚标明。

### 2）先盘点事实，再撰写正文

收集以下经常会过时的事实：

- 软件包名称
- 安装命令
- 运行时和框架版本
- 支持的浏览器或环境
- 环境变量
- URL、端点、端口、回调路径
- 权限、身份验证要求、密钥、令牌
- 构建、测试和部署命令
- 破坏性变更或限制

如果无法验证某项事实，请避免凭空编造。使用明确标注的占位符或假设。

### 3）先搭建页面框架

在撰写完整段落之前，先使用页面所需的确切章节搭建框架。

建议顺序：

- 背景
- 前提条件
- 操作步骤或正文
- 验证方式 / 预期结果
- 后续步骤 / 相关页面

### 4）以首次成功运行为目标进行编写

每个任务页面都应帮助读者尽早获得一次成功结果。

这意味着：

- 优先展示最短的可行路径
- 尽量减少分支
- 将高级选项放到后面
- 除非项目确实支持多个同等重要的入口，否则优先选择一种包管理器和一种框架
- 展示成功时的效果

### 5）确保示例可以运行

示例应该能够直接复制粘贴，或易于调整。

- 使用真实的文件名和符合实际情况的目录。
- 为代码围栏标注语言。
- 示例应保持精简，但内容完整。
- 仅在注释能够消除歧义时添加注释。
- 如果命令具有破坏性或会产生费用，请先发出警告。
- 在重要步骤后展示预期输出或可见结果。

### 6）精简文字

完成初稿后：

- 缩短引言
- 拆分长段落
- 将含糊的标题改为基于任务的标题
- 删除重复的说明
- 将理论内容移出操作流程页面
- 将详细内容移出落地页

### 7）执行审查清单

交付前使用 `assets/review-checklist.md`。

## 常见任务模式下的响应方式

### 当被要求从头编写页面时

交付：

1. 合适的页面类型
2. 一份完善的 Markdown 草稿
3. 如果有任何重要事实未知，清楚标明相关假设

### 当被要求改进现有文档时

按以下顺序执行：

1. 确定当前页面类型
2. 移除混杂模式
3. 优化结构
4. 重写内容以提高清晰度
5. 保留技术含义
6. 指出事实缺口或内容过时的风险

### 当被要求审查文档时

返回：

- 页面类型
- 按优先级排序的主要问题
- 具体的改写建议
- 缺失的章节
- 任何内容过时或可信度方面的问题

### 当被要求设计文档站点时

返回：

- 受众群体
- 入口点
- 所需的页面类型
- 站点地图
- 内容编写的优先顺序
- 缺口与风险

## 最终指示

最好的文档页面之所以让人感觉轻松，是因为作者为读者做出了一百个审慎的选择：

- 此页面应包含什么
- 不应包含什么
- 什么应放在最前面
- 应删减什么
- 应验证什么
- 应解释什么
- 应推迟什么

请审慎地做出这些选择。
