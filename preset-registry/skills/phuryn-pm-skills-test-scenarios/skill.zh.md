# 测试场景

根据用户故事创建全面的测试场景，包括测试目标、起始条件、用户角色、分步测试操作和预期结果。

**适用场景：** 编写 QA 测试用例、创建测试计划、定义验收测试场景或验证用户故事实现。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$USER_STORY`：要测试的用户故事（标题和验收标准）
- `$CONTEXT`：其他测试背景或约束条件

## 分步流程

1. **审阅用户故事**及验收标准
2. **定义测试目标**——需要验证的具体行为
3. **确定起始条件**——系统状态、数据准备、配置
4. **识别用户角色**——执行测试操作的人员
5. **创建测试步骤**——将交互分解为逐步操作
6. **定义预期结果**——每个步骤完成后的可观察结果
7. **考虑边界情况**——无效输入、边界条件
8. **输出详细测试场景**——可供 QA 执行

## 测试场景示例

**测试场景：** 在商品页面查看最近浏览的商品

**测试目标：** 验证“最近浏览”部分能够正确显示，并且不包含当前商品。

**起始条件：**
- 用户已登录或已启用浏览器历史记录
- 用户在当前会话中至少浏览过 2 件商品
- 用户当前位于一个不同于之前浏览商品的商品页面

**用户角色：** 在线购物者

**测试步骤：**
1. 导航至任意商品页面 → 页面底部应显示包含之前浏览商品的部分
2. 滚动至页面底部 → 可以看到包含商品卡片的“最近浏览”部分
3. 验证商品缩略图 → 图片、标题和价格均正确显示
4. 检查当前商品 → 当前商品**不应**出现在最近浏览列表中
5. 点击商品卡片 → 用户应导航至对应的商品页面

**预期结果：**
- 只有在浏览过至少 1 件之前的商品后，才会显示最近浏览部分
- 该部分显示 4-8 个包含完整信息的商品卡片
- 当前商品不包含在列表中
- 每张卡片显示“X 分钟/小时前浏览”的时间戳
- 点击卡片后会导航至正确的商品页面
- 性能：该部分在 2 秒内完成加载

## 输出交付物

- 针对每项验收标准的全面测试场景
- 与用户故事意图一致的清晰测试目标
- 详细的分步测试操作
- 每个步骤完成后的可观察预期结果
- 边界情况和错误场景覆盖
- 可供 QA 团队执行和记录的内容
