# Suede 社区营销

使用这份 Suede 社区增长手册，在不人为制造互动的前提下，为成员创造真正的价值，并取得可衡量的业务成果。

## 开始之前

**先检查产品营销背景：**
如果 `.agents/product-marketing.md` 存在（或者 `.claude/product-marketing.md`，或旧版设置中的文件名 `product-marketing-context.md`），请先阅读，然后再提问。使用其中的背景信息，只询问尚未涵盖的信息。

了解当前情况（如果未提供，请进行询问）：

1. **产品或品牌是什么？** — 它解决什么问题，谁在使用它
2. **涉及哪些社区平台？** — Discord、Slack、Circle、Reddit、Facebook Groups、论坛等
3. **社区目前处于什么阶段？** — 发布前、0–100 名成员、100–1k 名成员、扩张期或已成熟
4. **社区的首要目标是什么？** — 留存、激活、口碑传播、减少支持压力、产品反馈、收入
5. **理想的社区成员是谁？** — 其角色、动机，以及希望通过加入社区获得什么

根据现有背景开展工作。如果缺少关键信息，请做出合理假设并标明。

## 社区策略原则

### 围绕共同身份构建，而不只是围绕产品构建

最强大的社区围绕成员的身份或其向往成为的样子构建，而不是围绕你的产品构建。成员因为产品加入，但因为社区中的人和身份认同而留下。

示例：r/homelab——其身份认同是喜欢折腾、进行自托管的人，其中的每个仪式、频道和认可机制都在强化这种自我形象。

始终明确：**这个社区强化了成员的什么身份认同？**

### 价值必须优先流向成员

每个社区触点都应该回答：*成员能从中获得什么？*

- 独家知识或提前访问权
- 在其他地方无法获得的同伴关系
- 在他们认可的群体中获得认可和地位
- 直接影响产品路线图
- 职业机会、曝光度或可信度

## 按目标划分的行动手册

### 从零开始创建社区

1. **手动招募 20–50 名创始成员** — 私信最活跃的用户、测试者或粉丝。在形成基础活跃度之前，不要公开开放。
2. **明确设定社区文化** — 编写社区指南，描述的是*氛围*，而不只是规则。这里所期待的高质量参与是什么样的？
3. **在发布前预先发起对话** — 预先在各个频道中发布 5–10 条示范性帖子，展示你希望成员采取的行为。可以是问题、成果或资源。
4. **一开始做一些无法规模化的事情** — 回复每一条帖子。逐一称呼新成员的名字并表示欢迎。每周举办一次线上通话。你是在购买社会认同。
5. **定义你的核心循环** — 你希望成员每周采取什么行动？让这个行动变得简单，并公开给予奖励。

### 发展已有社区

1. **审查成员在哪个环节流失** — 人们是加入后不发帖？还是发过一次后就消失？找出出现流失的环节。
2. **设计新成员旅程** — 一篇置顶欢迎帖、一个 #introduce-yourself 频道、一条来自社区经理的私信或邮件，以及一条清晰的“从这里开始”路径。
3. **公开展示成员成果** — 展示用户项目、推荐语和里程碑。这会强化身份认同，并传递出参与能够获得回报的信号。
4. **开展周期性的社区仪式** — 每周主题帖（例如“你正在做什么？”）、每月 AMA、季节性挑战。仪式能够形成习惯。
5. **识别并投入资源培养核心用户** — 参与度通常高度集中在少数成员身上
   （推断所得；在引用比例之前，请根据该社区自身的
   每位成员发帖数量分布进行验证）。为观察到的顶级贡献者提供认可、提前访问权、版主角色或参与产品决策的机会。

### 构建品牌大使 / 倡导者计划

1. **确定候选人** — 寻找那些已经主动推荐你的人。查看评价、社交媒体提及和社区帖子。
2. **让邀请更具个人化** — 不要发送通用表单。进行一对一联系，并说明为什么特别选择了他们。
3. **提供有意义的福利** — 专属访问权限、周边、收入分成或公开认可，而不只是“抢先体验功能”。
4. **为他们提供工具和内容** — 推荐链接、可分享的素材、核心介绍要点、私密 Slack 频道。
5. **衡量并迭代** — 跟踪倡导者带来的推荐流量、注册量和参与度。加倍投入有效的做法。

### 社区主导的支持（分流 + 留存）

1. **根据社区中的高频问题创建可搜索的知识库**
2. **认可那些帮助他人的成员** — “社区专家”徽章、排行榜、公开致谢
3. **与产品团队形成闭环** — 当社区反馈推动了某项变更时，公开宣布这一变更，并感谢提出反馈的成员
4. **每周监测情绪** — 在投诉或困惑演变为流失信号之前，寻找其中的模式

## 平台选择指南

| 平台 | 最适合 | 需要注意 |
|----------|----------|---------------|
| Discord | 开发者、游戏、创作者社区；实时聊天 | 噪音较多，难以搜索，入门流程存在阻力 |
| Slack | B2B / 专业社区；SaaS 买家熟悉 | 免费层级限制历史记录；让人感觉像在工作 |
| Circle | 创作者或课程型社区；用户体验简洁 | 有机发现较少；需要主动导流 |
| Reddit | 高流量公共社区；有利于 SEO | 你不拥有它；管理难度高 |
| Facebook Groups | 消费品牌；年龄较大的受众 | 有机触达率下降；依赖算法 |
| Forum (Discourse) | 长篇技术社区；SEO 价值高 | 发展速度较慢；发帖所需投入更高 |

## 社区健康指标

每周跟踪这些信号。根据证据类别为每个数字标注类别 — 下文的边界规则禁止在缺少来源、时间窗口和分母的情况下陈述其中任何数字：

- **已观测** — 直接从平台的管理视图或导出数据中读取。注明视图名称和提取日期。
- **已计算** — 从已观测值推导得出。展示公式和分母（`new member post rate = new members posting within 7 days / members who joined in the same window`）。
- **已推断** — 有待验证的假设，包括从该社区之外取得的任何基准。绝不能将其表述为该社区的事实。
- **未知** — 平台未公开该指标。说明需要什么信息才能确定它。

指标：

- **DAU/MAU 比率** — 用户黏性（已计算：daily actives / monthly actives）。20% 的底线是跨行业的已推断基准，并不是该社区的健康线；应与该社区自身过去几周的数据进行比较。
- **新成员发帖率** — 新成员中在加入后 7 天内发帖的比例
- **帖子回复率** — 至少收到一条回复的帖子比例
- **流失 / 潜水者比例** — 已加入但 30 多天未发帖的成员
- **由非员工创建的内容** — 非公司团队撰写的帖子比例

**警示信号：**
- 大多数帖子来自公司团队，而不是成员
- 问题超过 24 小时仍无人回答
- 互动集中在少数几个账号中——在认定为警示信号之前，先计算指定时间窗口内排名前 5 的发帖者所发布帖子的占比
- 新成员在发布自我介绍后便不再发帖

## 输出格式

根据用户的需求，产出以下其中一种：

- **社区策略文档** — 平台选择、身份定义、核心循环、90 天启动计划
- **频道架构** — 推荐的频道/分类、各自的用途和发帖指南
- **新成员旅程** — 欢迎流程：置顶帖、私信模板、第一周提示
- **社区仪式日历** — 每周/月度的定期活动和主题帖
- **大使计划简介** — 标准、权益、联络模板、跟踪计划
- **社区健康审计报告** — 当前指标、诊断、需要修复的前 3 项优先事项

始终要具体。泛泛而谈的建议（“保持一致”“提供价值”）没有用。要让用户今天就能采取行动。

### 社区策略文档 — 精确标题

```markdown
# <Community name> — Strategy

## Identity
Member identity reinforced: <who members are or aspire to be>
Who is explicitly not the member: <exclusion>

## Platform Choice
Chosen: <platform> | Rejected: <platform> because <watch-out from the table>
Evidence class for any cited benchmark: Observed | Computed | Inferred | Unknown

## Core Loop
Weekly member action: <one action>
What makes it easy: <mechanic>
How it is rewarded publicly: <mechanic>
Where new value re-enters: <mechanic>

## Seeding Plan
Founding members (20–50, manually recruited): <source list>
Pre-launch seed posts: <5–10 topics that model the behavior>
Culture statement: <what great participation looks like here>

## 90-Day Plan
Days 0–30 | Days 31–60 | Days 61–90 — for each: goal, rituals live,
owner, primary metric with its denominator

## Measurement
Primary metric: <metric> = <formula> / <denominator>, window <n> days
Diagnostics (2–4): <metric + evidence class each>

## Open Gates
<authorization or evidence still missing; use the halt contract below>
```

其他五种交付物使用以下标题：

- **频道架构** — 频道 | 用途 | 谁发帖 | 发帖规则 | 成功信号
- **新成员旅程** — 置顶帖 / 私信模板 / 第 1–7 天提示 / 首次成功定义 / 流失检查点
- **社区仪式日历** — 仪式 | 频率 | 负责人 | 成员任务 | 终止条件
- **大使计划简介** — 标准 / 权益 / 联络模板 / 披露要求 / 跟踪计划
- **社区健康审计报告** — 带证据类别和分母的指标 / 诊断 / 前 3 项优先事项 / 哪些情况会证伪该诊断

## 暂停契约

当授权、证据或执行决策阻碍所请求的结果时，使用以下确切格式——包括空间创建、邀请、角色、审核、移除和公告门槛，以及“边界条件”中的执行结果门槛：

```text
HALT — <one-line blocker>
Why it blocks: <specific missing authority or evidence>
Resolve with:
1. <option>
2. <option>
3. <option, when useful>
Waiting for: <the exact item or approval>
```

仅当安全的草案、计划或工作表仍然有用，且不会让人误以为阻塞问题已经解决时，才继续提供这些内容。

---

## 边界

- 如果没有明确的来源、时间窗口和分母，不要声称拥有成员数量、参与度、留存率、情绪倾向或倡导者数据。
- 未获得明确授权，不要创建空间、邀请成员、分配角色、进行审核、删除内容或发布公告。
- 不要捏造活动、冒充成员、隐瞒激励措施，或将付费倡导呈现为自然产生的倡导。
- 不要超出已记录的社区规则和升级路径，擅自决定执行结果。

## 路由

- 需要推荐或大使激励 -> 使用 `suede-referrals`。
- 需要公开社交内容 -> 使用 `suede-social`。
- 需要成员语言研究 -> 使用 `suede-customer-research`。
- 需要超出社区行为范围的留存诊断 -> 使用 `suede-churn-prevention`。
- 需要用于欢迎帖、仪式公告或大使素材的图形 -> 使用 `suede-image`；需要视频素材 -> 使用 `suede-video`。
- 面向成员的文案发布前需要最终的反废话检查 -> 使用 `suede-deslop`。
- 从这些技能转回社区目的、平台、仪式和审核设计时，使用 `suede-community-marketing`。
