# 验收测试构建器

**目标：** 针对已陈述的需求，通过用户或外部系统可观察的边界，交付最小且可信的验收测试组合。仅修改已批准的测试和测试文档；在不修复产品代码的前提下，实施有充分理由的新增、更新、合并和删除。

**执行契约：** 将以下有序复选框工作流视为此技能的完成定义。将每个复选框都标记为 `PENDING`，然后使用具体证据将其解决为 `PROVEN`，使用证明其条件触发器不存在的证据将其解决为 `CLEARED`，或解决为 `UNPROVEN`；阅读、提及、委派、跳过或工具失败都不构成证明。
返回前，解决所有 `PENDING`，仅将 `PROVEN` 和 `CLEARED` 项计为完成，将此技能的判定、决策和批准规则应用于每个 `UNPROVEN` 项，并添加前缀 **Checklist: X/Y complete**<br>**Incomplete: None | section/item — reason; outcome impact; exact next action**；列出每个 `UNPROVEN` 项。

## 工具路由

| 需求 | 首选工具 | 使用时机 | 备用方案 |
|---|---|---|---|
| 工作区安全 | Git 状态、差异、仓库说明，以及分支或工作树检查 | 始终在编辑前执行 | 当无法安全区分用户更改时停止 |
| 现有测试约定 | 文件列表、搜索、清单、运行器配置、CI，以及定向读取 | 选择项目原生运行器、布局、固定装置和命令时 | 遵循距离最近的受维护测试模式 |
| 行为和接线 | 语言服务器或宿主原生代码智能 | 定位可观察入口点、注册、消费者和状态边界时 | 缩小范围搜索并直接检查 |
| 测试实现 | 原生编辑工具和项目生成器 | 创建测试、固定装置、辅助程序，以及必要范围内的测试文档时 | 使用符合项目规范的最少文件；绝不手动编辑生成状态 |
| 可观察执行 | 仓库定义的 shell 命令、浏览器、API 客户端、CLI 或一次性集成环境 | 证明 UI、协议、命令或持久状态结果时 | 返回 `INCOMPLETE` 并给出确切的缺失检查 |
| 外部契约 | 与版本匹配的官方文档或规范 | 预期行为依赖当前外部 API 或标准时 | 标记为 `UNVERIFIED`；不要编码猜测出的预言机 |

绝不要针对生产环境或未经批准的外部目标运行验收测试。不要部署、发布、迁移共享数据、轮换凭据，也不要仅为了让测试通过而接受变更后的输出。

## 证据规则

- 从需求、公共契约、示例、不变量或独立参考中推导预期行为；绝不要从被测试的实现计算中推导。
- 优先选择终端持久化结果或用户可见结果，而不是中间状态、模拟调用、日志行或内部方法结果。
- 仅对确定且可审查的契约使用黄金文件或快照。更新预期输出属于规范变更，而不是测试验证。
- 使设置、数据分配、执行、清理和重新运行行为可复现；在重试或清理使首次失败变得难以辨认之前保留首次失败。
- 一条通过的命令只能证明它实际执行的环境和场景。明确说明每个被排除的单元格和不可用的边界。
- 不要测试语言、框架、软件包、数据库供应商或其他通用行为；只测试依赖于这些因素的、由仓库拥有的可观察契约、配置、集成或策略。
- 将 `KEEP`、`ADD`、`UPDATE`、`MERGE`、`DELETE` 和 `NO_TEST` 视为组合决策，与执行结果区分开来。当现有证据、整合、淘汰或已接受的剩余风险是更好的答案时，不要默认选择 `ADD`。
- 仅当测试依据已经过时，或证据表明所有仍有要求的独特材料行为、失败模式、预言机强度和有用的失败定位仍然得到覆盖时，才删除或合并。

## 检查清单

### 1. 确定变更边界

- [ ] 明确需求、验收标准、参与者、受保护结果、可观测契约、明确的非目标、已批准的组合决策、允许的测试路径和允许的测试文档路径；将推断出的体验质量标记为假设。
- [ ] 在编辑前阅读适用的仓库说明，并检查 Git 状态、未跟踪文件、生成区域和现有用户变更。
- [ ] 识别项目原生的运行器、目录布局、命名方式、fixture、设置、清理、环境配置和 CI 调用方式。
- [ ] 在创建新测试前，盘点受需求或契约影响的现有测试，并梳理其实际断言依据。
- [ ] 将每项需求映射到能够证明它的边界：UI、API、CLI、消息、集成、文件或持久化状态。
- [ ] 识别场景所需的凭据、服务、账户、端口、设备、浏览器、数据集和破坏性影响。
- [ ] 当不存在安全的目标、可靠的预期契约或可分隔的工作区时，在编辑前返回 `BLOCKED`。

### 2. 设计可复现的验收证据

- [ ] 为每项需求定义受保护结果、缺陷类别、设置、操作、终止结果、独立断言依据、预期证据和清理步骤。
- [ ] 为每个受影响的测试和重大风险确认或推导出一项组合决策中的操作。当不存在已批准的策略时，根据影响、合理的失败可能性、独特性、可信度和维护成本论证该操作；使用现有证明、其他控制措施或已接受的剩余风险记录 `NO_TEST`。
- [ ] 对重大的用户可观察业务风险，优先采用确定性的端到端证据。只有在更窄的、贴近生产形态的契约或集成边界仍能更确定或更精确地证明终止结果时，才使用该边界；绝不要用单元实现检查替代验收证据，也不要覆盖可观测契约中不存在的内部细节。
- [ ] 仅当无效行为、授权行为、边界行为、部分失败、重试、幂等性、恢复和兼容性行为可能实质性改变受保护结果时，才将其纳入。
- [ ] 分配唯一的或带命名空间的测试数据，并在时钟、随机性、区域设置、顺序和并发性会影响可复现性时对其进行控制。
- [ ] 当模拟会绕过验收所需的行为时，使用真实依赖项或已批准的仿真器；固定版本，并验证就绪状态和重置行为。
- [ ] 对于确定性输出，根据独立契约推导 golden 或差异预期，并使产物保持足够小以便审查。
- [ ] 对于非确定性输出，断言稳定的不变量和语义字段，而不是通过标准化消除失败或对噪声进行快照。
- [ ] 仅通过稳定的、由仓库负责维护的 ID 或专用测试钩子定位 UI 和其他交互元素；绝不要通过可见文本或翻译后的文案、样式、布局、位置或偶然的结构进行定位；只有在精确文案属于明确契约时，才单独断言该文案。
- [ ] 当证据是临时的、受兼容性约束的、特定于事件的或与变化中的契约耦合时，定义所需的或诊断性的门禁，以及审查或退役触发条件。

### 3. 在测试范围内实施

- [ ] 按照现有项目布局创建或更新测试，使用能够识别被违反要求、受保护结果和所检测缺陷的行为描述名称与失败消息。
- [ ] 实施已批准的 `MERGE` 和 `DELETE` 操作，不得遗留已被取代的测试、fixture、快照、辅助工具、注册项或 CI 条目；通过仓库原生的路径、名称、标签或任务证据保留替换可追溯性。
- [ ] 仅当现有默认值和副作用仍然可见时，才复用受维护的 fixture 和辅助工具；避免为单个场景新增抽象。
- [ ] 在缺少前置条件时让设置过程快速失败，并确保清理操作在成功、断言失败、超时、取消或部分设置之后均安全执行。
- [ ] 确保测试可重复运行且幂等；不得依赖执行顺序，也不得静默复用上一次运行遗留的状态。
- [ ] 仅当贡献者无法以其他方式配置、运行、解释或清理新增证据时，才添加范围最窄的必要测试文档。
- [ ] 不得编辑生产代码、弱化断言、在没有证据的情况下扩大超时时间、跳过失败用例，或重新生成预期产物以获取通过结果。
- [ ] 检查差异，确认不存在无关格式调整、生成文件变动、机密信息、特定环境路径，以及超出已批准范围的更改。

### 4. 执行并保留证据

- [ ] 先运行受影响范围最小的场景，然后运行相关测试套件和所需的仓库门禁（如有）；当操作仅移除证据时，运行替代证据或最近的保留证明。
- [ ] 记录确切命令、工作目录、环境类别、目标、版本、退出状态、持续时间和产物位置。
- [ ] 保留重现缺陷所需的首次失败输出、种子、顺序、请求、响应、屏幕截图、差异或持久状态。
- [ ] 在修改测试之前，区分产品失败、测试缺陷、环境失败、不可用依赖和不稳定证据。
- [ ] 如果测试暴露出产品缺陷，则停止修改实现，保留失败的验收证据，并报告最小复现步骤。
- [ ] 在状态所有权或幂等性至关重要时，验证清理操作，并至少重新运行受影响的场景。
- [ ] 除非用于诊断非确定性，否则避免重试；重试不得将初始失败转化为静默通过。

### 5. 在不过度声称的前提下完成收尾

- [ ] 将每项要求和受保护结果映射到其最终测试路径或 `NONE`、命令或替代控制、判定依据或已接受风险，以及 `PASS`、`FAIL`、`BLOCKED` 或 `UNPROVEN` 结果。
- [ ] 核对计划中的操作与实际执行的测试组合操作，包括有理有据的偏差，并报告新增、更新、合并和删除测试的净数量；不得将数量视为质量目标。
- [ ] 当所有已批准的测试组合操作均已实施，且所需的验收证据均执行并记录为 `PASS` 或 `FAIL` 时，使用 `COMPLETE`；该判定描述的是证据完成情况，而非产品正确性。
- [ ] 当操作已实施，但环境、依赖或中断的运行阻止完整执行时，使用 `INCOMPLETE`；说明确切缺失的检查项。
- [ ] 当无法安全实施操作、要求缺少可靠的判定依据，或工作区无法得到保护时，使用 `BLOCKED`。
- [ ] 返回已创建、已更改、已合并和已删除的测试文件、命令、证据、清理结果、局限性、产品缺陷和剩余风险。

## 输出契约

```markdown
# Acceptance Test Build

**Verdict:** COMPLETE | INCOMPLETE | BLOCKED

## Scope and environment
- Requirements and approved paths
- Runner, boundary, target, and prerequisites

## Requirements matrix
| Protected outcome and test basis | Existing evidence or affected test | Action | Final test | Oracle and command | Gate and result | Review or retirement trigger |
|---|---|---|---|---|---|---|
| ... | path / command / NONE | KEEP / ADD / UPDATE / MERGE / DELETE / NO_TEST | path / NONE | ... | required / diagnostic; PASS / FAIL / BLOCKED / UNPROVEN | ... |

## Changes and evidence
- Created or changed test and documentation files
- Deleted or consolidated tests and their replacement evidence; net portfolio effect
- Exact commands, outputs, and evidence artifacts
- Product defects preserved without repair

## Cleanup, limitations, and residual risks
State cleanup, unavailable environments, excluded cells, and remaining evidence needs.
```
