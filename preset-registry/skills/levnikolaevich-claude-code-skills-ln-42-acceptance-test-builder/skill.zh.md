# 验收测试构建器

**目标：** 通过用户或外部系统可观察的边界，为既定需求交付规模最小且可信的验收测试组合。仅修改已获批准的测试和测试文档；在不修复产品代码的前提下，实施有充分理由的新增、更新、合并和删除。

**执行约定：** 将下方按顺序排列的复选框工作流视为此技能的完成定义。按顺序完成每一项，只有在其操作和所需证据均已完成时，才将其标记为完成。标记为 `N/A`、已跳过、不可用或已委派的项目仍视为未完成。
返回前，将此技能的裁定、决策和批准规则应用于每个未完成项目，并在回复开头添加 **Checklist: X/Y complete**<br>**Incomplete: None | section/item — reason; outcome impact; exact next action**；列出每个未完成项目。

## 工具选择

| 需求 | 首选工具 | 使用时机 | 后备方案 |
|---|---|---|---|
| 工作区安全 | Git 状态、差异、仓库说明以及分支或工作树检查 | 始终在编辑前执行 | 当无法安全地分离用户更改时停止 |
| 现有测试约定 | 文件列表、搜索、清单、运行器配置、CI 和针对性读取 | 选择项目原生的运行器、布局、夹具和命令时 | 遵循最近且仍在维护的测试模式 |
| 行为和连接关系 | 语言服务器或宿主原生代码智能工具 | 定位可观察入口点、注册位置、使用方和状态边界时 | 缩小范围的搜索加直接检查 |
| 测试实现 | 原生编辑工具和项目生成器 | 创建测试、夹具、辅助工具以及严格限定为必需的测试文档时 | 使用最少且符合项目惯例的文件；绝不手动编辑生成的状态 |
| 可观察执行 | 仓库定义的 shell 命令、浏览器、API 客户端、CLI 或一次性集成环境 | 证明 UI、协议、命令或持久状态结果时 | 返回 `INCOMPLETE`，并说明确切缺失的检查 |
| 外部契约 | 与版本匹配的官方文档或规范 | 预期行为依赖当前外部 API 或标准时 | 将其标记为 `UNVERIFIED`；不要编码基于猜测的判定依据 |

绝不要对生产环境或未经批准的外部目标运行验收测试。不要部署、发布、迁移共享数据、轮换凭据，也不要仅仅为了让测试通过而接受发生变化的输出。

## 证据规则

- 从需求、公开契约、示例、不变量或独立参考中推导预期行为；绝不要从被测实现的计算逻辑中推导。
- 相较于中间状态、模拟调用、日志行或内部方法结果，应优先选择最终的持久结果或用户可见结果。
- 仅将黄金文件或快照用于确定性且便于审查的契约。更新预期输出属于规范变更，而不是测试验证。
- 使设置、数据分配、执行、清理和重新运行行为可复现；在重试或清理掩盖首次失败之前保留该失败。
- 一条通过的命令只能证明其实际执行过的环境和场景。说明每个被排除的单元格和不可用的边界。
- 不要测试语言、框架、软件包、数据库供应商或其他通用行为；仅测试由仓库自身拥有且依赖这些内容的可观察契约、配置、集成或策略。
- 将 `KEEP`、`ADD`、`UPDATE`、`MERGE`、`DELETE` 和 `NO_TEST` 视为测试组合决策，并将其与执行结果区分开。当现有证据、整合、退役或已接受的剩余风险是更优选择时，不要默认选择 `ADD`。
- 仅当测试依据已过时，或有证据表明所有仍然需要的独特实质性行为、失败模式、判定依据强度和有用的失败定位能力仍然得到覆盖时，才删除或合并测试。

## 检查清单

### 1. 确立变更边界

- [ ] 明确需求、验收标准、参与者、受保护的结果、可观察契约、明确的非目标、已批准的测试组合决策、允许的测试路径以及允许的测试文档路径；将推断出的体验质量标记为假设。
- [ ] 编辑前，阅读适用的仓库说明，并检查 Git 状态、未跟踪文件、生成内容区域以及现有的用户变更。
- [ ] 识别项目原生的运行器、目录布局、命名方式、固件、设置、清理流程、环境配置以及 CI 调用方式。
- [ ] 创建新测试前，盘点受需求或契约影响的现有测试，并梳理其实际判定依据。
- [ ] 将每项需求映射到能够证明它的边界：UI、API、CLI、消息、集成、文件或持久状态。
- [ ] 识别场景所需的凭据、服务、账户、端口、设备、浏览器、数据集以及破坏性影响。
- [ ] 当不存在安全的目标、可靠的预期契约或相互隔离的工作区时，在编辑前返回 `BLOCKED`。

### 2. 设计可复现的验收证据

- [ ] 为每项需求定义受保护的结果、缺陷类别、设置、操作、最终结果、独立判定依据、预期证据和清理流程。
- [ ] 为每个受影响的测试和重大风险确认或推导一项测试组合操作。如果没有已批准的策略，则根据影响、可能的故障、独特性、可信度和维护成本说明该操作的理由；记录 `NO_TEST`，并注明现有证明、其他控制措施或已接受的残余风险。
- [ ] 对重大的、用户可观察的业务风险，优先采用确定性的端到端证据。仅当范围更窄且贴近生产的契约或集成边界仍能以更具确定性或更精确的方式证明最终结果时，才使用该边界；绝不使用单元级实现检查替代验收证据，也不要覆盖可观察契约中不存在的内部细节。
- [ ] 仅当无效输入、授权、边界、部分失败、重试、幂等性、恢复和兼容性行为可能实质性改变受保护的结果时，才将其纳入测试。
- [ ] 分配唯一或带命名空间的测试数据，并在时钟、随机性、区域设置、顺序和并发会影响可复现性时对其进行控制。
- [ ] 当模拟对象会绕过验收范围内的行为时，使用真实依赖项或已批准的模拟器；固定版本，并验证就绪状态和重置行为。
- [ ] 对于确定性输出，根据独立契约推导黄金文件或差异比较预期，并确保工件足够小，以便审查。
- [ ] 对于非确定性输出，断言稳定的不变量和语义字段，而不是通过归一化掩盖故障或对噪声创建快照。
- [ ] 仅通过稳定的、由仓库所有的 ID 或专用测试钩子定位 UI 及其他交互元素；绝不通过可见或已翻译的文案、样式、布局、位置或附带结构进行定位，并且仅当精确文案属于明确契约时，才单独对其进行断言。
- [ ] 当证据是临时性的、受兼容性约束的、特定于事件的或与不断变化的契约耦合时，定义必要的或诊断性的门禁，以及审查或退役触发条件。

### 3. 在测试范围内实施

- [ ] 在现有项目布局中创建或更新测试，使用能够体现行为的名称和失败消息，明确指出被违反的要求、受保护的结果以及检测到的缺陷。
- [ ] 实施已批准的 `MERGE` 和 `DELETE` 操作，不得遗留已被取代的测试、夹具、快照、辅助工具、注册项或 CI 条目；通过仓库原生的路径、名称、标签或任务证据保留替换可追溯性。
- [ ] 仅当受维护夹具和辅助工具的默认值及副作用仍然可见时才复用它们；避免为单个场景创建新的抽象。
- [ ] 设置流程应在缺少先决条件时快速失败，并确保在成功、断言失败、超时、取消或部分设置之后都能安全清理。
- [ ] 保持测试可重复运行且具备幂等性；不得依赖执行顺序，也不得静默复用上一次运行遗留的状态。
- [ ] 仅当贡献者无法以其他方式配置、运行、解读或清理新证据时，才添加范围最小的必要测试文档。
- [ ] 不得为了使测试通过而编辑生产代码、弱化断言、在缺乏证据的情况下延长超时时间、跳过失败用例或重新生成预期产物。
- [ ] 检查差异中是否存在无关的格式更改、生成内容扰动、机密信息、特定于环境的路径，以及超出已批准范围的更改。

### 4. 执行并保留证据

- [ ] 首先运行受影响范围最小的场景，然后运行相关测试套件，并在可用时运行仓库要求的门禁检查；如果操作仅删除证据，则运行替代证据或最接近的保留证明。
- [ ] 记录确切的命令、工作目录、环境类别、目标、版本、退出状态、持续时间和产物位置。
- [ ] 保留重现缺陷所需的首次失败输出、种子、顺序、请求、响应、截图、差异或持久状态。
- [ ] 在更改测试之前，区分产品失败、测试缺陷、环境失败、依赖项不可用和不稳定证据。
- [ ] 如果测试暴露出产品缺陷，请停止修改实现，保留失败的验收证据，并报告最小复现方式。
- [ ] 当状态所有权或幂等性很重要时，验证清理过程，并至少重新运行受影响的场景。
- [ ] 除非重试用于诊断非确定性，否则应避免重试；重试不得将首次失败转变为静默通过。

### 5. 最终确认，避免夸大结论

- [ ] 将每项要求和受保护的结果映射到其最终测试路径或 `NONE`、命令或替代控制措施、判定依据或已接受风险，以及 `PASS`、`FAIL`、`BLOCKED` 或 `UNPROVEN` 结果。
- [ ] 核对计划与实际执行的测试组合操作，包括有合理依据的偏差，并报告新增、更新、合并和删除的测试净数量，但不得将数量视为质量目标。
- [ ] 当所有已批准的测试组合操作均已实施，且所需的验收证据已执行并记录为 `PASS` 或 `FAIL` 时，使用 `COMPLETE`；该结论描述的是证据完备性，而非产品正确性。
- [ ] 当操作已实施，但环境、依赖项或执行中断导致无法完成全部执行时，使用 `INCOMPLETE`；说明确切缺失的检查。
- [ ] 当操作无法安全实施、要求缺少可靠的判定依据，或工作区无法得到保护时，使用 `BLOCKED`。
- [ ] 返回已创建、更改、合并和删除的测试文件、命令、证据、清理结果、限制、产品缺陷和残余风险。

## 输出契约

```markdown
# Acceptance Test Build

**Verdict:** COMPLETE | INCOMPLETE | BLOCKED

## Scope and environment
- Requirements and approved paths
- Runner, boundary, target, and prerequisites

## Requirements matrix
| Protected outcome and test basis | Existing evidence or affected test | Action | Final test | Oracle and command | Gate and result | Review or retirement trigger |
|---|---|---|---|---|---|---|
| ... | path / command / NONE | KEEP / ADD / UPDATE / MERGE / DELETE / NO_TEST | path / NONE | ... | required / diagnostic; PASS / FAIL / BLOCKED / UNPROVEN | ... |

## Changes and evidence
- Created or changed test and documentation files
- Deleted or consolidated tests and their replacement evidence; net portfolio effect
- Exact commands, outputs, and evidence artifacts
- Product defects preserved without repair

## Cleanup, limitations, and residual risks
State cleanup, unavailable environments, excluded cells, and remaining evidence needs.
```
