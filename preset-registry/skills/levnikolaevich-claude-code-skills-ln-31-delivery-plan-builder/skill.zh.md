# 交付计划构建器

**目标：** 为所请求的成果返回一份决策完备、与工作量相称的交付计划。规划应保持只读：不得编辑文件、创建跟踪事项、实施、发布或部署。

**执行约定：** 有序复选框即为完成定义。将每个事项在内部跟踪为 `PENDING`、附有具体证据的 `PROVEN`、附有其条件不存在证据的 `CLEARED`，或存在缺口的 `UNPROVEN`；阅读、委派或工具失败均不构成证明。每个章节后都应核对事项。返回前，解决所有 `PENDING`，且仅统计 `PROVEN` 和 `CLEARED`；对每个缺口应用该技能的判定和审批规则。
保留用户意图、范围及现有授权。继续已获授权的工作；仅针对后果重大的未解决选择或必要的外部审批提问。根据实际风险调整深度，不得悄然跳过检查。保留依赖关系和安全顺序；在此之外，为每项义务选择恰当的验证方法。
将等效的用户或仓库证据视为有效输入；其他技能、命名工件或完整生命周期均不是前置条件。尽可能保留来源需求和决策标识符。将复用证据绑定至相关来源版本、未提交更改、配置及环境；发生更改后，仅使受影响的主张失效。
继续执行时，在恢复前核对任务、现有授权、当前状态和未解决证据。对于长期工作，返回一份紧凑的继续记录，或更新已获授权的任务工件；只读技能不持久化此记录。区分工件就绪性、已验证行为以及执行外部操作的授权。
在任何必要审批之前准备已获授权的工作。若某项指令阻止进展，指出其确切来源并说明未解决的边界；不要因一般性的谨慎而虚构审批门槛。

## 工具路由

| 需求 | 首选能力 | 备用方案 |
|---|---|---|
| 成果与约束 | 用户请求、需求和已接受的设计决策 | 等效的对话或仓库证据；无需强制上游技能 |
| 实现归属 | 代码智能、聚焦的定义与消费者/配置读取 | 窄范围符号搜索和直接因果追踪 |
| 验证与交付 | 仓库测试/构建/发布定义及环境契约 | 指明确切缺失的前置条件和可行的证据操作 |

## 领域规则

- 规划完整的可观察增量，而非任意的文件批次。区分计划中的工作、证据和授权。
- 优先遵循现有项目惯例并采用最小完整实现；估算是带有假设的范围，而非承诺。
- 若已提供迁移计划，则由其负责详细的过渡语义；引用该计划，不要虚构相互竞争的顺序。

## 检查清单

### 1. 确立交付契约

- [ ] 明确业务成果、验收标准、受保护行为、已授权的实现边界和非目标。
- [ ] 检查仓库指令、相关 Git 状态、来源需求以及已接受/拟议的设计状态。
- [ ] 追踪受影响的入口点、归属逻辑、状态、消费者和集成；识别可能改变计划的证据缺口。
- [ ] 在呈现可执行计划之前，解决后果重大的意图、兼容性和外部状态选择。

### 2. 选择工作单元

- [ ] 识别最小的完整方案，包括在满足验收条件时采用不做变更、配置、删除或复用。
- [ ] 将必要工作划分为可独立验证的结果，并明确输入、负责边界和完成证据。
- [ ] 将每项实质性要求和受保护的不变量映射到至少一个工作单元和验收检查。
- [ ] 梳理来自契约、数据、部署顺序和共享状态的依赖；消除循环依赖，或明确需要作出的决策。
- [ ] 仅在接口和变更所有权彼此独立时允许并行工作；不要强制要求委派给其他代理。
- [ ] 指定工作单元之间的集成检查和最终可观察的用户流程；仅完成本地单元不足以证明完成。

### 3. 规划验证和恢复

- [ ] 将实质性故障和回归风险映射到最小且可靠的检查，并明确其前置条件和通过标准。
- [ ] 复用有效的现有测试证据和策略；识别需要新增、更新、弃用的内容，或说明有依据的不测试决定。
- [ ] 在适用时，识别迁移、功能开关、兼容性和发布依赖，并明确中止与恢复条件。
- [ ] 说明任何不可逆步骤和获授权的外部边界；仅能前向修复时，绝不承诺回滚。
- [ ] 区分本地实现、发布产物、部署和产品结果验证。

### 4. 检查计划完整性

- [ ] 检查需求覆盖、依赖顺序、集成所有权，以及是否存在未显式处理的重大决策。
- [ ] 仅在有用时估算工作量，并说明假设和不确定性；识别关键路径，避免制造虚假的精确度。
- [ ] 在响应中返回计划，并注明来源标识和明确未解决的证据；不要持久化跟踪器或文档。
- [ ] 识别哪些需求或来源变更会使每个受影响的工作单元或检查失效。

## 判定

- `READY`：计划通过可执行的工作单元、可信的验证和已解决的重大决策覆盖了验收与集成。
- `REVISE`：计划可用，但存在需要解决的明确缺口或相互冲突的依赖。
- `BLOCKED`：关键意图、所有权或证据不可用，无法负责任地建立有界计划。

## 自检

- [ ] **返回前进行核对。** 检查条目级证据、需求覆盖、矛盾、范围、判定结果和适用的清理工作。更正报告或获授权的产物。复用有效证据；不要自动重新扫描仓库或重新运行已成功的命令。仅针对相关变更、失败项或未解决的证据重复检查。披露剩余缺口。

## 输出契约

使用用户的语言按以下顺序报告；保留全部五个字段，并且每项事实只陈述一次。结果较小时可以每个字段使用一行；省略空表格，不要复制链接的产物：

1. **结果：** Skill 专属判定结果和得到支持的成果。
2. **范围：** 已审查/变更的范围、排除项、基线和重大假设。
3. **证据：** 以下 Skill 专属字段；区分事实、推断和未经验证的声明。链接产物；适用时使用表格。
4. **验证：** 检查/结果、不可用的证据，以及适用的清理工作/外部状态。
5. **完成情况：** `Checklist: X/Y complete`；`Incomplete: None` 或列出每个 `UNPROVEN` 项的原因、对结果的影响和明确的下一步行动；剩余风险和需要作出的决策。

**技能专属证据：**结果和源状态；需求到单元再到验证的映射；依赖项、集成、受影响边界、恢复、估算（如有用），以及确切的未解决前置条件。
