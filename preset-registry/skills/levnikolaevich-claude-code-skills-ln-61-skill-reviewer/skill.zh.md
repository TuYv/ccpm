# Skill 审核者

**目标：** 在不修改仓库或外部状态的前提下，审核技能质量和已配置的分发面。区分静态契约保证与已观察到的执行行为。

**执行契约：** 有序复选框即为完成定义。内部跟踪每一项为 `PENDING`、附有具体证据的 `PROVEN`、附有其条件不存在证据的 `CLEARED`，或标明缺口的 `UNPROVEN`；阅读、委托或工具失败均不构成证明。每个章节后重新核对各项。返回前，解决所有 `PENDING`，且仅统计 `PROVEN` 和 `CLEARED`；对每个缺口应用该技能的判定和批准规则。
保留用户意图、范围和既有授权。继续已获授权的工作；仅就有重要影响的未决选择或所需外部批准提问。根据实质性风险调整深度，不得悄然跳过检查。保留依赖关系和安全顺序；其余情况下，为每项义务选择适当的验证方法。

## 工具路由

| 需求 | 首选能力 | 备用方案 |
|---|---|---|
| 仓库范围和证据 | 原生文件搜索、聚焦阅读和 Git diff | 等效的只读 shell 命令 |
| Frontmatter 和技能结构 | 仓库定义或宿主原生的技能验证器 | 手动检查 YAML、路径、命名和仓库契约 |
| 插件集成 | 仓库定义的插件验证器加上清单解析 | 手动清单和适用目录比较 |
| 宿主发现 | 对每个已配置分发表面使用宿主原生验证器 | 手动检查目录、清单和源路径 |
| 当前宿主规则 | 官方宿主文档 | 不可用时将该主张标记为 `UNVERIFIED` |
| 行为独立性 | 全新的子代理或干净上下文 | 降低置信度披露的独立自审轮次 |

仅针对当前宿主行为或持续变化的标准使用外部研究。不得使用网络来源覆盖仓库实际文件、已安装版本或本地验证输出。

工具缺失本身不是技能缺陷。应用文档规定的备用方案，并且仅当缺失的能力妨碍可靠判定时使用 `BLOCKED`。

## 检查清单

### 确立范围和证据

- [ ] 解析目标路径、Git diff、已暂存和未跟踪文件；确定审核模式：静态内容/分发审核，或在被请求、合理且获许可时进行行为验证。遵守明确的不测试指令；在仅静态模式下不得运行场景或委托评估。
- [ ] 在判断仓库特定约定前，阅读仓库说明、技能契约和每个已配置的宿主目录；不得要求仓库未分发到的目录。
- [ ] 将主技能与受同一变更影响的清单、目录和文档分开。
- [ ] 确认仓库定义的规范技能布局；将未经授权、过时或偏离的宿主特定副本视为缺陷，同时允许仓库策略明确要求的适配器或生成副本。
- [ ] 确认 frontmatter 和文件夹命名满足仓库契约及每个目标宿主的要求；当声明的本地约定如此规定时，仅要求 `name` 和 `description`，而非将其作为通用要求强加。
- [ ] 检查每个描述均说明能力、正向触发条件和重要的近似负向边界。
- [ ] 检查描述是否处于宿主限制内，并避免作出超出工作流支持范围的主张。
- [ ] 确认每个技能都是独立的：不依赖必需的技能、MCP 服务器、追踪器、协调器、工作器或共享运行时。
- [ ] 应用仓库声明的完成约定；当有序检查清单即为完成定义时，标记重复的完成章节。
- [ ] 保留领域算法、工具路由、安全门控、证据、判定、输出和剩余风险。对于被移除的检查，识别保留义务的所有者，或说明该检查为何不支持目标；项目数量本身既不能证明损失，也不能证明保留。
- [ ] 标记不增加决策价值的泛泛解释；即使之前未记录失败，也要保留非显而易见的领域知识和具体保障措施。
- [ ] 检查内容层级和单一来源所有权：将每条规则保留在最狭窄的规范章节中，并标记正文、支持文件、清单和仓库说明中重复或矛盾的指导。
- [ ] 标记填充内容、生成式摘要文案、复制的实现或业务逻辑，以及可替换为稳定契约、权威来源、能力描述或明确更新触发条件的易变版本、路径、计数、默认值或宿主行为。
- [ ] 验证每项必需能力都有可用工具路径、可信备用方案或明确的 `BLOCKED` 结果。
- [ ] 检查每项技能的变更边界是否与其声明的结果一致；只读工作流不得获得隐式写入权限。
- [ ] 对于优化或实验技能，若其会变更状态，则要求作出基于证据的保留、丢弃或回滚决定。
- [ ] 对于测试构建器或其他受限写入器，确认其不能修复产品代码或触及未经批准的外部状态，除非其声明的契约明确授权。
- [ ] 在正常完成、工具缺失、上下文不足、Git 状态不干净、命令失败和证据冲突的情况下追踪文本。检查前置条件是否先于依赖操作，停止条件是否允许安全推进，以及判定是否无矛盾地涵盖失败状态。
- [ ] 检查输出契约是否区分事实、推断、缺失证据、判定和剩余风险。
- [ ] 将相邻触发条件与每项技能的目标比较；要求指令支持某项结果、证据需求或范围/安全约束。在不使技能相互依赖的前提下，标记无关工作、缺失义务和模糊分支。

### 仓库验证

- [ ] 发现并运行仓库对已更改技能目录要求的所有技能验证器；不要假设仓库证据中不存在的验证器名称或位置。
- [ ] 如果所需验证器不可用，则根据仓库和宿主环境契约，手动验证 YAML 解析、命名、描述约束以及所需文件布局。
- [ ] 运行受影响分发单元所需的所有仓库插件或包验证器。
- [ ] 当对应的 catalog 或 manifest 存在时，运行每个宿主原生的严格验证器；记录其实际覆盖范围，不要将 marketplace 验证视为技能 frontmatter 验证，除非宿主能够明确遍历这些技能。
- [ ] 解析所有已配置的 catalog；仅当仓库策略要求跨宿主一致性时，比较插件名称和顺序。
- [ ] 确认每个声明的 catalog source、manifest path 和 skill path 均存在。
- [ ] 在仓库要求保持一致性的所有位置，确认重复的元数据（例如插件描述）保持一致。
- [ ] 对于 marketplace 仓库，确认稳定标识符没有发生非预期变化；展示品牌信息不能替代标识符。
- [ ] 搜索过时名称、已删除路径、草稿标记、MCP 耦合、编排术语以及生成的副本。
- [ ] 仅当仓库策略定义了行数目标时才应用这些目标，并将其视为维护约束，而不是行为质量的证据。

### 行为审查（适用时）

- [ ] 仅当行为执行属于范围且已获授权时应用此阶段；否则，以范围原因将仅限执行的项目标记为 `CLEARED`，并说明未测试行为。静态检查无法证明激活或执行质量。
- [ ] 根据已声明的触发条件，而不是仅根据技能标题，推导具有代表性的正向提示。
- [ ] 根据相邻能力和用户可能使用的含糊措辞，推导相近的负向提示。
- [ ] 验证技能会针对正向提示激活，并针对相近的负向提示保持非激活状态。
- [ ] 至少演练一个正常场景、一个缺少证据的场景以及一个安全边界场景。
- [ ] 当技能编写代码或其他工件时，评估一个由智能体实际生成的结果，并根据独立的任务契约进行差异比较；不要用文案审查、答案简洁程度或静态检查替代执行行为评估。
- [ ] 分别评定任务完整性、正确性、安全性、范围控制和清理情况；只有在必需结果通过后，才能将代码或 token 减少作为辅助证据。
- [ ] 对于复杂或高风险的更改，在条件允许时使用全新的独立上下文，并且只提供技能和原始任务工件。
- [ ] 不要向独立评估者透露预期发现、计划中的修复或先前的结论。
- [ ] 将只有依赖泄露的上下文才能成功的正向测试视为技能缺陷。
- [ ] 检查独立上下文是否受到全局安装的技能、钩子、插件、用户指令、环境设置、缓存或工件的污染；证明目标技能已激活，并使行为无法可靠归因的评估分支失效。
- [ ] 除非具体且反复出现的失败证明其必要性，否则不要创建或保留评估工具链。

### 证据规则

- [ ] 将每项发现引用到确切的文件和最小有用的行或章节。
- [ ] 区分验证器失败、人工审查关注点和推测性改进。
- [ ] 在赋予阻断级严重性之前，要求确定性的验证器证据、经授权的复现，或完整的静态矛盾/失败路径；不要执行审查模式排除的场景。
- [ ] 记录已执行的命令、退出状态和重要输出，但不要暴露机密。
- [ ] 当必需的宿主环境或干净上下文测试无法运行时，报告覆盖缺口。任何获准的诊断产物都必须是临时的，存放在规范插件目录之外，并予以披露；审查期间不得暂存、发布或创建外部状态。

## 结论

- `PASS` — 所声明模式下的所有必需检查均已通过，且不存在重大关注点；仅静态检查的 `PASS` 不代表执行行为已获认证。
- `PASS WITH CONCERNS` — 在审查范围内没有已确认的阻断性缺陷，但仍存在有界的非阻断性不确定性；不得据此推断未经测试的发布或行为就绪状态。
- `FAIL` — 已确认的缺陷可能导致错误触发、不安全行为、安装失败或契约无效。
- `BLOCKED` — 必需的证据或工具不可用，且不存在可信的替代方案。

## 自检

- [ ] **返回前核对。** 检查条目级证据、需求覆盖、矛盾、范围、结论和适用的清理工作。修正报告或经授权的产物。复用有效证据；不要自动重新扫描仓库或重新运行已成功的命令。仅针对相关变更、失败或未解决的证据重复检查。披露剩余缺口。

## 输出契约

使用用户的语言，按以下顺序报告；保留全部五个字段，并且每项事实只陈述一次。结果较小时，每个字段可使用一行；省略空表格，不要复制链接的产物：

1. **结果：** Skill 特定的结论及有证据支持的结果。
2. **范围：** 已审查/变更的范围、排除项、基线和重要假设。
3. **证据：** 以下 Skill 特定字段；区分事实、推断和未经验证的声明。链接产物；适用时使用表格。
4. **验证：** 检查/结果、不可用的证据，以及适用的清理工作/外部状态。
5. **完成情况：** `Checklist: X/Y complete`；`Incomplete: None` 或列出每个 `UNPROVEN` 项的原因、对结果的影响和确切的后续操作；剩余风险及所需决策。

**Skill 特定证据：** 目标技能和分发界面；结构/宿主对等性、触发边界、静态与行为覆盖范围，以及验证器结果。发现项需要包含严重性、确切位置、影响、证据和最小修正。区分已确认的缺陷、人工审查关注点和推测性改进；报告不可用的干净上下文或运行时证据，并披露临时产物。
