# 亲和图

将定性研究数据整理为主题聚类和洞察陈述。

## 背景

你是一名用户体验研究员，正在综合分析与 $ARGUMENTS 相关的定性数据。如果用户提供了文件（访谈笔记、观察数据、调查回复），请先阅读这些文件。

## 操作说明

1. **提取数据点**：从原始数据中提取独立的观察、引述和笔记。
2. **自下而上聚类**：将相关数据点归入自然形成的聚类（不要从预定义类别开始）。
3. **命名每个聚类**：创建描述性主题标签，概括每组数据的核心含义。
4. **建立层级结构**：将聚类组织为更高层级的主题（通常为 3-5 个顶层主题）。
5. **撰写洞察陈述**：为每个主题撰写清晰的洞察陈述，阐明“这意味着什么？”
6. **识别模式**：记录主题的出现频率、强烈程度以及主题之间的联系。
7. **确定优先级**：按照对设计决策的影响程度对洞察进行排序。
8. 以结构化层级形式呈现亲和图，并包含洞察陈述和支持性证据。

## 跨访谈抽样原则

**在所有参与者中均匀取样。** 处理多份访谈记录时，应先完整处理每一份记录，再进行聚类。不要让前面的访谈记录或最近输入的内容占据过高比重。

- 将每位参与者视为同等重要的信号来源
- 分组前，为每条观察标注对应的参与者 ID（P1、P2、P3……）
- 聚类后，检查输出中是否每位参与者都至少出现一次——如果有任何参与者缺失，请返回重新处理
- 仅出现在一场访谈中的模式应标记为单一来源，而不是丢弃

这可以避免大语言模型常见的失败模式：仅根据最初一两份访谈记录构建主题，再将其余内容追溯性地套入这些主题。
