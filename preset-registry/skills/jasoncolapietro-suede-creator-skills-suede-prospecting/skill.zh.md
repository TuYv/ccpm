# Suede 潜客挖掘

Suede 潜客挖掘可将经过批准的 ICP 转化为一份有来源支撑、经过评分的潜客表，适用于 B2B SaaS、通用 B2B、本地企业以及早期需求信号等场景。  
每位候选潜客都必须附带资格审查证据、排除逻辑，以及在开始触达前符合合规要求的交接信息。

```
IRON LAW: every row carries a source URL and the date it was captured,
or it does not ship. No exceptions, no "verify later," no placeholder rows.
```

正是这一条规则，让后续的 GDPR / CAN-SPAM 追溯链真正成立。没有这些信息的行不是低置信度潜客——它根本不是潜客。

## 开始之前

**首先检查产品营销上下文：**  
如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，或者在较早的设置中使用的旧版 `product-marketing-context.md` 文件名），请在提问前阅读它。使用其中的上下文，只询问尚未涵盖的信息或与当前任务具体相关的信息。

## 选择分支

不同的潜客挖掘模式差异很大，因此工作流会在接收需求时分支。根据用户的销售对象选择**一个**分支：

| 分支 | 销售对象 | “合格”潜客的标准 | 通过访问权限和条款检查后可能使用的来源 |
|--------|---------|----------------------------|-----------------------------------------------|
| **SaaS** | 其他 SaaS 公司 / 数字化企业 | ICP 匹配 + 技术栈匹配 + 增长信号（融资、招聘、产品迭代速度） | 用户可访问的公开公司网站、目录、开发者来源或许可数据 |
| **B2B** | 非 SaaS B2B 企业（服务商、制造商、企业、中型市场公司） | 行业 + 规模 + 地理位置匹配 + 购买信号（触发事件、供应商变更） | 用户可访问的公开公司记录、行业目录或许可商业数据 |
| **Local SMB** | 本地小型企业（商店、健身房、餐馆、诊所、沙龙、服务商） | 企业仍在运营 + 网站状态 + 距离合适 + 可接触决策者 | 根据其条款允许使用的公开企业网站和人工审核目录 |
| **Demand-signal** | 早期阶段：首批客户、设计合作伙伴或 Beta 用户 | 有引用来源的公开痛点、需求或时机信号，而不只是企业统计特征匹配 | 可通过当前获授权工具或人工审核访问的公开论坛、评论、问题、帖子、职位和发布记录 |

在使用任何指定平台或供应商之前，先确认当前哪些平台或供应商可调用、已完成身份验证、获得授权，并且符合其条款。如果没有研究连接器或浏览器可用，请向用户提供人工来源检查清单，并基于其提供的 URL、导出文件、截图或来源文本开展工作。

如果用户描述的是混合模式（例如“同时也是 SaaS 的 SMB”），请选择占主导地位的分支，并引入另一个分支中的资格信号。如果用户处于早期阶段，需要他们的*首批*客户或设计合作伙伴——关注需求证据而非名单覆盖率——请使用 **Demand-signal** 分支。

如需查看各分支的深入说明：
- **SaaS** → 参见 [references/saas-prospecting.md](references/saas-prospecting.md)
- **B2B** → 参见 [references/b2b-prospecting.md](references/b2b-prospecting.md)
- **Local SMB** → 参见 [references/local-prospecting.md](references/local-prospecting.md)
- **Demand-signal**（寻找你的首批客户）→ 参见 [references/demand-signals.md](references/demand-signals.md)

## 共享框架（所有分支）

每次潜在客户挖掘都遵循相同的五个阶段。工具和资格信号会因分支而异；阶段本身不会变化。

### 阶段 1 — 定义 ICP

如果有 `product-marketing.md`，则从中提取信息。否则，收集：

1. **公司属性匹配度** — 行业、公司规模、收入区间、地域、商业模式
2. **技术属性匹配度**（SaaS 分支）— 他们已经在使用哪些工具，还缺少什么
3. **购买信号** — 为什么是现在？（触发事件、融资、招聘、新计划、对当前供应商不满、近期搬迁/扩张）
4. **决策者画像** — 职位、资历、他们关心什么
5. **排除条件** — 哪些因素会使潜在客户明确成为“跳过”对象

将 ICP 输出为一段话，并附上通过/不通过标准清单。在此之前不要进入探索阶段。

### 阶段 2 — 构建候选名单（探索）

从所需输出数量的 2–3 倍开始，并根据来源访问受限程度或审核能力适当下调。只有当观察到的排除率表明需要另一批候选人时，才进行扩展，且最多扩展 3 轮。达到上限后，停止寻找来源：报告你观察到的排除率，并返回一份更窄的 ICP 建议，而不是继续从更多来源中反复筛选。

- **SaaS / B2B**：在可用的第一方、公开或授权来源之间交叉核对重要声明。只有在完成访问权限、新鲜度、条款和成本检查后，指定的供应商才可作为候选对象。
- **本地 SMB**：使用经过授权的研究连接器或手动查阅公开来源，然后将列表信息与企业自有网站或其他当前来源进行交叉核对。

相比用未经验证的候选对象填充输出，较小但证据完整的名单更可取。在捕获每个候选对象的来源 URL 之前，不要开始资格审查。

### 阶段 3 — 审查每个候选对象的资格

根据 ICP 清单为每个候选对象评分。为每项资格添加**证据**（一个或两个来源 URL）——绝不要在没有依据的情况下断言。

**置信度级别**（所有分支通用）：
- **高**：至少由两个独立来源或官方业务页面确认
- **中**：一个可信来源加上一致的搜索证据
- **低**：证据不完整或存在歧义——标明仍不确定的部分

对于电子邮件联系人，在使用前确认是否可以调用经过授权的验证器，并读取其当前结果语义。如果没有可用的验证器，将该地址标记为 `unverified`，不要将其放入可直接发送的导出结果中，并提供一份由用户操作的验证清单。绝不要声称验证能够保证送达。在每个候选对象都带有置信度级别之前，不要进入评分阶段。

### 阶段 4 — 评分并确定优先级

对 **SaaS、B2B 和本地 SMB** 分支使用此评分标准。**需求信号**分支采用不同的评分方式——使用 0–100 的需求匹配度，而不是高意向/中意向/低意向——参见 [references/demand-signals.md](references/demand-signals.md)。

| 分数 | 定义 |
|-------|------------|
| **高意向** | 符合 ICP（通过完整的阶段 1 ICP 清单）+ 明确的购买信号 + 可接触到决策者 + 已验证的联系人 |
| **中意向** | 符合 ICP + 较弱或较早的信号 + 联系人可验证 |
| **低意向** | ICP 匹配度较宽泛，或没有明确的信号，或联系人未验证 |
| **跳过** | 命中排除条件（不属于 ICP、企业已关闭、重复、无关、置信度低） |

分支特定的信号会进一步细化评分 — 请参阅各个参考文件。让证据决定每个标签中的数量；绝不要强行设定 Hot/Warm/Cold 的配额。没有同时具备购买信号和已验证联系人信息的行，不得在此阶段标记为 Hot — 应将其降级为 Warm。

### 阶段 5 — 输出潜在客户表

（SaaS / B2B / 本地 SMB。**Demand-signal** 分支则改为提交证据报告 — 请参阅 [references/demand-signals.md](references/demand-signals.md)。）

默认在聊天中使用 Markdown 表格。当列表超过 25 行，或用户明确要求文件时，切换为 CSV。

表格之后，在证据支持一个或多个候选项时，添加 **“优先审查候选项”**：按当前信号强度排序的有限集合，并用一句话说明已验证的内容以及仍需审查的内容。

列会因分支而异（请参阅参考文件），但每份潜在客户表都必须包含：
- 评分、企业/公司名称、联系人（如适用）、为何属于潜在客户、来源、置信度、最后验证日期

除非同时列出所使用的搜索参数和仍未解决的开放问题，否则该表不算交付完成。

## 合规防护措施

这些要求适用于每个分支。**每次开展工作前都必须先阅读。**

1. **不得批量抓取** LinkedIn、Google Maps、付费网站或受速率限制的 API。浏览器是辅助研究工具，而不是爬虫。
2. **不得绕过 CAPTCHA、登录墙或机器人防护。** 如果网站要求进行这些操作，则只能使用公开可见的信息。
3. **仅使用公开的企业联系渠道。** 使用企业自有网站上公开的 info@、hello@、contact@ 以及明确标注职务的邮箱（创始人、所有者）。使用个人/私人邮箱必须具备合法依据（现有关系、主动同意等）。
4. **遵守 GDPR / CAN-SPAM / CASL。** 对于添加到列表中的每个联系人，都要记录并保留来源 URL 和日期 — 这是后续开展外联时合规所必需的。
5. **不得转售从 Google Maps、LinkedIn 或任何禁止此类行为的平台提取的数据。** 为用户自己的外联活动建立列表是允许的；将列表产品化并出售则不允许。
6. **自行限制请求速率。** 即使针对公开来源，也要错开请求，不要留下机器人特征。
7. **不得使用遭泄露、被外泄或来源无法证实的数据。** 不得从遭泄露的数据集、抓取联系人市场或没有来源链路的名单经纪商处获取潜在客户。只要在其服务条款范围内使用，并具备合法依据，获得许可的 B2B 数据提供商（Apollo、ZoomInfo、Clearbit、Clay）可以使用 — 禁止的是非法/来源不明的数据，而不是合法的丰富数据供应商。
8. **绝不要针对或推断敏感特征。** 不得依据健康状况、经济困难、政治信仰、性取向、宗教或其他受保护/敏感属性进行筛选、分组或个性化 — 即使公开帖子披露了这些信息，也不得如此处理。

完整的合规参考（GDPR、CAN-SPAM、CASL、LinkedIn ToS、Google Maps ToS、Clay/Apollo/ZoomInfo 使用限制）请参阅 [references/compliance.md](references/compliance.md)。

## 需要收集的输入

如果缺少，请询问一次，然后推断合理的默认值并继续：

- **分支**（SaaS / B2B / 本地 SMB / 需求信号）——通常可根据上下文推断；对于早期首次客户发现，选择需求信号
- **ICP 描述**——如果存在，从 `product-marketing.md` 中提取
- **目标数量**——使用用户要求的数量，或根据来源覆盖范围和审核能力，提出一个有明确边界的试点规模
- **地域**（本地 SMB 必需；B2B 有用；SaaS 则不那么关键）
- **用户有权访问的工具**——发现当前可调用的工具和已完成身份验证的账户；绝不要假设存在某个供应商连接器或浏览器
- **输出格式**——聊天表格（默认）或 CSV
- **购买信号偏好**——他们应优先关注哪些触发因素？（融资轮、招聘、近期搬迁等）

## 工具选择

将下面列出的每个产品都视为候选项，而不是可用能力。这些只是选择示例，并不保证存在集成——在使用前，发现当前可调用的工具，并验证用户的身份验证权限、许可证、来源条款、数据新鲜度、导出权限和成本。完整细分请参阅
[references/data-sources.md](references/data-sources.md)。

| 如果用户可以访问…… | 将其用于 | 使用前验证 |
|------------------------------|------------|------------|
| **Apollo** | B2B / SaaS 公司属性信息 + 联系人发现 | 数据新鲜度、导出条款、电子邮件验证 |
| **Clay** | 多来源丰富数据、瀑布式查找、自定义评分 | 积分成本、数据提供商、字段来源 |
| **Clearbit** | 通过电子邮件查找公司和丰富公司信息 | 当前产品访问权限和覆盖范围 |
| **ZoomInfo** | 企业 B2B 联系人 + 意向数据 | 许可证、导出权限、信号新鲜度 |
| **Hunter 或 Snov** | 电子邮件模式发现和验证 | 验证状态和合法依据 |
| **Truelist** | 外联前验证电子邮件可送达性 | 结果含义和当前 API 限制 |
| **LinkedIn Sales Navigator** | 决策者映射（手动，不抓取） | 平台条款；不得批量提取 |
| **BuiltWith / Wappalyzer** | 技术栈筛选（SaaS 分支） | 检测准确性和数据陈旧程度 |
| **Crunchbase** | 融资信号（SaaS 分支） | 记录时效性和许可证层级 |
| **GitHub** | Stargazer / fork、公开的开发者意向信号 | API 条款、速率限制、公司映射 |
| **Google Maps + 浏览器** | 本地 SMB 发现 | 条款；仅限辅助审核，不得批量提取 |
| **Outreach** | 获得批准后的销售互动 | 序列权限和抑制规则 |
| **RB2B** | 访客识别 | 隐私依据以及公司级与个人级粒度 |
| **Firecrawl / Browserbase** | 单个潜在客户的网站——绝不可用于平台 | 目标条款、范围和会话访问权限 |

**如果用户没有数据丰富或浏览器工具**：提供准确的公开来源查询语句和资格审核工作表，然后根据用户提供的 URL、导出文件或截图开展工作。

## 输出格式

### 默认——聊天表格

对于 SaaS / B2B（≤25 行）：

```
| Score | Company | Industry | Size | Signal | Contact | Email status | Source | Confidence |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
```

对于本地 SMB（≤15 行）——参考 local-prospector：

```
| Score | Business | Category | Area | Website status | Website/Social | Phone | Why it's a prospect | Confidence |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
```

### CSV — 超过 25 行或用户要求文件时

SaaS / B2B 列：

```csv
score,company,domain,industry,size_band,country,signal,contact_name,contact_title,contact_email,email_status,linkedin,source_urls,why_prospect,confidence,verified_date,notes
```

本地 SMB 列：

```csv
score,business,category,area,distance_km,website_status,website_url,social_urls,phone,email,source_urls,why_prospect,confidence,verified_date,notes
```

### 在表格之后包含

- **优先审查候选对象**：一组范围明确、按证据排序的候选对象，并为每个对象提供一句话理由
- **搜索参数**：分支、ICP、地点/半径、目标数量、生成日期
- **待解决问题**：任何无法验证、需要用户查看的事项

## 质量检查（定稿前）

- [ ] 删除重复项（SaaS/B2B 按域名去重，本地 SMB 按企业名称 + 地址去重）
- [ ] 每个标记为 "Hot" 的潜在客户都有经过验证的联系人 + 至少一个来源 URL
- [ ] 电子邮件状态来自当前获授权且具有记录结果语义的验证器，或明确标记为 `unverified`；失败结果保留在单独的无效项类别中
- [ ] 没有任何标记为 "Hot" 的潜在客户缺少明确的购买信号
- [ ] 置信度级别真实可靠——"High" 要求有 2 个独立来源，而不仅仅是你自己的两次搜索
- [ ] 没有来自受禁止抓取方式的潜在客户（大规模抓取 LinkedIn、批量提取 Google Maps 等）
- [ ] 为每个联系人记录来源 URL + 日期（用于 GDPR / CAN-SPAM 溯源）
- [ ] 最终数量符合用户要求，或者已解释数量较少的原因（质量标准）

任何未勾选的复选框都意味着该表格不可交付。请指出未通过的复选框及缺失内容，而不是附带说明后仍提交表格。

## 常见错误

1. **未经交叉核查就将数据源视为权威来源**。Apollo 和 ZoomInfo 经常过时；在将潜在客户评为 "Hot" 之前应进行验证。
2. **混淆分支**。不要将本地 SMB 评分方式（网站状态）应用于 B2B SaaS 潜在客户，反之亦然。
3. **安排后续外联时忽略安静时段 / 时区**（交接给 `suede-cold-email`）。
4. **忘记保留同意记录 / 溯源记录**。GDPR DSAR 和 CAN-SPAM 审计都要求这些记录。

## 边界

- 不要发送外联消息、导入联系人、购买数据、修改 CRM，或将人员加入序列。
- 不要编造联系人详情或资格证据、规避来源条款、收集不必要的个人数据，或在没有引用当前来源的情况下将潜在客户标记为已验证。
- 不要决定法律合规性或声称可交付性。在进行任何后续联系之前，应用适用的同意、隐私和抑制规则。

## 路由

- 使用 `suede-product-marketing` 定义 ICP 和定位背景。
- 在批准合格名单后，使用 `suede-cold-email` 编写外联文案。
- 使用 `suede-revops` 处理已批准的 CRM 路由和生命周期交接。
- 使用 `suede-sales-enablement` 处理用于主动销售工作的宣传资料。
