# 沟通受众建模

沟通的成败取决于接收者。发送者几乎总是清楚自己想表达什么——问题在于，考虑到接收者当前相信什么、真正关心什么，以及试图保护什么，他们听到的会是什么。沟通前对这些因素进行建模，是最具杠杆效应的准备步骤。

---

## 你的流程

**第 1 步：明确具体人员**
不要对“团队”或“领导层”进行笼统建模。明确将接收这条信息的具体个人或群体。同一场会议中的不同人员需要不同的模型。

**框架确认：** 在继续之前，确认信息、受众和目标。用一句话说明你识别出的内容——正在规划的具体沟通、沟通对象，以及需要达成的结果——然后使用 `AskUserQuestion`：
- **问题：**“我的理解是：[用一句话概括信息、受众和沟通目标]。对吗？”
- **标题：**“框架”
- **选项：**
  - **是——继续**——框架正确
  - **调整**——有一个要素不准确；用户会先予以纠正，然后你再继续
  - **重新界定**——实际情况与当前理解不同；纳入修正后再继续

**第 2 步：当前认知**
他们目前对这个话题有什么看法？不是你希望他们怎么想——而是他们此刻实际上怎么想。这是信息必须推动其发生转变的起点。

**第 3 步：真实目标**
他们深层的动机是什么？明确表达的偏好往往只是更深层需求的替代体现：安全感、认可、自主、公平、掌控。如果你只回应明确表达的偏好，而没有触及深层动机，信息就不会被接受。

**第 4 步：恐惧**
他们有什么是不能失去的？在大多数职业情境中，对大多数人而言，恐惧比抱负更能激发行动。一条威胁到他们正在保护之物的信息，即使逻辑合理，也会遭到拒绝。

**第 5 步：什么会改变他们的想法——什么不会**
什么样的证据、表达框架或社会认同能够推动他们改变？还有哪些方式——无论论证多么充分——对这个人都不会奏效？知道什么不会奏效，与知道什么会奏效同样重要。

**第 6 步：门槛条件**
他们必须先听到什么或感受到什么，才能接收真正的信息？有些人需要先感到自己的意见被倾听，才愿意听别人说。另一些人需要明确范围。还有一些人则需要先解决某个具体顾虑，之后其他内容才可能被接受。

## 人工确认

继续之前，请使用 `AskUserQuestion` 工具。用 1–2 句话说明你对情况的理解——正在分析什么，以及核心问题是什么——然后询问：

- **问题：**“我的理解是：[用 1–2 句话说明你的理解]。你希望如何继续？”
- **标题：**“范围”
- **选项：**
  - **完整分析**——完成所有步骤，并全程展示推理过程
  - **仅关键发现**——只输出结论，省略逐步细节
  - **仅恐惧与顾虑**——只说明受众最担心什么，省略认知和目标
  - **重新界定**——当前理解有误；请予以纠正，之后将按照修正后的框架进行分析

根据用户的选择继续。如果用户重新表述了问题，请在进行任何分析之前纳入其修正。

## 输出格式

**受众细分：**

| 人物 / 群体 | 当前认知 | 真正目标 | 恐惧 | 什么能打动他们 | 什么不会奏效 | 阈值条件 |
|-----------------|---------------|-----------|------|-----------------|-----------------|---------------------|
| | | | | | | |
| | | | | | | |

**信息传达要点：**
> [为了让信息被每个受众群体接受，必须按什么顺序做到哪些事情？]
> [不同受众群体之间存在哪些冲突——应如何化解这种矛盾？]

**风险最高的受众群体：**
> [最有可能拒绝这条信息的人或群体——以及原因]

---

## 注意事项

第 6 步中的阈值条件是最常被跳过、也是最有价值的要素。
如果一条信息在满足阈值条件之前就试图表达其核心观点，
那么它还未传达到受众那里就会被过滤掉。

## 后续步骤

交付此输出后，使用 `AskUserQuestion` 提供下一步选项：

- **问题：**“受众模型已建立。下一步做什么？”
- **标题：**“下一步”
- **选项：**
  - `/s4h-communication-objection-mapping` — 梳理该受众将提出的异议
  - `/s4h-communication-clarity-audit` — 审查信息对于这一特定受众而言是否清晰
  - `/s4h-writing-tone-alignment` — 调整语气，使其与受众模型保持一致
  - **完成** — 收尾并综合整理目前为止的成果
