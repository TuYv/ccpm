# Simplify: 代码审查与清理

审查所有已更改的文件，检查复用性、质量和效率。修复发现的任何问题。

## 阶段 1：识别变更

运行 `git diff`（如果有已暂存的变更，则运行 `git diff HEAD`）来查看改动了什么。如果没有 git 变更，则审查用户提到的、或你在本次对话中早些时候编辑过的最近修改的文件。

## 阶段 2：并行启动三个审查 Agent

使用 Agent 工具在同一条消息中并发启动全部三个 agent。向每个 agent 传递完整的 diff，使其拥有完整的上下文。

### Agent 1：代码复用审查

针对每项变更：

1. **搜索现有的工具函数和辅助函数**，它们可能可以替代新写的代码。在代码库的其他地方寻找相似的模式——常见位置包括工具目录、共享模块，以及与被更改文件相邻的文件。
2. **标记任何与现有功能重复的新函数。**并建议改用现有的函数。
3. **标记任何可以使用现有工具函数的内联逻辑**——手写的字符串处理、手动路径处理、自定义环境检查、临时拼凑的类型守卫及类似模式都是常见的候选项。

### Agent 2：代码质量审查

针对相同的变更审查是否存在取巧式（hacky）模式：

1. **冗余状态**：与现有状态重复的状态、本可以派生出来的缓存值、本可以是直接调用的观察者/副作用
2. **参数蔓延**：向函数添加新参数，而不是泛化或重构现有参数
3. **略有变化的复制粘贴**：本应通过共享抽象统一起来的近似重复代码块
4. **抽象泄漏**：暴露了本应封装的内部细节，或破坏了现有的抽象边界
5. **字符串类型化（stringly-typed）代码**：在代码库中已存在常量、枚举（字符串联合类型）或品牌类型（branded types）的情况下仍使用原始字符串
6. **不必要的 JSX 嵌套**：不带来布局价值的外层包裹 Box/元素——检查内部组件的 props（flexShrink、alignItems 等）是否已经提供了所需的行为
7. **不必要的注释**：解释代码“做什么”的注释（命名良好的标识符已经做到了这一点）、叙述本次变更的注释，或引用任务/调用方的注释——删除；只保留不显而易见的“为什么”（隐藏约束、微妙的不变量、变通方案）

### Agent 3：效率审查

针对相同的变更审查效率问题：

1. **不必要的工作**：冗余计算、重复的文件读取、重复的网络/API 调用、N+1 模式
2. **错失的并发机会**：本可以并行运行却按顺序执行的独立操作
3. **热路径膨胀**：向启动过程或每请求/每渲染的热路径中添加新的阻塞工作
4. **反复发生的无操作更新**：在轮询循环、定时器或事件处理器中无条件触发的状态/store 更新——添加变更检测守卫，使下游消费者在没有任何变化时不会被通知。另外：如果某个包装函数接受 updater/reducer 回调，请验证它会正确处理同引用返回（或任何“无变更”信号）——否则调用方通过提前返回实现的无操作会被静默破坏
5. **不必要的存在性检查**：在操作之前预先检查文件/资源是否存在（TOCTOU 反模式）——直接执行操作并处理错误
6. **内存问题**：无边界的数据结构、缺少清理、事件监听器泄漏
7. **过于宽泛的操作**：只需要一部分内容时读取整个文件、只需筛选某一项时加载全部条目

## 阶段 3：修复问题

等待全部三个 agent 完成。汇总它们的发现并直接修复每个问题。如果某个发现属于误报或不值得处理，记下它然后继续——不要与该发现争辩，直接跳过即可。

完成后，简要总结修复了什么（或确认代码已经很干净）。
