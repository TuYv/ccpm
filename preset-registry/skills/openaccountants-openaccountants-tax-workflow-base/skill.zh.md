# 税务工作流基础

此技能是所有税务分类或计算任务的工作流架构。它定义了**如何**开展工作——操作顺序、如何处理歧义、应生成什么输出、何时拒绝处理——但不指定应应用**哪些**规则。具体规则来自配套的内容技能。

**此技能必须始终与至少一个内容技能一同加载。** 单独加载此技能属于配置错误，模型必须拒绝继续处理。

## 插槽契约

符合此基础技能规范的内容技能需要提供：

1. **范围声明**——司法管辖区、表格、纳税人类型、纳税年度和币种。
2. **第 1 层确定性表格**——将交易对手模式直接映射到处理方式，无需推理。
3. **第 2 层保守默认值表格**——针对每种歧义类型，规定会使纳税人承担更多税款的默认处理方式，并提供产生该歧义的规则之来源引文。
4. **拒绝目录**——超出范围的情形，每种情形均包含触发条件和须逐字输出的拒绝消息。
5. **输出行定义**——内容技能所针对的表格行或代码（例如 Schedule C Line 27a、ICD-10 J45.x）。

此基础技能提供外围工作流、三状态契约、引用规范以及审核人员关注项的输出规范。

## 三状态契约

模型处理的每项输入都必须归入**且仅归入**以下三种状态之一。不存在第四种状态。未经说明便直接断言、含糊带过或作出“最佳猜测”均违反契约。

### 状态 A——明确解决

输入与第 1 层确定性模式匹配，或者内容技能的规则能够无歧义地适用，且认真阅读相同来源的审慎审核人员会得出相同结论。应用相应处理方式。引用主要来源。除非仅金额规模就足以需要审核人员关注，否则不要将其标记为需要审核人员关注（该阈值由内容技能定义）。

### 状态 B——使用保守默认值解决

某项规则适用，但缺少某个事实（百分比、计税基础、证明文件或日期），或者公开来源本身对此情况存在解释空间。模型**必须无一例外地按顺序完成以下四项操作**：

1. 在审核摘要中用一句话**说明歧义**。
2. **应用内容技能中的保守默认值**——选择会使纳税人承担更多而非更少税款的方案。
3. **引用产生该歧义之规则的主要来源**，以便审核人员核实。
4. **将相关问题添加到结构化问题表单中**，使用户能够通过一次往返沟通解决该问题。

这四项操作彼此关联。静默应用默认值违反契约。仅提出问题而不应用默认值违反契约。在未展示立场所依据规则的情况下陈述立场违反契约。

### 状态 C——超出范围，拒绝处理

该情形触发内容技能拒绝目录中的某项拒绝条件。**停止。** 逐字输出拒绝消息。建议用户咨询平台之外具备资质的专业人士。不要对被拒绝的情形进行部分处理。不要对其中属于范围内的部分进行分类。拒绝必须是全面的。

## 保守默认原则

当对某项税务处理不确定时，应选择会使纳税人承担更多税款的处理方式。复核人员可以在事后纠正过度保守的处理。相比之下，如果激进的处理方式在三年后的审计中暴露，而诉讼时效仍未届满，复核人员将很难挽回。

该原则适用于所有司法管辖区和所有税种：

- 资产的业务用途比例未知 → 业务用途比例按 0% 处理，不得扣除
- 费用是否可扣除未知 → 不得扣除
- 对于需要证明材料的项目，缺少同期证明文件 → 不得扣除
- 收入是否需要申报未知 → 需要申报
- 收入性质未知 → 普通收入
- 持有期限未知 → 短期
- 资产计税基础未知 → 计税基础为零
- 某项活动属于经营活动还是业余爱好未知 → 业余爱好
- 上一年度是否作出过某项选择未知 → 视为未作出
- 申报身份未知 → 在大多数情况下采用税负最高的选项

内容技能规定了每种歧义类型的具体默认处理方式。本基础技能规定了总体原则，以及内容技能的默认处理必须遵循该原则的规则。

## 引用规范

任何税务立场如果没有一手来源引用，均不成立。一手来源包括以下任一种：成文法条款（IRC §、ITA s 或其他司法管辖区的同等条款）、法规、税务机关发布的官方出版物、税收裁定或税收程序，或者税务机关自身发布的现行表格说明。

二手来源（评论文章、博客文章、顾问备忘录、培训材料）不可作为某项税务立场的引用依据。它们仅可作为补充背景信息引用。

如果内容技能无法为某项税务立场提供一手来源引用，则不得采用该立场。应改为默认采用状态 B（保守默认）或状态 C（拒绝）。

## 结构化问题格式

每次应用保守默认处理（即每次状态 B 分类）时，都必须向用户提出一个问题。按照工作流程，用户只有一次往返机会来回答问题。所有问题应集中在工作结束时一并提出，按类别分组，并按金额大小排序。

当问题数量超过 10 个时，应按类别分组，而不是针对每笔交易分别提问。（例如：“在 Shell 发生的 8 笔燃油交易合计 $X——该车辆是否……”而不是提出八个单独的问题。）

每个问题必须包括：

1. **问题本身**，使用通俗易懂的语言。
2. **当前采用的默认处理方式**，让用户知道如果不回答会发生什么。
3. **如果用户给出不同回答，将采用的替代处理方式**。
4. **默认处理与替代处理之间差额的美元金额（或等值金额）影响**。

缺少以上四项中任何一项的问题都不完整，必须在交付前修订。

## 复核人员关注事项输出约定

任何基于本基础技能构建的任务，其输出都应面向在相关司法管辖区具备资质的人类复核人员（例如美国受 Circular 230 约束的税务专业人士、英国的 ATT/CTA、马耳他的 Avukat 或 perit 等）进行结构化组织。输出的直接使用者是复核人员，而非纳税人。复核人员应先批准相关税务立场，之后这些立场才能体现在纳税申报表中或提交给税务机关。

每份输出都必须包含：

1. **最终结论** — 审核者最先需要看到的核心数字，并采用表单所要求的单位。
2. **高优先级标记清单** — 需要作出判断且金额重大的项目，按金额影响从高到低排列。审核者从上往下阅读，确认无误后即可停止。
3. **计算轨迹** — 对于采取的每个立场：得出了什么结论、使用了哪些源数据、应用了什么规则（附引文），以及由此产生了多少金额影响。
4. **已应用的保守默认值** — 按金额排序，完整列出每个状态 B 立场，包括歧义点、默认处理方式、不同处理方式之间的现金影响差额以及引文。
5. **拒绝处理轨迹** — 对内容技能目录中的每个拒绝代码，用一行说明“已清除”或“已触发”并注明原因。这样可使拒绝处理可供审计，而不仅仅是口头断言。
6. **范围限制** — 明确说明工作成果涵盖哪些内容，以及不涵盖哪些内容。

## 组合契约

当此基础技能与内容技能**一同**加载时，两个技能会进行组合：此基础技能提供工作流框架，内容技能提供实质性规则。任何任务都必须同时具备二者才能继续执行。

当此基础技能**单独**加载且没有内容技能时，基础技能必须拒绝运行。拒绝消息如下：

> “我是税务分类任务的工作流基础技能。我本身不包含任何税务规则、税率或特定司法管辖区的内容——这些内容来自配套的内容技能。请在加载我的同时加载一个内容技能（例如，用于美国 Schedule C 的 `classifying-tax-transactions`），然后再次提出您的问题。”

这是在运行时强制执行的插槽契约。

## 此基础技能不是什么

- 不是税务建议。输出是分类或计算辅助材料，供具备资质的专业人士审核。
- 不是报税代理人。它不会提交纳税申报表。
- 不针对特定司法管辖区。所有特定司法管辖区的规则均来自内容技能。
- 不能替代内容技能。没有内容技能，此基础技能就是空的。
