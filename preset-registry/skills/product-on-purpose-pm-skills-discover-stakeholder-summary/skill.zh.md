# 利益相关者摘要

利益相关者摘要用于记录对项目感兴趣或能够影响项目的人员和群体，涵盖他们的需求、担忧以及彼此之间的关系。有效的利益相关者管理往往比技术执行更能决定项目成败，因此，这份文档对于应对组织复杂性至关重要。

## 适用时机

- 在新项目或新计划开始时，用于梳理整体情况
- 从另一位 PM 手中接手现有项目时
- 在需要跨职能支持的重大决策点之前
- 在项目中途遇到阻力或目标不一致时
- 在改变利益相关者关系的组织变革期间
- 在为发布或变更准备沟通策略时

## 不适用时机

- 你需要的是将要发送给利益相关者的异步更新 -> 使用 `foundation-stakeholder-update`；此技能用于梳理利益相关者，那个技能用于与他们沟通
- 你正在为某一次特定的高风险会议做准备 -> 使用 `foundation-meeting-brief`
- 你需要的是客户研究综合，而不是影响力地图 -> 使用 `discover-interview-synthesis`
- 你想创建一个用于设计或营销的用户画像 -> 使用 `foundation-persona`

## 说明

当被要求创建利益相关者摘要时，请遵循以下步骤：

1. **识别所有利益相关者**
   列出所有与项目有利害关系的人：发起人、审批人、贡献者、产出物的使用者，以及会受到变更影响的人。起初要尽可能广泛地罗列，之后再进行优先级排序。个人和群体都要包括在内。

2. **评估影响力和关注度**
   对每位利益相关者评估其影响力（影响项目的能力）和关注度（他们对项目结果的重视程度）。这决定了每个人需要得到多少关注。

3. **理解他们的视角**
   记录每位利益相关者希望从项目中获得什么、他们认为存在哪些担忧或风险，以及在他们看来怎样才算成功。可能的话，应通过沟通直接验证这些信息。

4. **梳理关系**
   识别利益相关者之间的关键依赖关系、联盟和潜在冲突。了解谁会影响谁，有助于你应对组织动态。

5. **按参与程度分类**
   根据影响力和关注度，确定适当的参与方式：积极管理、保持满意、及时知会或持续监测。不同的利益相关者需要不同程度的关注。

6. **制定沟通计划**
   对于高优先级利益相关者，定义沟通频率、首选渠道和关键信息。良好的利益相关者管理应当主动出击，而不是被动响应。

7. **识别风险并制定缓解措施**
   记录利益相关者的哪些担忧可能导致项目偏离轨道，并制定应对计划。及早关注持反对态度的利益相关者，可以避免意外情况。

## 输出格式

使用 `references/TEMPLATE.md` 中的模板来组织输出。一份完整的摘要应填写模板中的每个部分：概览；利益相关者地图；利益相关者档案；利益相关者详细分析；关键关系；沟通计划；风险缓解；行动项；以及文档历史。

## 质量检查清单

在最终确定之前，请确认：

- [ ] 已识别出所有重要的利益相关者（而不只是显而易见的利益相关者）
- [ ] 对影响力和利益的评估切合实际，而非一厢情愿
- [ ] 已从利益相关者的角度记录其关注点，而非加以忽视
- [ ] 已梳理关系和依赖项
- [ ] 沟通计划具体且可执行
- [ ] 已为持反对态度的利益相关者制定缓解策略
