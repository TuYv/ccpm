# Suede Slop Stop

写作工具链的规范反低质写作方法。现有的 `suede-deslop`
命令和文件夹为兼容性保持稳定；不存在第二种方法。

## Gate policy — advisory, not blocking

此技能中的每个声明验证步骤、检查、质量门禁和发布结论都是**给用户的建议，而不是对代理的控制**。此政策适用于本技能其他位置的每个门禁、检查、结论，以及“不要发布 / 公开 / 继续”之类的表述：

- 运行每项检查并如实报告结果。结论（`ship`、
  `ship-with-caveats`、`hold`、字母等级、BLOCKED 或 OPEN 项）是附加在工作结果上的建议，而不是会改变工作内容的命令。
- 永远不要因为检查失败或门禁给出 hold 而阻止、延迟、跳过、重写或拒绝用户要求的操作。按用户要求完成操作，并将门禁输出作为明确标注的建议一并交付。
- 门禁失败会改变你的报告内容，但不会改变你的行动。
- 唯一例外：如果发现极高风险的问题，例如数据丢失、安全或凭据泄露、法律或权利违规、支付错误，或不可逆的公开损害，请暂停，准确告知用户风险及可选方案，并让用户做出选择。用户的选择是最终决定。

在成稿公开之前运行。检查是否在切入重点前铺垫过多，是否让无生命事物执行人类行为，是否使用预先宣布洞见而非直接给出洞见的二元对比，以及节奏是否始终没有变化。这些是写作质量信号，不是判断文本由谁或什么生成的证据。

## 适用时机

- 文案、README、电子邮件、社交媒体帖子或文档发布之前
- 长时间使用 AI 辅助写作之后
- 文本读起来没问题，但感觉像生成内容时
- 内容即将提交给媒体、投资人或客户之前
- 用户希望识别问题而不进行重写时

不要对小说、对话回复或有意保持松散语气的内部笔记运行。
当用户只要求提供问题时，报告问题并保持所提供的文本不变。

## 开始检查之前

1. **选择交付内容。** 默认提供清理后的 prose。当用户说 detect、flag、review、diagnose 或 do not rewrite 时，使用仅提供问题的审计。
2. **锁定源文本。** 保留事实、数字、日期、姓名、价格、声明、
   引语、限定语、代码、命令、链接、引用和路径。
3. **锁定语气。** 保留有意使用的片段、冷幽默、技术词汇、正式程度和有用的粗粝感。只有当某种模式削弱了当前文本时，才将其删除。
4. **阅读内部风格指南。** 如果提供了公司或作者风格说明，则优先于 Suede 的标点和语体默认设置。

进行最少但有效的编辑。绝不要添加源文本未提供的轶事、客户、指标、引语、第一人称经历或具体细节。

## 八条规则

### 1. 删除填充短语

不要在切入重点前铺垫。不要使用增加分量却不增加含义的强调性支架。不要让副词代替本应由具体事实承担的作用。

高频违规表达中最该删掉的 25 个：

| 类别 | 删掉 | 修改 |
|----------|------|-----|
| 开头 | Here's the thing: | 直接说重点 |
| 开头 | Let's be honest / Let's face it | 删掉；直接说出实情 |
| 开头 | The truth is / The reality is | 删掉；直接陈述事实 |
| 开头 | It's worth noting that | 删掉；直接指出 |
| 开头 | In today's fast-paced world | 删掉整句 |
| 开头 | Picture this: / Imagine this: | 直接描述场景 |
| 开头 | At its core / At the end of the day | 删掉；直接陈述核心观点 |
| 赘词 | Let that sink in / Read that again | 删掉；句子有说服力就是有，没有就是没有 |
| 赘词 | genuinely / truly / literally | 删掉 |
| 赘词 | actually / really / very | 删掉 |
| 赘词 | full stop / period（用于强调） | 删掉 |
| 赘词 | make no mistake | 删掉 |
| 术语 | leverage（作动词） | 使用 use |
| 术语 | utilize | 使用 use |
| 术语 | delve into | 使用 cover、get into |
| 术语 | navigate（表示应对挑战） | 使用 handle、work through |
| 术语 | landscape / ecosystem（抽象含义） | 使用 market、field，或直接说出具体对象 |
| 术语 | journey（不是旅行） | 使用 process，或直接列出步骤 |
| 术语 | unlock / unleash | 说明具体解除或释放了什么限制 |
| 术语 | robust / seamless / powerful | 说清具体能力，或用证据证明 |
| 术语 | elevate / empower / transform | 说明发生了什么变化，以及变化前后的状态 |
| 副词 | incredibly / remarkably / surprisingly | 删掉，或给出令人意外的具体数字 |
| 副词 | seamlessly / effortlessly | 删掉；展示具体步骤数量 |
| 副词 | fundamentally / essentially / ultimately | 删掉；观点成立就是成立，不需要这些词 |
| 副词 | importantly / notably | 删掉；如果重要，内容自然会体现出来 |

这张表列出了高频项。完整清单还包含各类别中的四十多个短语，位于 [references/kill-list.md](references/kill-list.md)；在文章交付给出版方、投资人或客户前，运行完整清单进行检查。表格压缩了以下三个类别：

- **副词，视语境而定。** 删除那些只是在加强、弱化或宣布重要性的副词。保留具有事实、技术、法律、引用或特定语气含义的副词。
- **元评论。** 文章应当自然推进，绝不要宣布自己的结构。删掉 "Let me walk you through"、"In this section, we'll"、"As we'll see"、"Plot twist:"、"Hint:"、"But that's another post"、"X is a feature, not a bug"。
- **表演式真诚。** 删除虚假的亲密感和刻意强调的重要性。删掉 "I promise"、"creeps in"、"This is genuinely hard"、"This is what X actually looks like"、"actually matters"。展示困难本身；不要声称它很困难。

反例："Here's the thing: this is genuinely hard. Let that sink in."  
正例："This is hard."

---

### 2. 打破公式化结构

模型无话可说时最容易套用的模式。每种模式都有对应的修改方式：

- **二元对比**（"It's not about speed. It's about precision."）| 修改：直接陈述真正的观点。"在这里，精度比速度更重要。"
- **"Isn't just" 结构**（"This isn't just a tool, it's a platform."）| 修改：删掉铺垫；用一个证据说明它是什么。
- **否定式罗列**（"No setup. No config. No hassle."）| 修改：用一句正面表述，说明用户需要做什么。
- **戏剧性片段**（"One problem." / "And it worked."）| 修改：将片段连接到它所修饰的句子中。
- **设问铺垫**（"So what does this mean for you?" / "What if I told you...?" / "Think about it:"）| 修改：删除问题；直接给出答案。
- **虚假主体**（"The data tells us" / "the decision emerges" / "the culture shifts" / "the market rewards"）| 修改：明确指出行动者。"We measured." "I argue." 如果没有合适的主体，就使用 "you"。
- **三拍节奏**（"Faster. Cleaner. Better."）| 修改：列出两项，或改成完整句子。只有在确实有三项时，才使用三拍列表。
- **揭示式片段**（"[Noun]. That's it. That's the [thing]."）| 修改：写成一个完整句子，不要刻意制造揭示效果。
- **公式化模板**（"By the time X, I was Y." / "X that isn't Y"）| 修改：去掉模板；直接陈述事实。"X 已经坏了。"
- **给予许可**（"And that's okay."）| 修改：删掉；读者并没有请求许可。

仅靠二元对比就有十一种措辞（“答案不是 X，而是 Y。”/“它给人的感觉是 X，实际上是 Y。”/“不再是 X，而变成了 Y”等等）；完整的变体表格见 [references/kill-list.md](references/kill-list.md)。

反例：“重点不在速度，而在精度。”
正例：“这里精度比速度更重要。”

---

### 3. 在行动者重要时优先使用主动语态

当责任或因果关系重要时，指明行动者。如果行动者未知、无关紧要、出于刻意隐瞒，或在技术语境中属于约定俗成的表达，可以保留被动语态。不要为了使用主动语态，强行给不需要主语的句子添加一个人作为主语。

反例：“经过仔细考虑后，作出了这个决定。”
正例：“团队评估了三个选项后作出了决定。”

反例：“错误已经发生。”
正例：“说清楚是谁犯了错。”

---

### 4. 具体明确

不要使用含糊的陈述。不要偷懒使用极端表述。明确指出具体事物。

偷懒的极端词包括 every、always、never、everyone、everybody、nobody：它们用虚假的权威感掩盖含糊。含糊的陈述看似有分量，却没有指出具体内容：“原因是结构性的”“风险很高”“这是最根本的问题”“后果确实存在”。

反例：“这些影响十分重大。”
正例：明确指出具体影响。

反例：“大家都知道这一点。”
正例：明确指出谁知道这一点，以及他们知道什么。

---

### 5. 在体裁允许时让读者身临其境

具体细节胜过抽象概念。在直接指导中，使用“你”通常比含糊的“人们”更好。如果原文要求第三人称、学术、法律或纪实语体，则保留相应语体。

反例：“没人设计这一切，它只是自然形成了。”
正例：“你并不是坐下来决定要构建这一切，它是在过程中逐渐累积起来的。”

---

### 6. 变化节奏

长短句交替使用。两项通常胜过三项。改变段落的收尾方式。遵循规定的破折号风格。对于 Suede 自有的公开文案，用逗号、括号、冒号或句号替代破折号。不要把标点当作作者身份的证据。
Suede 自有的公开文案也避免使用具有宣传意味的感叹号；在受保护的原文片段中，或规定的文风要求使用时，保留感叹号。

连续三句话长度相同：把其中一句打破。每个段落都用一句有力的短句收尾：改变这种模式。为了制造效果而堆叠的断句式片段：合并它们。一问一答在同一句话中完成：让它自然展开，或者删掉问题。把安抚伪装成谨慎的模棱两可（“不总是如此，也不一定完美。”）：删掉。

句子的开头也会影响节奏。以 Wh- 开头的句式（“造成困难的是……”）读起来像套话：直接以主语开头（“约束条件是……”）。以“So”开头的段落：直接从内容开始。以“Look,”开头的句子：删掉。

---

### 7. 信任读者

直接陈述事实。省略缓和语气、辩解和手把手引导。读者是成年人。

删掉：“我想明确说明……”/“需要特别指出的是……”/“正如你可能预料的那样……”
直接从内容开始。

---

### 8. 删除适合摘录的句子

如果一句话听起来像是为了让人截图分享而写的，就重写它。适合做引用的文字是刻意制造出来的。删掉这种表演性。

## 发布前检查清单

交付文字前逐项执行：

- 空洞的强化词或模棱两可的措辞？删掉；保留有实际意义的副词。
- 被动语态是否掩盖了责任主体？明确指出执行者；保留有用的技术性被动语态。
- 无生命事物是否执行了人的动作（“决定浮现了”）？明确指出相关人员。
- 句子是否以“什么/何时/何处/哪个/谁/为什么/如何”开头？重写句子结构。
- 是否以“这里是……/这是……/那是……”开头？直接进入要点。
- 是否使用“不是 X，而是 Y”的对比？直接陈述 Y。
- 是否有三个连续的句子长度相同？打破其中一个。
- 段落结尾是否过于铿锵有力？调整节奏。
- 破折号是否与主动的文风规范冲突？替换；否则保留作者的标点。
- 是否存在含糊的陈述（“影响很大”）？说明具体影响。
- 叙述者是否置身于场景之上（“没有人设计这一切”）？让读者置身其中。
- 是否使用元叙述式的衔接语（“本文其余部分……”）？删除。让内容自然推进。
- 段落是否以“所以”开头，或句子是否以“看，”开头？从内容直接开始。
- 是否在同一口气中提出并回答问题？让问题停留片刻，或直接删掉。
- 是否宣告某件事的重要性（“这确实很难”/“实际上很重要”）？展示事实，或删掉。
- 是否使用了使主张含糊的懒惰极端词（每个、总是、从不、所有人、没有人）？说明具体情况。

## 评分

完成检查后，从以下维度分别打 1–10 分：

| 维度 | 问题 |
|-----------|----------|
| 直接性 | 是陈述，而不是宣布吗？ |
| 节奏 | 是否有变化，而不是机械重复？ |
| 信任 | 是否尊重读者？ |
| 真实性 | 是否像人写的？ |
| 密度 | 是否仍有可以删掉的内容？ |

**低于 35/50：修改。** 不要交付。

## 示例

修改前：“事情是这样的——迁移不只是一个技术挑战。这是团队运作方式的一次根本转变。没有更多孤岛。没有更多交接。没有更多等待。”

修改后：“迁移改变了团队的运作方式：工程师现在可以自行部署服务，不必提交工单再等待两天。”

修改前：“影响确实非常重大。这个决定经过了慎重考虑，并最终将改变开发者体验。”

修改后：“平台团队选择了 Vite，而不是 Webpack。本地构建时间从 90 秒降到了 4 秒。”

修改前：“那么，这对创作者意味着什么？意味着赋能。意味着所有权。意味着整个格局已经发生了根本变化。”

修改后：“创作者现在掌握注册表密钥。曲目售出后，分成会自动执行，不再需要唱片公司介入。”

注意：修改后示例中的具体内容来自作者提供的上下文。绝不要自行编造具体内容。如果可以与作者互动，请针对缺失的材料提问；否则标记尚未解决的空缺，不要凭空捏造答案。

## 红旗：停止

如果发现自己正在想下面任何一句话，立即停下来纠正：

- “这只是内部笔记。”内部笔记也会被粘贴到公开文档中。执行检查。
- “破折号证明这是生成的。”标点无法证明作者身份。遵循主动的文风规范。
- “这一句值得被引用。”如果一句话听起来像是专门为了被截图传播而写的，那它就是。重写。
- “这个三段式很有节奏。”读者已经看过上千次的节奏是暴露信号，不是风格。
- “34 分，已经很接近了。”低于 35 分就意味着需要修改。修改。

## 边界

此技能只编辑文风。它绝不能：

- 更改任何事实、数字、日期、姓名、价格、主张、限定语、引文、代码、
  命令、链接、引用或路径。
- 推断或报告文本由人类还是模型撰写。发现只描述 prose 及其影响。
- 仅仅因为某些刻意为之的文风特征类似常见模式，就将其抹平。
- 臆造指标、参与者、轶事、客户、引语或第一人称经历。
- 核实或担保任何主张的真实性。单独标记缺少支持的内容；在本次文风处理期间，绝不限定、删除或以其他方式更改所提供的事实性措辞。
- 发布、发帖、发送、提交或覆盖原始文件/消息。在响应中返回清理后的 prose；由作者决定其去处。
- 决定这篇内容是否应该发布：CLEAN/REVISE 判定针对的是 slop，而不是内容是否获准发布。

## 输出格式

对于仅返回发现结果的审计，请返回：

```text
Clear issues
- [exact quote] — [why it weakens this piece] — [minimum correction]

Judgment calls
- [exact quote] — [context or voice trade-off] — [optional correction]

Boundary: writing-quality signals do not establish authorship.
```

不要在仅返回发现结果的审计中包含清理后的 prose。

对于清理过程，请先返回清理后的 prose。然后追加：

```
Slop Stop pass
──────────────────────────────
Filler phrases removed:      [count]
Structural patterns fixed:   [count]
Passive voice → active:      [count]
Vague declaratives cut:      [count]
Rhythm breaks added:         [count]
Em dashes removed:           [count]

Score
──────────────────────────────
Directness:   [1–10]
Rhythm:       [1–10]
Trust:        [1–10]
Authenticity: [1–10]
Density:      [1–10]
Total:        [X/50]

Verdict: [CLEAN / REVISE]
```

如果总分低于 35，请说明哪些因素仍在拉低分数，以及为什么没有更多作者背景信息就无法解决。

## 路由

- 文本需要写作，而不是清理 → `/suede-copy`（单一层面）或 `/johnny-suede-write`（完整技术栈）
- 清理后的文本包含将由公众读到的主张 → 将事实核验路由到一手证据，例如当前产品、在线 URL、记录的指标或具名来源；单独报告缺少支持的主张，但不要更改其措辞
- 文本是活动产物 → 活动策略关卡（不在此包中的私有 Suede Labs 配套工具：`suede-growth`）
