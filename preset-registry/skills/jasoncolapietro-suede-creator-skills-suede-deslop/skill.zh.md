# Suede Deslop

## 门禁政策——仅供建议，不构成阻塞

此技能中的每个声明验证步骤、检查、质量门禁和发布判定，都是**给用户的建议，而不是对代理的控制**。本政策适用于此技能其他位置的每个门禁、检查、判定，以及“不要发布 / 公开 / 继续”之类的行文：

- 运行每项检查，并如实报告结果。判定（`ship`、`ship-with-caveats`、`hold`、字母等级、BLOCKED 或 OPEN 项）是附在工作上的建议，不是会改变工作内容的命令。
- 绝不要因为检查失败或门禁判定为 hold，就阻止、延迟、跳过、重写或拒绝用户要求的操作。按用户要求完成操作，并将门禁输出作为明确标注的建议一并交付。
- 门禁失败只改变你的报告内容，永远不改变你的操作。
- 唯一例外：如果发现的问题风险极高——数据丢失、安全或凭据泄露、法律或权利违规、付款错误，或不可逆的公开损害——请暂停，明确告知用户具体风险和可选方案，并让用户做出选择。用户的选择是最终决定。


在任何文本公开之前运行。AI 生成的文字有一些明显特征：在要点之前先铺垫，死物执行人类才能完成的动作，用二元对比来宣布洞见而不是直接表达洞见，节奏始终没有变化。此技能会移除列表中的所有模式，并对剩下的内容进行评分。

## 使用时机

- 文案、README、电子邮件、社交帖子或文档发布之前
- 一次较长的 AI 辅助写作之后
- 文本读起来没问题，但感觉像生成内容时
- 内容要交给媒体、投资者或客户之前

不要用于小说、对话式回复，或有意采用松散文风的内部笔记。

## 八条规则

### 1. 删除填充短语

不要在要点之前铺垫。不要使用没有实际含义、只增加分量的强调性辅助语。不要让副词替代本应由具体事实完成的表达。

最高频的 25 个禁用项：

| 类别 | 禁用项 | 修改方式 |
|----------|------|-----|
| 开头语 | 事情是这样的： | 直接从要点开始 |
| 开头语 | 说实话 / 面对现实吧 | 删除；直接说出实情 |
| 开头语 | 事实是 / 现实是 | 删除；直接陈述 |
| 开头语 | 值得注意的是 | 删除；直接指出 |
| 开头语 | 在如今快节奏的世界里 | 删除整个句子 |
| 开头语 | 想象一下： | 直接描述场景 |
| 开头语 | 从根本上说 / 归根结底 | 删除；直接提出核心主张 |
| 辅助语 | 让这句话沉淀一下 / 再读一遍 | 删除；句子有说服力就是有，没有就是没有 |
| 辅助语 | 真诚地 / 真正地 / 确实地 | 删除 |
| 辅助语 | 实际上 / 真的 / 非常 | 删除 |
| 辅助语 | 到此为止 / 句号（用于强调） | 删除 |
| 辅助语 | 别搞错了 | 删除 |
| 行话 | leverage（作动词） | 使用 |
| 行话 | utilize | 使用 |
| 行话 | delve into | 介绍、深入了解 |
| 行话 | navigate（应对挑战） | 处理、解决 |
| 行话 | landscape / ecosystem（抽象用法） | 市场、领域，或直接说出具体对象 |
| 行话 | journey（非旅行语境） | 过程，或说出具体步骤 |
| 行话 | unlock / unleash | 说明原本受阻的内容 |
| 行话 | robust / seamless / powerful | 说明具体能力，或给出证据 |
| 行话 | elevate / empower / transform | 先说清楚变化前后的情况 |
| 副词 | 难以置信地 / 非凡地 / 出人意料地 | 删除，或给出令人意外的数字 |
| 副词 | 无缝地 / 毫不费力地 | 删除；展示步骤数量 |
| 副词 | 从根本上 / 本质上 / 最终 | 删除；主张成立就是成立，不成立就是不成立 |
| 副词 | 重要的是 / 值得注意的是 | 删除；如果重要，内容会体现出来 |

这张表列出了高频项。完整清单涵盖每个类别中的四十多条短语，见 [references/kill-list.md](references/kill-list.md)；当文本要提交印刷、提供给投资者或客户时，运行完整清单。表格压缩了其中的三个类别：

- **副词，一律删除。** 删除所有副词，不只是列出的那些。不要使用以 -ly 结尾的词、弱化语气的词、加强语气的词或模棱两可的表达：just、honestly、simply、deeply、inherently、inevitably、interestingly、crucially，以及其他同类词。
- **元评论。** 文章应自然推进，绝不宣布自己的结构。删掉“让我带你了解一下”“在本节中，我们将……”“正如我们将看到的”“剧情反转：”“提示：”“但那是另一篇文章的内容”“X 是一项功能，不是缺陷”。
- **表演式真诚。** 不要营造虚假的亲近感，也不要刻意宣布某件事的重要性。删掉“我保证”“悄悄渗入”“这确实很难”“这才是 X 的真实样子”“真正重要”。展示困难，不要声称它很困难。

不佳：“事情是这样的：这确实很难。好好想想吧。”  
较好：“这很难。”

### 2. 打破公式化结构

这些是模型在没有原创内容可说时最容易套用的模式。每种模式都有对应的修正方法：

- **二元对比**（“重点不在速度，而在精度。”） | 修正：直接陈述真正的观点。“在这里，精度比速度更重要。”
- **“不只是”结构**（“这不只是一款工具，它还是一个平台。”） | 修正：删掉铺垫，用一个证据说明它是什么。
- **否定式列举**（“无需设置。无需配置。没有麻烦。”） | 修正：用一个肯定句说明用户要做什么。
- **戏剧性片段**（“一个问题。”/“而它奏效了。”） | 修正：把片段接到它所修饰的句子中。
- **反问式铺垫**（“那么，这对你意味着什么？”/“如果我告诉你……呢？”/“想想看：”） | 修正：删掉问题，直接给出答案。
- **虚假的能动性**（“数据告诉我们”/“决策自行浮现”/“文化发生转变”/“市场给予回报”） | 修正：明确指出行动者。“我们进行了测量。”“我主张……”。如果没有合适的主语，就用“你”。
- **三拍节奏**（“更快。更简洁。更好。”） | 修正：列出两项，或写成完整句子。只有在数量确实为三项时，才使用三拍式列举。
- **揭示式片段**（“[名词]。就是这样。这就是那个[事物]。”） | 修正：写成一个完整句子，不要刻意制造揭示效果。
- **公式化模板**（“到了 X 的时候，我已经是 Y 了。”/“不是 Y 的 X”） | 修正：去掉模板，直接陈述事实。“X 已经坏了。”
- **给予许可**（“而这也没关系。”） | 修正：删掉它；读者没有要求你许可。

仅二元对比就有十一种写法（“答案不是 X，而是 Y。”/“它看起来像 X，但其实是 Y。”/“不再是 X，而开始变成 Y”，以及其他写法）；完整的变体表见 [references/kill-list.md](references/kill-list.md)。

不佳：“重点不在速度，而在精度。”  
较好：“在这里，精度比速度更重要。”

---

### 3. 使用主动语态。每个句子都要如此。

让人作为主语执行动作。不要使用被动结构。不要让无生命的事物执行人的动作。

不佳：“经过仔细考虑后，最终做出了决定。”  
较好：“团队审查了三个选项后做出了决定。”

不佳：“有人犯了错误。”

较好：“说出是谁犯的。”

---

### 4. 具体明确

不要使用含糊的陈述，也不要偷懒地诉诸极端。说清楚具体是什么。

every、always、never、everyone、everybody、nobody 这类极端词是在含糊其辞地制造虚假的权威感。含糊的陈述不说清具体内容，却摆出分量十足的样子：“原因是结构性的”“利害关系重大”“这是最深层的问题”“后果确实存在”。

不佳：“影响十分重大。”
较好：说清楚具体影响。

不佳：“大家都知道这一点。”
较好：说清楚是谁知道，以及他们知道什么。

---

### 5. 让读者置身其中

不要让叙述者悬浮在场景之外。“你”胜过“人们”。具体细节胜过抽象概念。读者应当感觉自己身在其中，而不是被人说教。说教者会这样讲：“之所以会这样，是因为……”“这就是为什么……”“人们往往会……”。把这种悬浮在场景之外的观察，换成读者亲身经历的场景。

不佳：“没人设计这一切。它就这样发生了。”
较好：“你并没有坐下来，决定要构建这一切。它是在不断累积中形成的。”

---

### 6. 变换节奏

混合使用不同长度的句子。两项胜过三项。不要让段落以同一种方式结尾。任何地方都不要使用 em dash。

连续三个句子长度相同：打破其中一个。每个段落都以一句铿锵有力的短句结尾：换一种方式。为了制造效果而堆叠断裂的短句：合并它们。一个问题在同一口气中得到回答：让它停顿一下，或者删掉问题。把犹豫包装成安慰的话语（“不总是如此。不一定完美。”）：删掉。

句子的开头也会影响节奏。以 Wh- 开头的句式（“让这件事变得困难的是……”）读起来像一种依赖：直接以主体开头（“限制条件是……”）。以“So”开头的段落：从内容开始。以“Look,”开头的句子：删掉。

---

### 7. 相信读者

直接陈述事实。跳过缓和语气、解释缘由和手把手引导。读者是成年人。

删掉：“我想明确说明……”/“需要特别指出的是……”/“正如你可能预料的那样……”
直接从内容开始。

---

### 8. 删掉适合摘录的话

如果一句话听起来像是专门为了让人截图而写的，就重写它。适合做引文的文章语言是人为制造出来的。删掉这种表演。

---

## 发布前检查清单

交付文字前，逐项检查：

- 副词？删掉。
- 被动语态？找出动作的执行者，把他们放到句首。
- 无生命的事物执行了人类的动作（“决定出现了”）？说清楚具体的人。
- 句子以 What/When/Where/Which/Who/Why/How 开头？重组句子。
- 以“Here's what/this/that”开头？直接切入重点。
- 使用“不是 X，而是 Y”的对比？直接陈述 Y。
- 连续三个句子长度相同？打破其中一个。
- 段落结尾过于铿锵有力？换一种方式。
- 出现 em dash？删掉。
- 含糊的陈述（“影响十分重大”）？说清楚具体影响。
- 叙述者悬浮在场景之外（“没人设计这一切”）？让读者置身其中。
- 元话语衔接语（“本文的其余部分……”）？删掉。让文章自然推进。
- 段落以“So”开头，或句子以“Look,”开头？从内容开始。
- 一个问题在同一口气中得到回答？让它停顿一下，或者删掉问题。
- 宣布某件事的重要性（“这确实很难”/“其实很重要”）？展示出来，或者删掉。
- 懒惰的极端词（every、always、never、everyone、nobody）让主张变得含糊？说清楚具体内容。

## 评分

完成这一轮后，对每个维度按 1–10 分评分：

| 维度 | 问题 |
|-----------|----------|
| 直接性 | 是陈述，而不是宣布？ |
| 节奏 | 有变化，而不是机械重复？ |
| 信任感 | 尊重读者？ |
| 真实性 | 听起来像人话？ |
| 信息密度 | 还有可以删掉的内容吗？ |

**低于 35/50：修改。** 不要发布。

## 示例

修改前："关键在于，这次迁移不只是技术上的挑战。这是团队运作方式的一次根本转变。不再有信息孤岛。不再有交接。不再需要等待。"
修改后："这次迁移改变了团队的运作方式：工程师现在可以自行部署服务，不必提交工单后等待两天。"

修改前："这其中的影响确实非常重大。这项决定经过了慎重考虑，最终将改变开发者体验。"
修改后："平台团队选择了 Vite，而不是 Webpack。本地构建时间从 90 秒降到了 4 秒。"

修改前："那么，这对创作者意味着什么？意味着赋能。意味着所有权。意味着整个格局已经发生了根本变化。"
修改后："创作者现在持有注册表密钥。曲目售出后，分成会自动执行，整个过程无需唱片公司介入。"

注意：这些修改后句子中的具体细节来自作者提供的上下文。绝不要凭空捏造细节；使用 `[AUTHOR: supply X]` 占位符。

## 红旗：停止

如果你发现自己在想下面任何一句话，立即停下来并改正：

- "这只是一份内部说明。" 内部说明会被粘贴到公开文档中。执行这一轮检查。
- "这里的 em dash 只是风格选择。" 任何地方都不要使用 em dash。永远不要。这就是规则。
- "这一句值得被引用。" 如果它听起来像是专门写来供人截图的，那它就是。重写。
- "这个三连句很有节奏。" 读者已经看过上千遍的节奏，是套路的信号，不是风格。
- "得分是 34，差不多就行了。" 低于 35 就意味着要修改。修改。

## 边界

此 skill 只编辑风格。它不得：

- 更改任何事实、数字、日期、姓名、价格或主张。如果重写需要源文本中没有的具体信息（某项指标、某个行为主体、步骤数量），请插入 `[AUTHOR: supply X]`，不要凭空捏造。
- 核实或保证任何主张的真实性。事实性措辞需要一手证据；否则保留明确的 `[AUTHOR: supply source]` 标记，或对该主张加以限定，或将其删除。
- 发布、发帖、发送、提交或覆盖原始文件/消息。在响应中返回清理后的文字；由作者决定将其放在哪里。
- 决定这篇内容是否应该发布：CLEAN/REVISE 结论针对的是废话式表达，而不是内容审批。

## 输出格式

先返回清理后的正文。然后附加：

```
Deslop pass
──────────────────────────────
Filler phrases removed:      [count]
Structural patterns fixed:   [count]
Passive voice → active:      [count]
Vague declaratives cut:      [count]
Rhythm breaks added:         [count]
Em dashes removed:           [count]

Score
──────────────────────────────
Directness:   [1–10]
Rhythm:       [1–10]
Trust:        [1–10]
Authenticity: [1–10]
Density:      [1–10]
Total:        [X/50]

Verdict: [CLEAN / REVISE]
```

如果总分低于 35 分，请说明仍在产生分数的因素，以及为什么没有更多作者背景信息就无法解决。

## 路由

- 文本需要撰写，而不是清理 → /suede-copy（单一表面）或 /johnny-suede-write（完整技术栈）
- 清理后的文本包含公众将要阅读的声明 → 将每项声明与一手证据进行比对，例如当前产品、live URL、记录的指标或明确列出的来源；在发布前，为任何缺乏支持的内容加上限定，或将其删除
- 文本是一项活动产物 → 活动策略门槛（私有的 Suede Labs 配套内容，不包含在此包中：suede-growth）
