# 压测

此技能会选取一个组件，在一个全新页面中，针对实际可能出现的每种场景进行渲染，并报告发生了哪些破坏。一个只针对单一理想路径构建的组件，在真实内容到来之前，看起来总像是已经完成了。

它只观察，不评判。这里的发现是指页面上明显发生的破坏，并使用负责修复该问题的领域技能所采用的术语来命名。依据标准审查代码属于 `interface-review` 和 `better-interface`；探索设计替代方案属于 `variant`。

`variant` 坚持在真实页面中进行，而此技能则有意隔离组件。你不是在判断组件放入上下文后看起来如何，而是在检查它面对最坏情况的内容时能否保护自身。

## 1. 将范围限定为一个组件

每次运行只测试一个组件。“设置页面”不是组件；个人资料表单中的文本输入框才是。如果请求涉及多个组件，请列出候选项并询问用户要测试哪一个，而不是替用户做出选择。

用一句话重述该组件是什么：它接受什么、渲染什么，以及将位于何处。

## 2. 根据组件推断场景

只对会变化的部分进行压力测试。当组件所接受的内容在生产环境中可能呈现某种形态时，该场景才值得占据一个测试位置。因此，先阅读组件：它的 props、插槽、状态以及它渲染的数据。

[scenarios.md](scenarios.md) 包含各个维度、每个维度上的取值，以及用于判断该维度是否适用的线索。根据组件逐项检查，只保留线索匹配的维度。文本输入框需要测试内容长度和状态，绝不需要测试条目数量。带有固定标签的静态图标按钮需要测试容器和环境，绝不需要测试长文本。

在构建之前写下保留的场景，每个场景一行，以确保测试工具渲染的是一组预先规划好的场景，而不是临时想到什么就渲染什么。然后用一行说明舍弃了哪些维度以及原因，以便在推断错误时能够轻松发现。

## 3. 构建测试页面

创建一个一次性页面，从项目中导入真实组件，并针对每个场景渲染一次，所有实例排列在同一列中。用场景名称标注每个实例，并在测试工具中为每个实例添加虚线轮廓，以便看清超出组件自身边界的溢出内容。

使用项目自身的技术栈：如果项目有开发服务器，就在其中创建一个临时路由；如果没有，就创建一个独立的自包含 HTML 文件。通过 props 和固件数据传入场景。测试工具绝不导入生产状态，绝不连接实时数据，生产代码也绝不从测试工具中导入任何内容。

确保测试工具在视觉上明显独立于设计系统，保持朴素且不添加样式，以免它添加的任何内容被误认为是组件自身的渲染结果。

## 4. 渲染并观察

一次从未实际渲染的运行，只是披着外衣的代码审查。加载页面，查看每个场景，并且只记录你亲眼看到的现象。阅读 CSS 并预测“这可能会溢出”不算一项发现。

如果有可编程浏览器，请截取页面截图，将窗口宽度调整为 320px 后再次截图，并使用 Tab 键依次检查交互场景。如果没有，请启动开发服务器或写入文件，然后让用户打开它，并根据用户报告的情况继续。

对于每个场景，记录以下两种结果之一：通过，或出现问题并记录可见现象。应写“文本超出卡片右边缘”，绝不要写“间距感觉太紧”。

## 5. 报告出现的问题，然后停止

以表格形式报告发现的问题，并将出现问题的场景排在前面：

| 场景 | 观察结果 | 归属方 |
| --- | --- | --- |
| 一个不可断行的 60 字符字符串 | 溢出卡片，既不换行也不截断 | `better-typography` |
| 零个项目 | 空白区域且没有提示消息 | `better-writing` |

归属方列用于指出其规则能够诊断该问题的领域技能，以便从正确的位置着手修复。此技能不包含任何领域规则，也不作出任何判定。

“所有场景均通过”是一份完整且有用的报告。说明运行了哪些场景以及使用了哪些宽度，然后到此为止，不要用偏好性建议来填充结果。

不要修复任何未被要求修复的问题。如果收到修复请求，请遵循归属技能的规则，然后重新渲染失败场景以进行确认。

## 6. 删除测试工具

测试工具是检测手段，而非交付物。报告提交后，删除该页面及其固件，除非被要求保留。

## 完成之前

| 错误 | 修正方式 |
| --- | --- |
| 针对每个组件运行所有维度 | 仅保留与线索匹配的维度，并说明舍弃了哪些维度 |
| 将预测的失败报告为已观察到的失败 | 将其渲染出来，否则不要报告 |
| 在测试工具中重新构建一个外观相似的组件 | 从项目中导入真实组件 |
| 使用主观偏好描述发现的问题 | 报告页面上可见的现象，否则什么也不报告 |
| 报告问题却未指定归属方 | 指出其规则能够诊断该问题的领域技能 |
| 在无问题的运行结果中添加多余建议 | 报告内容就是“所有场景均通过”加上场景列表 |
| 仅在一个宽度下进行判断 | 至少使用 320px 和一个宽视口 |
| 测试工具被遗留 | 除非被要求保留，否则将其删除 |
