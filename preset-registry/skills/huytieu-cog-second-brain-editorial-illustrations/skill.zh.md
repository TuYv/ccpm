# 编辑插图——主张 → 几何

你想要的视觉风格（monotykamary.com、linear.app/now）并不是一个图表库。它是一套
**准则**：每幅图都用几何形式呈现单一论点，置于极细线框中，以等宽大写文字标注其*含义*，
采用灰度绘制，并且仅使用一种强调色。遵循好这套准则，任何形状看起来都会像是“自家风格”。
盲目照搬模板，只会显得粗制滥造。

**不要依赖一套固定的图表。** 应采用下面的方法，构建这个特定句子所需要的图形。
`references/worked-examples.md` 中的六个完整示例证明了这种方法具有通用性，而不是一份可选菜单。

## 核心做法

> 找出这幅图必须证明的那一个句子。识别该句子的*结构*。
> 将这种结构呈现出来，让读者在阅读句子之前就相信它。

标题就是论点，应首先写好。如果你无法用一句话说明图形的主张，那么你还没有得到一幅图，
只有装饰。停下来。

## 方法（每次都执行）

1. **写出主张。** 使用一个陈述句。它将原样成为 `<figcaption>`。
   示例：“在工作跨越交付边界之前，没有任何内容可以计费。”

2. **说出主张的结构。** 这个句子本质上在讲什么？
   将它与一个几何图元对应起来：

   | 如果主张涉及……                            | 将其呈现为……                 | 图元（§5） |
   |---------------------------------------------|-------------------------------|------------|
   | 光谱 / 多与少 / 渐变                        | 有序单元格、递增填充          | 5a |
   | 数值排名 / 占比 / 比较                      | 水平条形、真实坐标轴          | 5b |
   | 带有临界点的序列                            | 阶段网格 + 移动圆点           | 5a + 轨道 |
   | 相互因果 / 反馈关系                         | 两个耦合轨道 + 桥接           | 5d |
   | 不确定条件下的分支 / 决策                   | 节点与分支构成的 SVG 树       | 5c |
   | 某个事物改变形态 / 数据管线                 | 阶段轨道，每个阶段一个字形    | 5e |
   | 朝目标累积                                  | 堆叠 / 填充条形               | 5a/5b |
   | 边界 / 内部与外部                           | 带框区域 + 穿越动作           | 组合 |
   | 分布 / 数据质量集中在哪里                   | 圆点条带或小多图              | 组合 |

   如果没有匹配项，**组合出一个新的图元**，使用
   `references/design-system.md §5` 中的基础图元。新颖性是预期之内且值得欢迎的；
   必须保持一致的是*设计令牌与克制感*。

3. **确定重点。** 哪一个元素能够单独证明该主张？只有它使用
   `--accent`（珊瑚色）。其他所有内容均保持灰度。使用一种强调色，最多两处。
   没有重点 → 图形没有论点 → 返回第 1 步。

4. **按照系统绘制。** 应用 `references/design-system.md`：设计令牌、
   字体排印法则（展示文字 = Inter 480–540 紧凑排版；其他所有文字均使用等宽字体、小字号、
   大写标签）、带边框的图形样式、宽度为 720 的 SVG viewBox、仅使用极细线、不添加图表垃圾。

5. **仅在动态效果能够阐明主张时添加。** 一个在边界前暂停的圆点；一道在两个循环之间穿越的脉冲；
   一个沿分支向下移动的信号。时长 2–6 秒，使用 `ease-in-out`，并始终在
   `prefers-reduced-motion` 下禁用。如果动态效果无法*展示*论点，就省略它。
   静态完全没问题，而且通常更好。

6. **添加图注。** 使用等宽字体、8px、全大写，置于分隔线上方。说明含义，而不只是
   数据来源。（写“……因为 X”，而不是“图 3”。）

## 一句话概括这种美学

- **底色：** 与宿主页面一致——深色页面使用近黑色 `--ground:#080807`，浅色页面使用白色/
  灰白色（两套令牌均见 `design-system.md`）。图表置于带有微弱底色的框架中；深色模式使用
  `backdrop-filter: blur(16px)`，浅色模式使用极细边线 + 淡淡的
  阴影。
- **字体：** 仅在少数大型展示文字中使用 Inter；**图表内部一律使用等宽字体**，
  字号为 7–11px，标签/图注使用全大写。绝不使用第二种无衬线字体，绝不使用粗体展示文字。
- **颜色：** 灰阶色带（`--ink → --quiet`）+ **一种**强调色 = Claude 珊瑚色
  `#D97757`，且仅用于重点。（若要忠实呈现 monotykamary 风格的纯灰阶效果，请设置
  `--accent: var(--ink)`。）
- **结构：** 1px 极细线、正圆形节点，虚线 = 暂定/失败，
  不使用阴影，不使用渐变，唯一例外是一条表示坐标轴方向的极细渐变线。
- **密度：** 小字号、紧凑单元格、内容铺满边缘。克制就是风格。

完整规范 + 可复制粘贴的令牌块（深色和浅色）+ 基础 CSS：
`references/design-system.md`。包含“主张→几何形式”推理过程的完整示例：
`references/worked-examples.md`。非图表类编辑元素（指标条、状态侧栏、
眉题+符号、编号章节索引、正文字体、行内卡片）：
`references/elements.md`。实时渲染效果展示（珊瑚色品牌风格，可切换）：
`assets/gallery.html`。

## 图表应始终遵循宿主页面的主题

图表是页面上的访客。它必须匹配该页面的明暗主题，而不能强加自己的主题。把深色展示面板放进浅色文章中，
看起来就像一个外来物体（2026-07-22 的惨痛教训）。

- **先观察宿主页面。** 浅色页面 → 浅色图表。深色页面 → 深色图表。
  宿主网站可能默认使用**浅色**，并带有自己的**主题切换器**（例如 Charter 衬线标题 + Public Sans 正文，
  蓝色强调色），该切换器会在 `<html>` 上设置 `data-theme="light"|"dark"`——其中的图表
  必须**遵循 `data-theme`**，并默认使用浅色主题。
- **如果宿主有明确的主题系统，应根据它来启用深色覆盖，而不是根据
  媒体查询。** 使用 `:root[data-theme="dark"] .yourfig { … }`，不要使用
  `@media (prefers-color-scheme: dark)`。真实缺陷（2026-07-22）：由于查看者的操作系统使用深色模式，
  而页面主题为浅色，基于媒体查询的图表在**浅色博客上渲染成了深色**。
  页面的 `data-theme` 才是事实来源；媒体查询仅适用于没有主题切换器的宿主。在支持主题切换的宿主中，应匹配网站自身的
  深色令牌（底色 `#171b22`、线条 `#262c36`、文字 `#f1f5f9`），使图表的深色
  面板融入网站的深色主题，而不是呈现为格格不入的近黑色。
- **基于令牌构建，使其能够自适应。** 在图表自身的作用域内定义调色板，
  默认值 = 宿主的默认主题，并添加 `:root[data-theme="dark"] .fig` 覆盖
  （仅当宿主没有主题切换器时，再添加 `@media (prefers-color-scheme: dark)` 覆盖）。
  这样几乎没有成本，还能让图表适应未来变化。
- **珊瑚色应针对不同底色满足 AA 标准。** 在白色背景上，文本/描边使用 `--accent:#c15f3c`
  （`#D97757` 仅用于大型节点填充）；在近黑色背景上直接使用 `#D97757`。
- **“主张→几何形式”方法和克制原则不受主题影响。** 只有
  调色板令牌需要替换。灰阶色带 + 一种珊瑚色强调色的规则适用于两种底色。

## 输出约定

- 每幅插图使用一个自包含的 `<figure>`：内联作用域限定于该 figure 的 `<style>`（或共享 token `:root`）、内联 SVG，且不发起外部请求。
- **主题 = 宿主主题**（见上文）：嵌入浅色页面时默认为浅色，但始终基于 token，并包含 `prefers-color-scheme` + `:root[data-theme]` 覆盖，同时**确保在减少动态效果设置下安全**。这两项都是内部规范，并非可选要求。
- 对于 **Artifact**：不得使用外部字体/CDN（CSP 会阻止它们）；使用内联 `@font-face` data-URI，或回退到 `system-ui`/`ui-monospace`。
- 对于**你自己网站上的博客文章**：将 figure 的 HTML/CSS 输出到文章正文中（Markdown 会通过 `build.py` 原样传递原始 HTML）。博客采用**浅色**主题，因此应用浅色 token；保留深色覆盖以确保可移植性。使用 `python3 build.py` 重新构建；构建后的页面使用绝对资源路径，因此请通过本地服务器或自包含的独立副本进行预览，绝不要直接使用 `file://` 打开（这会导致文章在无样式状态下渲染）。请参阅本地自包含 HTML 预览。

## 验证（强制要求——这是 UI/UX 输出）

根据视觉验证规则，仅做 DOM 检查是不够的。**请渲染并目视检查。**

1. 在 browser-harness 中打开 figure，并对其截图（`evidence_shot`）。
2. 对照论点检查图像：几何结构是否能让句意一目了然？珊瑚色是否仅出现在重点位置？是否存在等宽文本被裁切、SVG 标签未对齐、条形图计算偏差一位、在 ≤720px 时响应式堆叠布局损坏的问题？
3. 修复目视发现的问题，并重新截图以证明修复效果。也要检查浅色变体。
4. 确认在减少动态效果设置下，动态效果会停止。

## 粗制滥造检查清单（任一项不符合即拒绝该 figure）

- [ ] figcaption 是一个用一句话陈述的真实论点。
- [ ] 几何结构对该论点的*结构*进行了编码（而不是随意附上一个通用图表）。
- [ ] 恰好只有一个强调元素（珊瑚色），且位于重点位置。
- [ ] figure 内的每个标签/数值/说明文字都使用等宽字体和极小字号；标签全部为大写。
- [ ] 仅使用细线；无阴影、无渐变（条形图坐标轴细线除外），无圆角矩形。
- [ ] 仅当 figure 确实是定量图表时才显示网格线。
- [ ] 动态效果（如有）用于说明论点，并在减少动态效果设置下停止。
- [ ] 在深色和浅色主题下均能正确渲染，并能在移动端整齐地堆叠布局。
