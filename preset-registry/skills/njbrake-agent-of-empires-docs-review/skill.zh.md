# 文档审查

对照当前代码库审查所有项目文档的准确性。修复任何过时、错误或缺失的信息。

## 范围

**需要审查的文档文件：**
- `README.md`
- `CLAUDE.md`
- `docs/` 中的所有文件（指南、CLI 参考、安装说明、快速入门等）
- 仓库根目录下的任何其他 `.md` 文件

**用于交叉核对的源代码：**
- `src/cli/` 中的 CLI 命令定义（clap 结构体、子命令、标志、参数）
- `src/session/` 中的配置结构体（配置字段、默认值、验证）
- `src/process/` 中支持的代理及检测逻辑
- `src/tui/` 中的 TUI 键位绑定和导航
- `src/docker/` 中的 Docker/沙箱配置
- `src/git/` 中的 Git worktree 操作
- `src/` 各处的功能标志和能力

## 说明

1. 阅读上面列出的每个文档文件。

2. 对于每个文档文件，将其中的描述与实际源代码进行交叉核对：
   - CLI 标志和参数：与 `src/cli/` 中的 clap 定义进行比较
   - 配置选项：与 `src/session/` 中的配置结构体进行比较
   - 支持的代理：与 `src/process/` 中的代理检测逻辑进行比较
   - 键位绑定：与 `src/tui/` 中的输入处理逻辑进行比较
   - 安装步骤：验证 `scripts/` 中的脚本是否与文档中的命令一致
   - 功能描述：验证相关功能是否存在并按文档描述运行

3. 对于发现的每处差异：
   - 修正文档，使其与源代码一致（绝不要反过来修改源代码）
   - 保持修改最小且准确
   - 保留文档现有的写作风格和语气

4. 不要修改任何非文档文件。绝不要编辑 `.rs`、`.toml`、`.yml`、`.yaml`、`.sh`、`.js`、`.json` 或任何其他源代码/配置文件。

5. 审查完所有文件后，提供修改内容及修改原因的摘要。如果不需要任何修改，请报告所有文档均准确无误。

## 需要检查的内容

- 已添加、移除或重命名的 CLI 命令、标志或参数
- 默认值、名称或行为已更改的配置选项
- 文档中描述但已不存在的功能
- 代码中存在但尚未记录到文档中的功能
- 错误的文件路径或目录引用
- 过时的安装说明或版本要求
- 已更改的键位绑定
- 过时的受支持代理列表
