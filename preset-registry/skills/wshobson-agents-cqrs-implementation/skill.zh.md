# CQRS 实现

实现 CQRS（命令查询职责分离）模式的全面指南。

## 何时使用此技能

- 分离读与写的关注点
- 让读操作独立于写操作进行扩展
- 构建事件溯源系统
- 优化复杂查询场景
- 需要不同的读/写数据模型
- 高性能报表需求

## 核心概念

### 1. CQRS 架构

```
                    ┌─────────────┐
                    │   Client    │
                    └──────┬──────┘
                           │
              ┌────────────┴────────────┐
              │                         │
              ▼                         ▼
       ┌─────────────┐          ┌─────────────┐
       │  Commands   │          │   Queries   │
       │    API      │          │    API      │
       └──────┬──────┘          └──────┬──────┘
              │                         │
              ▼                         ▼
       ┌─────────────┐          ┌─────────────┐
       │  Command    │          │   Query     │
       │  Handlers   │          │  Handlers   │
       └──────┬──────┘          └──────┬──────┘
              │                         │
              ▼                         ▼
       ┌─────────────┐          ┌─────────────┐
       │   Write     │─────────►│    Read     │
       │   Model     │  Events  │   Model     │
       └─────────────┘          └─────────────┘
```

### 2. 关键组件

| 组件                | 职责                 |
| ------------------- | -------------------- |
| **命令**            | 改变状态的意图        |
| **命令处理器**      | 验证并执行命令        |
| **事件**            | 状态变更的记录        |
| **查询**            | 数据请求             |
| **查询处理器**      | 从读模型检索数据      |
| **投影器**          | 根据事件更新读模型    |

## 最佳实践

### 该做的

- **分离命令模型和查询模型** - 需求不同
- **采用最终一致性** - 接受传播延迟
- **在命令处理器中进行验证** - 在状态变更之前
- **对读模型进行反范式化** - 针对查询进行优化
- **对事件进行版本化** - 支持结构演进

### 不该做的

- **不要在命令中执行查询** - 仅用于写操作
- **不要耦合读/写数据结构** - 保持独立演进
- **不要过度设计** - 从简单开始
- **不要忽视一致性 SLA** - 定义可接受的延迟
