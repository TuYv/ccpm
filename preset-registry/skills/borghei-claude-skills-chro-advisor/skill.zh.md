# CHRO 顾问

提供与业务目标一致的人才招聘、薪酬、组织设计、绩效管理和可规模化文化建设所需的人才战略与人力资源运营框架。CHRO 将业务目标转化为人才需求，并确保组织具备实现目标所需的人才、结构和文化。

CHRO、首席人力资源官、人力资源、人力资源管理、人才战略、招聘计划、人员编制规划、人才获取、招聘、薪酬、薪资带、股权、组织设计、组织架构设计、职业发展阶梯、职级框架、人才保留、绩效管理、文化、员工敬业度、远程工作、混合办公、管理幅度、继任规划、人员流失、劳动力规划、人才分析、eNPS、入职、离职、DEI、雇主品牌

## 快速入门

### 劳动力规划决策树

```
START: Business goal identified
  |
  v
[Can existing team deliver this goal?]
  |
  +-- YES --> [Is current capacity sustainable?]
  |             |
  |             +-- YES --> No hiring needed. Optimize.
  |             +-- NO  --> Hire for sustainability (backfill/support)
  |
  +-- NO  --> [Is this a skill gap or capacity gap?]
              |
              +-- SKILL GAP --> [Can we develop internally in < 90 days?]
              |                  |
              |                  +-- YES --> Train/develop. No hire.
              |                  +-- NO  --> Hire specialist.
              |
              +-- CAPACITY GAP --> [Is this temporary or permanent?]
                                    |
                                    +-- TEMPORARY --> Contract/agency
                                    +-- PERMANENT --> Full-time hire with business case
```

## 核心职责

### 1. 劳动力规划与人员编制

每次招聘都需要有业务依据。“我们需要更多人”并不是业务依据。

#### 招聘理由框架

| 问题 | 必答内容 |
|----------|----------------|
| 该职位将带来多少收入或应对什么风险？ | 具体金额或风险描述 |
| 如果我们未能在 90 天内填补该职位，会发生什么？ | 具体的影响说明 |
| 现有团队能否通过重新确定优先级来承担这些工作？ | 是/否，并附说明 |
| 完全成本是多少（薪资 + 福利 + 股权 + 工具 + 管理费用）？ | 金额 |
| 达到完全生产力预计需要多长的适应期？ | 周/月 |
| 谁将管理此人？ | 有管理余力的指定经理 |

#### 按发展阶段划分的人员编制规划

| 阶段 | 团队规模 | CHRO 重点 | 招聘速度 |
|-------|-----------|------------|--------------|
| Pre-seed | 1-5 | 创始人直接招聘 | 每季度 1-2 人 |
| Seed | 5-15 | 首次采用结构化面试，尚无人力资源人员 | 每季度 2-4 人 |
| Series A | 15-40 | 招聘首位 People 岗位人员、建立薪酬带和职业发展阶梯 v1 | 每季度 4-8 人 |
| Series B | 40-100 | 配备 CHRO 或 VP People、完整招聘流程和 HRIS | 每季度 8-20 人 |
| Series C | 100-250 | 建立 People 团队（3-5 人）、管理者培训和绩效体系 | 每季度 15-40 人 |
| Growth | 250+ | 完整的人才职能、人才分析、L&D 和全面薪酬 | 每季度 30 人以上 |

### 2. 薪酬设计

#### 薪酬区间架构

```
Level Framework:
  IC Track                    Management Track
  ---------                   ----------------
  L1: Junior/Associate        --
  L2: Mid-level               --
  L3: Senior                  M1: Manager (first-time)
  L4: Staff/Principal         M2: Senior Manager
  L5: Distinguished/Fellow    M3: Director
  --                          M4: VP
  --                          M5: SVP/C-level
```

#### 薪酬区间构建方法

| 步骤 | 行动 | 数据来源 |
|------|--------|------------|
| 1 | 使用明确的能力标准定义职级 | 内部岗位描述 |
| 2 | 根据市场数据对各职级进行基准对标 | Levels.fyi、Pave、Radford、Option Impact |
| 3 | 设定区间宽度（通常跨度为 20-30%） | 市场数据 + 内部公平性 |
| 4 | 将区间中点设在目标百分位 | 现金薪酬采用 P50，总薪酬采用 P50-P75 |
| 5 | 定义各职级的股权区间 | 适用于相应阶段的股权计算器 |
| 6 | 设定职级之间的晋升标准 | 绩效 + 职责范围 + 影响力 |

#### 总薪酬构成

| 构成部分 | 目的 | 调整频率 |
|-----------|---------|-----------------|
| 基本工资 | 符合市场水平的现金薪酬 | 年度审查 |
| 年度奖金 | 与绩效挂钩的浮动薪酬 | 每年（如适用） |
| 股权（期权/RSU） | 长期利益一致与人才留任 | 初始授予 + 年度追加授予 |
| 福利 | 医疗、401k、额外福利 | 年度审查 |
| 签约奖金 | 提升录用通知竞争力 | 一次性 |

#### 各阶段股权授予指南

| 阶段 | IC 招聘（L2-L3） | 高级人才招聘（L4-L5） | VP/C-Level |
|-------|-----------------|---------------------|------------|
| 种子轮 | 0.25-1.0% | 1.0-2.5% | 2.0-5.0% |
| A 轮 | 0.05-0.25% | 0.25-0.75% | 0.5-2.0% |
| B 轮 | 0.01-0.10% | 0.10-0.30% | 0.25-1.0% |
| C 轮及以后 | 0.005-0.05% | 0.05-0.15% | 0.10-0.50% |

### 3. 组织设计

#### 管理跨度指南

| 角色类型 | 最优管理跨度 | 警示信号 |
|-----------|-------------|---------------|
| IC 经理（工程） | 5-8 名直接下属 | > 10：没有时间辅导。< 4：管理层级不必要 |
| IC 经理（非工程） | 6-10 名直接下属 | > 12：不堪重负。< 5：管理岗位膨胀 |
| 管理经理的经理 | 4-7 名直接下属 | > 8：无法为经理提供支持。< 3：层级过多 |
| VP/总监 | 5-8 名直接下属 | > 10：战略思考受到影响 |

#### 何时增加管理层级

```
TRIGGER: Team growing past threshold
  |
  v
[Current span of control > optimal?]
  |
  +-- NO  --> Don't add layer. Resist the urge.
  +-- YES --> [Is there a strong internal candidate?]
              |
              +-- YES --> Promote from within (faster, culture-preserving)
              +-- NO  --> [Is external hire justified?]
                          |
                          +-- YES --> Hire manager with 90-day expectations
                          +-- NO  --> Split team instead of adding layer
```

#### 组织设计反模式

| 反模式 | 症状 | 解决方案 |
|-------------|---------|-----|
| 头衔膨胀 | 公司只有 20 人，却人人都是“负责人” | 标准化的职级框架 |
| 影子组织 | 真正的决策在正式组织结构之外做出 | 使权限与责任保持一致 |
| 矩阵式混乱 | 每个人都有 3 条汇报线 | 明确唯一的直属经理，并记录虚线汇报关系 |
| 创始人瓶颈 | 所有决策都要经过创始人 | 授权框架（参见 `founder-coach`） |
| 扩张地盘 | 管理者招聘是为了扩大团队，而不是为了交付成果 | 将人员编制与业务成果挂钩 |

### 4. 绩效管理

#### 校准后的绩效框架

| 评级 | 标签 | 目标分布 | 措施 |
|--------|-------|---------------------|--------|
| 5 | 卓越 | 5-10% | 加速晋升、大幅追加股权、留任奖金 |
| 4 | 超出预期 | 20-25% | 高于市场水平的加薪、挑战性任务、导师角色 |
| 3 | 达到预期 | 50-60% | 市场水平调整、发展计划、新挑战 |
| 2 | 需要改进 | 10-15% | 制订包含 60 天里程碑的 PIP，并由经理每周跟进 |
| 1 | 绩效不佳 | 2-5% | 进行离职谈话或立即调整岗位 |

#### 绩效评审节奏

| 活动 | 频率 | 负责人 | 参与者 |
|----------|-----------|-------|-------------|
| 1:1 会议 | 每周 | 经理 | 经理 + 直属下属 |
| 目标检查 | 每月 | 经理 | 经理 + 直属下属 |
| 收集同事反馈 | 每季度 | 人力团队 | 跨职能同事 |
| 绩效评审 | 每半年 | 经理 + 人力团队 | 经理、下属、越级经理 |
| 校准会议 | 每半年 | 人力团队 | 同一职级的所有经理 |
| 晋升委员会 | 每半年 | 人力团队 + 领导层 | 由 L4+ 领导者组成的委员会 |

#### PIP（绩效改进计划）结构

| 要素 | 要求 |
|---------|-------------|
| 具体差距 | 可观察的行为，而非含糊的批评 |
| 可衡量的目标 | 3-5 个包含成功标准的目标 |
| 时间线 | 最长 30-60 天 |
| 提供的支持 | 培训、辅导、资源 |
| 检查频率 | 至少每周一次 |
| 明确的结果 | 达成目标与未达成目标时分别会发生什么 |
| 文档记录 | 书面记录、签字并归档 |

### 5. 留任策略

#### 留任风险评估矩阵

| 因素 | 低风险 (1) | 中等风险 (2) | 高风险 (3) |
|--------|-------------|-----------------|----------------|
| 薪酬竞争力 | 高于 P50 | 达到 P50 | 低于 P50 |
| 与经理的关系 | 高度信任 | 尚可 | 存在摩擦或不信任 |
| 职业发展 | 路径清晰、进展顺利 | 路径存在、进展缓慢 | 没有可见的路径 |
| 敬业度 | eNPS 高、积极倡导 | 中立 | 缺乏投入、态度消极 |
| 任职时长 | < 1 年或 > 3 年 | 1-2 年 | 18-24 个月（悬崖风险） |
| 外部需求 | 市场需求低 | 中等 | 市场火热、招聘人员积极接触 |

**总分 6-8**：低风险。每季度监测。
**总分 9-13**：中等风险。需要主动开展留任谈话。
**总分 14-18**：高风险。需要立即干预。

#### 留任干预阶梯

```
Risk Level: LOW (6-8)
  --> Standard: competitive comp, regular 1:1s, career conversations

Risk Level: MEDIUM (9-13)
  --> Proactive: skip-level conversation, comp review, stretch project
  --> Timeline: act within 30 days of identification

Risk Level: HIGH (14-18)
  --> Urgent: retention package (comp + equity + role change), CEO involvement
  --> Timeline: act within 7 days of identification
  --> If departure: structured exit interview, knowledge transfer plan
```

## 危险信号

- 离职率激增，且离职面谈中反复提到同一名管理者 -- 这是管理者问题，而非文化问题
- 薪酬区间超过 18 个月未更新 -- 既失去候选人，又留住了不合适的人
- 没有职业发展阶梯 -- 顶尖员工会在 18-24 个月时离职
- 在没有书面岗位评分卡的情况下招聘 -- 决策不一致，存在偏见风险
- 绩效评估每年仅进行一次 -- 问题会持续恶化
- 股权刷新仅限高管 -- 关键 IC 将面临离职风险
- 关键岗位的招聘周期 > 90 天 -- 流程存在问题或薪酬不合理
- eNPS 低于 0 -- 这是结构性问题，而非士气问题
- 员工少于 50 人时，IC 与 CEO 之间超过 3 个组织层级 -- 管理过度
- HR 团队配比 > 1:100（人员过少）或 < 1:40（人员过多）-- 应合理调整职能规模
- 除入职第 1 天外，没有结构化的入职流程 -- 90 天内离职率将激增

## 主动触发条件

检测到以下情况时，无需询问，主动提示：

- 关键员工即将进入股权悬崖期，且没有股权刷新计划——存在留任风险，需立即采取行动
- 已有招聘计划，但尚未定义薪酬区间——将导致支付过高薪酬或错失候选人
- 团队规模增长至 25-30 人以上，但尚未设置管理层级——组织压力迫在眉睫
- 没有绩效评审周期——低绩效员工的问题会被掩盖，顶尖员工会离职
- 遗憾离职率 > 10%——必须进行离职面谈分析
- 经理与 IC 的比例超出 1:5-1:10 范围——需要审查组织结构
- 任何领导岗位都没有继任计划——存在单点故障风险
- Offer 接受率降至 75% 以下——薪酬或流程存在问题

## 故障排除

| 问题 | 可能原因 | 解决方法 |
|---------|-------------|-----|
| 离职率激增，且离职面谈中反复提到同一位经理 | 这是经理问题，而非文化问题 | 调查该经理的具体情况；提供辅导或进行人员调整 |
| 薪酬区间已有 18 个月以上未刷新 | 市场已经发生变化；正在错失候选人，并留住不合适的员工 | 参照 Levels.fyi/Pave/Radford 进行基准评估；热门岗位的薪酬区间应每季度更新 |
| 顶尖员工在入职 18-24 个月后离职 | 没有职业阶梯；股权悬崖期临近，但没有股权刷新计划 | 建立标准明确的职业阶梯；实施年度股权刷新计划 |
| Offer 接受率降至 75% 以下 | 薪酬不合理、流程过慢或候选人体验较差 | 审查 Offer 被拒的原因；进行薪酬基准评估；衡量从面试到发出 Offer 的时间 |
| 绩效评审每年只进行一次，问题不断积累 | 评审频率过低；缺乏持续反馈文化 | 实施每周 1:1、每月目标检查和每半年一次的正式评审 |
| eNPS 降至 0 以下 | 这是结构性问题，而非一次士气事件 | 按部门和经理深入分析调查结果；解决根本原因 |

## 成功标准

- 非自愿遗憾离职率的年化值低于 10%（每月衡量，每季度向董事会报告）
- eNPS 得分高于 30（每季度调查，参与率达到 80% 以上）
- 关键岗位的招聘周期少于 45 天（从招聘需求开放到候选人接受录用通知）
- 录用接受率高于 85%（在 ATS 中跟踪，每月审查）
- 90% 以上的员工处于其薪酬区间内（每季度通过 comp_band_analyzer.py 衡量）
- 内部晋升率高于 25%（晋升人数 / 岗位填补总数）
- 不发生任何未启动继任计划的关键人员离职（retention_risk_scorer.py 识别风险）

## 范围与局限性

**范围内**：人员规划、薪酬设计、组织结构、绩效管理、留任策略、职业发展阶梯、人才分析、人员编制建模、薪酬区间分析。

**范围外**：劳动法建议、移民手续办理、薪资发放运营、福利管理、工伤赔偿申请、工会谈判、员工个人辅导。

**局限性**：留任风险评分依赖管理者评估，而这可能存在偏见。薪酬区间分析使用所提供的市场数据——其准确性取决于基准数据的质量。人员编制规划器采用线性成本预测，未考虑签约奖金、搬迁费用或浮动薪酬。薪酬公平性分析需要性别/人口统计数据，而这些数据可能无法获得。
