# 第一性原理

剥离假设的约束，还原为有独立依据的基本要素，然后重建。当惯例失效，或其代价看似被人为抬高时，跳出类比。

## 何时使用

- 某项约束被当作固定不变（“太贵”、“不可能”、“一直都是这么做的”）来对待，却没有独立依据支撑。
- 惯例或类比已经失效、停滞，或只能产生效果有限的增量变体。
- 从零开始的全新设计，此时行业默认做法可能夹带虚假需求。
- 成本或可行性主张建立在定价、先例或权威之上，而非物理、数学或实测需求。

## 何时不使用

- 该约束是已验证的物理规律、硬性法规或实测容量 → 接受它并在其范围内优化。
- 已有经过验证的标准库、协议或已知良好的模式能够适用 → 直接使用；不要重新推导。
- 时间紧迫的事件处置 → 先按最可能的原因采取行动；将第一性原理重建留给事后重设计。
- 对正常运行系统的增量打磨，且没有虚假约束信号 → 跳过。

## 流程

1. **陈述问题与所声称的约束。** 列出每一条被视为固定的限制（成本、规模、技术栈、流程、“必须使用 X”）。
2. **对每条约束分类。** 标记为 `physics/math`、`regulation/contract`、`measured fact` 或 `convention/analogy/authority`。除非有证据将某条惯例升级，否则仅将前三类视为有约束力的限制。
3. **分解为基本要素。** 必需的输入、守恒/复杂度边界、真正不可协商的项。要求独立依据（测量、推导、一手需求）——而非供应商定价或竞争对手先例。
4. **丢弃缺乏依据的假设。** 为每个惯例标签给出一个证伪手段。丢弃或重新协商任何缺乏依据的内容。
5. **仅从剩余的基本要素重建。** 满足有约束力限制、忽略人为限制的最简方案。优先选用通用化输入和更少的活动部件，而非依赖类比。
6. **验证并停止。** 对照真实物理规律、合同和实测需求进行检验。定义成本最低的证伪测试。当存在一个连贯的重建加上有区分力的验证，或只剩下已验证的硬约束时，即停止。

## 输出

输出一份第一性原理重建：

- `claimed_constraints`：带分类标签的约束清单
- `primitives`：仅有独立依据的事实
- `discarded_assumptions`：被丢弃的惯例及原因
- `rebuild`：仅由基本要素推导出的方案
- `binding_residuals`：仍然生效的真实限制
- `kill_test`：成本最低、能够证伪该重建的检验

## 验证

- **独立性检查：** 每个基本要素都必须援引测量、推导或一手需求——不能仅凭先例。
- **不得夹带类比：** 如果重建在没有基本要素支撑的情况下仍依赖“别人怎么做”，就把它剥离。
- **约束诚实性：** 已验证的物理规律/法规必须保留；不要凭主观意愿将其抹除。
- **过度应用防护：** 如果在已验证约束下标准方案已是最优，不要为了求新而重建。
- **停止：** 完成一轮分解 → 分类 → 重建 → 证伪测试；没有新证据就不要递归。
