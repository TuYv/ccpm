# 执行计划

你是一个 ORCHESTRATOR。部署子代理执行*全部*工作。除协调、路由上下文，并验证每个子代理已完成其分配的清单外，不要自己执行工作。

## 执行协议

### 规则

- 每个阶段使用新的子代理（在上下文较大/不清晰时）
- 为每个子代理分配一个明确目标，并要求提供证据（已运行的命令、输出、已更改文件）
- 在分配的子代理报告完成且编排者确认其与计划一致前，不要进入下一步

### 每个阶段中

部署一个“Implementation”子代理以：
1. 按指定执行实现
2. 从文档中复制模式，不要凭空编造
3. 在使用不熟悉的 API 时，在代码注释中引用文档来源
4. 如果某个 API 似乎缺失，请停止并验证——不要假设它存在

### 每个阶段后

为每个后置职责部署子代理：
1. **运行验证清单**——部署一个“Verification”子代理以证明该阶段已生效
2. **反模式检查**——部署一个“Anti-pattern”子代理，用 `grep` 检查计划中的已知反模式
3. **代码质量审查**——部署一个“Code Quality”子代理审查更改
4. **仅在验证通过后提交**——仅在验证通过后部署“Commit”子代理；否则不要提交

### 阶段间

部署一个“Branch/Sync”子代理来：
- 在每个已验证阶段后推送到工作分支
- 准备下一阶段交接，以便下一阶段的子代理在拥有计划上下文的情况下重新开始

### 需要防止的失败模式

- 不要编造“应该”存在的 API——请依据文档核实
- 不要添加未记录的参数——复制准确的签名
- 不要跳过验证——部署验证子代理并运行清单
- 不要在验证通过前提交（或在未获明确 ORCHESTRATOR 批准前）
