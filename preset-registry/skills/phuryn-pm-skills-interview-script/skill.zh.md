## 客户访谈脚本

创建一份结构化的访谈脚本，挖掘真实洞察，而不仅仅是观点。遵循“妈妈测试”（The Mom Test）原则——询问他们的生活，而不是你的想法。

### 领域背景

客户访谈是持续发现过程中 **第 1 阶段（探索）** 的一种信息来源。其他信息来源包括：利益相关者访谈、使用分析、数据分析、调查、市场趋势、SEO/SEM 分析。PM 需要直接接触用户、利益相关者、工程师和设计师——“不通过代理人”。**产品三人组**（PM + 设计师 + 工程师——Teresa Torres）应该共同开展发现工作，而不只是由 PM 单独完成。

### 上下文

你正在为针对 **$ARGUMENTS** 的研究准备一份客户访谈脚本。

如果用户提供了文件（用户画像、假设列表、产品简介或过往访谈笔记），请先阅读这些文件。

### 指令

1. **明确研究目标**：
   - 团队需要获得哪些具体问题的答案？
   - 这项研究将为哪些决策提供依据？
   - 哪些假设需要验证？

2. **创建访谈脚本**，包含以下部分：

   ### 开场（2-3 分钟）
   - 介绍自己和访谈目的（学习，而不是销售）
   - 设定预期：“没有正确或错误的答案。我们希望从你的经历中学习。”
   - 征得录音许可（如适用）
   - 确认可用时间

   ### 热身：背景与上下文（5 分钟）
   - “请介绍一下你的角色，以及你典型的一天/一周是什么样的。”
   - “你从事[与产品领域相关的活动]有多久了？”
   - 目标：建立融洽关系并了解对方的背景

   ### 核心探索：待完成的工作（15-20 分钟）

   **当前情况与行为**（使用过去时，询问具体实例）：
   - “请带我回顾一下你上一次[完成我们正在探索的事情]的经历。发生了什么？”
   - “你使用了哪些工具或方法？”
   - “花了多长时间？还有谁参与其中？”

   **痛点与挫折**（观察，不要引导）：
   - “那件事最困难的部分是什么？”
   - “如果你可以挥一挥魔法棒，你希望改变什么？”
   - “你尝试过什么方法来解决这个问题？结果如何？”

   **期望结果**（使用他们的措辞，而不是你的措辞）：
   - “对你来说，在这个领域中，‘做得好’是什么样的？”
   - “你如何判断这件事是否运行良好？”

   **付费意愿 / 优先级**（切身投入）：
   - “你目前在这件事上花费了多少时间/金钱？”
   - “你是否寻找过更好的解决方案？找到了什么？”
   - “如果能解决这个问题，你愿意放弃什么？”

   ### 追问技巧
   当你发现一个有趣的线索时，可以使用以下问题：
   - **“再详细说说。”**——引导对方展开任何话题
   - **“为什么？”**（温和地询问 2-3 次）——找到根本原因
   - **“你能举一个具体的例子吗？”**——从观点转向事实
   - **“接下来发生了什么？”**——跟随故事继续追问
   - **“这让你有什么感受？”**——捕捉情绪强度

   ### “妈妈测试”规则
   - 询问**他们的生活**，而不是你的想法
   - 询问**过去**，而不是未来（“你会使用 X 吗？”毫无用处）
   - **少说多听**——目标是达到 80/20 的比例
   - 访谈过程中**绝不推销**
   - 关注**强烈情绪**——它们表示真实的痛苦或愉悦
   - **赞美是噪音**——“听起来很酷！”什么信息也无法告诉你

### 总结（3-5 分钟）
   - “还有什么我没问到，但你认为很重要的吗？”
   - “还有谁是我应该就此事进行交流的吗？”
   - 感谢他们抽出时间
   - 分享后续步骤（如有）

3. **自定义脚本**：根据具体的产品领域、用户角色和研究目标调整问题。根据可用的访谈时长，添加或删除部分内容。

4. **包含一份记录笔记模板**：
   ```
   Participant: [Name / ID]
   Date: [Date]
   Key Jobs: [What they're trying to accomplish]
   Current Solution: [What they use today]
   Biggest Pain: [Their #1 frustration]
   Desired Outcome: [What success looks like]
   Willingness to Pay: [How much they invest / would invest]
   Surprise Finding: [Something unexpected]
   Follow-up: [Next steps]
   ```

保存为 markdown。包括脚本和记录笔记模板。
