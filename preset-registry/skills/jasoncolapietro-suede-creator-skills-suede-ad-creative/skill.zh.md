# Suede 广告创意

使用 Suede 效果型创意系统生成可测试的标题、描述、主要文案和视觉概念，然后根据真实的效果数据进行迭代。

## 开始之前

**先检查产品营销背景：**
如果 `.agents/product-marketing.md` 存在（或者是 `.claude/product-marketing.md`，或在较旧的设置中使用旧版文件名 `product-marketing-context.md`），请先阅读，然后再提问。使用其中的背景信息，只询问尚未涵盖或与当前任务具体相关的信息。

收集以下背景信息（如果用户未提供，请提问）：

### 1. 平台与格式
- 使用什么平台？（Google Ads、Meta、LinkedIn、TikTok、Twitter/X）
- 使用什么广告格式？（搜索 RSAs、展示广告、社交信息流、快拍、视频）
- 是要迭代现有广告，还是从头开始？

### 2. 产品与优惠
- 你要推广什么？（产品、功能、免费试用、演示、获客磁铁）
- 核心价值主张是什么？
- 与竞争对手相比，有哪些差异化之处？

### 3. 受众与意图
- 目标受众是谁？
- 处于什么认知阶段？（问题认知、解决方案认知、产品认知）
- 哪些痛点或愿望会驱动他们？

### 4. 效果数据（如需迭代）
- 当前正在投放哪些创意？
- 哪些标题/描述表现最好？（CTR、转化率、ROAS）
- 哪些表现不佳？
- 已测试过哪些角度或主题？

### 5. 约束条件
- 是否有品牌语调指南或需要避免使用的词语？
- 是否有合规要求？（行业法规、平台政策）
- 是否有任何必备元素？（品牌名称、商标符号、免责声明）

## 此技能的工作方式

此技能支持四种模式：

### 模式 1：从头生成
从头开始时，根据产品背景、受众洞察和平台最佳实践，生成一整套广告创意。

### 模式 2：根据效果数据进行迭代
当用户提供效果数据（CSV、粘贴内容或 API 输出）时，分析哪些内容有效，识别高表现内容中的模式，并围绕获胜主题生成新的变体，同时探索新的角度。

核心循环：

```
拉取效果数据 → 识别获胜模式 → 生成新的变体 → 验证规格 → 交付
```

### 模式 3：大规模静态批次（有依据）
对于定期、大批量制作静态广告（例如每批 50 个概念），请基于**有依据的输入语料库**和[静态广告模板库](references/static-ad-templates.md)开展工作。每个概念都必须能追溯到真实的源材料——请参阅下方的“有依据的输入”。如需按日或按周运行此流程，请将生产循环交由 `suede-marketing-loops` 处理。如需提交批次供客户或利益相关者审批，请生成[创意评审页面](references/creative-review-page.md)。

### 模式 4：创意策略循环
用于在制作广告之前决定**哪些广告值得制作**：综合三类信号来源（账户效果、客户语言、外部自然流量），生成按证据排序的概念；根据账户状态（探索期与扩量期）调整创意组合；维护一份经过产能检查的路线图，并进行每月复盘，为下一轮创意计划提供输入。完整系统位于[创意路线图](references/creative-roadmap.md)；如需在任何模式中生成钩子并诊断漏斗阶段，请加载 [hook-system.md](references/hook-system.md)。

## 有依据的输入

大多数 AI 广告生成失败的原因在于输入缺乏依据，而不是输出质量不高：缺乏依据的生成会基于训练数据产出听起来合理的广告，而不是基于真正能为该品牌带来转化的内容。对于规模化生产（模式 3），请维护一个持久的输入素材库：

```
inputs/
  winning-ads/   过去 90 天内表现最好的广告截图 10-20 张
  reviews/       50-100 条客户评价（Trustpilot、G2、Amazon、App Store），格式为 .md/.txt
  comments/      现有广告活动中的热门评论 — 异议、用户主动给予的好评、客户提出的角度
brand/           品牌语调文档、十六进制颜色值、徽标、产品/截图素材
outputs/         按日期命名的批次文件夹（outputs/YYYY-MM-DD/）
```

**每种输入的重要性：**
- **Winning ads** 包含已经为该品牌验证有效的钩子、结构和角度
- **Reviews** 包含买家描述痛点、转变和意外收益时使用的确切语言 — 直接逐字从中提取文案，而不是进行改写
- **Ad comments** 是最容易被忽略、但价值最高的输入：异议（“但它对 X 有效吗？”）会转化为 FAQ 卡片广告，而用户主动给予的好评则会挖掘出你未曾撰写的角度

**依据规则：**
- 每个创意都要注明其来源（对应的评价、获胜广告或评论）
- 绝不编造声明、统计数据或推荐语
- 如果 `inputs/winning-ads/` 或 `inputs/reviews/` 为空，请停止并要求用户先填充内容再生成。不要将生成缺乏依据的创意作为备用方案。
- 输入会逐渐失效：随着新广告规模化投放，及时更新 `inputs/winning-ads/`；每月更新 `inputs/reviews/` 和 `inputs/comments/`

## 平台规格

平台会拒绝或截断超出这些限制的创意，因此在交付前请确认每条文案都符合要求。

### Google Ads（响应式搜索广告）

| 元素 | 限制 | 数量 |
|---------|-------|----------|
| 标题 | 30 个字符 | 最多 15 个 |
| 描述 | 90 个字符 | 最多 4 个 |
| 显示网址路径 | 每段 15 个字符 | 2 段路径 |

**RSA 规则：**
- 标题必须单独成立，并且在任意组合中都有意义
- 仅在必要时将标题固定到特定位置（会降低优化空间）
- 至少包含一个以关键词为重点的标题
- 至少包含一个以利益点为重点的标题
- 至少包含一个 CTA 标题
- 上述数量是 Google 规定的上限。当请求通过 `suede-ads` 提交时，其 RSA 输出规格要求完整提供 15 个标题和 4 条描述 — 必须全部交付。

### Meta Ads（Facebook/Instagram）

| 元素 | 限制 | 备注 |
|---------|-------|-------|
| 主要文本 | 可见部分 125 个字符（最多 2,200 个字符） | 将钩子放在前面 |
| 标题 | 建议 40 个字符 | 位于图片下方 |
| 描述 | 建议 30 个字符 | 位于标题下方 |
| URL 显示链接 | 40 个字符 | 可选 |

### LinkedIn Ads

| 元素 | 限制 | 备注 |
|---------|-------|-------|
| 引导文本 | 建议 150 个字符（最多 600 个字符） | 位于图片上方 |
| 标题 | 建议 70 个字符（最多 200 个字符） | 位于图片下方 |
| 描述 | 建议 100 个字符（最多 300 个字符） | 在部分展示位置中显示 |

### TikTok Ads

| 元素 | 限制 | 备注 |
|---------|-------|-------|
| 广告文本 | 建议 80 个字符（最多 100 个） | 位于视频上方 |
| 展示名称 | 40 个字符 | 品牌名称 |

### Twitter/X Ads

| 元素 | 限制 | 备注 |
|---------|-------|-------|
| Tweet 文本 | 280 个字符 | 广告文案 |
| 标题 | 70 个字符 | 卡片标题 |
| 描述 | 200 个字符 | 卡片描述 |

有关详细规格和格式变体，请参阅 [references/platform-specs.md](references/platform-specs.md)。

## 生成广告视觉素材

**对于静态广告结构**，请使用 [references/static-ad-templates.md](references/static-ad-templates.md) 中的 15 个模板库——其中包含布局框架（我方 vs. 竞品、数据强调、评价卡片、前后对比、创始人寄语、FAQ 卡片等）、文案槽位、DTC 和 SaaS 示例，以及每个概念的输出格式。请轮流使用全部 15 个模板，而不是反复使用偏爱的模板：模板多样性就是角度多样性。

**当概念是 iOS 原生的揭示视频时**——例如 iMessage 对话、ChatGPT 答案、Apple Notes 自白或 AirDrop 分享，且屏幕界面本身就是广告——请在编写脚本前阅读 [references/imessage-video-ads.md](references/imessage-video-ads.md)。其中涵盖界面选择、概念角度、节奏规则、制作路径，以及戏剧化对话的合规规则。

**当概念是无真人出镜的动态/解释型视频时**（15–45 秒，由生成静帧 → image-to-video 动效 → TTS → 字幕组成），请在编写提示词前阅读 [references/motion-video-ads.md](references/motion-video-ads.md)。其中涵盖制作流程、包含填空式提示词公式的视觉风格库、品牌槽位契约，以及质量检查中的常见问题。

**当你需要选择图像、视频、语音或基于代码的生成工具时**——或需要为批量制作估算价格时——请阅读 [references/generative-tools.md](references/generative-tools.md)。该文档负责维护供应商列表、各广告位的图像规格和成本比较；这些信息会过时，因此请使用其中的数据，而不是凭记忆引用数字。

**规模化制作的推荐工作流程：**
1. 使用 AI 工具生成主视觉素材（用于探索，追求高质量）
2. 基于获胜模式构建 Remotion 模板
3. 使用数据源通过 Remotion 批量生成变体
4. 迭代——使用 AI 探索新角度，使用 Remotion 实现规模化

## 生成广告文案

### 第 1 步：定义你的角度

在撰写单条标题之前，先确定 3–5 个独特的**角度**——也就是促使某人点击的不同理由。每个角度都应触发不同的动机。

**常见角度类别：**

| 类别 | 角度示例 |
|----------|---------------|
| 痛点 | “停止在 X 上浪费时间” |
| 结果 | “在 Z 天内实现 Y” |
| 社会证明 | “加入 10,000+ 个已经……的团队” |
| 好奇心 | “顶尖公司使用的 X 秘密” |
| 对比 | “不同于 X，我们做到 Y” |
| 紧迫感 | “限时：免费获得 X” |
| 身份认同 | “为[特定角色/类型]打造” |
| 反常识 | “为什么[常见做法]不起作用” |

### 第 2 步：为每个角度生成变体

对于每个角度，生成多个变体。调整以下方面：
- **措辞** — 同义词、主动语态与被动语态
- **具体程度** — 数字与笼统表述
- **语气** — 直接陈述、提问与命令
- **结构** — 简短有力的表达与完整的收益陈述

达到一定数量（10 个以上的变体）后，进行一次自由发挥：针对没人要求过的角度提出 3-5 个概念——反主流、情绪化、具体到令人不适。这些往往是不走寻常路的创意来源，但会额外消耗一次迭代。

### 第 3 步：根据规范进行验证

交付前，检查每条创意是否符合平台的字符限制。标记超出限制的内容，并提供精简后的替代版本。

### 第 4 步：整理以便上传

按照广告平台的上传要求，以结构化格式呈现创意。

## 根据效果数据进行迭代

当用户提供效果数据时，遵循以下流程：

### 第 1 步：分析优胜者

查看表现最好的创意（根据 CTR、转化率或 ROAS——询问哪个指标最重要），并识别：

- **获胜主题** — 哪些主题或痛点出现在表现最好的创意中？
- **获胜结构** — 疑问句？陈述句？命令句？数字？
- **获胜词汇模式** — 哪些单词或短语反复出现？
- **字符利用率** — 表现最好的创意更短还是更长？

### 第 2 步：分析落败者

查看表现最差的创意，并识别：

- **表现不佳的主题** — 哪些角度没有引起共鸣？
- **低表现创意中的常见模式** — 太泛泛？太长？语气不对？

明确指出表现不佳的创意，并说明该角度为何失败。不要一开始就称赞现有创意集，也不要在声明的指标已经以足够的数据量得出结论后，将失败的角度委婉地说成“需要进一步测试”——要明确说它失败了，并弃用该角度。

### 第 3 步：生成新的变体

创作新的广告文案，要求：
- **加倍投入**获胜主题，但使用全新的措辞
- 将获胜角度**延展**为新的变体
- **测试** 1-2 个尚未探索的新角度
- **避免**表现不佳创意中出现的模式

### 第 4 步：记录迭代

记录已获得的经验以及正在测试的内容：

```
## Iteration Log
- Round: [number]
- Date: [date]
- Top performers: [list with metrics]
- Winning patterns: [summary]
- New variations: [count] headlines, [count] descriptions
- New angles being tested: [list]
- Angles retired: [list]
```

## 写作质量标准

### 能带来点击的标题

**优秀标题：**
- 具体（“将报告耗时缩短 75%”）胜过笼统（“节省时间”）
- 收益（“更快交付代码”）胜过功能（“CI/CD pipeline”）
- 主动语态（“自动生成报告”）胜过被动语态（“报告实现自动生成”）
- 尽可能加入数字（“快 3 倍”、“5 分钟内完成”、“10,000+ 个团队”）

**避免：**
- 受众无法理解的术语
- 缺乏具体性的断言（“最佳”、“领先”、“顶尖”）
- 全部大写或过度使用标点符号
- 落地页无法兑现的标题党内容

**绝不要发布这些字符串。** 它们是模型在没有提示时默认生成的广告文案，在每个产品、每个品类中都千篇一律——这正是广告位被浪费的定义。修正方式始终相同：使用基础输入中的具体数字、具体动词或具体客户原话进行替换。如果一个标题同样适用于竞争对手的产品，那么它就是这些字符串中的一种伪装形式。

- “释放你的潜力” / “释放……的力量” / “释放……” / “彻底革新你的……” / “改变你[工作/构建/销售]的方式”
- “告别[问题]” / “还在为[问题]烦恼吗？”
- “提升你的[事物]” / “让你的[事物]更上一层楼”
- “游戏规则改变者” / “革命性的” / “尖端的” / “无缝的” / “毫不费力地”
- “只需几分钟” / “只需几秒钟”（除非这是经过测量且真实的数字）
- “[类别]的未来已经到来” / “加入数千名……的行列”（没有真实数量时）
- “详细了解我们的解决方案” / “了解我们如何提供帮助”

### 能够带来转化的描述

描述应该补充标题，而不是重复标题。使用描述来：
- 添加证明性信息（数字、客户评价、奖项）
- 处理反对意见（“无需信用卡”，“小型团队永久免费”）
- 强化 CTA（“立即开始免费试用”）
- 在确有其事时增加紧迫感（“仅限前 500 名注册用户”）

## 输出格式

### 标准输出

按角度组织，并附上字符数：

```
## Angle: [Pain Point — Manual Reporting]

### Headlines (30 char max)
1. "Stop Building Reports by Hand" (29)
2. "Automate Your Weekly Reports" (28)
3. "Reports Done in 5 Min, Not 5 Hr" (31) <- OVER LIMIT, trimmed below
   -> "Reports in 5 Min, Not 5 Hrs" (27)

### Descriptions (90 char max)
1. "Marketing teams save 10+ hours/week with automated reporting. Start free." (73)
2. "Connect your data sources once. Get automated reports forever. No code required." (80)
```

### 批量 CSV 输出

大规模生成时（10 个以上变体），提供 CSV 格式以便直接上传：

```csv
headline_1,headline_2,headline_3,description_1,description_2,platform
"Stop Manual Reporting","Automate in 5 Minutes","Join 10K+ Teams","Save 10+ hrs/week on reports. Start free.","Connect data sources once. Reports forever.","google_ads"
```

### 静态批量输出（模式 3）

对于大规模静态批次，将内容保存到带日期的文件夹中，并附带索引：

```
outputs/YYYY-MM-DD/
  INDEX.md        # every concept: template type + grounding source, scannable in 2 min
  concepts/       # one .md per concept: headline, body, visual description, image prompt, grounding
  images/         # generated images, if an image tool is configured
```

每个概念的格式定义见 [references/static-ad-templates.md](references/static-ad-templates.md)。支持的人工工作流程是：打开文件夹，浏览 INDEX.md，在其中挑选最适合测试的 5-10 个——从 50 个概念中选出 5 个优胜者，比从 10 个概念中选出 5 个，能产出更好的创意。

### 创意审阅页面（客户 / 利益相关者审批）

当需要由不是你的人来审阅并挑选内容时——例如客户、合作伙伴或利益相关者——生成一个**创意审阅页面**：这是一个自包含的 HTML 工件，将每个概念呈现为信息流中的平台模拟界面（Instagram/Facebook，并带有白名单账号切换功能），将轮播图拆分为带标签的逐帧故事板，允许他们切换标题/文案变体，并披露哪些内容基于真实素材。这是 INDEX.md 的视觉升级版：通过一个链接即可完成决策，而不必阅读 markdown。模板位于 [assets/creative-review-template.html](assets/creative-review-template.html)（单文件、无需构建、可托管在任意位置）；请使用生成的概念填充其 `DATA` 对象。完整的数据模型、依据规则（披露区块为必需项）和交付方式见 [references/creative-review-page.md](references/creative-review-page.md)。

### 迭代报告

进行迭代时，请包含摘要：

```
## Performance Summary
- Analyzed: [X] headlines, [Y] descriptions
- Top performer: "[headline]" — [metric]: [value]
- Worst performer: "[headline]" — [metric]: [value]
- Pattern: [observation]

## New Creative
[organized variations]

## Recommendations
- [What to pause, what to scale, what to test next]
```

## 交付前自检

每种模式在交付任何内容前都必须通过这一关。这不是特定于某种模式的要求，也不是可选项。

- [ ] 每个标题和描述都以内联形式显示其字符数
- [ ] 没有任何变体超过其平台的限制——任何超出的内容都必须裁剪，并显示裁剪后的版本
- [ ] 每个 RSA 中至少包含 2-3 个 CTA 标题
- [ ] 没有两个变体使用相同的角度；删除近似重复项
- [ ] 每个 Mode 3 概念都注明其依据来源（哪条评价、哪条高表现广告或哪条评论）
- [ ] 上述 Never-ship 列表中的任何字符串都没有出现在任何变体中
- [ ] 没有任何内容明显可能违反目标展示位的平台政策

任何一项失败都意味着必须先修复再交付。不要在注明失败项作为附带说明的情况下交付一批内容。

## 常见错误

- **撰写只有组合在一起才有效的标题**——RSA 标题会被随机组合
- **所有变体听起来都一样**——要改变角度，而不只是措辞
- **没有 CTA 标题**——RSA 需要面向行动的标题来推动点击；至少包含 2-3 个
- **描述泛泛而谈**——“详细了解我们的解决方案”浪费了这个位置
- **一次测试太多内容**——每个测试周期只改变一个变量
- **过早停用创意**——在做出判断前，至少允许获得 1,000 次展示

## 工具集成

此工具包不提供广告平台连接器或 CLI 包装器。只能使用用户授权的平台 UI、导出功能、API 或已安装的连接器，并在构建调用之前核实当前的官方平台文档。

对于以效果为导向的一批内容：

1. 读取或导出指定日期范围和账户范围内当前的广告级效果数据。
2. 将平台、账户、货币、归因窗口和指标定义与数据一并记录。
3. 分析模式，然后在此 skill 中生成可追溯的变体。
4. 将广告系列、预算、受众或上传决策转交给 `suede-ads`。
5. 将激活视为在完成渲染审查之后的独立授权操作。

## 边界

- 不得虚构产品能力、客户评价、效果数字、紧迫感或平台原生证明。
- 未获得明确授权且未完成最终渲染审查前，不得上传、发布、激活创意或为创意支出费用。
- 不得生成替代版 Suede S；需要使用 Suede 品牌标志时，只能使用获批准的规范标志。
- 不得仅凭品味决定创意胜者；应使用已声明的指标、受众、支出和测试窗口。

## 路由

- 需要广告系列结构、定向、预算或优化 -> 使用 `suede-ads`。
- 需要统计有效的创意测试 -> 使用 `suede-ab-testing`。
- 需要来自客户的原始语言 -> 使用 `suede-customer-research`。
- 需要落地页文案或周期性生产 -> 使用 `suede-copy` 或 `suede-marketing-loops`。
- 在任何变体面向真实用户上线之前 -> 使用 `suede-deslop`。
- 从这些技能中，将付费媒体创意生产路由回 `suede-ad-creative`。
