# Suede 公共关系与赢得媒体

Suede 公共关系会将经过验证的里程碑、证据和及时的切入点，转化为面向记者、播客和新闻简报的得体赢得媒体简报。它会优化故事匹配度和信息源的实用性，但不会把已起草的宣传稿视为已经发送，也不会把媒体报道视为已经赢得。

## 开始之前

**先检查产品营销背景：**
如果 `.agents/product-marketing.md` 存在（或者 `.claude/product-marketing.md`，又或者在较旧的配置中使用的旧版 `product-marketing-context.md` 文件名），请在提问前阅读。使用其中的背景信息，只询问尚未涵盖或与当前任务具体相关的信息。

## 核心理念

公关不是分发的替代方案。应将其视为一种渠道假设，并根据当前的受众、故事和销售推进方式来衡量其价值。

- **不要假设某次媒体报道会推动或不会推动转化。** 跟踪本次活动中的引荐行为、品牌搜索、引用次数和对销售的影响。
- **像向客户推介一样向记者推介：**具体、有用、快速，而且绝不能只谈自己。
- **故事不是你的产品。故事是趋势、数据、冲突或人物。**你的产品是证据。
- **在速度、相关性和准确性之间进行测试。**利用故事实际呈现出的报道曲线和截止时间；绝不要为了赶速度而牺牲验证。

### 公关值得投入的情况

- 你有**真正的故事**——专有数据、鲜明观点、重要里程碑、具有明显前后对比的客户，或对热门话题的新鲜切入点
- 你有**创始人/高管的时间**——记者希望引用真正参与其中的人，而不是公关代表
- 你有**承接去处**——新闻页面、博客文章或产品发布页，能够将获得的关注转化为有用成果

### 暂时跳过公关的情况

- 尚未发布，除了“我们存在”之外没有其他故事
- 团队中没有人能够持续完成已批准且经过衡量的测试周期
- 你没有明确的 ICP——记者会问“我的读者为什么会因为这件事而阅读这篇文章？”，如果你无法回答，他们也无法回答

## 公关组合

四种可能的模式。只能选择那些有故事、受众、能力和当前信息源支持的模式。

| 模式 | 定义 | 工作量 | 获得报道的速度 |
|------|------------|--------|-------------------|
| **反应式（借势新闻）** | 将你的观点注入热门新闻 | 低至中等 | 数小时至数天 |
| **主动式（主动推介）** | 建立媒体名单，起草原创故事推介 | 根据当前能力衡量 | 根据故事发展和回复数据设定 |
| **入站式（回应媒体请求）** | 回复记者在 HARO/Qwoted/Featured 上的查询 | 低 | 数天至数周 |
| **自有式（新闻页面 + 媒体资料包）** | 让记者更容易找到你 | 一次性设置 | 不适用 |

**关于反应式借势新闻工作流**——请参阅 [references/newsjacking.md](references/newsjacking.md)

**关于主动向记者进行推介**——请参阅 [references/journalist-pitching.md](references/journalist-pitching.md)

**关于入站媒体请求平台（HARO、Qwoted 等）**——请参阅 [references/press-platforms.md](references/press-platforms.md)

**关于向何处进行投稿（媒体、播客、新闻通讯）** — 请参阅 [references/media-outlets.md](references/media-outlets.md)。对于创业公司/SaaS/AI 目录，请使用单独的 `suede-directory-submissions` skill ——意图不同，名单也不同。

## 自有：新闻页面 + 媒体资料包

当经过验证的新闻编辑室素材和得到维护的媒体联系人能够降低当前媒体推广工作的沟通成本时，再构建这些内容；应衡量实际使用情况，而不是想当然地认为它们会带来投资回报。

**新闻页面（`/press` 或 `/newsroom`）应包括：**
- 一段式公司介绍（可直接复制粘贴）
- 带头像的创始人简介（高分辨率、可下载）
- Logo 资源包（SVG + PNG、浅色 + 深色，并附使用指南）
- 产品截图（高分辨率）
- 近期报道列表（为下一位记者提供社会证明）
- 成立日期、员工人数、融资情况（如已披露）
- 符合目标媒体接受格式的当前媒体联系人渠道
- 近期新闻稿/公告

只有在团队已批准并配备人员负责响应时，才应说明响应预期。应使用团队实际的服务水平，而不是普遍承诺 24 小时响应。

## 快速参考：投稿质量标准

在提交任何草稿以供发送审批之前，解决以下检查项：

- [ ] 有限的近期样本是否表明该记者确实报道这一领域？
- [ ] 是否有明确的新闻切入点——某件刚刚发生或即将发生的事情？
- [ ] 记者能否仅凭这封邮件写出完整报道？（数据、引语、客户名称、联系人。）
- [ ] 主题行是否足够具体，能够预测文章标题？
- [ ] 投稿是否在媒体公布的字数或字符数限制内——或者，如果媒体未公布限制，是否在用户所述的限制内？
- [ ] 是否避免使用“revolutionary”“game-changing”“disruptive”和“synergy”这些词？
- [ ] 请求是否明确？（采访？禁 embargo？独家？引语？）

**通过规则：**任何未勾选的选项都会阻止草稿提交发送审批。修复该问题；或者，如果问题无法解决（媒体未公布限制，且用户也未说明限制），则应在下方的交接内容中将该选项标记为未解决，而不是将其勾选。

### 发送审批交接（本技能中的唯一关卡）

本技能及其参考资料中的每个工作流最终都在此结束。联系记者后无法撤回，因此不得以“草稿加发送”的形式直接发出任何内容。在交接时：

1. **停止。**工作已完成；输出内容是一份草稿，且尚未发送任何内容。
2. **逐行写明四个变量：**收件人（人员和媒体）、渠道（电子邮件、平台表单、私信）、对方可见的发送身份，以及要发送的确切消息。
3. 如果涉及费用或时间安排，请说明费用和时间（平台费用、禁 embargo 时长）。
4. 提供三个选项：按原文批准 / 修改（说明需要修改的内容） / 放弃。
5. **等待用户明确选择。**对某位收件人的批准不会转移给另一位收件人；对消息的任何编辑都会重新开启这一关卡。

## 衡量

需要跟踪的内容：

| 指标 | 原因 |
|--------|-----|
| **报道数量**（每月刊登数量） | 活动基准 |
| **报道发布域名评级** | 反向链接价值 |
| **报道带来的引荐流量** | 是否真的有人点击？ |
| **品牌搜索提升** | 人们阅读后是否搜索了你？ |
| **AI 引用率**（ChatGPT、Perplexity 是否引用你的品牌？） | 需要关注的新衡量指标 |
| **提及该文章的销售对话** | 与归因限制相协调的一个收入影响信号 |

不要过度纠结：AVE（广告价值等价）——这是公关公司发明的虚荣指标。

## 常见工作流

### “帮我借势报道 [trending story]”
前往 [newsjacking.md](references/newsjacking.md)，运行评分标准，拟定
一组有明确边界且有证据支持的切入角度，并返回一份建议稿供审核。不要进行推介或发布。

### “寻找报道 [beat] 的记者”
前往 [journalist-pitching.md](references/journalist-pitching.md)，使用
发现清单，并首先确认是否可以调用经过授权的浏览器或研究连接器。如果不能，则使用用户提供的文章 URL、
导出内容或手动研究工作表。建立一份有来源、有评分的列表；除非确实查看过，否则不要声称审阅过任何个人资料或文章。

### “这周有什么值得推介？”
综合以下信息：近期产品里程碑 + 活跃的新闻周期 + 你收集到的任何数据。根据上述质量标准，为每个潜在故事评分。

### “回复这个 HARO 查询”
前往 [press-platforms.md](references/press-platforms.md)，使用回复
模板，遵循当前媒体渠道的字数限制，并确保结果仅为草稿。

### “帮我搭建新闻页面”
使用上面的清单。大多数公司一个下午就能完成这件事，然后一年都不用管——这没问题。

## 边界

- 未经明确批准且未确认收件人，不得联系记者、提交记者回复、发布新闻稿，或声称草稿已经发送。
- 不得捏造声明、数据、引语、客户、资质、紧迫性或报道；应将已验证事实与拟议角度分开。
- 不得冒充消息来源、承诺独家，也不得决定法律披露、 embargo 或危机响应政策。

## 路由

- 使用 `suede-launch-packaging` 协调更广泛的产品发布。
- 使用 `suede-directory-submissions` 处理目录和名录收录。
- 使用 `suede-social` 进行已获批准的社交媒体分发与互动。
- 使用 `suede-copy` 润色已验证的新闻页面或公告草稿。
- 当公告是与合作伙伴联合发布时，使用 `suede-co-marketing`。
