# 依赖升级器

**目标：** 以小规模、可归因的批次升级依赖项。保留清单文件、锁文件、运行时支持和产品行为；如果没有兼容性、安全性或维护方面的依据，不要认为较新的版本本身就有价值。

**执行约定：** 将下方按顺序排列的复选框工作流视为此技能的完成定义。按顺序完成每一项，并且仅在其操作及所需证据均已完成时，才将其标记为完成。`N/A`、已跳过、不可用或已委派的项目仍视为未完成。
返回前，对每个未完成项目应用此技能的裁定、决策和审批规则，并在回复开头添加 **检查清单：已完成 X/Y 项**<br>**未完成：无 | 章节/项目 — 原因；对结果的影响；确切的下一步操作**；列出每个未完成项目。

## 工具选择

| 需求 | 首选工具 | 使用时机 | 后备方案 |
|---|---|---|---|
| 包管理器检测 | 清单文件、锁文件、工作区文件、运行时文件和仓库说明 | 始终在选择命令或更新范围之前使用 | 构建和 CI 配置 |
| 过时和存在漏洞的软件包 | 原生包管理器的过时检查和审计命令 | 管理器和注册表可用时 | 官方注册表、供应商公告和锁文件检查 |
| 破坏性变更和支持情况 | 官方发行说明、迁移指南、变更日志、公告和运行时支持表 | 每次进行有重大影响的次要版本更新、主要版本更新、替换或安全更新时 | 主要来源的仓库发行版；否则标记为 `UNVERIFIED` |
| 使用情况和影响范围 | 语言服务器或宿主原生代码智能工具 | 更新后的 API、类型、插件、构建工具或运行时可能影响使用方时 | 有针对性地搜索导入、符号、配置和脚本 |
| 安全的版本变更 | 原生包管理器命令 | 更新清单文件和生成的锁定状态时 | 不要手动编辑锁文件或模拟软件包解析 |
| 验证 | 仓库定义的安装、还原、构建、代码检查、类型检查、测试、迁移和冒烟测试命令 | 变更前以及每个批次完成后 | 检查 CI 和脚本，并明确标注未验证状态 |
| 差异和回滚 | Git 状态、差异以及隔离的提交或工作树 | 保护用户变更，并且仅还原失败的批次时 | 如果无法安全地隔离批次，则停止 |

绝不发布软件包、轮换凭据、部署，或削弱审计和验证关卡。对于来自不受信任软件包源的生命周期脚本，如果没有环境的常规安全防护措施，请勿运行。

## 证据规则

- 清单文件和锁文件定义了实际安装的内容；注册表中的“最新”版本不能凌驾于项目运行时或兼容性约束之上。
- 漏洞发现必须包含受影响的版本、公告、可达性或暴露上下文，以及可信的修复措施。
- 破坏性变更声明必须有与确切版本迁移相匹配的发行说明或迁移证据。
- 仅当生成的锁文件变更由选定的原生包管理器及仓库预期版本生成时，才予以保留。
- 升级成功需要通过仓库验证，而不能仅以安装或还原成功为依据。

## 检查清单

### 1. 明确范围并保护工作区

- [ ] 检测所有包管理器、工作区、清单、锁文件、集中式版本文件、注册表、运行时版本固定配置、工具清单以及生成的依赖文件。
- [ ] 将每个可交付成果分类为应用程序、库、插件、CLI、容器或构建工具，以便正确解读版本范围、锁文件、对等依赖约束以及受支持运行时承诺。
- [ ] 阅读仓库说明，并确定受支持的包管理器版本、更新命令、锁文件策略以及 CI 预期。
- [ ] 检查 Git 状态并隔离工作，确保用户现有的更改不会被覆盖，也不会被误认为升级产生的输出。
- [ ] 建立由本次运行拥有的资源台账，记录创建的每个绝对路径、工作树、进程 ID、缓存、报告和临时产物；绝不将预先存在的资源登记为清理目标。
- [ ] 明确请求的范围：仅安全更新、常规补丁或次要版本维护、选定的软件包、主要版本、运行时迁移或全面更新。
- [ ] 在编辑之前，获取安装或还原、构建、代码检查、类型检查、测试、冒烟测试以及安全审计的基线。
- [ ] 记录预先存在的失败、公告、弃用项、对等依赖冲突以及不受支持的运行时组合。

### 2. 调研并规划批次

- [ ] 使用原生的过时依赖检查和审计命令，在不更改文件的情况下盘点直接依赖和相关传递依赖的更新。
- [ ] 将移除项、安全修复、常规更新、主要版本变更、构建工具变更以及运行时或生态系统迁移分别归类。
- [ ] 查阅官方发布说明和迁移指南，了解 API 变更、配置变更、默认值、对等依赖约束、运行时支持以及已移除的行为。
- [ ] 解析环境标记、扩展功能、可选组/开发组、对等依赖、目标框架以及平台特定的软件包；当项目承诺支持更广泛的环境矩阵时，仅能在当前机器上解析成功的依赖图并不足够。
- [ ] 查阅官方安全公告，了解受影响的版本范围、利用条件、修复版本、变通方案，以及该依赖在此项目中是否可达。
- [ ] 针对每个影响重大的依赖，搜索其实际导入、符号、插件、脚本、配置、生成的代码以及运行时加载情况。
- [ ] 将未使用、重复、已弃用、已被替代或平台冗余的依赖识别为单独的移除候选项；要求提供运行时和动态加载证据，并且当移除操作超出请求的升级范围时，须获得用户的明确批准。
- [ ] 按先决条件安排批次顺序：包管理器或运行时、构建工具、基础库、框架、集成组件，最后是叶子软件包。
- [ ] 将常规批次控制在足够小的规模，以便定位失败原因；仅当兼容性矩阵有此要求时，才将框架系列、分析器、生成的客户端或约束紧密的对等依赖归入同一批次。
- [ ] 当互斥的版本策略、运行时支持、许可、注册表策略或迁移范围会改变产品意图时，暂停并请求用户指示。

### 3. 安全地应用每个批次

- [ ] 使用原生包管理器，按照仓库预期的版本和标志更新清单及锁文件。
- [ ] 当请求范围较小时，避免进行大范围的重新解析，除非包管理器无法安全地保留锁定图；说明不可避免的变动。
- [ ] 当安全风险需要时，检查安装脚本、注册表来源、校验和、包来源以及非预期新增的传递依赖包。
- [ ] 根据文档所述的破坏性变更，更新所需的导入、API、类型、配置、构建脚本、插件、生成的客户端和应用程序代码。
- [ ] 仅当已接受的行为、前置条件、配置或命令发生变化时，才更新用户或运维人员文档。
- [ ] 立即检查差异，查找无关的格式变更、被删除的约束、注册表漂移、行尾变动、生成的产物和意外降级。
- [ ] 检查解析后的依赖图，查找新增的重复主版本、不满足或被静默忽略的对等依赖、发生变化的可选功能，以及会改变运行时行为的传递依赖替换。
- [ ] 不要在没有证据的情况下抑制警告、禁用审计、跳过必需的检查、强制固定不兼容的对等依赖，或添加兼容性变通方案。

### 4. 验证并保留或还原

- [ ] 从足够干净的状态运行安装或还原，以证明锁文件可复现。
- [ ] 在每个批次之后运行相关的构建、代码检查、类型检查、单元测试、集成测试、冒烟测试、打包、迁移和应用程序启动检查。
- [ ] 根据需要将受影响的运行时、目标框架、操作系统、架构和功能组合归类为必需或可选；只有当每个必需组合都有本地或可信 CI 证据时，才保留该批次；当必需覆盖范围没有可信的替代验证方案时，返回 `BLOCKED`。
- [ ] 验证通用测试可能无法覆盖的已变更 API、插件、序列化器、构建输出和运行时路径。
- [ ] 当更新的依赖项可能对包体积、启动时间、产物或性能指标产生实质性影响时，比较这些指标。
- [ ] 重新运行安全审计，并区分已修复、仍存在、新引入、不可达以及无修复方案的安全公告。
- [ ] 仅当验证通过且预期行为仍受支持时，才保留该批次。
- [ ] 在不触碰用户工作的情况下还原整个失败批次，记录造成阻塞的包或迁移，并且仅继续处理相互独立的安全批次。
- [ ] 在应用下一个批次之前，将保留的依赖状态确立为基线。
- [ ] 将每个计划批次归类为：已应用并验证时标记为 `KEPT`；应用后因验证失败而完全回滚时标记为 `REVERTED`；因必需的决策、兼容性策略或独立前置条件尚未解决而有意不应用时标记为 `SKIPPED`。

### 5. 完成并报告

- [ ] 对合并后的保留状态运行仓库要求的完整验证。
- [ ] 确认清单、锁文件、运行时版本固定设置、CI、容器、文档和生成的元数据与最终版本一致。
- [ ] 仅移除本次运行所拥有的台账条目：验证绝对路径仍位于获准的临时根目录内，停止记录的确切进程 ID，保留脏工作树或预先存在的工作树，并保留有意在报告中列出的证据产物。
- [ ] 列出有意跳过的包，并注明确切的约束、风险、安全公告或迁移原因。
- [ ] 报告直接依赖和重要传递依赖的变更、移除项、代码迁移、安全公告、验证结果、锁文件变动以及剩余的维护风险。
- [ ] 当请求的每个保留批次都通过必需验证时，使用 `UPDATED`；当至少保留一个独立批次，而另一个批次被还原、跳过或仍有可选覆盖范围未验证时，使用 `PARTIAL`；当未保留任何批次且已恢复基线时，使用 `NO_CHANGE`；当没有任何安全批次可以继续，或无法进行必需验证时，使用 `BLOCKED`。

## 输出约定

```markdown
# Dependency Upgrade

**Verdict:** UPDATED | PARTIAL | NO_CHANGE | BLOCKED

## Scope and baseline
- Package managers, workspaces, and runtime constraints
- Requested update policy
- Pre-existing verification and advisories

## Batches
| Batch | Packages | Version changes | Decision | Verification |
|---|---|---|---|---|
| ... | ... | ... | KEPT / REVERTED / SKIPPED | ... |

## Security and compatibility
- Fixed, remaining, and introduced advisories
- Breaking changes and code migrations
- Runtime, peer, and registry constraints

## Final verification and residual risks
Commands, results, skipped packages, limitations, and follow-up decisions.

## Evidence artifacts
Run-owned paths and hashes for manifests, lockfiles, exact commands, final diff, rollback, and cleanup proof.
```
