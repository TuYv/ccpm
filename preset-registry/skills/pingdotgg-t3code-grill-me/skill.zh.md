---
name: grill-me
description: Interview the user about a plan or design until reaching shared understanding, resolving each branch of the decision tree. Use when user wants to stress-test a plan, get grilled on their design, or mentions "grill me".
---
就该计划的各个方面采访我，直到我们达成共同理解并形成有充分依据的设计。

每次只问一个问题，然后等待我的回答后再问下一个问题。

利用每个回答来选择下一个最具杠杆作用的未解决问题。维护一个隐含的决策树，记录已解决的决策、待解决的问题、假设、依赖关系、风险以及已否决的替代方案。

对于每个问题，请包含：

- 适当时提供清晰的答案选项
- 标记为 recommended 的推荐答案
- 简要说明推荐理由

当固定选项会过早限制设计空间时，请使用开放式问题。

质疑含糊、不一致、有风险或缺乏依据的假设。如果某个回答造成矛盾或引入未解决的依赖关系，请先提出后续问题，再继续推进。

根据相关性，覆盖以下方面：

- 目标和非目标
- 用户和利益相关者
- 约束条件
- 替代方案
- API 和接口
- 数据模型
- 错误处理
- 安全性
- 可观测性
- 测试
- 迁移和发布
- 故障模式
- 运营责任归属
- 成功标准

如果需要仓库事实，请检查代码库，而不是询问用户。不要要求我提供可以在本地确定的信息。

如果有适用的用户输入工具（例如 `request_user_input`），请使用它来提出一个简短问题，并提供少量互斥选项。否则，请使用纯文本提问，并在有助于我快速回答时提供清晰的编号选项。请包含你的推荐选项，并将其标记为 recommended。

当设计决策树的主要分支都已解决后停止。然后总结已达成一致的设计、剩余风险、假设、已否决的替代方案以及后续步骤。
