# learn

通过收集在线资源并创建针对 RAG 优化的索引，研究任意主题并生成全面的学习指南。

## 解析参数

```javascript
const args = '$ARGUMENTS'.split(' ').filter(Boolean);
const depth = args.find(a => a.startsWith('--depth='))?.split('=')[1] || 'medium';
const topic = args.filter(a => !a.startsWith('--')).join(' ');
```

## 输入

参数：`<topic> [--depth=brief|medium|deep]`

- **topic**：要研究的主题（必填）
- **--depth**：资源收集深度
  - `brief`：10 个来源（快速概览）
  - `medium`：20 个来源（默认，兼顾广度与深度）
  - `deep`：40 个来源（全面研究）

## 研究方法

基于以下最佳实践：
- Anthropic 的上下文工程
- DeepLearning.AI 的工具使用模式
- Anara 的 AI 文献综述

### 1. 渐进式查询架构

使用漏斗式方法，避免冗长的查询列表产生噪声：

**宽泛阶段**（梳理全貌）：
```
"{topic} overview introduction"
"{topic} documentation official"
```

**聚焦阶段**（核心内容）：
```
"{topic} best practices"
"{topic} examples tutorial"
"{topic} site:stackoverflow.com"
```

**深入阶段**（高级内容，仅当 depth=deep 时）：
```
"{topic} advanced techniques"
"{topic} pitfalls mistakes avoid"
"{topic} 2025 2026 latest"
```

### 2. 来源质量评分

多维度评估（最高分：100）：

| 因素 | 权重 | 最高分 | 标准 |
|--------|--------|-----|----------|
| 权威性 | 3x | 30 | 官方文档（10）、公认专家（8）、知名网站（6）、博客（4）、随机来源（2） |
| 时效性 | 2x | 20 | <6 个月（10）、<1 年（8）、<2 年（6）、<3 年（4）、更早（2） |
| 深度 | 2x | 20 | 全面（10）、详细（8）、概览（6）、浅显（4）、片段（2） |
| 示例 | 2x | 20 | 多个代码示例（10）、一个示例（6）、无示例（2） |
| 独特性 | 1x | 10 | 独特视角（10）、部分重叠（6）、内容重复（2） |

**选择阈值**：按分数选取前 N 个来源（N = 深度对应的目标数量）

### 3. 即时检索

不要预先加载所有内容（会导致上下文腐化）：

1. 首先通过 WebSearch **收集 URL**
2. **根据元数据评分**（标题、描述、URL）
3. 仅通过 WebFetch **获取入选来源**
4. **提取摘要**（而非完整内容）

### 4. 内容提取指南

对于每个来源，提取：

```json
{
  "url": "https://...",
  "title": "Article Title",
  "qualityScore": 85,
  "scores": {
    "authority": 9,
    "recency": 8,
    "depth": 7,
    "examples": 9,
    "uniqueness": 6
  },
  "keyInsights": [
    "Concise insight 1",
    "Concise insight 2"
  ],
  "codeExamples": [
    {
      "language": "javascript",
      "description": "Basic usage pattern"
    }
  ],
  "extractedAt": "2026-02-05T12:00:00Z"
}
```

**版权合规**：仅提供摘要和洞见，绝不逐字引用段落。

## 自我评估清单

在最终确定之前，对输出进行评分（1-10）：

| 指标 | 问题 | 目标 |
|--------|----------|--------|
| 覆盖度 | 指南是否涵盖主要方面？ | ≥7 |
| 多样性 | 来源类型是否多样？ | ≥6 |
| 示例 | 代码示例是否实用？ | ≥7 |
| 准确性 | 对内容准确性的信心如何？ | ≥8 |

**标记缺漏**：注明任何未涵盖的重要子主题。

## 错误处理

| 错误 | 操作 |
|-------|--------|
| WebSearch 失败 | 使用更简单的查询重试 |
| WebFetch 超时 | 跳过该来源，并在元数据中注明 |
| 找到的来源少于 <minSources | 警告用户，并使用现有来源继续 |
| 增强失败 | 跳过，并在输出中注明 |
| 索引不存在 | 创建新索引 |

## Token 预算

各阶段的预估 Token 使用量：

| 阶段 | Token 数 | 说明 |
|-------|--------|-------|
| WebSearch 查询 | ~2,000 | 5-8 次查询 |
| 来源评分 | ~1,000 | 仅元数据 |
| WebFetch 提取 | ~40,000 | 20 个来源 × 平均 2,000 |
| 综合整理 | ~10,000 | 生成指南 |
| 增强 | ~5,000 | 两次 Skill 调用 |
| **总计** | ~60,000 | 在 opus 预算范围内 |
