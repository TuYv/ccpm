# 技能名称

清晰、简洁地描述此技能涵盖的内容以及何时使用它。此描述会显示在技能发现过程中，应帮助智能体（和人类）判断此技能何时适用。

**重要提示**：为获得最佳性能，请将 SKILL.md 正文总长度控制在 500 行以内。将详细的参考资料移至 `references/` 目录中的单独文件。

每个技能正文都必须明确其职责边界。描述和`何时激活`部分应说明此技能负责什么，以及相邻技能负责哪些相关工作。这可以防止宽泛的技能抢占本应由更具体的技能触发的激活机会。

## 何时激活

描述应激活此技能的具体情形、任务或上下文。既要包括直接触发因素（特定关键词或任务类型），也要包括间接信号（表明此技能相关的更广泛模式）。

使用第三人称编写。该描述会被注入系统提示词，视角不一致可能会导致技能发现问题。

- 推荐："处理 Excel 文件并生成报告"
- 避免："我可以帮助你处理 Excel 文件"

为相邻技能添加一个简短的“不要激活”部分。示例：

- 不要因项目级流水线结构而激活：`project-development`。
- 不要因单个工具的模式设计而激活：`tool-design`。

## 核心概念

解释此技能涵盖的基础概念。这些是该技能所传授的心智模型、原则或框架。

默认假设：Claude 已经非常聪明。只添加 Claude 尚不了解的上下文。审视每一条信息：
- “Claude 真的需要这段解释吗？”
- “我可以假设 Claude 已经知道这些吗？”
- “这一段的价值足以抵偿其 token 成本吗？”

优先采用能够改变行为的机制，而非一般性背景信息。如果某个概念应在整个语料库中复用，请在 `researcher/mechanisms/registry.jsonl` 中添加或更新一条记录。

## 详细主题

### 主题 1

详细解释第一个主要主题。包括具体技术、模式或方法。使用示例阐释概念。

### 主题 2

详细解释第二个主要主题。根据需要继续添加其他主题。

对于较长的主题，可以考虑将内容移至 `references/` 并添加链接：
- 有关完整实现，请参阅[详细参考资料](./references/topic-details.md)

## 实践指南

提供应用此技能的可执行指导。包括常见模式、需要避免的反模式，以及用于在不同方法之间进行选择的决策框架。

根据任务的脆弱程度确定具体指导的详细程度：
- **高自由度**：多种方法均有效，决策取决于上下文
- **中等自由度**：存在首选模式，可接受一定变化
- **低自由度**：操作容易出错，必须遵循特定顺序

实践指南应当能够由智能体直接执行，例如工作流、检查清单、决策表或具体操作规则。如果某个部分仅解释历史或动机，请将其移至 `references/`。

## 示例

提供具体示例来说明技能的应用。示例应展示前后对比、演示正确用法，或说明如何处理边界情况。

使用输入/输出对以提高清晰度：

**示例：**
```
Input: [describe input]
Output: [show expected output]
```

## 指南

列出应用此技能时应遵循的具体指南。这些指南应是可检查或验证的可操作规则。

1. 指南一，包含具体且可验证的标准
2. 指南二，包含明确的成功条件
3. 根据需要继续添加

## 注意事项

列出从实践经验中总结出的失败模式、常见错误和反直觉行为。这些是任何技能中信息价值最高的内容。每个注意事项都应具体、可操作，并且不与技能正文中已有的指导内容重叠。使用编号格式：

1. **简短的描述性标题**：用一到两句话说明会出现什么问题以及如何预防。
2. **另一个注意事项标题**：描述失败模式以及应采取的替代做法。

## 集成

说明此技能如何与该集合中的其他技能集成。以纯文本形式（而非链接）列出相关技能，以避免跨目录引用问题：

- skill-name-one - 简要描述关联关系
- skill-name-two - 简要描述关联关系

该集合中的相关技能：

- 研究论文、文档或指南
