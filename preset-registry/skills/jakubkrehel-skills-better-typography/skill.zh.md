# 排版

排版主要在于克制：合理的比例、舒适的间距，以及足够的对比度。标签、表格单元格、营销标题和文章段落不应遵循同一套规则。

审查时，应阅读渲染后的页面，而不是扫读代码。糟糕的换行、孤行和截断只有在真实内容长度下才会显现。

每项修复都应使用项目的样式系统，并使用下面给出的准确值，而不是看似相近的常见等效值。[速查表](css-cheat-sheet.md)将每个声明映射到对应的 Tailwind 写法。

文字内容本身属于 `better-writing`。语义化标题结构属于 `better-accessibility`。空间上的 RTL 布局和逻辑属性属于 `better-layout`。对比度测量属于 `better-colors`。本技能负责文本在混合方向内容中的渲染、换行和表现方式。

## 使用正确的格式

在 Web 上使用 `.woff2`，以获得 Brotli 压缩和广泛支持。`.woff` 是针对非常老旧浏览器的回退格式。`.ttf` 和 `.otf` 是不支持 Web 压缩的桌面格式。文件如何加载属于项目自身的职责。

## 优先使用属性，而不是原始标签

当存在对应的 CSS 属性时，应使用它。使用 `font-weight: 650`，而不是 `font-variation-settings: "wght" 650`。使用 `font-optical-sizing: auto`，而不是 `"opsz"`。使用 `font-variant-numeric: tabular-nums`，而不是 `font-feature-settings: "tnum" 1`。

当非可变字体回退渲染时，属性仍能继续生效。只有对于没有对应属性的自定义轴（`"GRAD" 80`）和小众特性（`"ss01" 1`），才保留使用原始标签。轴和特性标签列于 [variable-fonts-and-opentype.md](variable-fonts-and-opentype.md)。

## 加载所需的字重和样式

如果当前字体系列不提供所需的字重或样式，浏览器会进行合成，从而扭曲真实字形。应加载设计中实际使用的字形。

`font-synthesis: none` 会关闭合成，但也会抹去强调效果，而不是报告缺失。只有在检查过回退字体栈中的每种必需粗体、斜体、小型大写、上标和下标形式仍然保持差异后，才设置它。

## 减少字体、字号和字重

很少需要使用超过三种字体。字重和字号定义层级；过度使用会迅速损害可读性。应通过对比进行搭配，而不是追求相似：衬线标题搭配无衬线正文会显得经过刻意设计，而两种几乎相同的无衬线字体则会显得像是错误。

低于 `18px` 时，应保持字重为 `400` 或更重。低于 `300` 的字重仅适用于 `28px` 及以上的展示文本；在正文大小下会消失。字体搭配指南见 [choosing-fonts.md](choosing-fonts.md)。

## 使用带语义名称的字号比例

定义一小组字号，并尽可能少地偏离它。没有系统支撑的硬编码字号在规模扩大后会逐渐失效。

独自开发时，只要使用规则明确，使用 `text-sm` 这类默认名称即可。在团队中，应根据用途命名字号（如 `text-body-sm`），让规则能够在其他人接手后继续成立。比例构建方式见 [spacing-and-sizing.md](spacing-and-sizing.md)。

## 标题字号应随层级递减

将标题层级映射到字号比例中递减的步阶，确保视觉上从属的标题不会压过其父级标题。在字号比例较小的一端，相邻层级可以共用字号，只要通过字重或间距使它们保持区分即可。语义元素属于 `better-accessibility`；本技能只设置视觉呈现。

## 按角色设置行高

标题使用更紧凑的行高，约为 `1.1`。正文使用 `1.5` 到 `1.6`。优先使用无单位值，这样行高会随字号缩放；固定的 `24px` 则不会。

紧凑的行高适用于短文本。任何换行后达到三行或更多的文本，行高至少需要 `1.4`，即使是在高度受限的行中也是如此。

## 按字号设置字间距

大标题通常使用略微为负的字间距会更好看。小号大写标签需要稍微增加字间距，否则字母会显得拥挤。阅读字号的正文不需要调整字间距。

## 限制每行长度

过长的行会让眼睛难以找到下一行。将长篇文本限制在每行约 60–75 个字符。只要设置了限制并且行长落在这个范围内，使用任何单位都可以。参见[单位选择及其对应的像素值](wrapping-and-punctuation.md#measure-line-length)。

## 有意识地控制换行

四个声明，各司其职：

- `text-wrap: balance` 会将文本均匀分配到各行。用于标题。
- `text-wrap: pretty` 会避免单个较短的单词落在最后一行。用于描述文本。
- 对于可能超出容器的长单词、链接或 ID，使用 `overflow-wrap: break-word`。
- 对于换行后看起来不对的标签和徽章，使用 `white-space: nowrap`。

在长篇文本中跳过 `balance` 和 `pretty`。

## 对会变化的值使用表格数字

数字默认具有不同的宽度，因此计时器、计数器和价格在更新时会使布局发生偏移。对任何会变化的值应用 `font-variant-numeric: tabular-nums`。

## 截断内容但不丢失信息

对于单行文本，使用 `text-overflow: ellipsis`，并配合 `overflow: hidden` 和 `white-space: nowrap`。对于多行文本，使用 `line-clamp`。截断会隐藏内容。当缺失的文本很重要时，应通过工具提示或展开视图确保用户仍能访问完整值。

## 自然地撰写文案，用 CSS 控制样式

以自然大小写存储文本，并使用 `text-transform` 控制呈现方式，这样重新设计时就不必重写文案。

在渲染的文本中使用智能标点：

- 正文中使用弯引号，代码中使用直引号。
- 表示范围时使用 en dash：`2010–2020`。
- 使用单个省略号字符，而不是三个句号。
- 使用 `&nbsp;` 让 `16 px` 在换行时保持在一起。
- 使用 `&shy;` 指定长单词可以在哪里换行。

## 从字体中获取下划线样式

默认下划线的位置由浏览器决定。使用 `text-underline-position: from-font` 和 `text-decoration-thickness: from-font`，从字体自身的度量信息中获取位置和粗细。使用 `text-decoration-thickness`、`text-underline-offset` 和 `text-decoration-skip-ink` 手动调整。

`text-decoration-style` 可以绘制点状、虚线或波浪线。点状下划线通常用于提示某个词包含额外信息，例如缩写或定义过的术语。

在真正的下划线中，只有颜色能够可靠地进行动画处理。因此，除非唯一需要动画的部分是颜色，否则应将下划线构建为独立元素，而不要使用 `text-decoration`。

## 移动端使用 16px 的输入框

当输入框中的文本小于 `16px` 时，iOS Safari 会缩放整个页面。有两种修复方式可以将字号保持为 `16px`，但它们呈现出的效果不同，因此需要确认设计需要哪一种：

- 在移动端放大输入框的字号（`text-base sm:text-sm`）。这会改变它在小屏幕上的外观。
- 保持 `font-size: 16px`，并使用 `transform: scale()` 渲染出预期字号，同时补偿宽度和 `line-height`。在每个视口中保持一致，但需要维护更多代码。

两种方案都在 [details-and-accessibility.md](details-and-accessibility.md) 中。

## 字号与对比度下限

将长篇正文的字号从浏览器默认值 `16px` 开始。只有在能明确说明原因时才偏离这一默认值：字体本身显得偏小、文本宽度较窄，或产品是高密度的专业工具。

UI 文本可以更小。输入框和菜单可以从 `14px` 开始，说明文字可以使用 `13px`，极少低于 `12px`。但在移动端，输入框仍需要使用 `16px`。

当文本看起来对比度不足时，使用 `better-colors` 测量渲染后的颜色组合，并使用 `better-accessibility` 判断要求。除非有人明确要求，否则不要改动颜色。

## 根元素上的字体平滑

在 macOS 上，文本渲染出来会比预期更粗。在根布局上统一应用一次 `-webkit-font-smoothing: antialiased` 和 `-moz-osx-font-smoothing: grayscale`，不要在各个组件上分别应用。Tailwind 的 `antialiased` 同时涵盖两者。

## 语言与双向文字行为

设置 `lang`，让浏览器和辅助技术选择正确的发音、引号和断字方式。在文档级别或方向发生变化的内容边界处设置 `dir`。保留数字顺序，并使用 `<bdi>` 隔离混合方向的值。空间镜像和逻辑 CSS 属性属于 `better-layout`。

## 保持有用文本可选中

默认保持文本可选中。只要选中后的组合仍然清晰易读，`::selection` 就可以将品牌风格延伸到阅读体验中。

`user-select: none` 应用于可拖动或由手势驱动的表面，在这些场景中意外选中文本会造成干扰。不要在整个界面中使用，也不要仅仅因为按钮标签可以被高亮选中就使用它。

## 完成前检查

| 错误 | 修复 |
| --- | --- |
| 合成字体与设计不一致 | 加载真实字体；仅禁用已验证的合成模式 |
| 子标题在视觉上压过了父标题 | 将该部分的层级映射到逐级递减的字号阶梯 |
| 因为默认字号而选择标题元素 | 先选择语义，再在 CSS 中设置字号 |
| 段落最后一行出现孤行 | `text-wrap: pretty` |
| 两行标题左右失衡 | `text-wrap: balance` |
| 在界面中使用两端对齐文本 | 使用 `text-align: start`；将两端对齐保留给特定的编辑类布局 |
| 下划线穿过降部 | `text-decoration-skip-ink: auto`，使用 `from-font` 度量值 |
| 混合方向的值以错误顺序渲染 | 修正 `lang`/`dir`；使用 `<bdi>` 隔离该值 |
| 在应用界面中禁用了文本选择 | 恢复文本选择；仅在文本选择会干扰拖动或手势时抑制它 |
| 带有额外信息的提示没有视觉提示 | 通过 `text-decoration-style: dotted` 添加点状下划线 |
| `14px` UI 文本使用 Thin/Light 字重 | `18px` 以下使用 `400`+ 字重；细字重仅用于展示性文本 |
| 在三行卡片描述上使用 `leading-none` | 对任何会换行成 3 行或更多行的文本，至少使用 `1.4` 行高 |

## 报告

**严重程度。** `HIGH` 表示文本无法阅读，或内容被截断且无法恢复。`MEDIUM` 表示破坏类型系统或标题层级。`LOW` 表示局部的润色问题。

**验证。** 无浏览器时：检查每个标题级别的计算尺寸和字重，并确认其按降序排列；检查声明的行高和度量宽度；根据实际的字符串长度检查截断规则。使用浏览器时：调整视口大小，以便在真实内容长度下发现换行、孤行和截断问题。将所有无法运行的检查报告为 `Not verified`。

**格式。** 按每个问题违反的原则分组，按严重程度排序；每个根本原因占一行，并列出其出现的所有位置：

| 严重程度 | 位置 | 修改前 | 修改后 | 原因 |
| --- | --- | --- | --- | --- |

`Location` 的格式为 `path/to/file:line`。`Why` 需要说明违反的原则及其对用户的影响。

当仍有任何 `HIGH` 问题时，以 `Block` 结尾；否则以 `Approve` 结尾；其余问题保留在表格中作为待处理事项。不要批准任何未检查的覆盖范围。如果没有需要报告的内容，请说明“没有可采取行动的排版问题”，并报告验证结果。
