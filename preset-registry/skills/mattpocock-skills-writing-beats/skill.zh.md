<what-to-do>

用户已提供（或将要提供）一份原始 Markdown 材料。此时是**探索**阶段：已完成素材梳理、素材池已固定——请在其中选定一条路径，并开采素材池来补齐每个节拍。

如果用户未说明文章要保存到哪里，请先提问一次并记住该路径。

然后进行逐节拍（beat-by-beat）的创作旅程，采用“选路冒险”模式：

1. **明确先决条件。** 在任何节拍之前，先和用户确认读者进入时已有哪些知识——那些从一开始就已**落地**的概念。其他内容必须先在某个节拍中落地，之后后续节拍才能使用它们。参见[基础概念](#grounding)。
2. 写出 2–3 个候选**起始节拍**，这些节拍需来自原始材料。每个节拍都应是文章的不同切入点。每个节拍只能依赖已落地的概念；并标注各自会落地哪些新概念。将这些节拍先展示给用户再写入文章文件。用户进行选择。预览该选择会解锁哪些后续节拍——就像用户先看到一段前方路径。
3. 用户选定起始节拍后，只将**该节拍**写入文章文件。一个节拍可是一句或多段，取决于该节拍的自然边界。此处暂停。
4. 从磁盘上重新读取文章文件。随后给出 2–3 个候选**下一节拍**，即从当前文章状态可转向的方向。每个节拍都必须从当前已落地集合可达，并注明其会落地哪些概念。
5. 重复步骤 3–5，直到文章自然收束。

## Grounding

每个**概念**在可被节拍使用前必须先被**落地**：读者要么一开始就知道它，要么在先前节拍中遇到它。一个倚重未落地概念的节拍会让读者迷失——这就是旅程无法继续的那一步。单位是“概念”，而不是该概念的词汇：节拍即便没有术语化表达，也仍可能倚赖读者缺失的想法。若一个概念有名称——即一个**术语**——则落地意味着同时让思想与术语都对齐。

一个概念有两种落地方式：

- **先决条件**：在第一节拍前已落地，由读者预先具备。起点固定。
- **已引入**：在某节拍中建立，之后该节拍到后续节拍都视为已落地。

因此每个节拍有两个任务：它**依赖**此前已落地的概念，并**落地**新的概念。持续维护一份已落地概念清单，每当一个节拍完成都更新该清单。

这就是“选路冒险”的核心。候选节拍仅在其所需条件全部已落地时才可达；选择一个落地了概念 X 的节拍，会解锁所有此前等待 X 的节拍。你在给出后续节拍时，必须确保都能从当前已落地集合可达，并说明每个节拍会落地哪些内容，以便用户看到其解锁路径。

关键在于你把什么设为先决条件、什么放入正文中落地。前置要求过多会把不了解该知识的读者挡在外；过多在正文中落地会让前面的节拍沉重到充满定义。应在确定先决条件时与用户确认，并在遇到诱人的节拍却依赖尚未落地概念时及时调整；解决方案要么是在其前面增加一个落地节拍，要么将该概念提升为先决条件。

## What is a beat

节拍是旅程中的一个动作。它只做一件事——营造场景、阐明观点、抛出问题、插入旁白、转变视角。然后停下来，让读者停在一个下一节拍可以转折的位置。

节拍规模取决于它的需求：

- 如果一切动作只需一句话，就是一句（如“接着三周里什么都没发生。”）。
- 如果需要铺垫，则用一个短段落。
- 如果这个节拍本身是一个独立的小场景、论证或示例，则用多段。

若一个“节拍”需要五段和三个子标题，那它就不是一个节拍——而是两个拼在一起的节拍。应将其拆分。

## Pulling from the pile

从原始素材堆中提取内容来填充每个节拍。你可以改写、拆分、重组或直接引用。素材堆就像一座采石场。

## Ending the journey

当旅程完成时文章结束，而不是等素材堆耗尽。多数素材堆都会剩下一些未使用的碎片，这是正常的；这也是素材量通常大于最终所需内容的意义所在。

## Writing rhythm

- 一次只追加一个节拍。永不提前写下一节拍以外内容。
- 每次写入前都从磁盘重新读取文章文件。完全保留用户修改。
- 若用户对前面的节拍作了实质改动，就据此调整后续内容。
- 若用户说“重写该节拍”或“回去再试一个不同的第 3 节拍”，就按要求执行——就地修改该处，其余内容不变。
