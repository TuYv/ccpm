# Suede 推荐与联盟计划

Suede 推荐机制旨在设计可衡量的客户、联盟和合作伙伴增长闭环，涵盖从激励经济学到归因与欺诈控制的完整流程。它将建模的闭环表现与观测结果分离，并确保激活和奖励发放均经过审批。

## 开始之前

**先检查产品营销背景：**
如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，或者在较旧的设置中使用旧版 `product-marketing-context.md` 文件名），请先阅读，然后再提问。使用其中的背景信息，只询问尚未涵盖或与此任务具体相关的信息。

收集以下背景信息（如果未提供则进行询问）：

### 1. 计划类型
- 客户推荐计划、联盟计划，还是两者都有？
- B2B 还是 B2C？
- 客户平均 LTV 是多少？
- 目前通过其他渠道获得客户的 CAC 是多少？

### 2. 当前状态
- 是否已有推荐/联盟计划？
- 当前推荐率是多少（进行推荐的客户占比）？
- 你尝试过哪些激励措施？

### 3. 产品契合度
- 你的产品是否便于分享？
- 是否具有网络效应？
- 客户是否会自然地谈论它？

### 4. 资源
- 你正在使用或考虑使用哪些工具/平台？
- 推荐激励预算是多少？

## 推荐与联盟的区别

### 客户推荐计划

**适用场景：**
- 现有客户向其社交网络进行推荐
- 具有自然口碑传播能力的产品
- 低客单价或自助式产品

**特点：**
- 推荐人是现有客户
- 一次性或有限次数的奖励
- 信任度较高，规模较小

### 联盟计划

**适用场景：**
- 触达你无法直接接触的受众
- 内容创作者、影响者、博主
- 足以支撑佣金的高客单价产品

**特点：**
- 联盟成员不一定是客户
- 持续性的佣金关系
- 规模较大，信任度不一

## 推荐计划设计

### 推荐闭环

```
触发时刻 → 分享行为 → 被推荐者转化 → 奖励 →（循环）
```

### 第 1 步：确定触发时刻

**高意向时刻：**
- 首次出现“啊哈”时刻之后
- 达成某个里程碑之后
- 获得出色支持之后
- 续费或升级之后

**针对尚未进行推荐的客户的提示节奏：**第 7 天、第 30 天、第 60 天，
以及每次达成里程碑之后。时间安排由此 skill 决定；消息文案则不是——将其交给
`suede-emails`。

### 第 2 步：设计分享机制

**按效果排序：**
1. 产品内分享（转化率最高）
2. 个性化链接
3. 电子邮件邀请
4. 社交分享
5. 推荐码（适用于线下场景）

### 第 3 步：选择激励结构

**单边奖励**（仅奖励推荐人）：更简单，适用于高价值产品

**双边奖励**（双方均获得奖励）：转化率更高，强调双赢

**阶梯式奖励**：让推荐流程游戏化，提高参与度

**有关示例和激励额度**：参见 [references/program-examples.md](references/program-examples.md)

## 计划优化

### 提高推荐率

**如果很少有客户进行推荐：**
- 在更合适的时机发起请求
- 简化分享流程
- 测试不同类型的激励
- 让推荐入口在产品中更加醒目

**如果推荐没有带来转化：**
- 改善被推荐用户的落地体验
- 加大对新用户的激励
- 确保推荐人的背书清晰可见

### 要运行的 A/B 测试

**激励测试：** 金额、类型、单边还是双边、时机

**消息测试：** 计划描述、CTA 文案、落地页文案

**展示位置测试：** 推荐提示出现的位置和时间

### 常见问题与解决方案

| 问题 | 解决方案 |
|---------|-----|
| 知晓度低 | 添加醒目的应用内提示 |
| 分享率低 | 简化为一次点击 |
| 转化率低 | 优化被推荐用户体验 |
| 欺诈/滥用 | 应用以下欺诈控制措施 |
| 推荐人只推荐一次 | 添加分级/游戏化奖励 |

### 欺诈控制

在设计奖励或撰写计划条款之前，请阅读 [references/affiliate-programs.md](references/affiliate-programs.md)
中的§防欺诈部分——其中包含技术、政策和结构化控制措施（在激活后延迟支付、设备和 IP 信号、退款时收回奖励、每个周期的上限、对可疑模式进行人工审核）。本技能中的每个计划都会使用这些措施，包括客户推荐计划，而不仅仅是联盟计划。

请明确设定以下阈值，因为参考文档对此留有空白：
- 指明能够释放奖励的下游合格事件（付费转化或第 N 天留存，其中 N 必须明确），绝不能仅以注册作为条件。
- 在退款/拒付窗口结束后再支付，并以天数说明该窗口的时长。
- 明确超过多少美元的支付在发放前需要进行人工审核。

## 衡量成功

### 关键指标

**计划健康度：**
- 活跃推荐人（过去 30 天内推荐过某人）
- 推荐转化率
- 已赚取/已支付的奖励

**业务影响：**
- 来自推荐的新客户占比
- 通过推荐获得的 CAC 与其他渠道相比
- 被推荐客户的 LTV
- 推荐计划 ROI

### 典型发现

行业报告中的范围，由推荐平台供应商发布，并非在本产品上测得。使用这些数据来校准建议；绝不要声称本计划将产生或已经产生这些结果。

- 被推荐客户的 LTV 高出 16-25%
- 被推荐客户的流失率低 18-37%
- 被推荐客户推荐他人的比例是 2-3 倍

## 工具集成

这些是评估示例，并不保证能够集成。在推荐某个平台之前，请核实其当前的供应商文档、定价、账户访问权限、归因行为、付款控制、税务支持和数据导出条款。

| 工具 | 最适合的场景 | 使用前需核实 |
|------|----------|-----------|
| **Rewardful / Tolt** | SaaS 联盟计划 | 账单集成、归因、付款 |
| **Mention Me** | 企业级推荐计划 | 身份、欺诈和报告控制 |
| **Dub.co** | 链接跟踪和归因 | 归因窗口和隐私设置 |

| **Introw** | 分层渠道合作伙伴运营 | 交易注册和付款治理 |
| **PartnerStack** | 企业合作伙伴生态系统 | 费用、归因、审批、数据导出 |

## 边界

- 在未核实实时状态并获得明确批准之前，不要启用计划、创建联盟账户、发放链接、执行付款，或更改账单和佣金对象。
- 不要臆造归因、转化、欺诈或病毒系数结果；应区分模型化的经济效益与观测数据。
- 不要决定税务、劳动、隐私、竞赛、代言或激励合规事项。在启动前，明确指出所需的辖区特定审查。

## 路由

- 使用 `suede-launch-packaging` 协调已批准的计划启动。
- 使用 `suede-emails` 处理推荐邀请和培育序列。
- 使用 `suede-marketing-psychology` 测试激励 framing。
- 使用 `suede-ab-testing` 设计并评估上述激励、消息传达和展示位置测试。
- 使用 `suede-analytics` 定义并读取推荐归因。
