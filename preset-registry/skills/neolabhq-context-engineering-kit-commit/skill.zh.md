# Claude 命令：提交

你的任务是使用规范化提交消息和表情符号，创建格式良好的提交。

## 指令

关键：严格按照以下步骤执行：

1. **分支检查**：检查当前分支是否为 `master` 或 `main`。如果是，则询问用户是否要在提交前创建单独的分支。如果用户确认需要新分支，则使用 `<type>/<username>/<description>` 模式创建分支（例如：`feature/leovs09/add-new-command`）
2. 除非指定了 `--no-verify`，否则自动运行提交前检查，例如根据项目语言运行 `pnpm lint` 或类似命令。
3. 使用 `git status` 检查哪些文件已暂存
4. 如果有 0 个文件已暂存，则自动添加所有已修改和新建的文件，使用 `git add`
5. 执行 `git diff` 以了解将要提交的更改
6. 分析差异，确定其中是否存在多个不同的逻辑变更
7. 如果检测到多个不同的变更，则建议将提交拆分为多个更小的提交
8. 对于每个提交（如果不拆分，则为单个提交），使用带表情符号的规范化提交格式创建提交消息

## 提交最佳实践

- **提交前验证**：确保代码已通过 lint 检查、能够正确构建，并且文档已更新
- **原子提交**：每个提交应包含服务于单一目的的相关变更
- **拆分大型变更**：如果变更涉及多个关注点，则将其拆分为多个独立提交
- **规范化提交格式**：使用 `<type>: <description>` 格式，其中 type 可选值包括：
  - `feat`：新功能
  - `fix`：错误修复
  - `docs`：文档变更
  - `style`：代码风格变更（格式化等）
  - `refactor`：既不修复错误也不添加功能的代码变更
  - `perf`：性能改进
  - `test`：添加或修复测试
  - `chore`：构建流程、工具等方面的变更
- **使用现在时和祈使语气**：将提交消息写成命令（例如使用“add feature”，而不是“added feature”）
- **简洁的第一行**：将第一行控制在 72 个字符以内
- **表情符号**：每种提交类型都对应一个适当的表情符号：

## 拆分提交的指南

分析差异时，请根据以下标准考虑拆分提交：

1. **不同的关注点**：修改代码库中不相关的部分
2. **不同类型的变更**：混合功能、修复、重构等变更
3. **文件模式**：修改不同类型的文件（例如源代码与文档）
4. **逻辑分组**：拆分后更易于理解或分别审查的变更
5. **大小**：非常大的变更，拆分后会更加清晰

## 命令选项

- `--no-verify`：跳过运行提交前检查（lint、build、generate:docs）

## 分支命名约定

在 `master` 或 `main` 上提交时，命令会询问你是否要创建新分支。如果选择是，它会按照以下模式创建分支：

```
<type>/<git-username>/<description>
```

**组成部分：**
- `<type>`：提交类型（feature、fix、docs、refactor、perf、test、chore 等）
- `<git-username>`：你的 git 用户名（通过 `git config user.name` 或系统用户名获取）
- `<description>`：对变更的 kebab-case 描述（例如 `add-user-auth`、`fix-login-bug`）

**示例：**
- `feature/leovs09/add-new-command`
- `fix/johndoe/resolve-memory-leak`
- `docs/alice/update-api-docs`
- `refactor/bob/simplify-error-handling`
- `chore/charlie/update-dependencies`

**工作流：**
1. 命令检测到你位于 `master` 或 `main` 上
2. 询问：“你当前位于主分支上。是否要创建单独的分支？”
3. 如果选择“否”：在当前分支上继续提交
4. 如果选择“是”：分析你的变更以确定类型，询问简短描述，创建分支，然后继续提交

## 重要说明

- 默认情况下，将运行预提交检查（`pnpm lint`、`pnpm build`、`pnpm generate:docs`）以确保代码质量
- 如果这些检查失败，系统会询问你是要继续提交，还是先修复问题
- 如果已有特定文件处于暂存状态，该命令只会提交这些文件
- 如果没有文件处于暂存状态，它会自动暂存所有已修改和新增的文件
- 提交消息将根据检测到的更改构建
- 提交前，该命令会检查差异，以确定是否更适合拆分为多个提交
- 如果建议进行多个提交，它将帮助你分别暂存并提交这些更改
- 始终检查提交差异，以确保提交消息与更改相符
