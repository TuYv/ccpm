# Suede：从视频片段到指南

构建一条由证据支持的路径，将视频中的某个精彩时刻引向更深入的书面内容资产。
将视频片段视为吸引注意力的层级，将指南视为提供权威信息的层级。不要假定这种模式一定有效；应根据账号基准测试这一衔接方式。

## 默认成功蓝图

当版权、来源、主张、平台和审批关卡均通过时，使用此模式作为推荐方案：

```text
Useful guide with one promise
        ↓
Self-contained video moment
        ↓
Rights route + 8/10 moment score
        ↓
Clip hook + source credit + subtitles
        ↓
Post explains why the moment matters
        ↓
One explicit bridge to the guide
        ↓
Max Effort/Fleet: dual certainty gate
        ↓
Exact-content approval
        ↓
Public readback + clip-to-guide measurement
        ↓
Keep, revise, or stop from the observed result
```

在以下情况下优先使用此蓝图：

- 已有指南能够回答视频片段自然引出的下一个问题；
- 目标是促进更深入的理解、收藏、有价值的回复、潜在客户转化或建立权威，而不只是追求原始播放量；
- 选定的时刻通过了 8/10 评分和主张支持阈值；
- 已记录版权使用路径和当前的平台操作顺序；
- 账号至少能够观测一项视频片段指标，以及一项指南跳转指标或活动指标。

在以下情况下不要使用此蓝图：

- 指南内容单薄、与视频片段无关、尚未发布且没有稳定草稿，或缺乏明确的价值承诺；
- 视频片段依赖缺失的上下文、歪曲了来源，或仅仅因为热门而被选中；
- 第三方内容复用受阻，或缺少责任明确的合理使用决定；
- 平台无法通过经过验证的操作顺序保留来源、视频片段和指南之间的衔接；
- 短帖本身已经完整表达了观点，而指南无法提供更深入的内容。

对于首次测试，仅当三个时刻均通过所有关卡时，才构建三个不同的内容包。将它们与该账号近期的同类帖子进行比较。只有在指定的指南跳转指标或活动指标满足决策规则时，才保留此模式；如果未满足，则每次只修改一个变量。

## 不可妥协的关卡

在整个执行过程中应用这些关卡。在撰写文案之前解决版权、来源和主张问题；在执行线上操作之前解决平台、确定性和审批问题：

1. **版权关卡** — 将视频分类为 owned、licensed、permission-recorded、native-repost-only、fair-use-review 或 blocked。可公开访问并不代表获得了复用许可。
2. **来源关卡** — 获取视频、文字稿或准确时间戳、指南草稿或 URL、目标平台、预期使用的账号，以及期望用户采取的下一步操作。
3. **主张关卡** — 将事实性主张和引文追溯至来源。将解读明确标注为解读。
4. **平台关卡** — 在承诺可以组合使用媒体、引用帖子、文章卡片、链接或回复之前，检查当前的官方要求和线上发布编辑器。
5. **审批关卡** — 在用户批准确切的媒体、文案、指南、账号和操作顺序之前，不得发布、定时发布、转发、上传、回复或编辑线上文章。
6. **确定性关卡** — 当 max-effort 或 worker-fleet 控制器运行此技能时，在将内容包标记为已批准或已发布之前，要求进行两项彼此独立的证据检查。工作进程的结论不能作为第二项检查。

当某个阻断性关卡未通过时，停止受影响的操作，并返回：

```text
HALT — <one-line blocker>
Options:
1. <bounded resolution>
2. <bounded resolution>
3. <bounded resolution, if useful>
Waiting on: <specific evidence or approval>
```

仅继续进行不绕过该阻断项的独立草稿工作。

### 违规前的合理化借口

下列每个借口都会在跳过关卡之前立即出现。当它出现在你自己的推理或请求中时，应将其视为执行关卡的信号，而不是豁免关卡的理由。

| 借口 | 事实 |
|---|---|
| “只有 12 秒而已。” | 时长不能作为权利依据。该片段仍然需要通过自有、已获许可、已记录授权、平台原生转发或有责任人认定的合理使用路径。 |
| “我注明了来源。” | 注明来源属于署名，而非权利许可。被阻止或未经审核的来源不会因为附上署名信息就变得可用。 |
| “它是公开的，所以可以重复使用。” | 可公开访问并不等于获准重复使用。在撰写文案之前，应先对视频进行分类。 |
| “发布工具已接受它，所以它已经发布了。” | 发布工具准备就绪、内容已排期或完成点击操作，都不代表已经发布。只有回读公开永久链接才能证明已发布。 |
| “执行工作单元已经检查过了。” | 在 Max Effort 或 Worker Fleet 模式下，执行工作单元的结论只是一次检查。确定性关卡需要第二次独立检查。 |
| “指南基本已经完成了。” | 未发布且没有稳定草稿或明确承诺的指南无法通过契合度测试。应当搭建通往实际存在内容的桥梁。 |
| “这个话题正获得关注，所以直接发布吧。” | 热度不是评分标准。评分低于 8/10，或论点支持度、指南衔接度中任一项低于 2 的话题均不合格。 |

## 工作流程

### 1. 定义漏斗契约

记录：

- 营销活动目标：文章阅读量、收藏量、有效回复、个人资料访问量、潜在客户，或其他明确指定的行动；
- 目标平台和公开显示的发布身份；
- 视频来源 URL 或文件、所有者、字幕文本可用性以及候选时间戳；
- 指南标题、URL 或草稿、其承诺以及当前发布状态；
- 受众以及一项后续行动；
- 用户需要的是私密草稿、已排期内容包，还是实时执行。

如果 `.agents/product-marketing.md`、`.claude/product-marketing.md` 或 `product-marketing-context.md` 中存在产品营销上下文，请先阅读这些内容，再询问其中已经涵盖的信息。

### 2. 选择合法的视频使用路径

| 权利状态 | 允许的路径 |
|---|---|
| `original` | 在用户批准的范围内剪辑并发布。 |
| `licensed` | 遵守许可条款并记录相关证据。 |
| `permission-recorded` | 严格遵守获批的平台、时长、署名和编辑范围。 |
| `native-repost-only` | 使用平台原生的引用、转发、拼接、合拍、嵌入或链接路径。不得下载后重新上传。应将其视为一种操作层面的分享路径，而非法律许可。 |
| `fair-use-review` | 针对评论、批评、新闻报道、教学、学术或研究用途准备四要素审查。在责任人记录决定之前，不得将该用途认定为合理使用，也不得发布。 |
| `blocked` | 不得使用该视频素材。改为提供原创评论视频、授权请求或来源链接。 |

对于任何并非原创、未获许可，或没有权限记录的来源，请阅读
[references/third-party-video-rights.md](references/third-party-video-rights.md)。
不要自行推断合理使用、所有权或许可。内容简短、注明出处、来源公开或仅仅添加了评论，
都不足以判定构成合理使用。不要移除水印、署名或来源信息。优先采用添加了分析的原生转发，
或制作原创的摄像拍摄或屏幕录制回应，在不复制原视频片段的前提下概述其观点。

### 3. 确立指南锚点

长篇内容必须具备：

- 一个具体且短视频可以如实引出的承诺；
- 一个标题以及稳定的草稿或 URL；
- 足够的深度，让用户从短内容转向长内容后有所收获；
- 对实质性事实主张提供来源；
- 一个与营销活动目标相符的下一步行动。

如果指南尚不存在，请返回一份简报，并将完整草稿交由
`suede-copy` 处理，将内容组合决策交由 `suede-content-strategy` 处理。在指南形成可供审核的草稿后，
再继续执行此技能。不要捏造已上线的 URL。

### 4. 为候选片段评分

从五个维度为每个候选片段打 0 到 2 分：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 开场清晰度 | 缺少前提 | 前提出现得太晚 | 在 1–3 秒内明确前提 |
| 独立价值 | 需要上下文才能理解 | 部分自成一体 | 是完整且有用的观点或故事 |
| 指南衔接 | 毫不相关 | 有一定关联 | 自然引出指南将回答的下一个问题 |
| 主张依据 | 无法验证或具有误导性 | 需要限定说明 | 有直接依据且表述准确 |
| 受众匹配度 | 未明确适合的受众 | 广泛适用 | 解决特定受众的问题 |

仅当某个片段得分至少为 8/10、主张依据得分为 2、指南衔接得分为 2，
且通过权利审核关卡时，才可选择该片段。如果没有片段符合条件，请返回评分表并请求提供
更合适的来源，而不是强行制作短视频。

### 5. 构建内容包

阅读 [references/package-template.md](references/package-template.md) 并
生成：

1. **决策摘要** — 目标、受众、平台、身份以及所选发布顺序。
2. **来源与权利记录** — 所有者、来源、证据、转录文本摘录、
   允许的使用方式、司法管辖区以及任何四要素审查。
3. **指南锚点** — 确切标题、承诺、URL 或草稿状态，以及用户看完短视频后
   该指南将回答的问题。
4. **短视频简报** — 入点/出点时间戳、目标时长、确切开场、字幕
   文本、画面署名、结尾衔接语以及导出负责人。
5. **漏斗帖子** — 完整准确的文案，承担四项任务：
   - 用视频片段吸引受众；
   - 解释其重要性；
   - 衔接到更深入的指南；
   - 给出一个具体的下一步行动。
6. **发布顺序** — 采用下方已验证模式中的一种。
7. **衡量计划** — 基准线、观察窗口以及决策规则。
8. **确定性记录** — 执行模式、两名检查负责人或两套检查流程、
   直接证据、矛盾之处以及最终结论。
9. **审批材料包** — 确切的媒体素材、帖子文案、指南、身份以及发布顺序。

不要用泛泛的铺垫、缺乏依据的效果描述或多个相互竞争的行动号召来填充帖子。

### 6. 选择已验证的发布顺序

选择以下一种：

- **锚点优先** — 先发布或验证指南，然后发布引用该指南、以剪辑为主的帖子。
- **剪辑优先** — 先发布剪辑，然后将指南放在平台已验证的配套位置，例如第一条回复或受支持的链接字段中。
- **原生转发** — 引用或转发第三方来源，并附上原创分析和指南衔接内容；不要重新上传来源媒体。

不要假定引用帖子还可以携带新媒体。验证当前的内容编辑器，并选择能够保留剪辑、指南和来源署名的最简发布顺序。

### 7. 在需要时执行双重确定性门控

将 `execution_mode` 记录为 `standard`、`max-effort` 或 `worker-fleet`。标准模式可以记录 `certainty_status: not-required`。最大努力模式和工作器集群模式必须执行两项检查，并且在 `certainty_status: proved` 之前不得将内容包标记为 `approved` 或 `published`。记录一个内容包版本、时间戳或内容哈希，确保两项检查评估的是同一个未经更改的制品。

**检查 1 — 生产证明**

- 在所选时间戳处重新打开视频或转录文本。
- 将引文、主张表述、权利证据、时刻评分、指南承诺、衔接内容、确切文案、身份、发布顺序和唯一的 CTA 与内容包进行核对。
- 对已保存的制品运行内容包验证器。
- 在集群模式下，集群工作器的验收标准自检可以满足此项检查，但结果仍为临时性质。

**检查 2 — 独立证明**

- 直接检查来源证据和已组装的内容包；不要只审查检查 1 的摘要。
- 使用不同的故障视角、证据来源或验收标准，并尝试推翻权利路径、事实表述、指南适配性、平台发布顺序和审批就绪状态。
- 在最大努力模式下，如果并行工作有实际作用，应将制作者与对抗性审查者分开。对于单个原子化的最大努力任务，请在重新加载来源证据后执行一次全新的第二轮检查。
- 在集群模式下，控制器必须执行此项检查，并将工作器输出标记为 `accepted`、`rejected` 或 `fix brief`。第二个工作器或重复自检不能替代控制器审查。

仅使用以下状态：

- `PROVED` — 两项检查均通过直接证据验证，并且所有矛盾均已解决；
- `UNPROVED` — 某项检查不完整、依赖间接证据，或与另一项检查结论不一致；
- `BLOCKED` — 访问权限、授权、权利或平台状态阻碍了必需的检查。

如果任一检查不是 `PROVED`，则应保持发布未获批准状态，使用中止格式，并指出所需的最小修复或证据。双重检查可提高置信度；它不保证内容真实，不构成法律许可，也不能取代上线前的实时复核。对媒体、时间戳、权利证据、指南、文案、身份、发布顺序或 CTA 的任何实质性更改，都会将 `certainty_status` 重置为 `pending`，并要求重新执行两项检查。

### 8. 要求对确切内容进行审批

在执行上线操作之前，展示：

```text
Account:
Platform:
Media:
Source/rights status:
Guide title and URL:
Exact post text:
Publish sequence:
```

批准仅对该内容包有效。如果媒体、文案、指南 URL、账号或发布顺序发生实质性变化，请展示变更后的内容包并重新获得批准。执行操作前，应立即核验可见身份；如遇账号不匹配、登录验证或发布编辑器不明确的情况，应采用封闭式失败策略并中止操作。

### 9. 验证完成情况

对于已保存的软件包，运行：

```bash
python3 /path/to/suede-clip-to-guide/scripts/validate_package.py path/to/clip-to-guide-package.md
```

对于实时运行，还应回读：

- 最终的公开永久链接；
- 可见的发布身份；
- 渲染后的帖子文本和媒体，或原生来源引用；
- 指南 URL 和发布状态；
- 时间戳以及任何平台警告。

不要仅凭一次点击就声称内容已发布。完整的实时运行必须包含公开回读。仅草稿运行在软件包验证器通过，且批准状态报告为 `draft` 时即告完成。

## 衡量

选择该账号能够支持的最小可比时间窗口。记录：

- 平台提供时的短片留存率或完播率；
- 平台提供时的指南打开次数或链接点击次数；
- 书签、收藏、有效回复和个人资料访问次数；
- 确切的推广活动操作；
- 可比较的近期基准。

当平台提供兼容的分母时，计算：

```text
guide transition rate = verified guide opens / clip-post impressions
qualified action rate = named qualified actions / verified guide opens
```

如果无法获得兼容的分母，请分别报告可用的计数。不要合并不匹配的平台时间窗口，也不要将点击称为文章阅读。

每次后续测试仅更改一个变量：片段、开场、衔接、顺序或 CTA。不要根据未配对或样本量极小的数据报告因果提升。

## 边界

- 如无记录在案的权利依据或由责任主体作出的合理使用决定，不得下载、剪辑或重新上传第三方影像。
- 不得提供法律许可，也不得将不确定的再利用标记为合理使用。
- 不得捏造转录文本、时间戳、许可、URL、表现数据、受众需求或平台能力。
- 未获得对确切内容的批准并完成可见身份核验，不得发布或安排发布。
- 不得为了增强吸引点而修改来源引文。
- 在当前分析数据支持指定的决策规则之前，不得将推广活动描述为成功。
- 当任一必需检查为 `UNPROVED` 或 `BLOCKED` 时，不得声称 Max Effort 或 Fleet 软件包是确定的、已获批准的或可发布的。

## 路由

- 需要完整的视频编辑、生成、字幕、调色或导出 -> 使用 `suede-video`，然后返回此处生成漏斗软件包。
- 需要通用的平台计划、日历、舆情监听或互动方案 -> 使用 `suede-social`。
- 需要撰写长篇指南 -> 使用 `suede-copy`；如需内容支柱和内容组合优先级，则使用 `suede-content-strategy`。
- 需要付费投放变体 -> 使用 `suede-ad-creative`。
- 需要最大投入的编排或大批量工作器集群批处理 -> 使用此软件包未包含的 Suede Labs 私有配套工具：suede-full-send 和 suede-codex-fleet。无论采用哪种模式，都应返回此处生成双重确定性记录。
- 从这些技能中，将视频到长篇内容的衔接、片段评分、权利处理路径、确切的批准内容包和回读结果路由回 `suede-clip-to-guide`。
