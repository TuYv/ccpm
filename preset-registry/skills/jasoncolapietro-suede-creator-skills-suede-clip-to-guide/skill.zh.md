# 从绒面剪辑到指南

从视频片段构建一条有证据支撑的路径，引导至更深入的书面内容资产。
将剪辑视为注意力层，将指南视为权威层。不要假设这种模式有效；应根据账户基线测试这座桥梁。

## 默认成功蓝图

当权利、来源、主张、平台和审批关卡均通过时，将此作为推荐模式：

```text
Useful guide with one promise
        ↓
Self-contained video moment
        ↓
Rights route + 8/10 moment score
        ↓
Clip hook + source credit + subtitles
        ↓
Post explains why the moment matters
        ↓
One explicit bridge to the guide
        ↓
Full Send/Fleet: dual certainty gate
        ↓
Exact-content approval
        ↓
Public readback + clip-to-guide measurement
        ↓
Keep, revise, or stop from the observed result
```

在以下情况下优先采用此蓝图：

- 指南已回答剪辑自然引出的下一个问题；
- 目标是更深入的理解、收藏、合格回复、潜在客户或权威性，而不只是原始观看量；
- 所选片段通过了 8/10 评分和主张支撑阈值；
- 权利路径和当前平台发布顺序已记录；
- 账户至少能够观测一项剪辑指标，以及一项指南转化或活动指标。

在以下情况下不要使用：

- 指南内容单薄、不相关、未发布且没有稳定草稿，或没有明确承诺；
- 剪辑需要缺失的上下文、歪曲来源，或仅仅因为热门而存在；
- 第三方复用被阻止，或缺少承担责任的合理使用决定；
- 平台无法以经验证的顺序保留来源、剪辑和指南之间的桥梁；
- 短帖已完整表达该想法，指南不会增加深度。

首次测试时，只有在三个片段都通过全部关卡后，才构建三个不同的内容包。将其与账户近期的可比帖子进行比较。仅当指定的指南转化或活动指标达到决策规则时才保留该模式；未达到时，一次只调整一个变量。

## 不可协商的关卡

在整个执行过程中应用这些关卡。写文案前解决权利、来源和主张问题；进行线上操作前解决平台、确定性和审批问题：

1. **权利关卡** — 将视频归类为自有、已授权、已记录许可、仅限原生转发、合理使用审查或已阻止。公开可获取并不等于拥有复用许可。
2. **来源关卡** — 获取视频、文字稿或精确时间戳、指南草稿或 URL、目标平台、预期账户和期望的下一步操作。
3. **主张关卡** — 将事实性主张和引述追溯至来源。将解读标注为解读。
4. **平台关卡** — 在承诺媒体、引用转帖、文章卡片、链接或回复可以组合之前，检查当前官方要求和实时发布编辑器。
5. **审批关卡** — 在用户批准确切的媒体、文案、指南、账户和发布顺序之前，不要发布、排期、转发、上传、回复或编辑已上线的文章。
6. **确定性关卡** — 当 `suede-full-send` 或 `suede-codex-fleet` 控制执行过程时，在将内容包标记为已批准或已发布前，要求进行两项不同的证据检查。工作者结论不构成第二项检查。

当阻断门禁失败时，停止受影响的操作并返回：

```text
HALT — <one-line blocker>
Options:
1. <bounded resolution>
2. <bounded resolution>
3. <bounded resolution, if useful>
Waiting on: <specific evidence or approval>
```

仅继续进行不绕过该阻断因素的独立草稿工作。

### 违规前的合理化说辞

以下每个借口都会在门禁被跳过之前立即出现。当它出现在你自己的推理中或请求中时，应将其视为执行门禁的信号，而非豁免门禁的理由。

| 借口 | 事实 |
|---|---|
| “只有 12 秒。” | 时长并非权利依据。该片段仍需通过自有、已获许可、已记录授权、原生转载或可追责的合理使用路径。 |
| “我标注了来源。” | 标注是署名，不是授权。被阻止或未经审核的来源，即使附上署名行，仍然处于被阻止状态。 |
| “它是公开的，所以可以复用。” | 公开可用不代表获准复用。先对视频进行分类，再撰写文案。 |
| “编辑器接受了，所以它已经发布。” | 已准备好的编辑器、已排期的条目或一次点击都不代表发布。只有公开永久链接的回读才能证明发布。 |
| “工作人员已经检查过了。” | 在 Full Send 或 Codex Fleet 模式下，工作人员的结论只是一次检查。确定性门禁需要第二次独立检查。 |
| “指南基本完成了。” | 未发布、没有稳定草稿或具体承诺的指南无法通过契合度测试。建立通往确实存在内容的桥梁。 |
| “这个时刻正在获得关注，所以发出去吧。” | 热度不是评分。评分低于 8/10，或主张支持度或指南桥梁低于 2 的时刻，均不符合资格。 |

## 工作流

### 1. 定义漏斗契约

记录：

- 营销活动目标：文章阅读、收藏、合格回复、个人资料访问、潜在客户，或其他已命名的行动；
- 目标平台和可见的发布身份；
- 视频源 URL 或文件、所有者、字幕稿可用性及候选时间戳；
- 指南标题、URL 或草稿、其承诺及当前发布状态；
- 受众和一项下一步行动；
- 用户希望获得私密草稿、排期包，还是进行实时执行。

如果 `.agents/product-marketing.md`、`.claude/product-marketing.md` 或 `product-marketing-context.md` 中存在产品营销上下文，请先阅读，避免询问其中已涵盖的信息。

### 2. 选择合法的视频路径

| 权利状态 | 允许的路径 |
|---|---|
| `original` | 在用户批准的范围内剪辑并发布。 |
| `licensed` | 遵循许可条款并记录证据。 |
| `permission-recorded` | 严格遵循已批准的平台、时长、署名和编辑范围。 |
| `native-repost-only` | 使用平台原生的引用、转载、拼接、合拍、嵌入或链接路径。不得下载后重新上传。将此视为操作层面的分享路径，而非法律授权。 |
| `fair-use-review` | 针对评论、批评、新闻报道、教学、学术研究或研究用途，准备四要素审查。在可追责的负责人记录决定之前，不得将该使用标记为合理使用，也不得发布。 |
| `blocked` | 不得使用该素材。改为提供原创评论片段、授权请求或来源链接。 |

对于任何并非原创、已获许可或已记录授权的来源，请阅读
[references/third-party-video-rights.md](references/third-party-video-rights.md)。
不要推断合理使用、所有权或许可。内容简短、注明出处、来源公开或仅添加评论，
均不足以单独判定为合理使用。不要移除水印、署名或来源信息。优先采用附加分析的原生转发，
或创建原创的镜头录制或屏幕录制回应，在不复制原始素材的前提下概述其观点。

### 3. 确立指南锚点

长篇资产必须具备：

- 一个短片能够如实引出的明确承诺；
- 标题以及稳定的草稿或 URL；
- 足够的深度，以回报用户从短内容转向长内容；
- 对重要事实性主张的来源；
- 一项与营销活动目标相匹配的下一步行动。

如果指南尚不存在，请返回一份简报，并将完整草稿交由
`suede-copy` 处理，将作品集决策交由 `suede-content-strategy` 处理。待指南拥有可供审核的草稿后，
再继续执行此 skill。不要编造有效的线上 URL。

### 4. 为候选片段评分

在五个维度上为每个候选片段评 0 至 2 分：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 开场清晰度 | 前提缺失 | 前提出现得较晚 | 前提在 1–3 秒内清晰呈现 |
| 独立价值 | 需要上下文 | 部分自成一体 | 完整且有用的观点或故事 |
| 指南衔接 | 无关 | 相邻 | 自然引出指南所回答的下一个问题 |
| 主张支持 | 无法验证或具有误导性 | 需要限定说明 | 有直接支持且表述准确 |
| 受众匹配度 | 未匹配具名受众 | 广泛匹配 | 解决具名受众的问题 |

仅当片段得分至少为 8/10、主张支持为 2 分、指南衔接为 2 分，且通过权利审核时，才选择该片段。
若没有片段符合条件，请返回评分卡并请求更好的来源，而不是强行制作片段。

### 5. 构建材料包

阅读 [references/package-template.md](references/package-template.md)，并产出：

1. **决策快照** — 目标、受众、平台、身份和选定的发布顺序。
2. **来源与权利记录** — 所有者、来源、证据、文字记录摘录、
   允许的路径、司法管辖区，以及任何四要素审查。
3. **指南锚点** — 确切标题、承诺、URL 或草稿状态，以及它在短片之后
   回答的问题。
4. **片段简报** — 入/出时间戳、目标时长、确切开场、字幕
   文本、屏幕署名、结尾衔接和导出负责人。
5. **漏斗帖子** — 包含以下四项职责的确切文案：
   - 钩住视频片段；
   - 解释其重要性；
   - 衔接至更深入的指南；
   - 给出一项明确的下一步行动。
6. **发布顺序** — 下方已验证模式中的一种。
7. **衡量计划** — 基线、观察窗口和决策规则。
8. **确定性记录** — 执行模式、两位检查负责人或流程、
   直接证据、矛盾之处和最终结论。
9. **审批材料包** — 确切媒体、帖子文案、指南、身份和发布顺序。

不要用泛泛的铺垫、缺乏支持的效果表述或多个相互竞争的行动号召来填充帖子。

### 6. 选择经过验证的发布顺序

使用以下其中一种：

- **锚点优先** — 发布或验证指南，然后发布引用该指南的短片主导帖子。
- **短片优先** — 发布短片，然后将指南放在平台经过验证的配套位置，例如首条回复或受支持的链接字段。
- **原生转发** — 引用或转发第三方来源，并附上原创分析和指南衔接；不要重新上传来源媒体。

不要假设引用帖子也可以携带新媒体。验证当前编辑器，并选择能够保留短片、指南和来源署名的最小发布顺序。

### 7. 在需要时运行双重确定性门禁

将 `execution_mode` 记录为 `standard`、`full-send` 或 `codex-fleet`。标准模式可以记录 `certainty_status: not-required`。Full Send 和 Codex Fleet 必须运行两项检查，并且在 `certainty_status: proved` 之前，不得将内容包标记为 `approved` 或 `published`。记录一个内容包版本、时间戳或内容哈希，以确保两项检查评估的是同一份未变更的制品。

**检查 1 — 制作证明**

- 在选定的时间戳处重新打开视频或文字稿。
- 将引文、声明表述、权利证据、片段评分、指南承诺、衔接、精确文案、身份、发布顺序和一个 CTA 与内容包进行匹配。
- 针对已保存的制品运行内容包验证器。
- 在 Fleet 模式中，Codex 工作器的验收标准自检可以满足此项检查，但仍属于暂定结果。

**检查 2 — 独立证明**

- 直接检查来源证据和已组装的内容包；不要只审查检查 1 的摘要。
- 使用不同的失败视角、证据来源或验收标准，尝试证伪权利路径、事实表述、指南匹配度、平台发布顺序和审批就绪状态。
- 在具有有用并行工作的 Full Send 中，应将制作人和对抗性审查者分开。对于一个原子性的 Full Send 任务，请在重新加载来源证据后执行一次全新的第二轮检查。
- 在 Fleet 模式中，控制器必须执行此项检查，并将工作器输出标记为 `accepted`、`rejected` 或 `fix brief`。第二个工作器或重复自检不能替代控制器审查。

仅使用：

- `PROVED` — 两项检查均以直接证据通过，并且每一处矛盾都已解决；
- `UNPROVED` — 某项检查不完整、间接，或与另一项检查结论不一致；
- `BLOCKED` — 访问、权限、权利或平台状态阻止执行所需检查。

如果任一检查不是 `PROVED`，则保持发布未获批准，使用暂停格式，并说明所需的最小修复或证据。双重检查会提高信心；它不保证真实性、不产生法律许可，也不能替代实时回读。对媒体、时间戳、权利证据、指南、文案、身份、发布顺序或 CTA 的重大更改，都会将 `certainty_status` 重置为 `pending`，并要求再次执行两项检查。

### 8. 要求对精确内容进行审批

在执行实时操作之前，展示：

```text
Account:
Platform:
Media:
Source/rights status:
Guide title and URL:
Exact post text:
Publish sequence:
```

批准仅对该素材包有效。如果媒体、文案、指南 URL、账号或序列发生实质性变化，请展示变更后的素材包并再次获得批准。执行操作前立即验证可见身份；如果账号不匹配、出现登录验证或编辑器存在歧义，则采取失败关闭策略。

### 9. 验证完成情况

对于已保存的包，运行：

```bash
python3 /path/to/suede-clip-to-guide/scripts/validate_package.py path/to/clip-to-guide-package.md
```

对于实时运行，还要回读：

- 最终公开永久链接；
- 可见的发布身份；
- 渲染后的帖子文本和媒体或原生来源引用；
- 指南 URL 和发布状态；
- 时间戳及任何平台警告。

不要仅凭一次点击就声称已发布。完整的实时运行需要公开回读。当包验证器通过且批准状态报告为 `draft` 时，仅草稿运行即为完成。

## 衡量

选择账号能够支持的最小可比较时间窗口。记录：

- 可获取时的片段留存率或完成率；
- 可获取时的指南打开次数或链接点击次数；
- 书签、收藏、合格回复和个人资料访问；
- 确切的营销活动操作；
- 可比较的近期基线。

当平台提供兼容的分母时，计算：

```text
guide transition rate = verified guide opens / clip-post impressions
qualified action rate = named qualified actions / verified guide opens
```

如果没有兼容的分母，请分别报告可用计数。不要合并不匹配的平台时间窗口，也不要把点击称为文章阅读。

每次后续测试只改变一个变量：时机、开场、桥接、序列或 CTA。不要基于未配对或样本量很小的数据报告因果提升。

## 边界

- 未记录权利依据或未作出可追责的合理使用决定时，不要下载、剪辑或重新上传第三方素材。
- 不要提供法律许可，也不要将不确定的再利用标记为合理使用。
- 不要编造转录文本、时间戳、权限、URL、表现、受众需求或平台能力。
- 未经精确内容批准和可见身份验证，不要发布或排期。
- 不要为了增强钩子而改动来源引语。
- 在当前分析数据支持指定决策规则之前，不要将营销活动描述为成功。
- 当任一必需检查为 `UNPROVED` 或 `BLOCKED` 时，不要将 Full Send 或 Fleet 包称为确定、已批准或可发布。

## 路由

- 需要完整的视频编辑、生成、字幕、调色或导出 -> 使用 `suede-video`，然后返回此处处理漏斗包。
- 需要通用平台计划、日历、监听或互动方案 -> 使用 `suede-social`。
- 需要撰写长篇指南 -> 使用 `suede-copy`；有关支柱和作品集优先级，请使用 `suede-content-strategy`。
- 需要付费变体 -> 使用 `suede-ad-creative`。
- 需要最大投入的编排 -> 使用 `suede-full-send`；需要高吞吐量的 Codex CLI 批处理 -> 使用 `suede-codex-fleet`。无论哪种模式，都返回此处记录双重确定性。
- 从这些技能中，将视频到长篇内容的桥接、片段评分、权利路由、精确批准素材包和回读路由回 `suede-clip-to-guide`。
