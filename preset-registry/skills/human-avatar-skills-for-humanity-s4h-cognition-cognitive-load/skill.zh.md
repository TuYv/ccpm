# 认知：认知负荷

工作记忆是思考发生的地方——而它的容量极其有限。乔治·米勒于 1956 年发表的里程碑式论文《神奇的数字 7±2》指出，人类的工作记忆大约只能同时容纳七个信息组块。约翰·斯威勒在 20 世纪 80 年代和 90 年代提出的认知负荷理论，让这一生物学限制具备了实际意义：并非所有认知需求都相同，而信息的呈现和组织方式，会对工作记忆是过载还是得到恰当利用产生直接且可衡量的影响。

斯威勒确定了三种认知负荷。**内在负荷**是材料本身固有的复杂性——为了理解材料，你必须同时保持在脑海中的相互作用元素的数量。如果不改变你正在学习或决定的内容，就无法降低这种负荷。**外在负荷**由糟糕的呈现、不良的设计或不必要的复杂性造成——它是与实际任务无关的信息架构开销。这是一种浪费，应当予以消除。**相关负荷**是构建新图式的有效认知投入——真正学习并整合新材料所需的脑力活动。认知负荷管理的目标是消除外在负荷，通过组块化管理内在负荷，并保护相关负荷。

这一点不仅适用于教育和培训设计。每当你试图清晰思考某个复杂问题时——设计系统、阐释策略、做出高风险决策——你都受到认知负荷的制约。某个人的白板杂乱无章，并不意味着其组织能力出了问题，而是其工作记忆管理出了问题。某项战略计划在会议结束后无人能够记住，并不是沟通失败，而是认知负荷管理失败。

## 你的流程

**第 1 步：定义认知任务和用户**
具体的认知任务是什么——为了完成它，必须在工作记忆中保持哪些内容？执行者又是谁——他们在该领域可能具备怎样的基础专业水平？（专家图式能够显著压缩内在负荷；新手则会直接面对原始的元素交互性。）

**框架检查：** 继续之前，确认具体的认知任务及其执行者。用一句话说明你所识别出的内容——任务、领域复杂性，以及需要将这些内容保持在脑海中的人——然后使用 `AskUserQuestion`：
- **问题：**“我的理解是：[用一句话概括具体的认知任务、其复杂性，以及需要执行该任务的人]。对吗？”
- **标题：**“框架”
- **选项：**
  - **是——继续**——框架正确
  - **调整**——其中一个要素有误；用户会在你继续之前予以纠正
  - **重新设定框架**——实际情况与当前理解不同；继续之前应纳入用户的纠正

**第 2 步：诊断负荷类型的分布**
分析当前有哪些因素正在造成认知负荷，并对每个来源进行分类：

- **内在负荷来源：** 必须同时保持在脑海中的真正复杂元素（相互作用变量的数量、依赖关系的深度、缺乏现有图式的新概念）
- **外在负荷来源：** 呈现和设计开销——注意力分散（相关信息位于不同位置）、冗余（同一信息以略有不同的形式多次呈现）、顺序不当（先介绍概念，后介绍其先决知识），以及不必要的细节
- **相关负荷来源：** 有助于构建图式的有效工作——整合并理解材料所需的真正认知投入

**步骤 3：评估过载风险**
总负荷（内在负荷 + 外在负荷）在哪些地方接近或超过了工作记忆容量？过载的迹象包括：任务切换增多、错误集中出现、记忆留存下降，以及人在执行后续步骤时开始忘记先前步骤。找出瓶颈——即负荷骤增、容量最为紧张的节点。

**在缩小范围之前：** 在给出解决方案前，使用 `AskUserQuestion` 分享诊断结果：
- **问题：**“我已经梳理了负荷来源。主要压力点是[简要总结——负荷最高的时刻及其类型]。在我建议干预措施之前，这是否符合你的体验，即困难主要集中在这里？”
- **标题：**“负荷诊断”
- **选项：**
  - **是——这就是压力点**——继续采取干预措施
  - **压力点不同**——用户将说明困难实际集中在哪里
  - **添加一个负荷来源**——用户将指出负荷图谱中遗漏的内容

**步骤 4：应用负荷降低策略**
针对每种负荷类型，应用适当的策略：

**对于外在负荷（消除）：**
- *邻近原则：* 将相关信息在空间和时间上彼此相邻放置。消除注意力分散效应。
- *减少冗余：* 删除以不同形式重复表述的相同信息。冗余看似有帮助，却会占用工作记忆。
- *分段：* 将连续的复杂信息流拆分成若干离散片段，并设置自然的完成节点。
- *信号提示：* 明确呈现结构——使用标题、编号和清晰的过渡——使确定当前位置不再消耗工作记忆。

**对于内在负荷（通过组块化管理）：**
- *组块化：* 将相关元素归入一个带标签的单元。不要记住 7 个变量，而是记住 3 个组块。米勒的“神奇数字”适用于组块，而不是单个元素。
- *排序：* 先介绍先决概念，再介绍依赖这些概念的内容。绝不要让学习者记住一个尚且无法与任何内容建立联系的概念。
- *完整示例：* 在要求实际应用之前，先提供完整示例。这可以在构建图式的同时，降低解决问题所带来的负荷。

**对于相关负荷（保护并提供支架）：**
- *变式：* 在多个情境中呈现同一概念，以构建稳健的图式。
- *自我解释提示：* 鼓励主动加工——问“这意味着什么？”，而不是被动吸收。
- *渐进式复杂化：* 从简化模型开始；待核心图式形成后，再增加复杂度。

**步骤 5：设计认知卸载策略**
通过外化，将有效工作记忆扩展到生理极限之外：
- **卸载什么：** 中间结果、列表、图表、决策树、带注释的示例——任何可以外部呈现而不必保留在头脑中的内容
- **何时卸载：** 在每个自然完成节点进行——不要让已完成的工作继续占用工作记忆；将其记录下来并从工作记忆中清除
- **如何设计外部表征：** 卸载系统应降低检索负荷，而不是增加负荷；设计良好的符号系统或图表应让视觉承担一部分原本由工作记忆完成的工作

## 人工确认

在继续之前，使用 `AskUserQuestion` 工具。用 1–2 句话说明你对当前情况的理解——主要的认知负荷问题是什么，以及工作记忆在哪个环节达到上限——然后询问：

- **问题：**“我的判断是：[用 1–2 句话说明你的理解]。你希望如何继续？”
- **标题：**“范围”
- **选项：**
  - **完整分析** — 负荷类型细分、瓶颈诊断、完整干预措施集、认知卸载策略
  - **快速改进** — 找出两到三个影响最大的外在负荷削减措施
  - **重新设计结构** — 重点对材料进行分块和排序，以最大限度提高可学习性或可用性
  - **重新界定** — 当前判断有误；请予以纠正，分析将按照修正后的框架进行

根据用户的选择继续。如果用户重新界定了问题，请在开展任何分析之前纳入其修正意见。

## 说明

认知负荷管理并不是要让事物变得比实际更简单，而是避免让它们变得比实际所需更困难。其目标是消除外在负荷（即对认知没有帮助的负荷），同时保护真正发挥作用的内在负荷和生成性负荷。

与其最接近的是 `/s4h-cognition-attention`——它关注的是能否持续集中注意力。注意力是入口（你能否投入其中？）；认知负荷则是容量问题（投入之后，你能否容纳这种复杂性？）。对于复杂问题，两者都需要处理。

对于沟通和演示设计，尤其应与 `/s4h-communication-clarity-audit` 配合使用——它用于评估信息结构是在帮助受众，还是在增加受众的认知负担。
