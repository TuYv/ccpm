# 调试口诀

任何调试会话的四步纪律。逐字背诵，然后按顺序应用。

## 背诵以下内容——逐字逐句，作为你第一次响应的第一件事

> **口诀：**
> 1. **首先是可复现性。** 问题能否可靠地复现？
> 2. **弄清失败路径。** 先用调试器；然后源码追踪 + 旋钮枚举；然后代码内插桩。
> 3. **质疑你的假设。** 什么能将其证伪？
> 4. **每一次运行都是一条面包屑。** 把它们全部交叉比对。

然后开始工作。

---

## 1. 可靠地复现

在做任何其他事情之前，先构建一个可运行的复现。

- **可靠的复现** → 把确切的步骤、输入和环境捕获为一个可运行的产物：失败测试、curl 脚本、CLI 调用、回放装置。
- **不稳定的复现** → 该 bug 尚不可调试。先提高复现率：循环触发、并行化、增加压力、收窄时间窗口、注入 sleep。50% 的偶发率尚可调试；1% 则不行。
- **完全没有复现** → 停下。明确说明这一点。向用户索要环境访问权限、已捕获的产物（HAR、日志转储、core）、或插桩许可。**不要**继续提出假设。

目标：一个快速（1–5 秒）、确定性的通过/失败信号。固定时间、为 RNG 设置种子、冻结网络、隔离文件系统。

## 2. 弄清失败路径

一旦可复现，就找出代码*在哪里*中断，以及*是什么让它不中断*。差分法可以缩小搜索范围。按此顺序尝试——只有前一种策略失败时才升级。

1. **附加调试器。** 如果环境支持，就附加调试器并单步执行到失败现场。一个断点胜过十条日志。在拧动任何旋钮**之前**先做这一步。
2. **源码追踪 + 旋钮枚举。** 如果没有调试器（或它触及不到该 bug），则端到端追踪代码路径，并列出所有可能影响结果的旋钮：
   - 配置标志、环境变量、功能开关
   - 分支条件、输入形态
   - 时序、并发、构建选项
   每个旋钮都是差分中可翻转的候选轴。一次只翻转一个。
3. **代码内插桩。** 如果外部旋钮无法改变失败现象，就深入内部：在疑似失败位置添加 `printf` / 日志语句，转储相关的内部状态。给每个探针打上唯一前缀（例如 `[DBG-a4f2]`），这样清理只需一次 grep。让追踪结果揭示现实在哪里偏离了你的模型。

## 3. 证伪假设

当候选根因浮出水面时，在测试它**之前**先仔细审视。

- 它是否真正端到端地解释了症状？完整推演一遍。
- 最简单的**证明**是什么？最干净的**证伪**是什么？
- **先运行证伪**。假设若经受住考验，它就是真实的；若被推翻，你就省去了追捕幻影的功夫。
- 生成 3–5 个排好序的假设，而不是一个。单一假设思维会锚定在第一个看似合理的想法上。

## 4. 每一次运行都是一条面包屑

为本次会话中的每一个实验维护一份持续更新的**台账**。每条记录：改了什么、发生了什么、它确认或排除了什么。

- 当新假设浮现时，翻查台账。它是否与**每一**条先前的观察都吻合，而不只是最近那条？
- 如果任何一次过往运行与它矛盾，该假设就是错误或不完整的——细化它或丢弃它。
- 拿不准时，设计那个结果能让结论板上钉钉的**单一实验**。下一步就运行它，而不是在相邻的运行上空耗。
- 每次运行后都更新台账。它是你贯穿整个会话的记忆。

## 操作规则

- 每个调试会话中只背诵口诀块**一次**，放在你的第一次响应里。不要在会话中途重新背诵。
- **逐字**背诵。绝不改述、缩短或跳过背诵内容的任何一行。
- 如果用户说 "skip the mantra" → 跳过背诵，但仍要默默地执行这四个步骤。
- **按顺序**应用这四个步骤：
  - 在 #1 得到满足（存在可靠复现）之前，不要提出修复方案。
  - 在 #2 缩小失败路径之前，不要开始测试假设。
  - 在 #3 尝试过证伪之前，不要笃定于某个假设。
  - 在 #4 对照每一条先前面包屑加以确认之前，不要宣布假设正确。
- 如果你发现自己在没有可靠复现的情况下提出修复方案，就停下来，回到第 1 步。
- 这份口诀是**你**要贯穿整个会话遵守的约束——不是要转达给用户的建议。
