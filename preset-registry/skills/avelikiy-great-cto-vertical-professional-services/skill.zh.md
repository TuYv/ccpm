# 垂直领域：专业服务——按工时计费、捍卫利润率、销售工作范围

代理机构、咨询公司和创意工作室销售的是工时和交付成果，而不是产品单位。其经济规律有悖直觉：收入可能增长，利润率却会崩塌；而赢得项目的文档（提案/SOW）也正是利润流失之处。现有成熟产品
（Scoro、Productive、Accelo、Ruddr、BigTime——统称为“PSA”，即专业服务自动化）
正确地建模了这一领域；草率构建的产品则没有。请依据真实的领域来制定规格。

## 1. 领域术语

- **SOW（工作说明书）**——具有约束力的工作范围：交付成果、时间表、价格、条款。
  它就是合同，也是追加销售的载体。
- **项目合作类型**：**项目制**（固定范围/价格）、**顾问服务费制**（按周期收取费用，
  对应一定的产能/工时额度）、**T&M**（工时与材料——按实际发生额计费）。
- **利用率**——可计费工时 ÷ 可用工时。影响利润率的第一个杠杆。
- **实现率**——已计费金额 ÷ 已完成工时的标准价值（即在你*本可以*计费的金额中，
  实际开票并收回了多少）。影响利润率的第二个杠杆。
- **可计费与不可计费**——每条工时记录都带有此标记；不可计费工时
  （行政、销售、返工）是纯成本。
- **WIP（在制工作）**——已交付但尚未计费的工作；收入已经赚取，但尚未
  开具发票。代理机构通常会将其挂账数周。
- **混合费率**——同一项目合作中，由不同资历人员组成的团队所采用的单一有效时薪
  （区别于按人员分别制定的费率表）。
- **变更单**——当工作范围扩大时签署的正式修订文件；是应对范围蔓延的解药。
- **里程碑计费**——发票与交付成果的验收挂钩，而不是与日历日期挂钩。
- **范围蔓延**——超出 SOW 且未获得补偿的工作；悄无声息的利润率杀手。
- **单项目毛利率**——（收入 − 已交付工时的成本）÷ 收入，按*每次项目合作*
  分别计算——不是全公司范围，也不是收入。
- **电子签名**——对提案具有法律约束力的接受确认（ESIGN/UETA，参见 §6）。
- **Net-30 条款**——发票开具后 30 天内到期付款；会影响现金流和催款提醒。

## 2. 不易察觉的领域规则

- **提案/SOW 既是合同，也是追加销售工具。** 它不是营销 PDF——价格、工作范围和验收
  都在其中确定。可选行项目和分级方案能将报价转化为扩展收入。应将其视为收入载体，
  而不是文档导出功能。
- **利润率取决于利用率 × 实现率，而不是收入。** 如果员工忙于不可计费的工作，
  或工时从未开票，公司即使账单收入增长，也可能亏损。盈利能力必须按*每次项目合作*
  计算利润率，绝不能只看营收。
- **顾问服务费制需要消耗进度跟踪。** 顾问服务费对应一组工时/费用额度，
  会在整个月内逐步消耗。如果没有消耗进度跟踪，要么会过度交付（利润率损失），要么会
  交付不足（客户流失）。应持续显示已消耗与剩余额度。
- **代理机构的生死取决于范围蔓延和变更单管理。** 人的默认行为是“直接做了再说”，
  而不是提出变更单——这会悄无声息地将可计费工作变成不可计费工作。
  产品必须让提出变更单变得毫无阻力。
- **工时跟踪令人厌烦，却是计费的事实依据。** 没有工时记录 → 就没有
  可辩护的发票 → 实现率下降。真正的约束是*采用率*，而不是功能。

## 3. 粗糙构建常犯的错误

- **将提案做成静态 PDF**，而不是实现**接受即付款**——错失了电子签名 +
  支付定金/首张发票这一真正完成交易并开始产生现金流的关键时刻。
- **没有变更单流程**——范围蔓延会在无形中侵蚀利润，因为超额交付从未被记录为
  可计费的修订。
- **工时录入过于繁琐，导致无人使用**——每次录入都要填写包含 12 个字段的模态框，会扼杀采用率；
  没有工时记录，计费和盈利能力就都是虚构的。计时器 + 一键录入 +
  默认值胜过完美的模式。
- **盈利能力只显示收入，而不显示利润**——计费金额仪表板只是
  虚荣指标；公司需要查看每个项目/顾问服务的利润，并扣除工时成本。
- **忽视顾问服务额度消耗**——将顾问服务视为固定订阅，
  而不是会逐渐耗尽的额度池，就忽略了顾问服务存在风险的根本原因。

## 4. 必须建模的实体

请明确规定这些实体；它们会反复出现在全部四款产品中。应按照
[[migration-ready-schema]] 构建它们（稳定的外部 ID、软删除、审计时间戳），因为
代理机构会在项目执行期间从现有供应商切换过来，并导入尚未完成的工作。

- **SOW / 提案**——头部信息（客户、合作类型、条款、net-N）+ **行项目**
  （描述、数量、费率、可选/分级标记）+ **电子签名**状态（已发送 → 已查看
  → 已签署）+ **接受即付款**链接（接受时支付定金或首张发票）。状态
  机：草稿 → 已发送 → 已签署 → 进行中 → 已结束。
- **顾问服务**——周期、承诺工时/费用、**额度消耗**（已使用与剩余）、
  结转政策、续约日期。
- **TimeEntry**——人员、项目/任务、时长、**可计费标记**、**费率**（在
  录入时生成快照，而不是实时查询）、已计费/未计费（WIP）状态。
- **Project**——预算（工时和/或费用）、合作类型、费率表、计算得出的
  **利润**（收入 − 已交付工时成本）、里程碑。
- **ChangeOrder**——关联到 Project/SOW，包含范围增量 + 价格增量、独立的
  电子签名/接受流程以及变更原因——从而将范围增长转化为已记录的收入。

## 5. 各产品说明（相较现有供应商的切入点 + 必须做好的关键点）

- **proposals**（轻量级 marketplace）——**切入点。** 与收入直接相关且**切换
  成本低**：公司可以在不迁移任何内容的情况下，将它用于*下一份*提案，而且它
  会立即触及资金流。现有供应商将提案功能埋在笨重的 PSA 套件中。**必须
  做好：接受即付款**——电子签名后直接进入定金/首张发票支付流程。参见
  [[vertical-onboarding]]：首次激活 = 第一份已签署且已付款的提案。
- **client-portal**（crud）——切入点：为客户提供一个简洁统一的界面，用于查看交付物、
  审批、状态和账单，以区别于现有供应商对内部运营的侧重。**必须做好：
  将审批作为计费触发器**——已批准的交付物应当可以开具发票
  （里程碑计费），而不应只是一个复选框。
- **time-invoicing**（crud）——切入点：计时器 → 发票 → 提醒，**中间无需电子表格**；
  现有供应商让工时录入变成了一件苦差事。**必须做好：无摩擦记录 +
  费率快照**——采用率就是产品本身；错误/过时的费率会破坏所有下游
  发票和收入实现率指标。
- **profitability**（dashboard）——切入点：**实时利润**，而不是月末收入
  报告。**必须做好：每项合作的利润 = 利用率 × 实现率**，同时
  扣除工时成本并展示顾问服务额度消耗——而不是提供计费金额图表。

## 6. 合规（轻量）

保持适度——将任何涉及资金流转的事项交由
subscription-billing-engineer 处理。

- **电子签名有效性**——《ESIGN Act》+《UETA》（美国）：记录签署意图、对
  电子记录的同意、审计跟踪（时间戳、IP、签署者身份），并保留一份可检测篡改的
  副本。对于欧盟客户，适用 eIDAS 等级。这正是使接受并付款
  具有法律约束力的要素。
- **发票/税务基础**——连续的发票编号、必填字段，以及适用情况下的销售税/VAT。
  **将引擎部分交由** subscription-billing-engineer 处理（税费计算、支付通道、催收）；
  架构文档只需说明与该引擎之间的*契约*。
- **承包商 1099 表格**——代理机构会向分包商/自由职业者付款；如果产品
  涉及承包商款项支付，则需跟踪收款人的税务信息，以用于 1099-NEC 申报（美国）。注明这一点即可；
  不要在提案工具中构建薪资系统。

## 输出

应用后，在架构文档中补充一则**领域模型**说明，涵盖：范围内的
合作类型（项目制/顾问月费制/T&M）、本产品负责且必须建模的上述实体、利润率定义（利用率 × 实现率，按每项合作计算，如果
范围包含盈利能力），以及提案在范围内时的电子签名/接受并付款契约。
