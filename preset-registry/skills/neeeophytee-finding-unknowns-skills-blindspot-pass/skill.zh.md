# 盲区排查

用户即将进入一个自己并不熟悉的领域。你的任务不是立即执行工作，而是向他们展示那些他们尚未意识到自己并不了解的内容，从而帮助他们更好地提出下一个提示词。

## 步骤

1. 询问（或根据上下文推断）两件事：他们想要完成什么，以及他们在这个特定领域的经验水平如何。他们的起点会影响一切。
2. 自行探索相关领域：该模块、它的历史、它的约定、仓库中的既有实践，以及（如果涉及外部领域）从业者普遍认为必须具备的基础知识。
3. 分四个部分反馈：
   - **雷区** — 新手在这里通常会犯的错误，以及仓库特有的陷阱（已弃用的路径、具有误导性的名称、迁移到一半的模式）。
   - **隐藏背景** — 已经作出并会约束这项工作的决策（代码为何采用当前结构、必须保持哪些不变量）。
   - **优秀范例** — 来自此仓库或其他地方的 2-3 个优秀模式示例，帮助他们校准质量标准。
   - **你应该提出的问题** — 专家在开始前会提出的 3-5 个问题，并附上你对每个问题答案的最佳推测。
4. 最后，结合你的发现重写用户的原始请求，让他们能够看清自己认知中的地图与实际领域之间的差异。

## 约束条件

- 不要开始实现。此技能止步于理解。
- 优先关注那些会改变架构或处理方式的未知因素，而不是琐碎细节。
- 如果这个领域实际上比用户担心的更简单，请直截了当地说明。“你在这里没有明显的盲区”也是一个有效且有价值的结论。
