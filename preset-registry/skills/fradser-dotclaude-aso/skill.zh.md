# ASO 审核

根据 ASO 最佳实践分析 App Store 和 Google Play 商店页面。获取实时商店页面数据，对元数据、视觉素材和评分进行评估，然后生成按优先级排序的行动计划。

## 适用场景

- 用户分享了 App Store 或 Google Play URL
- 用户要求审核或优化应用商店页面
- 用户希望将自己的应用与竞品进行比较
- 用户询问应用商店排名、可见性或下载转化率

## 审核前

**首先检查产品营销上下文：**
如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，旧版配置中则可能使用旧文件名 `product-marketing-context.md`），请在提问前先阅读。使用其中的上下文，只询问尚未涵盖或本任务特有的信息。

## 阶段 1 — 识别商店并获取数据

### 根据 URL 检测商店类型

```
Apple:  apps.apple.com/{country}/app/{name}/id{digits}
Google: play.google.com/store/apps/details?id={package}
```

如果用户提供的是应用名称而不是 URL，请在网上搜索：
`site:apps.apple.com "{app name}"` 或 `site:play.google.com "{app name}"`

### 获取商店页面

使用 WebFetch 获取商店页面。提取所有可用字段：

**Apple App Store 字段：**

- 应用名称（标题）— 30 个字符限制
- 副标题 — 30 个字符限制
- 描述（长描述）— 不计入搜索索引，但会影响转化
- 推广文本 — 170 个字符，无需发布新版本即可更新
- 类别（主要 + 次要）
- 截图（数量、顺序、说明文字）
- 预览视频（是否存在、时长）
- 评分（平均分 + 评分数量）
- 近期评论（可见评论）
- 价格 / 应用内购买
- 开发者名称
- 最后更新日期
- 版本历史说明
- 年龄分级
- 大小
- 列出的语言 / 本地化版本
- 应用内活动（如有可见内容）

**Google Play 字段：**

- 应用名称（标题）— 30 个字符限制
- 简短描述 — 80 个字符限制
- 完整描述 — 4,000 个字符限制，会计入搜索索引
- 类别 + 标签
- 宣传图片（是否存在）
- 截图（数量、顺序）
- 预览视频（是否存在）
- 评分（平均分 + 评分数量）
- 近期评论（可见评论）
- 价格 / 应用内购买
- 开发者名称
- 最后更新日期
- 更新内容文本
- 下载量范围
- 内容分级
- 数据安全部分
- 列出的语言

如果 WebFetch 返回的数据不完整（商店使用客户端渲染），请注明缺失项，并基于现有数据开展工作。如果缺失信息至关重要，请让用户粘贴相关字段。

### 视觉素材评估

WebFetch 无法提取截图图片或说明文字。**截取商店页面的屏幕截图**以获取视觉数据：

1. 前往商店页面 URL，并截取整页屏幕截图
2. 根据截图评估：图标质量、截图数量、说明文字、信息传达质量、是否有预览视频、宣传图片（Google Play）
3. 如果浏览器工具不可用，请让用户分享商店页面的屏幕截图

**推广文本（Apple）：** 这个 170 个字符的字段显示在描述上方，但在抓取的 HTML 中通常难以与描述区分。如果无法确认其是否存在，请注明这一点，并建议用户在 App Store Connect 中检查。

## 阶段 1.5 — 评估品牌成熟度

在评分之前，先将应用划分为以下三个层级之一。这决定了你应如何解读偏离“教科书式 ASO”的做法——家喻户晓的品牌所做出的刻意选择，与不知名应用错失优化机会并不是一回事。

### 层级定义

| 层级 | 特征 | 示例 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| **主导型** | 家喻户晓，拥有 100 万以上评分，位列所属类别前 10，品牌认知度近乎全民覆盖。用户会按品牌名称搜索，而不是使用通用关键词。 | Instagram、Uber、Spotify、WhatsApp、Netflix |
| **成熟型** | 在所属类别中广为人知，拥有 10 万以上评分，自然安装量强劲，品牌具有较高认知度，但尚未达到全民皆知。 | Strava、Notion、Duolingo、Cash App、Calm |
| **挑战型** | 正在建立知名度，评分数少于 10 万，需要通过关键词和 ASO 策略获得曝光。大多数应用都属于这一层级。 | 你的应用、大多数独立开发者/初创公司的应用 |

### 层级如何影响评分

**主导型应用**在以下方面采用调整后的评分标准：

- **标题：** 仅使用品牌名称或品牌名称优先的标题是合理的（如果品牌本身就是关键词，则评分可达 8+）。这些应用不需要依靠通用关键词获得曝光。
- **描述：** 仅根据转化质量评分，不考虑关键词是否存在。如果应用家喻户晓，那么精心撰写的品牌描述优于堆砌关键词的描述。
- **视觉素材：** 使用生活方式/品牌摄影而不是 UI 演示，是一种合理的转化策略。如果产品难以在 30 秒内完成演示，或品牌认知度近乎全民覆盖，则没有视频也是可以接受的。
- **新版内容：** 以每周或更高频率发布通用的版本说明是可以接受的（评分可达 8+）。达到一定规模后，详细更新日志的 ROI 极低，而且存在引发用户反感的风险。
- **App 内活动：** 对于拥有庞大安装基数的工具类应用（Uber、WhatsApp），缺少活动不应受到扣分。这些应用不需要借助活动提升曝光。
- **本地化：** 应根据实际市场而非语言的绝对数量评分。一款仅面向美国市场、支持 2 种语言（英语 + 西班牙语）的金融科技应用，其本地化程度是适当的。

**成熟型应用**可获得部分调整：

- 品牌优先的标题没有问题，但仍应包含 1-2 个关键词
- 对策略性的描述选择应给予合理推定
- 其他维度按正常标准评分

**挑战型应用**应严格按照教科书式 ASO 最佳实践进行评分——每个字符、每张截图和每个关键词都至关重要。

**关键原则：** 在扣分之前，先问：“这是一个错误，还是掌握了我所不了解的数据的团队所做出的刻意选择？”如果应用拥有 100 万以上评分以及专门的 ASO 团队，除非其做法明显错误，否则应假定这些选择以数据为依据。

## 阶段 2 — 对各维度评分

使用 `references/scoring-criteria.md` 中的标准，为每个维度给出 0-10 分。
应用阶段 1.5 中的品牌成熟度层级调整。

平台规范和基准数据的参考文件：

- `references/apple-specs.md` — Apple 官方字符限制、截图/视频规范、CPP/PPO 规则、拒绝触发条件
- `references/google-play-specs.md` — Google Play 官方限制、截图规范、Android Vitals 阈值、政策
- `references/benchmarks.md` — 转化数据、评分影响、视频提升效果、截图行为、CPP/活动基准

### 维度与权重

| #   | 维度           | 权重 | 涵盖内容                                                   |
| --- | -------------- | ---- | ---------------------------------------------------------- |
| 1   | 标题与副标题   | 20%  | 字符使用情况、关键词覆盖、清晰度、品牌与关键词的平衡       |
| 2   | 描述           | 15%  | 前 3 行、关键词密度（Google）、CTA、结构、推广文本          |
| 3   | 视觉素材       | 25%  | 截图数量/质量/信息传达、视频、图标、宣传图片                |
| 4   | 评分与评论     | 20%  | 平均评分、评论数量、时效性、开发者回复                     |
| 5   | 元数据与时效性 | 10%  | 类别选择、更新时效、本地化数量、数据安全                   |
| 6   | 转化信号       | 10%  | 价格定位、IAP 透明度、社会认同、下载量范围                 |

**最终得分** = 加权总分，满分 100 分。

### 分数解读

| 分数   | 等级 | 含义                                           |
| ------ | ---- | ---------------------------------------------- |
| 85-100 | A    | 优化良好；重点关注 A/B 测试和迭代              |
| 70-84  | B    | 基础良好；有明确的改进机会                     |
| 50-69  | C    | 存在显著差距；优先修复将带来较大影响           |
| 30-49  | D    | 多个维度需要进行重大优化                       |
| 0-29   | F    | 商店详情页需要全面彻底改造                     |

## 阶段 3 — 竞品比较（可选）

如果用户提供竞品 URL 或要求进行比较：

1. 获取同一类别中排名靠前的 2-3 个竞品
2. 对每个竞品执行相同的评分
3. 创建比较表，突出用户应用的弱项/强项
4. 识别关键词差距 — 竞品有排名但用户应用未覆盖的关键词

如果未指定竞品，建议用户提供 2-3 个竞品，或主动提出搜索其类别中的热门应用。

## 阶段 4 — 生成报告

使用 `references/report-template.md` 中的模板组织输出。

报告必须包含：

1. **评分卡** — 包含全部 6 个维度、得分和等级的表格
2. **最重要的 3 个速效改进项** — 耗时 <1 小时且影响最大的改动
3. **详细发现** — 按维度细分具体问题和修复方案
4. **关键词建议** — 基于标题/描述分析和竞品关键词差距
5. **视觉素材建议** — 具体的截图/视频改进方案
6. **优先行动计划** — 按影响与投入排序的改动列表

### 报告规则

- 每条建议都必须**具体且可执行**（应写成“将副标题从 X 改为 Y”，而不是“改进副标题”）
- 所有文本建议都要包含字符数
- 在相关情况下，标明平台特定差异（Apple 与 Google）
- 注明在没有付费工具的情况下无法评估的内容（搜索量、准确排名）
- 建议更改关键词时，解释每个关键词为何重要

## 平台特定规则

### Apple App Store — 关键事实

- 标题（30 个字符）+ 副标题（30 个字符）+ 关键词字段（100 **字节**，隐藏）= 被索引的文本
- 关键词字段按字节而非字符计算——阿拉伯语/CJK 字符每个占用 2-3 个字节
- 长描述不会被搜索索引——仅针对转化进行优化
- 推广文本（170 个字符）不会影响搜索（Apple 已确认）
- 切勿在标题/副标题/关键词字段之间重复词语（Apple 对每个词只索引一次）
- 关键词字段：使用逗号，不加空格（应写成 "photo,editor,filter"，而不是 "photo, editor, filter"）
- 截图：每种设备最多 10 张。搜索结果中会显示前 3 张——90% 的用户不会滑过第 3 张
- 自 2025 年 6 月起，截图文案会被索引（AI 提取）
- App 内活动：同时最多发布 10 个，每个最长持续 31 天。会被索引并显示在搜索结果中
- 自 2025 年 7 月起，自定产品页面（最多 70 个）会显示在自然搜索结果中。平均可使转化率提升 5.9%
- App 预览视频：最多 3 个，每个 15-30 秒。静音自动播放——可使转化率提升 20-40%
- SKStoreReviewController：每 365 天最多提示 3 次
- Apple 采用人工编辑精选机制——质量和设计更为重要
- 完整规范、尺寸及导致审核被拒的触发条件，请参阅 `references/apple-specs.md`

### Google Play — 关键事实

- 标题（30 个字符）+ 简短说明（80 个字符）+ 完整说明（4,000 个字符）= 被索引的文本
- 完整说明会被索引——以自然方式将关键词密度控制在 2-3%
- 没有隐藏的关键词字段——所有关键词都必须出现在可见文本中
- Google 具备 NLP/语义理解能力——会检测并惩罚关键词堆砌
- 标题中禁止使用：表情符号、全大写、"best"/"#1"/"free"、CTA（自 2021 年起强制执行）
- 截图：每种设备至少 2 张，**最多 8 张**（不像 Apple 那样是 10 张）
- 要获得精选展示位置，必须提供宣传图片（1024x500，尺寸必须精确）
- 视频不会自动播放——仅约 6% 的用户会点击播放（与 iOS 相比，ROI 较低）
- Android Vitals 会直接影响排名：崩溃率 >1.09% 或 ANR >0.47% = 曝光度降低
- 推广内容：提前 14 天提交以争取精选展示。App 的探索渠道获客量可达到 2 倍
- 自定义商品详情：最多 50 个（可针对已流失用户、特定国家/地区和广告活动）
- 商品详情实验：最多测试 3 个变体，运行 7 天以上，同时只能进行 1 个实验
- 完整规范和政策详情，请参阅 `references/google-play-specs.md`

### Apple 与 Google 分别索引哪些内容

| 字段                  | Apple 是否索引？      | Google 是否索引？      |
| --------------------- | --------------------- | ---------------------- |
| 标题                  | 是                    | 是（最强信号）         |
| 副标题 / 简短说明     | 是                    | 是                     |
| 关键词字段            | 是（隐藏）            | 不存在                 |
| 长描述                | 否                    | 是（权重很高）         |
| 截图文案              | 是（自 2025 年起）    | 否                     |
| App 内活动            | 是                    | 不适用（改用 LiveOps） |
| 开发者名称            | 否                    | 部分索引               |
| IAP 名称              | 是                    | 是                     |

## 常见问题检查清单

如发现以下问题，请予以标记。标有_（取决于层级）_的项目应根据
应用的品牌成熟度层级进行评估——对于主导型应用而言，它们可能是有意为之的选择。

**始终标记（所有层级）：**

- [ ] 评分低于 4.0
- [ ] 距离上次更新已超过 3 个月
- [ ] Google Play 描述没有关键词策略（密度低于 1%）
- [ ] Google Play 缺少宣传图片
- [ ] Apple 关键词字段可能包含重复词（根据标题和副标题推断）
- [ ] 分类不匹配——应用在其他分类中面临的竞争可能更小
- [ ] 截图少于 5 张

**仅针对挑战型/成熟型应用进行标记**_（对于主导型应用不属于错误）：_

- [ ] 标题仅使用品牌名称，浪费了字符空间（没有关键词）_（主导型：品牌本身就是关键词）_
- [ ] 副标题/简短描述重复使用标题中的关键词
- [ ] 描述的前 3 行内容宽泛空洞_（主导型：可能是品牌语调方面的选择）_
- [ ] 没有预览视频_（主导型：如果产品难以演示，这可能是合理选择）_
- [ ] 截图只是没有宣传信息/文案的 UI 截屏_（主导型：生活方式/品牌图片可能具有更高的转化率）_
- [ ] 仅有 1-2 种本地化版本_（应根据实际市场而非绝对数量进行评分）_
- [ ] 没有 App 内活动或推广内容_（主导型工具应用可能不需要提升发现度）_

**针对所有层级进行标记，但需注明背景：**

- [ ] 开发者未回复负面评论_（注明评论量——回复 1000 万以上评论与回复 1000 条评论面临的挑战截然不同）_
- [ ] “版本更新说明”文本内容宽泛空洞_（对于每周或更高发布频率的成熟型/主导型应用而言可以接受）_
