## 评估动画机会

分析哪些地方的动效能提升体验：

1. **识别静态区域**：
   - **缺失反馈**：没有视觉确认的操作（按钮点击、表单提交等）
   - **突兀的过渡**：显得生硬的瞬时状态变化（显示/隐藏、页面加载、路由切换）
   - **不清晰的关系**：不够明显的空间关系或层级关系
   - **缺乏愉悦感**：功能完备但毫无乐趣的交互
   - **错失引导**：可用来引导注意力或解释行为的机会

2. **理解上下文**：
   - 个性是什么？（活泼还是严肃，充满活力还是平静沉稳）
   - 性能预算是多少？（移动优先？复杂页面？）
   - 受众是谁？（对动效敏感的用户？追求速度的高级用户？）
   - 什么最重要？（一个主打动画，还是许多微交互？）

如果其中任何一点从代码库中无法明确，停下并调用 AskUserQuestionTool 进行澄清。

**关键**：尊重 `prefers-reduced-motion`。始终为有此需要的用户提供无动画的替代方案。

## 规划动画策略

制定一个有明确目的的动画计划：

- **高光时刻**：唯一的标志性动画是什么？（页面加载？主视觉区？关键交互？）
- **反馈层**：哪些交互需要确认反馈？
- **过渡层**：哪些状态变化需要平滑处理？
- **愉悦层**：我们在哪里可以带来惊喜和愉悦？

**重要**：一次精心编排的体验胜过四处散落的动画。专注于高影响力的时刻。

## 实现动画

在以下类别中系统地添加动效：

### 入场动画
- **页面加载编排**：错开元素显现（100-150ms 延迟），淡入 + 滑动组合
- **主视觉区**：主要内容的戏剧性入场（缩放、视差或创意效果）
- **内容显现**：使用 intersection observer 的滚动触发动画
- **模态框/抽屉入场**：平滑的滑动 + 淡入、背景遮罩淡入、焦点管理

### 微交互
- **按钮反馈**：
  - 悬停：细微的缩放（1.02-1.05）、颜色变化、阴影增强
  - 点击：快速先缩小再放大（0.95 → 1）、涟漪效果
  - 加载中：旋转加载图标或脉冲状态
- **表单交互**：
  - 输入框聚焦：边框颜色过渡、轻微缩放或发光
  - 校验：出错时抖动、成功时显示对勾、平滑的颜色过渡
- **开关切换**：平滑滑动 + 颜色过渡（200-300ms）
- **复选框/单选按钮**：对勾动画、涟漪效果
- **点赞/收藏**：缩放 + 旋转、粒子效果、颜色过渡

### 状态过渡
- **显示/隐藏**：淡入淡出 + 滑动（而非瞬时完成），时长恰当（200-300ms）
- **展开/收起**：带溢出处理的高度过渡、图标旋转
- **加载状态**：骨架屏淡入淡出、旋转加载动画、进度条
- **成功/错误**：颜色过渡、图标动画、轻柔的缩放脉冲
- **启用/禁用**：透明度过渡、光标变化

### 导航与流程
- **页面过渡**：路由间交叉淡入淡出、共享元素过渡
- **标签页切换**：滑动指示器、内容淡入/滑动
- **轮播/滑块**：平滑变换、吸附点、惯性滑动
- **滚动效果**：视差层、随状态变化的吸顶头部、滚动进度指示器

### 反馈与引导
- **悬停提示**：工具提示淡入、光标变化、元素高亮
- **拖放**：抬升效果（阴影 + 缩放）、放置区高亮、平滑重新定位
- **复制/粘贴**：粘贴时短暂的高亮闪烁、“已复制”确认提示
- **焦点流**：高亮表单或工作流中的路径

### 愉悦时刻
- **空状态**：插图上细微的漂浮动画
- **已完成的操作**：五彩纸屑、对勾的华丽动画、成功庆祝效果
- **彩蛋**：供用户探索发现的隐藏交互
- **情境动画**：天气效果、随时段变化的主题、季节性点缀

## 技术实现

为每个动画使用合适的技术：

### 时长与缓动

**按用途划分的时长：**
- **100-150ms**：即时反馈（按钮按下、开关切换）
- **200-300ms**：状态变化（悬停、菜单展开）
- **300-500ms**：布局变化（手风琴、模态框）
- **500-800ms**：入场动画（页面加载）

**缓动曲线（使用这些，而不是 CSS 默认值）：**
```css
/* Recommended - natural deceleration */
--ease-out-quart: cubic-bezier(0.25, 1, 0.5, 1);    /* Smooth, refined */
--ease-out-quint: cubic-bezier(0.22, 1, 0.36, 1);   /* Slightly snappier */
--ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);     /* Confident, decisive */

/* AVOID - feel dated and tacky */
/* bounce: cubic-bezier(0.34, 1.56, 0.64, 1); */
/* elastic: cubic-bezier(0.68, -0.6, 0.32, 1.6); */
```

**退出动画应比入场动画更快。**使用约入场时长 75% 的时长。

### CSS 动画
```css
/* Prefer for simple, declarative animations */
- transitions for state changes
- @keyframes for complex sequences
- transform + opacity only (GPU-accelerated)
```

### JavaScript 动画
```javascript
/* Use for complex, interactive animations */
- Web Animations API for programmatic control
- Framer Motion for React
- GSAP for complex sequences
```

### 性能
- **GPU 加速**：使用 `transform` 和 `opacity`，避免布局属性
- **will-change**：谨慎添加，仅用于已知开销较高的动画
- **减少绘制**：尽量减少重绘，在适当之处使用 `contain`
- **监控 FPS**：确保目标设备上达到 60fps

### 无障碍
```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

**绝不**：
- 使用弹跳或弹性缓动曲线——它们显得过时，并且会把注意力引向动画本身
- 对布局属性（width、height、top、left）做动画——改用 transform
- 为反馈使用超过 500ms 的时长——会显得迟滞
- 无目的地做动画——每个动画都需要理由
- 忽略 `prefers-reduced-motion`——这是无障碍违规
- 对所有东西都做动画——动画疲劳会让界面令人疲惫
- 在动画期间阻塞交互（除非是有意为之）

## 验证质量

全面测试动画：

- **60fps 流畅**：目标设备上无卡顿
- **感觉自然**：缓动曲线有机自然，而非机械生硬
- **时长恰当**：不太快（生硬）也不太慢（迟滞）
- **减弱动效可用**：动画被适当禁用或简化
- **不阻塞**：用户可以在动画期间/之后进行交互
- **增加价值**：让界面更清晰或更愉悦

记住：动效应当加深理解并提供反馈，而不只是添加装饰。带着目的去做动画，尊重性能限制，并始终考虑无障碍性。优秀的动画是无形的——它只是让一切都感觉恰到好处。
