# 扎实写作

## 核心原则

在产物所支持的范围内，让推理过程清晰可见。以对话式语气，写出清晰、基于证据的内容，然后删去所有臆造、泛泛而谈或仅仅为了模仿某种个性而加入的内容。

## 流程

1. 确认文本是否供用户发布或发送。无论篇幅长短，包括只有一句话的评审意见和回复，都应采用这种风格。不要将其应用于普通的助手回复、引用的源文本或归属于他人的文字。
2. 起草或修改前，先阅读[风格档案](references/style-profile.md)。
3. 明确受众、目的、要求的格式、已提供的事实以及用户的实际立场。保留用户要求的产物形态，不要把每种交付物都改写成博客文章。
4. 在面向公众的开发者文档中，解释可观察到的行为、设置选择、权衡取舍和相关限制。除非正确使用 API 需要，或用户明确要求，否则将实现细节以及测试或诊断细节保留在内部参考资料中。保留公开契约以及理解相关论断所需的背景。这不适用于内部设计文档或技术报告。
5. 写作前解决缺失的材料：
   - 当任务需要研究时，查找可发现的公开事实。
   - 如果缺失的个人观点或经历会实质性地改变文本，询问用户，并停止起草其中相关部分。
   - 如果缺口很小，使用醒目的占位符，或如实说明不确定性。绝不要编造第一人称的论断、结果、偏好或记忆。
6. 根据风格档案选择语体。使长度和正式程度与发布场景相匹配；简短的工作评论应保持简短。
7. 在润色句子前先组织推理。优先说明一个具体问题或观察，解释其机制，用证据或示例加以支持，承认重要的限制，说明实际影响，并以最清晰的要点作结。产物不需要的环节可以省略。对于简短评论，这可能只需要行动要点和一个支持事实。
8. 使用用户的默认语言和地区惯例，除非请求另有说明。保持段落聚焦，交替使用不同长度的句子，仅在有依据时使用第一人称，并让标题发挥实际作用。
9. 进行一次风格编辑，再进行一次事实编辑。删去泛泛的背景铺垫、营销语言、重复的结论、装饰性的口号和没有依据的确定性表述。将标题和开头的论断视为实质内容：删去或限定那些没有得到所提供证据直接支持的宣传性表述。
10. 对于无需修改的评审，说明使现有文本达到可发布标准的关键事实、机制和限定条件。只说“不需要修改”并不能表明已完成事实性和清晰度检查。

## 完成标准

只有在以下所有条件都满足时，才算完成：

- 结果仍符合所要求的格式和目的。
- 每项个人主张和实质性事实均已提供、核实、适当限定，
  或明确标记为缺失。
- 论述足够具体，便于理解，且不含宣传性套话。
- 所包含的任何保留说明都会改变读者的理解，而不仅仅是充当
  免责声明。
- 拼写和语法遵循用户默认语言及所在地区的
  规范。
- 结尾一次收束，不再回顾全文。
- 文本朗读时自然流畅，不堆砌借用的
  表述、反问句、插入语或表情符号。

如果某项检查未通过，请修改草稿。如果问题取决于未知的个人
立场，请询问用户，而不要含糊处理这一缺口。
