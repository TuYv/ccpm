# 有依据的写作

## 核心原则

在产物所支持的尺度上，让推理过程清晰可见。以对话式语气进行清晰、以证据为依据的写作，然后删去任何虚构、泛泛而谈或仅为模仿某种个性而加入的内容。

## 流程

1. 确认文本是供用户发布或发送的。无论篇幅长短，都应用此风格，包括一句话的评审评论和回复。不要将其应用于普通的助手回复、引用的源文本或归属于他人的文字。
2. 起草或修改前，先阅读[风格配置](references/style-profile.md)。
3. 明确受众、目的、所需格式、已提供的事实以及用户的真实立场。保留所要求的产物形态，不要把每项交付内容都改写成博客文章。
4. 写作前解决缺失的材料：
   - 任务需要研究时，查找可发现的公共事实。
   - 如果缺失的个人观点或经历会实质性地改变文本，请询问用户，并停止起草相关部分。
   - 如果缺口较小，请使用醒目的占位符，或诚实地说明不确定性。绝不要虚构第一人称的主张、结果、偏好或记忆。
5. 根据风格配置选择语体。使篇幅和正式程度与使用场景相匹配；简短的工作评论应保持简短。
6. 先组织推理，再润色句子。优先说明一个具体问题或观察，解释其机制，用证据或示例加以支持，承认重要的局限，说明实际影响，并以最清晰的剩余要点作结。产物不需要的阶段可以省略。对于简短评论，这可能只需要可执行的要点和一个支持性事实。
7. 除非请求另有说明，否则使用用户的默认语言和地区惯例。保持段落聚焦，交替使用不同长度的句子，仅在有依据时使用第一人称，并确保标题切实发挥作用。
8. 分别进行一次风格编辑和一次事实编辑。删去泛泛的背景铺陈、营销用语、重复的结论、装饰性的口号以及没有依据的确定性表述。

## 完成检查

仅当以下条件全部满足时才完成：

- 结果仍然满足所要求的格式和目的。
- 每一项个人主张和实质性事实都有来源、经过核实、带有限定，或被清楚标记为缺失。
- 论证足够具体，读者无需宣传性填充内容即可理解。
- 所加入的任何限定都改变了读者的理解，而不是充当免责声明。
- 拼写和语法遵循用户的默认语言和地区惯例。
- 结尾只落点一次，不重复概述全文。
- 朗读时文字听起来自然，没有堆积的借用短语、反问、插话或表情符号。

如果某项检查未通过，请修改草稿。如果问题取决于未知的个人立场，请询问用户，而不是掩盖这一缺口。

## RED/GREEN 代理场景

1. 直接案例：一则两句话的评审回复需要报告修复及其验证结果。RED 会将其扩展成一篇文章，或添加热情洋溢的表达。GREEN 先说明结果，点明相关检查，并将内容控制在两句话以内。
2. 新颖案例：一篇技术教程需要采用更温暖的语气。GREEN 偶尔使用疑问句或插话来引导读者，同时确保说明和代码处于主导地位。
3. 新颖案例：一份技术简报得益于两条来源中的观察。RED 会融合两位作者容易辨认的写作习惯。GREEN 只选取相关的结构性技巧，并保持用户自然的语气。
4. 无需改动的案例：一条单句评审评论已经直接、基于事实且适合其受众。GREEN 会保留原文，而不是扩展它。
5. 反例：用户要求助手为帮助自己理解而解释一个技术概念，而不是代其起草供发表的文本。GREEN 会正常回答，不会代用户引入第一人称表述。
