# 审查页面

通过让两名**对抗性**审查者对已构建的页面进行审查、修复他们发现的问题，并反复重新运行审查，直到新一轮审查结果**全部通过**。每名审查者都是一个子代理，系统提示要求其假设页面*有问题*并寻找证据——绝不敷衍认可。你（编排者）负责获取 Figma、分流问题和修复；审查者只负责报告。这是构建页面的 QA 环节——将其与 `/new-page` 配合使用，或单独针对任意现有页面运行。

按顺序执行这些步骤。每一步结束时都有一个可检查的条件——当前条件满足前，不要开始下一步。

## 步骤 0 — 事实依据

开始任何审查前，你需要准备两样东西：

1. **线上页面。** 启动 `pnpm dev`，加载路由（对于 `en`，去除 locale 后的路由为 `/<route>/`），确认 **HTTP 200**。500 表示构建或资源错误——先修复该问题；页面损坏时没有可审查的内容。
2. **设计来源。** Figma 链接或选区是黄金标准。书面规格可以为文案审查者提供依据，但无法支持像素级设计检查。**完全没有来源 → 文案审查者没有可用于同步的依据；说明这一点，并确认用户是否仍希望仅进行设计系统检查。**

**完成条件：**页面返回 200，并且设计来源已知（或已确认其缺失）。

## 步骤 1 — 获取双方材料

审查者会将*页面的实际渲染结果*与*设计中的规格*进行比较。将两者各获取一次，保存到临时目录，并将路径传给子代理——不要让每个审查者都重新获取 Figma（多次获取之间的读取结果可能发生漂移，而且会消耗速率限制）。

- **设计。** **重新**读取 Figma——绝不要读取更早轮次中的结果：使用 `get_metadata` 获取框架树，使用 `get_screenshot` 获取每个区域的截图，使用 `get_design_context` 获取文本，使用 `get_variable_defs` 获取令牌。保存各区域截图；保留文本和令牌转储。
- **线上页面。** 使用 `playwright-cli` 获取整页截图；对于较长页面，还要获取各分区截图。将它们保存在设计截图旁边。

**完成条件：**设计和线上页面的材料均已保存，并且路径已知。

## 步骤 2 — 启动对抗性审查者

阅读 `reviewers/` 中的两份简报，并**并行**为每份简报启动一个子代理——使用一条消息发起两个 `Agent` 调用。将每个子代理的简报原文、路由以及步骤 1 中的材料路径提供给它们。每个子代理都返回结构化的问题列表——`{location, claim, evidence, fix, severity}`——除此之外不返回任何内容。**审查者只负责报告，绝不编辑**（两个代理并行编辑会发生冲突）。

- `reviewers/copy.md` — 页面上的每一处字符串都必须与 Figma/来源中的文案一致。
- `reviewers/design-system.md` — 组件、间距、标题字号和颜色都必须来自设计系统，不得在基础组件上强行添加自定义 CSS。

**完成条件：**两个子代理都已返回各自的问题列表。

## 步骤 3 — 分流

对抗性审查者的设计目标就是过度报告。**你**必须在修改代码前判断每个问题——保留真实问题，丢弃噪声。有两类调用需要进行判断：

- **有意的文案差异。** 字符串不同可能是因为*设计已过时*，也可能是因为它是模板化或本地化的值——这不一定是文案错误。请根据来源确认，而不是依据审查者的假设。
- **有理由的自定义 CSS。** 在基础组件上*追求像素级一致*的自定义 CSS 属于问题；设计确实需要的自定义 CSS（即设计系统无法表达的一次性需求）则符合“匹配，而非模仿”的原则，可以接受。不要移除设计所需的样式。

向用户以表格形式展示**已确认**的发现——`区域 · 发现 · 修复 · 严重程度`——并标记任何含糊之处，交由用户判断。这是他们了解审查者所见内容的窗口。

**完成标准：**每一项发现都已确认或舍弃，并且已向用户展示确认后的表格。

## 步骤 4 — 修复

自行应用已确认的发现，优先复用——使用变体，而不是自定义 CSS；使用正确的基础组件，而不是重新发明。如果尚未加载，请加载 `design-system` skill，以便使用组件和设计令牌。

**完成标准：**工作树中的每一项已确认发现都已修复。

## 步骤 5 — 重新审查，直到通过

重新捕获**实时页面**（页面已经发生变化；Figma 端没有变化——复用步骤 1 中的设计产物），并重新启动相同的审查者。新一轮对抗式审查返回**零项已确认发现**时，即表示通过。在此之前，持续执行：分类处理 → 修复 → 重新审查。

设置上限：如果循环经过 **3 轮**后仍未通过，则停止，并将顽固的发现交给用户——一个在三次修复后仍然存在的发现，通常需要人工进行设计决策，而不是再进行一次审查。

**完成标准：**新一轮审查通过，或达到 3 轮上限并移交剩余发现。
