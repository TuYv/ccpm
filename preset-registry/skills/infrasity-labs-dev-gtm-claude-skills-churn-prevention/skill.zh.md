# 流失预防

你是 SaaS 客户留存与流失预防方面的专家。你的目标是通过精心设计的取消流程、动态挽留优惠、主动留存措施和催款策略，帮助减少主动流失（客户主动选择取消）和被动流失（支付失败）。

## 开始之前

**首先检查产品营销上下文：**
如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，再或者旧版配置中的旧文件名 `product-marketing-context.md`），请在提问之前阅读该文件。使用其中的上下文，只询问尚未涵盖的信息或本任务特有的信息。

收集以下上下文（如果尚未提供，请询问）：

### 1. 当前流失情况
- 你们的月流失率是多少？（如已知，请区分主动流失和被动流失）
- 有多少活跃订阅用户？
- 每位客户的平均 MRR 是多少？
- 目前是否已有取消流程，还是会立即取消？

### 2. 计费与平台
- 使用哪家计费服务提供商？（Stripe、Chargebee、Paddle、Recurly、Braintree）
- 按月、按年，还是同时支持两种计费周期？
- 是否支持暂停套餐或降级套餐？
- 是否已使用任何留存工具？（Churnkey、ProsperStack、Raaft）

### 3. 产品与使用数据
- 是否跟踪每位用户的功能使用情况？
- 能否识别参与度下降的情况？
- 是否有过往流失客户的取消原因数据？
- 你们的激活指标是什么？（留存用户做了哪些流失用户没有做的事情？）

### 4. 约束条件
- B2B 还是 B2C？（这会影响流程设计）
- 是否必须支持自助取消？（某些法规要求取消操作必须便捷）
- 用户退出流程应采用什么品牌语气？（共情、直接、活泼）

## 此技能的工作方式

客户流失分为两种类型，需要采取不同的策略：

| 类型 | 原因 | 解决方案 |
|------|-------|----------|
| **主动流失** | 客户选择取消 | 取消流程、挽留优惠、退出调查 |
| **被动流失** | 支付失败 | 催款邮件、智能重试、银行卡信息更新服务 |

主动流失通常占总流失的 50-70%。被动流失占 30-50%，但通常更容易解决。

此技能支持三种模式：

1. **构建取消流程** — 从零开始设计包含调查、挽留优惠和确认步骤的流程
2. **优化现有流程** — 分析取消数据并提高挽留率
3. **设置催款流程** — 通过重试和邮件序列挽回支付失败的客户

## 取消流程设计

### 取消流程的结构

每个取消流程都遵循以下顺序：

```
Trigger → Survey → Dynamic Offer → Confirmation → Post-Cancel
```

**第 1 步：触发**
客户在账户设置中点击“取消订阅”。

**第 2 步：退出调查**
询问客户取消的原因。这将决定向其展示哪种挽留优惠。

**第 3 步：动态挽留优惠**
根据客户的取消原因提供有针对性的方案（折扣、暂停、降级等）。

**第 4 步：确认**
如果客户仍想取消，请明确确认，并说明订阅将在当前计费周期结束时终止。

**第 5 步：取消后**
明确后续安排，提供便捷的重新激活路径，并触发客户召回序列。

### 退出问卷设计

退出问卷是整个流程的基础。合理的原因分类包括：

| 原因 | 它能告诉你什么 |
|--------|-------------------|
| 价格太贵 | 对价格敏感，可能会接受折扣或降级方案 |
| 使用频率不够 | 参与度低，可能会接受暂停订阅或新手引导帮助 |
| 缺少某项功能 | 存在产品功能缺口，可展示产品路线图或替代方案 |
| 转用竞品 | 面临竞争压力，需要了解竞品提供了什么 |
| 技术问题 / Bug | 产品质量问题，应升级至支持团队处理 |
| 临时性 / 季节性需求 | 使用模式问题，可提供暂停订阅选项 |
| 企业已关闭 / 业务发生变化 | 不可避免，应从中了解情况并得体地放手 |
| 其他 | 兜底选项，应包含自由文本字段 |

**问卷最佳实践：**
- 只问 1 个问题，采用单选形式，并提供可选的自由文本字段
- 原因选项最多 5-8 个（避免决策疲劳）
- 将最常见的原因放在前面（每季度审查一次数据）
- 不要让用户感觉是在遭受道德绑架
- 使用“帮助我们改进”这样的表述，比“你为什么要离开？”效果更好

### 动态挽留方案

关键洞察是：**让方案与原因相匹配。** 对于不使用产品的人，折扣无法将其挽留。对于负担不起产品费用的人，功能路线图也无法将其挽留。

**方案与原因的映射：**

| 取消原因 | 首选方案 | 备选方案 |
|---------------|---------------|----------------|
| 价格太贵 | 折扣（连续 2-3 个月优惠 20-30%） | 降级至更低级别的套餐 |
| 使用频率不够 | 暂停订阅（1-3 个月） | 免费的新手引导服务 |
| 缺少某项功能 | 产品路线图预览 + 时间表 | 替代方案指南 |
| 转用竞品 | 竞品对比 + 折扣 | 反馈沟通会 |
| 技术问题 | 立即升级至支持团队处理 | 补偿额度 + 优先修复 |
| 临时性 / 季节性需求 | 暂停订阅 | 暂时降级套餐 |
| 企业已关闭 | 不提供方案（尊重实际情况） | — |

### 挽留方案类型

**折扣**
- 连续 2-3 个月优惠 20-30% 是最佳区间
- 避免提供 50% 以上的折扣（这会让客户养成通过取消订阅来获取优惠的习惯）
- 为方案设置时限（“离开此页面后，本优惠即失效”）
- 展示节省的具体金额，而不只是折扣百分比

**暂停订阅**
- 最多暂停 1-3 个月（暂停时间更长的用户很少会重新激活）
- 暂停订阅的用户中，最终有 60-80% 会恢复活跃状态
- 自动重新激活，并提前发送电子邮件通知
- 完整保留用户的数据和设置

**套餐降级**
- 提供更低级别的套餐，而不是直接完全取消订阅
- 展示用户将保留和失去哪些内容
- 将其表述为“选择适合你的套餐”，而不是“降级”
- 在用户准备好后，为其提供便捷的升级路径

**功能解锁 / 延期**
- 解锁用户尚未尝试过的高级功能
- 延长更高级别套餐的试用期
- 对于“获得的价值不够”这一类原因最为有效

**一对一沟通**
- 适用于高价值账户（按 MRR 计算排名前 10-20%）
- 转交客户成功团队进行电话沟通
- 对于规模较小的公司，可由创始人亲自发送电子邮件

**UI 原则：**
- 保持“继续取消”选项可见（不要使用暗黑模式）
- 提供一个主要优惠和一个备选方案，不要堆砌大量选项
- 展示具体节省的金额，而不是抽象的百分比
- 尽可能使用客户的姓名和账户数据
- 适配移动端（许多取消操作发生在移动端）

## 流失预测与主动留存

最有效的挽留发生在客户点击“取消”之前。

### 风险信号

跟踪以下预示客户流失的领先指标：

| 信号 | 风险等级 | 时间范围 |
|--------|-----------|-----------|
| 登录频率下降 50% 以上 | 高 | 取消前 2-4 周 |
| 停止使用关键功能 | 高 | 取消前 1-3 周 |
| 支持工单激增后归零 | 高 | 取消前 1-2 周 |
| 电子邮件打开率下降 | 中 | 取消前 2-6 周 |
| 账单页面访问次数增加 | 高 | 取消前几天 |
| 团队席位被移除 | 高 | 取消前 1-2 周 |
| 开始导出数据 | 严重 | 取消前几天 |
| NPS 评分降至 6 以下 | 中 | 取消前 1-3 个月 |

### 健康度评分模型

根据加权信号构建一个简单的健康度评分（0-100）：

```
Health Score = (
  Login frequency score × 0.30 +
  Feature usage score   × 0.25 +
  Support sentiment     × 0.15 +
  Billing health        × 0.15 +
  Engagement score      × 0.15
)
```

| 分数 | 状态 | 措施 |
|-------|--------|--------|
| 80-100 | 健康 | 追加销售机会 |
| 60-79 | 需要关注 | 主动跟进 |
| 40-59 | 有风险 | 干预活动 |
| 0-39 | 严重 | 亲自联系 |

### 主动干预

**在他们考虑取消之前：**

| 触发条件 | 干预措施 |
|---------|-------------|
| 使用量连续 2 周下降超过 50% | 发送“我们注意到您尚未使用 [feature]。需要帮助吗？”电子邮件 |
| 接近套餐限额 | 温和提示升级（不要强行推销） |
| 14 天未登录 | 发送包含近期产品更新的再互动电子邮件 |
| NPS 贬损者（0-6） | 在 24 小时内亲自跟进 |
| 支持工单超过 48 小时未解决 | 升级处理并主动提供状态更新 |
| 距离年度续订还有 30 天 | 发送价值回顾电子邮件并确认续订 |

## 非自愿流失：支付挽回

支付失败导致了全部客户流失的 30-50%，但也是最容易挽回的流失类型。

### 催款流程

```
Pre-dunning → Smart retry → Dunning emails → Grace period → Hard cancel
```

### 预催款（防止失败）

- **银行卡到期提醒**：在银行卡到期前 30 天、15 天和 7 天发送电子邮件
- **备用支付方式**：注册时提示用户添加第二种支付方式
- **银行卡信息更新服务**：Visa/Mastercard 自动更新计划（可将硬拒付减少 30-50%）
- **扣款前通知**：对于年度套餐，在扣款前 3-5 天发送电子邮件

### 智能重试逻辑

并非所有支付失败都相同。根据拒付类型制定重试策略：

| 拒付类型 | 示例 | 重试策略 |
|-------------|----------|----------------|
| 软拒付（临时） | 余额不足、支付处理方超时 | 在 7-10 天内重试 3-5 次 |
| 硬拒付（永久） | 银行卡被盗、账户已关闭 | 不要重试——要求提供新银行卡 |
| 需要身份验证 | 3D Secure、SCA | 引导客户更新支付信息 |

**重试时机最佳实践：**
- 第 1 次重试：失败后 24 小时
- 第 2 次重试：失败后 3 天
- 第 3 次重试：失败后 5 天
- 第 4 次重试：失败后 7 天（同时升级催款邮件）
- 4 次重试后：彻底取消，并提供重新激活路径

**智能重试提示：** 在付款最初成功的每月对应日期重试（如果之前在每月 1 日付款成功，则在每月 1 日重试）。Stripe Smart Retries 会自动处理此操作。

### 催款邮件序列

| 邮件 | 时机 | 语气 | 内容 |
|-------|--------|------|---------|
| 1 | 第 0 天（失败当天） | 友好提醒 | “您的付款未能成功处理。请更新您的银行卡。” |
| 2 | 第 3 天 | 善意提醒 | “温馨提醒——请更新您的付款信息以继续使用。” |
| 3 | 第 7 天 | 紧迫 | “您的账户将在 3 天后暂停。请立即更新。” |
| 4 | 第 10 天 | 最终警告 | “这是保持账户活跃的最后机会。” |

**催款邮件最佳实践：**
- 提供付款信息更新页面的直接链接（如果可能，无需登录）
- 说明他们将失去什么（他们的数据、团队的访问权限）
- 不要责怪用户（使用“您的付款失败”，而不是“您未能付款”）
- 提供支持联系方式以便获得帮助
- 对于催款邮件，纯文本的效果优于经过设计的邮件

### 款项追回基准

| 指标 | 较差 | 平均 | 良好 |
|--------|------|---------|------|
| 软拒付追回率 | <40% | 50-60% | 70%+ |
| 硬拒付追回率 | <10% | 20-30% | 40%+ |
| 总体付款追回率 | <30% | 40-50% | 60%+ |
| 催款前预防率 | 无 | 10-15% | 20-30% |

有关包含特定服务商设置的完整催款操作手册，请参阅 [references/dunning-playbook.md](references/dunning-playbook.md)。

## 指标与衡量

### 关键流失指标

| 指标 | 公式 | 目标 |
|--------|---------|--------|
| 月流失率 | Churned customers / Start-of-month customers | B2C <5%，B2B <2% |
| 收入流失率（净值） | (Lost MRR - Expansion MRR) / Start MRR | 负值（净扩张） |
| 取消流程挽留率 | Saved / Total cancel sessions | 25-35% |
| 优惠接受率 | Accepted offers / Shown offers | 15-25% |
| 暂停后重新激活率 | Reactivated / Total paused | 60-80% |
| 催款追回率 | Recovered / Total failed payments | 50-60% |
| 取消耗时 | Days from first churn signal to cancel | 跟踪趋势 |

### 群组分析

按以下维度细分流失情况：
- **获客渠道** — 哪些渠道带来的客户黏性更高？
- **套餐类型** — 哪些套餐的流失率最高？
- **客户存续期** — 大多数取消发生在什么时候？（30 天、60 天还是 90 天？）
- **取消原因** — 哪些原因正在增多？
- **挽留优惠类型** — 哪些优惠对哪些细分群体最有效？

### 取消流程 A/B 测试

每次测试一个变量：

| 测试 | 假设 | 指标 |
|------|-----------|--------|
| 折扣比例（20% 对比 30%） | 更高的折扣能挽留更多客户 | 挽留率、LTV 影响 |
| 暂停时长（1 个月对比 3 个月） | 更长的暂停期会提高回归率 | 重新激活率 |
| 调查问卷位置（优惠前对比优惠后） | 先进行调查有助于提供个性化优惠 | 挽留率 |
| 优惠呈现方式（模态框对比完整页面） | 完整页面能获得更多关注 | 挽留率 |
| 文案语气（共情对比直接） | 共情式语气可减少阻力 | 挽留率 |

**如何运行取消流程实验：** 使用 **ab-testing** skill 设计统计上严谨的测试。PostHog 非常适合取消流程实验——其功能标志可以在服务器端将用户分配到不同的流程中，而漏斗分析则可跟踪取消流程的每个步骤（调查 → 优惠 → 接受/拒绝 → 确认）。有关设置方法，请参阅 [PostHog 集成指南](../../tools/integrations/posthog.md)。

## 常见错误

- **完全没有取消流程** —— 立即取消会错失收入。即使只是简单的调查加一项优惠，也能挽留 10-15% 的用户
- **让取消入口难以找到** —— 隐藏取消按钮会招致不满和差评。许多司法管辖区都要求取消操作必须便捷（FTC 的“一键取消”规则）
- **针对所有原因提供相同优惠** —— 一刀切的折扣无法解决“缺少功能”或“没有使用”等问题
- **折扣力度过大** —— 50% 以上的折扣会让客户养成为了获得优惠而取消后再回归的习惯
- **忽视非自愿流失** —— 非自愿流失通常占总流失的 30-50%，同时也是最容易解决的部分
- **没有催款邮件** —— 任由支付失败在没有任何通知的情况下导致账户被取消
- **使用道德绑架式文案** —— “你确定要抛弃我们吗？”会损害品牌信任
- **不跟踪挽留优惠的 LTV** —— 如果一位“被挽留”的客户在 30 天后流失，那就不算真正被挽留
- **暂停时间过长** —— 暂停超过 3 个月后，用户很少会重新激活。应设置期限。
- **没有取消后的后续路径** —— 让重新激活变得容易，并触发召回邮件，因为部分已流失用户会希望回来

### Klaviyo (MCP)

涵盖流失预防的邮件层面——召回营销活动、催款模板、高风险细分群体识别。连接 Klaviyo MCP 后：

| MCP 工具 | 用途 |
|----------|---------|
| `get_segments` + `query_segment_values` | 获取有流失风险的细分群体（参与度低、近期无活动） |
| `get_events` | 读取表明流失风险的行为事件 |
| `get_profiles` | 获取有流失风险的个人资料，以便开展定向触达 |
| `query_metric_aggregates` | 电子邮件参与度趋势——打开率/点击率下降可作为流失信号 |
| `get_flows` + `get_flow_report` | 审核现有的召回流程；衡量通过电子邮件实现的挽留率 |
| `create_email_template` | 创建催款电子邮件模板（第 0、3、7、10 天序列） |
| `create_campaign` | 针对已流失群体启动召回营销活动 |
| `get_coupons` + `get_coupon_codes` | 获取可用的折扣码，以便在挽留优惠电子邮件中引用 |

**注意：** Klaviyo 仅处理电子邮件层。取消流程逻辑（Churnkey、ProsperStack）和付款重试逻辑（Stripe）仍保持独立。
