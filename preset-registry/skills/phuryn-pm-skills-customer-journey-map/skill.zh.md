## 客户旅程地图

绘制从认知到倡导的端到端客户体验，识别每个阶段的情绪、痛点和改进机会。

### 背景

你正在为 **$ARGUMENTS** 创建客户旅程地图。

如果用户提供了文件（访谈记录、调查数据、分析数据、支持工单或现有的旅程地图），请先阅读这些文件。如果提供了 URL，请使用 Web 搜索了解该产品。

### 说明

1. **定义用户画像**：是谁在经历这段旅程？使用包含 JTBD 的具体用户画像，而不是泛泛的用户。

2. **绘制旅程阶段**（根据产品进行调整）：

   | 阶段 | 描述 |
   |---|---|
   | **认知** | 他们最初如何了解到该产品？ |
   | **考虑** | 他们会评估什么？会比较哪些替代方案？ |
   | **获取** | 他们如何注册或购买？ |
   | **上手** | 初次使用产品的体验——实现价值所需的时间 |
   | **互动** | 日常使用——培养习惯 |
   | **留存** | 什么会促使他们持续使用？什么可能导致用户流失？ |
   | **倡导** | 他们会在何时以及为何向他人推荐该产品？ |

3. **记录每个阶段的以下信息**：

   - **触点**：用户与产品、品牌或团队互动的渠道（网站、电子邮件、应用内、客户支持、社交媒体）
   - **用户行为**：他们在此阶段会做什么
   - **想法与问题**：他们在想什么（“这值得我花时间吗？”“我该如何……”）
   - **情绪**：他们的感受（兴奋、困惑、沮丧、愉悦）——使用量表评分或表情符号表示
   - **痛点**：阻碍、困惑和流失风险
   - **机会**：如何改进此时的体验

4. **识别关键时刻**：
   - **顿悟时刻**：用户首次体验到核心价值的时刻
   - **关键决策时刻**：用户决定继续投入或放弃的决策节点
   - **流失触发因素**：用户最常在哪些环节流失

5. **创建旅程地图表格**：

   | 阶段 | 触点 | 用户行为 | 情绪 | 痛点 | 机会 |
   |---|---|---|---|---|---|

6. **提出按优先级排序的改进建议**：
   - 哪些痛点对转化或留存的影响最大？
   - 哪些快速见效的措施可以立即改善体验？
   - 哪些措施需要更深入的投入，但能带来最大的回报？

逐步思考。保存为 markdown 文档。对于可视化旅程地图，建议用户以此分析为基础，在 Miro 或 FigJam 中创建。
