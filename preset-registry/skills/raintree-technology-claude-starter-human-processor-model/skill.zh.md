# 人类处理器模型

使用此技能从具体任务出发，快速做出明确的可用性估算。目标不是虚假的精确性，而是揭示感知、认知、记忆或动作在哪些环节使流程变慢或变得脆弱。

## 输入

收集或推断以下信息：

- 目标用户及相关约束：新手/专家、老年人、运动障碍、低视力、压力、被打断的风险。
- 明确的任务目标与成功状态。
- 当前方法：界面、控件、标签、数据录入、导航路径和反馈。
- 备选方法（如果用户希望进行对比）。

如果未提供 UI，请索取能够决定步骤的最小缺失材料：截图、路由、原型、任务列表或当前实现路径。

## 工作流程

1. 定义一个狭窄的任务，例如“为订单 1042 创建退款”，而不是“使用计费应用”。
2. 写出从起始状态到成功状态的用户可观察步骤。
3. 将每个步骤拆解为感知、认知、动作和记忆操作。
4. 在计算前说明假设：用户专业程度、阅读负荷、设备、输入方式、无错误路径，以及信息是否可以保持可见。
5. 使用下方的默认值估算每个操作，仅当界面或用户群体有充分理由时才进行调整。
6. 将时间求和，并将瓶颈与数字总计分开指出。
7. 推荐能够移除整个操作、保持所需信息可见、减少模式切换或让反馈即时的变更。

## 默认估算值

将这些用作粗略的规划常数：

| 操作 | 默认值 |
|---|---:|
| 眼球移动或视觉目标获取 | 230 ms |
| 感知处理器周期 | 100 ms |
| 认知处理器周期 | 70 ms |
| 动作处理器周期 | 70 ms |
| 视觉图像存储半衰期 | 200 ms |
| 听觉存储半衰期 | 1500 ms |
| 工作记忆有效容量 | 5-9 个组块 |
| 工作记忆实际容量 | 约 3 个组块 |

当 UI 描述不足或用户群体会改变估算结果时，使用区间而非单一数值。年长、分心、有障碍或不熟悉的用户通常需要更慢的周期假设和更多的恢复时间。

## 记忆风险

当用户必须记住以下内容时，标记记忆风险：

- 超过 3 个不相关的组块。
- 在使用前就消失的数值。
- 在继续阅读或导航期间需要记住的代码、日期、姓名或标识符。
- 隐藏在先前文案中的决策规则。

当回忆概率估算有用时，除非任务提供了明确的流逝时间和已知的记忆类型，否则对衰减进行定性建模。优先采用设计修复而非数学计算：保持源值可见、在目标位置附近复制一份，或将回忆转换为再认。

## 输出

对于审计，将回答按以下结构组织：

- 已建模的任务。
- 假设。
- 包含操作类型、估算值和问题的步骤表。
- 最佳估算总值或区间。
- 最主要的瓶颈。
- 按移除的操作数或降低的记忆负担排序的设计变更。

对于对比，在相同假设下展示两种方法，并突出操作数量的差异，而不仅是最终时间。

## 护栏

- 不要将估算值当作研究结果来呈现。
- 不要编造实证验证。
- 当安全性、信心、可访问性或防错更重要时，不要只针对速度进行优化。
- 如果流程风险很高，建议在模型缩小假设范围之后观察真实用户。
