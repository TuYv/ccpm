# 无障碍

如果使用平台提供的功能，大多数无障碍支持都是免费的。原生元素自带键盘支持，真正的标签会被自动播报，而可见的焦点环只需一条 CSS 规则即可实现。

将每项修复都写入项目的样式系统，并使用下方的确切值，而不是看起来相近的常用替代值。

审查分为两轮。第一轮仅使用键盘，确保每个流程都能在不使用鼠标的情况下完成。第二轮使用屏幕阅读器，确保每个控件都会播报名称、角色和状态。不确定时，优先采用平台默认行为，而不是自定义重建；与其添加 ARIA，不如移除 ARIA。

对比度测量和颜色修复属于 `better-colors`。文本大小和 iOS 输入框缩放属于 `better-typography`。空间上的 RTL 布局属于 `better-layout`。

## 优先使用原生元素

ARIA 的第一条规则：存在原生元素时不要使用 ARIA。操作使用 `<button>`，导航使用 `<a href>`，绝不要使用 `<div onClick>`。真正的链接必须支持 Cmd/Ctrl/中键点击。错误的 ARIA 不如不使用 ARIA。有关地标、按钮与链接的区别以及禁用状态，请参阅 [semantics-and-aria.md](semantics-and-aria.md)。

## 可见的焦点环

为 `:focus-visible` 设置样式，而不是使用单独的 `:focus`。键盘用户会看到焦点环，而鼠标用户通常不会看到。优先使用浏览器未经修改的指示器。

自定义焦点环需要项目的焦点令牌或其他明确的颜色。验证整个指示器与其跨越的每一种相邻颜色之间的对比度，包括 `currentColor`。至少使用 `2px` 的实线周长，或具有同等可见面积的方案。没有经过验证的替代方案时，绝不要使用 `outline: none`，并在强制颜色模式下保留系统颜色。相关方案请参阅 [focus-and-keyboard.md](focus-and-keyboard.md)。

## 完整的键盘支持

每个指针交互都需要对应的键盘操作路径。遵循 ARIA APG 模式：Escape 关闭叠加层，方向键在复合控件内移动，Tab 在控件之间移动，Enter 和 Space 执行操作。

只使用 `tabindex="0"` 加入自然 Tab 顺序，使用 `tabindex="-1"` 进行程序化聚焦。正值会破坏该顺序。复合控件使用 roving tabindex：当前活动项为 `0`，其他每一项都为 `-1`。

## 捕获并恢复焦点

模态框在背景内容上设置 `inert`，打开时将焦点移入其中，关闭时将焦点返回触发控件。添加 `overscroll-behavior: contain`，避免背景内容滚动。

## 最小点击区域

WCAG 2.5.8 的 AA 级基线是 24×24 CSS 像素的目标区域，或满足其间距、等效控件、行内、用户代理和必要例外之一。在触摸设备上以 44×44px 为目标，在桌面设备上则在密度允许的情况下以 40×40px 为目标。当可见元素应保持较小时，使用伪元素扩展点击区域。

绝不要让扩展后的点击区域相互重叠。为装饰层设置 `pointer-events: none`，这样光晕就不会吞掉原本要传递给下方控件的点击。尺寸和碰撞规则请参阅 [hit-areas.md](hit-areas.md)。

## 为每个控件添加标签并设置类型

每个输入控件都需要 `<label for>` 或包裹它的 `<label>`。占位符永远不能作为标签。标签和控件应共享一个点击目标，复选框与其文本之间不能存在无法点击的空白区域。

添加 `autocomplete` 和有意义的 `name`，再加上能够调出正确键盘的 `type` 和 `inputmode`。绝不要阻止粘贴；用户会粘贴密码和一次性验证码。参见 [forms.md](forms.md)。

## 能够播报的错误

在请求开始前保持提交按钮可用；请求开始后再禁用按钮，同时显示 spinner 并保留原始标签。提交时进行验证。将失败字段标记为 `aria-invalid="true"`，让 `aria-describedby` 指向内联错误文本，并将焦点移到第一个无效字段。

当控件确实不可用时，使用原生的 `disabled`。只有在控件应保持可聚焦时，才使用 `aria-disabled="true"`；然后在代码中阻止指针、键盘和表单行为，并明确设置该状态的样式。

## 处处提供可访问名称

只有图标的按钮需要描述性的 `aria-label`。可见的标签文本必须出现在可访问名称中。装饰性元素应设置 `aria-hidden="true"`，绝不要将其设置在可聚焦元素上。

## 不要只依赖颜色

状态需要冗余提示：在颜色之外，同时提供图标、文本或下划线。确定适用哪项 WCAG 对比度要求，然后使用 `better-colors` 测量渲染后的颜色对。如果不符合要求，报告该颜色对及其未满足的要求；除非有人要求，否则不要改动颜色。

## 遵循 prefers-reduced-motion

将动画包裹在 `@media (prefers-reduced-motion: no-preference)` 中，使其成为选择启用的功能。在减少动画的情况下，用透明度交叉淡化替代滑动和缩放，并彻底停用视差和自动播放。

无论用户偏好如何，以下两条规则始终适用。自动播放的媒体需要提供可见的暂停控件；携带操作或错误信息的 toast 则应一直显示，直到用户将其关闭。参见 [motion-and-zoom.md](motion-and-zoom.md)。

## 播报动态内容

三种机制，各司其职。`aria-describedby` 用于承载字段级验证信息。礼貌式 live region（`role="status"`）用于承载与控件无关的非紧急更新，例如 toast 和结果数量。`role="alert"` 用于承载与控件无关的紧急错误，除此之外不要用于其他内容。

重复的礼貌式播报需要一个稳定的空区域，并且该区域应在其文本更新前就已渲染。动态插入的 alert 在不同环境中的支持情况各异，因此要在目标屏幕阅读器上进行测试。参见 [screen-readers.md](screen-readers.md)。

## 根据用途提供替代文本

装饰性图片使用 `alt=""`。信息性图片描述其含义。功能性图片描述其操作：搜索图标按钮应使用 `alt="Search"`，而不是 `alt="magnifying glass"`。

## 结构就是导航

使用能够描述所属区块并形成连贯大纲的标题。页面应有一个 `<h1>`，其下各级标题按层级嵌套，不要跳级。提供一个可见的主 `<main>` landmark。当重复的导航或页面框架位于其前方时，将“跳转到内容”链接作为第一个可聚焦元素。锚定标题应设置 `scroll-margin-top`。

## 经受住缩放和文本调整

页面必须在 200% 缩放下正常工作，并在 320px 宽度下重新排版，且不得出现水平滚动。在文本容器上使用 `min-height`，而不是固定的 `height`。在适合代码库的情况下，优先使用 `rem` 断点，并且绝不要让 viewport meta 限制读者能够缩放的幅度。

## 完成前

| 错误 | 修复 |
| --- | --- |
| 假定自定义焦点颜色在任何地方都有效 | 针对每个相邻颜色以及强制颜色模式进行验证 |
| 重复的礼貌提示更新播报不一致 | 保持一个稳定的空状态区域，并更新其文本 |
| 将 `assertive` 实时区域用于常规 toast | 使用 `polite`；将 `assertive` 保留给错误 |
| 在可聚焦元素上设置 `aria-hidden="true"` | 移除它，或使该元素不可聚焦 |
| 直到表单有效才启用提交按钮 | 保持按钮启用；在提交时进行验证，并将焦点移至第一个错误 |
| 触摸操作后悬停样式仍然保持 | 使用 `@media (hover: hover)` 控制悬停样式 |
| 在原生 `disabled` 控件上使用工具提示 | 在控件旁显示文本，或使用 `aria-disabled` 使其保持可聚焦 |

## 报告

**严重性。** `HIGH` 会阻止任务、使辅助技术无法访问内容，或造成系统性故障。`MEDIUM` 会显著增加交互难度。`LOW` 是局部的细节优化。

**验证。** 无需浏览器：检查每个交互元素是否具有可访问名称、非原生控件是否具有键盘处理器、焦点样式、`prefers-reduced-motion` 防护，以及表单标签是否与其输入框绑定。使用浏览器时：按顺序通过 Tab 键操作整个流程，从无障碍树中读取计算后的名称和角色，确认每个停留位置都有可见的焦点指示器，并运行自动化审计。对于无法运行的每项检查，报告为 `Not verified`。

**格式。** 按每项违反的原则对发现的问题分组，按严重性排序；每个根本原因占一行，并列出其出现的所有位置：

| 严重性 | 位置 | 修改前 | 修改后 | 原因 |
| --- | --- | --- | --- | --- |

`Location` 的格式为 `path/to/file:line`。`Why` 应说明违反的原则以及对用户造成的影响。

只要仍有任何 `HIGH`，结尾就使用 `Block`；否则使用 `Approve`，同时将其余问题保留在表格中作为待完成工作。对于未检查的覆盖范围，绝不能使用 `Approve`。如果没有需要报告的内容，请写明 "No actionable accessibility findings"，并报告验证结果。
