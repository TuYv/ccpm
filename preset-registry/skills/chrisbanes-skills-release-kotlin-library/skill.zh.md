# 发布 Kotlin 库

## 核心原则

发布已准备并经过校验的发布提交，只有在验证其产物和 Git 状态之后，
才宣布发布完成。

## 前提条件

本技能依赖 `gradle-maven-publish-plugin`（`com.vanniktech.maven.publish`）
进行库发布，无论是本地运行还是通过标签触发的 CI。
API 快照支持假定存在由 Metalava 生成的 `api/api.txt` 文件；当仓库
不维护这些文件时，请禁用快照。

## 流程

1. 确定范围，并检查仓库说明、Git 状态、发布历史、版本属性、
   发布配置和必需的检查。确认已发布的模块直接或通过约定插件应用了
   `com.vanniktech.maven.publish`。仅有声明而未应用是不够的。如果
   缺失或未经核实，报告未满足的前提条件，并在进行发布变更之前停止；
   不要安装或迁移发布插件。区分就绪审查、准备请求和明确的发布授权。
   保持审查请求为只读，包括凭据。遵循现有的本地或 CI 发布机制；
   不要迁移它。在配置捆绑脚本之前，先阅读
   [助手契约](references/helper.md)。对于不支持的布局或目标不明确的情况，
   在变更之前停止。
2. 使用标签约定和祖先关系确定上一个适用的发布。基准不明确时需要
   加以解决，而不是猜测字典序最高的标签。使用提供的发布版本和
   下一个开发版本。在变更之前，针对每个缺失的值提出建议并加以确认；
   不要将预发布版本静默递增为下一个补丁快照。
3. 如果存在 `CHANGELOG.md`，将其 `Unreleased` 部分与基准以来的完整
   变更进行比较：检查历史、差异以及相关 issue 或 PR 的证据。保留
   精心撰写的措辞，补充缺失的对使用者可见的变更，更正不准确的条目，
   并省略对使用者没有影响的纯内部变更。在发布之前解决不确定的覆盖
   范围。报告已审查的范围和未解决的差距；仅检查标题无法证明语义上的
   完整性。保留现有格式和先前的发布条目。如果文件不存在，跳过此步骤，
   不要创建它。在调用准备之前，仅提交经授权的变更日志更正，
   以便其干净工作树门禁得以满足。
4. 识别仓库的发布检查，包括测试以及已配置情况下的 Metalava API
   生成和兼容性检查。在生成快照之前确认 API 文件是最新的；助手会
   复制它们而不运行 Metalava。不要将其他 API 转储格式视为 Metalava
   快照。要求发布代码具备通过的证据；在发生相关变更之后，仅父提交
   显示为绿色是不够的。对于 Gradle 执行，使用
   [gradle-run](../gradle-run/SKILL.md)，除非明确授权扫描，否则加上
   `--no-scan`。在授权范围内修复失败的检查；否则停止，并说明未通过
   的门禁和下一步行动。
5. 使用明确的版本、路径、标题样式、API 快照适用性、分支、远程、
   标签和命令参数来配置助手并执行预检。将配置和证据保留在受跟踪的
   发布文件之外。在写入之前检查索引、快照冲突以及本地/远程目标。
   对于本地发布，将 `~/.env` 作为数据加载，绝不通过 shell sourcing
   或打印的方式使用它。保留显式设置的进程环境值。缺少必需的凭据会
   阻止本地发布；不要请求或记录其值。对于标签触发的 CI，使用现有的
   Git 身份验证和由 CI 管理的发布密钥，不加载也不要求本地 dotenv 值。
6. 准备发布：更新版本，最终确定变更日志标题和适用的已发布模块 API
   快照，运行配置的检查，并仅提交发布文件。检查生成的提交。将验证
   证据绑定到此状态，并在相关代码发生变更时使其失效。助手在准备期间
   不得执行发布。
7. 当发布获得授权且所有门禁通过时，通过仓库选定的机制从该提交进行
   发布。本地发布和标签触发的 CI 是二选一的备选方案；不要两者都运行。
   明确的发布请求不需要多余的最终批准。仅要求准备的请求在准备完成的
   状态即停止。
8. 在配置的目标位置验证所有预期的产物坐标和版本，以及适用时的 CI
   完成情况。验证远程标签解析到准备好的提交。仅凭成功的命令或标签
   并不构成产物证据。只有在此时，才推进、提交、推送并验证商定的
   下一个开发版本。仅当仓库惯例有此要求时，才使用最终确定的发布说明
   创建并回读 GitHub Release。
9. 在部分成功或结果不确定的情况下，停止依赖性变更，并在不含密钥的
   情况下报告已验证、失败和未知的阶段。在恢复之前，检查实时的产物、
   工作流、标签和分支状态；绝不盲目重复发布、覆盖远程标签、删除已
   发布的产物或声称已回滚。仅在现有授权范围内恢复已被证实可行的剩余
   操作。

## 完成门禁

报告发布版本、发布提交/标签、验证证据、产物回读结果、下一个开发提交
以及视情况而定的 GitHub Release URL。只有当每项适用的检查都通过时，
才可声称完成。对于审查、准备或受阻的工作，请明确说明该较窄范围的
结果以及剩余的门禁。不要暴露凭据内容或原始的敏感命令输出。
