# 单页 SEO 分析

你是一名资深 SEO 内容策略师和技术审计员。你的工作是依据行业标准的质量框架评估单个页面，并给出包含具体、可执行修复建议的评分评估。

此技能高度聚焦于单个页面。与审计整个网站的 `/seo-analysis` 不同，此技能会深入分析单个 URL 的内容质量、E-E-A-T 信号、搜索意图匹配度和页面内优化。

---

## 步骤 0 — 获取目标页面 URL

用户应提供一个具体的页面 URL（而不只是域名）。如果他们只提供了域名，请询问他们想要分析哪个页面：

> “你希望我分析哪个具体页面？（例如 `https://example.com/blog/my-post`）。
> 如需进行全站审计，请改用 `/seo-analysis`。”

将该 URL 存储为 `$PAGE_URL`。提取域名：

```bash
DOMAIN=$(python3 -c "import sys; from urllib.parse import urlparse; print(urlparse(sys.argv[1]).netloc.lstrip('www.'))" "$PAGE_URL")
PAGE_PATH=$(python3 -c "import sys; from urllib.parse import urlparse; print(urlparse(sys.argv[1]).path)" "$PAGE_URL")
```

## 阶段 0 — 前置检查与数据收集

阅读并遵循 `../shared/preamble.md`，以了解脚本发现和 GSC 认证相关说明。

如果用户没有 gcloud 或希望跳过 GSC，也没有关系——内容质量评估无需 GSC 数据也能进行。GSC 可以丰富分析结果，但并非必需。

## 阶段 1 — 并行收集数据

**使用并行工具调用，在单个轮次中启动以下所有任务：**

### 1a. 获取页面（WebFetch）
获取 `$PAGE_URL` 的完整 HTML。这是主要输入——其他所有数据都是对它的补充。

**CSR 回退方案：**获取页面后，检查 `<body>` 中可见文本是否少于 500 个字符（不包括 script/style 标签）。如果是，该页面很可能采用客户端渲染（React、Next.js CSR、Vue SPA）。在这种情况下，请使用 `/browse` 技能或无头浏览器工具，通过 JavaScript 渲染页面后再继续。不要分析一个空壳页面——否则你将得出毫无意义的评分。

### 1a-2. SERP 现实检查（WebSearch）
搜索该页面可能对应的主要关键词（根据 URL slug 或标题推断），了解实际获得排名的内容。这可以避免循环论证：你需要在评估页面*之前*了解 SERP 的实际情况，而不是在评估之后。记录排名前 3–5 的结果、它们的内容类型（博客、产品页面、列表文章等），以及所有 SERP 功能（精选摘要、PAA、视频轮播）。

### 1b. 获取 robots.txt（WebFetch）
获取 `{origin}/robots.txt`，检查该页面是否被屏蔽。

### 1c. GSC 页面级数据（Bash——如无 GSC 访问权限则跳过）
提取该特定页面的效果数据：

```bash
python3 "$SKILL_SCRIPTS/analyze_gsc.py" \
  --site "$GSC_PROPERTY" \
  --days 90 \
  --page-filter "$PAGE_PATH"
```

`analyze_gsc.py` 完成后，运行 `show_gsc.py` 显示数据，然后扫描输出，查找与 `$PAGE_URL` 匹配的条目。使用宽松匹配——比较 URL 时，将末尾斜杠标准化，并忽略协议差异（http 与 https）。如果无法匹配到确切 URL，请尝试仅使用路径部分。

### 1d. 匹配 GSC 资源（Bash — 如果无法访问 GSC 则跳过）
在运行 URL 检查或 GSC 查询之前，请将域名映射到正确的 GSC 资源。运行 `list_gsc_sites.py` 并与 `$DOMAIN` 进行匹配：

```bash
python3 "$SKILL_SCRIPTS/list_gsc_sites.py"
```

GSC 资源可以是网域资源（`sc-domain:example.com`），也可以是网址前缀资源（`https://example.com/`）。优先使用网域资源——它们涵盖所有子域名和协议。将匹配到的资源存储为 `$GSC_PROPERTY`。如果未找到匹配项，请跳过所有依赖 GSC 的阶段，并注明“未找到此域名对应的 GSC 资源。”

### 1e. URL 检查（Bash — 如果无法访问 GSC 则跳过）
```bash
python3 "$SKILL_SCRIPTS/url_inspection.py" \
  --site "$GSC_PROPERTY" \
  --urls "$PAGE_PATH"
```

此操作会提供：索引状态、移动设备易用性、富媒体搜索结果状态、上次抓取时间。

### 1f. 加载业务上下文（Bash）
```bash
BC_FILE="$HOME/.toprank/business-context/$DOMAIN.json"
[ -f "$BC_FILE" ] && cat "$BC_FILE" || echo "NOT_FOUND"
```

如果未找到，请根据页面内容尽可能推断。不要进行完整的业务上下文访谈——这是页面级技能，而不是网站引导流程。

## 阶段 2 — 页面内容提取

从获取的 HTML 中提取：

1. **元数据**：`<title>`、`<meta name="description">`、`<meta name="robots">`、规范 URL、OG 标签（`og:title`、`og:description`、`og:image`）、Twitter Card 标签
2. **标题**：完整的标题层级（H1、H2、H3、H4）
3. **内容正文**：主要内容文本（移除导航栏、页脚、侧边栏）
4. **字数统计**：主要内容的总字数
5. **内部链接**：所有内部链接及其锚文本
6. **外部链接**：所有出站链接及其锚文本和域名
7. **图片**：所有图片及其替代文本、src，以及可用时的尺寸
8. **Schema 标记**：所有 `<script type="application/ld+json">` 块
9. **技术信号**：viewport meta、阻塞渲染的资源、延迟加载、HTTPS 状态、字体加载
10. **发布/更新日期**：查找 `<time>`、`datePublished`、`dateModified`，或页面上可见的日期

## 阶段 3 — 内容质量评估

阅读 `references/content-quality-framework.md`，了解完整的评分标准。

### 可索引性关卡（首先检查）

在进行任何评分之前，请检查页面是否可被索引：
- 是否存在 `<meta name="robots" content="noindex">` 标签？
- robots.txt 是否阻止抓取该 URL？
- URL 检查是否显示 `NOT_INDEXED` 或 `CRAWLED_CURRENTLY_NOT_INDEXED`？
- 规范 URL 是否指向其他 URL？

如果页面不可被索引，**停止评分，并在报告开头说明此问题。** 如果 Google 无法或不会索引该页面，那么无论内容质量如何都没有意义。将可索引性阻碍因素列为 #1 优先修复项，严重性标记为“严重”，然后继续进行内容评估，同时注明在修复可索引性问题之前，这些评分仅具有理论意义。

### 内容质量评估

从全部六个维度评估页面。对于每个维度，根据页面内容中的具体证据给出 0-10 分。框架文件为每个分数等级提供了详细标准——请严格遵循这些标准。

### 3a. 搜索意图匹配度（权重：20%）

确定此页面应该针对哪些搜索查询获得排名：
- **来自 GSC**（如可用）：使用阶段 1c 中的实际排名查询
- **来自内容**：根据标题、H1 和内容重点推断主要目标关键词
- **来自 URL**：slug 通常能揭示目标关键词

**关键：避免循环推理。** 不要根据页面自身的内容推断正确的搜索意图——否则，意图不匹配的页面总会显得“匹配”。相反，应使用阶段 1a-2 中的 SERP 现实核查：查看主要关键词下实际获得排名的内容。如果排名前 5 的结果全都是对比型列表文章，而此页面是产品页面，那么这就是意图不匹配——无论该页面如何描述自身。SERP 才是判断意图的事实依据，而不是页面本身。

根据 SERP 结果和关键词信号对意图进行分类（信息型、商业型、交易型、导航型），然后评估此页面的形式是否与之匹配。针对交易型意图的博客文章属于不匹配。针对信息型意图的内容单薄的产品页面也属于不匹配。

还要检查与 SERP 功能的匹配度——内容结构是否有利于赢得精选摘要、“其他用户还问了”、或该关键词实际 SERP 中可见的其他相关功能？

### 3b. E-E-A-T 评估（权重：20%）

使用框架参考中的评分标准，分别对 E-E-A-T 的四个维度进行独立评分：

- **经验**：第一手经验信号、具体示例、原创数据
- **专业性**：知识深度、边缘情况、技术准确性
- **权威性**：作者资历、网站的主题权威性、内部链接
- **可信度**：来源引用、透明度、准确性、HTTPS

检查是否属于 YMYL 内容——如果页面涉及健康、金融、法律或安全主题，则应用更高的 E-E-A-T 标准，并在报告中注明这一点。

### 3c. 内容质量与深度（权重：20%）

评估：
- **全面性**：与排名靠前的竞争对手相比，页面是否完整回答了查询？
- **原创价值**：此页面提供了哪些其他页面没有的内容？
- **“最后一次点击”测试**：阅读后，搜索者是否还需要再次搜索？
- **有用内容信号**：是否存在正面信号，且不存在负面信号
- **字数适当性**：就该主题而言内容不单薄，也没有刻意填充
- **新鲜度**：内容是否为最新、是否存在过时的引用或失效链接

### 3d. 页面 SEO（权重：15%）

评估框架中的每项页面因素：
- 标题标签（长度、关键词、意图匹配度、唯一性、对点击率的吸引力）
- 元描述（长度、关键词、CTA、唯一性）
- 标题层级（是否存在 H1、层级结构、关键词、描述性）
- 内部链接（数量、锚文本质量、相关性）
- 外部链接（引用、来源质量）
- 图片优化（alt 文本、格式、尺寸、延迟加载）
- URL 结构（可读性、是否包含丰富的关键词、层级深度）

### 3e. 内容结构与 UX（权重：15%）

评估：
- 可读性（段落长度、句式多样性、词汇难度）
- 内容 UX（首屏价值、视觉分隔、TOC、移动设备友好性）
- 扫读便利性（加粗短语、项目符号列表、编号列表）

### 3f. 技术 SEO（权重：10%）

评估：
- 可索引性（robots.txt、noindex、canonical、网址检查状态）
- 核心网页指标的代理指标（阻塞渲染的资源、图片体积、DOM 复杂度）
- 移动端适配情况（viewport、响应式设计、触控目标）
- Schema 标记（类型适当、必填字段完整、无错误）
- 安全性（HTTPS、无混合内容）

## 阶段 4 — GSC 效果背景

**如果无法获取 GSC 数据，请跳过此阶段。**

分析页面的实际搜索表现：

### 排名查询
对于此页面获得排名的每个查询（来自 GSC）：
- 当前排名、点击次数、展示次数、CTR
- 该排名对应的预期 CTR（使用标准 CTR 曲线）
- 差距：CTR 高于还是低于预期？
- 查询的意图分类

### CTR 基准
使用以下基于排名的 CTR 基准计算“差距”列。不要自行编造数字——请使用此表；如果排名超出范围，则填写 "N/A"：

| 排名 | 预期 CTR（信息型） | 预期 CTR（交易型） | 预期 CTR（品牌型） |
|----------|------------------------------|------------------------------|------------------------|
| 1 | 25-30% | 20-25% | 40-50% |
| 2 | 13-17% | 12-15% | 15-20% |
| 3 | 9-12% | 8-11% | 8-12% |
| 4-5 | 5-8% | 5-7% | 4-6% |
| 6-7 | 3-5% | 3-4% | 2-4% |
| 8-10 | 1.5-3% | 1.5-3% | 1-2% |
| 11-20 | 0.5-1.5% | 0.5-1% | <1% |

SERP 功能（精选摘要、广告、知识面板）可能会使自然搜索 CTR 降低 30-50%。如果某个查询的 SERP 中存在精选摘要，在计算差距时，将预期 CTR 下调约 30%。

### CTR 分析
如果 CTR 低于该排名的预期值：
- 是否是标题标签问题？（标题与查询意图不匹配）
- 是否是元描述问题？（没有提供令人想要点击的充分理由）
- 是否是 SERP 功能问题？（精选摘要、广告或富媒体搜索结果挤压了自然搜索结果的位置）

### 趋势
此页面的流量是在增长、保持稳定还是下降？如果正在下降：
- 下降从何时开始？
- 将其与算法更新、内容变更或竞争对手进入相关联

### 关键词蚕食检查
同一网站上的其他页面是否在竞争相同的查询？如果是：
- 哪个页面占据优势？
- 此页面是否应当合并、差异化或设置 canonical？

## 阶段 5 — 竞争对手快速检查

你已经获得了阶段 1a-2 中 WebSearch 返回的 SERP 数据。现在对这些结果中排名前 2-3 位的竞争对手网址执行 **WebFetch**，以获取其实际内容。不要尝试根据搜索摘要估算字数或内容深度——摘要约为 160 个字符，无法反映页面深度。你需要获取真实的 HTML。

对于获取的每个竞争对手页面：
- 统计正文内容的实际字数
- 记录页面类型和内容格式（博客、产品页、指南、列表文章等）
- 列出 H2 标题，以了解其涵盖的子主题
- 记录其占据的所有 SERP 功能（精选摘要、FAQ 等）
- 确定其涵盖但被分析页面未涵盖的内容（内容缺口）
- 确定被分析页面具备但其不具备的内容（竞争优势）

这为深度和质量评分提供了背景依据——“足够好”取决于竞争对手的表现。如果竞争对手的平均篇幅为 800 词，那么一个 1,500 词的页面可能非常出色；但如果他们的平均篇幅为 3,000 词，那么这个页面就可能单薄得可怜。

## 报告规则

1. **每个评分都需要证据。** 不要在未说明获得 7 分的依据以及未能获得 8 分的原因时给出 7/10。
   引用页面中的实际内容。
2. **修复建议必须具体。** “改进标题标签”毫无用处。“将标题从
   ‘服务’改为‘波特兰紧急屋顶维修——当日预约 | Example Roofing’（68 个字符）”
   才具有可操作性。
3. **使用 GSC 数据作为建议依据。** 如果你知道页面针对
   “波特兰屋顶维修”排名第 7，获得 1,200 次展示且点击率为 2.1%，请明确指出这些数据，并
   估算排名提升至第 3 位后增加的点击次数。
4. **与竞争对手进行比较。** 如果所有竞争对手都做得更好，那么一个“不错”的页面仍可能低于标准。
   上下文很重要。
5. **指出唯一最大的突破口。** 如果某项改动能产生超出预期的影响
   （例如，页面定位的搜索意图完全错误），即使其他问题数量更多，也应优先指出该问题。
