# visionOS 设计指南

基于 Apple 人机界面指南的 Apple Vision Pro 综合设计规则。这些规则可确保空间计算 App 舒适、直观，并与平台惯例保持一致。

---

## 1. 空间布局 [关键]

空间布局决定用户的舒适度和可用性。不当的放置会导致颈部疲劳、方向感迷失或内容难以访问。

### 规则

**SL-01：将内容置于视野中央。**
将主要窗口和内容放置在用户正前方，与视线齐平。舒适的垂直观看范围大约是视线水平上下各 30 度。查看超出此范围的内容需要移动头部，并会导致疲劳。

**SL-02：保持舒适的距离。**
将内容放置在距离用户自然舒适的位置，窗口通常为 1-2 米。内容太近会让人感觉受到侵扰；太远则难以阅读。系统默认放置距离约为 1.5 米。除非有充分理由需要覆盖此设置，否则应遵循该默认值。

**SL-03：切勿将内容放置在用户身后。**
用户必须实际转身才能看到身后的内容。所有 UI 元素都必须出现在朝向前方的半球范围内。如果内容必须环绕用户，请提供清晰的导航方式，以便用户旋转或重新定位。

**SL-04：尊重个人空间。**
不要将 3D 对象或窗口放置在距离用户头部不到一臂（约 0.5 米）的位置。个人空间内的对象会引起不适和被侵扰感。直接触摸交互属于例外，此时对象会被有意放置在触手可及的范围内。

**SL-05：使用 Z 轴深度建立层级。**
距离用户更近的元素看起来更突出，也更具可交互性。将次要内容或背景内容放置得更远。对于分层元素，应使用细微的深度偏移（几厘米），而不是采用会使界面显得割裂的大幅间隔。

**SL-06：合理管理多个窗口。**
显示多个窗口时，应将它们沿用户周围排列成平缓的弧形，而不是堆叠或重叠。每个窗口都应能够单独调整位置。避免同时生成过多窗口，以免让空间显得不堪重负。

**SL-07：将内容锚定到环境，而不是头部。**
当用户移动头部时，窗口和对象应固定在世界空间中。头部锁定内容（跟随头部移动的内容）会引起不适和晕动症。仅对工具提示等短暂出现的临时元素使用相对于头部的定位。

## 2. 眼动与手势输入 [关键]

visionOS 使用间接交互作为其主要输入模型：用户注视目标，然后通过捏合手势进行选择。这与触摸或鼠标输入有本质区别。

### 规则

**EH-01：将“注视并捏合”设计为主要交互方式。**
标准交互方式是：用户注视某个元素（眼睛负责目标定位），然后将拇指和食指捏合在一起（手部负责确认）。围绕此模型设计所有主要交互。用户无需抬起双手或指向对象。

**EH-02：交互目标的最小尺寸为 60pt。**
眼动追踪存在固有的精度误差。所有可点击元素的直径必须至少为 60 点，才能通过注视可靠地确定目标。这比 iOS 的触控目标（44pt）更大。更小的目标会导致用户感到沮丧和误选。

**正确：**
```swift
// visionOS — button meeting 60pt minimum
Button(action: confirmAction) {
    Label("Confirm", systemImage: "checkmark")
        .frame(minWidth: 60, minHeight: 60)
        .padding(.horizontal, 16)
}
.buttonStyle(.borderedProminent)
```

**错误：**
```swift
// visionOS — 32pt button too small for reliable gaze targeting
Button(action: confirmAction) {
    Image(systemName: "checkmark")
        .frame(width: 32, height: 32)  // Below 60pt minimum; unreliable with eye tracking
}
```

**EH-03：为注视提供悬停反馈。**
当用户的视线停留在交互元素上时，显示可见的高亮效果或轻微放大，以确认该元素已成为目标。由于没有光标，这种反馈至关重要。如果没有悬停状态，用户就无法判断自己即将选择什么。

**EH-04：为近距离对象支持直接触控。**
当 3D 对象或 UI 元素位于手臂可触及的范围内时，应允许直接触控交互（实际伸手并点击）。直接触控应当感觉自然：接触时提供视觉和音频反馈。在能够增强临场感的沉浸式体验中使用直接触控。

**EH-05：切勿出于内容目的追踪注视。**
眼睛位置仅用于系统交互目标定位。不要使用注视方向来推断用户兴趣、根据用户注视的内容更改内容，或记录用户的注视位置。这是该平台的一项核心隐私原则。系统不会向应用暴露原始眼动追踪数据。

**EH-06：保持自定义手势简单且直观。**
如果你定义了系统捏合手势以外的自定义手势，请确保这些手势易于发现、操作起来身体舒适，并且不会与系统手势冲突。对于基本操作，应避免使用需要持续抬手、复杂手指动作或双手协调的手势。

**EH-07：不要要求精确的手部位置。**
用户交互时，双手会自然地放在腿上或身体两侧。不要要求用户将手保持在特定位置、伸向特定地点或持续保持某种手势。间接交互模型的存在正是为了减少体力消耗。

**EH-08：在交互开始时确认用户意图。**
系统一旦识别出注视目标、捏合、拖拽拾取或直接触控接触，就应显示可见的状态变化。延迟确认会破坏眼手配合，使选择过程产生不确定感。

### 空间交互快速参考

| 交互 | 方法 | 使用场景 |
|---|---|---|
| 点击／选择 | 注视 + 捏合 | 按钮、链接、列表项 |
| 滚动 | 注视 + 捏合并拖动 | 列表、长篇内容 |
| 缩放 | 双手捏合 | 地图、图像、3D 模型 |
| 旋转 | 双手扭转 | 3D 对象操控 |
| 拖动 | 注视 + 捏合、保持并移动 | 调整窗口位置 |
| 直接触控 | 伸手并点击 | 近距离 3D 对象 |
| 长按 | 注视 + 捏合并保持 | 上下文菜单 |

### 目标尺寸参考

| 元素 | 最小尺寸 | 推荐尺寸 |
|---|---|---|
| 按钮 | 60pt | 60-80pt |
| 列表行 | 60pt 高 | 80pt 高 |
| 标签栏项目 | 60pt | 72pt |
| 关闭/退出控件 | 60pt | 60pt |
| 工具栏项目 | 60pt | 60pt |
| 3D 交互对象 | 等效于 60pt | 根据情境缩放 |

## 3. 窗口 [高优先级]

visionOS 中的窗口悬浮在用户的物理空间内。窗口使用玻璃材质，与现实环境融为一体。

### 规则

**WN-01：默认使用玻璃材质作为窗口背景。**
系统玻璃材质会动态适应用户周围的现实环境，提供一致且易读的背景。除非有特定的设计理由（例如媒体播放），否则不要使用不透明纯色替代玻璃材质。玻璃材质能让界面自然融入共享空间。

**WN-02：保留标准窗口控件。**
窗口底部包含系统提供的窗口栏，用于调整位置，同时还包含关闭按钮。不要隐藏、覆盖或替换这些控件。用户依赖所有应用中一致的窗口管理方式。

**WN-03：在适当情况下允许调整窗口大小。**
如果你的内容适合以不同尺寸呈现（例如文档、浏览器、媒体），请支持调整窗口大小。使用系统的大小调整手柄。定义合理的最小和最大尺寸。随着窗口大小的变化，以响应式方式调整布局。

**WN-04：将标签栏作为前缘装饰件放置（左侧）。**
在 visionOS 中，标签栏（应用导航）作为垂直装饰件放置在窗口的前缘（左侧），而不是像 iOS 那样放在底部。这样既能让导航易于访问，又不会占用窗口内容区域。标签图标应使用 SF Symbols。

**WN-05：将工具栏作为底部装饰件放置。**
主要操作控件显示在锚定于窗口底部边缘的工具栏装饰件中。这样可使控件靠近用户双手自然停留的位置，同时避免遮挡内容区域。

**WN-06：窗口悬浮在空间中，不存在固定屏幕。**
这里不存在固定显示屏。窗口位于用户的物理环境中。设计内容时，应确保从略微倾斜的角度和不同距离观看时都能正确呈现。避免采用依赖固定视口尺寸或像素级精确定位的设计。

## 4. 体积空间 [高优先级]

体积空间在有边界的盒状区域内显示 3D 内容。它们非常适合展示 3D 模型、可视化内容，以及供用户从多个角度查看的对象。

### 规则

**VL-01：将 3D 内容限制在体积空间边界内。**
所有内容都必须置于定义的体积空间尺寸内。超出边界的内容将被裁剪。根据所承载的内容合理设置体积空间大小，并遵守系统强制执行的限制。

**VL-02：针对从所有角度观看进行设计。**
用户可以在体积空间周围走动，也可以重新调整其位置。确保 3D 内容从所有观看角度看起来都正确，而不仅仅是从正面观看时如此。避免使用从侧面看起来像纸板剪影的扁平立面。

**VL-03：不要要求特定的观看位置。**
用户可能从上方、下方或任意一侧观看体积空间。无论观看角度如何，内容都必须保持易于理解。如果方向很重要，请使用视觉提示（例如底座或标签），而不是强制用户处于特定位置。

**VL-04：根据空间适当调整内容尺寸。**
立体内容的尺寸应与其内容和用户所处的环境相适应。分子模型可以较小，方便用户伸手托住。建筑可视化模型则可以铺满一张桌子。请考虑用户与立体内容交互时所处的情境。

**VL-05：将立体空间用于自成一体的 3D 体验。**
立体空间并不是内部放置了 3D 对象的窗口。当 3D 内容是主要体验时（例如检查产品模型、查看 3D 图表），应使用立体空间。对于以 2D 界面为主、可能包含一些 3D 元素的体验，应使用窗口。

## 5. 沉浸式空间 [高]

visionOS 支持一系列不同程度的沉浸体验，从共享空间（应用与现实环境并存）到完全沉浸（完整的虚拟环境）。

### 规则

**IS-01：从共享空间开始。**
默认情况下，应用会启动到共享空间中，在这里，多个应用窗口与现实世界并存。只有当用户明确提出请求时，才应过渡到更具沉浸感的体验。不要在启动时强制用户进入沉浸状态。

**IS-02：采用渐进式沉浸。**
逐步切换不同的沉浸级别：从共享空间（窗口与现实环境并存），到全空间（你的应用接管空间，但仍保留透视），再到完全沉浸（完全虚拟的环境）。每一步都应目的明确，并由用户主动发起。

**IS-03：始终提供退出路径。**
用户必须始终能够返回沉浸程度较低的状态，或完全退出体验。数码旋钮是系统级的退出方式。在应用内，应提供清晰的控件来降低沉浸程度。绝不要将用户困在沉浸式体验中。

**IS-04：使用透视功能保障安全。**
在用户可能会移动身体的体验中，应保留现实环境的透视画面，或提供安全边界。用户需要了解实体障碍物、其他人员和房间边界的位置。只有当用户保持静止时，才适合使用完全沉浸。

**IS-05：逐渐调暗透视画面。**
过渡到更高沉浸程度时，应逐渐调暗透视环境，而不是突然切换为黑屏。突兀的视觉变化会令人迷失方向。在不同沉浸级别之间使用平滑的动画过渡。

**IS-06：不要假定房间的布局或大小。**
用户所处的实体空间各不相同。不要设计需要最低房间面积、假定地面存在空旷区域或要求家具采用特定摆放方式的体验。应根据任何可用的实体空间进行良好适配。

**IS-07：提供空间音频提示。**
在沉浸式空间中，使用空间音频帮助用户确定方位。声音应来自其声源在虚拟环境中所在的方向。音频提示可以引导注意力并提供反馈，而无须用户将视觉焦点移至相应位置。

## 6. 材质与深度 [中]

visionOS 使用基于物理的材质系统，可响应现实世界中的光照。正确使用材质可以建立深度层级并确保内容清晰易读。

### 规则

**MD-01：为 UI 表面使用系统玻璃材质。**
玻璃材质是 visionOS UI 的基础。它可提供深度感、半透明效果以及与环境的融合。应使用系统提供的玻璃材质变体（常规、薄、超薄），而不是自定义的半透明材质。

**MD-02：镜面高光应响应环境。**
visionOS 中的材质会对现实世界的光照条件作出反应。应利用这一特性来设计元素：交互元素上的细微镜面高光可强化其立体感。不要使用完全哑光的表面来弱化材质的质感。

**MD-03：通过分层材质创建深度层级。**
前景元素使用更亮、更厚的玻璃，背景元素使用更暗、更薄的玻璃。侧边栏使用与内容区域略有不同的玻璃色调。这种分层无需清晰的边框即可形成自然的视觉层级。

**MD-04：应用鲜明度效果以提高文本可读性。**
玻璃材质上的文本使用鲜明度效果，以确保无论背景环境如何都清晰易读。使用包含适当鲜明度效果的系统文本样式。在玻璃上进行自定义文本渲染时，必须考虑背景明度和颜色的变化。

**MD-05：使用阴影和高光表现抬升效果。**
悬浮在窗口表面上方的元素（弹出框、菜单、悬停状态）应投射细微阴影，并在其上边缘呈现轻微的镜面高光。这些深度线索有助于用户理解界面各层之间的空间关系。

**MD-06：避免在共享空间中使用完全不透明的背景。**
不透明表面会在共享空间的环境中形成视觉空洞。应使用能让环境透出的半透明玻璃材质。媒体播放（视频、照片）属于例外情况，此时不透明背景可以改善观看体验。

## 7. 装饰控件 [中]

装饰控件是附着在窗口边缘、部分悬浮于窗口边界之外的 UI 控件。它们用于提供工具栏、导航和上下文操作。

### 规则

**OR-01：将控件作为装饰控件附着，而不是内嵌。**
工具栏、标签栏和常驻操作按钮应作为装饰控件，而不是嵌入窗口内容区域。装饰控件可使内容区域保持整洁，并在控件与内容之间建立清晰的空间层级。

**OR-02：将主要操作放置在底部装饰控件中。**
底部边缘的装饰控件是放置操作控件（播放/暂停、格式化工具、共享）的主要位置。这个位置在人体工学上易于操作，并且在不遮挡内容的情况下具有醒目的视觉效果。

**OR-03：将导航放置在前缘（左侧）装饰控件中。**
应用级导航（相当于标签栏）应附着在窗口的前缘。这样既能让导航保持常驻且便于访问，又能将内容区域和底部装饰控件留给上下文控件。

**OR-04：不要让装饰控件遮挡窗口内容。**
装饰控件应从窗口边缘向外延伸，而不是向内延伸。它们不应覆盖窗口的内容区域，也不应与其重叠。应合理设置装饰控件的尺寸，使其既能保持功能性，又不会在视觉上凌驾于内容之上。

**OR-05：适当按上下文显示装饰控件。**
并非所有装饰控件都需要始终可见。工具栏可以在悬停时（当用户注视窗口时）出现，并在用户移开视线时淡出。这样既能保持界面整洁，又能维持可发现性。

**OR-06：使用标准装饰件样式。**
装饰件使用与窗口相同的玻璃材质系统，但深度略有不同。应使用系统提供的装饰件容器，而不是自定义悬浮 UI。这样可以确保与其他 visionOS App 在视觉上保持一致。

**OR-07：确保基本控件易于发现。**
对于用户必须反复使用的命令（例如导航、播放或主要操作），应使用装饰件。不要将基本控件隐藏在需要记忆的手势或仅在悬停时显示的交互提示之后。

## 8. 辅助功能 [关键]

visionOS 支持 VoiceOver、切换控制和指针控制替代方案。空间 UI 必须能够在不完全依赖眼动和手部输入的情况下进行导航。

### 规则

**ACC-01：每个交互元素都必须具有含义明确的辅助功能标签。**
按钮、控件以及用户可以与之交互的 3D 对象必须具有可供 VoiceOver 朗读的标签。不要仅依赖视觉外观或位置。

**ACC-02：VoiceOver 必须能够访问所有交互元素。**
确保辅助功能树涵盖所有可聚焦控件。可交互的自定义 `RealityKit` 实体必须注册到辅助功能层级结构中。

**ACC-03：支持指针控制和切换控制替代方案。**
并非所有用户都能使用眼动追踪和手指捏合操作。确保 App 可以通过头部指针、切换控制或键盘导航等替代输入方式进行完整导航。

**ACC-04：遵循“减弱动态效果”设置。**
启用“减弱动态效果”时，必须停用或减弱空间动画、沉浸式过渡和视差效果。空间环境中的突然运动可能会使人失去方向感。

```swift
@Environment(\.accessibilityReduceMotion) var reduceMotion

var body: some View {
    Model3D(named: "SceneObject")
        .rotation3DEffect(reduceMotion ? .zero : rotation, axis: (0, 1, 0))
}
```

**ACC-05：响应“粗体文本”设置。**
当用户启用“粗体文本”时，visionOS 中自定义渲染的文本必须相应调整。SwiftUI 动态字体样式会自动处理此设置；自定义渲染必须检查 `UIAccessibility.isBoldTextEnabled`，或使用 `@Environment(\.legibilityWeight)` 检测该设置并应用更粗的字重。

**ACC-06：响应“增强对比度”设置。**
当用户启用“增强对比度”时，自定义颜色必须提供对比度更高的变体。在 SwiftUI 中使用 `@Environment(\.colorSchemeContrast)` 检测 `.increased`，并为显示在玻璃或环境背景上的文本和 UI 元素替换为对比度更高的颜色值。

## 反模式

以下是 visionOS 设计中的常见错误。请避免这些错误。

| 反模式 | 问题 | 正确做法 |
|---|---|---|
| 头部锁定式 UI | 会导致晕动症，并产生幽闭感 | 将 UI 锚定到世界空间 |
| 过小的轻点目标 | 眼动追踪无法可靠地定位小于 60pt 的目标 | 交互目标最小为 60pt |
| 无悬停状态 | 用户无法判断哪些元素可以交互 | 凝视时始终显示高亮效果 |
| 共享空间中的不透明窗口 | 会在环境中形成视觉空洞 | 使用系统玻璃材质 |
| 强制完全沉浸 | 会令人迷失方向，使用户感觉受困 | 从共享空间开始，逐步增强沉浸程度 |
| 内容位于用户身后 | 内容不可见，需要用户转动整个身体 | 将内容保持在前方半球范围内 |
| 由凝视驱动的内容 | 侵犯隐私，让用户感觉受到监视 | 仅将凝视用于系统目标定位 |
| 扁平的 3D 体积 | 从侧面看起来像纸板剪影 | 针对所有观察角度进行设计 |
| 内联工具栏 | 浪费内容空间，违背平台惯例 | 使用装饰件承载控件 |
| 假设房间空间较小 | 在狭窄空间中无法正常使用 | 适应可用的物理空间 |
| 突然改变沉浸程度 | 会令人迷失方向，破坏临场感 | 使用动画进行渐进式过渡 |
| 长时间抬起手臂 | 几分钟内就会造成身体疲劳 | 按双手自然垂放于身体两侧的状态进行设计 |
| 自定义窗口装饰 | 破坏平台一致性 | 使用系统窗口控件 |
| 图层深度冲突 | 导致视觉闪烁，层级不清晰 | 使用有意设置的深度偏移 |
