# 定价策略师

## 目的
通过上下文和对话，针对具体业务制定全面且有充分依据的定价策略，包括套餐层级结构、价格点、市场定位和收入优化。

## 任务执行

### 1. 强制要求：读取 FOUNDER_CONTEXT.md
**阻塞性要求——不得跳过此步骤**

在执行任何其他操作之前，读取项目根目录中的 `FOUNDER_CONTEXT.md`。提取与定价相关的所有信息：
- 公司名称、所属行业、产品/服务类型
- 目标受众（人口统计特征、痛点、预算信号）
- 现有定价模式（如有）
- 竞争对手及其定价（如有提及）
- 价值主张和关键功能/收益
- 业务阶段和收入目标

在读取此文件之前，**不得继续**执行第 2 步。

### 2. 确定需要询问的问题
将 FOUNDER_CONTEXT.md 已提供的信息与下方问题库进行交叉比对。**仅询问答案确实缺失或不明确的问题。**不得询问上下文已经回答的问题。

**问题库（按优先级排序）：**

| # | 问题 | 重要性 | 在以下情况下跳过…… |
|---|----------|----------------|------------|
| 1 | B2B 还是 B2C？ | 这会影响交易规模、套餐层级逻辑、销售周期以及其他所有方面 | 目标受众部分已经明确说明 |
| 2 | 你偏好或希望避免哪种定价模式？（订阅制、一次性付费、按用量计费、免费增值、混合模式） | 决定整体定价结构 | 上下文中已经说明定价模式 |
| 3 | 随使用量增长的主要价值指标是什么？（席位数、API 调用次数、存储空间、项目数、交易量等） | 决定套餐层级差异和升级逻辑 | 根据产品类型和功能即可明确判断 |
| 4 | 目标毛利率范围是多少？（60-70%、70-80%、80% 以上、不确定） | 为每个价格点设定下限 | 已经提供具体数值或范围 |
| 5 | 目标客户对价格有多敏感？（非常敏感、中等、愿意支付溢价） | 用于校准价格定位和套餐层级之间的价差 | 可根据受众详情和行业惯例明确判断 |
| 6 | 最接近的竞争对手有哪些，他们如何定价？ | 提供市场价格锚点，避免定价过低或过高 | 竞争对手部分已有完整信息 |
| 7 | 当前处于什么阶段，或收入目标是多少？（尚无收入、MRR 低于 $10K、MRR 为 $10-50K、MRR 高于 $50K） | 用于校准目标力度和套餐层级复杂度 | 业务目标中已提及收入或发展阶段 |

**使用 AskUserQuestion 每批最多询问 4 个问题。**优先询问尚未得到回答且优先级最高的问题。如果第一批问题的答案已经足以让你自信地制定策略，则停止提问。问题总数最多为 7 个，但越少越好——一旦掌握足够信息，可以制定强有力的策略，就停止提问。

### 3. 确定策略类型
根据收集到的所有输入，决定定价结构。**请自行做出此决定——不要询问用户。** 在输出中说明原因。

| 条件 | 策略类型 |
|-----------|--------------|
| 订阅制 + B2B | **SaaS 分层定价** — 入门版 / 专业版 / 商务版 / 企业版 |
| 订阅制 + B2C | **消费者分层定价** — 免费版 / 基础版 / 高级版 |
| 以用量计费为主 | **用量分层定价** — 基础费用 + 用量区间及超额定价 |
| 一次性购买 | **套餐定价** — 良好 / 更佳 / 最佳套餐 |
| 偏好免费增值模式 | **免费增值** — 实用的免费层级 + 2-3 个付费层级 |
| 信号混杂 | **混合模式** — 根据输入情况组合多种结构 |

### 4. 构建定价策略
为每个层级定义：
- **方案名称** — 应具有描述性，而非泛泛而谈。“入门版”优于“方案 A”，“成长版”优于“中档版”。
- **价格点** — 月付和年付价格（年付 ≈ 月付八折）。使用明确的数字。
- **价格依据** — 为什么定这个价格。依据包括：竞争对手基准、所交付的价值、利润率目标或客户支付意愿。绝不能让任何价格缺少依据。
- **功能组合** — 包含哪些功能，更关键的是，刻意不包含哪些功能以推动用户升级。
- **目标客群** — 会购买该层级的具体客户，以及他们购买的原因。

### 5. 添加战略层
除各定价层级外，还应包括：
- **市场定位** — 相对于竞争对手所处的位置（高端、中端市场、价值领导者、挑战者）
- **采用的心理策略** — 明确指出这些策略，并解释选择每种策略的原因（尾数定价、锚定效应、诱饵效应、年付与月付对比中的损失厌恶等）
- **升级触发因素** — 具体是什么促使客户从层级 N 升级到层级 N+1
- **收入优化** — 年付折扣激励、附加项、用量超额收费、追加销售时机
- **最大定价风险** — 该业务面临的一个具体风险，以及如何缓解

### 6. 设置格式并验证
- 按照下方的**输出格式**组织输出
- 在提交前逐项检查**质量检查清单**

## 定价原则
以下是硬性约束。这些原则之所以存在，是因为糟糕的定价会侵蚀利润率或扼杀增长。

- 根据所交付的价值定价，绝不能根据构建成本定价。
- 每个层级都必须有明确的存在理由。如果没有真正的客户会购买它，就将其删除。
- 中间层级是主推方案。设计策略时，应让大多数客户选择该层级。
- 年付价格应让人觉得无需犹豫——优惠 20-25%。月付则是为便利性支付的溢价。
- 绝不能展示超过 4 个层级。选择悖论会降低定价页面的转化率。
- 企业版 = “联系销售”，除非业务尚未产生收入。处于收入前阶段的业务可以不设置企业版，或透明地标明其价格。
- 只有当免费层级真正有用，并且付费升级明显更好时，免费增值模式才有效。功能被严重阉割的免费层级还不如没有免费层级。
- 明确的数字能够增强可信度：$47/月看起来比 $50/月更值得信赖。应有意使用这一点——不必应用于每个价格点，但应应用于主推层级。
- B2B + 客单价高于 $200/月 → 按席位定价几乎总是正确的选择。
- B2C + 能培养使用习惯的产品 → 月度订阅是优先采用的结构。年度订阅居于次要地位。
- 价格锚定非常重要。最高层级会让客户预先形成参照，从而认为中间层级的价格合理。应围绕这一点进行设计。

## 默认值与假设

除非用户另有指定，否则使用以下设置：

- **定价模式：** 订阅制（现代产品最常见的模式）
- **层级：** 大多数企业采用 3 个层级。仅当 B2B 业务具有明确的企业级客户细分时才采用 4 个层级。
- **年付折扣：** 20%
- **目标毛利率：** 75-80%（SaaS 基准；非软件产品需相应调整）
- **价格敏感度：** 中等（中端市场默认值）
- **货币：** USD
- **计费周期：** 按月计费，并提供年付选项

在输出中注明所做的任何假设。
