# Signal Postmortem

## 概述

Signal Postmortem 记录并分析由 edge 流水线、选股器及其他技能生成的交易信号的最终结果。它将预测的 edge 方向与 5 日和 20 日已实现收益进行对比，对结果进行分类（真阳性、假阳性、错失机会、市场状态错配），并生成用于 edge-signal-aggregator 权重调整以及技能改进待办事项的反馈。

## 何时使用

- 在交易已平仓、想要记录其结果时
- 在审查一批已达到持有期（5 天或 20 天）的信号时
- 用于识别来自特定技能的系统性假阳性模式
- 用于生成 edge-signal-aggregator 权重校准所需的反馈
- 在基于决策质量指标构建技能改进待办事项时
- 用于周期性（每周/每月）的信号质量审计

## 前置条件

- Python 3.9+
- FMP API 密钥（可选，用于在未手动提供时获取已实现收益）
- 标准库 + `requests`，用于 API 调用
- 输入：JSON 格式的信号记录（来自 edge-signal-aggregator 或选股器的输出）

### API 密钥设置（可选）

如果希望自动获取价格数据以计算收益，请设置 FMP API 密钥：

```bash
export FMP_API_KEY=your_api_key_here
```

或者，通过命令行传入密钥：`--api-key YOUR_KEY`。如果没有 API 密钥，你仍可以通过提供 `--exit-price` 和 `--exit-date` 手动记录结果。

## 工作流程

### 第 1 步：准备信号记录

收集已平仓或已到期的信号记录。每条记录应包含：
- `signal_id`：唯一标识符
- `ticker`：股票代码
- `signal_date`：信号生成日期
- `predicted_direction`：LONG 或 SHORT
- `source_skill`：生成该信号的技能
- `entry_price`：信号生成时的价格（可选，用于手动覆盖）

```bash
# Example: List signals ready for postmortem (5+ days old)
python3 skills/signal-postmortem/scripts/postmortem_recorder.py \
  --list-ready \
  --signals-dir state/signals/ \
  --min-days 5
```

### 第 2 步：记录结果

运行复盘记录器，获取已实现收益并对结果进行分类。

```bash
python3 skills/signal-postmortem/scripts/postmortem_recorder.py \
  --signals-file state/signals/aggregated_signals_2026-03-10.json \
  --holding-periods 5,20 \
  --output-dir reports/
```

手动记录结果时（即价格数据已到手时）：

```bash
python3 skills/signal-postmortem/scripts/postmortem_recorder.py \
  --signal-id sig_aapl_20260310_abc \
  --exit-price 178.50 \
  --exit-date 2026-03-15 \
  --outcome-notes "Closed at target, +3.2% in 5 days" \
  --output-dir reports/
```

### 第 3 步：对结果分类

记录器会自动将每个信号归类为以下四类之一：

| 类别 | 定义 |
|----------|------------|
| TRUE_POSITIVE | 预测方向与已实现收益的符号一致 |
| FALSE_POSITIVE | 预测方向与已实现收益相反 |
| MISSED_OPPORTUNITY | 信号未被采纳，但本可以盈利 |
| REGIME_MISMATCH | 信号因市场状态变化而失败 |

分类规则记录在 `references/outcome-classification.md` 中。

### 第 4 步：生成反馈文件

为下游消费者生成反馈：

```bash
# Generate weight adjustment suggestions for edge-signal-aggregator
python3 skills/signal-postmortem/scripts/postmortem_analyzer.py \
  --postmortems-dir reports/postmortems/ \
  --generate-weight-feedback \
  --output-dir reports/

# Generate skill improvement backlog entries
python3 skills/signal-postmortem/scripts/postmortem_analyzer.py \
  --postmortems-dir reports/postmortems/ \
  --generate-improvement-backlog \
  --output-dir reports/
```

### 第 5 步：查看汇总统计

按技能、按股票代码以及按时间段生成汇总统计：

```bash
python3 skills/signal-postmortem/scripts/postmortem_analyzer.py \
  --postmortems-dir reports/postmortems/ \
  --summary \
  --group-by skill,month \
  --output-dir reports/
```

  "signal_id": "sig_aapl_20260310_abc",
  "ticker": "AAPL",
  "signal_date": "2026-03-10",
  "source_skill": "edge-signal-aggregator",
  "predicted_direction": "LONG",
  "entry_price": 172.50,
  "realized_returns": {
    "5d": 0.032,
    "20d": 0.058
  },
  "exit_price": 178.50,
  "exit_date": "2026-03-15",

  "regime_at_signal": "RISK_ON",

```json
{
  "schema_version": "1.0",
  "generated_at": "2026-03-17T10:35:00Z",
  "analysis_period": {
    "from": "2026-02-01",
    "to": "2026-03-15"
  },

      "sample_size": 42
    }
  ],
  "confidence": "MEDIUM",

}
```

### 技能改进待办条目（YAML）

```yaml
- skill: vcp-screener
  issue_type: false_positive_cluster
  severity: medium
  evidence:
    false_positive_rate: 0.15
    sample_size: 42
    regime_correlation: RISK_OFF
  suggested_action: "Add regime filter or reduce signal confidence in RISK_OFF"
  generated_by: signal-postmortem
  generated_at: "2026-03-17T10:35:00Z"
```

### 汇总报告（Markdown）

报告保存在 `reports/` 目录下，文件名为 `postmortem_summary_YYYY-MM-DD.md`。

## 资源

- `scripts/postmortem_recorder.py` -- 记录单个信号的结果
- `scripts/postmortem_analyzer.py` -- 生成反馈和汇总统计
- `references/outcome-classification.md` -- 分类规则与边界情况
- `references/feedback-integration.md` -- 如何将反馈集成到下游技能

## 核心原则

1. **诚实归因** -- 每个结果都归因于其来源技能，以确保可问责性
2. **市场状态感知** -- 记录市场状态背景，以区分技能失效与市场状态转变
3. **最小样本量** -- 权重调整需要 20 个以上的信号才能满足统计有效性
4. **反馈闭环** -- 结果回流，用于同时改进信号聚合与技能质量
