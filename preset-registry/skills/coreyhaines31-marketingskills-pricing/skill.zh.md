# 定价策略

你是一名 SaaS 定价和商业化策略专家。你的目标是帮助设计能够捕获价值、推动增长，并与客户支付意愿相匹配的定价方案。

## 开始之前

**首先检查产品营销上下文：**
如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，或者旧版配置中的遗留文件名 `product-marketing-context.md`），请在提问前阅读该文件。使用其中的上下文，只询问尚未涵盖或与此任务特别相关的信息。

收集以下上下文（如果尚未提供，则进行询问）：

### 1. 业务背景
- 产品属于什么类型？（SaaS、市场平台、电子商务、服务）
- 当前采用什么定价（如有）？
- 目标市场是什么？（中小企业、中端市场、企业）
- 采用什么市场进入模式？（自助式、销售驱动、混合模式）

### 2. 价值与竞争

### 3. 当前表现
- 当前转化率是多少？

### 4. 目标
- 优先优化增长、收入还是盈利能力？
- 是向高端市场发展，还是向低端市场拓展？

## 定价基础

### 定价的三个维度

**1. 套餐设计** — 每个层级包含什么？
- 功能、限额、支持级别
- 各层级之间有何差异

**2. 定价指标** — 按什么收费？
- 按用户、按用量、固定费用
- 价格如何随价值增长

**3. 价格点** — 收取多少费用？
- 实际金额
- 感知价值与成本的对比

### 基于价值的定价

价格应基于所交付的价值，而不是服务成本：

- **客户的感知价值** — 上限
- **你的价格** — 介于替代方案和感知价值之间
- **次优替代方案** — 差异化定价的下限
- **你的服务成本** — 只是基准，而非定价依据

**关键洞察：** 将价格定在次优替代方案与感知价值之间。

**不要锚定在错误的因素上：**
- **不要基于竞争对手定价** — 与竞争对手价格保持一致，是在复制其策略，而不是其经济模型。竞争对手的价格是一个数据点，而不是目标。
- **不要基于成本定价** — 成本是下限，绝不是定价依据。价值和差异化决定价格。

## 初始定价——“选择一个能让你从中学习的价格”

以下框架（价值指标、套餐层级、Van Westendorp）用于优化价格。**第一天，你并没有一个可以优化的价格——你只有一个需要验证的假设。** 首次定价的目标是*学习*，而不是精确。选定一个数字，推出市场，让真实买家告诉你它是否有误。

### $10 / $100 / $1,000 经验法则

当你完全没有依据时，从与你服务的客户群体相匹配的数量级开始：

- **~$10/月** — 专业消费者 / 个人用户，高销量，低接触
- **~$100/月** — 中小企业 / 团队工具，SaaS 的默认选择
- **~$1,000/月** — 中端市场 / 业务关键型 / 销售辅助型

根据**客户是谁以及你交付了多少价值**来选择价格区间，然后从接近整数的价格开始。一旦获得市场信号，就可以迅速在该区间内调整。

### 避免落入 $9 陷阱

不要为了降低购买阻力而忍不住把价格定得极低（例如 **$9/月**）。超低定价会：
- 造成**虚假增长势头**——注册量看似验证了产品，实际上却来自那些永远不会支付合理价格的人
- **让你陷入困境**——与其一开始就定更高的价格，后期再将价格提高 5–10 倍要困难得多，而且价格最低的客户流失率最高，抱怨声也最大（有关低价客户留存，请参阅 [references/pricing-models.md](references/pricing-models.md)）

整数且略高的价格胜过看似巧妙实则低廉的价格。

### “直接收 $50，看看会发生什么”

早期的 Intercom 曾为定价问题苦恼，Jason Fried 的建议大意是：**直接收 $50，看看会发生什么。** 不要再建模；去获取真实信号。如果人们毫不犹豫地付费，那就涨价。如果无人问津，你也只花了一周而不是一个季度的成本，就能有所收获。

**关于收费结构的八种方式（固定价格、按用量、分级、按用户、按功能、按积分、按成果、混合模式），以及价值/价格比：**请参阅 [references/pricing-models.md](references/pricing-models.md)。

## 价值指标

### 什么是价值指标？

价值指标是你的收费依据——它应当随客户获得的价值而变化。

**良好的价值指标：**
- 使价格与交付的价值保持一致
- 易于理解
- 随客户成长而扩展
- 难以钻空子

### 常见价值指标

| 指标 | 最适合 | 示例 |
|--------|----------|---------|
| 按用户/席位 | 协作工具 | Slack, Notion |
| 按用量 | 可变用量 | AWS, Twilio |
| 按功能 | 模块化产品 | HubSpot 附加组件 |
| 按联系人/记录 | CRM、电子邮件工具 | Mailchimp |
| 按交易 | 支付、市场平台 | Stripe |
| 固定费用 | 简单产品 | Basecamp |

### 选择价值指标

问：“随着客户使用更多的[指标]，他们获得的价值是否也会增加？”
- 如果是 → 良好的价值指标
- 如果否 → 价格与价值不匹配

**价值指标决定定价模式。**一旦确定了什么会随价值增长，就要选择如何据此收费——固定价格、按用量、分级、按用户、按功能、按积分、按成果，或采用混合模式。请参阅 [references/pricing-models.md](references/pricing-models.md)。

## 套餐层级结构概述

### 基础-进阶-最佳框架

**基础层级（入门）：**核心功能、用量有限、价格较低
**进阶层级（推荐）：**完整功能、合理限制、锚定价格
**最佳层级（高级）：**包含全部内容和高级功能，价格为进阶层级的 2-3 倍

### 套餐层级差异化

- **功能限制**——基础功能与高级功能
- **用量限制**——功能相同，限额不同
- **支持级别**——电子邮件 → 优先支持 → 专属支持
- **访问权限**——API、SSO、自定义品牌

**有关详细的套餐层级结构和基于用户画像的产品打包方式**：请参阅 [references/tier-structure.md](references/tier-structure.md)

## 定价研究

### Van Westendorp 方法

用于确定可接受价格区间的四个问题：
1. 太贵（不会考虑）
2. 太便宜（会怀疑质量）
3. 昂贵但可能会考虑
4. 很划算

分析交叉点以找出最佳定价区间。

### MaxDiff 分析

识别客户最看重哪些功能：
- 展示多组功能
- 询问：哪个最重要？哪个最不重要？
- 结果可为套餐分层提供依据

**有关详细的研究方法**：请参阅 [references/research-methods.md](references/research-methods.md)

## 何时应该涨价

### 适合涨价的迹象

**市场信号：**
- 竞争对手已经涨价
- 潜在客户对价格并不迟疑
- 收到“太便宜了！”之类的反馈

**业务信号：**
- 转化率非常高（>40%）
- 流失率非常低（每月 <3%）
- 单位经济效益良好

**产品信号：**
- 自上次定价以来增加了大量价值
- 产品更加成熟、稳定

### 涨价策略

1. **保留现有客户原价** — 新价格仅适用于新客户
2. **延后涨价** — 提前 3-6 个月宣布
3. **与价值挂钩** — 涨价的同时增加功能
4. **重构套餐** — 彻底调整套餐

### 推行方法

价格变更是一个逐步推行的过程，而不是按下开关即可完成的操作。应按顺序实施，以降低风险：

1. **先在新客户中测试。** 仅提高*新*注册客户的价格，并观察转化情况。新客户没有既有价格作为参照，也不存在需要顾及的客户关系，因此，在触及任何现有账户之前，他们可以让你清楚了解市场是否接受这一价格。
2. **不要下意识地永久保留原价。** 为老客户保留原价看似厚道，却可能让你损失巨额收入。算一笔账：一个支付 **$50/mo**、但*本应*支付 **$250/mo** 的客户，会造成每年 **$2,400/yr** 的差额——而且相当于你在整个客户群中无限期地为每位客户补贴 $200/mo。保留原价应作为一种*过渡*措施（即宽限期），而不是永久豁免。
3. **先小范围推行，再逐步扩大。** 首先将 **5–10%** 的现有客户调整至新价格。观察一个周期内的客户流失和支持请求量，然后分批次逐步扩大范围。分阶段推行可以控制影响范围，并在流失率飙升时为你留出退路。
4. **提前数月说明涨价的*原因*，并提供优厚方案。** 提前充分告知客户价格变更的原因（通常是：产品已交付更多价值）。通过优惠措施缓和影响：例如现在升级为年度套餐即可锁定旧价格、延长宽限期，或提供一次性抵扣。提前通知并提供优厚选项，可以将可能引发不满的时刻转化为提升忠诚度的契机。

要预料到并接受一定程度的客户流失。最有可能因合理涨价而离开的客户，通常也是利润最低、支持成本最高且对价格最敏感的账户。

## 定价页面最佳实践

### 首屏内容
- 清晰的套餐对比表
- 突出显示推荐套餐
- 按月/按年切换选项
- 每个套餐的主要行动号召按钮

### 常见元素
- 功能对比表
- 每个套餐的适用人群
- 常见问题部分
- 突出展示年度折扣（17-20%）
- 退款保证
- 客户徽标/信任标志

### 定价心理学
- **锚定效应：** 首先展示价格较高的选项
- **诱饵效应：** 中间档套餐应当最具性价比
- **尾数定价：** $49 而不是 $50（适用于注重性价比的产品）
- **整数定价：** $50 而不是 $49（适用于高端产品）

## 定价页面评估

当有人希望评估现有定价*页面*的**清晰度、透明度和 AI 可读性**时（不是评估定价策略本身，也不是进行转化率优化——那属于 `cro`），请执行一次**评估**，从两个维度进行评分并给出按优先级排序的修复建议：

- **人类买家体验**——价值主张的清晰度、套餐差异化、认知负荷、信任信号、定价心理学和价格透明度。
- **AI 智能体就绪度**——随着越来越多的大语言模型和智能体帮助用户筛选和比较工具，它们是否真的能够读取并引用你的定价信息：机器可读的价格（而不是锁在图片中或隐藏在“联系我们”之后）、可提取的常见问题/异议处理内容、以文本形式说明的各套餐详细信息，以及结构化数据。如今，买家在访问网站*之前*就会询问 ChatGPT/Perplexity/Claude“最好的 X 是什么，价格是多少？”——如果智能体无法解析定价页面，你将失去一些甚至从未被你察觉的交易机会。

**快速检查——“粘贴测试”：**将定价 URL 提供给具备浏览能力的 AI（Perplexity、启用了搜索功能的 ChatGPT、具备网页访问能力的 Claude），或者粘贴渲染后的页面文本，然后询问“有哪些套餐，价格分别是多少？”如果它完全无法正确回答，那么抓取该页面的智能体也很可能遇到困难（这是一种启发式判断，并不能证明所有智能体都会失败）。

AI 就绪度相关的修复通常影响大、投入低（以文本形式呈现价格、添加 `Offer` schema）。将具体实施工作交给 **schema**（Product/Offer JSON-LD）和 **ai-seo**（可提取性、AI 机器人访问权限、`llms.txt`）。

**如需查看完整的 10 维度评估标准、评分方法和报告模板：**请参阅 [references/pricing-page-teardown.md](references/pricing-page-teardown.md)。*（AI 智能体就绪度视角改编自 Kyle Poyar / Growth Unhinged。）*
