# 交互设计构建器

**目标：** 创建或更新经过授权的交互设计产物，使产品旅程易于使用且可实现，同时保护受保护的体验。不得编辑产品代码，也不得在未获授权的情况下对外发布设计。

**执行契约：** 有序复选框即为完成定义。内部将每一项标记为 `PENDING`、`PROVEN`（附有具体证据）、`CLEARED`（附有该条件不存在的证据）或 `UNPROVEN`（存在缺口）；阅读、委派或工具失败均不能作为证明。每完成一个部分后重新核对各项。返回前解决所有 `PENDING` 项，并仅统计 `PROVEN` 和 `CLEARED`；针对每个缺口应用此技能的判定和批准规则。
保留用户意图、范围和现有授权。继续执行已获授权的工作；仅针对尚未解决且影响重大的选择或所需的外部批准提问。根据实质性风险调整深度，不得默默跳过检查。保留依赖关系和安全顺序；除此之外，为每项义务选择合适的验证方式。
将等价的用户或仓库证据视为有效输入；其他技能、命名产物或完整生命周期均不是前置条件。保留可用的源需求标识符和决策标识符。将复用的证据绑定到相关源版本、未提交的变更、配置和环境；发生变更时，仅使受影响的声明失效。
继续执行时，在恢复工作前重新核对任务、现有授权、当前状态和未解决的证据。对于长期工作，返回一份精简的续接记录，或更新已获授权的任务产物；只读技能不持久化该记录。区分产物就绪状态、已验证的行为，以及执行外部操作的权限。
在任何所需批准之前准备好已获授权的工作。如果某条指令阻碍了进展，指出其确切来源并解释尚未解决的边界；不得仅凭一般谨慎臆造批准门槛。


## 工具路由

| 需求 | 首选能力 | 备用方案 |
|---|---|---|
| 需求和体验 | 已接受的产品意图、现有 UI 和设计规范 | 用户提供的场景；缺少必要意图则为 BLOCKED |
| 交互证据 | 浏览器、屏幕截图、无障碍检查和现有设计文件 | 具有明确视觉限制的文本状态/流程规范 |
| 设计产物 | 可用的设计编辑器或本地文档/图表能力 | 经授权的 Markdown 或 HTML 模拟稿；不要求使用设计服务 |

## 领域规则

- 复用已建立的设计来源和设计系统。选择能够解决交互决策的最小产物；不要强行制作高保真模拟稿。
- 原型是设计证据，不是生产实现，也不能证明真实用户的可用性。标注模拟数据和未经测试的假设。
- 保留需求标识符，并区分现有的、拟议的和已获授权的面向用户的变更。

## 检查清单

### 1. 界定体验

- [ ] 识别参与者、旅程、任务、设备、语言环境、无障碍需求和获准的产物目标位置。
- [ ] 检查相关需求、现有流程、设计规范和受保护的用户工作。
- [ ] 分别记录已观察到的 UX、拟议的改进和未解决的产品决策。
- [ ] 根据产物必须解决的决策，选择规范、线框图或交互式模拟稿的详细程度。

### 2. 设计流程和状态

- [ ] 描述每个范围内旅程的进入、导航、进度、完成和退出路径。
- [ ] 指定控件、操作、反馈、信息层级和有意义的交互过渡。
- [ ] 设计适用的空状态、加载中、部分成功、错误、重试、取消和恢复状态。
- [ ] 定义验证时机和可执行的错误消息，且不暴露敏感的内部信息。
- [ ] 考虑破坏性操作、权限变更和恢复机制，不要为无害的交互增加确认步骤。
- [ ] 针对相关设备和区域设置，指定响应式行为和内容扩展方式。

### 3. 使设计可实现

- [ ] 在适用情况下，定义键盘导航、焦点转移、可访问名称、公告以及非颜色提示。
- [ ] 复用已建立的组件和设计令牌；通过具体的未满足用户需求解释任何新模式。
- [ ] 将需求映射到交互状态、文案和可观察的验收标准；标记缺失的业务规则，不要自行编造。
- [ ] 创建获得授权的制品，并标注模拟行为、假设和未解决的备选方案。

### 4. 验证旅程

- [ ] 通过实际制品走查每条关键路径和有意义的恢复路径；生成渲染稿时检查这些稿件。
- [ ] 在选定的保真度下，检查导航、状态转换、文案、焦点和需求覆盖的一致性。
- [ ] 将制品检查与可用性研究分开；记录哪些结论需要真实用户证据。
- [ ] 保留无关的设计内容，并报告实现限制和可能改变决策的缺口。

## 结论

- `READY`：关键交互已在约定的保真度下完成指定和验证，不存在尚未解决且会产生后果的设计决策。
- `REVISE`：制品已存在，但指定的交互或验收缺口阻碍了就绪。
- `BLOCKED`：关键意图、安全的制品授权或必要能力没有可信的替代方案。

## 自检

- [ ] **在返回前完成核对。** 检查条目级证据、需求覆盖、矛盾、范围、结论和适用的清理工作。修正报告或获得授权的制品。复用有效证据；不要自动重新扫描代码库或重新运行已成功的命令。仅针对相关变更、失败项或未解决的证据重复检查。披露剩余缺口。

## 输出约定

使用用户的语言，按以下顺序报告；保留全部五个字段，并且每项事实只陈述一次。较小的结果可以每个字段使用一行；省略空表格，不要复制链接的制品：

1. **结果：** 技能专属的结论和有证据支持的结果。
2. **范围：** 已审查/变更的范围、排除项、基线和重大假设。
3. **证据：** 以下技能专属字段；区分事实、推断和未经验证的声明。链接制品；适合时使用表格。
4. **验证：** 检查/结果、不可用的证据以及适用的清理工作/外部状态。
5. **完成情况：** `Checklist: X/Y complete`；`Incomplete: None` 或列出每项 `UNPROVEN` 的原因、对结果的影响和确切的下一步操作；剩余风险和必需的决策。

**特定于 Skill 的证据：**产物与保真度、需求到流程/状态的映射、经授权的 UX 变更、组件复用、无障碍行为、检查结果，以及未经测试的可用性假设。
