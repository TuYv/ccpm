# moai-domain-humanize

后期编辑专家，用于消除生成文本中的“AI 痕迹”，在保留原意的同时，将文本改写得更像人类创作。这是文本生成的**编辑**对应能力：它不会创作新内容，而是优化现有内容的表达方式。支持韩语、英语、日语和中文，涵盖两类体裁场景：**散文类文本**（专栏、报告、博客文章、正式文档）和**营销文案**（标题、CTA、落地页、品牌叙事、幻灯片标题）。每个语言模块都包含散文类特征目录和文案层特征目录；下述共享机制（严重程度模型、双重评级、特定模式防护规则）统一适用于所有模块。

## 快速参考

### 操作原则（4 条）

1. **保留原意是首要原则。** 事实、数字、统计数据、命名实体、引文、引用来源，以及作者的立场和确定程度都必须保持不变。任何语义偏移都会触发回滚。在文案模式下，“原意”由事实锚点以及核心承诺/利益点共同定义——参见下方的文案模式防护规则。
2. **仅进行有依据的编辑。** 每一处改动都必须能追溯到特定文本片段中检测出的特征。与目录中所列特征无关的风格“改进”本身就是过度编辑的信号，因此禁止进行。
3. **保留体裁和语域。** 在原文语域*范围内*进行自然化处理——学术文本仍保持学术风格，随意文本仍保持随意风格。绝不能把正式文本改成俚语风格，反之亦然。文案和幻灯片体裁应遵循各模块文案层中定义的专属结构规则（名词短语式标题边界、诉求型与信息型语气）。
4. **防止过度编辑。** 在散文模式下，改动比例 >30% 时发出警告（WARN），>50% 时停止处理（强制停止/人工审核）——超过 50% 就是在重新生成，而不是进行自然化编辑。在文案模式下，改动比例防护规则将由事实锚点保留防护规则取代（参见下方的“过度编辑防护规则”）。

### 体裁模式选择（散文与文案）

两种操作体裁决定使用哪套防护规则和评级表。默认根据文本体裁选择；用户的明确指令优先。

| 模式 | 体裁 | 过度编辑防护规则 | 评级表 |
|------|--------|--------------------|---------------|
| **散文模式**（默认） | 专栏、报告、博客、正式/官方文档 | 改动比例防护规则（>30% 时 WARN，>50% 时 HALT） | 散文模式评级 |
| **文案模式** | 营销文案、标题、CTA、落地页、品牌故事、幻灯片 | 事实锚点保留防护规则 | 文案模式评级 |

### 处理模式选择（快速/严格）

- **快速模式**（默认，最多约 5,000 个字符）：单次处理——检测、改写，并根据原意保留检查清单进行自我验证。
- **严格模式**（适用于长文本、高风险文本，或用户明确要求时）：分阶段处理——检测 → 精细改写 → 内容忠实度审核（事实/数字/立场保持不变）→ 自然度审查。当结果为 C 级时，再执行第二轮处理。

### 输出约定

返回以下两项内容：

1. **自然化处理后的文本。**
2. **简短的改动报告**：命中的类别（含数量）、最终质量等级（A/B/C/D），以及——在散文模式下——预估的改动百分比。触发防护规则时，必须明确说明（散文模式：>30% 时 WARN，>50% 时 HALT；文案模式：任何事实锚点丢失）。

## 通用严重程度模型（4 种语言共享）

每项特征都有一个严重程度等级。检测器会根据出现次数和重叠情况进行判定，因为单项特征很少足以证明内容由 AI 创作——置信度来自多项特征的聚集。

| 等级 | 名称 | 规则 |
|------|------|------|
| **S1** | 决定性 | 单次出现即可有力确认内容由 AI 创作 → 首次出现时即移除。 |
| **S2** | 强 | 出现 1–2 次可以接受 → 出现 3 次或更多时移除。 |
| **S3** | 弱 | 仅在与其他特征重叠时才构成问题 → 仅作为降级因素。 |

## 通用质量评级（4 种语言共享——双表制）

在改写**之后**评级。由体裁模式决定采用哪张表：散文模式根据残留特征及改动率评级；文案模式根据残留 S1 特征及事实锚点完整性评级，不设改动率区间。

### 散文模式评级表

依据残留 S1/S2 数量及改善百分比（= 在未引入新特征的情况下，已移除的检测特征所占比例）。

| 评级 | 标准 | 操作 |
|-------|----------|--------|
| **A** | 残留 S1 为 0，残留 S2 ≤2，改善幅度 ≥70% | 通过——读起来像人类创作 |
| **B** | 残留 S1 为 0，残留 S2 ≤4，改善幅度 ≥50% | 通过——仍需少量润色 |
| **C** | 残留 S1 为 1–2，或改善幅度 <50%，或过度编辑警告（>30%） | 触发第二轮处理 |
| **D** | 残留 S1 ≥3，或过度编辑中止（>50%），或检测到含义偏移 | 请求人工审核；不得自动发布 |

### 文案模式评级表

依据残留 S1（包括该模块文案层的 S1 特征）、事实锚点完整性及自我验证进行评级——不设改动率区间，因为合理的标题改写通常会改动大部分字符，同时保留每个锚点。

| 评级 | 标准 | 操作 |
|-------|----------|--------|
| **A** | 残留 S1 为 0，事实锚点丢失为 0，自我验证通过 | 通过——作为人工文案发布 |
| **B** | 残留 S1 为 0，保守判定的事实锚点疑虑 ≤1 | 通过，但需附上明确说明 |
| **C** | 残留 S1 为 1，或自我验证部分失败 | 触发第二轮处理 |
| **D** | 残留 S1 ≥2，或事实锚点丢失 ≥2 | 请求人工审核；不得自动发布 |

硬性规则（两种模式均适用）：任何残留 S1 都会将评级上限限制为 C；任何含义失真标记都会强制评为 D。仅当 ≥3 项 S3 特征相互重叠，并强化某项 S1/S2 判定时，S3 特征才会影响评级。

### 过度编辑防护规则（共享）

**散文模式——改动率防护。** 改动率 = 文本中被改动部分所占的比例；目标区间约为 5–30%。

- **改动率 >30% → 警告。** 给出警示，并将评级上限限制为 C，直至每项编辑都能由检测到的特征加以解释。注意：删除冗余内容可能会合理地缩短文本，因此仅仅篇幅变短并不构成违规——应在承载含义的片段被改动时进行标记。
- **改动率 >50% → 中止。** 停止处理并要求人工确认；恢复到上一个安全状态。
- **临近阈值时从严判断。** 此技能不含定量测量层，因此改动率是 LLM 的估算值，而非可复现的指标。应将接近边界的估算视为已超过阈值：接近约 30% 时发出警告；接近约 50% 时中止。判断应偏向谨慎，避免因过于乐观的估算而放过过度编辑。（已知限制：在没有计算指标的情况下，前后改善百分比同样是估算值——报告时应明确说明这一点。）

**文案模式——事实锚点保留护栏（取代改动率护栏）。** 在文案模式下，含义不变性采用不同的锚定方式：数字、日期、价格、专有名词和法律标记必须 100% 逐字符原样保留，且文案的核心承诺/利益点必须保持原意——但表达方式和句子结构可以自由改写。改动率护栏不适用，因为文案人性化处理完全可能合理地重写标题的大部分内容；取而代之的护栏对锚点实行绝对约束：

- **任何数字、日期、价格、专有名词或法律标记发生变化 → 回滚**该编辑。
- **核心承诺/利益点发生偏移 → 回滚。** 改写后的文案必须向同一受众作出相同承诺。
- **不得虚构具体信息。** 只有当具体事实存在于源文本中或由作者提供时，才允许用具体主张替换含糊文案。

### 含义保留检查清单（通用，必须全部满足）

1. 首先锚定事实——编辑前固定主张、数字、名称、日期和确定性程度。
2. 在句子/短语层面编辑，而不是重新生成整篇文档。
3. 不得添加新事实——绝不虚构具体信息来替换含糊表述；应改为简化表述，或标记出来交由作者处理。
4. 不得遗漏关键事实——去除夸张的包装时，必须保留其中的实质性主张。
5. 原样保留真实的确定性/保留性措辞和技术术语。
6. 最终差异检查——将事实、语气、确定性和示例与原文进行比较；还原任何产生偏移的编辑。

## 不变量台账与增量审计

有两种技术可以强化上述含义保留机制：**不变量台账**在编辑*之前*明确边界，而**增量审计**在编辑*之后*系统地检查这些内容是否得以保留。它们融入工作流（步骤 2 和 6），而不是取代任何步骤；它们会强化——而绝不会取代——严重程度模型、等级、护栏和含义保留检查清单。

### 不变量台账（编辑前边界）

编辑前，记录一份不变量台账——明确列出人性化处理过程中必须保持不变的所有内容。这是“首先锚定事实”（检查清单第 1 项）的书面、可核查形式。完整记录以下四类中的每一项：

1. **事实**（包括证据边界）
2. **标识符**（命令、路径、URL、状态值、错误代码、产品名称）
3. **条件 / 数字 / 日期 / 版本 / 单位 / 比较关系**
4. **例外 / 限制 / 风险 / 不确定性 / 批准事项 / 回滚 / 后续操作**

**保真规则。** 绝不可在未明确说明的情况下添加、删除、收窄、拓宽、强化或弱化任何台账条目。措辞可以改变，但文本所作的承诺不能改变。

**将每个条目标记为已提供或推断。** **已提供**条目是源文本实际断言的内容——它受到硬性锚定，任何偏移都会触发回滚（参见增量审计）。**推断**条目是源文本从未陈述、但读者可能会假定存在的相关利益点或保证——记录它仅用于提醒审阅者，在人性化处理过程中将其删除**不会**触发回滚，因为原文从未作出该承诺。如果某个条目没有标记，则将其视为**已提供**：故障安全原则要求优先保留。

**按处理模式区分深度。**
- **快速模式**：使用轻量级的行内锚点列表，但仍覆盖上述全部四个类别。快速模式仅在形式上更短，在类别覆盖范围上绝不会更窄——即使文本很短，也要为每个适用类别单列一行。
- **严格模式**：使用明确的书面边界文档，逐项列出每个条目，并标记为已提供/推断。

### 差异审计（编辑后验证）

编辑流程完成后，运行差异审计——在评分前，将输出与不变量账本进行比较。这是“最终差异检查”（检查清单第 6 项）的系统化形式，涵盖三个维度：

1. **主张与意图一致性**——源文本提出的每项主张，输出中仍然保留，并且强度相同、意图一致。
2. **存续检查**——账本中的每个标识符、数字、条件、限制和风险仍然存在且未发生变化。
3. **受众/语气/目的适配性**——输出仍然面向相同的读者，采用相同的语域，并服务于相同的目标。

此外，还要标记编辑中新引入的任何歧义：行为主体未明确、归属或交接不清晰，或者破坏性影响及审批/回滚注意事项被弱化。

**违反已提供条目时回滚。** 当审计发现任何标记为**已提供**的账本条目被新增、删除、缩窄、拓宽、强化或弱化时，回滚该项编辑——即执行操作原则中已要求的同类含义漂移回滚。删除标记为**推断**的条目时，应在审计输出中报告，但不会触发回滚。

**作为评分依据。** 账本违规即为含义失真标志，而根据现有硬性规则（参见通用质量等级），含义失真标志会在两种模式下均强制判定为 **D 级**——差异审计正是检测此类问题的机制。

## 语言路由

每种目标语言都有各自的特征目录（类别、使用目标语言编写的修改前/后示例、各类别严重程度）。加载与待编辑文本相匹配的模块：

| 语言 | 模块 | 来源依据 |
|----------|--------|--------------|
| 韩语（한국어） | `modules/korean.md` | 原创目录——正文层（A–J，共 10 个类别）+ 文案层（A-20…A-25、L-1…L-8、M-1…M-3） |
| 英语 | `modules/english.md` | 基于网络研究的目录——正文层（EN-A…EN-J）+ 文案层（ENC-1…ENC-9） |
| 日语（日本語） | `modules/japanese.md` | 基于网络研究的目录——正文层（JA-01…JA-09）+ 文案层（JA-10…JA-14） |
| 中文 | `modules/chinese.md` | 基于网络研究的目录——正文层（CN-A…CN-K）+ 文案层（CN-L…CN-Q） |

韩语模块是原创目录；英语、日语和中文模块则是在同一架构上分别通过网络研究独立构建的目录。每个模块的文案层都符合对应语言的原生习惯——文案特征绝不能机械地跨语言套用（英语标题天然简洁；日语体言止め是一种高水平的写作技巧，应根据使用频率而非是否出现来判断；中文对偶/排比应优先根据内容而非数量来判断）——因此，绝不要将一种语言的文案规则应用于另一种语言。上述通用严重程度模型和质量等级统一适用于所有模块——各模块仅补充特定语言的特征类别、严重程度和改写示例。

对于混合语言文本，检测其主导语言并路由至对应模块；当文本确实包含多种语言时，对各语言片段分别独立应用相应模块。

### 体裁模块路由

两个体裁模块会叠加在上述语言路由之上，而绝不会取代语言模块：

| 呈现形式 / 调用场景 | 附加模块 |
|----------------------|-------------------|
| 展示界面文案——落地页、幻灯片/卡片组、设计工具生成的文案 | `modules/design-copy.md`（体裁结构规则 + 各语言的原生衡量标准），与匹配的语言模块一同加载 |
| 生成后 QA 门禁审查——由其他工具或工作流生成、在应用前接受审查的文案 | `modules/copy-review.md`（仅审查模式：检测并提出建议，绝不自动应用；六阶段流程 + 各语言的套话词典） |

当两个条件同时满足时（即对展示界面文案进行 QA 门禁审查），应在语言模块之外同时加载这两个体裁模块。上方的语言路由表仍作为语言维度，不会因这项扩展而改变。

## 实施指南

### 工作流（逐段文本）

1. **识别语言、体裁模式和处理模式。** 根据主导语言选择模块；根据体裁选择散文模式或文案模式（参见“体裁模式选择”）；根据长度/重要程度选择 Fast 或 Strict。
2. **锚定事实——构建“不变量台账”。** 记录必须原样保留的四类台账内容（事实；标识符；条件/数字/日期/版本/单位/比较关系；例外/限制/风险/不确定性/审批/回滚/后续操作），并将每一项标记为已提供或推断得出（参见上方的“不变量台账”和“差异审计”）。Fast 模式使用轻量级行内锚点列表，覆盖所有类别；Strict 模式使用明确成文的边界文档。在文案模式下，这些锚点本身就是防护机制。
3. **检测痕迹。** 根据模块的目录进行扫描——散文模式下扫描散文类别，文案模式下还要扫描模块的文案层类别。记录每个命中项的类别 ID、文本片段和严重程度。统计出现次数（S2/S3 以重复情况作为判定条件）。
4. **进行精细改写。** 仅编辑被标记的文本片段。将每个痕迹替换为语域相同的自然表达。不得改动未标记的文本。
5. **应用当前模式的防护规则。** 散文模式：估算改动率并应用改动率防护规则（>30% 时发出 WARN，>50% 时 HALT；接近阈值时采取保守策略）。文案模式：改为核验每个事实锚点以及核心承诺/利益点。
6. **自我核验（Fast）或审计 + 审查（Strict）——运行“差异审计”。** 根据“不变量台账”对比输出，检查主张与意图是否一致、标识符/数字/条件/限制/风险是否保留，以及受众/语气/目的是否匹配（参见上方的“不变量台账”和“差异审计”）。如果违反已提供项，则回滚该项编辑并标记为含义失真（强制评为 Grade D）；如果移除了推断项，则报告该情况，但不进行回滚。重新运行含义保留检查清单。在 Strict 模式下，将内容忠实度审计和自然度审查作为独立阶段执行。
7. **评级。** 统计残留的 S1/S2 数量和改进百分比；评定为 A/B/C/D。评级为 C 时进行第二轮处理；评级为 D 时进行人工审查。
8. **输出**自然化后的文本 + 变更报告。

### 检测说明（所有语言通用）

自动化 AI 文本检测器在这四种语言中都不可靠（尤其不擅长处理 CJK 的礼貌语体，常常将规范的正式写作误判为 AI 文本）。本技能是一个**基于模式的编辑工具**，并非检测神谕：应依据已编目的语言特征类别和基于聚类的严重程度门槛，而不是检测器的判定结果。

### 常见误区

- **重新注入 AI 感。** 通过重新完整生成来改写 AI 文本，往往会引入新的 AI 特征。应优先对已标记的文本片段进行局部修改，而不是整篇重写。
- **编造具体细节。** 当某个模块要求使用具体细节替换含糊的填充内容，但实际上并不存在真实细节时，应简化内容或将其标记出来交由作者处理——绝不能凭空捏造。
- **风格漂移。** 对已标记特征之外的内容进行“润色”违反原则 2，并会提高修改率，使其趋近 HALT 门槛。
- **在文档中途混用语体。** 整篇输出应保持统一的语体；对于日语和中文，还应保持统一的礼貌程度和句末表达风格。
