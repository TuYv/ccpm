# 产品需求构建器

**目标：** 创建或更新一份可用的产品需求工件，保留所有者的意图，并使预期行为可测试。仅修改已获授权的产品文档；不得臆造承诺、设计架构或进行实现。

**执行契约：** 有序复选框即为完成定义。内部跟踪每一项，状态只能为 `PENDING`、具有具体证据的 `PROVEN`、具有条件不存在证据的 `CLEARED`，或存在缺口的 `UNPROVEN`；阅读、委派或工具失败都不能作为证明。每完成一个部分后重新核对各项。返回前解决所有 `PENDING` 项，仅统计 `PROVEN` 和 `CLEARED`；将技能的判定和审批规则应用于每个缺口。
保留用户意图、范围和现有授权。继续执行已获授权的工作；仅针对仍未解决且具有重大影响的选择或所需的外部审批提问。根据实质风险调整深度，不得默默跳过检查。保留依赖关系和安全顺序；除此之外，为每项义务选择合适的验证方法。
将等价的用户或仓库证据视为有效输入；其他技能、指定工件或完整生命周期都不是前置条件。尽可能保留源需求和决策标识符。将复用的证据绑定到相关源版本、未提交变更、配置和环境；发生变更时，仅使受影响的声明失效。
继续执行时，在恢复之前重新核对任务、现有授权、当前状态和未解决的证据。对于长期工作，返回一份精简的继续执行记录，或更新已有的获授权任务工件；只读技能不持久化该记录。区分工件就绪状态、已验证行为，以及执行外部操作的权限。
在任何所需审批之前准备好已获授权的工作。如果某条指令阻止了进展，指出其确切来源并解释尚未解决的边界；不要仅凭一般性谨慎臆造审批门槛。


## 工具路由

| 需求 | 首选能力 | 备用方案 |
|---|---|---|
| 意图和既有决策 | 用户请求、产品文档和已接受的决策 | 有边界的假设；仅针对缺失的重大影响意图提问 |
| 现有行为 | 有针对性的仓库、UI、契约和分析证据 | 明确说明不确定性的已提供示例 |
| 需求工件 | 现有的规范性产品文档和有针对性的编辑器 | 用户批准的目标位置；如果没有可安全使用的目标位置，则为 BLOCKED |

## 领域规则

- 复用现有的需求所有者；否则使用已获授权的 `docs/product/requirements.md`。不要在已建立的项目中强行引入新的文档层级。
- 分离已观察到的行为、所有者偏好、拟议需求、已接受的承诺和未解决的选择。发现阶段的建议不等于构建授权。
- 当可追溯性跨越多个工件时，使用稳定的需求标识符。在此处保留功能规则，并通过来源引用架构约束；用户故事是可选的表达形式。

## 检查清单

### 1. 确立意图与权限

- [ ] 明确问题、受影响的参与者、预期结果、时间范围、获准的文档范围，以及需要保护的现有体验。
- [ ] 阅读仓库说明、相关用户证据和现有需求；在编辑前检查目标文件和用户的变更。
- [ ] 确定一个权威的需求归档位置和适用的决策负责人；保留未解决的冲突来源。
- [ ] 区分非目标、可选想法和已承诺范围；仅对会改变验收标准或产品意图的选择进行澄清。

### 2. 明确可观察行为

- [ ] 为每个纳入范围的用户旅程描述触发事件、参与者权限、前置条件、成功结果以及有意义的替代路径。
- [ ] 在业务规则、计算、实体和生命周期转换会决定可观察行为的情况下，对其进行明确规定。
- [ ] 规定适用的失败、空状态、加载、重试、重复、取消和恢复行为，不凭空添加无关状态。
- [ ] 根据权威来源记录受影响的集成、外部承诺、兼容性和数据约束。
- [ ] 捕获适用的可访问性、隐私和其他面向用户的约束；引用会影响架构的目标，并避免重复其负责方的内容。
- [ ] 区分必须新增的 UX 与需要保护的现有流程、文案和行为。

### 3. 定义验收与结果

- [ ] 为每项重要需求提供可观察的验收条件，包括前置条件和预期结果，且不依赖具体实现。
- [ ] 定义预期的业务效果、可用基线、衡量窗口和证据来源；未知目标保持未知。
- [ ] 识别可能改变范围、验收标准或所选产品方向的依赖项和假设。
- [ ] 区分功能验收、产品影响，以及发布或运行实验的许可。

### 4. 编写与验证

- [ ] 编写获批准的产物，其中包含需求 ID、来源/状态、验收标准、非目标、假设和未解决的决策。
- [ ] 保留无关内容以及已变更承诺的历史；标记取代关系，不要悄然替换已接受的意图。
- [ ] 检查规则、场景和验收标准之间的一致性；暴露当前无法安全实现或测试的需求。
- [ ] 报告确切的重大缺口和后续证据行动；不要将文档的存在视为已具备就绪条件。

## 结论

- `READY`：需求一致且可测试，没有会阻碍下一步决策的重大未解决意图；提议的状态不代表负责人已接受。
- `INCOMPLETE`：有用的产物已经存在，但指定的需求或决策仍未解决。
- `BLOCKED`：范围、权限、关键意图或安全的归档位置存在问题，无法负责任地创建产物。

## 自检

- [ ] **返回前进行协调。** 检查逐项证据、需求覆盖范围、矛盾、范围、结论和适用的清理工作。修正报告或获授权的产物。复用有效证据；不要自动重新扫描仓库或重新运行已成功的命令。仅针对相关变更、失败或未解决的证据重复检查。披露剩余缺口。

## 输出契约

使用用户的语言进行报告，按以下顺序；保留全部五个字段，并且每项事实只陈述一次。简短结果可以每个字段占一行；省略空表格，不要复制链接的工件：

1. **结果：** Skill-specific verdict and supported outcome.
2. **范围：** Reviewed/changed scope, exclusions, baseline, and material assumptions.
3. **证据：** Skill-specific fields below; distinguish facts, inferences, and unverified claims. Link artifacts; use tables when useful.
4. **验证：** Checks/results, unavailable evidence, and applicable cleanup/external state.
5. **完成情况：** `Checklist: X/Y complete`; `Incomplete: None` 或列出每个 `UNPROVEN` 项的原因、对结果的影响以及确切的下一步行动；残留风险和所需决策。

**Skill-specific evidence:** Artifact, intent, protected behavior, requirement/source/status/acceptance mapping, changed commitments, outcome measures, and consequential unknowns with their next evidence action.
