## 首先澄清

在优化页面之前，请确认以下输入信息。如果有任何信息未知或含糊不清，请询问——不要自行假设：

- [ ] **页面类型**——首页、着陆页、定价页、功能页或博客（用于选择相应的页面类型行动手册和基准）
- [ ] **流量来源**——自然流量、付费流量、电子邮件或社交媒体（决定信息匹配要求）
- [ ] **主要转化目标 + 当前转化率**——聚焦七维分析并设定基准线
- [ ] **可用的行为数据**——热图 / 会话录制（揭示仅靠分析数据无法发现的阻力）

停止规则：只询问对输出影响最大的 2–3 个问题。如果用户说“直接起草”，则继续执行，并在审计报告顶部列出你的假设。

## 初步评估

### 必要背景信息

| 问题 | 重要性 |
|----------|---------------|
| 页面类型是什么？（首页、着陆页、定价页、功能页、博客） | 决定要应用的 CRO 框架 |
| 主要转化目标是什么？ | 聚焦分析 |
| 流量来自哪里？（自然流量、付费流量、电子邮件、社交媒体） | 决定信息匹配要求 |
| 当前转化率是多少？ | 确立基准线 |
| 点击后的流程是什么样的？ | 页面本身的转化表现可能良好，但下一步流程可能失败 |
| 你是否有热图或会话录制？ | 行为数据能够揭示分析数据无法发现的问题 |
| 你已经尝试过哪些方法？ | 避免重新测试已经失败的实验 |

## 七维 CRO 框架

按照通常的影响程度顺序，从以下七个维度分析每个营销页面。

### 维度 1：价值主张清晰度（影响最大）

**5 秒测试：**首次访问者能否在 5 秒内理解这是什么、适合谁，以及为什么值得关注？

| 信号 | 通过 | 未通过 |
|--------|------|------|
| 明确陈述主要收益 | “每周节省 10 小时的报告制作时间” | “下一代分析平台” |
| 使用客户的语言撰写 | “了解哪些营销活动带来了收入” | “多触点归因解决方案” |
| 差异化优势清晰 | “唯一专为代理机构打造的 CRM” | “更好的 CRM” |
| 具体明确 | 包含数字、时间范围和成果 | 模糊的最高级表述（“强大”“创新”） |

### 维度 2：标题有效性

**标题评分标准：**

| 标准 | 0 分 | 1 分 | 2 分 |
|----------|---------|---------|---------|
| 传达核心价值 | 否 | 部分传达 | 清晰传达 |
| 具体明确（数字、成果） | 宽泛 | 较为具体 | 非常具体 |
| 面向目标受众 | 宽泛 | 隐含体现 | 明确指出 |
| 与流量来源匹配 | 无关联 | 大致匹配 | 信息完全匹配 |
| 情感或逻辑吸引力 | 两者皆无 | 具备其一 | 两者兼具 |

**总分：0-10 分。得分 < 6 = 需要重写。**

### 维度 3：CTA 层级与位置

| 检查项 | 通过 | 未通过 |
|-------|------|------|
| 一个明确的主要 CTA | 单一、醒目的操作 | 多个相互竞争的 CTA |
| 无需滚动即可看到 CTA | 首屏可见 | 仅在首屏以下可见 |
| CTA 文案传达价值 | “开始免费试用” | “提交” |
| 在决策点重复展示 CTA | 在优势之后、社会证明之后和页面底部 | 仅在顶部或仅在底部 |
| 次要 CTA 明显处于次要地位 | 更小、使用不同颜色或文本链接 | 与主要 CTA 的视觉权重相同 |

### 维度 4：视觉层级与可扫读性

| 检查项 | 通过 | 未通过 |
|-------|------|------|
| 最重要的元素最醒目 | 标题 + CTA 占据主导地位 | 导航或图片占据主导地位 |
| 可在 10 秒内快速扫读 | 可通过标题、粗体和项目符号看到要点 | 大段密集文字 |
| 留白充足 | 各部分之间有足够的间隔 | 布局杂乱、密集 |
| 图片有助于传达信息 | 产品截图、相关图像 | 素材照片、装饰性图形 |
| F 型或 Z 型布局 | 内容遵循自然的视觉动线 | 随意排列 |

### 维度 5：社会证明与信任

| 检查项 | 通过 | 未通过 |
|-------|------|------|
| 客户徽标清晰可见 | 首屏可见的知名品牌徽标 | 没有徽标或仅有不知名公司的徽标 |
| 客户评价具体明确 | “收入提高了 40%” | “很棒的产品！” |
| 客户评价注明来源 | 全名、职位、公司、照片 | 匿名或仅有名字 |
| 提供信任徽章（如适用） | 安全、合规、奖项 | 没有信任标识 |
| 基于数字的证明 | “已有 10,000 多个团队使用……” | 没有规模指标 |

### 维度 6：异议处理

| 检查项 | 通过 | 未通过 |
|-------|------|------|
| 解决价格/价值异议 | ROI 计算、“起价为 $X” | 没有价格背景信息 |
| 回答“这对我有用吗？” | 使用场景、行业示例 | 只有宽泛的定位 |
| 提供风险降低措施 | 免费试用、保证、无需信用卡 | 没有风险逆转措施 |
| 解决实施方面的顾虑 | “5 分钟内完成设置” | 没有设置或复杂度方面的信息 |
| 提供 FAQ 部分 | 回答最主要的 5 个异议 | 没有 FAQ 或问题不相关 |

### 维度 7：阻碍点

| 检查项 | 通过 | 未通过 |
|-------|------|------|
| 表单经过优化 | 字段最少、标签清晰 | 字段过多、用途不明确 |
| 下一步清晰明确 | 每个部分都有明确的前进路径 | 导航混乱或存在死胡同 |
| 移动端体验 | 完全响应式、适合触控操作 | 仅支持桌面端的设计 |
| 加载时间 | < 3 秒 | > 5 秒 |
| 没有分散注意力的元素 | 简洁、聚焦的设计 | 弹窗、自动播放视频、加载时出现聊天小组件 |

## 首屏区域工程设计

首屏区域是任何页面上最宝贵的空间。它决定了访问者是继续向下滚动还是直接离开。

### 必需元素（首屏区域）

```
┌──────────────────────────────────────────┐
│  [Nav: Logo + 3-5 links + Primary CTA]  │
├──────────────────────────────────────────┤
│                                          │
│  HEADLINE: Primary value proposition     │
│                                          │
│  SUBHEADLINE: Supporting detail          │
│                                          │
│  [PRIMARY CTA BUTTON]                   │
│  [Secondary CTA: text link]             │
│                                          │
│  [Social proof: logos or stat]           │
│                                          │
│  [Hero image or product screenshot]      │
│                                          │
└──────────────────────────────────────────┘
```

### 首屏区域规则

- 标题是页面上字号最大的文本
- CTA 按钮是视觉上最醒目的交互元素
- 社会认同元素应出现在首屏区域（即使只是品牌 Logo 条）
- 首屏主图应展示产品的实际使用场景（而不是抽象图形）
- 不使用会分散用户对 CTA 注意力的自动播放视频或动画
- 导航应保持精简（最多 3-5 项，并在导航中放置 CTA）

## 社会认同层级

并非所有社会认同都同等有效。应在合适的位置使用合适的类型。

### 社会认同影响力排名

| 排名 | 类型 | 说服力 | 最佳位置 |
|------|------|----------|----------------|
| 1 | 包含指标的案例研究 | “X 公司在 3 个月内将营收提高了 40%” | 页面中部，优势部分之后 |
| 2 | 附照片的实名用户证言 | 完整姓名、职位、公司、头像 | CTA 附近，消除疑虑之后 |
| 3 | 汇总数据 | “10,000+ 个团队”或“G2 评分 4.8/5” | 首屏区域，标题附近 |
| 4 | 客户 Logo | 辨识度高的品牌 Logo | 首屏区域，Logo 条 |
| 5 | 奖项/徽章 | “G2 Leader 2026”“SOC2 Certified” | 页脚或 CTA 附近 |
| 6 | 泛泛的用户证言 | “很棒的产品！”——没有具体信息 | 不要使用（缺乏可信度） |

### 放置规则

- Logo 条：首屏区域内，CTA 下方
- 用户证言：放在它所佐证的主张所在部分之后
- 案例研究：页面中部，作为独立部分
- 数据：与标题或副标题放在一起
- 信任徽章：主要 CTA 附近及表单附近

## 疑虑消除架构

### 5 个普遍疑虑

每个产品页面都必须回应以下五个疑虑。如果页面没有回应，转化就会流失。

| 疑虑 | 回应方式 | 页面元素 |
|-----------|---------------|--------------|
| “这值得花这些钱吗？” | ROI 计算器、价格对比、“节省 X 小时” | 优势部分 + 定价背景信息 |
| “这适合我的情况吗？” | 行业示例、使用场景部分、目标用户画像 | “谁在使用此产品”部分 |
| “设置起来困难吗？” | “5 分钟内完成设置”、引导流程预览、集成服务 Logo | 功能部分或 FAQ |
| “如果不起作用怎么办？” | 免费试用、退款保证、无需信用卡 | CTA 附近 |
| “为什么选择它而不是其他替代方案？” | 对比表、差异化优势、迁移用户证言 | 页面中部或 FAQ |

### 用于处理异议的常见问题设计

常见问题部分应当成为转化前的最后一道防线。围绕以下 5 种异议来组织内容：

1. “设置需要多长时间？”（复杂度异议）
2. “我可以随时取消吗？”（承诺异议）
3. “免费试用包含哪些内容？”（价值异议）
4. “你们能与[热门工具]集成吗？”（兼容性异议）
5. “这与[竞争对手]有什么不同？”（替代方案异议）

## 页面类型实战指南

### 主页

| 元素 | 最佳实践 |
|---------|---------------|
| 受众 | 可能不了解你的冷访问者 |
| 标题 | 定位公司，而不是某一项功能 |
| CTA 划分 | 主要：“开始免费试用” / 次要：“观看演示”或“了解更多” |
| 内容 | 收益概述、社会认同、功能亮点、使用场景 |
| 导航 | 完整的站点导航（与落地页不同） |

### 落地页（付费流量）

| 元素 | 最佳实践 |
|---------|---------------|
| 导航 | 移除或最小化（不留退出路径） |
| 标题 | 与带来点击的广告保持信息一致 |
| CTA | 单一操作，在页面中向下重复 2-3 次 |
| 内容 | 在一个页面上完成完整论证：问题 > 解决方案 > 证明 > CTA |
| 社会认同 | 与广告受众直接相关 |

### 定价页

| 元素 | 最佳实践 |
|---------|---------------|
| 套餐展示 | 采用“基础—进阶—最佳”结构，并突出推荐套餐 |
| 切换选项 | 年付/月付，并显示节省百分比 |
| 功能对比 | 在首屏下方提供完整表格 |
| 常见问题 | 将“哪种套餐适合我？”作为第一个问题 |
| CTA | 为每种套餐设置具有针对性文案的 CTA |
| 社会认同 | 与各档套餐相关的徽标和客户证言 |

### 功能页

| 元素 | 最佳实践 |
|---------|---------------|
| 标题 | 展示功能带来的收益，而不是功能名称 |
| 内容 | 使用场景 > 技术能力 |
| 演示 | 截图、GIF 或交互式演示 |
| CTA | “试用此功能”或“开始免费试用” |
| 内部链接 | 链接到相关功能和定价页面 |

### 博客文章

| 元素 | 最佳实践 |
|---------|---------------|
| CTA 类型 | 与内容主题相匹配的上下文内嵌 CTA |
| 位置 | 引言之后、自然分隔处以及文章末尾 |
| CTA 样式 | 内嵌横幅或文本链接，而不是咄咄逼人的弹窗 |
| 内容 CTA | 提供相关资源（模板、清单、工具） |

## 文案备选方案方法论

在建议修改文案时，始终提供 2-3 个备选方案并说明理由。

### 备选方案生成框架

针对每个关键元素（标题、副标题、CTA），沿以下维度生成不同版本：

| 维度 | 版本 A | 版本 B | 版本 C |
|------|-----------|-----------|-----------|
| 收益重点 | 以结果为重点 | 以问题为重点 | 以功能为重点 |
| 具体程度 | 数字和数据 | 客户引言 | 使用场景 |
| 语气 | 直接且坚定 | 对话式 | 愿景式 |

### 示例

**当前标题：**“营销自动化软件”

| 版本 | 文案 | 理由 |
|---------|------|-----------|
| A（结果） | “无需增加员工人数，即可获得 3 倍的高质量潜在客户” | 具体结果 + 痛点 |
| B（问题） | “不要再因为团队无法及时跟进而流失潜在客户” | 直击痛点 |
| C（社会认同） | “2,000 多个营销团队如何达成销售管道目标” | 权威性 + 具体性 |

**建议：** 先测试 A（最具体），如果 A 的表现未优于当前版本，则测试 B（不同的心理角度）。

## 流量来源匹配

不同的流量来源需要不同的页面优化策略。

| 来源 | 访客状态 | 页面必须做到 |
|--------|-------------|-------------|
| 付费搜索（品牌词） | 了解你，意向强烈 | 提供快速行动路径，尽量减少教育内容 |
| 付费搜索（非品牌词） | 已意识到问题，正在寻找解决方案 | 证明你能解决他们的具体问题 |
| 付费社交媒体 | 注意力被打断，意向较低 | 吸引注意力、进行教育、激发兴趣 |
| 自然搜索 | 处于调研模式 | 提供全面内容，逐步促成转化 |
| 电子邮件 | 已经参与互动 | 兑现电子邮件中的承诺，减少阻力 |
| 推荐流量 | 已被推荐者提前说服 | 印证推荐者的推荐，并提供快速 CTA |

### 信息匹配审查

对于付费流量：比较广告文案与落地页标题。二者必须具备：
- 相同的语言/术语
- 相同的承诺
- 相同的优惠
- 视觉一致性（如果是展示广告）

**不匹配 = 浪费广告支出。** 用户点击宣传“免费 SEO 审计”的广告后，如果进入的是一个通用主页，就会直接离开。

## A/B 测试框架

### 测试优先级矩阵

| 优先级 | 测试内容 | 预期影响 |
|----------|-------------|-----------------|
| 1 | 标题文案 | 转化率提升 10-30% |
| 2 | CTA 文案和颜色 | 转化率提升 5-20% |
| 3 | 社会认同的展示位置 | 转化率提升 5-15% |
| 4 | 首屏布局 | 转化率提升 5-20% |
| 5 | 减少表单字段 | 完成率提升 5-10% |
| 6 | 主视觉图片与视频的对比 | 提升 2-10%（因情况而异） |

### 测试设计规则

- 每次测试一个变量（除非在流量充足的情况下运行多变量测试）
- 每个版本至少获得 200 次转化后，才能宣布胜出版本
- 测试应覆盖完整的业务周期（至少 2 周）
- 跟踪下游指标（不仅是页面转化率，还包括潜在客户质量/收入）

### 修复与测试的决策

| 情况 | 操作 |
|-----------|--------|
| 明显的 UX 问题（表单损坏、缺少 CTA） | 立即修复，无需测试 |
| 缺少社会认同 | 添加，无需测试 |
| 标题文案备选方案 | 进行 A/B 测试 |
| 布局变更 | 进行 A/B 测试 |
| 移除页面元素 | 进行 A/B 测试 |
| 添加新板块 | 进行 A/B 测试 |

## 指标和基准

### 转化率基准

| 页面类型 | 低于平均水平 | 平均 | 良好 | 优秀 |
|-----------|-------------|---------|------|-----------|
| SaaS 主页 | < 2% | 2-4% | 4-7% | > 7% |
| 落地页（付费流量） | < 5% | 5-10% | 10-20% | > 20% |
| 定价页面 | < 3% | 3-5% | 5-10% | > 10% |
| 博客文章（转化为电子邮件订阅） | < 1% | 1-3% | 3-5% | > 5% |
| 功能页面 | < 2% | 2-5% | 5-8% | > 8% |

### 关键指标

| 指标 | 它能告诉你什么 |
|--------|------------------|
| 跳出率 | 页面是否符合访客的预期？ |
| 滚动深度 | 访客浏览了多少页面内容？ |
| 页面停留时间 | 访客是在阅读，还是立即离开？ |
| CTA 点击率 | CTA 是否有吸引力且清晰可见？ |
| 表单开始填写率 | 访客是否开始了转化流程？ |
| 表单完成率 | 他们是否完成了表单？ |

## 输出产物

| 产物 | 格式 | 描述 |
|----------|--------|-------------|
| CRO 审计报告 | 7 维度分析 | 按维度评估并标注严重程度 |
| 快速改进清单 | 项目符号列表（最多 5 项） | 可于当天实施，并附预期影响 |

| A/B 测试计划 | 按优先级排序的表格 | 假设、变体、成功指标、优先级 |
| 流量来源匹配审计 | 流量来源 × 页面元素表格 | 按流量来源评估信息匹配度 |

## 相关 Skill

- **form-cro** -- 当页面上的表单是具体瓶颈时使用（字段优化、验证、移动端表单用户体验）。
- **signup-flow-cro** -- 当用户在页面上完成转化，但在注册流程中流失时使用。
- **popup-cro** -- 当考虑将弹窗作为页面上的额外转化层时使用。
- **onboarding-cro** -- 当转化后的激活才是真正的问题，而页面本身的转化表现已足够好时使用。
- **pricing-strategy** -- 当定价页面需要进行结构性重新设计（套餐层级结构、价值衡量指标），而不仅仅是 CRO 微调时使用。

## 故障排除

| 问题 | 可能原因 | 解决方案 |
|---------|-------------|----------|
| 落地页跳出率较高（>70%） | 与流量来源的信息不匹配，或首屏表现不佳 | 审查信息匹配度：将广告文案与落地页标题进行比较；确保用户能在最初 5 秒内看到价值主张 |
| 页面在桌面端有转化，但在移动端没有 | 移动端用户体验未优化 | 检查触控目标（44px+）、移动端表单字段数量，以及无需滚动即可看到的 CTA；使用 page_cro_scorer.py 评分 |
| CTA 点击率低于 2% | CTA 过于笼统、位于首屏下方或视觉效果较弱 | 将“Submit”替换为明确体现价值的文案；确保 CTA 在首屏可见，并在关键部分之后重复展示 |
| 滚动深度较高，但转化率较低 | 访客阅读了内容，但尚未被说服采取行动 | 在 CTA 附近添加社会认同；在 FAQ 中回应异议；加入风险逆转措施（免费试用、无需 CC） |
| A/B 测试 4 周后仍未出现显著优胜版本 | 改动太小而难以检测，或流量不足 | 使用 form-cro 中的 ab_test_calculator.py 验证样本量；测试更大的改动（重写标题，而不是替换单个词语） |
| 付费流量的转化表现不如自然流量 | 落地页未针对付费流量的意图进行定制 | 为付费广告活动创建信息匹配的专用落地页；移除付费落地页上的导航 |
| 社会认同部分被忽略 | 推荐语过于笼统或位置不佳 | 使用包含具体信息、明确归属且带有指标的推荐语；将其放在所验证主张对应的部分之后 |

## 成功标准

- 在 7 维框架中，页面 CRO 得分达到 70+（由 page_cro_scorer.py 评分）
- 标题在 10 分制评分标准中达到 7+（由 headline_scorer.py 评分）
- 转化率达到或超过相应页面类型的行业基准（由 conversion_benchmark_calculator.py 验证）
- 首屏包含：标题、CTA 和至少一个社会认同元素
- 所有付费流量广告活动均已验证信息匹配度（广告文案与落地页标题匹配）
- 移动端转化率与桌面端转化率的差距在 20% 以内
- 每个页面至少回应 5 种普遍异议中的 3 种

## 范围与限制

- **范围内：** 页面级转化优化、标题有效性、CTA 层级、社会认同的布局、异议处理、流量来源匹配、A/B 测试优先级排序
- **范围外：** 表单优化（使用 form-cro）、注册流程优化（使用 signup-flow-cro）、弹窗优化（使用 popup-cro）、定价结构变更（使用 pricing-strategy）
- **页面速度：** 此技能涵盖 CRO 元素，不涉及技术性能；加载时间 >3 秒的页面需要先进行技术优化
- **最低流量要求：** A/B 测试建议要求每个版本获得 200+ 次转化；低流量页面应直接实施最佳实践，而不进行测试
- **定性输入：** 热图和会话录制可提供仅靠分析数据无法揭示的关键行为数据；可考虑投资使用这些工具

## 集成点

- **form-cro** -- 当页面上的表单成为瓶颈时（字段优化、验证用户体验、移动端表单体验）
- **signup-flow-cro** -- 当用户在页面上完成转化，但在注册流程中途流失时
- **popup-cro** -- 当考虑将弹窗作为叠加在页面之上的额外转化层时
- **onboarding-cro** -- 当转化后的激活才是真正的问题，而页面本身的转化表现尚可时
- **pricing-strategy** -- 当定价页面需要结构性重新设计（套餐层级结构、价值指标），而不仅仅是 CRO 微调时
- **competitive-teardown** -- 当对比页面需要竞品数据来构建可信内容时
