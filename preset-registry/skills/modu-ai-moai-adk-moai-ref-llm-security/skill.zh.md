# LLM / AI 防御性安全参考

面向防御实践人员的参考资料，用于加固由 LLM 支持的应用程序和智能体。
每一节均从防御、加固、检测或验证的角度展开——说明错误配置、如何检测以及如何防止，而绝不会说明如何利用它。跨领域的 Web 应用程序漏洞参见
`moai-ref-owasp-checklist`；API 设计参见 `moai-ref-api-patterns`。

## 适用场景

在审查或构建由 LLM 支持的系统时使用——包括聊天产品、检索增强型应用程序、自主智能体或 MCP 服务器。
本文采用不可信输入威胁模型：模型读取的任何文本（用户对话轮次、检索到的文档、工具结果、文件内容）都可能携带对抗性指令，而模型生成的任何文本都可能被下游系统执行或处理。

## LLM 系统中的信任边界

核心防御要点：LLM 无法像解析器那样区分“数据”与“指令”。应将到达模型的每个文本通道都视为对抗性指令可能进入的边界。

| 通道 | 入口风险 | 主要防御措施 |
|---------|-----------|-----------------|
| 最终用户提示词 | 直接提示词注入 | 强制执行指令层级、输入筛查 |
| 检索到的文档（RAG） | 间接提示词注入 | 来源标记、内容隔离、检索允许列表 |
| 工具／函数结果 | 工具输出中注入的指令 | 将工具输出视为不可信数据，在重新提供给提示词之前再次验证 |
| 系统／开发者提示词 | 泄露、覆盖 | 尽量减少提示词中的秘密信息，假定提示词可被恢复 |
| 模型输出 | 下游处理不当 | 模式验证、编码、绝不自动执行原始输出 |
| 训练／微调数据 | 投毒 | 数据血缘、来源验证、金丝雀检测 |

## OWASP LLM 十大风险——防御映射

OWASP LLM 应用程序十大风险（2025 版）是 LLM 系统的权威风险索引。
下表每一行都列出了风险、防御检查项和加固控制措施。引用仅用于防御性关联。

| ID | 风险 | 防御检查项 | 加固控制措施 |
|----|------|-----------------|-------------------|
| LLM01 | 提示词注入 | 外部文本能否覆盖系统指令？ | 强制执行指令层级、输入／输出筛查、内容隔离 |
| LLM02 | 敏感信息披露 | 模型能否泄露秘密信息、PII 或系统提示词？ | 输出过滤、尽量减少上下文中的秘密信息、响应脱敏 |
| LLM03 | 供应链 | 模型权重、数据集和插件是否来自经验证的来源？ | 来源验证、模型／数据集签名、依赖项版本锁定 |
| LLM04 | 数据和模型投毒 | 训练／微调数据是否可能携带对抗性内容？ | 数据血缘、金丝雀制品、训练集异常检测 |
| LLM05 | 输出处理不当 | 模型输出是否未经验证便被执行／渲染？ | 模式验证、上下文感知编码、禁止自动执行 |
| LLM06 | 过度代理能力 | 智能体是否拥有超出所需范围的能力／权限？ | 最小权限工具设计、高影响操作引入人工干预 |
| LLM07 | 系统提示词泄露 | 系统提示词中是否包含可能在提取时泄露的秘密信息？ | 绝不在提示词中存储秘密信息；假定提示词可被恢复 |
| LLM08 | 向量与嵌入弱点 | 嵌入／RAG 存储是否可能被投毒或发生跨租户泄露？ | 按租户隔离、嵌入来源验证、访问控制 |
| LLM09 | 错误信息 | 未经验证的模型输出是否被作为权威信息呈现？ | 事实依据、引用要求、置信度标示 |
| LLM10 | 无界资源消耗 | 请求能否耗尽令牌、成本或计算资源？ | 速率限制、令牌预算、请求大小上限、强制执行超时 |

## 提示词注入防御

提示词注入是发生频率最高的 LLM 风险（LLM01）。防御需要采用纵深防御策略——任何单一控制措施都不足以应对，因此应分层实施以下控制措施。

### 直接注入（用户即攻击者）

| 层级 | 控制措施 | 目的 |
|-------|---------|---------|
| 指令层级 | 将系统指令标记为最高优先级；指示模型下游文本无法覆盖这些指令 | 降低指令被覆盖的成功率 |
| 输入筛查 | 在传入的提示词到达模型之前，扫描其中已知的注入标记 | 检测明显的覆盖尝试 |
| 权限分离 | 将高可信的规划模型与接触不可信内容的低可信任务模型分开运行 | 限制成功注入造成的影响范围 |
| 输出门控 | 在根据模型响应采取行动之前，对照预期格式的允许列表验证响应 | 阻止注入指令在下游生效 |

### 间接注入（攻击者污染检索内容）

间接注入通过模型读取的文档、网页、电子邮件或工具结果进入。防御方法是将所有检索到的内容都视为不可信数据，而绝不能视为指令。

- **来源标记**：将检索到的内容包装在边界清晰、带有标签的块中，以指示模型将其中的文本视为需要分析的数据，而不是需要服从的命令。
- **内容隔离**：将检索到的内容置于与指令通道分离的通道中；不要把不可信文本直接拼接在系统指令之后。
- **检索允许列表**：将 RAG 来源限制为经过验证的语料库；拒绝或隔离来源未经验证的文档。
- **工具调用后重新验证**：当工具返回的文本重新进入提示词时，再次对其进行筛查——工具结果是不可信通道，而不是可信通道。

此类攻击对应 MITRE ATLAS **AML.T0051**（LLM 提示词注入）；上述防御措施用于检测和防止此类攻击，而不是攻击流程。

## MCP / 智能体工具调用加固

调用工具（包括 MCP 服务器）的智能体系统会扩大攻击面：成功的注入现在可以驱动真实操作。防御方法是采用最小权限工具设计，并重新验证输出（LLM06 过度代理权）。

### 工具权限范围限定

| 控制措施 | 防御依据 |
|---------|---------------------|
| 最小权限工具集 | 仅开放任务所需的工具；无法执行删除操作的智能体就不会被诱骗去执行删除 |
| 每个工具使用限定范围的凭据 | 工具仅持有其功能所需的最低权限凭据，绝不持有权限宽泛的管理员令牌 |
| 人在回路门控 | 无论模型的置信度如何，高影响操作（付款、删除、对外发布、强制推送）都需要明确确认 |
| 可调用目标允许列表 | 限制工具可以访问的主机、路径或资源；阻止访问内部端点或元数据端点 |
| 幂等性 + 试运行 | 优先采用可撤销或可预览的操作；在执行不可逆操作之前进行确认 |

### 工具输出验证

将每个工具结果在返回模型的过程中都视为不可信输入：

- 在重新提示之前，**对工具结果进行模式验证**——拒绝格式错误或
  过大的载荷。
- **移除或中和工具输出中形似指令的内容**（返回网页的工具可能会在该页面中
  携带注入内容）。
- **限制工具调用循环**——限定每项任务的工具调用次数，以
  防止注入的指令导致无限操作链
  （LLM10 无界消耗）。
- **记录每次工具调用**及其参数和结果，以便进行审计和异常
  检测。

这种加固措施通过最大限度减少被攻陷的工具路径所能触及的范围，防范 MITRE ATLAS **AML.T0053**（LLM 插件入侵）
类别的风险。

## 训练数据和模型投毒检测

投毒（LLM04）通过将对抗性样本插入
训练或微调数据，或者替换被篡改的模型制品来破坏模型行为。
防御重点是来源追踪和检测，而不是重新训练方案。

| 防御措施 | 检测对象 | 应用方式 |
|---------|-----------------|--------------|
| 数据血缘 | 未经追踪或验证便进入训练集的数据 | 记录每个数据集的来源、哈希值和获取路径 |
| 金丝雀制品 | 已知的标记样本是否意外影响了模型 | 插入已知的金丝雀记录；在训练后验证模型对这些记录的行为 |
| 来源验证 | 被替换或篡改的模型/数据集 | 使用前验证模型权重和数据集的加密签名 |
| 分布监控 | 训练数据统计特征的异常偏移 | 将新数据批次与已建立的分布基线进行比较 |
| 来源白名单 | 来自未经验证来源的数据 | 将训练语料限制为经过审查且已签名的来源 |

投毒对应 MITRE ATLAS **AML.T0020**（训练数据投毒）；上述检测
控制措施属于防御性关联，绝不是攻击方法。

## 模型输出验证和护栏

输出处理不当（LLM05）是指下游系统信任原始模型输出。
防御措施是在验证之前将模型输出视为不可信内容。

### 输出验证层

| 层级 | 控制措施 | 防范内容 |
|-------|---------|----------|
| 结构化输出 | 对响应强制实施模式约束（类型化对象、受限语法） | 携带注入命令的自由格式输出 |
| 内容过滤 | 筛查输出中的策略违规、泄露的机密信息或禁止内容 | 敏感信息泄露（LLM02）、系统提示词泄露（LLM07） |
| 上下文感知编码 | 根据输出接收端进行编码（HTML 转义、shell 引号转义、SQL 参数化） | 针对下游解释器的输出处理注入 |
| 禁止自动执行 | 绝不将原始模型输出直接传入 shell、eval 或查询 | 通过模型实施远程代码执行 |
| 事实锚定 + 引用 | 要求模型为事实性声明引用来源 | 将错误信息（LLM09）呈现为权威结论 |

### 护栏设置位置

护栏应部署在模型的**两端**——输入护栏筛查进入模型的内容，输出护栏筛查离开模型的内容。仅有输出护栏会漏掉已经改变模型计划的注入；仅有输入护栏会漏掉响应中的敏感信息泄露。两者应分层部署。

## MITRE ATLAS — 防御关联

MITRE ATLAS 收录了针对 AI 系统的对抗技术。这些技能引用 ATLAS 技术 ID，是为了将防御措施与其所对抗的技术相关联——绝不是为了提供攻击方法。具有代表性的防御关联如下：

| ATLAS 技术 | 技术名称 | 应对该技术的防御控制措施 |
|-----------------|----------------|------------------------------------|
| AML.T0051 | LLM 提示词注入 | 指令层级强制执行、内容隔离、输入/输出筛查 |
| AML.T0020 | 训练数据投毒 | 数据血缘、金丝雀制品、来源验证 |
| AML.T0054 | LLM 越狱 | 输出过滤、拒绝策略强制执行、响应门控 |
| AML.T0057 | LLM 数据泄露 | 输出脱敏、最小化上下文中的秘密、按租户隔离 |

对于每项技术，技能说明的是如何检测和防御，而不是如何实施。将 ATLAS 技术 ID 当作攻击方法，正是本技能明确禁止的反模式。

## NIST AI RMF — 治理映射

NIST AI 风险管理框架（AI RMF 1.0）将 AI 风险划分为四项职能。可将 LLM 安全控制映射到这些职能，以实施防御性治理：

| 职能 | 防御活动 |
|----------|--------------------|
| GOVERN | 为 LLM 系统制定 AI 安全策略，明确问责机制和事件响应责任归属 |
| MAP | 盘点 LLM 组件、数据源、工具权限和信任边界；识别威胁模型 |
| MEASURE | 测试提示词注入抵抗能力、输出验证覆盖率和护栏有效性；跟踪发现的问题 |
| MANAGE | 确定已识别风险的优先级并进行修复；监控生产环境行为；维护响应计划 |

这四项职能提供了防御性治理框架；OWASP LLM Top 10 和 MITRE ATLAS 则提供需要映射、衡量和管理的具体风险。

## 防御严重性级别

| 级别 | 标签 | 措施 | 示例 |
|-------|-------|--------|---------|
| P0 | 严重 | 阻止发布 | 在 shell 中执行原始模型输出；拥有破坏性工具的智能体未进行输出验证 |
| P1 | 高 | 合并前修复 | 处理不受信任文档的系统未强制执行指令层级 |
| P2 | 中 | 在当前迭代内修复 | 工具调用循环没有上限；缺少输入筛查 |
| P3 | 低 | 在待办事项中跟踪 | 系统提示词略微过度披露内部结构（未泄露秘密） |

## 常见的自我辩解

| 自我辩解 | 事实 |
|---|---|
| “模型足够智能，能够忽略注入的指令” | 模型无法可靠地区分数据与指令。即使能力强大的模型仍可能受到注入文本的操纵；真正的控制措施是纵深防御，而非模型能力。 |
| “我们只读取内部文档，因此 RAG 内容是可信的” | 内部文档可能被遭入侵的账户或上游数据源修改。间接注入并不需要外部攻击者——应将所有检索到的内容视为不可信。 |
| “输出验证会拖慢响应速度，用户不会注意到这种风险” | 未经验证的输出正是模型响应演变为 shell 命令和 XSS 的途径。验证是聊天回复与远程代码执行之间的边界。 |
| “智能体需要广泛的权限才能发挥作用” | 过度的自主权是 OWASP LLM Top 10 风险之一。应根据任务限定工具范围；智能体不具备的能力无法通过注入被滥用。 |
| “我们对输出设置了防护措施，这就足够了” | 仅针对输出的防护措施无法发现已经改变模型计划和工具调用的注入。输入和输出两端都应设置防护措施。 |
| “提示词注入是研究问题，而不是生产环境中的问题” | 如今，间接提示词注入已被用于攻击生产环境中的 RAG 和智能体系统。这是当前的运营风险，而非理论风险。 |

**默认不可信**：到达模型的每个文本通道——用户输入、
检索到的文档、工具结果——在经过筛查之前均不可信。模型不是
信任边界；你的验证层才是。

## 危险信号

- 模型输出未经模式验证或编码，便被直接传入 shell、eval、query 或 `innerHTML`
- 检索到的 RAG 内容未经隔离或来源标记，便直接拼接在系统指令之后
- 智能体持有具有破坏性或高权限的工具，但高影响操作没有人在环审核关卡
- 工具结果未经重新筛查并作为不可信输入处理，便重新进入提示词
- 系统提示词中嵌入了机密信息、API 密钥或凭据（应假定提示词可以被恢复）
- 每个请求的工具调用循环次数或令牌消耗没有上限
- 仅在模型的一端设置了防护措施（仅输入端或仅输出端）

## 验证

- [ ] 到达模型的每个文本通道均被归类为可信或不可信，并对不可信通道进行筛查
- [ ] 系统指令采用指令层级强制执行机制，以防止被下游文本覆盖
- [ ] 检索到的/RAG 内容经过隔离并标记来源，而不是拼接在指令之后
- [ ] 模型输出在任何下游使用之前均经过模式验证和上下文编码；不得自动执行任何原始输出
- [ ] 智能体工具遵循最小权限范围限定原则；高影响操作设有人在环审核关卡
- [ ] 工具结果在重新提示之前被重新验证并作为不可信输入处理；工具调用循环受到限制
- [ ] 设计已对照 OWASP LLM Top 10 进行映射（说明评估了哪些项目），并依据 NIST AI RMF 的各项职能进行治理
- [ ] 系统提示词中不存在任何机密信息；输出过滤会筛查敏感信息泄露
