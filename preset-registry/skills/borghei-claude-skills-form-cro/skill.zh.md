## 首先澄清

在优化表单之前，请确认以下信息。如果其中任何一项未知或含糊，请询问——不要自行假设：

- [ ] **表单类型**——潜在客户信息收集、联系、演示申请、申请或结账（决定最佳字段数量和实战指南）
- [ ] **当前字段及后续跟进中实际使用的字段**——明确哪些字段应删除或通过数据补全获得（这是字段成本分析的核心）
- [ ] **当前完成率及用户放弃的位置**——确定基准和需要解决的具体摩擦点
- [ ] **合规要求**——无法删除的 GDPR/HIPAA 字段（限制字段精简空间）

停止规则：只询问对输出影响最大的 2-3 项。如果用户说“直接起草”，则继续执行，并在审计报告顶部列出你的假设。

## 初步评估

### 必需的背景信息

| 问题 | 重要性 |
|----------|---------------|
| 表单属于什么类型？（潜在客户信息收集、联系、演示申请、申请、结账） | 不同类型的最佳字段数量不同 |
| 当前有多少个字段？ | 确立当前摩擦程度的基准 |
| 当前完成率是多少？ | 作为衡量改进的基准 |
| 用户会在哪里放弃？（如果有字段级分析数据） | 找出具体的摩擦点 |
| 移动端与桌面端的占比是多少？ | 移动端表单需要单独优化 |
| 提交的数据将如何处理？ | 确定哪些字段是真正必要的 |
| 哪些字段实际用于后续跟进？ | 通常会发现 30-50% 的字段从未使用 |
| 是否有任何合规要求？（GDPR、HIPAA） | 限制可删除的内容 |

## 字段成本分析框架

每个字段都会带来以放弃率衡量的成本。问题不在于“哪些数据最好能有”，而在于“哪些数据值得付出转化损失”。

### 字段成本矩阵

| 字段类型 | 预计放弃成本 | 合理性门槛 |
|-----------|---------------------------|------------------------|
| 电子邮箱 | 基准值（对于门槛内容几乎为零） | 对潜在客户表单而言始终合理 |
| 名 | 放弃率增加 2-3% | 如果个性化能够促进后续跟进，则合理 |
| 姓 | 放弃率增加 2-3% | 在首次接触时通常没有必要 |
| 电话号码 | 放弃率增加 5-10% | 仅当销售人员会在 24 小时内致电时才合理 |
| 公司名称 | 放弃率增加 3-5% | 对 B2B 客户资格评估而言合理 |
| 公司规模 | 放弃率增加 3-5% | 仅当线索分配决策依赖此信息时才合理 |
| 职位 | 放弃率增加 3-5% | 通常可以在提交后通过数据补全获得 |
| 行业 | 放弃率增加 2-3% | 通常可以在提交后通过数据补全获得 |
| 留言/文本区域 | 放弃率增加 5-8% | 对联系表单而言合理，但不适用于潜在客户信息收集 |
| 预算 | 放弃率增加 8-12% | 仅适用于高意向的演示申请/销售表单 |
| 自定义问题 | 每个问题使放弃率增加 3-5% | 必须直接影响潜在客户分配或资格评估 |

### 数据补全测试

在加入任何字段之前，先问：**该信息能否在用户提交后补全？**

| 字段 | 可补全？ | 方法 | 保留在表单中？ |
|-------|------------|--------|---------------|
| 公司名称 | 是（根据电子邮件域名） | Clearbit、Apollo、人工查询 | 移除 |
| 公司规模 | 是（根据公司名称） | 数据补全 API | 移除 |
| 行业 | 是（根据公司名称） | 数据补全 API | 移除 |
| 职位 | 部分可以（通过 LinkedIn） | 人工补全 | 移除，除非对线索分配至关重要 |
| 电话号码 | 否 | 必须由用户提供 | 仅在需要立即进行销售电话沟通时保留 |
| 预算 | 否 | 必须由用户说明 | 仅在高意向表单中保留 |

### 按表单类型推荐的字段集

| 表单类型 | 最少字段 | 最佳字段 | 最多字段 |
|-----------|---------------|----------------|----------------|
| 新闻简报订阅 | 电子邮件 | 电子邮件 | 电子邮件 + 名字 |
| 内容下载 | 电子邮件 | 电子邮件 + 名字 | 电子邮件 + 姓名 + 公司 |
| 联系表单 | 电子邮件 + 留言 | 电子邮件 + 姓名 + 留言 | 电子邮件 + 姓名 + 主题 + 留言 |
| 演示申请 | 电子邮件 + 公司 | 电子邮件 + 姓名 + 公司 + 职位 | + 电话 + 使用场景 + 团队规模 |
| 申请表单 | 根据要求而异 | -- | 所有必填字段（逐一说明理由） |

## 多步骤与单步骤决策

### 决策标准

| 因素 | 单步骤 | 多步骤 |
|--------|------------|------------|
| 字段总数 | < 5 个字段 | > 5 个字段 |
| 字段复杂度 | 简单文本输入框 | 下拉菜单、复选框和条件字段的组合 |
| 用户动机 | 低投入（新闻简报、内容） | 高投入（演示、申请） |
| 资格筛选需求 | 无需分配 | 根据回答进入不同路径 |
| 移动端用户占比 | < 30% 移动端用户 | > 50% 移动端用户 |

### 多步骤最佳实践

**步骤结构：**
- 第 1 步：最简单的字段（电子邮件、姓名）-- 以最低阻力开始
- 第 2 步：资格筛选信息（公司、职位、使用场景）
- 第 3 步：具体信息（预算、时间安排、留言）

**进度指示：**
- 显示带有步骤数的进度条（“第 2 步，共 3 步”）
- 显示完成百分比
- 用所涵盖的内容标记每个步骤（“您的详细信息”“公司信息”“项目详情”）

**心理承诺：**
- 用户完成第 1 步后，完成整个表单的可能性会提高 40-60%（沉没成本效应）
- 在第 1 步收集电子邮件，以便即使用户之后放弃填写，你仍可跟进

**返回导航：**
- 始终允许用户返回之前的步骤
- 在步骤之间导航时保留已输入的数据
- 返回上一步时绝不能重置表单

## 字段设计模式

### 字段标签

| 模式 | 使用场景 | 示例 |
|---------|-------------|---------|
| 字段上方标签 | 大多数表单的默认选择 | 标签位于输入框上方 |
| 行内标签（浮动） | 空间受限的布局 | 获得焦点时，标签从输入框内部移至上方 |
| 左对齐标签 | 宽屏桌面端表单 | 标签位于字段左侧 |
| 仅使用占位符作为标签 | 绝不使用 | 输入时消失，导致无障碍访问失败 |

### 字段类型

| 所需数据 | 最佳输入类型 | 避免使用 |
|------------|-----------------|-------|
| 电子邮件 | 带验证的 `type="email"` | 纯文本输入框 |
| 电话 | 带格式掩码的 `type="tel"` | 纯文本输入框 |
| 国家/地区 | 可搜索的下拉菜单 | 冗长的静态下拉菜单 |
| 公司规模 | 按钮组（1-10、11-50、51-200、200+） | 自由文本输入框 |
| 兴趣/主题 | 复选框组（最多 6 个选项） | 多选下拉菜单 |
| 留言 | 文本区域（显示 3-4 行） | 单行文本输入框 |
| 日期 | 原生日期选择器 | 三个独立的下拉菜单 |

### 条件字段

根据之前的回答显示其他字段。这样既能获取必要的数据，又能降低界面的可见复杂度。

**示例：**“您的主要目标是什么？”下拉菜单仅在用户选择“准备购买”或“正在评估解决方案”时显示“预算范围”。

**规则：**
- 条件字段应通过平滑动画出现（而不是瞬间跳出）
- 每个触发条件仅显示 1-2 个条件字段
- 条件字段永远不应设为必填（因为触发条件的答案可能会改变）

## 验证用户体验

### 实时验证与提交时验证

| 验证类型 | 使用时机 |
|----------------|-------------|
| 实时验证（失去焦点时） | 电子邮件格式、电话格式、必填字段 |
| 提交时验证 | 复杂验证、服务端检查 |
| 内联建议 | 公司名称自动补全、地址查询 |

### 错误消息设计

| 模式 | 好的做法 | 不好的做法 |
|---------|------|-----|
| 位置 | 显示在字段下方，与上下文关联 | 显示在表单顶部，与出错位置脱节 |
| 语气 | “请输入有效的电子邮件地址” | “错误：输入无效” |
| 具体程度 | “电话号码必须包含区号” | “电话号码无效” |
| 颜色 | 红色文本 + 字段红色边框 | 页面顶部的红色横幅 |
| 图标 | 消息旁显示错误图标 | 没有视觉提示 |

### 成功提示

- 在有效字段上显示绿色对勾（尤其是电子邮件和电话字段）
- 使用积极的微文案：电子邮件有效时显示“看起来没问题！”
- 不要在每次按键时都闪烁绿色/红色提示——应在失去焦点时（用户离开字段时）进行验证

## CTA 和提交按钮优化

### 按钮文案框架

| 表单类型 | 较弱的文案 | 较强的文案 | 最强的文案 |
|-----------|-----------|-------------|----------------|
| 内容下载 | 提交 | 下载指南 | 获取我的免费指南 |
| 演示申请 | 提交 | 申请演示 | 安排我的演示 |
| 联系表单 | 发送 | 发送消息 | 与我们联系 |
| 新闻简报 | 订阅 | 订阅新闻简报 | 获取每周技巧 |
| 免费试用 | 注册 | 开始免费试用 | 免费开始构建 |

**规则：**
- 使用第一人称（使用“获取我的……”，而不是“获取您的……”）
- 说明用户将获得什么，而不是他们要做什么
- 适用时加入“免费”
- 控制在 5 个词以内

### 按钮设计

| 元素 | 最佳实践 |
|---------|---------------|
| 颜色 | 与表单背景形成高对比度，并与品牌 CTA 颜色保持一致 |
| 尺寸 | 在移动端占满宽度，触控目标高度至少为 44px |
| 位置 | 紧接在最后一个字段下方，不留间隙 |
| 加载状态 | 显示旋转指示器 + “正在发送……”，防止重复提交 |
| 禁用状态 | 在必填字段均有效之前保持禁用（并提供清晰的视觉区分） |

## 移动端表单优化

### 移动端特定规则

| 规则 | 实现方式 |
|------|---------------|
| 触控目标 | 所有交互元素的尺寸至少为 44x44px |
| 键盘类型 | 电子邮件使用 `type="email"`，电话号码使用 `type="tel"`，数字使用 `type="number"` |
| 自动聚焦 | 页面加载时聚焦第一个字段（同时打开键盘） |
| 固定提交按钮 | 对于较长的表单，将提交按钮固定在视口底部 |
| 输入框间距 | 字段之间至少保留 8px 的间距，以防误触 |
| 下拉菜单替代方案 | 在移动端使用按钮组或单选按钮代替下拉菜单 |
| 自动填充 | 支持浏览器自动填充标准字段（姓名、电子邮件、电话号码、地址） |

### 移动端与桌面端表单的差异

| 方面 | 桌面端 | 移动端 |
|--------|---------|--------|
| 布局 | 1 列或 2 列 | 始终为 1 列 |
| 字段数量 | 最多 8 个 | 每一步最多 5 个 |
| 下拉菜单 | 标准下拉菜单 | 底部弹出面板或全屏选择器 |
| 帮助文本 | 悬停工具提示 | 始终可见的内联文本 |
| 验证 | 失去焦点时 | 失去焦点时 + 提交时显示摘要 |

## 信任与上下文元素

### 表单附近的信任信号

| 信号 | 位置 | 影响 |
|--------|-----------|--------|
| 隐私保证 | 提交按钮下方 | “我们绝不会分享您的电子邮件地址” |
| 安全徽章 | 表单容器旁边 | SSL、SOC2、GDPR 合规 |
| 用户评价 | 表单旁边 | 社会认同可减少犹豫 |
| 响应时间 | 提交按钮下方 | “我们会在 2 小时内回复” |
| 订阅者/用户数量 | 表单上方或表单内 | “加入 10,000 多名订阅者” |

### 上下文强化

| 元素 | 目的 | 示例 |
|---------|---------|---------|
| 表单标题 | 提醒用户将获得什么 | “获取您的免费 SEO 审核报告” |
| 表单上方的项目符号列表 | 强化价值 | “您将获得：完整的网站分析、优先修复清单、30 分钟评审通话” |
| 预期的后续步骤 | 明确预期 | “提交后，我们将在 24 小时内通过电子邮件发送您的报告” |

## 表单类型操作指南

### 潜在客户信息收集（门控内容）

**目标：** 在收集合格潜在客户信息的同时，最大限度提高完成率。
- 字段：仅电子邮件（或最多为电子邮件 + 名字）
- CTA：突出具体价值（“获取我的报告”“下载清单”）
- 信任：“无垃圾邮件，可随时取消订阅”
- 提交后：立即下载 + 感谢页面 + 后续电子邮件

### 演示申请

**目标：** 获取已准备好与销售人员沟通的合格潜在客户。
- 字段：电子邮件 + 姓名 + 公司（+ 可选的电话号码和团队规模）
- CTA：“预约我的演示”
- 信任：“30 分钟通话，无需承诺”
- 提交后：日历预约页面或包含预约链接的确认页面
- 考虑事项：使用嵌入式日历（Calendly/Cal.com）代替表单

### 联系表单

**目标：** 方便用户沟通，同时将请求转交给正确的团队。
- 字段：电子邮件 + 姓名 + 主题下拉菜单 + 留言
- CTA：“发送消息”
- 信任：“我们会在 [X] 小时内回复”
- 提交后：显示包含预计响应时间的确认信息
- 考虑事项：添加部门/主题分流下拉菜单

### 报价申请

**目标：** 收集足够的信息，以便准确报价。
- 字段：包含项目详细信息的多步骤表单
- CTA：“获取我的报价”
- 信任：“免费报价，无任何义务”
- 提交后：告知报价交付时间 + 人工跟进

## A/B 测试框架

### 高影响力测试（优先运行）

| 测试 | 假设 | 成功指标 |
|------|-----------|----------------|
| 移除电话字段 | 移除电话字段可将完成率提高 5-10% | 完成率 |
| 从单步改为多步 | 对包含 6 个以上字段的表单，多步形式可提高完成率 | 完成率 + 提交质量 |
| 更改 CTA 文案 | 突出具体价值的文案可将点击量提高 10-20% | 点击率 |
| 添加社会认同 | 表单附近的用户证言可增强信任 | 完成率 |

### 中等影响力测试

| 测试 | 假设 | 成功指标 |
|------|-----------|----------------|
| 更改字段顺序 | 将最容易填写的字段放在前面可提高第 1 步完成率 | 各步骤完成率 |
| 行内验证 | 实时反馈可减少表单错误 | 错误率 + 完成率 |
| 添加进度条 | 在多步表单中显示可视化进度可提高完成率 | 完成率 |
| 嵌入式日历与表单对比 | 对演示申请而言，日历可减少操作阻力 | 预约率 |

### 衡量规则

- 每项测试至少运行 2 周，或每个变体达到 200 次转化（以时间较长者为准）
- 同时跟踪数量（完成率）和质量（潜在客户评分、SQL 转化率）
- 如果测试提高了完成量，却降低了潜在客户质量，则不能视为成功

## 指标与衡量

### 关键指标

| 指标 | 公式 | 基准 |
|--------|---------|-----------|
| 表单完成率 | 提交次数 / 表单查看次数 | 潜在客户表单为 20-40%，长表单为 5-15% |
| 字段级流失率 | 每个字段的放弃率 | 找出流失率最高的字段 |
| 完成耗时 | 从首次交互到提交的平均秒数 | 简单表单 < 60 秒，复杂表单 < 3 分钟 |
| 错误率 | 看到错误的用户数 / 用户总数 | < 10% |
| 移动端完成率 | 移动端提交次数 / 移动端表单查看次数 | 与桌面端完成率的差距应在 20% 以内 |

### 数据埋点要求

在分析工具中跟踪以下事件：
- 表单查看（曝光）
- 表单交互（首次聚焦字段）
- 每个字段的完成情况（每个字段失去焦点时）
- 表单提交尝试
- 表单提交成功
- 表单验证错误（按字段）

## 相关技能

- **signup-flow-cro** -- 当表单用于账户创建或试用注册流程时使用。Form-cro 用于潜在客户信息收集、联系和演示申请表单。
- **popup-cro** -- 当表单位于模态框或弹窗内时使用。Form-cro 处理表单本身；popup-cro 处理触发方式、时机和容器。
- **page-cro** -- 当表单周围的页面需要优化时使用（标题、价值主张、布局）。
- **onboarding-cro** -- 当瓶颈在于提交表单后的激活，而非表单本身时使用。

## 工具参考

### 1. form_scorer.py

**用途：** 根据字段数量、字段类型、CTA 质量、移动端适配情况和信任信号等 CRO 最佳实践对表单进行评分。

```bash
python scripts/form_scorer.py form_config.json
python scripts/form_scorer.py form_config.json --json
```

| 标志 | 必需 | 说明 |
|------|----------|-------------|
| `form_config.json` | 是 | 包含表单字段、CTA 和上下文元数据的 JSON 文件 |
| `--json` | 否 | 以 JSON 格式输出结果 |

### 2. field_cost_analyzer.py

**用途：** 计算每个表单字段预计导致的放弃成本，并建议应删除、保留或设为可通过数据丰富补全的字段。

```bash
python scripts/field_cost_analyzer.py form_fields.json
python scripts/field_cost_analyzer.py form_fields.json --json
```

| 标志 | 必需 | 说明 |
|------|----------|-------------|
| `form_fields.json` | 是 | 包含表单字段及其类型的 JSON 文件 |
| `--json` | 否 | 以 JSON 格式输出结果 |
| `--monthly-visitors` | 否 | 用于估算金额影响的每月表单访问者数量（默认值：1000） |
| `--current-rate` | 否 | 当前表单完成率，以百分比表示（默认值：25） |
| `--value-per-lead` | 否 | 用于计算 ROI 的每条潜在客户线索的美元价值（默认值：50） |

### 3. ab_test_calculator.py

**用途：** 计算表单优化实验中 A/B 测试的样本量、持续时间和统计显著性。

```bash
python scripts/ab_test_calculator.py --baseline 25 --lift 10 --traffic 500
python scripts/ab_test_calculator.py --baseline 25 --lift 10 --traffic 500 --json
```

| 标志 | 必需 | 说明 |
|------|----------|-------------|
| `--baseline` | 是 | 当前转化率，以百分比表示（例如，25 表示 25%） |
| `--lift` | 是 | 最小可检测提升幅度，以百分比表示（例如，10 表示相对提升 10%） |
| `--traffic` | 是 | 每日流量（每天访问表单的访客数） |
| `--confidence` | 否 | 置信水平，以百分比表示（默认值：95） |
| `--json` | 否 | 以 JSON 格式输出结果 |

## 故障排除

| 问题 | 可能原因 | 解决方案 |
|---------|-------------|----------|
| 表单完成率低于 15% | 字段过多或存在高摩擦字段 | 运行 field_cost_analyzer.py 以识别并删除高成本字段；对于首次接触的潜在客户表单，以仅收集电子邮件地址为目标 |
| 移动端完成率比桌面端低 50% 以上 | 表单未针对触控输入进行优化 | 确保触控目标为 44px、采用单列布局并使用原生键盘类型；在移动端用按钮组替换下拉菜单 |
| 用户开始填写但未完成表单 | 中间字段（电话、预算、留言）造成摩擦 | 在多步骤表单中，将高摩擦字段移至后续步骤；在第 1 步收集电子邮件地址 |
| 电子邮件或电话字段的错误率较高 | 验证过于严格或错误消息不清晰 | 在失去焦点时进行验证（而非按键时）；使用具体的错误文案（“请在电子邮件地址中包含 @”），而非笼统的提示（“输入无效”） |
| 4 周后 A/B 测试结果仍无定论 | 样本量不足或提升目标过小 | 使用 ab_test_calculator.py 确认所需样本量；考虑测试幅度更大的改动（删除字段，而非微调文案） |
| 尽管页面流量良好，但 CTA 点击量较低 | CTA 文案过于笼统或按钮不够醒目 | 将“提交”替换为体现具体价值的文案（“获取我的报告”）；确保 CTA 在移动端为全宽并使用高对比度颜色 |

## 成功标准

- 潜在客户获取表单的填写完成率高于 25%（高于 35% 为优秀）
- 移动端填写完成率与桌面端填写完成率的差距在 20% 以内
- 错误率低于表单交互次数的 10%
- 字段级流失分析能够识别具体的阻碍点，并提供明确的改进措施
- 每个表单字段都有记录在案的设置依据（业务需要，或可在提交后补充）
- 每个变体至少获得 200 次转化后，才能判定 A/B 测试的胜出者
- 演示申请表单和联系表单提交后，须在 24 小时内进行跟进

## 范围与限制

- **范围内：** 表单字段优化、CTA 文案、验证体验、移动端优化、信任信号的放置、A/B 测试设计、字段成本分析
- **范围外：** 页面级 CRO（使用 page-cro）、弹窗触发机制优化（使用 popup-cro）、注册流程（使用 signup-flow-cro）、表单提交后的培育序列
- **数据依赖：** 字段级分析数据（每个字段的流失情况）能提供最具可操作性的洞察，但需要配置分析埋点
- **合规限制：** GDPR/HIPAA 可能要求保留无法删除的特定字段；优化前应记录相关合规要求
- **统计有效性：** A/B 测试建议需要足够的流量；低流量表单可能需要更长的测试周期或其他评估方法

## 集成点

- **page-cro** -- 当表单本身转化良好，但周围页面无法有效推动用户与表单交互时，应先优化页面级元素
- **popup-cro** -- 当表单位于弹窗或模态框内时，由 popup-cro 处理触发时机和容器设计
- **signup-flow-cro** -- 对于账户创建和注册表单（而非潜在客户获取表单），使用 signup-flow-cro 处理多步骤身份验证流程
- **onboarding-cro** -- 当瓶颈在于表单提交后的激活，而不是表单填写完成率本身时使用
- **free-tool-strategy** -- 免费工具通常包含潜在客户获取表单；使用 form-cro 优化工具内的获取表单
