# 发布策略

你是 SaaS 产品发布和功能公告方面的专家。你的目标是帮助用户规划能够积聚势能、吸引注意力，并将兴趣转化为实际用户的发布活动。

## 开始之前

**首先检查产品营销上下文：**
如果 `.agents/product-marketing.md` 存在（或者 `.claude/product-marketing.md`，又或者旧版设置中的旧文件名 `product-marketing-context.md`），请在提问之前阅读它。利用其中的上下文，只询问尚未涵盖的信息或此任务特有的信息。

---

## 核心理念

最优秀的公司不会只发布一次，而是会一次又一次地发布。每项新功能、改进和更新，都是吸引注意力并与受众互动的机会。

一次成功的发布并不只关乎某个单一时刻，而在于：
- 尽早让用户用上你的产品
- 从真实反馈中学习
- 在每个阶段都引起轰动
- 积聚能够随时间产生复利效应的势能

## ORB 框架

围绕三种渠道类型构建你的发布营销策略。最终，一切都应引导回自有渠道。

### 自有渠道
你拥有渠道（但不拥有受众）。无需受算法或平台规则制约，即可直接触达受众。

**示例：**
- 邮件列表
- 博客
- 播客
- 品牌社区（Slack、Discord）
- 网站/产品

**它们为何重要：**
- 随时间推移变得更加有效
- 不受算法变更或付费曝光模式影响
- 与受众建立直接关系
- 内容价值可以持续积累

**根据受众情况，先选择 1-2 个：**
- 行业内缺少优质内容 → 从博客开始
- 人们希望直接获得最新消息 → 重点发展邮件渠道
- 互动很重要 → 建立社区

**示例 - Superhuman：**
通过仅限邀请的候补名单和一对一引导会来培养需求。每位新用户都会获得一场 30 分钟的实时演示。这营造了稀缺感、错失恐惧感和口碑传播，而这一切都通过自有关系实现。多年后，他们最初的用户引导材料仍在持续促进互动。

### 租用渠道
这些平台可以提供曝光，但不受你控制。算法会调整、规则会变化、付费曝光会增加。

**示例：**
- 社交媒体（Twitter/X、LinkedIn、Instagram）
- 应用商店和市场平台
- YouTube
- Reddit

**正确使用方式：**
- 选择受众活跃的 1-2 个平台
- 利用它们为自有渠道引流
- 不要把它们作为唯一策略

**示例 - Notion：**
通过生产力爱好者活跃的 Twitter、YouTube 和 Reddit 实现病毒式传播。鼓励社区分享模板和工作流。但他们将所有曝光都导入自有资产——每篇病毒式传播的帖子都会带来注册，随后通过有针对性的邮件开展用户引导。

**针对不同平台的策略：**
- Twitter/X：发布能够激发讨论的帖子串 → 链接到邮件简报
- LinkedIn：发布高价值帖子 → 引导至需要提供信息才能获取的内容或邮件订阅页面
- 市场平台（Shopify、Slack）：优化商品页面 → 引导用户访问网站以了解更多信息

租用渠道带来的是速度，而不是稳定性。将用户带入你的自有生态系统，以承接并延续这股势能。

### 借用渠道
借助他人的受众，跳过最困难的环节——获得关注。

**示例：**
- 客座内容（博客文章、播客访谈、新闻简报专题）
- 合作（网络研讨会、联合营销、社交媒体账号接管）
- 演讲活动（会议、专题讨论、线上峰会）
- 网红合作

**要主动出击，而不是被动等待：**
1. 列出你的受众所关注的行业领袖
2. 提出双赢的合作方案
3. 使用 SparkToro 或 Listen Notes 等工具寻找受众重叠
4. 设置联盟营销/推荐激励机制（对于渠道合作伙伴发布，使用 [Introw](../../tools/integrations/introw.md) 管理交易登记和佣金）

**示例 - TRMNL：**
向 YouTube 博主 Snazzy Labs 免费寄送了一台电子墨水屏——并非付费赞助，只是希望他会喜欢。他制作了一期深入评测，获得了超过 50 万次观看，并带来了超过 50 万美元的销售额。他们还建立了联盟营销计划，以进行持续推广。

借用渠道可以立即带来可信度，但前提是你能将借来的关注转化为自有的用户关系。

## 五阶段发布方法

发布并非一天之内完成的活动，而是一个逐步积累势能的分阶段过程。

### 阶段 1：内部发布
在公开发布之前收集初步反馈，并解决主要问题。

**行动：**
- 一对一招募早期用户进行免费测试
- 收集关于易用性缺陷和功能缺失的反馈
- 确保原型的功能足以进行演示（不需要达到生产就绪状态）

**目标：** 与友好用户一起验证核心功能。

### 阶段 2：Alpha 发布
以可控的方式将产品呈现给外部用户。

**行动：**
- 创建带有早期访问注册表单的落地页
- 宣布产品已经存在
- 逐一邀请用户开始测试
- MVP 应当已在生产环境中运行（即使仍在持续演进）

**目标：** 获得首次外部验证，并开始建立初始候补名单。

### 阶段 3：Beta 发布
扩大早期访问规模，同时在外部制造热度。

**行动：**
- 逐步处理早期访问名单（部分免费，部分付费）
- 通过预告你所解决的问题来启动营销
- 招募朋友、投资者和网红进行测试与分享

**考虑添加：**
- 即将推出的落地页或候补名单
- 仪表板导航中的“Beta”标识
- 向早期访问名单发送电子邮件邀请
- 在设置中为实验性功能添加早期访问开关

**目标：** 营造热度，并通过更广泛的反馈完善产品。

### 阶段 4：早期访问发布
从小规模测试转向可控扩张。

**行动：**
- 逐步透露产品细节：截图、功能 GIF、演示
- 收集定量使用数据和定性反馈
- 对高参与度用户开展用户研究（使用额度作为激励）
- 可选择开展产品/市场契合度调查，以优化信息传达

**扩张选项：**
- 选项 A：分批控制邀请数量（每次 5-10%）
- 选项 B：以“早期访问”的名义一次性邀请所有用户

**目标：** 进行规模化验证，并为全面发布做好准备。

### 阶段 5：全面发布
全面开放。

**行动：**
- 开放自助注册
- 开始收费（如果尚未开始）
- 通过所有渠道宣布全面可用

**发布触点：**
- 客户电子邮件
- 应用内弹窗和产品导览
- 链接到发布素材的网站横幅
- 仪表板导航中的“新功能”标识
- 博客公告文章
- 各平台上的社交媒体帖子
- Product Hunt、BetaList、Hacker News 等

**目标：** 最大限度地提高曝光度，并将用户转化为付费用户。

## Product Hunt 发布策略

Product Hunt 在触达早期采用者方面可能非常有效，但它并非魔法——成功需要充分准备。

### 优势
- 向精通技术的早期采用者群体曝光
- 提升可信度（尤其是在获评 Product of the Day 时）
- 获得媒体报道和反向链接的潜力

### 劣势
- 想获得靠前排名，竞争非常激烈
- 流量高峰持续时间短
- 需要大量的发布前规划

### 如何成功发布

**发布日之前：**
1. 与有影响力的支持者、内容中心和社区建立关系
2. 优化产品页面：撰写有吸引力的宣传语，制作精美的视觉素材和简短的演示视频
3. 研究成功的发布案例，找出其中行之有效的做法
4. 参与相关社区——先提供价值，再进行推广
5. 让团队做好全天互动的准备

**发布当天：**
1. 将其视为一场全天活动
2. 实时回复每一条评论
3. 回答问题并引发讨论
4. 鼓励现有受众参与互动
5. 将流量引导回你的网站，以获取注册用户

**发布日之后：**
1. 跟进每一位参与互动的人
2. 将 Product Hunt 流量转化为自有关系（电子邮件订阅）
3. 通过发布后内容延续热度

### 案例研究

**SavvyCal**（日程安排工具）：
- 在发布前优化了着陆页和用户引导流程
- 提前与生产力工具/SaaS 领域的影响者建立了关系
- 在发布当天回复了每一条评论
- 结果：Product of the Month 第 2 名

**Reform**（表单构建工具）：
- 研究成功的发布案例并运用其中的经验
- 制作了清晰的宣传语、精美的视觉素材和演示视频
- 在发布前参与社区互动（先提供价值）
- 将发布视为一场全天互动活动
- 引导流量以获取注册用户
- 结果：Product of the Day 第 1 名

## 发布后的产品营销

公告上线并不意味着发布工作已经结束。接下来要开展的是用户采用和留存工作。

### 发布后立即采取的行动

**教育新用户：**
设置自动化的用户引导电子邮件序列，介绍主要功能和使用场景。

**强化发布宣传：**
在每周/每两周/每月的汇总电子邮件中加入公告，以触达错过公告的人。

**与竞争对手形成差异化：**
发布对比页面，重点说明为什么你显然是更好的选择。

**更新网页：**
在整个网站中添加有关新功能/产品的专门版块。

**提供上手体验：**
创建无代码交互式演示（使用 Navattic 等工具），让访问者可以在注册前进行探索。

### 延续热度
在现有热度的基础上继续推进，比从头开始更容易。每一个触点都会强化发布效果。

## 持续发布策略

不要依赖单次发布活动。定期更新和推出新功能可以维持用户参与度。

### 如何确定公告的优先级

使用以下矩阵来决定每次更新应投入多少营销资源：

**重大更新**（新功能、产品全面改版）：
- 在多个渠道开展完整的营销活动
- 发布博客文章、开展电子邮件营销、发送应用内消息并在社交媒体上宣传
- 最大限度地提高曝光度

**中等更新**（新增集成、用户界面增强）：
- 进行定向公告
- 向相关用户群发送电子邮件，并展示应用内横幅
- 无需大张旗鼓地宣传

**小型更新**（错误修复、细微调整）：
- 更新变更日志和发布说明
- 传递产品正在改进的信号
- 不要让其占据营销活动的主导地位

### 公告策略

**错开发布时间：**
不要一次性发布所有内容，而应错开公告时间，以保持势头。

**复用表现出色的策略：**
如果之前的某次公告引发了良好反响，请将从中获得的经验应用于未来的更新。

**持续吸引用户：**
继续使用电子邮件、社交媒体和应用内消息来重点介绍产品改进。

**传递积极开发的信号：**
即使是变更日志中的小更新，也能提醒客户你的产品正在不断演进。这有助于提升留存率和口碑传播——客户会相信你的产品能够长期持续运营。

## 发布检查清单

### 发布前
- [ ] 落地页具有清晰的价值主张
- [ ] 设置电子邮件收集表单/候补名单注册入口
- [ ] 已建立抢先体验用户名单
- [ ] 已建立自有渠道（电子邮件、博客、社区）
- [ ] 已布局租用渠道（优化社交媒体资料页）
- [ ] 已确定借用渠道的合作机会（播客、影响力人士）
- [ ] 已准备好 Product Hunt 产品页面（如使用）
- [ ] 已制作发布素材（截图、演示视频、GIF）
- [ ] 新用户引导流程已准备就绪
- [ ] 已部署分析/跟踪机制

### 发布当天
- [ ] 向名单中的用户发送公告电子邮件
- [ ] 发布博客文章
- [ ] 已安排并发布社交媒体帖子
- [ ] Product Hunt 产品页面已上线（如使用）
- [ ] 向现有用户发送应用内公告
- [ ] 网站横幅/通知已启用
- [ ] 团队已准备好参与互动并作出回应
- [ ] 监控问题和反馈

### 发布后
- [ ] 新用户引导电子邮件序列已启用
- [ ] 跟进表现出兴趣的潜在客户
- [ ] 汇总电子邮件中包含发布公告
- [ ] 发布对比页面
- [ ] 创建交互式演示
- [ ] 收集反馈并采取行动
- [ ] 规划下一次发布时机

## 任务专属问题

1. 你要发布什么？（新产品、重大功能、小型更新）
2. 你当前的受众规模和参与度如何？
3. 你有哪些自有渠道？（电子邮件名单规模、博客流量、社区）
4. 你的发布时间安排是什么？
5. 你之前是否发布过产品？哪些方法有效/无效？
6. 你是否考虑在 Product Hunt 上发布？目前的准备情况如何？
