# 代码简化

审查指定代码（或最近的更改），找出不必要的复杂度并加以简化。

## 需要关注的问题

1. **过度抽象** — 只被使用一次的辅助函数、工具函数或包装函数。将其内联。
2. **不必要的间接层** — 仅做数据透传的回调链、事件总线或服务层。
3. **过度防御** — 为不可能发生的情况做错误处理，在可信的内部代码深处做空值检查。
4. **死代码** — 未使用的导入、不可达分支、被注释掉的代码块、未使用的变量。
5. **复杂条件判断** — 本可改写为提前返回的嵌套 if/else，本可改写为查找表的 switch 语句。
6. **过早的泛化** — 只为一个用例设计的配置对象、只有一个插件的插件系统、只为一种类型设计的工厂模式。
7. **冗余注释** — 复述代码内容而非解释原因的注释。

## 原则

- 三行相似的代码好于一次过早的抽象
- 尽可能删除代码而非添加代码
- 如果移除某段代码不会破坏任何功能，那它本就不该存在
- 恰当的复杂度是满足当前需求所需的最小复杂度
- 不要为假设的未来需求做设计

## 流程

1. 阅读目标文件
2. 对发现的每个问题，说明其过于复杂之处以及为何可以简化
3. 展示简化后的版本
4. 应用修复
5. 验证更改不会破坏任何功能（如有测试则运行测试）
