# Suede 营销循环

Suede 将可重复的营销工作转化为有边界的循环，并为其定义触发条件、执行频率、输入契约、自检机制、持久化状态、人工检查点和停止条件。循环可以监测 SEO 机会、广告疲劳或流失信号，但它绝不会仅仅因为按计划运行，就获得发布内容、花费预算或修改生产环境的许可。

这是对 `suede-marketing-ideas` 的运营补充：ideas 用于识别哪些事项可能值得尝试一次；Suede 循环则定义已获批准的工作应重复执行什么，以及公开的 Suede 技能如何协调这些工作。

## 如何使用此技能

如果 `.agents/product-marketing.md` 存在，请先阅读它，并且只询问其中未涵盖的内容；路径回退方案请参阅 `suede-product-marketing`。

然后：
1. **明确工作目标。** 这个循环应该保护或提升什么结果？（排名、广告效率、激活、留存、收入、推荐）
2. 从 `references/loop-catalog.md` 的目录中**选择一个循环**——或者调整最接近的那个。
3. 根据底层信号实际变化的速度**调整执行频率**（参见下方的频率规则）。
4. **确认人工检查点。** 决定循环哪些工作可以自主完成，哪些工作必须先暂存并获得人工批准后才能发布或花费预算——参见 `references/loop-guardrails.md`。
5. **安排执行计划**（参见下方的“安排循环”）。

如果要构建多个循环，或构建完整的营销运营系统，请参阅 `references/loop-orchestration.md`，了解循环如何组合以及采用顺序（从跟踪 + 每周审查开始；不要一次性构建 45 个循环）。

## 营销循环的构成

目录中的每个循环都包含以下九个部分。创建或调整循环时，请完整填写所有部分——缺少停止条件、自检机制或状态处理的循环不是资产，而是负担。

| 部分 | 定义内容 |
|------|----------|
| **检查频率** | 循环多久进行一次*查看*（每周 / 每日 / 触发时）。应与信号速度匹配。 |
| **执行条件** | 操作条件——实际*执行*某项操作必须满足什么条件，而不仅仅是检查后跳过。一个好的循环大多数运行结果都是“已检查，无需操作”。 |
| **目的** | 这个循环存在的唯一目标。 |
| **使用的技能** | 循环每次迭代所编排的营销技能。 |
| **循环主体** | 每次迭代运行的有序步骤。 |
| **自检** | 执行操作*之前*进行的验证——确保循环不会因噪声、季节性或跟踪错误而采取行动。 |
| **状态 / 幂等性** | 循环在两次运行之间记住的内容：上次运行标记、去重键、冷却窗口、“已处理”集合。如果没有这些机制，循环就会重复执行操作、反复提醒同一批人，或重复对同一事项发出警报。对于任何按计划运行的循环而言，这都是不可或缺的——状态存储位置和幂等性模式请参阅 `references/loop-state.md`。 |
| **停止 / 退出** | 循环何时跳过、停止、升级给人工处理或禁用自身——以及发生错误时如何处理。每个循环都需要这一项，包括心跳循环（它们的停止条件是“手动禁用 + 错误停止”，绝不能是“n/a”）。 |
| **输出** | 结果写入的位置：文件、PR、暂存的草稿、通知或报告。 |

**检查频率 / 触发行动条件** 的区分很重要：一个流失信号循环可能每天*检查*，但只有当某个账户跨越了风险阈值，且在冷却窗口内尚未就此联系过时才*采取行动*。混淆两者会导致循环要么错过窗口，要么造成骚扰。

## 频率规则

将频率与信号实际变化的速度相匹配——而不是与你*希望*获得更新的频率相匹配。

| 信号 | 现实的频率 | 原因 |
|--------|-------------------|-----|
| 排名、反向链接、域名权威度 | 每周 | 变化缓慢；每日检查只是噪声 |
| 广告素材疲劳、CPA 漂移 | 每 2–3 天 | Meta/Google 的反馈循环以天计，而非小时 |
| 激活 / 引导漏斗 | 每周 | 需要足够的注册量才具有统计显著性 |
| 流失信号 | 每天或按触发条件 | 早期干预窗口很短 |
| 内容 / 文案衰减 | 每月 | 流量流失是渐进的 |
| 竞争对手变化 | 每周 | 定价/定位调整并不频繁，但很重要 |
| 社交聆听 / 提及 | 每天 | 互动窗口关闭得很快 |

过于频繁的循环是最常见的失败模式：它们会制造忙碌工作、消耗预算，并让你习惯于忽略输出。

## 不应使用循环的情况

并非所有事情都应按频率自动化。在以下情况中，应跳过循环——或添加强制性人工检查点：

- **真正的工作是策略或创意方向。** 循环用于维护和优化；它们不会设定定位、构思营销活动或作出品牌决策。
- **行动会在未经审核的情况下发布或花费。** 自动*起草*广告、电子邮件或帖子没有问题。除非用户已明确授权自主行动并设置护栏（上限、允许列表），否则自动*发布*或自动*调整预算*需要人工检查点。
- **信号过于稀疏，无法具有统计显著性。** 对每周 40 位访客进行每周转化率循环是在测量噪声。
- **这是一个虚荣循环。** 如果没有人根据输出采取行动，就删除该循环。一个向无人阅读的仪表板发送电子邮件的循环，比什么都不做更糟。

对于任何发送、花费、发布或接触个人数据的循环，请应用 `references/loop-guardrails.md`——双层行动模型（自主安全型与受控型）、花费/发送上限、CAN-SPAM/GDPR/FTC/ToS 规则、始终升级处理清单，以及必需的终止开关。

## 为循环安排调度

这些循环与代理无关——*主体*可在任何代理中运行。*调度方式*取决于你的环境：

- **具备调度能力的环境** ——先发现已安装的调度器、自动化连接器或原生调度原语，并阅读其当前说明。仅在它们确实可用且用户授权调度时使用它们。已创建调度的证明是连接器自身的确认记录——创建任务的 id 或名称及其下一次运行时间，并将其原样引用回来。
- **支持 Cron 的主机** ——当 cron 可用时，将循环主体封装为定时提示或脚本（例如，`0 9 * * 1` 表示每周一上午 9 点）。证明是显示新增行的 `crontab -l` 输出。
- **手动频率** ——对于需要高度判断的循环，“每周一运行此技能”是完全合理的循环。价值在于可重复的*主体*，而非自动化。证明是可复制的频率指令本身，以及一项明确说明：未安排任何调度。

如果没有展示相应证据，不得将循环报告为已完成调度。如果没有可用的调度机制，则返回完整的循环主体，并附上可复制的执行频率指令，同时标记调度未创建。

对于审查类循环（每周审查、排名监控），默认使用按时间执行的 cron；对于持续监控直至达到阈值的循环（流失监控、发布日跟踪），默认使用动态节奏。

## 目录

`references/loop-catalog.md` 存放完整的循环库——包含 45 个营销循环，全面覆盖各个漏斗环节：SEO 与内容、付费、自然传播/社交/合作伙伴、激活、留存、收入、推荐与倡导，以及持续运营。每个循环都是完整且可调整的规范。先从这里开始，选择最接近的匹配项，再根据用户的产品、阶段和工具进行调整。

## 编写新循环

当目录中没有合适的循环时，使用 `references/loop-template.md` 编写一个新循环——这是一个可复制粘贴的模板，其中包含填空提示、完整的前后示例，以及发布检查清单。填写全部九个结构部分；如果无法具体回答自检、幂等性以及停止/退出条件，该循环就还没准备好运行。

**当某个部分无法填写时，使用暂停格式。** 停止。指出九个结构部分中未填写的是哪一部分，以及缺少什么内容才能完成填写。提供以下选项并等待用户选择——(1) 现在补充缺失部分，(2) 降级为手动执行频率并发布主体但不进行调度，(3) 缩小循环范围，直到不再需要缺失部分，或 (4) 放弃此循环。不要进行调度，也不要将不完整的循环呈现为已准备就绪。上述第 4 步中的人工检查点决策同样适用：如果尚未决定哪些操作可以自主运行、哪些操作需要提交审批，则应在那里停止，而不是自行选择默认方案。

## 反模式

- 没有停止条件却持续循环 → 导致失控的支出或无限流失。
- 所有循环使用相同的执行频率 → 大多数循环运行过于频繁，最终被忽略。
- 没有自检 → 循环会对噪声、季节性因素或跟踪故障采取行动。
- 对支出/发布操作没有人工检查点。
- 一次构建 10 个循环 → 先从一个开始，证明它值得维护后，再添加下一个。

## 禁用词汇

避免使用：“设置好后无需再管”、“完全自主的营销”、“AI 做所有事情”、“自动驾驶实现 10 倍增长”、“增长黑客机器”。循环是带有检查点的纪律化系统，不是魔法。应当如实描述它们。

## 边界

- 未经明确授权，不得创建、启用、调度或修改循环自动化。
- 如果没有指定的人工检查点，不得让循环发布内容、支出、发送消息、删除内容或更改生产状态。
- 没有当前的执行记录，不得声称循环已运行、检测到某个条件或改善了某项指标。
- 不得用“自主运行”之类的语言掩盖缺失的数据、权限、阈值、负责人或停止条件，也不得替用户决定这些控制项。

## 路由

- 一次性策略使用 `suede-marketing-ideas`，实验使用 `suede-ab-testing`。
- 测量输入使用 `suede-analytics`。
- 内容循环背后的组合决策——哪些支柱已经存在，以及哪些内容应当刷新、合并或淘汰——使用 `suede-content-strategy`。本技能负责持续执行频率；该技能负责决定执行频率作用于哪些内容。
- 将渠道操作路由至 `suede-ads`、`suede-seo-audit`、`suede-emails`、`suede-social`、`suede-churn-prevention`、`suede-pricing` 或 `suede-referrals`。
