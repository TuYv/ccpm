# 高管导师

不是又一个顾问，而是一位对抗性思考伙伴。在竞争对手、董事会或客户发现漏洞之前，先替你找出来。每项计划都存在致命假设——问题在于，你是现在发现它们，还是以后在事后复盘中才发现。

## 关键词

高管导师、事前验尸、董事会准备、艰难决策、压力测试、事后复盘、计划质疑、唱反调、创始人辅导、对抗性思考、危机、转型、裁员、联合创始人冲突、盲点、决策质量、假设检验、情景规划

---

## 区别所在

其他高管技能用于制定计划。高管导师则负责打破计划。

| 其他技能 | 高管导师 |
|-------------|-----------------|
| “这是战略” | “你的战略存在三个致命假设” |
| “这是财务模型” | “如果这个假设的偏差达到 40%，会发生什么？” |
| “这是招聘计划” | “如果收入晚一个季度达标，你就负担不起这项计划” |
| “这是路线图” | “你最大的竞争对手会在 60 天内推出这个功能。然后呢？” |

## 框架 1：事前验尸分析

### 流程

```
Step 1: STATE THE PLAN
  Describe the plan as if it succeeded perfectly.

Step 2: ASSUME FAILURE
  "It's 12 months from now. This plan failed completely. Why?"

Step 3: IDENTIFY FAILURE MODES
  List every way the plan could fail. Minimum 5 failure modes.
  Rate each: Probability (1-5) x Impact (1-5) = Severity (1-25)

Step 4: FIND THE KILLERS
  Focus on severity > 15. These are the ones that will actually kill you.

Step 5: BUILD HEDGES
  For each killer: What's the earliest warning signal?
  What's the cheapest hedge that reduces severity by 50%?

Step 6: SET TRIPWIRES
  Define specific conditions that trigger plan modification.
  "If [metric] drops below [threshold] by [date], we [action]."
```

### 事前验尸输出模板

| 失败模式 | 概率（1-5） | 影响（1-5） | 严重程度 | 最早预警信号 | 对冲措施 | 触发线 |
|-------------|-------------------|--------------|----------|-----------------|-------|----------|
| 关键招聘人选不胜任 | 3 | 4 | 12 | 60 天绩效评估 | 立即启动后备人才渠道 | 如果 60 天后表现仍未达标，则启用后备人选 |
| 市场变化快于预期 | 2 | 5 | 10 | 竞争对手宣布类似产品 | 构建模块化架构，为转型做好准备 | 如果竞争对手在 90 天内发布产品，则召集董事会 |
| 收入低于目标 20% 以上 | 3 | 5 | 15 | 销售管道覆盖率降至 2 倍以下 | 准备好削减非必要支出的方案 | 如果第一季度收入低于目标 15% 以上，则执行成本削减方案 |

## 框架 2：董事会准备

### 48 小时董事会准备流程

```
T-48 hours: INFORMATION GATHERING
  - Pull all metrics the board tracks
  - Identify every number that missed target
  - List every hard question they could ask
  - Review previous board meeting action items

T-24 hours: NARRATIVE CONSTRUCTION
  - Build the story: where we said we'd be, where we are, why, what next
  - Prepare the bad news delivery (Framework: State, Own, Understand, Fix)
  - Practice the three hardest questions out loud
  - Prepare specific asks (not "any help appreciated")

T-2 hours: FINAL PREP
  - Review deck one more time
  - Ensure every metric has a target and status
  - Confirm every variance has a one-sentence explanation
  - Know your three key messages cold

During: EXECUTION
  - Lead with the most important thing (slide 3, not slide 30)
  - Deliver bad news early, with ownership and a plan
  - End with specific, actionable asks
```

### 最棘手的 10 个董事会问题

无论你的议程是什么，都要准备好回答这些问题：

| 问题 | 他们真正想知道什么 |
|----------|-------------------------------|
| “带我复盘一下这次未达预期的情况” | 你能否诚实地诊断问题？ |
| “实现盈利的路径是什么？” | 你是否具备严谨的单位经济效益意识？ |
| “谁是你们最大的竞争威胁？” | 你是具有清醒认知和战略思维，还是不以为然？ |
| “什么事情让你夜不能寐？” | 你是在坦诚面对风险，还是只顾推销？ |
| “如果必须裁掉 30% 的团队，你会留下谁？” | 你是否清楚谁是关键人员？ |
| “我们为什么应该继续投入更多资金？” | 风险回报是否仍然有吸引力？ |
| “你会采取哪些不同的做法？” | 你能否学习并适应？ |
| “给我看看同期群数据” | 留存是否真实，还是增长掩盖了客户流失？ |
| “你在招聘方面犯过的最大错误是什么？” | 你是否有自知之明，并且能够果断决策？ |
| “你们什么时候需要更多资金？” | 你是否了解自己的现金状况？ |

### 董事会成员互动矩阵

| 董事会成员类型 | 行为 | 应对方式 |
|-------------------|----------|---------------|
| 运营型 | 深挖执行细节 | 准备好相关数据，尊重其经验 |
| 财务型 | 把一切都视为 IRR 计算 | 以单位经济效益和资本效率为切入点 |
| 战略型 | 希望看到全局 | 将战术与战略联系起来，展示愿景 |
| 质疑型 | 质疑一切，扮演反方角色 | 欢迎挑战，不要产生防御心态 |
| 被动型 | 赞同一切，但贡献很少 | 分配具体议题，直接提问 |

## 框架 3：艰难决策框架

适用于不存在好选项、只有相对不那么糟糕的选项时的决策。

### 艰难决策流程

```
Step 1: REVERSIBILITY TEST
  [Is this decision reversible within 90 days?]
  |
  +-- YES --> Make it faster. Speed > perfection for reversible decisions.
  +-- NO  --> Proceed through full framework.

Step 2: 10/10/10 ANALYSIS
  - How will you feel about this in 10 minutes?
  - How will you feel in 10 months?
  - How will you feel in 10 years?

Step 3: STAKEHOLDER IMPACT MAP
  For each stakeholder group:
  | Stakeholder | Impact | Severity | Can You Mitigate? |
  | Team        | [desc] | [H/M/L]  | [Yes/No/Partially] |
  | Customers   | [desc] | [H/M/L]  | [Yes/No/Partially] |
  | Investors   | [desc] | [H/M/L]  | [Yes/No/Partially] |
  | Partners    | [desc] | [H/M/L]  | [Yes/No/Partially] |

Step 4: OPTION MATRIX
  | Option | Upside | Downside | Reversibility | Speed | Regret Risk |
  | A      |        |          |               |       |             |
  | B      |        |          |               |       |             |
  | C (do nothing) | | |                      |       |             |

Step 5: DECIDE AND COMMUNICATE
  - Make the call
  - Communicate to affected stakeholders within 24 hours
  - Own the decision fully -- no "I was advised to"
```

### 常见的艰难决策

| 决策 | 关键考量 | 常见错误 |
|----------|-------------------|----------------|
| 裁员 | 一次性裁减到位；不要分批滚动裁员 | 裁减幅度太小，导致需要进行第二轮裁员 |
| 解雇联合创始人 | 拖延造成的损失大于采取行动带来的痛苦 | 一直等到双方关系彻底破裂 |
| 终止产品 | 沉没成本无关紧要；机会成本才是一切 | 因为“我们已经投入了这么多”而继续维持产品 |
| 转型 | 基于数据转型，而不是出于绝望 | 尚未理解当前方向失败的原因就贸然转型 |
| 拒绝融资 | 条款不合适的错误资金比没有资金更糟糕 | 因为“我们需要延长现金跑道”而接受糟糕的条款 |
| 拒绝大客户 | 权衡单个客户的需求与产品愿景 | 开发导致路线图偏离方向的定制功能 |

## 框架 4：压力测试协议

### 假设压力测试

```
Step 1: IDENTIFY THE ASSUMPTION
  State it explicitly: "We assume [X]"

Step 2: FIND COUNTER-EVIDENCE
  What data or scenarios would make this assumption false?
  - Historical precedent
  - Competitor actions
  - Market shifts
  - Customer behavior changes
  - Regulatory changes

Step 3: MODEL THE DOWNSIDE
  If this assumption is wrong by 20%, what happens?
  By 40%? By 60%?
  At what point does the plan break?

Step 4: PROPOSE THE HEDGE
  What's the cheapest action that protects against this assumption being wrong?

Step 5: SET THE MONITORING
  What metric tells us earliest if this assumption is weakening?
```

### 需要质疑的常见假设

| 假设 | 质疑 | 对冲措施 |
|-----------|-----------|-------|
| “收入将同比增长 2 倍” | 如果只增长 1.3 倍呢？ | 按 1.5 倍增长规划支出，按 2 倍增长进行投资 |
| “50 亿美元的 TAM” | 这部分市场可服务吗？你的 SAM 是多少？ | 聚焦 SAM，而非 TAM |
| “3 年护城河” | 如果资金雄厚的竞争者在 12 个月内入场呢？ | 构建转换成本，而不只是功能 |
| “我们今年将招聘 20 名工程师” | 如果招聘周期是 90 天，而不是 45 天呢？ | 立即启动招聘渠道建设，并考虑使用承包商 |
| “客户流失率将保持在 5%” | 如果竞争对手提供更便宜的替代方案呢？ | 投资提升用户黏性，而不只是获客 |

## 框架 5：事后复盘协议

### 无责事后复盘结构

```
POST-MORTEM: [Event Name]
Date of Event: [YYYY-MM-DD]
Date of Review: [YYYY-MM-DD]
Facilitator: [Name]
Participants: [Names]

TIMELINE
  [Chronological sequence of events, facts only]

IMPACT
  - Customer impact: [description, magnitude]
  - Revenue impact: [$ amount]
  - Team impact: [description]
  - Reputation impact: [description]

5 WHYS ANALYSIS
  1. Why did [event] happen?
     Because [cause 1].
  2. Why did [cause 1] happen?
     Because [cause 2].
  3. Why did [cause 2] happen?
     Because [cause 3].
  4. Why did [cause 3] happen?
     Because [cause 4].
  5. Why did [cause 4] happen?
     Because [root cause].

ROOT CAUSE: [One sentence]

CONTRIBUTING FACTORS (not root cause, but made it worse):
  - [Factor 1]
  - [Factor 2]

WHAT WENT WELL (always include this):
  - [Thing 1]
  - [Thing 2]

CHANGES REQUIRED
  | Change | Owner | Deadline | Verification Method |
  |--------|-------|----------|-------------------|
  | [Change 1] | [Name] | [Date] | [How we verify it's done] |
  | [Change 2] | [Name] | [Date] | [How we verify it's done] |

FOLLOW-UP REVIEW: [Date to check all changes are implemented]
```

### 事后复盘中的反模式

| 反模式 | 失败原因 | 更好的方法 |
|-------------|-------------|-----------------|
| 追究个人责任 | 人们下次会隐瞒信息 | 无责复盘：聚焦系统，而非个人 |
| “我们会更加小心” | 无法付诸行动 | 明确的流程或系统变更 |
| 行动项过多 | 最终什么都无法完成 | 最多 5 项变更，并排定优先级 |
| 没有后续跟进 | 变更永远不会实施 | 设定并跟踪强制性的后续跟进日期 |
| 粉饰问题 | 同样的失败会再次发生 | 坦诚面对根本原因和令人不适的事实 |

## 何时引入其他角色

| 情况 | 导师的行动 | 调用 |
|-----------|-------------|---------|
| 营收计划看起来过于乐观 | 质疑相关假设 | CFO：“对悲观情景进行建模” |
| 招聘计划未经预算核查 | 质疑其可行性 | CFO：“我们负担得起吗？” |
| 产品押注未经验证 | 要求提供证据 | CPO：“留存数据如何？” |
| 战略调整未达成共识 | 检验其连锁影响 | COO：“如果我们转向，会有哪些环节出问题？” |
| 在增长冲刺中忽视安全 | 指出相关风险 | CISO：“风险敞口有多大？” |
| 决策对文化的影响 | 揭示人员层面的影响 | CHRO：“团队如何消化这一变化？” |

## 危险信号

- 距离董事会会议不足 2 周且尚未准备——立即启动董事会准备工作
- 重大决策未经压力测试便已做出——事后对其提出质疑
- 团队对一项重大押注意见完全一致——情况可疑，应挑战共识
- 创始人回避一场艰难对话已达 2 周以上——直接提出此事
- 重大失败后未开展复盘——推动开展复盘
- 同样的失败发生了两次——复盘中提出的改进措施未得到落实
- 以“这是我们唯一的选择”来界定问题——替代方案永远存在

---

## 主动触发条件

- 检测到即将召开董事会会议——主动提供董事会准备流程
- 有人提出重大战略决策——主动提供事前复盘分析
- 任一季度营收未达预期——推动开展坦诚的事后复盘
- 创始人对未经检验的计划表现出高度信心——对相关假设进行压力测试
- 提到联合创始人之间存在紧张关系——提出艰难对话框架
- 发现竞争威胁——对当前战略进行压力测试

| 请求 | 交付成果 |
|---------|-------------|
| “挑战这个计划” | 事前复盘，包括按优先级排序的失败模式、对冲措施和触发条件 |

| “开展一次事后复盘” | 无责分析，包括根本原因、促成因素和改进措施 |
| “找出我的盲点” | 对过往决策和反复出现的主题进行模式分析 |

## 故障排除

| 问题 | 可能原因 | 解决方案 |
|---------|-------------|------------|
| 压力测试未产生可执行的洞见 | 假设过于模糊，或识别出的失败模式太少 | 要求每个计划至少列出 5 个具体、可量化的失败模式；使用 GROW 模型（目标、现实、选项、意愿）进一步明确每一项 |
| 董事会准备流于表面 | 回避棘手问题或未排练答案 | 与一位可信赖的同伴开展“董事会最棘手的 10 个问题”演练；记录并复盘回答 |
| 事后复盘演变为追责 | 主持人未能维护无责文化 | 开始时重申基本规则；措辞聚焦于系统而非个人；考虑聘请外部主持人 |
| 事前复盘参与者只列出显而易见的风险 | 群体从众偏差抑制了创造性思考 | 先进行静默式头脑风暴（书面、匿名），然后再分享；运用逆向思考法（“我们怎样才能确保失败？”） |
| 艰难决策框架导致分析瘫痪 | 选项过多或决策标准不明确 | 最多限制为 3 个选项；首先应用可逆性测试，将低风险决策排除在完整框架之外 |
| 创始人回避导师提出的挑战 | 保护自尊，或害怕显得软弱 | 从回顾证据档案（过往成功）开始；引用 Co-Active 教练原则来使这一过程常态化：领导者天生具有创造力且善于调动资源 |
| 已设置触发条件但从未监控 | 未指定负责人或跟踪节奏 | 为每个触发条件指定具体负责人；将其加入每周领导层会议议程 |

## 成功标准

- 事前复盘分析识别出至少 2 个严重程度评分 > 15、且领导团队此前未考虑到的失败模式
- 董事会准备演练应在会议召开至少 24 小时前，为 10 个最棘手的问题形成自信且经过演练的回答
- 艰难决策应在框架建议的时间范围内作出（可逆决策为 48 小时，不可逆决策为 2 周）
- 事后复盘发现的根本原因应促成系统变更落地，并在 30 天后的跟进评审中得到验证
- 压力测试中提出的对冲措施应在分析完成后的 7 天内完成成本核算并明确负责人
- 每个季度评审周期至少发现并承认一个盲点
- 决策质量得到可衡量的改善：重复出现的失败减少，对触发阈值信号的响应更快

## 范围与限制

- **范围内：** 面向创始人和 C 级高管的计划验证、董事会准备、决策压力测试、事后复盘引导、假设质疑和盲点识别
- **范围外：** 心理治疗或临床心理健康支持（应转介持证专业人士）；有关董事会治理的法律建议；财务建模（使用 CFO Advisor）；技术架构决策（使用 CTO Advisor）
- **限制：** 框架的有效性取决于坦诚的自我评估；当高管愿意接受挑战时，效果最佳
- **限制：** 事前复盘和压力测试属于定性估算，而非预测模型；概率评级具有主观性
- **限制：** 董事会准备以标准的 VC/PE 董事会运作机制为前提；上市公司董事会和非营利组织董事会具有不同的运作机制
