将界面突破传统极限。这不仅仅关乎视觉效果——而是要充分发挥浏览器的全部能力，让界面的任何部分都呈现出非凡体验：能够处理一百万行数据的表格、从触发元素变形展开的对话框、通过流式反馈进行实时验证的表单，以及具有电影质感的页面转场。

## 强制准备工作

调用 /impeccable——其中包含设计原则、反模式以及 **Context Gathering Protocol**。继续之前，请遵循该协议——如果目前尚无设计上下文，则必须先运行 /impeccable teach。

**对本技能而言尤其重要**：上下文决定了什么才算“非凡”。粒子系统用在创意作品集上会令人印象深刻。同样的粒子系统用在设置页面上则会让人尴尬。但如果设置页面具备即时乐观保存和动态状态转换，那同样堪称非凡。在决定采用何种方案之前，先了解项目的个性与目标。

### 构建前先提出方案

本技能最容易产生适得其反的结果。不要直接开始实现。你必须：

1. **构思 2-3 个不同方向**——考虑不同的技术、目标高度和美学方案。对于每个方向，简要描述最终效果的外观与体验。
2. **停止并调用 AskUserQuestion 工具进行澄清。** 展示这些方向，并在编写任何代码之前让用户选择。说明各自的权衡（浏览器支持、性能成本、复杂度）。
3. 仅按照用户确认的方向继续。

跳过此步骤可能会做出令人尴尬、最终只能全部推倒重来的东西。

### 使用浏览器自动化进行迭代

技术上雄心勃勃的效果几乎不可能一次成功。你必须主动使用浏览器自动化工具预览成果、直观验证效果并反复迭代。不要想当然地认为效果看起来没问题——亲自检查。做好进行多轮完善的准备。从“技术上可用”到“看起来非凡”之间的差距，需要通过视觉迭代来弥合，而不能只靠代码。

## 评估这里的“非凡”意味着什么

合适的技术野心完全取决于你正在处理的内容。在选择技术之前，先问：**什么会让这个特定界面的用户感叹“哇，真不错”？**

### 对于视觉化/营销型界面

页面、首屏区域、落地页、作品集——这里的“惊艳”通常来自感官体验：由滚动驱动的渐显效果、着色器背景、电影质感的页面转场，或响应光标移动的生成艺术。

### 对于功能型 UI

表格、表单、对话框、导航——这里的“惊艳”在于它的体验：通过 View Transitions 从触发按钮变形展开的对话框、借助虚拟滚动以 60fps 渲染 100k 行数据的数据表格、通过流式验证营造即时反馈体验的表单，以及带有弹簧物理效果的拖放交互。

### 对于性能关键型 UI

这里的“惊艳”不可见，却能被感受到：搜索功能可毫无闪烁地筛选 50k 个项目、复杂表单从不阻塞主线程、图像编辑器能够近乎实时地完成处理。整个界面始终毫无迟滞。

### 对于数据密集型界面
图表和仪表盘——其“惊艳之处”在于流畅性：通过 Canvas/WebGL 对海量数据集进行 GPU 加速渲染、在不同数据状态之间实现动画过渡，以及采用能够自然稳定下来的力导向图布局。

**共同点**：实现方式中的某些部分超出了用户对 Web 界面的预期。技术服务于体验，而不是反过来。

## 工具集

按照你要实现的目标组织，而不是按照技术名称组织。

### 让过渡具有电影般的质感
- **View Transitions API**（同文档：所有浏览器；跨文档：Firefox 不支持）——在不同状态之间实现共享元素变形。列表项展开为详情页。按钮变形为对话框。这是最接近原生 FLIP 动画的方案。
- **`@starting-style`**（所有浏览器）——仅使用 CSS 将元素从 `display: none` 动画过渡为可见状态，包括入场关键帧
- **弹簧物理效果**——使用质量、张力和阻尼实现自然运动，而不是使用 cubic-bezier。库：motion（原 Framer Motion）、GSAP，或者自行编写弹簧求解器。

### 将动画与滚动位置关联
- **滚动驱动动画**（`animation-timeline: scroll()`）——仅使用 CSS，无需 JS。视差效果、进度条和显现序列均由滚动位置驱动。（Chrome/Edge/Safari；Firefox：仅可通过 flag 启用——始终提供静态回退方案）

### 实现超越 CSS 的渲染效果
- **WebGL**（所有浏览器）——着色器效果、后期处理、粒子系统。库：Three.js、OGL（轻量级）、regl。用于实现 CSS 无法表达的效果。
- **WebGPU**（Chrome/Edge；Safari 部分支持；Firefox：仅可通过 flag 启用）——下一代 GPU 计算。比 WebGL 更强大，但浏览器支持有限。始终回退到 WebGL2。
- **Canvas 2D / OffscreenCanvas**——自定义渲染、像素操作，或者通过 Web Workers + OffscreenCanvas 将繁重的渲染工作完全移出主线程。
- **SVG 滤镜链**——使用位移贴图、湍流和形态学处理实现有机扭曲效果。可通过 CSS 制作动画。

### 让数据鲜活起来
- **虚拟滚动**——对于包含数万条数据的表格/列表，仅渲染可见行。简单场景无需使用库；复杂场景可使用 TanStack Virtual。
- **GPU 加速图表**——对于规模大到无法使用 SVG/DOM 的数据集，使用 Canvas 或 WebGL 渲染数据可视化。库：deck.gl、基于 regl 的自定义渲染器。
- **数据过渡动画**——在图表状态之间进行变形，而不是直接替换。可使用 D3 的 `transition()`，或者针对基于 DOM 的图表使用 View Transitions。

### 为复杂属性制作动画
- **`@property`**（所有浏览器）——注册带类型的自定义 CSS 属性，从而为 CSS 通常无法插值的渐变、颜色和复杂值制作动画。
- **Web Animations API**（所有浏览器）——由 JavaScript 驱动、具有 CSS 级性能的动画。可组合、可取消、可反转。它是复杂动画编排的基础。

### 突破性能边界
- **Web Workers**——将计算工作移出主线程。繁重的数据处理、图像操作、搜索索引——任何可能导致卡顿的任务。
- **OffscreenCanvas**——在 Worker 线程中渲染。在复杂视觉效果于后台渲染时，主线程仍可保持空闲。
- **WASM**——为计算密集型功能提供接近原生的性能。图像处理、物理模拟、编解码器。

### 与设备交互
- **Web Audio API** — 空间音频、音频响应式可视化、声音反馈。需要用户手势才能启动。
- **Device APIs** — 设备方向、环境光、地理位置。谨慎使用，并始终征得用户许可。

**注意**：此技能旨在增强界面的感受，而不是改变产品的功能。添加实时协作、离线支持或新的后端能力属于产品决策，而非 UI 增强。应专注于让现有功能带来非凡体验。

## 严谨实施

### 渐进增强不容妥协

每项技术都必须能够优雅降级。即使没有增强效果，体验仍然必须良好。

```css
@supports (animation-timeline: scroll()) {
  .hero { animation-timeline: scroll(); }
}
```

```javascript
if ('gpu' in navigator) { /* WebGPU */ }
else if (canvas.getContext('webgl2')) { /* WebGL2 fallback */ }
/* CSS-only fallback must still look good */
```

### 性能规则

- 目标是 60fps。如果降至 50 以下，就简化效果。
- 始终尊重 `prefers-reduced-motion`。提供美观的静态替代方案。
- 仅在接近视口时，才延迟初始化重量级资源（WebGL contexts、WASM modules）。
- 暂停屏幕外渲染。停止所有不可见的内容。
- 在真实的中端设备上测试，而不只是在开发机器上测试。

### 打磨决定成败

“酷”与“非凡”之间的差距，在于最后 20% 的精细打磨：弹簧动画的缓动曲线、交错呈现的时间偏移，以及让过渡产生物理质感的细微次级运动。不要交付第一个能用的版本，而要交付一个让人觉得一切本该如此的版本。

**绝不要**：
- 忽略 `prefers-reduced-motion`——这是无障碍要求，而不是建议
- 交付会在中端设备上造成卡顿的效果
- 在没有可用回退方案的情况下使用前沿 API
- 未经用户明确选择启用就添加声音
- 用技术野心掩盖薄弱的设计基础——先使用其他技能解决这些问题
- 叠加多个相互争夺注意力的非凡时刻——聚焦才能产生冲击力，过度只会制造噪声

## 验证结果

- **惊艳测试**：展示给一个从未见过它的人。他们有反应吗？
- **移除测试**：将其移除。体验是否有所减损，还是根本没人注意？
- **设备测试**：在手机、平板电脑和 Chromebook 上运行。仍然流畅吗？
- **无障碍测试**：启用减少动态效果。仍然美观吗？
- **情境测试**：这适合这个品牌和受众吗？

请记住：“技术上的非凡”并不在于使用最新的 API，而在于让界面实现用户未曾想过网站能够做到的事情。
