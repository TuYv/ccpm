**参数检查：** 如果未提供赛季名称或事件描述，则输出：
> “用法：`/team-live-ops [season name or event description]` — 请提供要规划的赛季或实时活动的名称或描述。”
然后立即停止，不要生成任何子智能体，也不要读取任何文件。

当使用有效参数调用此技能时，通过结构化规划流程协调实时运营团队。

**决策点：** 在每次阶段转换时，使用 `AskUserQuestion` 将子智能体的提案作为可选项呈现给用户。先在对话中写出智能体的完整分析，然后使用简洁的标签记录决策。必须获得用户批准后才能进入下一阶段。

## 阶段 0：确定评审模式

1. 如果参数中传入了 `--review [mode]`，则使用该模式。
2. 否则，读取 `production/review-mode.txt`——使用其中写明的模式。
3. 如果仍未确定，则默认为 `lean`。

模式：
- `full`——按说明生成所有总监和负责人关卡
- `lean`——跳过总监关卡，除非其属于 PHASE-GATE 类型（CD-PHASE-GATE、TD-PHASE-GATE、PR-PHASE-GATE、AD-PHASE-GATE）
- `solo`——完全跳过所有总监关卡的生成；在不经过任何智能体关卡的情况下运行此技能

存储确定后的模式，以供所有后续阶段使用。

## 团队构成
- **live-ops-designer**——赛季结构、活动节奏、留存机制、战斗通行证
- **economy-designer**——实时经济平衡、商店轮换、货币定价、保底机制
- **analytics-engineer**——成功指标、A/B 测试设计、事件追踪、仪表板规范
- **community-manager**——面向玩家的公告、活动描述、赛季信息传达
- **narrative-director**——赛季叙事主题、故事线、世界事件框架
- **writer**——活动描述、奖励物品名称、赛季氛围文本、公告文案

## 如何委派

使用 Task 工具将每位团队成员生成为子智能体：
- `subagent_type: live-ops-designer`——赛季/活动结构和留存机制
- `subagent_type: economy-designer`——实时经济平衡和奖励定价
- `subagent_type: analytics-engineer`——成功指标、A/B 测试和活动埋点
- `subagent_type: community-manager`——面向玩家的沟通和信息传达
- `subagent_type: narrative-director`——赛季主题和叙事框架
- `subagent_type: writer`——所有面向玩家的文本：活动描述、物品名称和文案

始终在每个智能体的提示中提供完整上下文（游戏概念路径、现有赛季文档、伦理政策路径、当前经济状态）。在流程允许的情况下并行启动相互独立的智能体（阶段 3 和阶段 4 可以同时运行）。

## 流程

### 阶段 1：赛季/活动范围界定
委派给 **live-ops-designer**：
- 定义赛季或活动：类型（赛季、限时活动、挑战）、持续时间、主题方向
- 概述内容清单：新增内容（模式、物品、挑战、故事节点）
- 定义留存钩子：在本赛季期间，哪些内容能吸引玩家每日/每周回归
- 确定资源预算：需要创建多少新内容，以及复用多少现有内容
- 输出：包含范围、内容清单和留存机制概述的赛季简报

### 阶段 2：叙事主题
委派给 **narrative-director**：
- 阅读阶段 1 的赛季简报
- 设计赛季叙事主题：该活动如何与游戏世界产生联系？
- 定义玩家将在活动期间发现的核心故事钩子
- 确定本赛季可以推进哪些现有的背景故事线索
- 输出：叙事框架文档（主题、故事钩子、背景故事关联）

### 阶段 3：经济系统设计（如果主题明确，可与阶段 2 并行）
委派给 **economy-designer**：
- 阅读赛季简报以及 `design/live-ops/economy-rules.md` 中的现有经济系统规则
- 设计奖励路线：免费层级的进度设计、付费层级的价值主张
- 规划赛季内经济系统：赛季货币、商店轮换、定价
- 为所有随机元素定义保底机制和坏运气保护
- 确认付费奖励路线中不存在付费获胜道具
- 输出：包含奖励表、定价和货币流向的经济系统设计文档

### 阶段 4：分析与成功指标（与阶段 3 并行）
委派给 **analytics-engineer**：
- 阅读赛季简报
- 定义成功指标：参与率目标、留存率提升目标、战斗通行证完成率
- 设计赛季期间要运行的所有 A/B 测试（例如不同的奖励发放节奏）
- 指明本赛季内容所需的新遥测事件
- 输出：包含成功标准和埋点要求的分析计划

### 阶段 5：内容撰写（并行）
并行委派：
- **narrative-director**（如需要）：为本赛季撰写所有游戏内叙事文本（过场动画脚本、NPC 对话、世界事件描述）
- **writer**：撰写所有面向玩家的文本——活动名称、奖励道具描述、挑战目标文本、赛季风味文本
- 两者都应阅读阶段 2 的叙事框架文档

### 阶段 6：玩家沟通计划
委派给 **community-manager**：
- 阅读赛季简报、经济系统设计和叙事框架
- 起草赛季上线公告（语气、主要亮点、各平台专用版本）
- 规划沟通节奏：上线前预告、上线当天帖子、赛季中期提醒、最后一周的 FOMO 推广
- 为首日补丁说明起草已知问题部分的占位内容
- 输出：包含每个沟通触点文案草稿的沟通日历

### 阶段 7：审查与签署批准
收集所有阶段的输出，并提交一份整合后的赛季计划：
- 赛季简报（阶段 1）
- 叙事框架（阶段 2）
- 经济系统设计和奖励表（阶段 3）
- 分析计划和成功指标（阶段 4）
- 书面内容清单（阶段 5）
- 沟通日历（阶段 6）

向用户提交摘要，其中包括：
- **内容范围**：将创建哪些内容
- **经济系统健康检查**：奖励路线是否公平且不存在掠夺性设计？
- **分析准备情况**：是否已定义成功标准并完成埋点？
- **伦理审查**：依据 `design/live-ops/ethics-policy.md` 检查阶段 3 的经济系统设计
  - 如果文件不存在：标记“伦理审查已跳过：未找到 `design/live-ops/ethics-policy.md`。经济系统设计尚未依据伦理政策进行审查。建议在开始制作前创建该文件。”将此标记包含在赛季设计输出文档中。在后续步骤中添加：创建 `design/live-ops/ethics-policy.md`。
  - 如果文件存在且发现违规：标记“伦理问题：[阶段 3 经济系统设计中的元素]违反了[政策规则]。在解决此问题之前，不予批准。”不要给出 COMPLETE 结论，也不要编写输出文档。使用 `AskUserQuestion` 并提供以下选项：修改经济系统设计 / 在记录理由后推翻该结论 / 取消。如果用户选择修改：重新启动 economy-designer 以生成修正后的设计，然后返回阶段 7 进行审查。如果用户选择取消：以“结论：BLOCKED——由于存在尚未解决的伦理违规问题，在线运营设计已取消。请解决标记的问题并重新运行 /team-live-ops。”结束。
- **待决问题**：开始制作前仍需做出哪些决策

在委派给制作团队之前，请用户批准赛季计划。只有在用户批准且不存在未解决的伦理违规问题后，才能给出 COMPLETE 裁定。如果仍有未解决的伦理违规问题，请以裁定：**BLOCKED** 结尾。

## 输出文档

所有文档均保存到 `design/live-ops/`：
- `seasons/S[N]_[name].md` — 赛季设计文档（来自阶段 1-3）
- `seasons/S[N]_[name]_analytics.md` — 分析计划（来自阶段 4）
- `seasons/S[N]_[name]_comms.md` — 沟通日历（来自阶段 6）

## 错误恢复协议

如果任何派生的代理（通过 Task）返回 BLOCKED、报错或无法完成：

1. **立即披露**：在继续执行依赖阶段之前，向用户报告“[AgentName]: BLOCKED — [reason]”
2. **评估依赖关系**：检查后续阶段是否需要被阻塞代理的输出。如果需要，则在没有用户输入的情况下，不得越过该依赖节点继续执行。
3. **通过 AskUserQuestion 提供选项**，选项包括：
   - 跳过此代理，并在最终报告中注明这一缺失
   - 缩小范围后重试
   - 在此停止，优先解决阻塞问题
4. **始终生成部分报告** — 输出所有已完成的内容。绝不能因为某个代理被阻塞而丢弃已有工作。

如果 BLOCKED 状态无法解决，请以裁定：**BLOCKED** 结尾，而不是 COMPLETE。

## 文件写入协议

所有文件写入操作（赛季设计文档、分析计划、沟通日历）均委派给通过 Task 派生的子代理。每个子代理都会执行“我可以写入 [path] 吗？”协议。此编排器不会直接写入文件。

## 输出

一份摘要，涵盖：赛季主题和范围、经济系统设计亮点、成功指标、内容列表、沟通计划，以及在投入制作前仍需用户决定的所有未决事项。

裁定：**COMPLETE** — 赛季计划已生成并移交制作。
