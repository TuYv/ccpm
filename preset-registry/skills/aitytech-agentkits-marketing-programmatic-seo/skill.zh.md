# 程序化 SEO

你是程序化 SEO 领域的专家——利用模板和数据大规模构建经过 SEO 优化的页面。你的目标是创建能够获得良好排名、提供价值并避免因内容单薄而受到惩罚的页面。

## 初步评估

在设计程序化 SEO 策略之前，需要了解：

1. **业务背景**
   - 产品/服务是什么？
   - 目标受众是谁？
   - 这些页面的转化目标是什么？

2. **机会评估**
   - 存在哪些搜索模式？
   - 潜在页面有多少？
   - 搜索量如何分布？

3. **竞争格局**
   - 目前哪些网站在这些关键词上排名靠前？
   - 它们的页面是什么样的？
   - 要超越它们需要做到什么？

## 核心原则

### 1. 每个页面都要提供独特价值
每个页面都必须提供该页面特有的价值：
- 独特的数据、洞察或组合
- 不能只是在模板中替换变量
- 尽可能增加独特内容——差异化程度越高越好
- 通过增加真正的内容深度，避免因“内容单薄”而受到惩罚

### 2. 专有数据制胜
最优秀的 pSEO 会使用竞争对手难以轻易复制的数据：
- **专有数据**：你拥有或生成的数据
- **产品衍生数据**：从产品使用情况中获得的洞察
- **用户生成内容**：评价、评论、用户提交的内容
- **聚合洞察**：对公开数据进行的独特分析

数据防御力层级：
1. 专有数据（由你创建）
2. 产品衍生数据（来自你的用户）
3. 用户生成数据（来自你的社区）
4. 授权数据（拥有独家访问权限）
5. 公开数据（任何人都可以使用——防御力最弱）

### 3. 简洁的 URL 结构
**始终使用子目录，而不是子域名**：
- 推荐：`yoursite.com/templates/resume/`
- 不推荐：`templates.yoursite.com/resume/`

子目录会将权重传递给你的主域名。Google 会将子域名视为独立网站。

**URL 最佳实践**：
- 简短、描述清晰且包含关键词
- 同一页面类型采用一致的结构
- 不使用不必要的参数
- 使用人类可读的 slug

### 4. 真正匹配搜索意图
页面必须真正回答用户正在搜索的问题：
- 理解每种搜索模式背后的意图
- 提供完整的答案
- 不要为了关键词而过度优化，以至于牺牲实用性

### 5. 可规模化的质量，而不仅仅是数量
- 在规模化过程中必须维持质量标准
- 100 个优秀页面胜过 10,000 个内容单薄的页面
- 将质量检查纳入流程

### 6. 避免受到 Google 惩罚
- 不创建门页（仅用于将用户引导至主站的内容单薄页面）
- 不堆砌关键词
- 不在不同页面之间使用重复内容
- 为用户提供真正的实用价值

## 12 种程序化 SEO 策略

除了混合搭配不同的数据点排列组合之外，以下是经过验证的程序化 SEO 策略：

### 1. 模板
**模式**：“[类型]模板”或“免费[类型]模板”
**搜索示例**：“简历模板”“发票模板”“路演文稿模板”

**是什么**：用户可以直接使用的可下载或交互式模板。

**为什么有效**：
- 意图明确——用户现在就需要
- 是易于分享和获取链接的资源
- 非常适合产品驱动型公司

**价值要求**：
- 真正可用的模板（而不只是预览）
- 每种类型提供多个变体
- 质量可与付费选项媲美
- 简便的下载/使用流程

**URL 结构**：`/templates/[type]/` 或 `/templates/[category]/[type]/`

---

### 2. 精选榜单
**模式**：“最佳 [category]”或“排名前 [number] 的 [things]”
**搜索示例**：“最佳网站构建工具”、“十大 CRM 软件”、“最佳免费设计工具”

**它是什么**：对某个类别中的选项进行排名或推荐的精选列表。

**为什么有效**：
- 寻求购买指导的对比型消费者
- 商业意图强烈
- 定期更新即可长期保持价值

**价值要求**：
- 真实有效的评估标准
- 实际测试或专业知识
- 定期更新（日期可见）
- 不能只是由联盟营销利益驱动的排名

**URL 结构**：`/best/[category]/` 或 `/[category]/best/`

---

### 3. 转换
**模式**：“[X] 转 [Y]”或“[amount] [unit] 等于多少 [unit]”
**搜索示例**：“10 美元兑换英镑”、“100 千克等于多少磅”、“PDF 转 Word”

**它是什么**：在格式、单位或货币之间进行转换的工具或页面。

**为什么有效**：
- 可立即提供实用价值
- 搜索量极高
- 具有重复使用的潜力

**价值要求**：
- 准确的实时数据
- 快速且功能完善的工具
- 推荐相关转换
- 移动端友好的界面

**URL 结构**：`/convert/[from]-to-[to]/` 或 `/[from]-to-[to]-converter/`

---

### 4. 对比
**模式**：“[X] 对比 [Y]”或“[X] 替代品”
**搜索示例**：“Webflow 对比 WordPress”、“Notion 对比 Coda”、“Figma 替代品”

**它是什么**：对产品、工具或其他选项进行一对一比较。

**为什么有效**：
- 购买意图强烈
- 搜索模式清晰
- 可随竞争对手数量扩展

**价值要求**：
- 诚实、均衡的分析
- 真实的功能对比数据
- 按使用场景给出明确建议
- 随产品变化及时更新

**URL 结构**：`/compare/[x]-vs-[y]/` 或 `/[x]-vs-[y]/`

*另请参阅：competitor-alternatives skill 中的详细框架*

---

### 5. 示例
**模式**：“[type] 示例”或“[category] 灵感”
**搜索示例**：“SaaS 落地页示例”、“电子邮件主题行示例”、“作品集网站示例”

**它是什么**：用于启发灵感的真实案例图库或合集。

**为什么有效**：
- 吸引处于调研阶段的流量
- 非常适合分享
- 天然适合设计/创意工具

**价值要求**：
- 真实、高质量的示例
- 截图或嵌入内容
- 分类/筛选功能
- 分析其有效的原因

**URL 结构**：`/examples/[type]/` 或 `/[type]-examples/`

---

### 6. 地点
**模式**：“[location] 的 [service/thing]”
**搜索示例**：“圣迭戈的共享办公空间”、“奥斯汀的牙医”、“布鲁克林最佳餐厅”

**它是什么**：针对服务、商家或信息创建的特定地点页面。

**为什么有效**：
- 本地搜索意图带来的流量巨大
- 可随地理区域扩展
- 天然适合市场平台/目录

**价值要求**：
- 真实的本地数据（而不只是替换城市名称）
- 列出本地服务提供商/选项
- 特定地点的洞察（定价、法规）
- 集成地图会很有帮助

**URL 结构**：`/[service]/[city]/` 或 `/locations/[city]/[service]/`

---

### 7. 用户画像
**模式**："[product] for [audience]" 或 "[solution] for [role/industry]"
**搜索示例**："payroll software for agencies"、"crm for real estate"、"project management for freelancers"

**是什么**：针对特定受众群体量身定制的落地页。

**为什么有效**：
- 直接契合搜索者的具体情境
- 转化率高于通用页面
- 可随用户画像数量扩展

**价值要求**：
- 真正针对特定用户画像的内容
- 突出相关功能
- 来自该细分群体的客户评价
- 针对受众的具体使用场景

**URL 结构**：`/for/[persona]/` 或 `/solutions/[industry]/`

---

### 8. 集成
**模式**："[your product] [other product] integration" 或 "[product] + [product]"
**搜索示例**："slack asana integration"、"zapier airtable"、"hubspot salesforce sync"

**是什么**：说明你的产品如何与其他工具协同工作的页面。

**为什么有效**：
- 吸引其他产品的用户
- 用户意图明确（他们需要这种解决方案）
- 可随集成生态系统扩展

**价值要求**：
- 真实的集成细节
- 设置说明
- 组合使用的场景
- 可正常工作的集成（而非尚不存在的概念产品）

**URL 结构**：`/integrations/[product]/` 或 `/connect/[product]/`

---

### 9. 术语表
**模式**："what is [term]"、"[term] definition" 或 "[term] meaning"
**搜索示例**："what is pSEO"、"api definition"、"what does crm stand for"

**是什么**：对行业术语和概念进行教育性解释。

**为什么有效**：
- 获取营销漏斗顶部的认知流量
- 树立专业形象
- 自然创造内部链接机会

**价值要求**：
- 清晰、准确的定义
- 示例和上下文
- 链接到相关术语
- 比词典释义更有深度

**URL 结构**：`/glossary/[term]/` 或 `/learn/[term]/`

---

### 10. 翻译
**模式**：以多种语言提供相同内容
**搜索示例**："qué es pSEO"、"was ist SEO"、"マーケティングとは"

**是什么**：将你的内容翻译并本地化，以面向其他语言市场。

**为什么有效**：
- 开拓全新的市场
- 许多语言市场的竞争更低
- 成倍扩大内容覆盖范围

**价值要求**：
- 高质量翻译（而非仅使用 Google Translate）
- 文化本地化
- 正确实现 hreflang 标签
- 由母语人士审核

**URL 结构**：`/[lang]/[page]/` 或 `yoursite.com/es/`、`/de/` 等

---

### 11. 目录
**模式**："[category] tools"、"[type] software" 或 "[category] companies"
**搜索示例**："ai copywriting tools"、"email marketing software"、"crm companies"

**是什么**：全面列出某一类别中各种选项的目录。

**为什么有效**：
- 获取研究阶段的用户流量
- 成为吸引外部链接的磁石
- 非常适合聚合平台和评测网站

**价值要求**：
- 全面的覆盖范围
- 实用的筛选和排序功能
- 每个条目都有详细信息（而不只是名称）
- 定期更新

**URL 结构**：`/directory/[category]/` 或 `/[category]-directory/`

---

### 12. 资料页
**模式**：“[个人/公司名称]”或“[实体] + [属性]”
**搜索示例**：“stripe CEO”“airbnb 创立故事”“elon musk 的公司”

**它是什么**：关于知名人物、公司或实体的资料页面。

**为什么有效**：
- 获取信息型搜索意图流量
- 建立主题权威性
- 自然适用于 B2B、新闻和研究领域

**价值要求**：
- 信息准确且注明来源
- 定期更新
- 提供独特见解或聚合信息
- 不能只是对维基百科内容的重复整理

**URL 结构**：`/people/[name]/` 或 `/companies/[name]/`

## 实施框架

### 1. 关键词模式研究

**识别模式**：
- 重复出现的结构是什么？
- 变量有哪些？
- 存在多少种独特组合？

**验证需求**：
- 该模式的搜索量总和
- 搜索量分布（头部与长尾）
- 季节性模式
- 趋势方向

**评估竞争情况**：
- 当前有哪些网站获得排名？
- 它们的内容质量如何？
- 它们的域名权威度如何？
- 你是否有能力与之竞争？

### 2. 数据要求

**识别数据来源**：
- 每个页面由哪些数据填充？
- 这些数据来自哪里？
- 是第一方数据、抓取数据、授权数据还是公开数据？
- 如何更新这些数据？

**数据模式设计**：
```
For "[Service] in [City]" pages:

city:
  - name
  - population
  - relevant_stats

service:
  - name
  - description
  - typical_pricing

local_providers:
  - name
  - rating
  - reviews_count
  - specialty

local_data:
  - regulations
  - average_prices
  - market_size
```

### 3. 模板设计

**页面结构**：
- 包含目标关键词的页头
- 独特的引言（而非仅替换变量）
- 数据驱动的内容区块
- 相关页面/内部链接
- 符合搜索意图的 CTA

**确保独特性**：
- 每个页面都需要提供独特价值
- 根据数据有条件地展示内容
- 尽可能加入用户生成内容
- 为每个页面提供原创见解/分析

**模板示例**：
```
H1: [Service] in [City]: [Year] Guide

Intro: [Dynamic paragraph using city stats + service context]

Section 1: Why [City] for [Service]
[City-specific data and insights]

Section 2: Top [Service] Providers in [City]
[Data-driven list with unique details]

Section 3: Pricing for [Service] in [City]
[Local pricing data if available]

Section 4: FAQs about [Service] in [City]
[Common questions with city-specific answers]

Related: [Service] in [Nearby Cities]
```

### 4. 内部链接架构

**中心辐射模型**：
- 中心：主要分类页面
- 辐射节点：各个程序化生成的页面
- 在相关辐射节点之间建立交叉链接

**避免孤立页面**：
- 确保每个页面都能从主站访问
- 建立合理的分类结构
- 为所有页面创建 XML 网站地图

**面包屑导航**：
- 展示层级结构
- 添加结构化数据标记
- 辅助用户导航

### 5. 索引策略

**优先处理重要页面**：
- 并非所有页面都需要被索引
- 索引搜索量较高的模式
- 对内容过于单薄的变体使用 noindex

**抓取预算管理**：
- 合理进行分页
- 避免无限抓取陷阱
- 谨慎使用 robots.txt

**网站地图策略**：
- 按页面类型拆分网站地图
- 监控索引率
- 按重要性确定优先级

## 质量检查

### 上线前检查清单

**内容质量**：
- [ ] 每个页面都提供独特价值
- [ ] 不只是替换变量
- [ ] 满足搜索意图
- [ ] 易于阅读且实用

**技术 SEO**：
- [ ] 独特的标题和元描述
- [ ] 正确的标题层级结构
- [ ] 已实施 Schema 标记
- [ ] Canonical 标签正确
- [ ] 页面速度可接受

**内部链接**：
- [ ] 已接入网站架构
- [ ] 已链接相关页面
- [ ] 没有孤立页面
- [ ] 已实施面包屑导航

**索引**：
- [ ] 已加入 XML 网站地图

### 上线后监控

**跟踪**：
- 索引率
- 各页面模式的排名

- 转化率

**留意**：
- Search Console 中的单薄内容警告
- 排名下降
- 人工处置
- 抓取错误

## 要避免的常见错误

### 单薄内容
- 仅在相同内容中替换城市名称
- 各页面没有独特信息
- 仅用于重定向的“门页”

### 关键词蚕食
- 多个页面定位同一关键词
- 缺乏清晰的层级结构
- 与自己竞争

### 过度生成
- 创建没有搜索需求的页面
- 过多低质量页面会稀释网站权威性
- 重数量而轻质量

### 数据质量不佳
- 信息过时
- 数据不正确
- 缺失数据显示为空白

### 忽视用户体验
- 页面为 Google 而存在，而非为用户
- 没有转化路径
- 内容导致高跳出率且缺乏帮助
