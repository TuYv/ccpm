# 个人战略信号情报

## 概述

个人战略信号情报（PSSI）将个人长期积累的信息轨迹转化为决策支持。它并不是一个附带书签导入功能的内容创意生成器。它的首要任务是阐明操作者正在关注什么、验证什么、怀疑什么，以及正准备做出哪些决定。内容、产品、商业方案和实验都是下游应用。

该系统可以读取多种个人信号来源，包括：

- 稍后阅读资料库
- 浏览器或知识库中的收藏内容
- 社交平台书签
- 明确标记为已读的内容
- 高亮和批注
- 个人笔记和备忘录
- 会议后续事项和决策记录
- 实验、原型和已发布的应用
- 用户提供的公开文章或过往决策

将每个来源都视为具有已知强度、日期和来源链路的证据。绝不要把推断出的信念表述为已明确声明的事实。

## 何时使用

当用户提出以下请求时，请使用此技能：

- 了解其注意力或战略兴趣正在如何变化
- 识别其似乎正在接近做出的决策
- 将其明确表达的信念与近期证据或行为进行比较
- 将收藏的材料转化为实验、原型或运营调整
- 重新组合现有框架，形成有充分依据的创始人或高管知识产权
- 发现由反复出现的市场痛点所暗示的商业方案或服务
- 找出其持续研究但尚未公开讨论的重要主题
- 开展每周个人情报回顾
- 在重大决策、大量相关收藏、矛盾或应用实验发生后，触发一次聚焦式回顾

请勿将其用于：

- 诊断人格、心理健康状况或私人动机
- 在缺乏决策问题的情况下总结整个资料库
- 根据私人活动对人员、客户或员工进行排名
- 公开推断出的信念或敏感来源材料
- 将书签、点赞或关注视为认同
- 创建任意的高频综合分析循环

## 运行原则

### 1. 决策情报优先于内容

始终先询问信号可能为哪项决策、资源分配、信念更新、风险或实验提供信息。只有在此之后，系统才应提出内容建议。如果未发现与决策的相关性，应将输出标记为探索性内容，而不是强行赋予其商业意义。

### 2. 注意力不等于确信

收藏是注意力的证据，而不是赞同的证据。反复收藏可能意味着好奇、焦虑、主动研究、竞争监测或持不同意见。

默认使用以下信号强度阶梯：

| 信号 | 默认解读 | 相对强度 |
|---|---|---:|
| 收藏、点赞、关注或添加书签 | 弱注意力信号 | 1 |
| 跨时间或来源反复收藏 | 持续关注 | 2 |
| 明确标记为已读 | 有意识地接触 | 3 |
| 高亮或批注 | 显著观点 | 4 |
| 原创笔记或综合分析 | 主动解读 | 5 |
| 决策引用或明确表达的信念 | 已表达的确信 | 6 |
| 实验、原型、购买或运营调整 | 已付诸实践的确信 | 7 |
| 反复应用并获得可衡量的结果 | 经验证的运营信念 | 8 |

权重可配置。绝不能仅仅因为存在许多弱信号，就将其转化为强结论。

### 3. 私有推断信念必须保持私有

系统可以推断候选信念，以帮助用户思考。每项推断都必须标记为 `private inferred belief`，包含支持性证据和矛盾证据，并注明置信度。未经明确确认，不得发布、发送给协作者，也不得将其视为用户明确表达的立场。

请谨慎措辞：

- 恰当："你最近的笔记可能表明，你对广泛自动化的怀疑正在增加。"
- 不当："你认为广泛自动化是一个错误。"

### 4. 先追溯来源，再进行综合

每项重要结论都必须能够追溯到其源记录。在内部保留原始来源标识符，并在输出中显示人类可读的引用。如果某项结论无法追溯，请将其标记为 `unverified synthesis`，或将其删除。

### 5. 禁止将衍生内容循环用作证据

先前的综合内容不属于新证据。不要将仪表板、每周简报、生成的笔记或模型先前的推断作为独立支持依据，除非其中包含新的第一手观察。

请遵守以下规则：

1. 一手证据是源条目、用户明确陈述、观察到的应用情况或测量结果。
2. 衍生证据是基于一手证据构建的摘要、聚类标签、分数或推断。
3. 衍生证据可以帮助导航，但不能通过被重复计数来提高置信度。
4. 如果用户后来对生成的产物添加了注释，则只有新增的注释属于一手证据；生成的文本仍然属于衍生内容。
5. 保留 `derived_from` 列表，以便检测并拒绝循环引用。

## 来源契约

在分析之前对源记录进行标准化：

```yaml
signal_id: stable-source-id
source_type: read_later | social_bookmark | highlight | note | decision | application | other
source_system: user-facing connector name
source_url: optional canonical URL
source_item_id: optional connector-native ID
captured_at: ISO-8601 timestamp
engaged_at: optional ISO-8601 timestamp
engagement: saved | opened | read | highlighted | annotated | applied | measured
text_excerpt: minimal relevant excerpt
user_text: optional user-authored note
privacy: private | shareable | public
content_hash: hash of normalized source content
```

每项衍生结论都必须包含以下溯源字段：

```yaml
claim_id: stable-derived-id
claim: concise statement
claim_type: observation | private_inferred_belief | hypothesis | recommendation
source_ids: [signal-id-1, signal-id-2]
derived_from: []
supporting_evidence: []
contradicting_evidence: []
confidence: low | medium | high
created_at: ISO-8601 timestamp
```

拒绝 `source_ids` 为空的结论，除非它们被明确标记为问题或假设。

## 分析工作流

### 第 1 步：确定范围和决策背景

记录：

- 审查时间范围
- 可用的来源类型
- 当前决策或战略问题（如有）
- 隐私边界
- 预期输出：决策备忘录、矛盾简报、构建队列、产品方案图、内容图谱或每周回顾

如果用户没有提供决策问题，则从广泛的信号检测开始，但不要人为制造紧迫感。

### 步骤 2：最低限度地摄取数据

仅请求所选模块必需的字段。优先采用增量同步，而不是导出完整资料库。将连接器令牌存储在笔记、提示词和生成的产物之外。如果来源 ID、标题和相关摘录已经足够，就不要包含完整的私有文档。

### 步骤 3：标准化并去重

根据规范 URL、原生来源 ID 和内容哈希进行去重。将多次互动作为同一来源上的多个事件保留，而不要将它们视为彼此独立的来源。如果连接器提供编辑和删除信息，请予以记录。

### 步骤 4：为证据评分

按不同维度分别评分：

- `attention_strength`：频率、时效性、来源多样性
- `conviction_strength`：笔记、决策、应用、实测结果
- `source_quality`：一手证据、具体程度、可信度
- `strategic_relevance`：与当前决策或既定优先事项的关联
- `novelty`：与已知主题的差异
- `contradiction`：与先前陈述或行为之间的矛盾

绝不要将关注度和确信度合并成一个不透明的分数。一个主题可能具有较高的关注度，但确信度较低。

### 步骤 5：构建包含反面证据的论断

对于每个高价值聚类：

1. 陈述可观察到的模式。
2. 列出一手证据。
3. 列出合理的替代解释。
4. 搜索相互矛盾的证据。
5. 将任何信念推断标记为私密且暂定。
6. 明确它为哪个决策、测试或问题提供信息。
7. 根���证据质量而非修辞上的连贯性来设置信心水平。

### 步骤 6：应用专家评审组

使用可配置的评审组和通过阈值。默认通过阈值为 **90/100**。用户可以为探索性工作设置不同的阈值，但所选阈值必须出现在输出中。

推荐的评审视角：

| 视角 | 问题 |
|---|---|
| 证据审计员 | 论断是否可以追溯到一手证据，并且没有重复计算？ |
| 决策策略师 | 这是否能实质性地改善一项真实决策？ |
| 逆向审查员 | 哪些证据或解释会推翻该结论？ |
| 执行者 | 是否存在具体且范围明确的下一步行动？ |
| 隐私监督员 | 输出对于其目标受众是否安全？ |
| 领域专家 | 分析在相关领域是否可信？ |
| 衡量审查员 | 建议能否产生可观察的反馈？ |

为每个视角给出 0-100 分，计算平均分，并记录平均分和阈值。低于 90 分的条目仍可作为探索性假设保留，但在默认配置下不得将其提升为建议。

### 步骤 7：生成行动产物

每条被提升的洞察都应最终形成以下成果之一：

- 一个包含选项和证据的决策问题
- 一个可证伪的实验
- 一份小型构建规格
- 一个需要解决的矛盾
- 一个有待验证的产品假设
- 一个基于来源形成明确观点的内容空白
- 一个受到监测且具有明确重新审查触发条件的主题

### 第 8 步：记录反馈

记录用户接受、拒绝、纠正、应用或衡量的内容。用户的纠正会成为新的第一手证据。模型的复述不会。

## 七大能力模块

### 模块 1：注意力漂移

**目的：** 检测操作者的注意力如何变化，同时避免将注意力与信念混为一谈。

按主题、来源多样性、重复出现情况和参与深度比较不同时间窗口。报告：

- 新兴主题
- 加速升温的主题
- 逐渐消退的主题
- 持续存在的主题
- 从收藏转向笔记或应用的主题
- 受到高度关注但没有证据表明已形成确信的主题

在私有工作区之外分享时，优先使用比例和方向性表述，而不是语料库总量的精确数字。

### 模块 2：决策前预判

**目的：** 在操作者尚未明确提出决策之前，揭示其可能正在接近的决策。

寻找汇聚信号，例如反复研究、对立观点、实施笔记、供应商比较和应用测试。将候选决策以问题而非预测的形式输出：

```markdown
## Candidate decision
**Question:** Should we standardize this workflow now or keep it experimental?
**Why it may be approaching:** <source-grounded pattern>
**Evidence for acting:** <citations>
**Evidence for waiting:** <citations>
**Smallest reversible test:** <action>
**Confidence:** medium
```

不要声称知道用户将做出什么决定。

### 模块 3：矛盾 / 决策法庭

**目的：** 让有建设性的矛盾变得可见，并迫使相互竞争的假设面对同一组证据。

默认使用以下可配置的混合准入策略：

- **明确且在范围内的决策自动进入。** 当用户明确将某个范围内的事项标记为决策时，将其加入决策法庭，无需单独进行提名审批。
- **推断得出的范围内候选事项需要审批。** 当系统推断一项潜在的高风险决策正在形成时，使用简短且有来源依据的理由提名该事项，并等待用户批准后再运行完整的决策法庭分析。
- **普通活动不是决策。** 不要仅仅因为日常对话、问题、任务、笔记或待办事项可能具有战略相关性，就将其视为决策。

除非用户另行配置，否则使用以下经过泛化处理的 V0 范围：

- 战略押注
- 产品或服务变更
- 高级职位招聘
- 资本配置
- 合并、收购或合作
- 影响重大的客户押注

日常运营事项不包括在内，除非至少满足一个已配置的重大性门槛。V0 默认值为：

- 预期损失或承诺支出至少为 **USD 5,000**
- 预期工作量至少为 **40 person-hours**
- 存在重大声誉风险
- 该选择具有显著的不可逆性

这些只是初始默认值，并非普遍适用的常量。应允许配置纳入范围的决策类别、货币、损失或支出门槛、工作量门槛及其单位、重大声誉风险的定义、显著不可逆性的定义，以及任何明确的纳入项或排除项。在每次决策法庭输出中记录当前生效的范围和门槛。如果用户尚未提供配置，则使用上述 V0 默认值。当缺少证据时，不要编造精确的风险敞口或工作量估算；将该门槛标记为未知，并在准入前请求确认。

用户还可以配置决策标签、提名格式和自动录入行为。除非另有配置，否则应保留上述区别，并遵循现有的隐私、溯源和授权规则。

流程：

1. 中立地陈述表面上的矛盾。
2. 为双方构建最有力的论证。
3. 引用支持双方观点的一手证据。
4. 确定分歧是事实性、时间性、情境性还是价值观层面的。
5. 指出缺失的证据。
6. 建议采用测试、决策规则或明确标记为尚未解决。

矛盾并不等同于虚伪。人们会更新自己的信念、在不同情境中采用不同规则，或探索相互对立的观点。

### 模块 4：从收藏到构建

**目的：** 将反复收藏的想法转化为小型、可测试的操作性产物。

推进顺序：

`save -> read -> annotate -> synthesize -> specify -> build -> measure`

除非用户要求快速制作原型，否则不要直接从收藏跳到构建。构建简报应包括用户问题、证据、最小可用产物、负责人、时间限制、成功指标、安全边界和停止条件。

### 模块 5：创始人知识产权重组

**目的：** 将运营者自己经过验证的框架、笔记、决策和应用重新组合成独特的知识产权。

规则：

- 将外部来源用作背景，而不是模仿材料。
- 将运营者的原创贡献与借鉴的概念区分开来。
- 引用思想渊源，并避免在未经核查的情况下声称具有新颖性。
- 优先采用有实践经验支持的重组方式。
- 仅在框架有助于决策或行动时才创建框架。

输出：组成概念、来源脉络、新组合、真正独特之处、现有证明，以及仍需验证的主张。

### 模块 6：服务产品套利

**目的：** 发现市场反复遇到的难题与运营者能够可信交付的能力之间的缺口。

交叉参照：

- 已收藏或高亮材料中反复出现的问题
- 用户关于实施阻力的笔记
- 已在内部或个人实践中得到验证的应用
- 公开市场上的替代方案
- 可获得时的付费意愿证据

根据痛点出现频率、紧迫性、交付优势、证明、实施成本和可逆性，对服务假设进行排序。不要使用私有客户数据，也不要仅根据关注度推断需求。通过访谈、预售或有限试点进行验证。

### 模块 7：内容负空间

**目的：** 找出运营者正在研究、应用或私下讨论，但尚未公开论述的、具有战略重要性的想法。

将私有主题与经用户授权的公开输出进行比较。将空白分类为：

- 尚未涉及但具有战略相关性
- 仅有浅层讨论但尚未解决
- 已在私下应用并有可信证明
- 相对于当前关注重点，公开讨论过多
- 不宜或尚不成熟，不适合发布

输出是一份内容机会地图，而不是自动发布队列。对于根据私有信息推断出的信念，在将其作为公开主张之前，必须获得明确确认。

## 节奏与触发条件

### 每周审查

当有足够的新证据时，进行一次精简的每周审查。建议包含以下部分：

1. 注意力漂移
2. 确信度变化
3. 候选决策
4. 最有力的矛盾
5. 一项构建或实验
6. 一个可选的内容空白机会
7. 未解决的问题与数据缺口

如果变化很少，如实说明。不要为了追求新意而凭空制造内容。

### 事件触发式审查

当发生以下任一情况时，进行一次聚焦审查：

- 出现一组可配置的、彼此相关的高强度信号
- 某条笔记明确提及一项待定决策
- 某个来源被标注、应用或衡量
- 矛盾证据超过配置的阈值
- 重大策略事件改变了决策背景
- 用户请求进行决策法庭评审或生成构建简报

**不要**每六小时或按照其他任意的日内定时器进行综合分析。高频摄取数据或许可以接受，但综合分析应每周进行或由事件触发，以避免噪声、递归式摘要和虚假的紧迫感。

## 连接器安全

对每个连接器应用最小权限和数据最小化原则：

- 优先使用只读权限范围
- 仅请求必需的集合和字段
- 将凭据保存在密钥管理器或受保护的环境变量中
- 绝不将令牌放入提示词、笔记、日志、代码仓库或生成的输出中
- 对传输中和静态存储的数据进行加密
- 将原始私密记录与派生产物分开存放
- 在每一项输出中强制执行各个来源的隐私标签
- 如果个人数据并非分析所必需，则在调用模型前对其进行脱敏
- 记录访问和派生事件，但不记录敏感内容
- 支持删除、撤销授权和重新同步
- 当授权或数据血缘检查失败时，默认拒绝操作
- 发布、发送内容或修改外部系统时，必须获得明确批准

当连接器不可用时，报告这一缺口。不要悄然使用旧的综合分析结果替代实时来源数据。

### 每周信号简报

```markdown

**Sources:** <source types, counts optional>
**Panel threshold:** 90

## Executive decision signal
<one source-grounded pattern and why it matters>

## Attention vs conviction
| Theme | Attention | Conviction | Direction | Evidence |
```

## 生命周期

对每条进入正式流程的建议采用明确的生命周期：

1. **已观察** — 记录主要信号并去重。
2. **已推断** — 创建包含反证的临时主张。
3. **已审查** — 完成专家小组和隐私检查。
4. **已提议** — 起草决策、测试或构建产物。
5. **已接受或已拒绝** — 用户明确给出处置意见。
6. **测试中** — 正在开展有明确边界且设有指标的行动。
7. **已验证、已修订或已停用** — 根据结果更新主张。
8. **已归档或已删除** — 应用保留策略；仅在允许的范围内保留溯源关系。

绝不要让建议在没有负责人和审查日期的情况下无限期保持“活跃”状态。

## 验证清单

交付任何结果之前，请验证：

- [ ] 审查具有明确的时间范围和受众。
- [ ] 关注度和确信度分别评分。
- [ ] 保存和书签被视为弱信号。
- [ ] 强主张以阅读、重点标记、笔记、决策、应用或可衡量的结果为依据。
- [ ] 每项实质性主张都链接到主要来源 ID。
- [ ] 派生产物未被递归计为证据。
- [ ] 私密的推断性信念已添加标签和置信度评级，并从可共享输出中排除。
- [ ] 已考虑反证和其他可能的解释。
- [ ] 已显示专家小组阈值；默认值为 90。
- [ ] 建议与决策相关、边界明确且可衡量。
- [ ] 遵守连接器权限和隐私标签。
- [ ] 输出中不包含凭据、原始私密语料库、客户数据或不必要的个人数据。
- [ ] 外部写入或发布需要明确批准。
- [ ] 每个进入正式流程的项目都有负责人、状态和审查日期。

## 常见陷阱

1. **书签占卜：** 根据保存行为推断确信度。解决方法是使用信号强度阶梯，并寻找更强的参与证据。
2. **内容优先偏差：** 将每个聚类都转化为一篇帖子。解决方法是先说明决策或实验。
3. **递归置信：** 将先前的摘要视为佐证。解决方法是沿溯源关系追踪到主要来源 ID，并拒绝循环引用。
4. **连贯叙事越界：** 尽管证据薄弱，仍对有说服力的叙事给予较高评价。解决方法是分别对来源质量和反证进行评分。
5. **监控式框架：** 分析同意授权的用户以外的其他人。解决方法是将系统限制为仅使用用户授权的个人来源。
6. **私密信息泄露至公开渠道：** 发布推断性信念或原始笔记。解决方法是使用隐私标签并要求明确的发布批准。
7. **定时器驱动的噪声：** 因为数据摄取频繁而频繁生成摘要。解决方法是采用每周一次并结合事件触发的综合分析。
8. **永久性建议：** 让过时的建议持续保持活跃。解决方法是设置生命周期状态、负责人、审查日期和停用规则。
