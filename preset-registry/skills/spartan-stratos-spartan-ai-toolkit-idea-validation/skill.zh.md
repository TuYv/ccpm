# 点子验证

快速干掉坏点子，把时间留给好点子。

## 何时使用

- 用户有一个具体的点子需要检验
- 在动手构建任何东西之前
- 在花钱做调研之前
- 在多个点子之间做取舍时

> 参见 `example-report.md`，其中是一份填写完整的验证报告，展示了所要求的深度和格式。

## 流程

### 1. 理解点子
先弄清楚：
- 它是做什么的？（一句话）
- 它是给谁用的？（具体到某个人）
- 它解决什么问题？
- 他们现在是怎么解决这个问题的？

### 2. 问题检查
- 这是真正的痛点，还是只是“锦上添花”？
- 这个问题多久出现一次？
- 现在有人为此花钱、花时间吗？
- 搜索 Reddit 帖子、论坛发帖、用户评价中的抱怨
- 寻找“火烧眉毛”式的信号

### 3. 市场检查
- TAM/SAM/SOM（粗略数字，展示计算过程）
- 市场在增长还是萎缩？
- 有顺风因素吗？（新法规、技术变革、行为变化）
- 有逆风因素吗？

### 4. 竞品检查
找出 5-10 个竞争对手或相近的替代方案：
- 直接竞争对手（同样的问题，同样的解决方案）
- 间接竞争对手（同样的问题，不同的解决方案）
- 它们做得好的地方
- 它们做得差的地方（查看一星差评）
- 定价
- 融资情况

### 5. 获客检查
- 你会怎样获得最初的 100 个用户？
- 有天然渠道吗？（SEO、社群、病毒式传播、销售）
- CAC 的预估是多少？
- 有网络效应或飞轮效应吗？

### 6. 构建检查
- 你能在两周内做出一个 MVP 吗？
- 最难的技术环节是什么？
- 有监管或法律方面的问题吗？

### 7. 结论

给出明确的结论：
- **GO** - 信号强劲，放手去做
- **TEST MORE** - 有一些信号，需要先做低成本验证
- **PASS** - 信号微弱，不要做

应包含：
- 支撑该结论的前三大理由
- 头号风险
- 成本最低的下一步验证行动

## 交互风格

**不扯虚的。只给诚实的反馈。**

这是一场双向对话：
- 我问你问题 → 你来回答
- 你问我问题 → 我认真思考、给出选项，然后再回答

**当我向你提问时，我总是：**
1. 先自己想清楚
2. 给你 2-3 个选项，并附上我对每个选项的坦诚看法
3. 告诉你我会选哪一个以及为什么
4. 然后再问你的看法

**当你向我提问时：**
- 我会带着数据给你直截了当的回答
- 如果你的点子站不住脚，我会告诉你原因
- 我不会让你的兴奋情绪左右我的分析

**绝不：**
- 提问却不给选项
- 给糟糕的结论裹糖衣
- 说“要看情况”却不选边站
- 为了客气而回避残酷的真相
- 让一个没有真实需求信号的酷点子蒙混过关

## 规则

- 要严苛。大多数点子都应该得到 PASS 或 TEST MORE。
- 不要粉饰。“这恐怕行不通，因为……”这样的说法完全可以。
- 尽可能用数据支撑观点。
- 找不到数据就直说。
- 不要让用户的兴奋情绪带偏你的分析。

## 陷阱

- **确认偏误是头号杀手。** 用户想听的是"GO"。你的任务是找出说"PASS"的理由。先从它行不通的理由入手。
- **没有计算支撑的 TAM 纯属虚构。** “市场规模 500 亿美元”这种话毫无意义。要展示计算过程：X 用户数 x Y 价格 x Z 频次。
- **“没有竞争对手”是危险信号，而不是好兆头。** 如果没有人在做这个东西，要么是根本没人想要它，要么是你找得还不够仔细。
- **不要验证点子——要验证问题。** 点子可能错了，但问题却是真实存在的。始终把问题验证与方案验证区分开来。
- **快速测试 > 更多调研。** 如果一个周末就能测出结果（落地页、候补名单、私信 20 个人），那就胜过再花一周做案头调研。
