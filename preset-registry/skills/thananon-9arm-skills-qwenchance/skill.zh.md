# 保持正轨

长时间的多步骤工作会以三种方式失败：**循环**、**过度思考**和**上下文耗尽**。在**每一步之前**运行以下检查清单。当某个触发条件命中时，直接执行对应的操作——不要犹豫斟酌。

## 每一步之前——先运行这个检查

| 检查项 | 触发条件为…… | 执行操作 |
|---|---|---|
| **陷入循环？** | 你即将重复某个操作（见下方信号） | 打破循环——从下方选择一种解决办法 |
| **过度思考？** | 你已推理超过约 1000 字却仍未行动 | 停下来。按当前的最佳决定行动，或向用户提出一个问题 |
| **上下文吃紧？** | 出现了低上下文提醒，**或** 2+ 个预算信号成立 | 完成这一步，然后交接 |

如果没有任何触发，就执行这一步。

## 1. 循环——检测并打破

如果以下**任意**一条成立，这一步就是一个循环：

- 你正在重新读取本次会话中已经读过的文件（且此后它**没有**发生变化）。
- 你正在用相同的参数重新运行某个命令/工具，并期待相同的结果。
- 你正在回到一个已经尝试过并放弃的假设。
- 你在没有新证据的情况下“从头重新考虑”。
- 最近 2 步没有获得任何新信息。

**重新读取你刚刚编辑过的文件不是循环**——那是在验证。

当循环触发时，**停下**，并只做以下一件事：

1. 用一句话说明阻塞点，并向用户提出一个具体的问题。
2. 写下你知道什么、不知道什么，然后采取一个与上次**不同**的操作。
3. 在同一个子问题上循环了 2+ 次？宣布它暂时无法解决；继续推进或交接。

永远不要重复一个失败的操作并指望得到不同的结果。

**重试上限：**绝不要第三次运行同一个失败的命令。尝试约 3 次（*哪怕是不同的尝试*）后仍无法让某个东西正常运行（命令、测试运行器、import）——停下，询问用户；不要硬磨更多变体。

**不要盲目编辑**——这是循环的头号来源。在编辑*之前*先读够内容，确认改动是正确的。每次编辑之后，在进入下一步**之前**验证它（读 diff / 运行它 / 运行测试）。一次编辑 → 一次检查。

## 2. 思考——保持在限度内

把推理限制在**每步约 1000 字**以内。超过这个限度，你就是在反复斟酌而不是行动。

- 决定 → 行动 → 观察。不要重新推导你已经做出的决定。
- 用了约 1000 字还做不了决定？说明任务规范不足——**向用户提出一个切中要害的问题**。
- 不要向自己复述整个问题。引用你已得出的结论；不要重建它。

## 3. 上下文预算——数信号，不要估算

**权威信号：**出现了关于上下文不足 / 即将自动压缩的 `<system-reminder>`。→ **立即交接**（第 4 节）。不要开始新的工作。

**否则，数一数以下各项现在有多少条成立：**

- [ ] 任务已进行 20+ 轮助手回合。
- [ ] 读取了 5+ 个文件，或任何一个巨大的文件/日志/转储。
- [ ] 有你需要不断往回滚动查看的长工具输出。
- [ ] 还剩 3+ 个计划步骤。

**数出成立的复选框数量，然后将数量映射到相应操作：**

- **数量为 0 或 1 → 继续**正常工作。
- **数量为 2、3 或 4 → 交接**——完成当前步骤，然后转到第 4 节。

先数数，再做决定——不要凭感觉判断。数量更高意味着上下文压力*更大*，而不是更小。正处于最后一步或“快要完成”**不会**降低数量，也不会取消交接。

在任何**高成本**步骤（大量读取、新的子任务、长文本生成）之前，先问：*“还有余量完成这件事、并且之后还能交接吗？”*如果计数结果表明需要交接，就完成当前的原子单元，然后交接——不要开始下一步。

## 4. 干净利落地交接

当上下文吃紧，或用户提出要求时：

1. **先把持久产物落地**——保存文件、提交、写出结果。确保不丢失任何东西。
2. **调用 `handoff` 技能**来压缩对话。不要手写交接内容。
3. 直截了当地告诉用户：“上下文开始吃紧——现在交接；请开启新会话（`/clear`）。”
