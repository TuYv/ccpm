# 视频内容引擎

将一个有据可依的源素材转化为最有价值且依据充分的内容组合。不要机械地制作固定数量的衍生内容。找出彼此不同的价值承诺，选择能够兑现这些承诺的格式，并让每项资产在内容组合中各司其职。

## 前言

如果可用，请运行仓库中保护隐私的版本检查和遥测初始化程序：

```bash
python3 telemetry/version_check.py 2>/dev/null || true
python3 telemetry/telemetry_init.py 2>/dev/null || true
```

远程遥测采用主动选择加入机制。绝不记录内容、URL、路径、凭据、姓名或业务数据。

## 声明执行约定

开始工作前，明确说明确切的源素材、所有者、频道、目标位置、请求的模块、交付格式、本轮产出物、停止条件以及已知的阻碍类别。

保持源素材只读。没有最新证据时，绝不声称已完成渲染、上传、预览、发布或质检。将绩效目标视为实验，而不是预测。

## 接受任何有据可依的源素材

接受公开或已获授权的 URL、上传的文件、本地文件、文字稿、音频录音或源文件夹。对于诸如 `run this skill on this video` 这样未提供细节的请求，默认执行**诊断并提出建议**，而不是自动制作。

对于链接：

1. 确认确切页面、所有者、频道、标题、时长，以及可访问的媒体或文字稿。
2. 优先使用原始文件，其次是已获授权且可下载的母版，最后才是已发布的流媒体。
3. 绝不替换为镜像、其他上传版本、其他账号、其他单集或其他文字稿。
4. 如果身份验证、权限、DRM、媒体缺失或文字稿不可用导致无法进行有据可依的分析，请索取可访问的源素材。不要仅根据元数据提出编辑建议。

除非请求进行制作，否则应返回一份简报，其中包括源素材评分、推荐的编辑与执行模式、机会数量、首批发布内容、修复项与依赖项、制作复杂度、内容组合中的职责，以及开始制作所需的批准。

## 清点源素材

1. 在可用时记录路径或 URL、大小、时长、媒体流和 SHA-256。
2. 制作能够区分说话者且带有时间戳的文字稿。对照源素材修正姓名、产品名称和数字。
3. 构建：
   - 一份主张台账，将结果、估算、轶事、预测和目标区分开来；
   - 一份权利台账，记录第三方媒体、徽标、授权同意、禁发期和赞助商；
   - 一份带有时间戳、观众、承诺、证据、张力、框架、回报、视觉素材、注意事项和依赖项的内容原子清单。
4. 阅读 [references/opportunity-routing.md](references/opportunity-routing.md)，为可行的内容原子评分，并记录入选和被拒绝的机会。

机会清单是唯一可信来源。根据源素材能够支撑的内容数量提出建议；不要默认采用固定配额。

## 选择转化方式

阅读 [references/quality-gates.md](references/quality-gates.md)。分别从 0–20 分评估钩子、清晰度、证据、节奏和回报。

选择破坏性最小的编辑模式：

1. **润色** — 删除错误、无效停顿和技术干扰。
2. **精简** — 在保留结构的同时删除重复内容和离题内容。
3. **重构** — 重新设计冷开场、调整证据位置、重排各部分并衔接内容缺口。
4. **重制** — 添加补拍内容、旁白、演示或图形，以创作出实质上全新的作品。

对于精简、重构或重建，在最终剪辑前创建与源内容精确对应、带单词级或句子级时间戳的转录稿。备忘录中的时间戳仅作为章节指引，绝不能直接作为剪切点。

阅读 [references/format-modes.md](references/format-modes.md)。选择一种主要模式和理由充分的辅助模块。如果未指定模式，默认采用**作品集审计**，并推荐规模最小但有实际作用的发布批次。

## 锁定作品集主线

写出：

`[Viewer] should believe [verdict] because [proof], then use [framework] to reach [outcome].`

为每个选定素材分别指定一个承诺、受众、平台、任务、回报、父级内容、目标去向和包装意图。拒绝承诺重复、节选不完整、缺乏依据的主张，以及无法独立成立的素材。

## 制作选定模块

### 长内容

渲染前创建剪切/重排图和 EDL。根据精确转录稿定位片段，并确保片段从完整观点开始、到完整观点结束。运行：

```bash
python3 scripts/audit_edit_boundaries.py \
  --transcript <exact-source-transcript.json> \
  --clips <retained-clips.json> \
  --output <boundary-audit.json>
```

渲染后，转录母版并审查每个衔接点。记录左侧尾部、右侧开头、转场、判定和修复方式。技术解码不能取代语义审查。将之前的渲染结果保留为带版本号的文件。

### 中等长度内容

围绕一个框架、案例研究、问题、论点或演示，制作可独立成立的 3–12 分钟视频。为每个视频提供独立的钩子、背景、证据、回报、包装和目标去向。

### 短内容和微内容

仅使用完整内容单元制作 15–90 秒的竖屏素材。从钩子开始，保留主张的上下文，以 1080×1920 渲染，包含内嵌字幕和 SRT，并以回报或有价值的问题结尾。

仅在能够如实引导受众时，制作 6–20 秒的预告片、钩子测试、故事单元、付费广告精简版或动态引语。单独标记推广类片段。

### 字幕和开场处理

除非用户选择不使用，否则母版默认采用清晰易读的内嵌字幕，并附带匹配的 SRT。验证字幕提示按时间单调递增且互不重叠、最多两行、边距适合移动端，并确保字幕提示的结束时间不晚于母版结束时间。

除非需求说明要求干净的开场，否则默认在前三秒使用经过设计的钩子叠加层。强化口头表达的承诺，但不要夸大主张。检查其是否与字幕、下三分之一字幕、章节卡片和限定说明发生冲突。主张限定说明的优先级最高。

### 轮播内容和文字衍生内容

当相应格式有助于理解或分发时，制作滑动叙事、新闻通讯、文章、帖子、帖子串、节目说明、检查清单或摘要。必须使用已提供的品牌素材，否则采用中性视觉系统；绝不能凭记忆重建人物、吉祥物、徽标或身份形象。

## 包装每项素材

- **长内容：**标题、缩略图说明、冷开场、前 30 秒承诺、描述、章节、置顶评论和结束画面。
- **中等长度内容：**浏览/搜索标题、封面、开场语、系列标签、描述和父级内容导流路径。
- **短内容/微内容：**首帧视觉、口播钩子、标题、封面、帖子文案、评论引导语和 CTA。
- **轮播内容：**封面承诺、滑动推进结构、配文、CTA、末页、来源和替代文本。

创建关于内容承诺的假设，而不是表面修饰性的变体。拒绝采用无法兑现其承诺的包装方案。

## 规划分发并控制副作用

盘点有充分理由使用的 B-roll、截图、引用、图表、下三分之一字幕、限定说明、章节卡、叠加层、字幕、画面推近、音乐、声音设计、补拍镜头、旁白、赞助商植入和片尾画面衔接。定义各元素发生冲突时，应由哪个视觉层让位。

如有要求，生成发布规划图，其中包括顺序、间隔、平台、路径、时效性内容与常青内容的状态、内容蚕食警告以及重新剪辑窗口。

未经明确批准和权威复核确认，绝不得发布、排期、上传、更改共享设置、消耗配额或启动营销活动。

## 收敛、交付并学习

应用 [references/quality-gates.md](references/quality-gates.md)。确认来源完整性、内容组合一致性、媒体解码与时序、剪辑边界、渲染后的衔接、字幕、叠加层、内容声明、权利、包装方案和交付文件。

`technical integrity does not equal a coherent edit`

阅读 [references/delivery-contract.md](references/delivery-contract.md)，生成其中规定的模块化文件夹和清单，然后运行：

```bash
python3 scripts/validate_delivery.py --root <delivery-folder>
```

返回评分、模式、机会数量、内容组合图、运行时长、交付包、来源、输出、QC、经验证的目标位置、发布状态，以及 24 小时、72 小时和七天的衡量计划。只有在可比结果多次重复出现后，才能将某项发现提升为经验。
