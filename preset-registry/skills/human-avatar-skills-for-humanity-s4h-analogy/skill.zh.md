# 类比

将类比推理应用于任何问题。诊断需要哪种类比处理方式，并应用正确的工具。

## 哪种工具适用

| 你需要…… | 工具 |
|---|---|
| 找出现有类比或隐喻失效的地方 | boundary-testing |
| 从完全不同的领域引入解决方案 | domain-transfer |
| 通过不同领域的视角处理问题 | perspective-shifting |
| 检验两种情境之间的结构对应关系 | structure-mapping |

## 路由决策

- **已经在使用某个类比，并希望对其进行压力测试** → boundary-testing
- **在某个问题上陷入困境，希望找到其他领域中解决过类似问题的人** → domain-transfer
- **需要来自不同领域专家的新视角** → perspective-shifting
- **想知道两种情境是否确实在结构上相似** → structure-mapping
- **不明确** → 先使用 structure-mapping（严谨地建立类比），再使用 boundary-testing（找出类比失效的地方）

**情境确认：** 在进行路由之前，确认具体的类比情境。用一句话说明你识别出的内容——正在考察的类比或问题，以及目标（压力测试、引入解决方案、转换视角或验证结构）——然后使用 `AskUserQuestion`：
- **问题：**“我的理解是：[用一句话概括类比情境和目标]。对吗？”
- **标题：**“情境确认”
- **选项：**
  - **是的——继续**——情境理解正确
  - **调整**——有一个要素不准确；用户会先进行纠正，然后你再继续
  - **重新表述**——实际情境与理解不同；先纳入修正内容，然后再继续

## 确认方向

诊断出适用的工具后，使用 `AskUserQuestion` 工具确认方向。动态构造问题，并包含你的诊断：

- **问题：**“我的判断是：**[诊断出的工具]**——[用一句话说明它为何适用]。你希望如何继续？”
- **标题：**“方向”
- **选项：**
  - **是的，运行该工具**——使用已提供的上下文立即执行诊断出的技能
  - **显示所有选项**——列出此类别中的所有技能，并为每个技能提供一句话说明
  - **快速版本**——如果当前情境存在更轻量的替代方案，则运行该方案
  - **重新诊断**——重新审视情境描述，以得出不同的判断

根据用户的选择继续。

## 边界测试

*在依赖某个类比之前，找出它失效的地方。*

明确说出该类比：A 类似于 B，因为[共同属性]。然后系统地检验比较的每个维度。对于每个共同属性：它是否确实成立？存在哪些差异？找出类比失效的维度，且这种失效会影响当前决策。类比会悄无声息地失效——当人们基于在相关维度上并不成立的映射做出决策时，危害就会发生。

**输出：** 类比映射（哪些成立、哪些不成立）、具体的失效维度，以及哪些决策不应依赖此类比。

## 领域迁移

*通过寻找结构相似性，从不相关的领域引入解决方案。*

指出问题的核心结构：在表面细节之下，这究竟属于哪一类挑战？寻找已经解决过结构相似问题的领域——这些领域通常可能完全不相关（例如，用生物学解决网络设计问题、用军事战略解决资源约束问题、用爵士乐解决即兴系统问题）。对于每个候选领域：其解决方案是什么？如何将其映射回原问题？

**输出：** 核心问题结构、具有已解决类比问题的候选领域，以及映射回原问题的具体解决方案。

---

## 视角转换

*通过一个完全不同领域的视角来处理问题。*

指出本领域——即默认采用的专业视角。然后选择 2-3 个截然不同的领域：当一位[生物学家 / 游戏设计师 / 城市规划师 / 等]审视这个问题时，会看到什么？真正运用每一种视角，而不是流于表面。目标是揭示从本领域内部无法察觉的假设。

**输出：** 按视角分别进行分析——每个领域注意到什么、质疑哪些假设，以及提出哪些本领域不会想到的解决方案。

---

## 结构映射

*识别两种情境之间深层的结构对应关系。*

列出情境 A 的各个要素。列出情境 B 的各个要素。对于 A 中的每个要素：B 中是否存在对应要素？要素之间的关系是否得以保留？检验这种映射是真正的同构，还是仅仅表面相似。表面相似无法经受深层结构的检验；真正的同构能够准确预测行为。

**输出：** 逐要素对应表、关系保留检查、关于该类比在结构上是否有效的结论，以及该映射所能预测的结果。
