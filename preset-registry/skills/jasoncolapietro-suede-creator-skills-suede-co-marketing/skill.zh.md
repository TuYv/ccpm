# Suede 联合营销

使用此 Suede 联合营销手册，识别可信赖的合作伙伴，并设计角色和价值交换明确、可衡量的联合营销活动。

## 开始前

**首先检查产品营销背景信息：**
如果 `.agents/product-marketing.md` 存在（或者，在较早的配置中，存在 `.claude/product-marketing.md` 或旧版文件名 `product-marketing-context.md`），请先阅读它再提问。使用该背景信息，并且仅询问其中尚未涵盖或与此任务具体相关的信息。

## 合作伙伴识别框架

### 1. 受众重叠分析

最佳合作伙伴与你拥有相同的受众，但不会争夺同一笔预算。

**理想合作伙伴特征：**
- 相同的买方角色，不同的问题解决方案
- 在工作流程中相邻（位于你的工具之前、之后或同时使用）
- 相似的公司阶段和客户规模
- 互补而非竞争

**识别合作伙伴的问题：**
- 你的客户已经在使用哪些工具？
- 他们在使用你的产品之前或之后会使用什么？
- 还有谁在向你的 ICP 销售？
- 客户最常请求哪些集成？

### 2. 合作伙伴评分标准

使用以下锚点，对每位候选合作伙伴在全部六项标准上按 1-5 分评分。评分依据用户或公开来源提供的证据；没有证据的标准记为 `?`，并将其列为待解决问题，绝不猜测。

| 标准 | 1 | 3 | 5 |
|----------|---|---|---|
| **受众匹配度** | 不同的买方，不同的问题 | 相同的买方，部分重叠 | 相同 ICP，相邻的工作流程步骤 |
| **受众规模** | 触达范围明显低于你方 | 同一数量级 | 在共享渠道上的触达范围达到或超过你方 |
| **品牌契合度** | 在与其关联前你会有所保留 | 中立；没有已知冲突 | 即使没有提示，你也会在自己的营销中提及他们 |
| **互动质量** | 有触达但没有可观察到的回应 | 有一定互动，但未经验证 | 在营销活动将使用的渠道中有已记录的互动表现 |
| **互惠潜力** | 没有可提供的同等价值 | 单向但可接受 | 双方交换等值的受众或资产价值 |
| **执行难易度** | 没有合作联系人，也没有过往联合营销 | 有联系人，但没有历史记录 | 既有合作团队，也有已落地的联合营销经历 |

**推进/淘汰规则：** 仅推进在**受众匹配度**和**互惠潜力**两项上都获得 **4+** 分的合作伙伴。低于该标准的对象应被报告为已评分并淘汰，并说明未达标的标准——不得悄然省略。

**候选名单上限：5。** 达到上限时，对这五个对象进行排序并报告；不得扩展名单。额外候选对象应列在一个名为“本轮未推进”的条目中。

### 3. 在哪里寻找合作伙伴

**集成生态系统：**
- 你现有的集成合作伙伴
- 同一应用市场类别中的工具
- 你的产品可接入的平台

**相邻类别：**
- 解决你之前环节问题的工具
- 解决你之后环节问题的工具
- 由相同角色使用但服务于不同工作流程的工具

**社区信号：**
- 谁赞助了相同的播客/新闻通讯？
- 谁在相同的会议上参展？
- 谁活跃于相同的社区？
- 你的受众会分享谁的内容？

**数据来源：**
- 使用 Crossbeam 或 Reveal 获取账户重叠情况
- 客户调研（“您还在使用哪些产品？”）
- G2/Capterra 中的相邻类别
- 提及你的工具及其他工具的招聘信息

## 联合营销活动类型

四大类别，以及每种形式的投入程度、潜在客户共享方式和最适用场景，见
[references/campaign-formats.md](references/campaign-formats.md)。每当选择活动形式时，都应打开该文件
——活动计划必须从该文件中命名其形式。

- **内容合作** —— 当双方都能产出内容，且两方受众都会阅读时。
- **网络研讨会与活动** —— 当目标是通过门槛表单获取潜在客户或进行教育时。
- **产品与集成营销** —— 当存在已上线的集成或共同客户时。
- **社区与社交媒体** —— 当目标是曝光或名单增长，而非销售管道时。

## 与合作伙伴共同构思活动

与特定合作伙伴进行头脑风暴时，请考虑：

### 1. 共同受众的关键时刻

- 哪些触发事件对双方受众都很重要？
- 哪些季节性时机与双方产品相契合？
- 哪些行业趋势会影响双方的客户群？

### 2. 组合价值主张

- 客户使用两个工具能够实现哪些单独使用其中一个工具无法实现的目标？
- 这种组合能够支持什么工作流程？
- 该集成解决了什么痛点？

### 3. 双方各自带来的独特资源

盘点双方在受众、内容专业能力、产品能力、品牌可信度和客户案例方面各自带来的资源，
并明确活动实际依赖的是哪项资源。

## 接触潜在合作伙伴

### 外联门槛（仅草稿，强制停止）

可以产出外联草稿；绝不发送外联信息。在交接时：停止，并分别用一行说明以下四个变量
——收件人、渠道、可见的发送身份、确切消息——声明结果仅为草稿，且尚未发送任何内容，
提供 **批准 / 修改 / 放弃** 选项，并等待用户选择。该门槛同样适用于与合作伙伴共享任何客户
或重叠数据。

### 冷启动外联模板

```
Subject: [Your Company] + [Their Company] co-marketing idea

Hey [Name],

I'm [Role] at [Your Company]. We [one-line description].

I noticed we share a lot of the same audience—[specific observation about overlap].

I have an idea for [specific campaign type] that could work well for both of us: [one-sentence pitch].

Would you be open to a quick call to explore?

[Your name]
```

### 为通话准备的内容

1. **账户重叠数据**（如可通过 Crossbeam/Reveal 获取）
2. **2-3 个具体活动创意**（而不只是“我们做点什么吧”）
3. **你的受众指标**（名单规模、流量、互动情况）
4. **过往合作案例**（证明你具备执行能力）
5. **明确诉求**（你希望对方提供什么、你将提供什么）

## 构建合作关系

### 需要达成一致的关键问题

- **潜在客户归属**：门槛表单/拆分（一个共享表单、约定的拆分方式、书面数据
  和同意条款）或各自保留（不共享名单——在数据条款达成一致前的默认方式）。从 `references/campaign-formats.md`
  选择的形式会说明其假定采用哪种安排。
- **推广承诺**：各方将采取哪些措施进行推广？
- **资源创建**：谁创建什么？谁负责批准？
- **时间线**：各阶段分别在何时进行？
- **成功指标**：将如何衡量成功？
- **后续合作**：如果效果良好，是否会继续开展更多合作？

### 简单联合营销协议大纲

1. **活动描述**：你们共同开展什么活动
2. **职责**：谁负责什么
3. **时间线**：关键日期和截止时间
4. **线索处理**：如何收集、共享和跟进线索
5. **推广**：双方各自的最低承诺
6. **品牌**：Logo 使用、审批流程
7. **成本**：谁支付哪些费用（如有）
8. **指标共享**：活动结束后将共享哪些数据

## 衡量联合营销成功

- 生成的线索（总量及每位合作伙伴的数量）
- 线索质量（MQL/SQL 转化率）
- 归因收入
- 受众增长（新增订阅者、关注者）
- 内容互动（浏览量、下载量、分享量）

基线和目标应来自用户当前的分析数据，而非通用
基准。仅报告双方同意共享的指标。

## 联合营销清单

### 合作伙伴识别
- [ ] 列出你的客户已经在使用的工具
- [ ] 检查 Crossbeam/Reveal 以了解账户重叠情况
- [ ] 按全部六项标准为候选方评分，并应用推进/放弃规则（上限 5 个）
- [ ] 调研其过去的联合营销活动

### 活动规划
- [ ] 就活动类型和目标达成一致
- [ ] 定义线索共享安排
- [ ] 分配职责和截止时间
- [ ] 设定成功指标

### 执行
- [ ] 创建共享资产（落地页、内容等）
- [ ] 协调推广排期
- [ ] 向双方团队说明沟通要点

### 活动后
- [ ] 与合作伙伴共享指标
- [ ] 复盘哪些方面有效/无效
- [ ] 讨论未来合作机会

## 输出格式

此技能返回两种交付物之一。逐字复制
[references/output-templates.md](references/output-templates.md) 中匹配的骨架——在编写任一交付物之前
先打开该文件。

**已评分的合作伙伴候选名单**必须包含：

1. 按排名列出的候选名单（最多 5 个），包含每个合作伙伴的全部六项标准评分
2. 已评分但被放弃的列表，列出每个候选方未通过的标准
3. 针对评分为 `?` 的任何标准列出的待确认问题
4. 本轮未推进的候选方
5. 推荐的第一步行动，并使用 `references/campaign-formats.md` 中命名的一种形式

**联合活动计划**必须包含：

1. 活动形式（使用形式参考中命名的形式）、目标及其唯一验证指标
2. 双方的价值交换
3. 各阶段的职责和时间线，每个阶段均包含负责人和审批人
4. 线索处理——设门槛/拆分，或各自保留自己的线索，并说明收集路径
5. 推广承诺、品牌审批和最高已批准成本
6. 包含已同意共享指标及复盘日期的衡量计划
7. 一行审批状态，说明尚未发送、发布或承诺任何内容

## 任务特定问题

1. 你是在寻找合作伙伴，还是在与特定合作伙伴规划活动？
2. 你最感兴趣的联合营销类型是什么？（内容、活动、集成、社区）
3. 你的受众规模是多少？（邮件列表、社交媒体关注者、流量）
4. 你是否有现有的集成合作伙伴？
5. 你以前做过联合营销吗？哪些方面有效/无效？
6. 你的联合营销时间线和预算是多少？

## 工具集成

此包不提供合作伙伴平台连接器。请使用已获授权的产品 UI、当前导出文件、API 或已安装的连接器，并且在读取或更改合作伙伴数据之前，核实提供商当前的官方文档。

根据营销活动选择能力：

- 具备最低群组规模阈值的、保护隐私的聚合账户重叠分析
- 合作伙伴记录、负责人、审批、承诺和交易登记
- 共享资产审阅、版本历史、截止日期和发布审批
- 特定来源的链接或代码，以及已达成一致的线索/收入归因
- 导出、删除、访问控制和审计历史要求

## 边界

- 未经双方证据支持，不得声称存在合作关系、受众重叠、背书、触达范围或已承诺的交付成果。
- 未经明确授权，不得联系合作伙伴、共享客户名单、签署条款、花费预算或发布联合成果。
- 不得代替各方决定所有权、许可、归因、线索共享或收入分成条款。
- 不得为证明重叠情况而暴露私有客户或合作伙伴数据；应使用获批的聚合或保护隐私的方法。

## 路由

- 需要推荐或联盟营销机制 -> 使用 `suede-referrals`。
- 需要发布节奏和发布资产 -> 使用 `suede-launch-packaging`。
- 需要联合创作的编辑规划 -> 使用 `suede-content-strategy`。
- 需要面向合作伙伴的宣传材料 -> 使用 `suede-sales-enablement`。
- 需要为联合发布公告获取赢得媒体报道 -> 使用 `suede-public-relations`。
- 从上述技能中，将合作伙伴选择和联合营销活动设计路由回 `suede-co-marketing`。
