# 转化文案写作——以数据驱动、促成转化的文案

> 使用 Joanna Wiebe 研究优先的客户之声方法，撰写让人说“是”的文案

## 何时使用此 Skill

- **撰写着陆页、电子邮件或销售页面**，且需要获得可衡量的转化结果时
- **开始一个新的文案项目**，需要一套系统化流程作为指导时
- **不知道该写什么**，只能盯着空白页面发愁时
- **希望通过数据支持的决策**向客户证明投资回报率时
- **通过验证和测试改进现有文案**时
- **使用专业的文案写作方法论培训自己或团队**时

## 此 Skill 的作用

此 Skill 将文案写作从猜谜游戏转变为系统化、数据驱动的流程。你不必再盯着空白页面等待灵感降临，而是会：

1. **先研究**——从客户的语言中寻找信息，而不是凭空想象
2. **多倾听，少写作**——让客户之声（VOC）数据承担主要工作
3. **发布前验证**——在全面投入之前测试文案
4. **衡量一切**——了解哪些内容有效以及为何有效

最终成果：能够促成转化的文案，因为它使用客户已经在使用的措辞，说出了客户真正想听的内容。

## 说明

### 三阶段流程概览

```
┌─────────────────────────────────────────────────────────────┐
│  1. RESEARCH & DISCOVERY  │  2. WRITE, WIREFRAME, EDIT  │  3. VALIDATE & TEST  │
│      (Biggest phase)      │      (Synthesis phase)      │   (Proof phase)      │
└─────────────────────────────────────────────────────────────┘
```

没有哪个阶段是可选的。即使客户说“直接写就行”，你仍然需要进行调研。

### 第 1 部分：调研与探索

> “如果调研不是工作中占比最大的部分，那么 99% 的情况下，都说明你的做法有问题。”

**目标**：从客户的语言中找到你的信息——不要凭空编造。

#### 调研清单

**内部来源：**
- [ ] 审查现有网站文案
- [ ] 产品页面和功能描述
- [ ] 销售通话文字记录/录音
- [ ] 客户支持工单
- [ ] 聊天记录
- [ ] 当前正在使用的电子邮件序列
- [ ] 宣传册和销售材料

**客户来源：**
- [ ] 客户调查（现有或新开展的）
- [ ] 感谢页面问卷
- [ ] 客户访谈（已转录）
- [ ] 评论挖掘（Amazon、G2、Capterra、Trustpilot）
- [ ] 社交媒体评论和讨论
- [ ] 论坛帖子和 Reddit 主题帖
- [ ] 客户证言和案例研究

**竞争来源：**
- [ ] 审查竞争对手网站
- [ ] 竞争对手评论（尤其是负面评论）
- [ ] 行业论坛和讨论

**分析数据来源：**
- [ ] 点击追踪数据
- [ ] 热力图和滚动深度图
- [ ] 转化漏斗分析
- [ ] 退出调查数据

#### 如何挖掘 VOC 数据

**要寻找的内容：**

1. **痛点语言** - 他们如何描述自己的问题？
2. **渴望语言** - 他们想要什么结果？
3. **异议语言** - 是什么阻碍了他们？
4. **触发语言** - 是什么促使他们开始寻找解决方案？
5. **价值语言** - 哪些收益对他们最重要？
6. **情绪语言** - 对上述所有方面，他们有何感受？

**如何整理：**
- 按类型标记每条洞察（痛点、渴望、异议等）
- 记录来源和出现频率
- 识别规律和反复出现的主题
- 按强度/情绪程度排序

### 第 2 部分：写作、线框设计与编辑

#### 写作准备

**Joanna 的分屏方法：**

1. 在屏幕左侧打开调研/VOC 数据
2. 在屏幕右侧打开写作文档
3. 在 VOC 数据中搜索相关关键词
4. 复制粘贴客户的原话
5. 将其打磨成文案（不要重新编造）

> “你不能只是坐在那里直接开始写。把屏幕一分为二，将人们所说的话放到页面上。”

#### 写作流程

**第 1 步：确定认知阶段**

你的读者目前处于哪个起点？

| 阶段 | 他们知道什么 | 标题写法示例 |
|-------|-----------|---------------------------|
| 无认知 | 一无所知 | 从问题/痛点切入 |
| 问题认知 | 他们知道自己有问题 | 强化问题 |
| 解决方案认知 | 他们知道存在解决方案 | 突出你的解决方案有何不同 |
| 产品认知 | 他们知道你的产品存在 | 证明你是最佳选择 |
| 高度认知 | 已准备购买 | 让优惠变得不可抗拒 |

**第 2 步：梳理信息层级**

需要呈现哪些信息，以及应按什么顺序呈现？

1. **核心信息** - 他们必须理解的一件事
2. **支持性信息** - 支撑核心信息的证据
3. **异议处理** - 解决阻碍他们行动的问题
4. **行动号召** - 明确的下一步行动

**第 3 步：选择框架**

| 框架 | 最适合 |
|-----------|----------|
| PAS（问题-激化-解决） | 短文案、对问题有高度认知的受众 |
| AIDA（注意-兴趣-欲望-行动） | 较长的销售页面 |
| PPPP（描绘-承诺-证明-推动） | 视觉型产品 |
| PASOP（问题-激化-解决方案-结果-证明） | 复杂的解决方案 |

**第 4 步：使用 VOC 起草文案**

获取原始 VOC 并进行转化：

**原始 VOC：**
> “电子表格让我非常抓狂。每个月，我光是核对数据就要花 8 个小时，但最后还是会发现错误。”

**转化后的文案：**
> “厌倦了每个月在电子表格数据核对上浪费 8 个多小时，结果却仍然会发现错误？”

#### 7 轮文案编辑流程

完成初稿后，按顺序进行以下几轮检查：

| 轮次 | 重点 | 关键问题 |
|-------|-------|--------------|
| **1. 清晰度** | 是否清晰？ | 12 岁的孩子能理解吗？ |
| **2. 语气** | 听起来对吗？ | 这是品牌或客户说话的方式吗？ |
| **3. 证明** | 可信吗？ | 证据在哪里？ |
| **4. 具体性** | 是否具体？ | 我能否加入数字、名称和细节？ |
| **5. 记忆点** | 是否令人难忘？ | 他们明天还能记住吗？ |
| **6. 情感** | 能否让他们产生感受？ | 情感钩子在哪里？ |
| **7. 归零** | 哪些内容可以删掉？ | 每个词都有存在的价值吗？ |

**清晰度永远是第一位的。** 最重要的是，文案必须清晰。

#### 线框图设计

创建一个可视化布局，展示：
- 每个信息区块的位置
- 带有注释的图片/视频占位符
- CTA 的位置和文案
- 移动端注意事项

工具：Figma、Balsamiq、Photoshop，甚至可以使用带方框的 Google Docs

### 第 3 部分：验证与实验

> “我们通过测试进行验证和学习。”

**目标**：确保在正式投入之前推出的是最佳版本。

#### 验证方法

| 方法 | 最适合 | 它能告诉你什么 |
|--------|----------|-------------------|
| **5 秒测试** | 标题、首屏区域 | 清晰度（而非说服力） |
| **UserTesting** | 完整页面体验 | 可用性、理解程度 |
| **Wynter** | B2B 信息传达 | 信息共鸣度 |
| **预览邮件** | 电子邮件文案 | 打开/点击行为 |
| **滚动/点击热图** | 软发布 | 互动模式 |

#### 尽可能进行 A/B 测试

每次测试一个变量：
- 标题
- CTA
- 主视觉图片
- 优惠结构
- 社会认同内容的位置

**注意**：你无法对所有内容进行 A/B 测试。验证可以填补其中的空白。

## 示例

### 示例 1：SaaS 落地页流程

**调研阶段（第 1 周）：**
- 采访了 5 位客户
- 挖掘了 50 条 G2 评论
- 分析了 10 个竞争对手的页面
- 查看了 20 条支持工单

**关键 VOC 发现：**
> “我被 Slack 通知淹没了。等我找到需要的消息时，已经浪费了 20 分钟，思路也被打断了。”

**信息层级：**
1. 主要信息：“几秒钟内找到任何消息，而不是花费几分钟”
2. 支持信息：由 AI 驱动，可跨所有频道进行搜索
3. 异议处理：“与你现有的 Slack 配合使用——无需迁移”
4. CTA：“开始免费试用”

**标题初稿：**
> “别再淹没在 Slack 消息里。几秒钟内找到任何消息。”

**经过 7 轮审校后：**
> “3 秒内找到任何 Slack 消息，而不是 20 分钟。”
> （增加了具体性，删去了不必要的词语）

**验证：**
- 5 秒测试：85% 的人理解了价值主张
- 与对照版本进行 A/B 测试：注册量提升 34%

### 示例 2：课程发布邮件序列

**调查中的客户原声（VOC）：**
> “我总是报名各种课程，却从来没有学完。每次在收件箱里看到又一封课程邮件，我都会感到内疚。”

**第 1 封邮件主题（问题感知阶段）：**
> “那门你从未学完的课程？不是你的错。”

**第 1 封邮件开头：**
> “你以前买过课程。一开始干劲十足。然后……就没有然后了。
>
> 那份内疚就躺在你的收件箱里。每一封来自课程创作者的邮件，都像是在提醒你，又有一件事没能坚持到底。
>
> 关键在于：这并不是意志力的问题。”

**转化说明：**
- 使用了“从来没有学完”这一原话
- 捕捉了客户原声中的“内疚”情绪
- 从问题过渡到解决方案的铺垫

## 检查清单与模板

### 写作前研究检查清单

```markdown
## Research Checklist for: [Project Name]

### Customer Voice Sources
- [ ] Customer interviews (min 3-5)
- [ ] Survey responses (min 50)
- [ ] Review mining completed
- [ ] Support tickets analyzed
- [ ] Sales call recordings reviewed

### Competitive Intel
- [ ] Top 3 competitors audited
- [ ] Competitor reviews analyzed
- [ ] Positioning gaps identified

### Internal Sources
- [ ] Existing copy audited
- [ ] Analytics reviewed
- [ ] Team interviewed (sales, support)

### Synthesis
- [ ] Pain points ranked
- [ ] Desires ranked
- [ ] Objections listed
- [ ] Key messages identified
- [ ] Messaging hierarchy drafted
```

### 从客户原声到文案的转化模板

```markdown
## VOC Translation for: [Page/Email Name]

### Raw VOC Quote:
"[Paste exact customer language]"

### Source:
[Interview / Review / Survey / Support ticket]

### Message Type:
[ ] Pain  [ ] Desire  [ ] Objection  [ ] Trigger  [ ] Value

### Transformed Copy:
[Your refined version]

### Placement:
[ ] Headline  [ ] Subhead  [ ] Body  [ ] CTA  [ ] Testimonial
```

### 7 轮审校工作表

```markdown
## 7 Sweeps for: [Asset Name]

### Sweep 1: Clarity
- [ ] Main message understood in 5 seconds?
- [ ] No jargon or insider language?
- [ ] Simple sentence structure?

### Sweep 2: Voice
- [ ] Sounds like the brand?
- [ ] Sounds like how customers talk?
- [ ] Consistent throughout?

### Sweep 3: Proof
- [ ] Claims backed by evidence?
- [ ] Testimonials/case studies included?
- [ ] Numbers and data where helpful?

### Sweep 4: Specificity
- [ ] Generic words replaced with specific?
- [ ] Numbers instead of "many" or "some"?
- [ ] Names, places, details added?

### Sweep 5: Stickiness
- [ ] Memorable phrases or hooks?
- [ ] Would reader recall this tomorrow?
- [ ] Any "quotable" lines?

### Sweep 6: Emotion
- [ ] Emotional trigger present?
- [ ] Reader can feel the pain/desire?
- [ ] Human, not robotic?

### Sweep 7: Zero
- [ ] Every word earns its place?
- [ ] Redundancies removed?
- [ ] Could be shorter without losing meaning?
```
