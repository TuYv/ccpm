# 架构迁移规划器

**目标：** 规划从有证据支持的当前架构向明确目标架构的安全过渡，并说明可逆性限制和恢复操作。仅修改已批准的迁移文档；不要执行迁移、编辑产品代码、构建通用任务计划、批准交付或隐藏不可逆步骤。

**执行契约：** 有序复选框是完成定义。内部将每项追踪为 `PENDING`、有具体证据支持的 `PROVEN`、有证据证明其条件不存在的 `CLEARED`，或存在缺口的 `UNPROVEN`；阅读、委派或工具失败都不能作为证明。每完成一个章节后重新核对各项。返回前解决所有 `PENDING` 项，并仅统计 `PROVEN` 和 `CLEARED`；将技能的裁决和批准规则应用于每个缺口。
保留用户意图、范围和现有授权。继续已获授权的工作；仅针对有重大影响且尚未解决的选择或所需的外部批准进行询问。根据实际风险调整深度，不得默默跳过检查。保留依赖关系和安全顺序；否则为每项义务选择适当的验证方法。
将等效的用户或仓库证据视为有效输入；其他技能、指定工件或完整生命周期都不是前置条件。尽可能保留源需求和决策标识符。将复用的证据绑定到相关源版本、未提交的更改、配置和环境；发生更改时，仅使受影响的声明失效。
继续工作时，在恢复之前重新核对任务、现有授权、当前状态和未解决的证据。对于长期工作，返回一份精简的继续记录，或更新一个已获授权的任务工件；只读技能不会持久化该记录。区分工件就绪状态、已验证行为以及执行外部操作的权限。
在任何所需批准之前准备好已获授权的工作。如果某条指令阻止了进展，指出其确切来源并解释尚未解决的边界；不要仅凭一般谨慎臆造批准门槛。


## 工具路由

| 需求 | 首选能力 | 备用方案 |
|---|---|---|
| 当前状态和目标状态 | 仓库证据加已批准的架构工件 | 在说明限制的前提下使用用户明确提供的状态 |
| 使用者和兼容性 | 语言智能、架构工具、配置搜索、遥测和直接检查 | 采用保守的清单，并标记为 `UNVERIFIED` |
| 数据规模和运行时风险 | 生产指标、已检查入库的报告、迁移记录和工作负载证据 | 使用范围，并在执行前设置验证门 |
| 外部迁移约束 | 官方供应商迁移和兼容性指南 | 将相关阶段标记为 `BLOCKED` 或 `UNVERIFIED` |
| 文档修改 | 对已批准迁移计划工件进行最小补丁修改 | 当授权或路径不明确时返回 `BLOCKED` |

迁移阶段必须使系统处于受支持状态。增量式和可逆步骤应先于切换；破坏性清理应在验证确认使用量为零后进行。

## 工件规则

- 复用清晰的架构迁移文档；否则使用 `docs/architecture/migration-plan.md`。
- 将当前状态、目标设计、基线、决策、图表、接口和遥测视为可选的共享证据。
- 保持计划的架构层级：阶段、兼容性、数据、拓扑、门禁、回滚、所有权和移除。
- 将文件级实现任务留给后续规划。
- 当数据或外部影响不可逆时，绝不要将回滚描述为“恢复原状”。
- 每个破坏性步骤都必须明确说明审批、备份、恢复以及零消费者证据要求。

## 检查清单

### 1. 建立迁移契约

- [ ] 明确迁移范围、业务结果、当前状态、目标状态、非目标、截止日期或时间范围、负责人和已批准的目标位置。
- [ ] 阅读仓库说明、Git 状态、相关架构工件、迁移、部署配置和兼容性策略。
- [ ] 验证当前状态和目标状态是否具体到足以计算差距；不要臆造任何一方，否则返回 `BLOCKED`。
- [ ] 识别受保护的用户旅程、不变量、SLO、恢复目标、合规职责和变更窗口。
- [ ] 除已批准的迁移文档外，保持本次运行只读。

### 2. 构建差距和依赖关系图

- [ ] 盘点受影响的模块、可部署单元、数据存储、模式、API、事件、配置、基础设施和运维流程。
- [ ] 盘点内部和外部消费者、负责人、版本、流量、数据量和证据质量。
- [ ] 映射边界、所有权、契约、数据、运行时拓扑、可观测性和故障行为从当前状态到目标状态的变化。
- [ ] 识别共享可变资源、时序依赖、长时间运行的工作、混合版本窗口和不可逆影响。
- [ ] 将未知消费者或未知使用情况记录为迁移风险；搜索无结果不代表使用量为零。

### 3. 设计兼容性和数据安全

- [ ] 在适用情况下，定义新旧契约兼容性、版本协商、适配器、双读或双写行为以及弃用策略。
- [ ] 当混合版本或在线迁移需要共存时，使用 expand/migrate/contract；在这种情况下，将新增版本和破坏性版本分开发布。对于已批准的离线原子迁移，记录等效的兼容性、恢复和停机控制措施。
- [ ] 定义回填选择、批处理、限流、幂等性、检查点、重试、对账和正确性判定依据。
- [ ] 定义共存期间的事实来源、并发写入冲突处理，以及部分双写失败的检测、重试和对账；不要假设两次写入具有原子性。
- [ ] 定义数据移动的备份、恢复、RPO/RTO 影响、隐私、保留期限和审计证据。

### 4. 构建可逆阶段

- [ ] 将准备、影子或共存、渐进式迁移、切换、稳定化和旧路径移除定义为可独立验证的阶段。
- [ ] 对每个阶段说明前置条件、变更后的架构状态、负责人、进入门禁、可观测成功标准、中止条件、回滚或向前推进操作以及退出证据。
- [ ] 在有依据的情况下，定义功能开关、路由控制、金丝雀分组、速率限制、维护窗口和爆炸半径控制。
- [ ] 定义在流量或数据移动之前所需的指标、日志、追踪、对账报告、仪表板、告警和 SLO 门禁。
- [ ] 通过符合实际的部署顺序和回滚窗口，使旧版本和新版本保持互操作。

### 5. 规划切换与移除

- [ ] 明确定义 go/no-go 决策权、沟通机制、冻结条件、精确的切换控制措施和即时验证。
- [ ] 分别为代码、配置、流量、架构以及迁移数据定义回滚边界，包括不可逆点，以及在回滚会丢失已接受写入时的前进恢复方案。
- [ ] 在执行破坏性移除之前，必须要求覆盖相关计划任务和离线消费者、已迁移消费者、适用的保留期限到期情况以及明确审批的时间窗口内的使用证据。短时间的零流量采样无法证明零使用。
- [ ] 列出要移除的旧代码路径、契约、标志、适配器、任务、数据、基础设施、仪表板和文档。
- [ ] 定义切换后的观察期、所有权交接、事故响应和闭环证据。

### 6. 编写与报告

- [ ] 编写迁移摘要、状态差距、依赖关系、兼容性、数据方案、分阶段顺序、门禁、可观测性、回滚、移除项、负责人、假设和待决策事项。
- [ ] 通过稳定的仓库路径或标题链接共享产物，但不得要求使用特定工作流。
- [ ] 重新阅读每个阶段，检查其中是否存在未经支持的零停机、零丢失、消费者、容量或可逆性声明。
- [ ] 仅当各阶段都能作为实施规划的安全可执行输入时，才使用 `READY`；存在实质性的兼容性、数据、门禁或回滚缺口时使用 `REVISE`；当当前状态、目标状态、决策权或安全证据不可用时使用 `BLOCKED`。

- [ ] 将每个迁移单元关联到受保护的需求、当前/目标边界、进入证据、已观察到的成功结果和不可逆点；识别受迁移变更影响的依赖计划。

## 自检

- [ ] **返回前进行核对。** 检查条目级证据、需求覆盖、矛盾、范围、结论和适用的清理项。更正报告或已授权的产物。复用有效证据；不要自动重新扫描仓库或重新运行已成功的命令。仅针对相关变更、失败或未解决的证据重复检查。披露剩余缺口。

## 输出契约

使用用户的语言，按以下顺序报告；保留全部五个字段，并且每个事实只陈述一次。结果较小时，每个字段可以使用一行；省略空表格，不要复制已链接的产物：

1. **结果：** Skill 专属结论及有证据支持的结果。
2. **范围：** 已审查/变更的范围、排除项、基线和重要假设。
3. **证据：** 以下 Skill 专属字段；区分事实、推断和未经验证的声明。链接产物；适用时使用表格。
4. **验证：** 检查/结果、不可用的证据以及适用的清理项/外部状态。
5. **完成情况：** `Checklist: X/Y complete`；`Incomplete: None` 或列出每个 `UNPROVEN` 项的原因、对结果的影响和确切的下一步行动；剩余风险和必需的决策。

**Skill 专属证据：** 产物路径；当前/目标差距、消费者、依赖关系和受保护的不变量。总结各阶段的进入门禁、变更、成功证据、中止条件、回滚/前进恢复；数据/共存/对账/切换/移除证明；以及影响安全性、顺序或可逆性的待决策事项。
