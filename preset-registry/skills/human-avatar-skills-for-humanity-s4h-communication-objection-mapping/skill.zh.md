# 沟通异议映射

预料之中的异议会让人觉得已得到妥善处理。意料之外的异议则会让沟通偏离正轨。两者的区别不在于异议的内容，而在于接收者是否感受到发送者已经对此进行了充分思考。一份在异议提出之前就回应了可能异议的提案，传递出严谨和尊重。反之，则表明发送者只从自己的角度进行了思考。

---

## 你的流程

**步骤 1：陈述提案**
清晰地写出提案——提出了什么请求、计划做什么，以及要求受众做什么（批准、提供资源、改变行为、改变看法）。

**框架检查：** 在继续之前，确认信息、受众和目标。用一句话陈述你识别出的内容——正在分析的实际提案、提案面向谁，以及要求他们做什么——然后使用 `AskUserQuestion`：
- **问题：**“我的理解是：[用一句话概括提案的框架、受众和期望达成的结果]。对吗？”
- **标题：**“框架”
- **选项：**
  - **是——继续**——框架正确
  - **调整**——其中一个要素有偏差；用户会先进行纠正，然后再继续
  - **重新设定框架**——实际情况与当前理解不同；纳入纠正内容后再继续

**步骤 2：列出受众群体**
谁会收到这条信息？不同角色和个人会有不同的异议。财务利益相关者对提案的异议，与工程负责人的异议在结构上有所不同，即使他们都说“这有风险”。

**步骤 3：为每个群体生成异议**
对于每个群体：考虑到他们关心什么、担忧什么，他们最可能提出的异议是什么？要具体——“他们可能会在成本问题上反对”过于模糊。“他们会认为 ROI 模型假设的使用模式与上一季度的数据相矛盾”才有用。

**步骤 4：对每项异议进行分类**
- **合理：** 异议提出了提案确实应该认真回应的真实问题。轻率否定会损害可信度。
- **无依据：** 异议源于误解、信息缺失，或提案已经回应过的假设。需要澄清，而不是让步。

**步骤 5：回应合理异议**
对于每项合理异议：诚实、直接的回应是什么？真诚地承认该问题，并有针对性地回应。不要假装问题不存在，也不要淡化其重要性——这些做法会被察觉。

**步骤 6：预先应对措施**
对于每项重大异议：是否可以在信息本身中加入某些内容，在不向异议让步的情况下削弱其影响？主动提出异议并预先应对，比受到质疑后再作回应更具可信度。

## 人工确认

在继续之前，使用 `AskUserQuestion` 工具。用 1–2 句话陈述你对当前情况的理解——正在分析什么，以及核心问题是什么——然后询问：

- **问题：**“我的理解是：[用 1–2 句话说明你的理解]。你希望如何继续？”
- **标题：**“范围”
- **选项：**
  - **完整分析**——完成所有步骤，并全程展示推理过程
  - **仅关键发现**——只输出结论，省略逐步细节
  - **仅列出三大异议**——只列出最可能造成阻碍的三项异议，省略完整映射
  - **重新设定框架**——当前理解有偏差；纠正后，分析将按照修正后的框架进行

根据他们的选择继续。如果用户重新表述了问题，请在进行任何分析之前纳入其修正。

## 注意事项

步骤 4 中的分类需要保持诚实。人们很容易将所有异议都归类为无根据——认为这些异议反映的是误解，而非合理的担忧。如果某项异议是合理的，而你却将其驳回，你就会在其他所有问题上失去可信度。

## 后续步骤

交付此输出后，使用 `AskUserQuestion` 提供下一步选项：

- **问题：**“异议已梳理。下一步做什么？”
- **标题：**“下一步”
- **选项：**
  - `/s4h-writing-argument`——构建直接回应每项已梳理异议的论点
  - `/s4h-communication-clarity-audit`——检查对异议的回应是否清晰
  - `/s4h-logic-argument-validation`——验证你将用于回应关键异议的论点
  - **完成**——收尾并综合整理目前为止的成果
