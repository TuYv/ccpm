# 所有权与生命周期

> **第一层：语言机制**

## 核心问题

**谁应该拥有这些数据，以及拥有多久？**

在修复所有权错误之前，先理解数据的作用：
- 它是共享的还是独占的？
- 它是短期存在的还是长期存在的？
- 它会被转换，还是只会被读取？

---

## 错误 → 设计问题

| 错误 | 不要只说 | 应该问 |
|-------|----------------|-------------|
| E0382 | “克隆它” | 谁应该拥有这些数据？ |
| E0597 | “延长生命周期” | 作用域边界是否正确？ |
| E0506 | “先结束借用” | 修改操作是否应该在其他地方进行？ |
| E0507 | “移动前先克隆” | 为什么要从引用中移出数据？ |
| E0515 | “返回拥有所有权的值” | 是否应该由调用方拥有这些数据？ |
| E0716 | “绑定到变量” | 为什么这是一个临时值？ |
| E0106 | “添加 'a” | 实际的生命周期关系是什么？ |

---

## 思考提示

在修复所有权错误之前，先问：

1. **这些数据在领域中扮演什么角色？**
   - 实体（具有唯一身份）→ 应拥有所有权
   - 值对象（可互换）→ 可以克隆/复制
   - 临时值（计算结果）→ 可能需要重构

2. **这种所有权设计是有意为之吗？**
   - 有意设计 → 在约束范围内解决
   - 意外形成 → 考虑重新设计

3. **修复症状还是重新设计？**
   - 如果是第 3 次尝试 → 上升到第二层

## 向下追溯 ↓

从设计决策落实到实现：

```
"Data needs to be shared immutably"
    ↓ Use: Arc<T> (multi-thread) or Rc<T> (single-thread)

"Data needs exclusive ownership"
    ↓ Use: move semantics, take ownership

"Data is read-only view"
    ↓ Use: &T (immutable borrow)
```

## 快速参考

| 模式 | 所有权 | 成本 | 适用场景 |
|---------|-----------|------|----------|
| 移动 | 转移 | 零 | 调用方不再需要数据 |
| `&T` | 借用 | 零 | 只读访问 |
| `&mut T` | 独占借用 | 零 | 需要修改 |
| `clone()` | 复制 | 分配 + 复制 | 确实需要一份副本 |
| `Rc<T>` | 共享（单线程） | 引用计数 | 单线程共享 |
| `Arc<T>` | 共享（多线程） | 原子引用计数 | 多线程共享 |
| `Cow<T>` | 写时克隆 | 修改时分配 | 可能需要修改 |

## 错误代码参考

| 错误 | 原因 | 快速修复 |
|-------|-------|-----------|
| E0382 | 值已被移动 | 克隆、引用或重新设计所有权 |
| E0597 | 引用比所有者存活更久 | 扩大所有者的作用域或重构 |
| E0506 | 在借用期间赋值 | 修改前结束借用 |
| E0507 | 从借用的值中移出数据 | 克隆或使用引用 |
| E0515 | 返回局部引用 | 返回拥有所有权的值 |
| E0716 | 临时值被丢弃 | 绑定到变量 |
| E0106 | 缺少生命周期 | 添加 `'a` 标注 |

## 反模式

| 反模式 | 为何不好 | 更好的做法 |
|--------------|---------|--------|
| 到处使用 `.clone()` | 掩盖设计问题 | 正确设计所有权 |
| 与借用检查器对抗 | 增加复杂性 | 与编译器协同工作 |
| 所有地方都使用 `'static` | 限制灵活性 | 使用适当的生命周期 |
| 使用 `Box::leak` 泄漏内存 | 内存泄漏 | 正确设计生命周期 |
