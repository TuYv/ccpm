# Suede 入门与激活

Suede 围绕经过验证的首次价值和与留存相关的激活来设计入门流程，而不是装饰性的清单或强制互动。在宣称用户获得“啊哈时刻”之前，先定义激活证据，消除不必要的摩擦，安排首次会话流程，并对整个路径进行埋点。

## 初步评估

**先检查产品营销背景：**
如果 `.agents/product-marketing.md` 存在（或者 `.claude/product-marketing.md`，又或者在较旧的设置中使用的旧版 `product-marketing-context.md` 文件名），请在提问前阅读。使用其中的背景信息，只询问尚未涵盖或与当前任务具体相关的信息。

在提供建议之前，先了解：

1. **产品背景** - 这是什么类型的产品？面向 B2B 还是 B2C？核心价值主张是什么？
2. **激活定义** - 什么是“啊哈时刻”？什么行为表明用户“理解了它的价值”？
3. **当前状态** - 用户注册后会发生什么？用户在哪些环节流失？你的目标激活率是多少？是否有区分留存用户和流失用户的队列分析？

## 核心原则

### 1. 缩短价值实现时间至关重要
移除注册与体验核心价值之间的每一个步骤。

### 2. 每次会话只有一个目标
让首次会话专注于一个成功结果。将高级功能留到之后再介绍。

### 3. 让用户行动，而不是展示给用户看
互动体验 > 教程。亲自完成操作 > 了解操作本身。

### 4. 进展会带来动力
展示进展。庆祝完成。让路径清晰可见。

### 默认拒绝的做法
以下是本技能不会产出的命名俗套，无论它们在演示中表现得多么出色：
- 在用户尚未进行任何产品操作之前就运行的模态产品导览。
- 横亘在用户与首次操作之间的“欢迎！让我们开始吧”插页。
- 将设置开关而不是价值行为作为清单项目。

## 定义激活

### 找到你的啊哈时刻

与留存相关性最强的行为：
- 留存用户会做而流失用户不会做什么？
- 哪个行为是未来互动的最早指标？

**按产品类型划分的示例：**
- 项目管理：创建首个项目 + 添加团队成员
- 分析：安装跟踪代码 + 查看首份报告
- 设计工具：创建设计稿 + 导出/分享
- 市场平台：完成首笔交易

### 激活指标
- 达到激活状态的注册用户占比
- 激活所需时间
- 激活所需步骤数
- 按队列/来源划分的激活情况

## 入门流程设计

### 注册后立即开始（前 30 秒）

| 方式 | 最适合 | 风险 |
|----------|----------|------|
| 产品优先 | 简单产品、B2C、移动端 | 空白状态带来的不知所措 |
| 引导式设置 | 需要个性化的产品 | 在创造价值之前增加摩擦 |
| 价值优先 | 带有演示数据的产品 | 可能让人感觉“不真实” |

**无论选择哪种方式：**
- 明确的单一下一步操作
- 没有死胡同
- 如果包含多个步骤，则显示进度

### 入门清单模式

**适用场景：**
- 需要完成多个设置步骤
- 产品包含多个待探索的功能
- 自助式 B2B 产品

**最佳实践：**
- 3-7 项（不要让人应接不暇）
- 按价值排序（最有影响力的优先）
- 从快速见效的操作开始
- 进度条/完成百分比——仅当剩余步骤就是激活路径时使用
- 完成时庆祝——应在激活事件发生时庆祝，而不是在两步设置完成时庆祝
- 提供关闭选项（不要困住用户）

### 空状态

空状态是引导用户上手的机会，而不是死胡同。

**良好的空状态：**
- 解释此区域的用途
- 展示有数据时的样子
- 提供清晰的主要操作，用于添加第一项内容
- 可选：预先填充示例数据

### 工具提示和引导式导览

**使用时机：**复杂的 UI、不言自明的功能、用户可能错过的高级功能

**最佳实践：**
- 每次导览最多 3-5 步
- 随时可以关闭
- 不要向回访用户重复展示

## 多渠道引导

### 电子邮件 + 应用内协调

**基于触发条件的电子邮件：**
- 欢迎邮件（立即发送）
- 未完成引导（24 小时、72 小时）
- 达成激活（庆祝 + 下一步）
- 功能发现（第 3、7、14 天）

**电子邮件应该：**
- 强化应用内操作，而不是重复这些操作
- 通过具体的 CTA 将用户带回产品
- 根据用户已执行的操作进行个性化

## 处理停滞用户

### 检测
定义“停滞”的标准（闲置 X 天、设置未完成）

### 重新吸引策略

1. **电子邮件序列** - 提醒用户产品价值，解决阻碍，并提供帮助
2. **应用内恢复** - 欢迎回来，让用户从上次中断处继续
3. **人工触达** - 对于高价值账户，进行个性化联系

## 衡量

### 关键指标

| 指标 | 描述 |
|--------|-------------|
| 激活率 | % 达到激活事件 |
| 激活耗时 | 首次获得价值所需的时间 |
| 引导完成率 | % 完成设置 |
| 第 1/7/30 天留存率 | 按时间范围计算的回访率 |

### 漏斗分析

跟踪每一步的流失：
```
Signup → Step 1 → Step 2 → Activation → Retention
100%      80%       60%       40%         25%
```

找出流失最大的环节，并重点关注。

## 输出格式

### 引导审核
针对每个问题：发现 → 影响 → 建议 → 优先级

### 引导流程设计
按以下顺序逐字输出这些标题：

**Activation Goal** — 该事件，以及支持它的留存证据，或填写“unverified”
**Flow** — 每一步对应一项，每项包含：触发条件、用户操作、成功信号、流失衡量
**Checklist Items** — 3-7 项价值操作（没有清单时省略该标题）
**Empty State Copy** — 按界面分别列出
**Email Triggers** — 每项对应的事件和延迟时间
**Metrics Plan** — 激活率、激活耗时、每一步的流失率

## 按产品类型划分的常见模式

| 产品类型 | 关键步骤 |
|--------------|-----------|
| B2B SaaS | 设置向导 → 首次价值操作 → 邀请团队成员 → 深度设置 |
| Marketplace | 完善个人资料 → 浏览 → 首次交易 → 重复循环 |
| Mobile App | 权限 → 快速见效 → 设置推送 → 习惯循环 |
| Content Platform | 关注/自定义 → 消费 → 创建 → 互动 |

## 实验想法

推荐实验时，请考虑测试以下方面：
- 流程简化（步骤数量、顺序）
- 进度与动机机制
- 按角色或目标进行个性化
- 支持与帮助的可用性

## 边界

- 当产品数据不可用时，不要臆造激活事件、留存相关性、队列结果或基准数据。
- 未经明确授权，不要更改产品流程、权限、通知、实验或分析。
- 不要仅仅为了改善局部指标，就增加阻力、强制邀请、过早设置付费墙或操纵性的进度机制。
- 不要替用户决定敏感数据收集、同意、无障碍或产品风险政策。

## 路由

- 在首次运行引导之前进行注册时，使用 `suede-signup`。
- 对于引导邮件序列，使用 `suede-emails`；对于升级时机，使用 `suede-paywalls`。
- 使用 `suede-ab-testing` 验证引导流程变更，并使用 `suede-analytics` 衡量激活。
