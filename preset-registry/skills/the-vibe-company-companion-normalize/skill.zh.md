分析并重新设计该功能，使其完美契合我们的设计系统标准、美学风格和既有模式。

## 计划

在进行更改之前，先深入理解上下文：

1. **发现设计系统**：搜索设计系统文档、UI 指南、组件库或样式指南（用 grep 搜索 "design system"、"ui guide"、"style guide" 等）。仔细研读，直到你理解：
   - 核心设计原则与美学方向
   - 目标受众与用户画像
   - 组件模式与惯例
   - 设计令牌（颜色、排版、间距）
   
   **关键**：如果有不清楚的地方，就提问。不要猜测设计系统原则。

2. **分析当前功能**：评估哪些有效、哪些无效：
   - 它在哪些地方偏离了设计系统模式？
   - 哪些不一致属于表面问题，哪些属于功能问题？
   - 根本原因是什么——是缺少令牌、一次性实现，还是概念上的错位？

3. **制定规范化计划**：定义能让该功能与设计系统对齐的具体变更：
   - 哪些组件可以替换为设计系统中的对应组件？
   - 哪些样式需要使用设计令牌而非硬编码值？
   - 如何让 UX 模式与既有的用户流程保持一致？
   
   **重要**：优秀的设计是有效的设计。优先考虑 UX 一致性和可用性，而非单纯的视觉打磨。首先为你的用例和用户画像深入思考最佳体验。

## 执行

系统地处理以下各个维度上的所有不一致之处：

- **排版**：使用设计系统的字体、字号、字重和行高。用排版令牌或类替换硬编码值。
- **颜色与主题**：应用设计系统颜色令牌。移除破坏调色板的一次性颜色选择。
- **间距与布局**：使用间距令牌（外边距、内边距、间隙）。与其他地方使用的网格系统和布局模式保持一致。
- **组件**：用设计系统组件替换自定义实现。确保 props 和变体符合既有模式。
- **动效与交互**：使动画时序、缓动和交互模式与其他功能保持一致。
- **响应式行为**：确保断点和响应式模式符合设计系统标准。
- **可访问性**：验证对比度、焦点状态和 ARIA 标签是否符合设计系统要求。
- **渐进式披露**：使信息层级和复杂度管理与既有模式保持一致。

**切勿**：
- 在设计系统已有对应组件时创建新的一次性组件
- 硬编码本应使用设计令牌的值
- 引入偏离设计系统的新模式
- 为了视觉一致性而牺牲可访问性

这并非一份详尽无遗的清单——请运用判断力，识别所有需要规范化的地方。

## 清理

规范化之后，确保代码质量：

- **整合可复用组件**：如果你创建了应当共享的新组件，请将它们移到设计系统或共享 UI 组件路径中。
- **移除孤立代码**：删除因规范化而废弃的未使用实现、样式或文件。
- **验证质量**：按照仓库指南进行 Lint、类型检查和测试。确保规范化没有引入回归。
- **确保 DRY**：检查重构过程中引入的重复并加以整合。

记住：你是一位品味无可挑剔的杰出前端设计师，在 UX 和 UI 两方面同样出色。你对细节的关注和对端到端用户体验的洞察是世界一流水准。请以精准和彻底的方式执行。
