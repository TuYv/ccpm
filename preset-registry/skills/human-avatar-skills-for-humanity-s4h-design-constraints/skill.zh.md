# 设计：设计约束

每个设计问题都有一个解空间——即所有能够满足需求的形式的集合。约束并非阻碍优秀设计的因素；正是约束对问题进行了足够精确的定义，使其得以解决。没有约束的问题就没有解决方案，因为它没有明确的形态。设计师的任务是完整理解约束集合：哪些限制确实不可改变，哪些只是可以调整的偏好，以及它们共同划定了怎样的开放空间。

克里斯托弗·亚历山大关于模式语言的研究明确阐释了这一点：每一种优秀的设计形式，都是对一组彼此张力作用的特定力量的回应。理解这些力量——它们要求什么、在哪里冲突、在哪里一致——正是设计师找到能够化解这些张力之形式的方法。乔纳森·艾维在苹果公司的方法与此类似：从最严苛的约束入手（制造公差、材料特性、散热），再让设计决策由此逐层展开。最严苛的约束往往最能催生创意。

此技能会梳理完整的约束集合，根据约束的刚性程度对其进行分类，揭示约束之间的相互作用，并确定在它们共同划定的边界内，富有成效的设计空间位于何处。

## 你的流程

**第 1 步：引出完整的约束集合**
列出所有已知约束。暂时不要分类或评判——只需逐一列举。包括：
- 技术约束（媒介或材料所允许的范围）
- 物理约束（尺寸、重量、空间、材料特性）
- 经济约束（成本、时间、资源）
- 监管或法律约束（必须满足的要求）
- 组织约束（团队、系统或流程所能支持的范围）
- 用户约束（用户能够理解、执行或接受的内容）
- 美学或品牌约束（必须与现有形式保持一致的内容）

**问题界定检查：** 在继续之前，确认设计情境和约束领域。用一句话说明你识别出的内容——正在设计的对象以及其中涉及的主要约束类型——然后使用 `AskUserQuestion`：
- **问题：**“我的理解是：[用一句话概括你对设计情境和约束的界定]。对吗？”
- **标题：**“问题界定”
- **选项：**
  - **是——继续**——问题界定正确
  - **调整**——有一处不准确；用户会在你继续之前予以纠正
  - **重新界定**——实际情况与你的理解不同；在继续之前纳入用户的纠正

**第 2 步：按刚性程度分类**
对每项约束进行分类：
- **硬约束：** 确实不可改变——物理定律、已签署的合同、技术上不可能实现的事项、具有约束力的法规
- **软约束：** 确实存在但可以协商——某人的偏好、可以更改的政策、惯例而非规则
- **假定约束：** 被表述为约束但从未经过验证——习惯、恐惧或来源不明的观念

对于每项软约束或假定约束，注明需要满足什么条件才能改变它。

**第 3 步：梳理约束之间的相互作用**
有些约束会相互叠加：两项约束结合在一起时所排除的空间，比其中任何一项单独作用时都要大。有些约束彼此冲突：它们无法同时得到完全满足，因此需要进行权衡。有些约束则是冗余的：满足其中一项便会自动满足另一项。

识别：
- **叠加约束对：** 共同排除某一类解决方案的约束
- **冲突约束对：** 产生权衡、需要做出设计决策的约束
- **冗余约束：** 满足其中一个约束时，另一个约束也随之自动得到满足

**步骤 4：找出最严格的约束**
最严格的真实约束是解集最小的约束。它决定了设计应从何处开始。它通常也是最具生成性的约束——因为它将范围缩小到实际可行的方案，并且常常指向在这些限制条件下独具可能性的方案。

找出最严格的约束或约束对。思考：如果完全接受这一约束，并将其视为一项设计要求，设计会是什么样子？

**步骤 5：绘制解决方案空间**
根据硬约束集合，描述仍然开放的范围。哪些类别的解决方案是可行的？在这一范围内有哪些变化维度？最有趣的子区域在哪里——是存在多个可行方向的区域，还是约束以富有生成性的方式相互作用的区域？

## 人工确认

继续之前，使用 `AskUserQuestion` 工具。用 1–2 句话说明你对当前情况的理解——正在设计什么，以及哪些约束看起来最为重要——然后询问：

- **问题：**“我的理解是：[用 1–2 句话说明你的理解]。你希望如何继续？”
- **标题：**“范围”
- **选项：**
  - **完整分析**——完成所有步骤，并全程展示推理过程
  - **仅关键结论**——只输出最终结论，跳过逐步分析细节
  - **聚焦解决方案空间**——跳过单项约束分析，直接描述可行范围
  - **重新界定**——当前理解有误；请予以纠正，后续分析将依据修正后的框架进行

根据用户的选择继续。如果用户重新界定了问题，请先纳入修正内容，再进行任何分析。

## 备注

此技能与 `/s4h-constraint-hardness-testing` 密切相关，后者侧重于检验各项约束是否真实存在。设计约束更进一步：它将完整的约束集视为一个系统，并考察其共同定义了怎样的解决方案空间。当你需要质疑某个具体约束时，请使用硬度测试；当你需要了解完整的约束图谱如何塑造设计问题时，请使用此技能。

最常见的错误是把所有约束都视为同等严格，并以此为由不去探索实际上仍然开放的领域。在断定某一类解决方案不可行之前，先将硬约束与软约束区分开来。
