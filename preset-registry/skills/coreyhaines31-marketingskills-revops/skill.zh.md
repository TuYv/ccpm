# 收入运营

你是收入运营领域的专家。你的目标是帮助设计和优化相关系统，将市场营销、销售和客户成功连接成一个统一的收入引擎。

## 开始之前

**首先检查产品营销上下文：**
如果 `.agents/product-marketing.md` 存在（或者 `.claude/product-marketing.md`，又或者旧版设置中的旧文件名 `product-marketing-context.md`），请在提问前阅读它。使用其中的上下文，只询问尚未涵盖的信息或此任务特有的信息。

收集以下上下文（如果尚未提供，请询问）：

1. **GTM 模式** — 产品驱动（PLG）、销售驱动，还是混合模式？
2. **ACV 范围** — 平均合同价值是多少？
3. **销售周期长度** — 从首次接触到成交赢单需要多少天？
4. **当前技术栈** — 使用哪些 CRM、营销自动化、日程安排和数据丰富工具？
5. **当前状态** — 目前如何管理潜在客户？哪些方面有效，哪些方面无效？
6. **目标** — 提高转化率？缩短潜在客户响应时间？修复交接漏洞？还是从零开始搭建？

根据用户提供的信息开展工作。如果他们有明确的问题领域，就从那里开始。不要因为缺少输入而停滞——使用已有信息，并说明哪些补充信息可以让解决方案更完善。

## 核心原则

### 单一事实来源
为每个潜在客户和账户使用一个记录系统。如果数据存在于多个地方，就会产生冲突。选择一个 CRM 作为权威数据源，并将所有信息同步到其中。

### 先定义，再自动化
在构建工作流之前，先在书面层面明确阶段定义、评分标准和路由规则。对有缺陷的流程进行自动化，只会更快地产生有缺陷的结果。

### 衡量每一次交接
团队之间的每次交接都可能产生漏洞。从市场营销到销售、从 SDR 到 AE、从 AE 到 CS——每次交接都需要 SLA、跟踪机制，以及负责确保后续执行的人员。

### 收入团队协同
市场营销、销售和客户成功团队必须就定义达成一致。如果市场营销将某个对象称为 MQL，但销售团队不愿跟进，那么这个定义就是错误的。协同会议不是可有可无的。

## 潜在客户生命周期框架

### 阶段定义

| 阶段 | 进入标准 | 退出标准 | 负责人 |
|-------|---------------|---------------|-------|
| **订阅者** | 选择订阅内容（博客、新闻简报） | 提供公司信息或表现出互动行为 | 市场营销 |
| **潜在客户** | 已识别且具备基本信息的联系人 | 满足最低匹配标准 | 市场营销 |
| **MQL** | 达到匹配度与互动度阈值 | 销售在 SLA 内接受或拒绝 | 市场营销 |
| **SQL** | 销售接受并通过沟通完成资格判定 | 创建商机或重新进入培育流程 | 销售（SDR/AE） |
| **商机** | 已确认预算、决策权、需求和时间计划 | 成交赢单或成交丢单 | 销售（AE） |
| **客户** | 已成交赢单 | 扩购、续约或流失 | CS / 客户管理 |
| **推广者** | NPS 较高、积极推荐、参与案例研究 | 持续参与相关计划 | CS / 市场营销 |

### MQL 定义

MQL 必须同时满足**匹配度**和**互动度**要求：

- **匹配度评分** — 此人是否符合你的 ICP？（公司规模、行业、职位、技术栈）
- **互动度评分** — 他们是否表现出购买意向？（访问定价页面、申请演示、多次访问）

仅满足其中一项是不够的。一家完全符合条件但从不互动的公司不是 MQL。一个下载了所有电子书的学生也不是 MQL。

### MQL 到 SQL 的移交 SLA

明确响应时间并将其记录下来：
- 向指定销售代表发送 MQL 提醒
- 销售代表在 **4 小时**内（工作时间）联系
- 销售代表在 **48 小时**内完成资格认定或拒绝
- 被拒绝的 MQL 进入回收培育流程，并附上原因代码

**有关完整的生命周期阶段模板和 SLA 示例**：请参阅 [references/lifecycle-definitions.md](references/lifecycle-definitions.md)

## 线索评分

### 评分维度

**显性评分（匹配度）** — 他们是谁：
- 公司规模、行业、营收
- 职位、职级、部门
- 技术栈、地理位置

**隐性评分（互动度）** — 他们做了什么：
- 页面访问（尤其是定价、演示、案例研究页面）
- 内容下载、参加网络研讨会
- 邮件互动（打开、点击）
- 产品使用情况（适用于 PLG）

**负向评分** — 不符合资格的信号：
- 竞争对手的电子邮件域名
- 学生/个人电子邮件
- 退订、垃圾邮件投诉
- 职位不匹配（实习生、学生）

### 构建评分模型

1. 定义 ICP 属性并为其分配权重
2. 从已成交数据中识别高意向行为信号
3. 为每项属性和行为设置分值
4. 设置 MQL 阈值（在 100 分制中通常为 50-80 分）
5. 使用历史数据进行测试——该模型能否正确识别过去赢得的交易？
6. 上线、衡量效果，并按季度重新校准

### 常见评分错误

- 赋予内容下载过高的权重（调研 ≠ 购买意向）
- 未纳入负向评分（导致不合格线索通过）
- 设置后便不再调整（买家行为会发生变化；应按季度重新校准）
- 对所有页面访问给予相同评分（定价页面 ≠ 博客文章）

**有关详细的评分模板和示例模型**：请参阅 [references/scoring-models.md](references/scoring-models.md)

## 线索路由

### 路由方法

| 方法 | 工作原理 | 最适用于 |
|--------|-------------|----------|
| **轮询分配** | 在线索代表之间平均分配 | 区域条件相同、交易规模相近 |
| **基于区域** | 按地理位置、垂直行业或细分市场分配 | 区域团队、行业专家 |
| **基于账户** | 将指定账户分配给指定销售代表 | ABM 业务模式、战略客户 |
| **基于技能** | 按交易复杂度、产品线或语言进行路由 | 多样化产品线、全球团队 |

### 路由规则要点

- 首先路由到**最具体的匹配项**，然后再回退到通用匹配项
- 设置一个**后备负责人**——未分配的线索会迅速变冷，并浪费销售管道
- 轮询分配应考虑**销售代表的工作负荷和可用性**（PTO、配额完成情况）
- 记录每项路由决策，以便审计和优化

### 线索响应速度

响应时间是影响线索转化的最大单一因素：
- 在 **5 分钟**内联系 = 资格认定成功率提高 21 倍（Lead Connect）
- **30 分钟**后，转化率下降 10 倍
- **24 小时**后，线索实际上已经变冷

构建优先保障响应速度的路由规则。立即提醒销售代表。如果未达到 SLA，则进行升级处理。

**有关路由决策树和特定平台的设置**：请参阅 [references/routing-rules.md](references/routing-rules.md)

## 销售管道阶段管理

### 销售管道阶段

| 阶段 | 必填字段 | 退出条件 |
|-------|----------------|---------------|
| **已确认合格** | 联系信息、公司、来源、匹配度评分 | 已安排需求探索通话 |
| **需求探索** | 痛点、当前解决方案、时间表 | 需求已确认，演示已安排 |
| **演示/评估** | 技术要求、决策者 | 评估结果积极，客户已索要提案 |
| **提案** | 定价、条款、利益相关者关系图 | 提案已交付并完成审阅 |
| **谈判** | 修订意见、审批链、预计成交日期 | 条款已达成一致，合同已发出 |
| **成交** | 已签署合同、付款条款 | 已完成向 CS 的交接 |
| **未成交** | 失败原因、竞争对手（如有） | 已记录复盘结果 |

### 阶段规范

- **各阶段的必填字段** — 如果销售代表未填写必需数据，不允许其将交易推进到下一阶段
- **停滞交易提醒** — 标记在某阶段停留时间超过平均时长的交易（例如，平均天数的 2 倍）
- **跳过阶段检测** — 当交易跨阶段推进时发出提醒（已确认合格 → 提案，跳过需求探索）
- **预计成交日期规范** — 延期时必须说明原因；不得无理由静默延期

### 销售管道指标

| 指标 | 指标含义 |
|--------|-------------------|
| 阶段转化率 | 交易在哪个环节失败 |
| 阶段平均停留时间 | 交易在哪个环节停滞 |
| 销售管道速度 | 每天通过漏斗产生的收入 |
| 覆盖率 | 销售管道价值与配额之比（目标为 3-4 倍） |
| 按来源划分的赢单率 | 哪些渠道能产生实际收入 |

## CRM 自动化工作流

### 基础自动化

- **生命周期阶段更新** — 满足条件时自动推进阶段
- **交接时创建任务** — 将 MQL 分配给销售代表时创建跟进任务
- **SLA 提醒** — 如果销售代表未达到响应时间 SLA，则通知经理
- **交易阶段触发器** — 自动发送提案、更新预测，并在成交时通知 CS

### 从营销到销售的自动化

- **MQL 提醒** — 立即向获分配的销售代表发送包含潜在客户背景信息的通知
- **会议已预约** — 潜在客户通过日程安排工具预约会议时通知 AE
- **潜在客户活动摘要** — 每日汇总活跃潜在客户的高意向行为
- **重新互动触发器** — 沉寂的潜在客户再次访问网站时提醒销售人员

### 日历安排集成

- **轮询式日程安排** — 在团队成员之间平均分配会议
- **按条件路由** — 将企业客户线索分配给资深 AE，将 SMB 客户线索分配给初级销售代表
- **会前信息补充** — 在通话前自动填充 CRM 记录
- **未出席工作流** — 如果潜在客户未出席会议，则自动跟进

**有关特定平台的工作流方案**：请参阅 [references/automation-playbooks.md](references/automation-playbooks.md)

## 交易审批流程

### 何时需要交易审批团队

- ACV 高于 **$25K**（或你为非标准交易设定的阈值）
- 非标准付款条款（net-90、按季度计费）
- 采用定制定价的多年期合同
- 超出已公布档位的批量折扣
- 定制法律条款或 SLA

### 审批工作流层级

| 交易规模 | 所需审批 |
|-----------|-------------------|
| 标准定价 | 自动批准 |
| 10-20% 折扣 | 销售经理 |
| 20-40% 折扣 | 销售副总裁 |
| 40% 以上折扣或自定义条款 | 交易审核团队审查 |
| 多年期 / 企业级 | 财务 + 法务 |

### 非标准条款处理

记录每一项例外。跟踪哪些非标准条款最常被提出——如果所有人都要求同一项例外，就应将其纳入标准条款。每季度审查一次。

## 数据质量与数据补充

### 去重策略

- **匹配规则** — 以电子邮件域名 + 公司名称 + 电话号码作为主要匹配键
- **合并优先级** — CRM 记录优先于营销自动化系统；字段值以最近活动对应的记录为准
- **定期去重** — 每周运行自动去重，并人工审查边缘情况

### 必填字段强制执行

- 在每个生命周期阶段强制要求填写必填字段
- 如果字段为空，则阻止推进至下一阶段
- 使用渐进式信息收集——不要一开始就要求提供所有信息

### 数据补充工具

| 工具 | 优势 |
|------|----------|
| Clearbit | 实时数据补充，适合科技公司 |
| Apollo | 联系人数据 + 触达序列，潜在客户开发能力强 |
| ZoomInfo | 企业级，拥有最大的 B2B 数据库 |

### 季度审计检查清单

- 审查并合并重复记录
- 验证长期未更新的联系人电子邮件送达率
- 归档超过 12 个月无活动的联系人
- 审计生命周期阶段分布（查找瓶颈）
- 通过抽样数据集验证补充数据的准确性

## RevOps 指标仪表板

### 关键指标

| 指标 | 公式 / 定义 | 基准 |
|--------|---------------------|-----------|
| 潜在客户至 MQL 转化率 | MQL 数量 / 潜在客户总数 | 5-15% |
| MQL 至 SQL 转化率 | SQL 数量 / MQL 数量 | 30-50% |
| SQL 至销售机会转化率 | 销售机会数 / SQL 数量 | 50-70% |
| 销售管道速度 |（交易数量 x 平均交易金额 x 赢单率）/ 平均销售周期 | 因 ACV 而异 |
| CAC | 销售与营销总支出 / 新客户数 | LTV:CAC > 3:1 |
| LTV:CAC 比率 | 客户生命周期价值 / CAC | 3:1 至 5:1 为健康水平 |
| 潜在客户响应速度 | 从表单提交到销售代表首次联系的时间 | 理想值为 < 5 分钟 |
| 赢单率 | 已成交赢单数 / 销售机会总数 | 20-30%（因情况而异） |

### 仪表板结构

构建三个视图：
1. **营销视图** — 潜在客户数量、MQL 转化率、来源归因、单个 MQL 成本
2. **销售视图** — 销售管道价值、阶段转化率、销售管道速度、预测准确率
3. **高管视图** — CAC、LTV:CAC、收入与目标对比、销售管道覆盖率
