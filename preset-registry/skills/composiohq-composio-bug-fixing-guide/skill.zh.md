# Bug 修复指南

修复 Composio SDK 中 Bug 的标准实践。对于重大 Bug，务必添加回归测试。

## Bug 修复流程

### 1. 理解 Bug

- **复现问题** - 创建最小复现用例
- **确定根本原因** - 调试并追踪问题源头
- **检查现有测试** - 查看受影响代码是否已有测试
- **审查相关代码** - 检查其他位置是否存在类似问题

### 2. 修复 Bug

- **实施修复** - 以最小改动解决根本原因
- **避免范围蔓延** - 不要重构无关代码
- **遵循编码标准** - 与现有代码保持一致
- **本地测试** - 验证修复是否按预期工作

### 3. 验证修复（快速功能测试）

**可选但建议：** 在添加单元测试之前测试实际功能。

对于影响框架集成或实际使用场景的 Bug：

- 使用**临时 E2E 测试**快速验证修复是否能端到端正常工作
- 阅读 `ephemeral-e2e-sdk-tests` skill，了解快速验证设置
- 在 `.agent_cache/test-<bug-description>` 中进行测试（切勿提交这些内容）
- 示例：`.agent_cache/test-fix-openai-tool-execution`

### 4. 添加回归测试（重大 Bug 必须执行）

**关键要求：** 对于重大 Bug，务必添加测试以防止回归。

有关详细测试要求，请参阅 `.claude/rules/bug-fix-testing.mdc`：

- 在何处添加测试（TypeScript：`ts/packages/<package>/test/`，Python：`python/tests/`）
- 如何组织测试（TS 使用 Vitest，Python 使用 pytest）
- 测试命名约定和模式
- Mock 策略

**要点：**

- 将测试添加到受影响功能的**现有测试文件**中
- 测试应在**修复前失败**，在**修复后通过**
- 覆盖与该 Bug 相关的边界情况
- 提交前运行测试：`pnpm test`（TS）或 `make tst`（Python）

### 5. 记录修复内容

- **清晰的提交消息** - 说明修复了什么以及修复原因
- **引用问题** - 链接到 GitHub issue 或工单
- **更新文档** - 如果该 Bug 暴露出文档表述不清的问题
- **添加注释** - 在代码中解释不直观的修复

## 何时添加测试

**以下情况务必添加测试：**

- 逻辑错误和不正确的行为
- 边界情况和边界条件
- 竞态条件和异步问题
- 安全漏洞
- 数据损坏或丢失问题

**以下情况考虑添加测试：**

- 类型错误（如果 TypeScript/mypy 未捕获）
- 轻微的 UI/UX 问题
- 性能优化

**以下情况可以跳过测试：**

- 注释/文档中的简单拼写错误修复
- 格式或 lint 问题

## 测试资源

- **快速验证**：阅读 `ephemeral-e2e-sdk-tests` skill（在 `.agent_cache/` 中测试）
- **完整测试指南**：`.claude/rules/bug-fix-testing.mdc`
- **TypeScript 测试**：`ts/packages/<package>/test/`
- **Python 测试**：`python/tests/`
- **E2E 测试**：`ts/e2e-tests/`（用于运行时兼容性问题）

## 常见陷阱

- 只修复表象，而非根本原因
- 未针对重大 Bug 添加回归测试
- 破坏现有测试却未更新它们
- 将测试添加到新文件，而非现有文件
- 提交前未运行完整测试套件
