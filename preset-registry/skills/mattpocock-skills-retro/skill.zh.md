用户要求进行一次**回顾**。你需要提出改进编码代理**环境**的建议，以改进未来的运行。

## 步骤

1. 调用 `writing-for-agents` Skill，获取写作风格指南。

2. 阅读用户指定会话的主要来源。这可能意味着搜索此机器上的会话日志。如果用户未指定会话，则默认使用当前会话。

3. 在以下类别中寻找改进候选项。

- **导航**：代理找到正确文件的难易程度如何？文件之间是否存在隐藏依赖？添加**导航指针**是否会更容易？_适用情形：代理花费了很长时间才找到某条信息。_
- **自动化检查**：是否有自动化检查可以捕获代理所犯的错误？例如 lint、类型检查、测试、文件系统 lint 工具？_适用情形：代理犯了本可以通过自动化检查发现的错误。_
- **编码规范**：是否应向**审查代理**提供一条新的规则来执行？是否应删除或澄清现有规则？_适用情形：审查代理未能发现错误。_
- **全局 AGENTS.md**：是否应将某些指导说明从 AGENTS.md 移至编码规范（或自动化检查）中？_适用情形：仓库范围内或用户全局范围内的 AGENTS.md 文件特别庞大。_
- **工具经济性**：代理是否进行了代价高昂、但可以简化的工具调用？是否有特别消耗 token 的自定义工具（CLI、MCP）？_适用情形：代理进行了一次代价高昂的工具调用。_
- **无操作项**：检查指导文件中是否存在不会改变代理行为的指令。_适用情形：指导文件庞大且难以处理。_
- **信息访问**：是否有机会增加代理对信息的访问？例如转接开发服务器日志、提供对第三方服务的只读访问权限。_适用情形：代理无法获取某项关键的信息。_

4. 按严重程度顺序向用户展示这些候选项。

## 参考

### 实现与审查

请记住，所有工作都要经过两个阶段：实现和审查。实现代理承受的**上下文压力**最大。它们负责探索、编写代码以及调试失败。

审查代理承受的上下文压力最小——它会收到一个差异，因此无需进行探索。它通常也不需要编写代码或调试。

这意味着应由审查代理负责施加编码规范，而不是实现代理。

### 文件

你可以访问仓库中的以下文件：

- `CLAUDE.md`/`AGENTS.md`：这些文件会被推送到在此仓库中工作的任何代理的上下文窗口中。应极其谨慎地使用它们，通常只用于指向其他文件的**导航指针**。
- `CODING_STANDARDS.md`：审查期间会读取此文件，而非实现期间。如果规范文件超过 1,000 行，请向文档文件夹添加**导航指针**。
- 文档：将文档作为参考文件，并由其他文件指向它们。编写新文档前，请先查找现有文档。
- Skills：将 Skills 用于文档（因为其描述会进入代理的上下文窗口），或用于用户调用的命令。遵循 `writing-for-agents` Skill 中的建议。
