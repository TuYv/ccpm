# Basic Memory 图像

基于证据内容生成仓库视觉素材，并输出到规范路径。为保持兼容性，文件名和标记名称仍使用「infographic」，但 PR 生成以图像为先：场景、海报、绘画、照片、封面、场面、布置好的实物，或其他能够描述 PR 意图的编辑性视觉瞬间。PR 图像是非门禁性的 BM Bossbot 产物；变更日志和发布摘要图像则采用手动证据包工作流。

## 输出约定

- 基础输出目录：`docs/assets/infographics/`
- PR 图像：`docs/assets/infographics/pr-<number>.webp`
- 变更日志图像：`docs/assets/infographics/changelog.webp`
- 每周图像：
  - 始终采用 2 周回顾窗口：从上一个 ISO 周到当前 ISO 周（`start-week = current-week - 1`，`end-week = current-week`）。
  - 同一年份窗口：`docs/assets/infographics/<year>-w<start-week>-w<end-week>.webp`
  - 跨年份窗口：
    `docs/assets/infographics/<start-year>-w<start-week>-<end-year>-w<end-week>.webp`

## PR 模式

PR 模式使用 BM Bossbot 摘要块作为源材料。不要手动编写 PR 正文中不存在的陈述。

1. 获取 PR 正文：

```bash
gh pr view <number> --json body --jq '.body // ""' > /tmp/bm-pr-body.md
```

2. 生成规范资产：

```bash
uv run --script scripts/generate_pr_infographic.py \
  --pr-number <number> \
  --pr-body-file /tmp/bm-pr-body.md \
  --theme "<optional visual theme>" \
  --provenance-output /tmp/bm-infographic-provenance.md \
  --output docs/assets/infographics/pr-<number>.webp
```

如果 PR 正文包含托管的图像主题块，脚本会自动读取：

```markdown
<!-- BM_INFOGRAPHIC_THEME:start -->
<theme>
<!-- BM_INFOGRAPHIC_THEME:end -->
```

在消耗一次图像调用之前，先在本地测试提示词路径：

```bash
uv run --script scripts/generate_pr_infographic.py \
  --pr-number <number> \
  --pr-body-file /tmp/bm-pr-body.md \
  --theme "<optional visual theme>" \
  --output docs/assets/infographics/pr-<number>.webp \
  --print-prompt
```

`--dry-run` 是 `--print-prompt` 的别名；两者都会打印最终提示词，并在不调用 OpenAI 的情况下退出。

如果未提供主题，脚本会根据 PR 编号和 Bossbot 摘要，从下方的风格池中选择一个确定性的 BM 视觉方向。这样可以避免反复生成的 PR 图像都退化为同一种通用视觉效果。

生成图像时，还应通过 `--provenance-output <path>` 写入溯源信息。BM Bossbot 会使用以下标记将该托管块发布到 PR 正文中：

```markdown
<!-- BM_INFOGRAPHIC_PROVENANCE:start -->
...
<!-- BM_INFOGRAPHIC_PROVENANCE:end -->
```

溯源块会记录所生成资产的路径、图像模型、尺寸、质量、图像模式、主题来源以及选定的视觉方向。它刻意不将完整的生成提示词写入 PR 正文。此块仅用于调试和创意溯源；它不是合并门禁。

PR 图像仅提供视觉辅助。具有权威性的合并门禁是名为 `BM Bossbot Approval` 的 GitHub 提交状态。

## 变更日志模式

在编写提示词之前，先构建证据包：

- 差异事实来源：已合并 PR 的差异、合并提交或本地重建的差异
- 变更文件概览：`git diff --stat` 加上对关键文件的阅读
- 影响清单：与实际变更相关联的变更前/后结果
- 排除清单：具有误导性的标题、已还原的工作、仅重命名产生的变动、推测性的 TODO
- 选定的图像形式：海报、场景、情境画面、封面、绘画、照片、
  布置式实物作品或其他编辑性视觉瞬间
- 选定的 BM 风格类别：严格从下方选择池中选择一个类别

在起草提示词之前，请阅读以下参考资料：

- `references/prompt-blueprint.md`
- `references/style-balance.md`

阅读当前的 `CHANGELOG.md` 条目，并纳入最新的、有实际意义的
变更。

## 风格和类别选择

根据语义契合度，为每张图像严格选择一个 BM 风格类别。
视觉语言应具有辨识度且品味得当，同时保持商务可读性。

创建一种以图像为先、能够传达变更的视觉形式：海报、场景、
情境画面、封面图、绘画、照片、布置式实物作品或其他
编辑性视觉瞬间。地图、图表、档案、统计图和标签可以作为场景中的
道具出现，但不要制作文字密集的信息图。

BM 类别选择池：

- 计算机科学大学教材：SICP 风格图示、算法课程、
  编译器流水线、自动机、数据库系统、类型论、操作系统
- 经典文学题材：海上航行、哥特式庄园、狄更斯式城市地图、
  奥斯汀式社交关系图、图书馆页边批注、旅行日志
- 奇幻/D&D 风格：任务地图、地下城钥匙、公会账簿、魔法书、
  怪物图鉴、酒馆告示板；不得使用受版权保护的设定
- 音乐：金属、硬摇滚、朋克、Techno、灵魂乐、雷鬼乐队；不得使用流行音乐，不得
  直接使用乐队标志、专辑封面或音乐人肖像
- 科幻：受《星球大战》启发的仿作、接近《太空炮弹》风格的太空歌剧、舰队
  航线、任务控制台、违禁品清单；避免使用受版权保护的角色、
  标志或具名虚构宇宙
- 受野蛮人柯南启发的剑与魔法：神庙遗迹、沙漠路线、
  战旗、古代地图；不得使用具名角色的肖像
- 漫画书：期刊封面、跨页大图、动作分镜地图、说明文字框、
  网点效果的动感、整洁的拟声词排版
- 法国新浪潮电影：海报风格、鲜明的排版、城市路线图、
  跳切式编排、高对比度编辑摄影风格
- 二战宣传海报：后方公共信息海报语言、
  后勤箭头、配给图表、动员地图、大胆简化的人物形象；
  不得使用现实世界政党符号、仇恨图像、非人化口号或虚假
  历史主张
- 意大利电影海报：手绘戏剧感、醒目的演职员表、富有表现力的色彩、
  路线图拼贴、20 世纪 60 或 70 年代的电影活力；不得直接使用电影片名或
  演员肖像
- 莎士比亚：舞台地图、幕与场、剧中人物表、王室宫廷、
  后台提示单
- 希腊神话：神庙图示、星座路线、英雄之旅地图、
  神谕石板、迷宫、航海路线
- 黑色电影侦探板：案件档案、红线串联地图、打字机风格证据标签、
  警局墙面图表
- NASA 任务控制仪表板：发射时间线、遥测地图、轨道
  路线、状态板
- 太空探索与天文学：星空图集、天文台图表、
  星野地图、轨道力学图示、行星勘测路线、
  望远镜批注、任务轨迹、深空时间线
- 绘画：抽象画、古典风景画、受雷明顿启发的西部动作画、
  受伦勃朗启发的明暗对照、历史壁画、暴风雨海景、
  寓言式编辑绘画
- 经典黑白摄影：纪实现场报道、新闻编辑室
  档案照片、编辑摄影专题、街头摄影、高对比度
  暗房照片、样片、城市基础设施摄影
- 80 年代动作电影：实拍爆炸、烟雾弥漫的逆光仓库、霓虹城市
  街道、直升机探照灯、任务档案、英雄式剪影、
  高风险倒计时、手绘群像海报；不得直接使用演员肖像、
  真实电影片名、系列标志或经典台词
- 炼金术手稿：转化图示、带批注的符号、配方式
  流程图、装饰性页边图案
- 粗野主义城市规划：交通地图、混凝土标识、分区街区、
  基础设施图示

选择规则：

- 只选择一个类别；不要创建混合拼接的类别。
- 选择最合适的图像形式。相比文字密集的信息图，优先选择真实场景、海报、
  绘画、照片、场景造型或封面。
- 让隐喻与内容相匹配，但不要过度思考。类别是创意的
  催化剂，而不是语义约束。
- 采用精致的编辑渲染风格：平滑的抗锯齿
  文本、高对比度、清晰边缘、易读标签。
- 让类别通过易于理解的舞台化瞬间、
  编辑式构图、象征性环境、路线、物件或视觉
  隐喻来驱动构图。
- 保持结构足够直观，以帮助理解，但不要过于繁重而
  掩盖工程含义。
- 在布局、结构、调色板和视觉隐喻方面给予图像生成器创作自由。
  精确说明要展示什么内容，但对如何
  展示保持宽松。
- 不要使用受版权保护的角色、徽标或具名的虚构宇宙。应使用
  类型化暗示、仿作和原创构图。

## 内容优先的美学约定

含义必须易于理解，并具有清晰的层次结构。除此之外的一切都属于
创意空间：图像形式、布局、视觉隐喻、装饰元素、
色彩选择，以及特定类别的视觉语言。

层次结构：

1. 含义：必须清楚说明发布了什么、改变了什么，以及为什么重要。
2. 如果图像使用文本、标签、分区或证据要点，它们必须
   清晰易读。
3. 所选类别的视觉基因应当驱动构图，使其成为海报、
   场景、绘画、照片、场景造型、封面或象征性的物件组合。
4. 不要保守求稳。相比正确但乏味的图像，一张让人想要观看的
   视觉冲击力强的图像更好。

硬性规则：

- 内容分区和标签在出现时必须清晰易读。文本不能被
  装饰元素遮挡。
- 不要使用会与工程或商业含义争夺注意力的重设定文案。
- 每个提示词都必须包含清晰的图像优先构图指引：舞台化场景、
  海报构图、绘画、照片、象征性场景造型、主角物件、
  任务室、档案、物件、路线或视觉隐喻。
- 不要过度规定精确坐标或面板几何结构；提供构图
  骨架，并让模型围绕它进行构图。

## 生成

1. 将最终提示词写入临时 markdown 文件。
2. 使用共享图像辅助工具生成：

```bash
uv run --script scripts/generate_infographic.py \
  --prompt-file /tmp/bm-infographic-prompt.md \
  --output docs/assets/infographics/<name>.webp
```

3. 在报告成功之前，验证图像存在且清晰易读。

## 质量标准

- 讲述具体的前后价值变化，而不是模糊的改进主张。
- 确保工程师和非技术利益相关者都能理解。
- 出现文本时，使用通俗易懂的分区标题和标签。
- 包含清晰的视觉层次结构：标题、舞台化焦点、象征性场景、
  证据性道具或主角物件。
- 避免虚构事实；仅使用所提供的源材料。
- 优先呈现已发布的成果，而不是中间过程或已回退的工作。
- 通过高对比度、大小适宜的标签和整洁的
  布局来保持可读性。
