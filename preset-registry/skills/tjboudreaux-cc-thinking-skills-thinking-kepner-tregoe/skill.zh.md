# Kepner-Tregoe 分析

**核心规则：** 通过让候选原因同时对照 IS 与 IS-NOT 进行检验来诊断偏差；通过筛选 MUST 项、为 WANT 项加权、并在做出选择前揭示不利后果，来比较有重大影响的选择。

## 何时使用

- 某缺陷影响了部分对象、地点、时间或群体，却未影响其他可比的同类。
- 仍存在多个候选原因，且对比边界能够将它们区分开来。
- 某项有重大影响的选项抉择包含明确的不可让步条件、相互竞争的目标，以及需要以一致方式比较的风险。

## 何时不应使用

- 故障全面发生、不存在有意义的 IS-NOT 对比，或者原因已经确认。
- 一次低成本的观察即可定案原因，或某个选项明显全面胜过所有要求。
- 各项标准尚无法操作化；应先将其澄清，再分配权重。
- 任务是对计划中的变更进行前瞻性故障发掘，而非诊断或选项选择。

## 流程

1. **选择模式。** 针对偏离预期行为的偏差，使用问题分析（Problem Analysis）；针对选项之间的抉择，使用决策分析（Decision Analysis）。陈述目标，且不要将评分与因果证据混在一起。
2. **界定目标。** 对偏差：记录对象、缺陷、地点、时间、程度和影响。对选择：陈述决策事项、备选方案、约束条件和截止期限。
3. **问题分析——构建 IS/IS-NOT。** 针对 WHAT、WHERE、WHEN 和 EXTENT 各维度，记录 IS、最接近的可比 IS-NOT，以及 IS 一侧所独有的差异。列出首次发生附近的变化。
4. **问题分析——对候选原因做差异检验。** 从差异和变化中生成候选原因。只有能同时解释 IS 和 IS-NOT 的候选才能保留。执行成本最低的区分性检验；当某个已验证的原因能解释完整边界时即停止。
5. **决策分析——筛选与评分。** 在评分之前，先定义以通过/不通过判定的 MUST 项以及带权重的 WANT 项（重要性 1–10）。淘汰任何一项 MUST 未通过的选项；让幸存选项逐项对照各 WANT 打分，并按同一分值尺度计算加权总分。
6. **决策分析——检验下行风险与敏感性。** 针对领先选项，列出不利后果及其概率 × 影响，并找出会使排名逆转的假设或权重变动。不要让高总分掩盖灾难性的失败模式。
7. **做出决定或揭示缺口。** 返回已验证的原因或排名最高且可接受的选项、其背后的证据/评分、残余风险以及下一步验证。如果没有原因通过验证，或没有选项通过 MUST 筛选，则返回『未定/无』，而不是强行选出一个胜者。

## 输出

返回一份与模式对应的决策产物：

- **问题分析：** 问题陈述；带差异项的 IS/IS-NOT 矩阵；附近的变化；候选原因与边界的对照检验；已确认的原因或下一步区分性检验。
- **决策分析：** 决策陈述；备选方案；MUST 筛选；加权 WANT 矩阵；不利后果表；敏感性/逆转条件；选定的选项或无。

## 验证

- **证伪/终止：** 拒绝无法解释边界两侧的原因。若某个选择未通过某项 MUST、依赖于前后不一致的评分，或在某个此前被隐藏的合理权重/风险变动下落败，则拒绝该选择。
- **防止过度套用：** 对于显而易见的原因、琐碎的选择或一次性检查，跳过完整矩阵。当原因已获验证，或选项对已声明的利害程度而言足够稳健时，即行停止；多余的行只是走过场的形式。
