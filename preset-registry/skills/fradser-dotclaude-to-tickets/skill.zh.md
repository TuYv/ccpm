# 转为工单

将计划、规范或对话拆分为一组**工单**——采用曳光弹式垂直切片，每个工单都声明**阻塞**它的其他工单。如果规范包含 Gherkin 场景（来自 `/mattpocock:bdd`），则每个工单都应映射到一个或多个场景；这些场景是权威的验收标准。

你应该已经获得问题跟踪器和分诊标签词汇表——如果尚未获得，请运行 `/mattpocock:setup-matt-pocock-skills`。

## 流程

### 1. 收集上下文

基于对话上下文中已有的所有信息开展工作。如果用户通过参数传入了某个引用（规范路径、问题编号或 URL），请获取它并阅读其完整正文和评论。

### 2. 探索代码库（可选）

如果你尚未探索过代码库，请进行探索，以了解代码当前的状态。工单标题和描述应使用项目领域术语表中的词汇，并遵循与你所修改区域相关的 ADR。

寻找对代码进行预重构、以降低实现难度的机会。“先让变更变得容易，再完成这个容易的变更。”

### 3. 起草垂直切片

将工作拆分为**曳光弹式**工单。

<vertical-slice-rules>

- 每个切片都应沿着每一层（数据结构、API、UI、测试）贯穿一条狭窄但完整的路径——它应是垂直切片，而不是某一层的水平切片
- 每个完成的切片都可以独立演示或验证
- 每个切片的规模都应能在一个全新的上下文窗口中完成
- 任何预重构都应优先完成

</vertical-slice-rules>

## 关键要求：仅使用垂直切片

每个工单都应沿着每一层——数据结构、API、UI、测试——贯穿一条狭窄但完整的路径，其规模应能在一个全新的上下文窗口中完成，并且可以独立演示。大范围重构属于例外：应按扩展–收缩的方式安排，而不要强行将其塞入曳光弹式工单。

为每个工单提供其**阻塞边**——即必须先完成、该工单才能开始的其他工单。没有阻塞项的工单可以立即开始。

**大范围重构是垂直切片的例外。****大范围重构**是指一种机械式变更——例如重命名某一列、重新定义某个共享符号的类型——其**影响范围**会扩散到整个代码库，以至于一次编辑就会破坏数千个调用点，且任何垂直切片都无法在保持绿色状态的情况下落地。不要强行将其塞入曳光弹式工单；应按**扩展–收缩**的方式安排。首先进行扩展：在旧形式旁添加新形式，确保不会破坏任何内容。然后根据影响范围，将调用点分批迁移（按包、按目录）；每一批都作为单独的工单，并被扩展工单阻塞。由于旧形式仍然存在，因此应在各批次之间始终保持 CI 绿色。最后进行收缩：在不再有任何调用方后删除旧形式；该工单应被所有迁移批次阻塞。如果连单独的迁移批次也无法保持绿色，则仍然沿用这一顺序，但让它们共享一个集成分支，并全部阻塞最终的集成与验证工单——只要求该最终工单保持绿色。

### 4. 向用户提问确认

以编号列表的形式展示建议的拆分方案。对于每个工单，请展示：

- **标题**：简短的描述性名称
- **被阻塞于**：必须先完成的其他工单（如有）
- **交付内容**：该工单所实现的端到端行为

使用 AskUserQuestion 工具向用户发起测验，一次调用包含三个问题：
- “粒度是否合适？”——选项：刚刚好 / 太粗 / 太细
- “阻塞关系是否正确？”——选项：是的，它们确实存在 / 不正确，需要调整
- “是否还需要合并或进一步拆分某些工单？”——选项：不需要，继续 / 需要——通过 “Other” 指明具体工单

反复确认，直到用户批准该拆分方案。

### 5. 将工单发布到已配置的跟踪器

发布已批准的工单。具体**方式**取决于 `/mattpocock:setup-matt-pocock-skills` 所配置的跟踪器——无论使用哪种方式，工单本身都相同，只有阻塞关系的呈现形式不同：

- **本地文件** → 在 `.scratch/<feature-slug>/issues/<NN>-<slug>.md` 下为每个工单写入一个文件，按照依赖顺序从 `01` 开始编号（阻塞项优先）。每个文件中的“Blocked by”应列出其所依赖工单的编号/标题。使用下方的单工单文件模板——每个工单对应一个文件，绝不能合并到单个文件中。
- **真实的议题跟踪器（GitHub、Linear 等）** → 按依赖顺序为每个工单发布一个议题（阻塞项优先），以便每个工单的阻塞关系都能引用真实标识符。如果平台原生支持阻塞/子议题关系，请使用该功能；否则，将每个工单的“Blocked by”设置为相应的阻塞议题。除非另有指示，否则应用 `ready-for-agent` 分类标签——这些工单在设计上就是可由智能体直接领取的。

处理**前沿工单**：即所有阻塞项均已完成的工单。对于纯线性依赖链，这意味着从上到下依次处理。

不要关闭或修改任何父议题。
