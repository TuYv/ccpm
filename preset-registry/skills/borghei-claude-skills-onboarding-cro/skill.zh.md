## 首先澄清

在设计新用户引导之前，请确认以下信息。如果其中任何一项未知或含糊，请询问——不要自行假设：

- [ ] **产品类型** — B2B SaaS、B2C 应用、市场平台或内容平台（用于选择新用户引导模式）
- [ ] **激活事件（顿悟时刻）** — 与 30 天留存相关的操作（定义整个流程要推动用户达成的目标）
- [ ] **当前激活率及用户流失环节** — 确定基准，以及需要解决的最大漏斗瓶颈
- [ ] **第 1/7/30 天留存率** — 确定紧迫程度，并判断问题出在新用户引导还是产品与市场匹配度

停止规则：只询问对输出影响最大的 2–3 项。如果用户说“直接起草即可”，则继续执行，并在交付物顶部列出你的假设。

| 问题 | 重要性 |
|----------|---------------|

## 激活定义框架

### 找到顿悟时刻

顿悟时刻是指用户完成后，其留存可能性会显著提高的特定操作。它不是某项功能——而是用户体验到核心价值的时刻。

**识别方法：**

1. **同期群比较：** 比较 90 天留存用户与流失用户。留存用户在前 7 天内完成了哪些流失用户没有完成的操作？
2. **相关性分析：** 针对每个候选操作，计算在第 1 周完成该操作与第 30 天仍然留存之间的相关性。
3. **时机分析：** 留存用户何时完成该操作？（第 1 天？第 3 天？第 7 天？）

### 激活事件示例

| 产品类型 | 激活事件 | 有效原因 |
|-------------|-----------------|----------------|
| 项目管理 | 创建项目并邀请 1 名团队成员 | 协作会产生转换成本 |
| 分析工具 | 安装跟踪功能并查看第一份报告 | 看到自己的数据就是价值所在 |
| 设计工具 | 创作第一个设计并导出或分享 | 产出成果 = 实现价值 |
| CRM | 导入联系人并记录第一次活动 | 数据投入会形成锁定效应 |
| 交易平台 | 完成第一笔交易 | 完成交易 = 交付价值 |
| 内容平台 | 关注 3 个以上的信息源并浏览 5 条以上的内容 | 个性化会促进习惯养成 |
| 沟通工具 | 发送第一条消息并收到回复 | 激活双边价值 |

### 激活指标结构

```
Activation Rate = Users who reach activation event / Total signups
                  (within first N days)

Target: 40-60% activation within 7 days for B2C
        25-40% activation within 14 days for B2B
```

## 新手引导流程架构

### 流程类型选择

| 方式 | 最适合 | 风险 | 缓解措施 |
|----------|----------|------|------------|
| 产品优先（直接进入产品） | 简单产品、B2C、移动应用 | 面对空白界面时不知所措 | 预先填充示例数据 |
| 引导式设置（向导） | 需要配置的产品 | 在实现价值前增加操作阻力 | 最多保持在 3-5 个步骤 |
| 价值优先（立即展示结果） | 带有演示数据的产品 | 可能缺乏个性化体验 | 尽可能使用用户自己的数据 |
| 模板优先 | 创意/生产力工具 | 选择困难 | 精选 3-5 个入门模板 |
| 视频演示 | 复杂的 B2B 产品 | 用户会跳过视频 | 将时长控制在 90 秒以内 |

### 最初 30 秒法则

无论选择哪种流程类型，用户进入产品后的 30 秒内都必须：

1. 看到一个清晰且唯一的下一步操作（而不是 5 个选项）
2. 明白产品能为他们做什么
3. 看到明确的前进路径（没有死胡同）

### 流程设计原则

| 原则 | 实施方式 |
|-----------|---------------|
| 每次会话一个目标 | 首次会话只专注于让用户到达顿悟时刻 |
| 让用户动手，而非演示给用户看 | 用户亲自执行操作，而不是观看相关教程 |
| 进度会带来动力 | 展示推进情况（检查清单、进度条、庆祝提示） |
| 延后复杂内容 | 在激活之后再呈现高级设置和功能 |
| 始终可以退出 | 用户可以跳过或关闭任何新手引导元素 |
| 记住状态 | 如果用户离开后又返回，从上次中断的位置继续 |

## 价值实现时间工程

### 价值实现时间（TTV）缩短框架

TTV 是从注册到用户体验到核心价值之间所经过的时间。越短越好。

| 瓶颈 | 识别方式 | 解决方案 | 预计缩短 TTV |
|-----------|-----------|-----|----------------------|
| 使用前需要设置 | 用户在设置过程中流失 | 减少必需的设置步骤，使用默认值 | 30-50% |
| 等待数据 | 数据到达前无法体现价值 | 立即提供示例/演示数据 | 40-60% |
| 等待团队成员 | 需要协作才能体现价值 | 先让用户独自获得价值，再引入团队 | 20-40% |
| 需要集成 | 不连接其他工具就无法使用 | 提供手动输入作为替代方案 | 30-50% |
| 学习曲线 | 产品过于复杂，无法快速取得成果 | 使用模板引导用户完成首次操作 | 20-30% |
| 需要批准/验证 | 电子邮件验证、管理员批准 | 将验证推迟到用户首次获得价值之后 | 40-60% |

### 快速成果架构

设计入门流程，使用户在最初 3 分钟内获得“快速成果”：

1. 确定产品能够提供的最简单且有价值的输出
2. 尽可能预先填充输入内容
3. 尽量减少需要做出的决策（使用智能默认值）
4. 庆祝成果（“你刚刚创建了自己的第一个 [X]！”）
5. 立即展示下一步操作

## 空状态设计

空状态是引导用户上手的时机，而不是死胡同。每个空白页面都是引导用户完成激活的机会。

### 空状态的构成

```
┌─────────────────────────────────────┐
│                                     │
│      [Illustration or Preview]      │  Show what this will look like with data
│                                     │
│   What this section does            │  1 sentence, benefit-focused
│                                     │
│   [Primary CTA: Create First X]    │  Single clear action
│                                     │
│   Or try with sample data →        │  Low-friction alternative
│                                     │
└─────────────────────────────────────┘
```

### 空状态规则

| 规则 | 好的做法 | 不好的做法 |
|------|------|-----|
| 展示最终状态 | 使用示例数据预览 | 完全空白的页面 |
| 单一 CTA | “创建你的第一个项目” | “了解更多” + “观看视频” + “阅读文档” |
| 说明价值 | “在一个视图中跟踪团队进度” | “未找到项目” |
| 提供示例数据 | “使用示例数据体验”链接 | 强制用户从头创建 |

## 不同产品类型的入门模式

### B2B SaaS

```
Signup → Setup Wizard (3-5 steps) → First Value Action → Team Invite → Deep Setup
         ├── Company info              ├── Template selection     ├── Email invites
         ├── Role/goal selection       ├── Quick configuration    └── Permissions
         └── Integration connect       └── First output created
```

**关键指标：** 从注册到首次团队协作所需的时间

### 市场平台 / 双边平台

```
Signup → Complete Profile → Browse/Discover → First Transaction → Repeat Loop
         ├── Photo/avatar         ├── Curated feed          ├── Guided first action
         ├── Preferences          ├── Search + filters      └── Transaction completion
         └── Verification         └── Saved/bookmarked
```

**关键指标：** 从注册到首次完成交易所需的时间

### 移动应用（B2C）

```
Install → Permission Requests → Quick Win → Push Notification Setup → Habit Loop
          ├── Location (if needed)   ├── Core action            ├── Value-based ask
          ├── Notifications          ├── Immediate result       └── Frequency choice
          └── Camera/contacts        └── Celebration
```

**关键指标：** 首日留存率

### 内容 / 媒体平台

```
Signup → Interest Selection → Personalized Feed → First Engagement → Social Connection
         ├── Topic picks          ├── Curated content      ├── Read/watch/listen
         ├── Creator follows      ├── Algorithmic mix      └── Like/save/share
         └── Format preferences   └── Notification prefs
```

**关键指标：** 前 14 天内每周的会话次数

## 多渠道协同

### 电子邮件 + 应用内矩阵

| 触发条件 | 应用内操作 | 电子邮件操作 | 时机 |
|---------|--------------|--------------|--------|
| 注册完成 | 显示包含第一步的欢迎界面 | 发送仅包含一个 CTA 的欢迎邮件 | 立即 |
| 第 1 步完成 | 显示第 2 步 | --（不要每一步都发送邮件） | 立即 |
| 已过 24 小时，仍未完成引导 | 显示常驻横幅/检查清单 | 发送“完成你的设置”邮件 | 注册后 24 小时 |
| 已过 72 小时，仍未激活 | 显示欢迎回来模态框 | 发送“你可以这样使用”邮件 | 注册后 72 小时 |
| 已完成激活 | 显示庆祝模态框 + 下一个功能 | 发送庆祝邮件 + 下一步 | 立即 |
| 第 7 天，功能探索 | 显示情境式工具提示 | 发送“你知道吗？”功能介绍邮件 | 第 7 天 |
| 第 14 天，参与度下降 | -- | 使用用例示例重新吸引用户 | 第 14 天 |

### 电子邮件设计规则

- 每封邮件仅包含一个 CTA，引导用户返回产品
- 根据用户已经执行的操作进行个性化（不要要求他们执行已经完成的操作）
- 邮件应保持简短（正文少于 150 个单词）
- 主题行应提及具体的下一步，而不是笼统的“欢迎使用 [Product]”

## 停滞用户挽回

### 停滞用户定义

| 停滞状态 | 标准 | 挽回优先级 |
|--------------|----------|------------------|
| 从未开始 | 已注册，但之后再未登录 | 中（可能不符合 ICP） |
| 部分完成引导 | 完成了 1-2 个设置步骤后停止 | 高（已投入精力，但遇到了障碍） |
| 活跃但未激活 | 登录 3 次以上，但从未到达顿悟时刻 | 最高（有参与度，但陷入了困境） |
| 已激活但正在流失 | 已到达顿悟时刻，但使用量正在下降 | 高（这是留存问题，而不是用户引导问题） |

### 挽回策略

| 停滞状态 | 策略 1 | 策略 2 | 策略 3 |
|--------------|----------|----------|----------|
| 从未开始 | 发送“我们已为你设置好 [X]”邮件 | 预先填充账户 | -- |
| 部分完成引导 | 发送“从上次中断的地方继续”邮件 | 简化剩余步骤 | 提供实时帮助 |
| 活跃但未激活 | 应用内引导式演练 | 提供“与你类似的用户会执行 [X]”建议 | 对高价值用户进行人工联系 |
| 已激活但正在流失 | 发送功能探索邮件 | 根据其工作流程提供使用技巧 | 针对企业客户进行 CSM 联系 |

### 人工介入触发条件

对于高价值账户（企业客户、高 ACV），在以下情况下触发人工联系：
- 用户在引导过程中停滞超过 48 小时
- 用户在一次会话中访问帮助文档超过 3 次
- 用户开始执行同一操作后又放弃，累计 2 次以上
- 用户的参与度评分在初次激活后降至阈值以下

## 用户引导检查清单设计

### 何时使用检查清单

- 需要完成多个设置步骤才能获得完整价值
- 产品有多个功能需要探索
- 用户自行完成引导的自助式 B2B 产品
- 具有明确“已完全设置”状态的产品

### 检查清单最佳实践

| 规则 | 实现方式 |
|------|---------------|
| 3-7 项 | 少于 3 项 = 不值得使用检查清单。多于 7 项 = 令人不知所措。 |
| 按价值排序 | 将最具影响力的操作放在首位 |
| 从快速见效的操作开始 | 第一项应能在 60 秒内完成 |
| 显示进度 | 显示进度条或“5 项中已完成 3 项”计数器 |
| 预先勾选已完成的项目 | 如果用户已经执行过某项操作，将其标记为已完成 |
| 庆祝完成 | 动画、彩纸效果、“一切已准备就绪！”消息 |
| 可关闭 | 提供“稍后再做”选项。绝不要困住用户。 |
| 常驻但不阻塞 | 使用侧边栏组件或仪表板卡片，而不是阻塞式模态框 |

### 检查清单项目设计

每个项目应包括：
- 清晰的操作标签（“导入联系人”）
- 说明其重要性（“以便你跟踪互动情况”）
- 预计所需时间（“大约需要 2 分钟”）
- CTA 按钮（“立即导入”）

## 工具提示和引导游览设计

### 何时使用工具提示/引导游览

- 功能不直观的复杂 UI
- 用户可能忽略的高级功能
- 重大更新后的 UI 变更
- 需要按特定顺序发现的功能

### 引导游览最佳实践

| 规则 | 实施方式 |
|------|---------------|
| 每次引导游览最多 3-5 个步骤 | 超过 5 个步骤，用户就会关闭 |
| 可随时关闭 | 每个步骤都提供“跳过引导” |
| 不要向回访用户重复展示 | 跟踪引导完成情况，完成后不再展示 |
| 突出显示实际 UI 元素 | 对正在说明的元素应用聚光灯效果 |
| 以操作为导向 | 使用“点击此处创建项目”，而不是“项目位于这里” |
| 渐进式展示 | 第 1 天展示基础引导，第 7 天展示高级功能引导 |

## 指标与衡量

### 关键指标

| 指标 | 公式 | 目标 |
|--------|---------|--------|
| 激活率 | 达到激活状态的用户数 / 注册总人数 | B2C：40-60%，B2B：25-40% |
| 激活耗时 | 从注册到触发激活事件的时间中位数 | B2C：< 1 天，B2B：< 7 天 |
| 新手引导完成率 | 完成所有步骤的用户数 / 注册总人数 | > 60% |
| 第 1 天留存率 | 注册后次日回访的用户数 / 注册总人数 | > 40% |
| 第 7 天留存率 | 注册 7 天后仍活跃的用户数 / 注册总人数 | > 25% |
| 第 30 天留存率 | 注册 30 天后仍活跃的用户数 / 注册总人数 | > 15% |
| 检查清单完成率 | 完成所有项目的用户数 / 看过检查清单的用户数 | > 50% |

### 漏斗分析模板

```
Signup                  100%
├── First login          85%  (-15% never return)
├── Setup step 1         70%  (-15% drop during setup)
├── Setup step 2         55%  (-15% setup friction)
├── First value action   40%  (-15% blank slate / confusion)
├── Activation event     30%  (-10% incomplete value delivery)
└── Day-7 return         20%  (-10% no habit formed)
```

重点优化绝对流失量最大的步骤。

## 实验框架

### 高影响力实验

| 实验 | 假设 | 指标 |
|-----------|-----------|--------|
| 减少设置步骤 | 步骤越少，完成率越高 | 激活率 |
| 预填充示例数据 | 减少面对空白状态时的焦虑 | 首次价值操作耗时 |
| 添加新手引导检查清单 | 展示进度可提高完成率 | 新手引导完成率 |
| 延后电子邮件验证 | 在用户获得价值前减少阻碍 | 激活耗时 |
| 根据角色/目标进行个性化 | 相关路径可提高激活率 | 各细分群体的激活率 |

### 中等影响力实验

| 实验 | 假设 | 指标 |
|-----------|-----------|--------|
| 欢迎视频与文本对比 | 视频可能带来改善，也可能产生负面影响，具体取决于产品 | 激活率 + 首个页面停留时间 |
| 更改检查清单顺序 | 价值优先的排序可提高完成率 | 检查清单完成率 |
| 引导游览与自主探索对比 | 引导游览有助于理解复杂产品 | 功能采用率 |
| 在新手引导期间提供应用内聊天 | 实时帮助可减少流程停滞 | 停滞率、激活率 |

| 实验待办列表 | 按优先级排序的表格 | 根据预期影响和投入对测试想法进行排序 |
| 停滞用户行动手册 | 决策树 | 检测标准、挽回策略、升级规则 |

## 相关技能

- **signup-flow-cro** -- 用于优化用户进入产品前的注册流程。Onboarding-cro 从注册完成后开始。
- **paywall-upgrade-cro** -- 当用户引导流程会进入升级节点时使用。在用户达到 Aha 时刻之前，不要展示付费墙。
- **churn-prevention** -- 当用户已激活但随后流失时使用。如果用户从未激活，问题出在用户引导，而不是流失。
- **page-cro** -- 当瓶颈在注册前的营销页面，而非注册后的体验时使用。

## 故障排查

| 问题 | 可能原因 | 解决方案 |
|---------|-------------|----------|
| 激活率低于 25%（B2B）或 40%（B2C） | 未能足够快地达到 Aha 时刻 | 运行 ttv_estimator.py 以识别 TTV 瓶颈；目标是在 5 分钟内实现首次价值 |
| 用户完成用户引导，但在第 7 天没有回访 | 用户引导只带用户完成设置，而没有让用户获得价值 | 重构流程，让首次会话交付有意义的产出，而不仅仅是完成配置 |
| 用户引导清单完成率低于 50% | 条目过多，或第一个条目过于复杂 | 减少到 3-7 个条目；从可在 60 秒内完成的快速成果开始；使用 onboarding_checklist_scorer.py 进行审查 |
| 停滞用户占注册用户的 40% 以上 | 空白状态问题或下一步不明确 | 添加预填充的示例数据和空状态 CTA；在 24h 和 72h 实施停滞用户挽回邮件 |
| 第 1 天留存率低于 30% | 首次使用体验存在死胡同或令人困惑之处 | 应用 30 秒规则：在 30 秒内，用户能看到一个明确的下一步操作、理解产品价值，并知道如何继续 |
| 用户引导邮件序列的打开率较低 | 主题行过于笼统或发送时机不当 | 对主题行进行个性化处理，使其提及具体的下一步操作；按触发条件决定发送时机，而不是采用固定时间表 |
| 团队邀请率较低 | 邀请步骤安排在展示价值之前 | 将团队邀请推迟到用户独自体验过核心价值之后 |

## 成功标准

- B2B 产品在 14 天内的激活率达到 30-40%（B2C 产品为 40-60%）
- 首次价值实现时间低于 5 分钟（通过 ttv_estimator.py 验证）
- 新用户引导完成率高于 60%
- 第 1 天留存率高于 40%
- 第 7 天留存率高于 25%
- 针对停滞用户的召回邮件达到 10% 以上的重新激活率
- 新用户引导清单在 onboarding_checklist_scorer.py 评估中得分达到 70 分以上

## 范围与限制

- **范围内：** 激活定义、新用户引导流程设计、价值实现时间工程、空状态设计、清单设计、工具提示/导览设计、邮件协同、停滞用户召回、实验设计
- **范围外：** 注册流程（使用 signup-flow-cro）、营销页面优化（使用 page-cro）、长期留存策略、功能开发
- **数据依赖：** 要获得最佳结果，需要漏斗分析数据（各步骤的流失数据）；如果没有这些数据，只能根据启发式方法进行优化
- **产品类型很重要：** B2B SaaS、市场平台、移动应用和内容平台的新用户引导模式存在根本差异；请为你的产品类型采用正确的模式
- **没有万能方案：** 如果产品无法提供价值，再多的新用户引导优化也无法改善留存；应先验证产品与市场的契合度

## 集成点

- **signup-flow-cro** -- 优化新用户引导开始前的注册流程；交接点是账户成功创建后的那一刻
- **churn-prevention** -- 当用户激活后又流失时，问题就从新用户引导转向了留存；对于激活后的用户流失，请使用 churn-prevention
- **paywall-upgrade-cro** -- 升级提示只能在用户达到顿悟时刻后出现；切勿在初始新用户引导期间展示付费墙
- **page-cro** -- 当瓶颈在于营销页面（用户没有注册）时，应先优化页面，再优化新用户引导
- **customer-success-manager** -- 对于企业账户，人工辅助的新用户引导可作为产品驱动流程的补充；客户成功团队应监控激活指标
