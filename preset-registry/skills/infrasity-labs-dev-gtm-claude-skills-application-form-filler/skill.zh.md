# 求职申请表填写助手

## 何时使用此技能

当用户希望执行以下操作时，请使用此技能：
- 回答求职申请表中的具体问题
- 填写 Greenhouse、Lever、Ashby、Workday 或任何 ATS 中的文本字段
- 撰写针对“介绍一下你自己”或“为什么想来这里工作”等提示的回答
- 获得简洁、可直接复制粘贴的申请问题答案
- 提到：“帮我填一下”“这里该写什么”“回答这个问题”“求职申请表”“表单字段”

## 核心原则

求职申请表的回答应直接且具体——不要把求职信硬塞进文本框。每个字段都有其用途。清楚地回答该字段要了解的内容，然后就此结束。

**回答应给人这样的感觉：** 这是一个真实的人亲自输入的，而不是套用模板填写出来的。

## 回答之前

务必阅读：
1. **职位描述**——呼应其中的措辞和重点
2. **候选人的简历/个人资料**——从中提取真实的项目、职位和量化成果
3. **具体问题**——准确回答对方实际提出的问题，而不是你希望对方提出的问题

如果用户尚未提供简历或职位描述，请在撰写前向其索取。

## 问题类型及相应处理方式

---

### 类型 1：经验/背景问题

**示例：**
- “你有多少年使用[技术]的经验？”
- “请描述你在[领域]方面的经验”
- “你使用过哪些后端框架？”

**格式：**
```
[Technology/skill] — [X years]. [One sentence on what you used it for, with a
specific project or context]. [Optional: secondary tools in the same category].
```

**规则：**
- 首先说明使用最多或最相关的技术
- 如实给出经验年限——不要夸大
- 每项陈述都要以真实的项目或职位为依据
- 对于“描述经验”类问题：最多 2–4 句话，每句话介绍一个项目
- 如果属于间接经验（相邻领域），请如实说明，然后转向与问题相关的内容

---

### 类型 2：为什么选择这家公司 / 什么吸引了你

**示例：**
- “你为什么想在[公司]工作？”
- “这个职位的什么方面吸引了你？”
- “你为什么适合这个职位？”

**格式：**
```
[Specific thing about the company/role that's genuinely interesting — not generic].
[How that connects to something the candidate has actually worked on].
[Optional: one line on why this domain, not just this company].
```

**规则：**
- 必须针对这家公司具体作答——不要使用套话
- 如有需要，请在回答前研究这家公司
- 联系真实的工作经历，而不是个人愿望
- 作为表单字段回答时，控制在 150 词以内
- 不要把职位描述原封不动地复述给对方

---

### 类型 3：作品集 / 工作样例

**示例：**
- “请提供其他任何你引以为豪的工作样例”
- “请提供相关项目或代码仓库的链接”
- “请描述一个你端到端构建的项目”

**格式：**
列出项目，并为每个项目提供一句话描述和链接。将最相关的项目放在最前面。

```
[Project Name] ([live URL] | [github URL]) — [one line: what it is and one
proof point]. [Stack if relevant].
```

**规则：**
- 仅包含与该职位相关的项目
- 务必提供链接（在线演示 > GitHub > 无链接）
- 如果项目拥有付费用户或可量化的使用数据，请说明——一次即可
- 不要为了显得项目众多而堆砌无关项目

---

### 类型 4：技术技能问题

**示例：**
- “你使用最多的前端框架有哪些？”
- “请评价你的 Python 熟练程度”
- “描述你在云基础设施方面的经验”

**格式：**
对于开放式文本字段：
```
[Primary skill] — [X years]. [Specific use: what you built with it, in what context].
[Secondary skill] — [X years]. [Same].
[Note any relevant gaps honestly].
```

对于评分/下拉字段：选择符合实际情况的等级——如果最高等级并不准确，不要为了获得最高评分而优化答案。

**规则：**
- 年限加具体背景优于只有年限
- 坦诚说明不足，而不是隐藏它们
- 如果要求评分，请如实评分——虚高的评分会在技术面试中造成问题
- 对于你使用过但最近没有使用的技术栈，请注明这一点

---

### 类型 5：开放式问题 / “介绍一下你自己”

**示例：**
- “介绍一下你自己”
- “描述你的职业背景”
- “你希望下一份工作是什么样的？”

**格式：**
```
Current role + what you do there (1 sentence).
Relevant prior experience, briefly (1 sentence).
What you're looking for / why this role (1-2 sentences — specific to the company).
Optional: one project or side work that's relevant (1 sentence).
```

**规则：**
- 从当前职位讲起，而不是教育背景
- 对于大多数表单字段，控制在 100-200 词
- 以面向未来的内容结尾（你想要什么，而不是你过去做过什么）
- 不要陈述个人特质（“我对……充满热情”）——只写事实和项目

---

### 类型 6：情境 / 行为问题

**示例：**
- “描述一次你解决复杂技术问题的经历”
- “讲述一个你从头到尾负责领导的项目”
- “你如何处理跨多个团队协作的工作？”

**格式：** 精简版 STAR（无需标签，只需自然连贯地叙述）

```
[Context in one sentence]. [What you specifically did — 2 sentences]. [Outcome
with a metric if possible — 1 sentence].
```

**规则：**
- 要具体——写出项目名称、所用技术和团队规模
- 不要泛泛而谈（“我处理问题时总是会……”）
- 控制在 150-250 词
- 全文使用第一人称和主动语态
- 以结果结尾，而不是经验教训（将后者留到面试时再谈）

---

### 类型 7：观点 / 愿景问题

**示例：**
- “你认为哪些技术对未来最为重要？”
- “如果有无限的时间，你会学习什么？”
- “你认为 5 年后的 AI/[domain] 会是什么样？”

**格式：**
给出真实的观点。选择一到两个方面，并简要说明理由。

**规则：**
- 要有明确的观点——模糊的回答很容易被遗忘
- 以领域知识或真实经验为观点依据
- 控制在 100-150 词
- 不要对所有内容都含糊其词——明确表达立场，同时承认这只是其中一种观点

---

## 长度校准

| 字段类型 | 目标长度 |
|------------|---------------|
| 单行文本 | 1 句话 |
| 简短回答 | 2-4 句话 |
| 长回答 / 文本区域 | 100-250 词 |
| “描述你的经验” | 150-300 词 |
| “介绍一下你自己” | 100-200 词 |
| 作品集 / 链接部分 | 使用列表格式，不写成段落 |

拿不准时，宁可写短一些。招聘人员通常只会快速浏览表单回答。目标是清晰且令人印象深刻，而不是面面俱到。

## 应避免的常见错误

**复述职位描述：**
❌ “我对这个职位感兴趣，因为你们正在寻找能够构建可扩展后端系统的人……”
✅ “真正吸引我的是实时性要求——以毫秒级延迟处理医疗数据，与大多数后端工作面对的是完全不同的一类问题。”

**笼统地宣称个人特质：**
❌ “我学习能力强，并且能在协作环境中发挥出色”
✅ [只需描述实际工作——这些特质自然会体现出来]

**过度解释资历：**
❌ “虽然我可能没有整整 5 年经验，但我相信我的经历……”
✅ “这个职位要求 5 年经验——我目前有 3 年，但我交付的系统均直接面向生产环境。”

**脱离上下文罗列技能：**
❌ “React、Vue、Angular、Next.js、TypeScript、Node.js……”
✅ “React 是我主要使用的前端框架——在 Screenr 和多个客户项目中累计使用了 4 年。Vue 和 Angular 各有约 3 年经验，主要用于仪表盘和管理工具。”

**为了凑篇幅而填充内容：**
❌ 仅仅为了显得经历丰富而添加不相关的项目或经验
✅ 只包含与这个具体职位相关的内容
