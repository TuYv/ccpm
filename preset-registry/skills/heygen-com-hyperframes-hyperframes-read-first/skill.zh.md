# HyperFrames — 请先阅读本文

**任何 HyperFrames 任务都从这里开始**——尤其是在没有项目智能体配置（`CLAUDE.md` / `AGENTS.md` / `.cursorrules`）的情况下。下方提供能力图谱和视频路由。

## 能力图谱——不同意图应使用哪项技能

| 你想要……                                                                                                                                     | 前往                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| **制作视频**（根据 URL、简要说明、主题、GitHub PR、现有素材或要制作动画的单个元素）                                         | 下方的**视频路由**（§ 视频路由） |
| **创作 / 编辑 HTML 合成**——`data-*` 契约、片段、轨道、子合成、变量                                        | `/hyperframes-core`                          |
| **制作动画**——原子运动规则、场景蓝图、转场、运行时适配器（GSAP / Lottie / Three.js / Anime.js / CSS / WAAPI / TypeGPU） | `/hyperframes-animation`                     |
| **创意指导**——`design.md`、调色板、排版、旁白、节拍规划、音频响应                                             | `/hyperframes-creative`                      |
| **媒体预处理**——TTS 配音、背景音乐、转录、背景移除、字幕                                           | `/hyperframes-media`                         |
| **CLI 开发循环**——初始化、代码检查、验证、检查、预览、渲染、发布、诊断                                                               | `/hyperframes-cli`                           |
| **安装注册表区块 / 组件**（`hyperframes add`）                                                                                     | `/hyperframes-registry`                      |

> 合成的**创作契约**（每个定时元素都需要 `data-start` / `data-duration` / `data-track-index`；定时元素需要 `class="clip"`；GSAP 时间线必须暂停并注册到 `window.__timelines`；只能使用确定性逻辑——禁止使用 `Date.now()` / `Math.random()` / 网络）**不会在此重复说明**——它位于 `/hyperframes-core` 中。编写合成 HTML 前请先阅读该文档。

## HyperFrames 无法完成的事项——请先检查此处

HyperFrames 使用代码创作 HTML 合成并将其渲染为 MP4。这种模式有明确的硬性边界。超出其中任何边界的请求都不是路由选择问题，而是**超出范围**，因此应拒绝该请求（或将用户引导至正确的工具），而不是尝试套用某个工作流。这些限制源于其架构，而非任何单一请求：

- **渲染是确定性且自包含的。** 每个值、资源和文本片段都会在创作时固化；渲染过程中不会发起网络调用，也不会实时 / 在渲染时拉取数据（核心规则：禁止使用 `Date.now()` / `Math.random()` / 网络）。“在渲染时实时刷新数字”超出范围——应在创作时获取一次数据并将其固化，否则就拒绝该请求。
- **现有视频只能被叠加内容，不能被编辑。** HyperFrames 在源片段_之上_合成帧——`/embedded-captions` 添加字幕图层，`/graphic-overlays` 添加经过设计的图形卡片（下三分之一字幕、数据标注、标题）——源片段在下方保持不变地播放，但二者都不会对编码后的视频流进行后处理。更改素材_本身_（其时序、颜色、构图、顺序或音频）属于 NLE 风格的编辑，超出范围。
- **Remotion 导入是单向的。** `/remotion-to-hyperframes` 将 _Remotion 框架的_源代码转换为 HyperFrames。不存在反向转换（HyperFrames → Remotion，或 → 任何其他框架——均超出范围），而非 Remotion 的 React / Web 动画源代码中没有可供转换的 Remotion 源代码——应通过 `/general-video` 重新创建。
- **它无法生成其未拥有的输入。** 不支持屏幕 / 会话录制、摄像头采集，也不支持生成 AI 数字人 / 口型同步虚拟形象。如果素材或资源尚不存在，HyperFrames 无法凭空生成——应先要求用户提供（或使用正确的采集工具）。

其他所有内容——来自 URL 的视频、简介、主题、PR、待标注的素材，或要制作动画的单个元素——都在支持范围内；请按下文进行路由。

# 视频路由

本节仅了解顶层工作流。它不会加载工作流内部阶段、领域技能（`hyperframes-*`——参见上方的能力图谱）或技术参考资料。

## 决策表

**输入类型（意图）是首要维度；输出时长只是上限，而不是准入条件。** 对于匹配的输入，专用工作流可处理**最长约 3 分钟**的任何内容——进入哪个工作流取决于意图（即输入类型；对于文本，还取决于主题），而不是时长。时长只在较长内容中起作用：真正较长的内容（3-5 分钟的教程、5 分钟以上的深度解析）属于不同类型，应路由到 `/general-video`。在 ≤约 3 分钟的范围内，第三个维度会进一步区分两个以文本为输入的工作流——即**主题**：是正在被*营销*的产品，还是正在被*讲解*的主题（参见下方步骤 3 中的消歧规则）。

| 时长 / 输入 | 产品发布（URL / 简介 / 脚本） | 常规网站 / URL | GitHub PR / 代码变更 | 主题 / 文章 / 笔记（无产品、无 URL） | 现有视频（真人出镜）† |
| --------------- | ------------------------------------- | --------------------- | ----------------------- | -------------------------------------------- | -------------------------------------------- |
| **≤ 约 3 分钟** | `/product-launch-video` | `/website-to-video` | `/pr-to-video` | `/faceless-explainer` | `/embedded-captions` · `/graphic-overlays` † |
| 3-5 分钟教程 | `/general-video` | `/general-video` | `/general-video` | `/general-video` | `/embedded-captions` · `/graphic-overlays` † |
| 5 分钟以上深度解析 | `/general-video` | `/general-video` | `/general-video` | `/general-video` | `/embedded-captions` · `/graphic-overlays` † |
| 静态 / 循环 | `/general-video` | `/general-video` | `/general-video` | `/general-video` | `/general-video` |

当前覆盖范围：**≤ 约 3 分钟**这一档针对**产品发布 / 常规网站 / GitHub PR / 主题**输入提供了专用工作流（URL 先按*类型*区分，再按*意图*区分——参见步骤 3）；而**现有视频**这一列在**任何时长**下都受支持——根据意图（参见步骤 2），使用 `/embedded-captions`（字幕）或 `/graphic-overlays`（经过设计的图形叠加层）。**其他所有单元格均为 `/general-video`**——通用 HTML 合成创作流程（不受输入和时长限制）：所有**超过约 3 分钟**的内容（3-5 分钟 / 5 分钟以上这两行）以及所有**静态 / 循环**格式。对于可创作的视频，路由器绝不会无路可走；唯一真正应回答“通用 / 无”的情况，是请求本身超出了 HyperFrames 的范围（例如，对已完成的视频文件进行 NLE 式编辑——重新调整时间、重新调色、重新构图、重新排序、处理音频）。

† **现有素材按意图而非时长分流。** 字幕 → `/embedded-captions`；经过设计的图形叠加层 / 包装——下三分之一字幕条、数据标注、带标题的卡片、重点引语——→ `/graphic-overlays`。两者都会叠加在视频片段之上，底层片段保持不变地播放；两者都不会编辑素材本身。

**类型短路规则（优先于表格）。** 简短（约 10 秒以内）、无旁白、设计驱动的**动态图形**——动态文字、统计数据 / 图表的一击式呈现、徽标短动画、下三分之一字幕条 / 叠加层，或动画化的推文 / 标题 / 页面截取重点标示——无论输入为何，都路由到 `/motion-graphics`。它是一种输出类型，而非输入类型，因此，当请求明显以动态表现为主且没有旁白时，它优先于上面的输入类型表（参见第 2 步）。更长或带旁白的处理方式按输入类型路由，或路由到 `/general-video`。

## 迁移现有合成项目（特殊情况）

上表适用于根据输入**创建**视频。有一种工作流不在其中：如果用户明确要求将**现有 Remotion (React) 合成项目移植 / 转换 / 迁移**到 HyperFrames → `/remotion-to-hyperframes`。这是源代码转换，而不是从输入创建内容，因此没有对应的输入 × 时长单元格。仅在出现明确的迁移表述时才路由到这里（“移植我的 Remotion 项目”“转换这个 Remotion 合成项目”“用 HyperFrames 重写这个项目”）——仅仅提及 Remotion 并不足以触发该路由；默认使用创建流程表或 `/hyperframes-core`。

## 路由流程

1. **确定输入类型和目标时长。** 路由需要知道**视频的主题是什么**——即其主题和输入。如果主题本身未指定（例如“制作一个关于我们这个东西的视频”，但没有提供 URL、已命名的产品、主题或可使用的素材），或输入类型未知，**请在进入任何工作流之前询问**——先澄清；不要先调用某个工作流 Skill 再提问，因为选定工作流本身就是路由决策。最多提出 2 个澄清问题：
   - “你的输入是什么——产品（URL 或简介）、普通网站 / URL、GitHub PR / 代码变更、需要解释的主题或文章，还是需要添加字幕的现有真人出镜视频？”
   - “目标时长是约 3 分钟以内，还是更长（3–5 分钟的教程 / 5 分钟以上的深度讲解）？”
   - **规格默认值——直接说明，不要询问**（这些不会影响路由，因此绝不能因其阻塞路由）：**宽高比**为 16:9（引擎也支持 **9:16** 竖屏——仅当用户明确指定 TikTok / Reels / Shorts 等竖屏发布平台时才切换）；旁白 / 字幕的**语言**与用户使用的语言一致。只有当用户提出异议时才确认；所选工作流会在自己的第 0 步再次确认具体设置。
2. **首先按输入类型（意图）选择；时长只是上限，不是门槛。**
   - **简短、设计驱动的动态图形（类型短路规则，优先于输入表）**——动态表现本身就是信息：动态文字、统计数据 / 数字递增动画、图表的一击式呈现、徽标短动画、下三分之一字幕条 / 叠加层，或动画化的推文 / 标题 / 页面截取重点标示；通常约 10 秒以内，**没有旁白 / 配音** → `/motion-graphics`。它是一种输出类型，而非输入类型——当请求明显是快速、无旁白、设计驱动的动态内容时，无论输入为何都路由到这里。对相同素材进行**更长或带旁白**的处理则不属于此类（按输入类型路由，或路由到 `/general-video`）。
   - **现有真人出镜视频**（用户已有视频片段，并希望在其上添加内容）→ 在**任何时长**下都按意图拆分（输入类型优先于时长）：**字幕**（将口述内容呈现为可读文字）→ `/embedded-captions`；**经过设计的图形叠加层**——下三分之一字幕条、数据标注、带标题的信息卡、重点引语、图形包装式剪辑 → `/graphic-overlays`。（编辑素材_本身_——重新调整时间、重新着色、重新构图、重新排序、处理音频——属于 NLE 风格的工作，超出范围；参见 § HyperFrames 无法完成的工作。）
   - **GitHub PR / 代码变更**（`github.com/<owner>/<repo>/pull/<N>` 链接、`owner/repo#N` 引用或“这个 PR”）→ `/pr-to-video`（最长约 3 分钟）。
   - **其他情况**（产品 URL / 简介 / 主题文本）：由第 3 步根据意图选择工作流，并且相应工作流可处理**最长约 3 分钟**的任何内容——无论是 15–30 秒的短促销片，还是约 100 秒的解说片，都按意图而非时长路由。仅当目标明显**超过约 3 分钟**（3–5 分钟的教程、5 分钟以上的深度讲解）时，才路由到 `/general-video`（不受时长限制的后备选项——参见第 4 步）。绝不要强行将真正的长视频塞进不超过约 3 分钟的工作流——在该时长范围内由意图决定，其余情况由 `/general-video` 处理。
3. **消除最长约 3 分钟的 URL / 文本输入歧义（意图拆分）。** 分为两类：
   - **URL 类型和意图**——URL 不再自动优先路由到 PLV；先由其_类型_、再由其_意图_决定：**GitHub PR** 链接（`.../pull/<N>`、`owner/repo#N`、“这个 PR”）→ `/pr-to-video`；其他网站 URL 则按意图拆分——**营销 / 发布 / 推广某个具体产品或 SaaS** → `/product-launch-video`；**普通网站 → 视频**（网站导览、作品集 / 博客 / 落地页展示、使用网站自身视觉素材制作社交媒体短片，或只是“把这个网站制作成视频”）→ `/website-to-video`。两者都使用无头 Chrome 抓取；PR URL 则通过 `gh` 读取。如果确实无法判断某个网站 URL 是产品发布视频还是普通网站视频，请提出一个问题。
   - **产品与主题**（文本，无 URL）——决定性问题是**视频讲什么**，而不是输入格式：
     - 对某个具体**产品 / 公司 / SaaS / 应用 / 网站**进行**营销、发布或推广** → `/product-launch-video`。
     - **解释**某个**概念 / 主题 / 文章 / 某事物的运作方式**，且**没有产品、没有 URL** → `/faceless-explainer`。
     - 决胜规则：出现“推广 / 发布 / 销售 / 我们的产品”等措辞 → PLV。出现“解释 / 教授 / X 如何运作 / X 是什么”，且没有产品 → faceless。faceless 交付时的样式始终为 `pin-and-paper`。
     - **未粘贴 URL 的已命名网站仍然属于 PLV。** 即使没有可点击的链接，只要脚本提及某个产品或其网站（“我们的网站是 acme.io”“推广 <brand>”），就路由到 PLV——PLV 可以通过网页搜索找到该网站，并抓取其品牌素材（除非用户选择退出，→ 无抓取预设模式）。没有粘贴 URL 并**不**意味着它属于 faceless / 无抓取任务。对于用户提供的脚本，是逐字使用还是重构，属于 PLV 内部选择，绝不会改变路由。
     - **线索冲突 → 询问，不要猜测。** 如果提供的来源是某个产品**自己的营销内容**（其落地页、宣传_其_平台的博客），但用户明确要求**去除宣传色彩**——制作关于底层概念的_中立_解说，_而不是广告_——则应将其视为确实存在歧义（视频讲的是_他们的产品_，还是_通用概念_？），并**提出一个问题**，而不是仅凭“中立”这一线索就决定路由到 faceless。对比之下，如果是一个普通主题，而产品只是顺带提及，并且用户明确要求_排除_该产品（“解释 OAuth 如何运作——我们销售身份验证产品，但不要提到它”），则明确属于 **faceless**——无需询问。
   - 阅读请求后仍不明确 → 只问一个问题：_“这是要推广某个具体产品、根据普通网站制作视频、解释某个主题 / 概念、讲解 GitHub PR，还是为现有视频添加字幕？”_
4. **回退到 `/general-video`。** 如果上面的专用工作流都不匹配，则路由到 `/general-video`——通用 HTML 合成创作流程（即原始的 `hyperframes` 流程：设计系统 → 规划 → 先布局后动画 → 构建 → 验证），它不受输入和时长限制。不要_伪路由_到某个专用工作流（不要强行把教程塞进 PLV）；`/general-video` 才是正确的通用归宿，而不是选择一个勉强匹配的工作流。唯一真正应返回“无工作流 / 通用”的情况，是请求本身超出 HyperFrames 的能力范围——例如，对成品视频文件进行 NLE 风格的裁剪 / 编辑（为真人出镜视频片段添加字幕应使用 `/embedded-captions`；在其上叠加经过设计的图形应使用 `/graphic-overlays`）。

## 工作流说明（用于消除歧义）

### `/product-launch-video`

- **输入：** 要营销的产品，以下列形式之一提供：**(a) 产品 URL** → 使用无头 Chrome 抓取素材、品牌标识和页面结构；**(b) 指明产品网站的脚本/简报**（即使未粘贴链接）→ PLV 通过网络搜索找到该网站，并抓取其品牌标识和素材，_除非_用户选择不进行搜索；**(c) 无法推导出网站的脚本/简报**（或明确要求“不要抓取”）→ 无捕获模式，由你选择一个提供调色板和设计系统的样式预设（文本/排版场景，不使用抓取的素材）。提供的脚本可以**逐字用作旁白**，也可以**重构**为更有冲击力的逐场景旁白——PLV 会询问用户选择哪一种。
- **输出：** 产品发布视频/SaaS 讲解视频/宣传视频，以 HyperFrames 合成形式制作并渲染为 MP4——**最长约 3 分钟**（最佳时长约为 30-90 秒；如果逐字使用的脚本较长，视频也会更长——逐字模式下的时长取决于脚本）
- **触发语：** “为 X 制作一个发布视频”、“为我们的网站制作宣传视频”、“用一分钟讲解我的 SaaS”、“为 X.com 制作功能发布视频”、“为我们的产品制作营销视频”、“我有一份脚本——把它制作成 60 秒的宣传视频”、“这是我为 <brand> 准备的发布脚本，我们的网站是 <name>”、“逐字使用我的脚本作为旁白”、“制作一个纯文本发布视频，不使用网站/不要抓取任何内容”
- **请勿用于：** **没有产品**、仅以纯文本讲解某个主题/概念的视频（→ `/faceless-explainer`）——请注意，即使没有粘贴 URL，只要脚本中_指明了产品或其网站_，就应使用 PLV，而不是无真人出镜讲解；**一般性（非发布类）的网站 → 视频**——不以产品营销为核心的网站导览/展示/社交媒体短片（→ `/website-to-video`）；GitHub PR/代码变更讲解视频（→ `/pr-to-video`）；为现有视频添加字幕（→ `/embedded-captions`）；任何明显超过约 3 分钟的内容（教程、深度解析 → `/general-video`）；客户访谈、没有产品背景的动态图形、静态品牌素材（简短的产品宣传视频，即使只有 15-30 秒，也仍应使用 PLV——时长不是判断标准，产品营销意图才是）

### `/website-to-video`

- **输入：** 用户希望转换为视频的**一般网站/URL**——适用于目标是制作网站本身的或基于网站的视频，而不是产品发布视频。使用无头 Chrome 捕获真实截图和品牌素材。（如果是对产品进行**营销/发布/推广**，则应使用 `/product-launch-video`，即使输入来自 URL。）
- **输出：** 使用捕获的网站内容制作的视频——网站导览、作品集/博客/落地页展示，或由网站自身视觉素材组成的社交媒体短片——以 HyperFrames 合成形式制作并渲染为 MP4。
- **触发语：** “把这个网站制作成视频”、“捕获这个网站并制作成视频”、“用我的网站制作一个视频”、“根据 <url> 制作网站导览/展示视频”、“用我们的首页制作一个社交媒体短片”、“我只有一个 URL——随便做点什么”
- **请勿用于：** 对产品进行**营销/发布/推广**——以发布/宣传/功能发布/“推销我们的产品”为导向的内容（→ `/product-launch-video`，即使输入来自 URL）；**没有网站**的主题/概念讲解视频（→ `/faceless-explainer`）；GitHub PR（→ `/pr-to-video`）；为现有视频文件添加字幕（→ `/embedded-captions`）；仅用于突出显示/动画呈现所捕获页面的简短无旁白动态图形（→ `/motion-graphics`——单个快速的页面突出显示镜头，而不是带旁白的多场景网站视频）。如果确实无法判断某个网站 URL 应制作成产品发布视频还是一般网站视频，请提一个问题进行确认。

### `/faceless-explainer`

- **输入：** 任意文本——主题句、文章、笔记或简报——用于**解释说明**，**不营销任何产品，也不采集任何网站**。（如果文本中提到了某个产品或其网站，则应使用 `/product-launch-video`；它可以解析并抓取该网站——即使没有粘贴 URL。）由 `/product-launch-video` 分支而来；输入阶段无需抓取网站（输入阶段不使用无头 Chrome）
- **输出：** 以 HyperFrames 合成形式制作并渲染为 MP4 的无出镜讲解视频——**最长约 3 分钟**（最佳时长约 30–90 秒）。每个场景中的所有视觉元素均由 LLM 创作（排版 / 抽象图形 / 图表 / 数据可视化）；附带 `pin-and-paper` 风格预设
- **触发语句：** “制作一个关于 X 的无出镜讲解视频”“用视频解释 DNS 的工作原理”“把这篇文章转成讲解视频”“制作一个解释[概念]的视频，不涉及产品”“主题 → 教育类短视频”“根据我的笔记制作讲解视频”
- **请勿用于：** 任何以营销特定产品 / 公司为核心的内容，或即使未粘贴 URL、脚本中也_提及_产品网站的情况（→ `/product-launch-video`，它会进行网页搜索并抓取网站）；提供了 URL 的请求——产品网站（→ `/product-launch-video`）、**需要转换为视频的普通网站**（→ `/website-to-video`）或 GitHub PR（→ `/pr-to-video`）；为现有视频添加字幕（→ `/embedded-captions`）；明显超过约 3 分钟的内容（教程、深度解析 → `/general-video`）；产品广告 / 宣传形式（→ `/product-launch-video`）；需要让视觉元素与**预先录制 / 用户提供的配音或其他媒体对齐时间**的情况——faceless 会创作所有视觉元素并生成自己的旁白（TTS），不会与提供的音频同步（→ `/general-video`）；需要真实截图或从网站抓取的品牌素材的视频（即使短于 30 秒，只要是简短的讲解视频，也仍属于 faceless——时长不是判断标准，解释主题的意图才是）

### `/embedded-captions`

- **输入：** 用户希望添加字幕的现有**口播 / 单主体视频**（MP4）——必须是实际视频素材，而不是 URL 或文本简报。在本地进行转录（Whisper，无需 API 密钥）并进行主体抠像（RVM），使主体能够遮挡字幕；无需抓取网站，也不使用无头 Chrome。
- **输出：** **完全未经改动的同一段视频素材**，仅添加字幕图层——**标准模式**（默认）：使用逐字稿形式的下三分之一字幕栏承载转录文本，并在高潮时刻将嵌入式高潮字幕合成到主体后方；或**电影感模式**：采用纯嵌入形式，将每条字幕都合成到场景中主体的后方。**不限时长**——从短视频到长篇讲解均可。
- **触发语句：** “为这个视频添加字幕”“把字幕嵌入场景中”“让字幕显示在主体后方”“为我的视频片段添加电影感 / 嵌入式字幕”“给这个视频加字幕”
- **请勿用于：** 根据 URL 生成视频（→ `/product-launch-video` / `/website-to-video`）、根据主题 / 文本生成视频（→ `/faceless-explainer`），或根据 GitHub PR 生成视频（→ `/pr-to-video`）；**没有明确单一主体**的视频片段（抠像需要单一主体）；**编辑视频素材本身**——重新调整时间、调色、重新构图、重新排序、替换音频（属于非线性编辑，不在范围内）；尚不存在的视频素材（HyperFrames 无法录制——请用户提供素材）；在视频片段上添加**设计型图形叠加元素**（下三分之一图文、数据标注、带标题的信息卡片），而不是将口述内容呈现为可读文本 → `/graphic-overlays`。

### `/graphic-overlays`

- **输入：** 用户希望通过精心设计的屏幕图形对现有的**人物访谈 / 采访 / 撅客视频**（MP4）进行**包装**——必须是实际视频素材，而不是 URL 或需求简述。在本地转录（Whisper）。片段会在底层**完整播放**；不会进行剪切、重新计时或调色。
- **输出：** 在同一段视频素材的上方 / 旁边合成一系列**定时出现的图形叠加卡片**——动态标题、下三分之一字幕条、数据标注、重点引语、侧边面板、画中画——通过包含 10 种样式 × 4 种布局 × 3 种画框的设计系统，与转录文本同步。**长度不限。**（此工作流取代了已移除的 `/footage-recut` 信息卡叠加流程。）
- **触发语：**“包装一下这个视频”“为视频添加图形叠加 / 屏幕图形”“给我的讲话添加下三分之一字幕条 / 数据标注 / 动态标题 / 信息卡”“把这段采访制作成带图形包装的成片”“叠加与我所说内容同步的卡片”
- **不要用于：** 简单易读的**字幕**——将说话内容显示为文字（→ `/embedded-captions`）；**单个简短且无旁白的**动态元素，例如一个下三分之一字幕条或一个 Logo 短动画（→ `/motion-graphics`——此技能用于通过许多同步卡片包装完整的有旁白片段）；**编辑视频素材本身**——重新计时、调色、重新构图、重新排序、音频处理（属于 NLE 编辑，超出范围）；基于 URL / 主题 / PR 制作视频（→ 创建类工作流）；尚不存在的视频素材。

### `/pr-to-video`

- **输入：** 一个 **GitHub 拉取请求**——即代码变更，以 PR URL（`github.com/<owner>/<repo>/pull/<N>`）、`owner/repo#N` 引用，或在已检出的仓库中以“此 PR”的形式提供。它是一个 URL，但必须是通过 `gh` CLI 读取的 **PR 链接**——而不是需要抓取的营销网站。
- **输出：** 代码变更解说视频——**最长约 3 分钟**（理想时长约为 30–90 秒）——（变更日志 / 功能发布 / 修复说明 / 重构讲解）——包含 diff 重点、前后对比、文件树和影响分析场景
- **触发语：**“制作一个介绍此 PR 的视频”“把 PR #1187 做成变更日志视频”“用视频解释这个拉取请求做了什么”“根据 github.com/org/repo/pull/123 制作发布说明视频”“把这个 PR 做成视频”
- **不要用于：** 产品 / 营销网站 URL（→ `/product-launch-video`）或需要转化为视频的一般网站（→ `/website-to-video`）；没有 PR 的主题 / 文章 / 文本（→ `/faceless-explainer`）；为现有视频添加字幕（→ `/embedded-captions`）；整个仓库的导览或涉及多个 PR 的版本发布（目前尚无对应工作流 → `/general-video`）

### `/remotion-to-hyperframes`

- **输入：** 现有 **Remotion**（React）视频合成项目的源代码——用户明确要求将其移植 / 转换 / 迁移 / 重写为 HyperFrames。**转换方向是单向的**（Remotion → HyperFrames），且仅针对 _Remotion 框架_；这不是一个根据输入从头创建内容的工作流。
- **输出：** 从 Remotion 源代码转换而来的 HyperFrames HTML 合成项目，使用 SSIM 评估工具与分层测试语料库，对照 Remotion 渲染结果进行评级
- **触发语：**“将我的 Remotion 项目移植到 HyperFrames”“转换这个 Remotion 合成项目”“从 Remotion 迁移”“将其重写为 HyperFrames HTML”
- **不要用于：** 创作全新的合成项目（即使同时对 Remotion 视频进行 A/B 测试）、仅仅提及 Remotion，或在没有明确迁移请求的情况下要求“制作与我的 Remotion 视频相同的视频”（→ 创建类工作流 / `/hyperframes-core`）；**反向转换**——将 HyperFrames 导出回 Remotion 或任何其他框架（超出范围，参见 § HyperFrames 无法完成的事项）；**非 Remotion** 的 React / Web 动画源代码（没有可供转换的 Remotion 源代码 → 通过 `/general-video` 重新创建）

### `/motion-graphics`

- **输入：** 对以设计为主导的**短动态视觉**的请求，其中动态本身就是信息——通常不超过约 10 秒（最长约 30 秒），**无旁白 / 配音**。包含九种输出类型：动态排版、统计数据 / 数字递增、图表 / 数据可视化亮相、徽标短片 / 品牌组合标识、下三分之一字幕条 / 标注 / 社交媒体叠加层，或由搜索驱动的网页 / 新闻 / 推文 / 素材融合镜头（可通过 `hyperframes capture` 捕获页面，或在适用时提取图片 / 标题）。这是一条按输出类型判定的捷径——它横跨多种输入，因此当请求明确以动态优先且无旁白时，它位于输入类型表之前。
- **输出：** 以 HyperFrames 合成形式制作的短动态视觉——渲染为 MP4，或用于下三分之一字幕条 / 标注的**透明叠加层**（带 Alpha 通道的 WebM / MOV）。
- **触发语句：** “一个 8 秒的徽标短片”“为这个统计数据 / 数字制作动画”“一个动态排版开场”“一个快速的统计数据 / 图表亮相”“把这个标题或推文做成动态视觉”“一张动态海报”“一个透明的下三分之一字幕条 / 标注叠加层”
- **请勿用于：** 更长的、多场景的或**带旁白的**作品、品牌展示片，或任何超过约 10–15 秒的自定义合成（→ `/general-video`）；**介绍网站且带旁白的视频** / 网站导览（→ `/website-to-video`——motion-graphics 的网页类型是单个快速的页面重点展示镜头，而不是带旁白的网站视频）；带旁白的主题讲解视频（→ `/faceless-explainer`）；产品发布 / 宣传视频（→ `/product-launch-video`）；GitHub PR（→ `/pr-to-video`）；为现有视频素材添加字幕（→ `/embedded-captions`）

### `/general-video`

- **输入：** 上述工作流未处理的任何内容——创意简报、要制作动画的单个元素，或对你正在构建的合成进行编辑。不受输入类型和时长限制。
- **输出：** 使用原始 `hyperframes` 流程创作的 HyperFrames HTML 合成（任意时长 / 格式）：设计系统 → 提示词扩展 → 规划 → 先布局后动画 → 构建（委派给 `hyperframes-*` 领域技能）→ 验证。
- **触发语句：** “制作一个标题卡”“为这个制作动画”“一个较长的品牌 / 炫技展示片”“一个多场景合成”“一个具有一定时长的静态循环 / 海报”，或任何不符合上述工作流的“制作一个视频”请求。（短小、无旁白、单镜头的动态视觉——徽标短片、动态排版亮相、统计数据 / 图表弹出、下三分之一字幕条 / 叠加层——应使用 `/motion-graphics`，而不是此技能。）
- **请勿用于：** 已投入市场的产品（→ `/product-launch-video`）；一般的网站 → 视频（→ `/website-to-video`）；主题 / 概念讲解视频（→ `/faceless-explainer`）；GitHub PR（→ `/pr-to-video`）；为现有视频添加字幕（→ `/embedded-captions`）；迁移 Remotion（→ `/remotion-to-hyperframes`）；**短小、无旁白、以设计为主导的动态视觉**——徽标短片、动态排版亮相、统计数据 / 图表弹出、下三分之一字幕条 / 叠加层，或动态推文 / 标题 / 页面重点展示（→ `/motion-graphics`）；对成品视频进行 NLE 风格的编辑（超出范围）。

## 不属于视频路由范围

- **领域技能**（`/hyperframes-core`、`/hyperframes-animation`、`/hyperframes-cli`、`/hyperframes-creative`、`/hyperframes-media`、`/hyperframes-registry`）——此处不会路由到这些技能，但它们确实位于本技能顶部的**能力地图**中；工作流的构建阶段会将它们作为技术参考加载。
- **工作流内部阶段**——各阶段位于每个工作流的文件夹内，由该工作流的编排器分派，而不是由此路由器分派。
