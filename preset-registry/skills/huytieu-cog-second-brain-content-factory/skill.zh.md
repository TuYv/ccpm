# COG 内容工厂 Skill

## 目的

充当用户的自主内容创作者：搜寻其领域中刚刚发生的事件，筛选真正具有热度的内容，并以用户的表达风格将其转化为内容——确保零重复、严格限制发布数量，并且任何内容只有经过验证后才算发布成功。本 Skill 旨在按计划（每晚）无人值守运行，并可安全地重复运行：**空跑是有效的运行；低质量的帖子则不是。**

## 何时调用

- `/content-factory` / “运行内容工厂”
- 定时运行（例如每晚通过 cron/launchd 运行 2-4 次）
- “把今天的新闻转化为内容”

## 前置条件

从 `00-inbox/MY-PROFILE.md` 读取用户的表达风格和重点领域，并从 `00-inbox/MY-INTERESTS.md` 读取主题。发布目标来自 `00-inbox/MY-INTEGRATIONS.md`——静默跳过已禁用的渠道。

## 状态文件（最先读取，最后更新——这是去重机制的核心）

- `04-projects/content-factory/ledger.md`——记录曾经涵盖或发布过的所有内容（主题 slug、来源 URL、内容形式、链接、日期）。绝不要再次涵盖账本中已有的主题或来源 URL，除非确实出现了新消息（后续版本发布算新消息；换一种说法重述同一次发布则不算）。
- `04-projects/content-factory/tonight-<YYYY-MM-DD>.md`——今晚的运行日志（在当晚首次运行时创建）。记录先前运行中搜寻、暂存、制作和发布的内容，以及剩余的数量预算。
- `04-projects/content-factory/sources.md`——关注列表。添加你发现有价值的来源；移除已失效的来源。

## 数量预算（当晚所有运行合计，严格上限）

| 渠道 | 每晚上限 | 备注 |
|---------|-----------|-------|
| 短篇社交媒体帖子/帖子串 | 2 | 主力发布渠道；一个帖子串计为 1 条 |
| 博客文章 | 1 | 仅在内容深度足以支撑时发布 |
| 短视频 | 1 | 仅当创意适合视觉呈现/演示时发布 |
| 长篇专业帖子 | 1 | 仅在具备有力的专业视角时发布 |
| 长视频/深度文章 | 0 | 绝不自主发布；在运行日志中提出建议 |

在今晚的文件中跟踪预算。后续运行继承剩余额度。可按偏好调整上限——不变的原则是必须设定上限，并且上限适用于当晚的所有运行，而不是每次运行。

## 阶段 1——搜寻（每次运行）

1. 在 Web 上搜索过去 24 小时内与用户关注列表主题相关的公告，以及任何已经出现热度的内容。
2. 获取 `sources.md` 关注列表中的博客/变更日志。
3. 如果浏览器集成可用，则快速浏览用户的社交媒体信息流以寻找互动信号——原始互动数据是最佳的趋势信号。
4. 将搜寻工作严格限制在约 20 分钟内。

## 阶段 2——筛选（评分，而不是凭感觉）

按以下维度为每个候选内容评 1-5 分：
- **(a) 趋势动能**——主要账号和聚合平台现在是否正在讨论它？
- **(b) 重点领域契合度**——它是否符合用户的某个重点领域（来自 MY-PROFILE.md）？
- **(c) 独特视角**——我们能否加入只有该用户才能提供的内容（实验、实践者观点、逆向解读），而不是任何人都能写出的摘要？

总分 ≥11 → 制作。8-10 → 暂存到今晚的文件中，供后续运行重新评分。<8 → 忽略。

产出前进行去重检查：将主题 slug + 来源 URL 与台账进行比对，并在可以访问的情况下，与用户最近发布的帖子（约 20 篇）进行比对。

## 阶段 3 — 产出（形式阶梯——根据内容实质而非目标大小来决定）

- **默认：一篇短帖或一个帖子串**——开头使用吸引人的句子，附上媒体，将链接放在最后，并尽量少用话题标签。
- 只有在有 ≥3 个原创观点，或有一个包含产物的真实概念验证时，才写**博客文章**。如果用户有适合做 PoC 的主题：实际构建这个小型 PoC（限时约 45 分钟），并发布真实结果，包括失败情况。绝不捏造 PoC 结果；“它在这里出错了”也是好内容。
- 当创意具有视觉表现力，或可在 ≤60 秒内演示时，制作**短视频**。
- 让所有内容互相链接（视频 ↔ 博客 ↔ 帖子串彼此引用）。

## 阶段 4 — 发布（安全门禁）

1. **环境门禁**：如果发布平台不可用，或者用户似乎正在使用浏览器/机器——不要发布。将完成的内容包写入 `04-projects/content-factory/out/<date>/`，交由后续运行（或用户）发布。
2. **发布后状态检查（强制）**：每次发布后，都要实际查看产物——截取线上帖子的屏幕截图、对线上 URL 执行 curl——然后才能将其记录为已发布。绝不能仅凭发布调用就报告成功。
3. 绝不参与争论，绝不引用嘲讽，绝不回复陌生人。该内容工厂只在用户自己的平台上创建原创帖子。
4. 任何屏幕截图都必须通过凭据检查（不得显示账户电子邮箱、令牌或内部 URL）。
5. 绝不删除已经产生互动的帖子；如果需要修正，应直接编辑原帖。

## 阶段 5 — 台账 + 日志（始终执行，即使本次运行没有产出）

- 将已发布项目追加到 `ledger.md`：`| date | slug | beat | formats | source URL | published links |`。
- 更新 `tonight-<date>.md`：记录已搜集列表、评分、暂存项目、剩余预算，以及下一次运行应优先查看的内容。
- 如果某个重大公告值得由用户参与塑造的长篇内容，请在今晚文件中将其写成提案，并附上建议大纲——不要自主尝试完成它。

## 风格检查清单（任一项不通过就删除草稿）

- [ ] 听起来像一位构建者在分享，而不是新闻机器人（“我试了”“我弄坏了”“这件事让我很意外”）
- [ ] 至少包含一项只有这位用户才能表达的内容（他们的设置、数据、PoC 或视角）
- [ ] 不使用 AI 垃圾内容词汇（“game-changer”“revolutionary”“unleash”），不堆砌表情符号，话题标签数量不超过上限
- [ ] 已附加媒体；包含链接；不含任何机密信息
- [ ] 不是重复内容（已检查台账 + 最近的帖子）

## 循环（参见 /loop-engineering）

每晚都会跨多次运行执行扫描，直到预算耗尽：今晚文件是共享的循环状态，台账是去重验证器，数量预算是硬性上限，风格检查清单是质量门禁。终止条件：预算已耗尽、没有任何内容评分达到 ≥11，或者环境门禁阻止发布。
