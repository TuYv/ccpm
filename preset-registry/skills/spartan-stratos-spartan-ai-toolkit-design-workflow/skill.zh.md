# 设计工作流技能

用于让 UI 设计不像 AI 生成的指导原则。这些规则适用于任何设计工作——原型、设计文档或 UI 代码。

## 本技能的功能

1. 教你如何避免“泛用 AI”式设计模式
2. 提供设计质量检查清单
3. 指导逐个组件的设计方法
4. 设定原型质量标准

## 规则 1：使用现有设计系统

**绝不发明新的颜色、字体或间距。**始终使用项目中已定义的内容。

### 首先要阅读的内容
1. `.planning/design-config.md` —— 项目颜色、字体、间距、品牌识别
2. design-config 中列出的主题文件 —— 实际的 CSS tokens
3. 代码库中已有的组件 —— 与它们保持一致的模式

### 要点
- 使用项目调色板中的精确十六进制值（而不是像 `bg-blue-500` 这样的 Tailwind 默认值）
- 使用项目指定的字体——不要换成 Inter、Poppins 或 Space Grotesk
- 使用项目定义的圆角和阴影值
- 引用 CSS 变量或 tokens——不要硬编码

---

## 规则 2：避免泛用 AI 模式

这些模式会大声宣告“这是 AI 做的”——全部避免：

### 颜色
- 不要使用项目调色板之外的颜色
- 不要随意的紫色/紫罗兰色渐变（AI 第一大陈词滥调）
- 不要霓虹色或彩虹渐变
- 不要灰上加灰而没有强调色
- 使用项目的强调色——这正是让它独特的原因

### 布局
- 不要所有内容都居中、每个区域都设置统一的 max-width
- 不要在 hero 区文字后面放一个巨大的渐变色块
- 不要三列特性卡片配上一模一样的图标
- 不要每个区域都是图片在右、文字在左的 50/50 分栏
- 偶尔打破网格——不对称更有趣

### 排版
- 不要所有内容都用单一字号
- 建立清晰的层级：大标题、中等副标题、小正文
- 使用字重对比
- 不要对长文本块使用居中对齐

### 组件
- 不要全是一模一样的圆角矩形
- 让卡片有视觉多样性——不同的尺寸、重点与普通的区分
- 按钮应有清晰的 primary/secondary/ghost 层级
- 不要什么都加图标——有时文字更好

### 文案
- 不要泛泛的营销空话（"Unlock your potential"、"Take it to the next level"）
- 要具体——使用真实的功能名称和真实的数字
- 与 design-config 中 Design Personality 的语气保持一致

---

## 规则 3：逐个组件进行设计

不要一次设计整页。先构建各个部分，再进行组合。

### 工作顺序
1. **Design tokens** —— 从现有主题文件确认颜色、字体、间距
2. **基础组件** —— Button、Card、Badge、Input（小型、独立）
3. **复合组件** —— Nav bar、Sidebar、Hero section、Feature card
4. **完整屏幕** —— 将组件组合成页面
5. **状态** —— 为每个组件添加加载、空、错误状态
6. **响应式** —— 为手机/平板/桌面端调整每个屏幕

---

## 规则 4：使用视觉参考

当提供参考时：
1. 研究它好看的原因（布局、颜色、排版、留白）
2. 从中获取灵感而非照搬——对齐的是质量水平，而不是精确布局
3. 应用到项目的设计系统中

当完全没有参考时：
- 查看 design-config 中的 Reference Apps
- 关注留白——空间越多 = 越显高级
- 少用强调色——最多占屏幕的 10-15%
- 每个区域让一个元素大而醒目（层级）

---

## 规则 5：原型质量标准

### 必须具备
- 来自项目主题文件的精确颜色
- 加载真实字体
- 恰当的间距（不是到处随机的 padding）
- 真实内容（不是 "Lorem ipsum"）
- 所有状态可见（加载、空、错误、成功）
- 响应式：在 375px、768px、1440px 下正常显示

### 绝不可有
- 占位图片或图库照片 URL
- Tailwind 默认颜色
- 缺少 hover/focus 状态
- 在任何视口下布局错乱
- 难以阅读的文字（检查对比度）
