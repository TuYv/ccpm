# Suede 内容编辑部

六个指向同一品牌的聊天机器人并不等于一个内容团队。内容编辑部是连接它们的循环，而其中的每一条箭头都是带有契约的交接：

```text
idea -> research -> angle -> flagship -> distribution -> review -> performance -> playbooks
```

断开其中一条箭头，失败就会变得可预期，而不再神秘：

| 断开的箭头 | 实际发布的内容 |
|---|---|
| 研究结果没有传到策略师手中 | 一个任何竞争对手都能写出的泛泛角度 |
| 写作者看不到证据包 | 论断比来源实际表达的内容多走了一步 |
| 分发从完成的初稿开始 | 五个渠道承载着同一篇缩短后的文章 |
| 表现数据没有反馈到作战手册 | 以更高的频率重复同一个错误 |

这项技能负责整个流程：由谁决定什么、哪些内容在角色之间流转，以及一个想法如何变成多个各自论证不同观点的资产。如果 `.agents/product-marketing.md` 存在，请先阅读它——其中包含产品、受众、定位和证明材料，而这里不会重复这些内容。

## 第 1 步——把活动写入文件，而不是留在对话中

每个活动在 `.agents/newsroom/<slug>.md` 中对应一条记录。它是唯一必须在不同角色、不同会话和重启之间保留下来的东西。

角色之间的对话有两个文件不会遇到的失败模式：重启后上下文消失，而下一个角色必须推断哪些句子是承重的。记录为每个角色提供可预测的输入，也让人类无需重新打开六个会话就能审计一项活动。

保持记录聚焦——只记录决策及其背后的证据。初稿放在旁边，不要放进记录中。模板和各阶段的完成规则见 [references/campaign-record.md](references/campaign-record.md)。

## 第 2 步——让每个角色负责一个决策

毁掉多智能体内容团队最快的方法，就是给每个角色同一条指令：创作优秀内容。每个角色负责一个决策、产出一个工件，并有一个明确的停止点。

| 角色 | 负责 | 返回 | 交给 |
|---|---|---|---|
| 信号侦察员 | 一个想法现在是否有存在的理由 | 评分后的候选项 | 研究员 |
| 研究员 | 哪些内容已验证，哪些内容是推断 | 证据包 | 策略师 |
| 策略师 | 唯一的编辑角度 | 角度简报 | 写作者 |
| 写作者 | 这个想法最深入的版本 | 主内容 | 分发角色 |
| 分发角色 | 每个渠道要论证什么 | 带有内容入口的资产集 | 编辑 |
| 编辑 | 整套内容是否前后一致 | 批准、修改或拒绝 | 人类 |

每份契约都包含五个字段——**负责**、**读取**、**返回**、**不得**、**完成条件**。六个角色的完整文本，以及 `must not` 和 `done when` 条款，见 [references/role-contracts.md](references/role-contracts.md)。请逐字复制；对 `must not` 的改写，正是写作者开始挑选角度的起点。

**让契约可检查的阈值：**

- 侦察员最多返回三个候选项，每个候选项都要包含一个衰减窗口，并为它淘汰的每个候选项说明拒绝理由。一个批准了所有发现内容的运行过程，实际上什么都没有筛选。
- 研究员返回三到七条已验证的论断，每条具有影响的论断都要附带一个 URL，并明确列出`来源无法证明的内容`。
- 策略师只返回一个推荐角度，并至少列出两个被拒绝的方向以及每个方向较弱的原因。提供菜单会把决策推回给人类，而做出这个决策正是该角色存在的意义。
- 分发角色为每个资产返回一个内容入口，并且不得重复使用任何内容入口。
- 编辑在一次审阅中共同检查所有资产，绝不逐个检查。

## 第 3 步——为每次交接设置门槛

当一个阶段负责的每个字段都已填写完毕，并且下一角色能够读取时，该阶段才算完成——不是起草出来，不是讨论过，而是写入记录。

**退回发送者。** 当当前阶段需要的字段为空时，该角色应将记录退回，并指出该字段。不得用看似合理的假设填补空缺。一个由各角色互相修补空缺的流水线，产出的是没有可追溯来源的自信结果；这比活动停滞更糟，因为没有任何信号会提示问题所在。

**暂停格式。** 停止。用一行写明空字段及其所属阶段。向人类提供以下选项并等待：(1) 现在提供该字段，(2) 将记录退回一个阶段以再次尝试，(3) 缩小活动范围，直到不再需要该字段，或 (4) 终止。不得推进记录，也不得将不完整的交付包呈现为完整内容。

同一个字段被退回两次，意味着流水线无法提供它。应升级处理，而不是尝试第三次——针对同一个缺口的第三次尝试，正是编造开始的地方。

## 第 4 步——按论点分发，而不是按格式分发

这是最常失败的阶段，而且失败得悄无声息。

一篇文章不会因为少了 1,500 个单词就变成一篇短帖，通讯也不会因为把段落铺到幻灯片上就变成轮播图。这两种做法产出的资产，只是在不同长度下承载同一个论点——所以连续一周阅读下来，就像同一篇帖子重复发布。

**从角度简报着手，而不是从完成的草稿着手。** 一份草稿承载一个论点，因此从它衍生出的任何内容都会继承这个论点。先读草稿，正是制造缩短版文章的机制。

### 为每项资产分配一个切入口

| 切入口 | 它提出的论点 | 需要 |
|---|---|---|
| **证据** | 这是真实的，证据在这里 | 某个陌生人可以核验的材料 |
| **机制** | 它之所以有效，原因在这里 | 因果链，而不是描述 |
| **工作流** | 你今天就可以运行它 | 某人可以遵循的有序步骤 |
| **风险** | 这里是会出问题的地方，以及发生的时机 | 一个明确指出的故障模式及其触发条件 |
| **结果** | 这里是它产出的结果 | 一个结果及其条件 |
| **批评** | 常见做法比看上去更糟 | 真正的默认做法，以及它如何失败 |
| **压缩** | 整体形态就在这里 | 将想法压缩成一行文字或一张图 |

每项资产只能有一个切入口。一项资产如果承载两个切入口，就是一篇披着标签的缩短版文章。来源无法提供的切入口即不可用——应报告这一点，并说明需要什么证据才能解锁它，而不是编造一份材料来填补空缺。

各切入口的具体示例、表面适配方式，以及每个切入口会陷入的失败模式，见 [references/entryways.md](references/entryways.md)。

### 评估每项资产能否独立成立

针对整组资产执行三项检查，每项通过得一分：

| 检查 | 在以下情况下通过 |
|---|---|
| **新信息** | 它承载了其他资产都没有承载的主张、步骤、数字或对象 |
| **第二位读者** | 已经读过旗舰内容的人仍能从中获得一些东西；“链接里有更多内容”不算 |
| **移除** | 删除它会让活动失去某个具体且可以明确命名的东西 |

3 个发布。2 个退回修改，并指出未通过的检查项。0–1 个则砍掉，并说明这组内容失去了什么——通常什么也没失去。

### 运行冲突检查

先将每个素材压缩成一句话；比较完整草稿会掩盖冲突。

1. **主张冲突** —— 两个素材的核心主张是同一句话。
2. **开头冲突** —— 两个素材以同一个故事、统计数据或句子开头。  
   这是最常见、也最容易被同时关注两个渠道的人察觉的冲突。
3. **入口冲突** —— 同一个入口被使用了两次。

**暂停格式。** 停止。指出两个素材、冲突类型，以及它们共用的句子。提供以下选项：(1) 将其中一个重新分配到未使用的入口，(2) 砍掉较弱的那个，并说明这组内容失去了什么，或 (3) 将其记录为有意重复，并说明原因。等待。不要通过改写措辞来解决冲突——真正发生冲突的是底层主张。

渠道数量少于入口数量是正常的。拥有三个不同入口的三个素材，胜过使用两个入口的七个素材。

## 步骤 5——让人在编辑边界处把关

第一个版本负责准备一切，但不发布任何内容。人需要批准切入角度、主稿、每一项重要事实性主张、每一条公开发布的内容、任何对语气或方案的更改，以及任何在成为长期规则之前的效果经验。

每一次批准和拒绝，都是一个标记了人工判断的示例。当同一个决定在连续三次营销活动中以相同方式再次出现时，将其纳入编辑器的审核规则，使其在人看到整套内容之前就被应用。

**只有在以下两点同时满足时，才转移发布权限：** 内容队列已连续三次营销活动无需修改，并且错误发布的内容可以通过删除来挽回。自主化应该移除重复决策，而不是移除品味判断。

## 步骤 6——让效果重写操作手册

报告数字不是学习。每次营销活动结束后，记录信号、角度、入口、渠道、触达量、有意义的互动，以及与目标相关的行动。然后让编辑器返回三张清单：

| 清单 | 达标标准 |
|---|---|
| **保留** | 在两次或更多营销活动中表现稳定，并且仍符合策略 |
| **测试** | 一次有希望的结果——形成假设，再运行一次 |
| **停止** | 失败两次、与另一个素材重复，或投入成本高于带来的回报 |

每项提案都要列出支持它的营销活动。一次强劲的结果属于**测试**，绝不属于**保留**。任何规则变更都必须先获得人的批准。没有这条反馈链，每次营销活动就会永远从同一个通用提示开始。

按入口记录，而不只是按渠道记录——经过几次营销活动后，这会揭示受众实际走进的是哪扇门，这比知道哪个平台表现更好更有用。

## 在现有主机上运行

六个角色是模型，而不是托管要求。

| 主机 | 角色映射方式 | 会出现什么问题 |
|---|---|---|
| 一个会话 | 每个角色运行一遍，在角色之间记录重新阅读 | 角色混淆——它会编辑自己的草稿 |
| 子代理 | 每个角色一个子代理，按阶段顺序调度 | 如果每个子代理都拖入完整上下文，会产生额外成本 |
| 独立配置文件 | 每个角色一个，记忆彼此隔离 | 如果它们通过聊天协调，会出现偏移 |
| 一个人 | 按顺序为每个角色各进行一次工作 | 什么也不会出问题；这是诚实的第一周 |

无论宿主是什么，始终有两条规则成立。**对话负责协调；文件承载状态。**
并且，**在宿主允许的情况下隔离角色记忆**——共享记忆会让六个专家重新变成一个读过所有内容、却什么都无法区分的通才。

## 从少于六个角色开始

先建立侦察员、研究员和编辑，让它们处理三个真实想法。等三份证据包中有两份无需返工后，再加入策略师；等简报能够约束草稿、不再需要进一步提问后，再加入写作者；等一篇旗舰内容发布并完成测量后，再加入分发角色。

第一个有用版本会交付一个经过研究的机会、一个角度简报，以及一篇附有来源、可供审批的帖子。这已经超过了大多数内容运营所能产出的成果。

## 反模式

- **六个角色共用一份记忆**——专家会坍缩成一个对所有事情都有看法的通才。
- **散文式交接**——下一个角色只能猜测哪些句子是承重的。
- **角色互相填补空缺**——输出看似自信，却没有可追溯的来源。
- **拆分草稿而不是拆分论点**——只会产出不同长度的版本。
- **用七种方式重写同一个钩子**——底层主张完全相同，因此即使措辞不同，读者仍然会看出重复。
- **先加入写作者**——这是最显眼的角色，但如果面前没有证据包，它产生的价值最少。
- **没有人将其转化为规则的表现日志**——分析剧场。

## 禁用词汇

避免使用 `"fully autonomous media company"`、`"content on autopilot"`、`"replaces a marketing team"`、`"repurpose"`、`"atomize"` 和 `"one piece into fifty posts"`。前三个词掩盖了审批步骤；后三个词描述的是重新格式化，而用这种方式命名工作，就会产出这种工作。要说明每项资产提出的是哪个论点。

## 边界

- 不要发布、排期或发送任何内容。流水线负责准备内容包；由人来发布。
- 不要记录没有支持来源的主张，也不要在任何阶段将推断升级为已验证的主张。
- 不要在分发阶段引入证据包未携带的主张、数字或引语。
- 不要为了填补来源不支持的入口而臆造证明对象、结果或失败模式。将该入口报告为不可用。
- 不要将未评分的资产集呈现为已准备就绪，也不要通过改写而不是重新分配来解决冲突。
- 不要在负责该阶段的记录字段尚未填满时报告阶段完成，也不要捏造触达量或互动量。未测量的活动应记录为未测量。

## 路由

- 流水线应该处理哪些主题、支柱或集群 -> 使用
  `suede-content-strategy`。该技能决定处理什么；本技能决定如何流转。
- 平台组合、发布频率、日历、监听，以及从长篇内容中提取原子内容
  -> 使用 `suede-social`。Instagram 专属项目 -> 使用
  `suede-instagram-growth`。
- 已排期阶段的发布频率、状态、幂等性和停止条件 -> 使用
  `suede-marketing-loops`。
- 为高风险公共渠道撰写旗舰内容 -> 使用 `suede-ship-copy`。
  单个较短渠道 -> 使用 `suede-copy`。
- 将一个视频片段桥接到一篇长篇指南 -> 使用 `suede-clip-to-guide`。
- 去除草稿资产中的 AI 写作模式 -> 使用 `suede-deslop`。
- 表现日志背后的测量基础设施 -> 使用 `suede-analytics`。
- 这些角度的付费版本 -> 使用 `suede-ad-creative`。
- 由代理并行编辑代码，并处理文件所有权和回滚 -> 使用
  `suede-agent-teams`。本技能覆盖编辑流程，而不是代码仓库流程。
- 来自 `suede-content-strategy` 和 `suede-social`：将角色契约、交接记录和入口分配路由回此处。
