# Suede 新闻编辑部

六个指向同一品牌的聊天机器人，不等于一个内容团队。新闻编辑部是将它们连接起来的循环，而其中的每一条箭头，都是一份带有契约的交接：

```text
idea -> research -> angle -> flagship -> distribution -> review -> performance -> playbooks
```

断掉其中一条箭头，接下来会出现什么问题是可以预料的，并不神秘：

| 断掉的箭头 | 实际发布的内容 |
|---|---|
| 研究结果没有传到策略师手中 | 一个任何竞争对手都可能写出的泛泛角度 |
| 作者没有看到证据包 | 论断比来源实际表达的内容多走了一步 |
| 分发从完成的初稿开始 | 五个渠道都在传播同一篇被缩短的文章 |
| 表现数据没有反馈到 playbooks | 以更高频率重复同一个错误 |

这项技能负责整个流程：谁决定什么、哪些内容在角色之间传递，以及一个想法如何变成多个各自论证不同观点的内容资产。如果存在 `.agents/product-marketing.md`，请先阅读它——其中包含产品、受众、定位和证明材料，而本文档不会重复这些内容。

**创始人主导模式。** 当固定的信息来源是创始人访谈、语音笔记或运营者复盘时，或者个人账号和公司账号需要承担不同职责时，请在步骤 1 之前阅读
[references/founder-content-loop.md](references/founder-content-loop.md)。它会为此流程增加一份信息接收契约和账号分工；下文的六份角色契约、证据门槛、碰撞检查、审批边界以及 Keep/Test/Stop 阈值保持不变。

## 步骤 1——将活动写入文件，而不是留在对话中

每个活动在 `.agents/newsroom/<slug>.md` 中对应一条记录。它是唯一必须在不同角色、会话和重启之间保留下来的内容。

角色之间的对话有两个文件不会遇到的问题：重启后上下文会消失，而下一个角色必须推断哪些句子是承重的。记录为每个角色提供可预测的输入，也让人类无需重新打开六个会话，就能审查一项活动。

保持内容聚焦——只记录决策及其背后的证据。草稿放在旁边，不要写入其中。模板和各阶段的完成规则见
[references/campaign-record.md](references/campaign-record.md)。

## 步骤 2——让每个角色负责一个决策

毁掉多智能体内容团队最快的方法，就是给每个角色相同的指令：制作出色的内容。每个角色只负责一个决策、一个产物，并有一个明确的停止点。

| 角色 | 负责 | 返回 | 交给 |
|---|---|---|---|
| 信号侦察员 | 一个想法现在是否有存在的理由 | 经过评分的候选项 | 研究员 |
| 研究员 | 哪些内容已验证，哪些内容是推断 | 证据包 | 策略师 |
| 策略师 | 唯一的编辑角度 | 角度简报 | 作者 |
| 作者 | 这个想法最深入的版本 | 旗舰内容 | 分发 |
| 分发 | 每个渠道要论证什么 | 带有入口的资产集 | 编辑 |
| 编辑 | 整套内容是否协调一致 | 批准、修改或拒绝 | 人类 |

每份契约都包含五个字段——**负责**、**读取**、**返回**、**不得**、**完成条件**。六份契约的完整文本，以及其中的 `must not` 和 `done when` 条款，见
[references/role-contracts.md](references/role-contracts.md)。请逐字复制；对 `must not` 的改写，正是作者开始自行选择角度的起点。

**让契约可检查的阈值：**

- Scout 最多返回三个候选项，每个候选项都带有一个衰减窗口，并为它放弃的每个候选项说明拒绝原因。一轮运行如果批准了它找到的所有内容，就说明它没有进行任何筛选。
- Researcher 返回三到七条经过验证的断言，为每条会产生后果的断言提供一个 URL，并明确列出 `what the sources do not prove`。
- Strategist 恰好返回一个推荐角度，另外至少列出两个明确命名的被拒方向，并说明每个方向为何较弱。提供选单会把决策推回给人类，而做出这个决策正是该角色存在的意义。
- Distribution 为每个资产返回一个入口，且任何入口都不得重复。
- Editor 在一次流程中共同审阅所有资产，绝不逐个审阅。

## 第 3 步——为每次交接设置关卡

当某个阶段负责的每个字段都已填写，并且下一个角色能够读懂时，该阶段才算完成——不是草拟完成，也不是讨论过，而是写入记录。

**退回发送方。** 当当前阶段需要的某个字段为空时，该角色将记录退回，并指出该字段。它不会用看似合理的假设来填补空缺。一个由各角色互相弥补缺口的流水线，会产出没有可追溯来源却充满自信的结果；这比停滞的活动更糟糕，因为没有任何信号表明问题所在。

**暂停格式。** 停止。用一行指出空字段及其所属阶段。向人类提供以下选项并等待：(1) 立即提供该字段，(2) 将记录退回一个阶段，再尝试一次，(3) 缩小活动范围，直到不再需要该字段，或 (4) 终止。不要推进记录，也不要把不完整的方案当作完整方案呈现。

同一个字段被退回两次，意味着流水线无法提供它。应当升级处理，而不是尝试第三次——对同一个缺口进行第三次尝试，正是编造开始的地方。

## 第 4 步——按论点分发，而不是按格式分发

这是最常失败的阶段，而且失败得悄无声息。

一篇文章不会因为删去 1,500 个词就变成一篇短帖，一份 newsletter 也不会因为把段落铺到幻灯片上就变成轮播图。这两种做法都会产出以不同长度承载同一论点的资产——这正是为什么一周下来，读起来像是同一篇帖子被重复发布。

**从角度简报着手，而不是从完成的草稿着手。** 一份草稿承载一个论点，因此任何从它派生的内容都会继承该论点。先阅读草稿，正是产出缩短版文章的机制。

### 为每个资产分配一个入口

| 入口 | 它提出的论点 | 需要 |
|---|---|---|
| **证据** | 这是真实的，而这就是证据 | 陌生人可以核查的内容 |
| **机制** | 这就是它为何有效 | 因果链，而不是描述 |
| **工作流** | 你今天就可以运行它 | 某人可以遵循的有序步骤 |
| **风险** | 这就是会出什么问题，以及何时出问题 | 一个明确命名的故障模式及其触发条件 |
| **结果** | 这就是它产出的结果 | 一个结果及其条件 |
| **批评** | 常见做法比看起来更糟 | 真正的默认做法，以及它如何失败 |
| **压缩** | 这就是整体形态 | 将想法压缩成一行文字或一张图 |

每个素材只能有一个切入口。一个带有两个切入口的素材，只是披着标签的缩短版文章。来源无法提供的切入口就是不可用的——应报告这一点，并说明需要什么证据才能解锁它，而不是凭空捏造一个产物来填补空缺。

[references/entryways.md](references/entryways.md)中列出了实际示例、表面适配情况，以及每个切入口会落入的失败模式。

### 评估每个素材能否独立成立

针对整组素材进行三项检查，每项一分：

| 检查项 | 在以下情况下通过 |
|---|---|
| **新信息** | 它承载了其他素材都没有承载的论点、步骤、数字或对象 |
| **第二位读者** | 已经读过旗舰素材的人仍能从中获得一些东西；“链接中有更多内容”不算 |
| **移除** | 删除它会让活动失去某个具体且可以明确命名的东西 |

得分为 3 分即可发布。得分为 2 分则退回修改，并指出未通过的检查项。得分为 0–1 分则删掉，并说明整组素材会失去什么——通常什么也不会失去。

### 运行冲突闸门

先把每个素材压缩成一句话；比较完整草稿会掩盖冲突。

1. **论点冲突**——两个素材的核心论点是同一句话。
2. **开头冲突**——两个素材用同一个故事、统计数据或句子开头。这是最常见、也最容易被同时关注两个渠道的人察觉的冲突。
3. **切入口冲突**——同一个切入口被使用了两次。

**暂停格式。** 停止。指出两个素材、冲突类型以及共享的句子。提供以下选项：(1) 将其中一个重新分配到未使用的切入口；(2) 删除较弱的一个，并说明整组素材会失去什么；或 (3) 将其记录为有意重复，并说明理由。等待。不要通过改写措辞来解决冲突——真正发生冲突的是底层论点。

发布渠道少于切入口是正常的。三个拥有三个不同切入口的素材，胜过七个素材共用两个切入口。

## 步骤 5 — 将人工置于编辑边界

第一个版本准备好一切，但不发布任何内容。人工需要批准切入角度、旗舰稿、每一项重要事实性论断、每一条公开帖子、任何对语气或 oferta 的更改，以及任何在成为固定规则之前的绩效经验。

每一次批准和拒绝，都是一个带标签的人类判断示例。当同一个决定连续三个活动都以同样的方式返回时，就将其纳入编辑器的审核规则，使其在人看到这组内容之前就得到应用。

**只有在以下两个条件同时满足时，才转移发布权限：** 队列连续三个活动都没有产生修改，并且错误发布的帖子可以通过删除来恢复。自主性应该移除重复决策，而不是移除品味。

## 步骤 6 — 让绩效重写操作手册

报告数字不等于学习。每次活动结束后，记录信号、角度、切入口、渠道、触达量、有意义的互动，以及与目标相关的行动。然后让编辑返回三份列表：

| 列表 | 达标标准 |
|---|---|
| **保留** | 在两个或更多活动中持续有效，并且仍然符合策略 |
| **测试** | 一次有希望的结果——形成一个假设，再运行一次 |
| **停止** | 失败两次、与另一个素材重复，或成本高于带来的回报 |

每个提案都会列出支持它的活动。一项强有力的结果是**测试**，而不是**保留**。任何规则变更都必须先获得人的批准。没有这条箭头，每个活动都会永远从同一个通用提示开始。

按入口记录，而不只是按表面记录——经过几次活动后，这会揭示受众实际是从哪扇门进入的；相比之下，这比知道哪个平台表现更好更有用。

## 在现有主机上运行

六个角色是模型，而不是主机要求。

| 主机 | 角色映射到 | 会出什么问题 |
|---|---|---|
| 一个会话 | 每个角色执行一轮，其间重新读取记录 | 角色混淆——它会编辑自己的草稿 |
| 子代理 | 每个角色一个子代理，按阶段顺序调度 | 成本问题，如果每个子代理都拖带完整上下文 |
| 独立配置文件 | 每个角色一个，记忆相互隔离 | 协作漂移，如果它们通过聊天协调 |
| 一个人 | 每个角色单独进行一次，按顺序完成 | 没有问题；这是第一周最诚实的做法 |

无论使用哪种主机，都有两条规则始终成立。**对话负责协调；文件负责承载状态。**
并且，在主机允许的情况下，**隔离角色记忆**——一份共享记忆会把六个专家重新变成一个什么都读过、却无法区分任何东西的通才。

## 从少于六个角色开始

先建立侦察员、研究员和编辑这三个角色，并让它们处理三个真实想法。等到三个证据包中有两个无需返工后，再加入策略师；等到简报能够约束草稿、无需进一步提问后，再加入写作者；等到一个旗舰内容发布并完成衡量后，再加入分发角色。

第一个有用版本会交付一个经过研究的机会、一个角度简报，以及一篇附有来源、可供批准的帖子。这已经超过了大多数内容运营所能产出的成果。

## 反模式

- **六个角色共用一份记忆**——专家会坍缩成一个对所有事情都有看法的通才。
- **用散文式交接**——下一个角色只能猜测哪些句子是承重的。
- **让角色互相填补空白**——输出看似自信，却没有可追溯的来源。
- **拆分草稿，而不是拆分论点**——只会产生不同长度的版本。
- **把一个钩子改写成七种说法**——底层主张完全相同，所以即使措辞不同，读者仍然会看出重复。
- **先添加写作者**——这是最显眼的角色，但如果面前没有证据包，它产生的价值最少。
- **没有人将其转化为规则的表现日志**——分析作秀。

## 禁用词汇

避免使用“完全自主的媒体公司”“内容自动驾驶”“取代营销团队”“再利用”“原子化”和“一个内容变成五十篇帖子”。前三个词掩盖了审批步骤；后三个词描述的是重新排版，而用这种方式命名工作，就会产生这样的工作。要说明每项资产提出了哪个论点。

## 边界

- 不要发布、排期或发送任何内容。流水线负责准备内容包；由人来发布。
- 不要记录没有支持来源的主张，也不要在任何阶段将推断升级为已验证的主张。
- 不要在分发阶段引入证据包中没有的主张、数字或引语。
- 不要为了填补来源不支持的入口而编造证明对象、结果或失败模式。将该入口报告为不可用。
- 不要将未经评分的资产集呈现为已准备就绪，也不要通过改写而不是重新分配来解决冲突。
- 不要在负责该阶段的记录字段尚未填满时报告阶段完成，也不要捏造触达量或互动量。未经衡量的活动应记录为未经衡量。

## 路由

- 管道应处理哪些主题、支柱或集群 -> 使用
  `suede-content-strategy`。该技能决定其操作对象；本技能决定其推进方式。
- 平台组合、发布频率、日历、监听，以及从长篇内容中提取原子内容
  -> 使用 `suede-social`。针对 Instagram 的专项计划 -> 使用
  `suede-instagram-growth`。
- 计划阶段的发布频率、状态、幂等性和停止条件 -> 使用
  `suede-marketing-loops`。
- 为高风险公共渠道撰写旗舰内容 -> 使用 `suede-ship-copy`。
  单个较短渠道 -> 使用 `suede-copy`。
- 将一个视频片段衔接到一篇长篇指南 -> 使用 `suede-clip-to-guide`。
- 从已起草的资产中去除 AI 写作模式 -> 使用 `suede-deslop`。
- 性能日志背后的度量基础设施 -> 使用 `suede-analytics`。
- 这些角度的付费版本 -> 使用 `suede-ad-creative`。
- 由代理并行编辑代码，并处理文件所有权和回滚 -> 使用
  `suede-agent-teams`。此技能涵盖编辑流程，而非代码仓库流程。
- 从 `suede-content-strategy` 和 `suede-social` 开始：将角色契约、
  交接记录和入口分配路由回此处。
