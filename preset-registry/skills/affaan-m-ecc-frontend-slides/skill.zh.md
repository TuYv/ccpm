# 前端幻灯片

创建零依赖、动画丰富且完全在浏览器中运行的 HTML 演示文稿。

灵感来自 [zarazhangrui](https://github.com/zarazhangrui) 作品中展示的视觉探索方法。

## 何时启用

- 创建演讲幻灯片、推介幻灯片、研讨会幻灯片或内部演示文稿
- 将 `.ppt` 或 `.pptx` 幻灯片转换为 HTML 演示文稿
- 改进现有 HTML 演示文稿的布局、动效或排版
- 与尚不清楚自己设计偏好的用户一起探索演示文稿风格

## 不可妥协的要求

1. **零依赖**：默认生成一个内联 CSS 和 JS 的自包含 HTML 文件。
2. **必须适配视口**：每张幻灯片都必须完整容纳在一个视口内，且不得出现内部滚动。
3. **展示，而非讲述**：使用视觉预览，而非抽象的风格问卷。
4. **独特的设计**：避免通用的紫色渐变、白底 Inter 字体以及模板化的幻灯片。
5. **生产级质量**：确保代码有注释、具备无障碍性、响应式且高性能。

生成之前，请阅读 `STYLE_PRESETS.md`，了解视口安全的 CSS 基础、内容密度限制、预设目录和 CSS 注意事项。

## 工作流程

### 1. 检测模式

选择一种路径：
- **新建演示文稿**：用户已有主题、笔记或完整草稿
- **PPT 转换**：用户已有 `.ppt` 或 `.pptx`
- **增强**：用户已有 HTML 幻灯片并希望进行改进

### 2. 了解内容

仅询问必要的最少信息：
- 用途：推介、教学、会议演讲、内部更新
- 长度：短篇（5-10 张）、中篇（10-20 张）、长篇（20 张以上）
- 内容状态：定稿文案、粗略笔记、仅有主题

如果用户已有内容，请在设计样式之前让他们粘贴内容。

### 3. 探索风格

默认采用视觉探索。

如果用户已经知道所需的预设，请跳过预览并直接使用该预设。

否则：
1. 询问演示文稿应该营造何种感受：令人印象深刻、充满活力、专注或鼓舞人心。
2. 在 `.ecc-design/slide-previews/` 中生成 **3 个单页幻灯片预览文件**。
3. 每个预览都必须是自包含的，清晰展示字体排版、色彩和动效，并将幻灯片内容控制在大约 100 行以内。
4. 询问用户要保留哪个预览，或希望混合哪些元素。

将情绪映射到风格时，请使用 `STYLE_PRESETS.md` 中的预设指南。

### 4. 构建演示文稿

输出以下任一种文件：
- `presentation.html`
- `[presentation-name].html`

仅当演示文稿包含提取的图片或用户提供的图片时，才使用 `assets/` 文件夹。

必需结构：
- 语义化的幻灯片区段
- 来自 `STYLE_PRESETS.md` 的视口安全 CSS 基础
- 用于主题值的 CSS 自定义属性
- 用于键盘、滚轮和触摸导航的演示文稿控制器类
- 用于呈现动画的 Intersection Observer
- 对减少动态效果偏好的支持

### 5. 强制适配视口

将此视为硬性门槛。

规则：
- 每个 `.slide` 都必须使用 `height: 100vh; height: 100dvh; overflow: hidden;`
- 所有字号和间距都必须使用 `clamp()` 进行缩放
- 当内容无法容纳时，将其拆分到多张幻灯片中
- 绝不能通过将文本缩小到低于可读尺寸来解决溢出问题
- 绝不允许幻灯片内部出现滚动条

使用 `STYLE_PRESETS.md` 中的密度限制和强制 CSS 块。

### 6. 验证

在以下尺寸下检查完成的演示文稿：
- 1920x1080
- 1280x720
- 768x1024
- 375x667
- 667x375

如果可以使用浏览器自动化，请用它验证所有幻灯片均无内容溢出，并且键盘导航正常工作。

### 7. 交付

交接时：
- 删除临时预览文件，除非用户希望保留
- 适当时，使用与平台相匹配的打开工具打开演示文稿
- 汇总文件路径、所用预设、幻灯片数量以及便于自定义主题的要点

根据当前操作系统使用正确的打开命令：
- macOS：`open file.html`
- Linux：`xdg-open file.html`
- Windows：`start "" file.html`

## PPT / PPTX 转换

对于 PowerPoint 转换：
1. 优先使用带有 `python-pptx` 的 `python3` 来提取文本、图像和备注。
2. 如果 `python-pptx` 不可用，请询问是否安装，或回退到手动/基于导出的工作流。
3. 保留幻灯片顺序、演讲者备注和提取的资源。
4. 提取后，按照新演示文稿执行相同的样式选择工作流。

确保转换过程跨平台。能够使用 Python 完成时，不要依赖仅限 macOS 的工具。

## 实现要求

### HTML / CSS

- 除非用户明确要求多文件项目，否则使用内联 CSS 和 JS。
- 字体可来自 Google Fonts 或 Fontshare。
- 优先使用富有氛围感的背景、鲜明的字体层级和清晰的视觉方向。
- 使用抽象形状、渐变、网格、噪点和几何图形，而不是插图。

### JavaScript

应包括：
- 键盘导航
- 触摸/滑动导航
- 鼠标滚轮导航
- 进度指示器或幻灯片索引
- 进入时触发的显现动画

### 无障碍

- 使用语义化结构（`main`、`section`、`nav`）
- 保持易读的对比度
- 支持纯键盘导航
- 遵循 `prefers-reduced-motion`

## 内容密度限制

除非用户明确要求幻灯片承载更密集的内容，并且仍能保持可读性，否则使用以下上限：

| 幻灯片类型 | 限制 |
|------------|-------|
| 标题 | 1 个标题 + 1 个副标题 + 可选的标语 |
| 内容 | 1 个标题 + 4-6 个项目符号，或 2 个短段落 |
| 功能网格 | 最多 6 张卡片 |
| 代码 | 最多 8-10 行 |
| 引用 | 1 条引用 + 署名 |
| 图像 | 1 张受视口约束的图像 |

## 反模式

- 缺乏视觉辨识度的通用创业公司风格渐变
- 使用系统字体的演示文稿，除非是有意采用编辑设计风格
- 冗长密集的项目符号列表
- 需要滚动查看的代码块
- 在较矮屏幕上会出现布局破坏的固定高度内容框
- 类似 `-clamp(...)` 的无效取反 CSS 函数

## 交付物检查清单

- 演示文稿可通过浏览器从本地文件运行
- 每张幻灯片均适配视口，无需滚动
- 风格独特且设计意图明确
- 动画有实际意义，而非制造干扰
- 遵循减少动态效果的偏好设置
- 交接时说明文件路径和自定义要点
