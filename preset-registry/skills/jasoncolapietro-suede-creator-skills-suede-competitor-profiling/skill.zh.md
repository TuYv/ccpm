# Suede 竞争对手画像

使用这套 Suede 竞争情报行动手册，将当前的公开证据转化为结构化画像，并将事实、推断和未知信息分别保留。

## 初步评估

检查 `.agents/product-marketing.md`（或 `.claude/product-marketing.md`，或旧版的 `product-marketing-context.md`）是否存在，如存在则读取——你自身的定位和 ICP 决定了哪些竞争对手真正具有可比性，以及哪些维度值得进行画像分析，而这些信息通常已经记录在其中。

然后处理下方“特定任务问题”中的信息收集清单。如果用户提供了 URL，且上下文文件涵盖了其余信息，则无需提问，直接继续。

---

## 保存原始数据

在综合画像之前，将所有原始页面抓取结果、SEO 输入和评测证据持久化到磁盘，以便重新读取、审计或复用，避免重复请求数据提供方或手动收集。

**目录结构**（相对于项目根目录）：

```
competitor-profiles/
├── raw/
│   └── <competitor-slug>/
│       └── <YYYY-MM-DD>/
│           ├── scrapes/    # one .md file per captured page (homepage.md, pricing.md, ...)
│           ├── seo/        # one .json or .csv file per authorized metric source
│           └── reviews/    # one .md or .json file per review source (g2.md, capterra.md, ...)
├── <competitor-slug>.md    # final synthesized profile
└── _summary.md             # cross-competitor summary
```

规则：

- `<competitor-slug>` 使用小写字母和连字符（例如 `responsehub`、`safe-base`）
- `<YYYY-MM-DD>` 是数据提取日期——支持随着时间推移重新运行并比较快照差异
- 将每个通过浏览器、手动方式或经授权获取的页面捕获结果，以原始 markdown 格式保存到 `scrapes/<page-name>.md`
- 将每个经授权获取的 SEO 响应或用户提供的导出文件保存到 `seo/<source-name>.<json|csv>`
- 将每个评测来源保存到 `reviews/<source>.md`（清理后的文本）或 `.json`（原始数据）
- 每次新运行时始终新建日期文件夹；绝不覆盖此前日期的数据

综合后的画像（`<competitor-slug>.md`）应在其 `## Raw Data Sources` 部分引用生成该画像所依据的原始数据文件夹。

## 研究流程

### 阶段 1：公开网站证据

针对每个竞争对手 URL，抓取关键公开页面，以提取其定位、功能、定价和信息传达内容。

**可用性门槛：** 在选择数据获取方式之前，检查当前会话中实际暴露的工具。只有当某个命名连接器确实可用、在适用时已连接到目标账户、已获授权执行此任务，并且其当前 schema 已被读取时，才能使用该连接器。不要根据下方示例臆造工具调用。

如果没有可用的映射工具或页面获取工具，则使用与浏览器无关的/手动备用方式：打开公开网站，沿其主要导航浏览；在可访问时检查其公开 sitemap 或搜索结果；记录确切 URL 和访问日期；并且只捕获用户可见的证据。遵守访问控制、网站条款、适用的 robots 指令以及速率限制。

**当访问闸门阻止你时** — 如果某个来源需要你未获提供的账户、某个平台未连接、某个网站的条款或 robots 指令使页面不可访问，或者用户希望在未授权的情况下发布或转发资料包 — 请分四步暂停处理：

1. 停止。不要收集受阻的来源，也不要发布资料包。
2. 用一行说明阻碍因素（“<competitor> 的 G2 评价需要登录账户；此会话没有获得授权的 G2 连接”）。
3. 提供 2-4 个选项（不使用该来源继续，并将相关字段标记为 `not collected`；由用户提供导出文件；由用户授权连接；替换为获准的来源）。
4. 等待答复。不要自行选择其中一个选项并继续。

#### 第 1 步：梳理网站

如果当前已授权的连接器提供站点地图或爬取功能，请使用其文档规定的 schema 来发现网站结构。例如，某些 Firecrawl 连接会提供 `firecrawl_map` 操作，但不能保证名称一定如此。否则，通过手动备用方案构建 URL 列表。

```
可用的站点地图功能或手动导航 → 已验证的竞争对手 URL
```

根据站点地图，识别并优先处理以下页面类型：
- 主页
- 定价页面
- 功能 / 产品页面
- 关于 / 公司页面
- 博客（顶层页面，用于获取内容策略信号）
- 客户 / 案例研究页面
- 集成页面
- 更新日志 / 最新动态（如有）

#### 第 2 步：捕获关键页面

如果当前已授权的连接器提供单页面抓取或提取功能，请对每个已识别的 URL 使用其文档规定的 schema。比如，某些 Firecrawl 连接会提供 `firecrawl_scrape`。否则，打开每个公开页面并手动捕获相关可见文本。

```
可用的页面抓取功能或浏览器 / 手动捕获 → 页面证据
```

在提取字段之前，将每个结果保存到 `competitor-profiles/raw/<competitor-slug>/<YYYY-MM-DD>/scrapes/<page-name>.md`。

从每个页面提取：

| 页面 | 提取内容 |
|------|----------------|
| **主页** | 标题、副标题、价值主张、主要 CTA、社会证明声明、目标受众信号 |
| **定价** | 层级、价格、每个层级的功能细分、计费选项、免费层级 / 试用详情、企业定价信号 |
| **功能** | 功能类别、关键能力、对各项功能的描述方式、截图 / 演示信号 |
| **关于** | 创立故事、团队规模、融资情况、使命宣言、总部 |
| **客户** | 指名客户、Logo、服务行业、案例研究主题 |
| **集成** | 集成数量、关键集成、类别 |
| **更新日志** | 发布速度、近期重点领域、产品方向信号 |

#### 第 3 步：捕获竞争对手评价（可选但价值很高）

如果有已连接且获得授权的搜索 / 抓取工具，请使用其当前 schema 查找以下来源。否则，手动搜索或浏览这些来源。只有在相应平台确实已连接且用户已授权时，才能访问特定于平台或仅限账户访问的内容。
- 竞争对手的 G2 评价页面
- Capterra 评价页面
- Product Hunt 发布页面
- TrustRadius 资料页

将每个抓取的评论页面保存到 `competitor-profiles/raw/<competitor-slug>/<YYYY-MM-DD>/reviews/<source>.md`。然后提取：总体评分、评论数量、常见好评主题、常见差评主题，以及 3-5 条具有代表性的引述。

---

### 第 2 阶段：可选的 SEO 和市场数据

首先检查当前可用的工具和用户提供的文件。如果已公开可用且经过授权的
SEO 数据连接器，请读取其当前 schema，并为每个竞争对手收集相同的指标。某些 DataForSEO 连接使用下面列出的 capability 名称，但无法保证这些 capability 存在，也无法保证其确切 schema。如果没有可用的 provider，请分析当前由用户提供的导出文件，或将这些字段标记为 `not collected`；绝不能用猜测的值替代。

在解析之前，将每个原始响应或导出文件保存到
`competitor-profiles/raw/<competitor-slug>/<YYYY-MM-DD>/seo/`。
记录 provider、访问日期、市场、设备、数据库，并注明流量、权威度和价值指标是 provider 的估算值。有关条件式 capability 映射和手动回退方案，请参阅
[references/tool-reference.md](references/tool-reference.md)。

#### 域名权威度与反向链接

当连接的 provider 提供 `backlinks_summary` 的等效功能时，收集：
- 域名排名 / 权威度分数
- 反向链接总数
- 引荐域名数量
- 垃圾链接分数

当其提供 `backlinks_referring_domains` 的等效功能时，收集：
- 主要引荐域名（质量信号）
- 链接获取模式

#### 关键词与流量情报

当其提供排名关键词数据时，收集：
- 获得排名的自然搜索关键词总数
- 排名进入前 3、前 10、前 100 的关键词数量
- 预估自然搜索流量

当其提供域名自然搜索概览时，收集：
- 域名级自然搜索指标
- 预估流量价值
- 按流量排名的主要关键词

当其提供网站关键词发现功能时，收集：
- 他们所针对的关键词
- 与你的网站相比的内容差距

#### 竞争定位数据

当其提供自然搜索竞争对手重叠数据时，收集：
- 他们最接近的自然搜索竞争对手（可能会揭示你尚未考虑的竞争对手）
- 市场重叠数据

当其提供相关页面估算数据时，收集：
- 他们流量最高的页面
- 带来最多自然搜索价值的内容

---

### 第 3 阶段：综合分析

将抓取的内容与 SEO 数据结合起来，构建档案。交叉核对各项声明（例如，如果他们在网站上声称“拥有 10,000 名客户”，请检查其流量 / 反向链接概况是否支持这一规模）。

### 第 4 阶段：交付前验证

在档案交付前运行此检查。这只需对第 1 阶段和第 2 阶段已经生成的结构执行一次 `ls`：

```
ls -R competitor-profiles/raw/<competitor-slug>/<YYYY-MM-DD>/
```

- 每个未标记为 `[unknown]` 且未标记为 `not collected` 的字段，都必须能追溯到该文件夹中保存的文件。`[fact: ...]` 字段必须能追溯到读取该字段的 `scrapes/`、`reviews/` 或 `seo/` 文件；`[inference]` 字段必须能追溯到据此推断出它的抓取文件，而不是某个单独的产物。
- 任何无法追溯到来源的字段都必须重新收集，或重新标记为 `[unknown]`。绝不能将其弱化后写成确定性的表述——这正是下面的边界规则所禁止的。
- `## Raw Data Sources` 区块会列出构建档案所依据的日期文件夹，因此之后其他人可以重复执行相同的检查。

## 输出格式

### 竞品档案文档结构

为每个竞品生成一个 Markdown 文件，保存到项目根目录中的 `competitor-profiles/` 目录。

**文件名**：`competitor-profiles/[competitor-name].md`

**在编写一次运行中的第一个档案之前，请先阅读 [references/templates.md](references/templates.md)**：其中包含每个字段使用的证据标记图例、完整的深度档案模板、快速扫描模板，以及摘要、定位图、SWOT 和变更日志模板。不要凭记忆重建档案结构——档案之间的一致性正是使其具备可比性的关键。

深度档案依次包含以下部分：概览、定位与信息传达、产品与功能、定价、客户与社会认同、SEO 与内容策略、优势与劣势、竞争影响、原始数据来源。

---

### 摘要文档

在完成所有竞品档案后，生成一个 `competitor-profiles/_summary.md`，其中包括：

1. **竞品格局概览** — 用一段文字总结竞争领域
2. **对比表** — 并列展示所有已建档竞品的关键指标
3. **定位图** — 标示每个竞品所处的位置（例如，简单↔复杂、低价↔高端）
4. **关键要点** — 基于研究得出的 3-5 条战略观察
5. **空白与机会** — 市场中尚未得到充分满足的领域

## 快速扫描与深度档案

### 快速扫描（更快、成本更低）
- 公开网站证据：首页 + 定价页
- SEO：当授权来源或用户导出数据可用时，提供一份统一的服务商概览和排名关键词摘要；否则标记为 `not collected`
- 跳过：评价、技术栈、反向链接详情
- 输出：简化档案（概览 + 定位 + 定价 + SEO 摘要）

### 深度档案（全面）
- 公开网站证据：所有关键页面 + 可用的评价来源
- SEO：完整的反向链接分析 + 关键词情报 + 竞品发现
- 包含：技术栈、内容策略分析、评价挖掘
- 输出：完整档案模板

除非用户请求深度建档或指定较少数量的竞品（3 个或更少），否则默认使用**快速扫描**。

## 处理多个竞品

在为多个竞品建档时：

1. **仅在支持时并行处理** — 仅当可用工具支持且其配额允许时，才并发抓取相互独立的首页或定价页；否则按顺序处理
2. **使用一致的指标** — 对每个竞品使用相同的可用服务商、市场、设备、数据库、日期范围和指标定义；否则将该对比标记为不可用
3. **最后构建摘要** — 在所有单独档案完成之后
4. **按相关性排序优先级** — 如果用户提供了 10 个或更多竞品，建议先根据域名重叠度或市场相似性分析排名前 5 的竞品

## 更新档案

档案是快照。更新时：

- 首先检查定价页（波动最大）
- 仅通过相同的可用服务商，并使用匹配的市场/设备/数据库参数刷新 SEO 指标，否则将其标记为不可用
- 扫描变更日志以了解产品变化
- 更新“Generated”日期
- 在底部的 `## Change Log` 部分记录自上次建档以来发生的变化

## 任务专属问题

仅在上下文或输入中未得到回答时提问：

1. 我应该分析哪些竞争对手 URL？
2. 快速扫描还是深度分析？
3. 是否有需要重点关注的特定维度（定价、SEO、定位）？
4. 我是否应该将发现结果与你的产品进行比较？

## 边界

- 不要将推断、过时的定价、流量估算、评论摘要或功能可用性表述为已验证的当前事实。
- 不要访问私有账户、绕过控制措施、抓取禁止来源、联系竞争对手，或在未经授权的情况下发布竞争对手档案。
- 未提供明确的比较标准和证据时，不要将竞争对手标记为弱势、具有欺骗性或不合规。
- 不要决定产品、定价、法律或销售策略；应呈现有支持依据的影响和未解决的问题。

## 路由

- 需要公开的对比或替代方案页面 -> 使用 `suede-competitors`。
- 需要销售竞争卡 -> 使用 `suede-sales-enablement`。
- 需要评论和论坛综合分析 -> 使用 `suede-customer-research`。
- 需要定价、广告或内容方面的影响分析 -> 使用 `suede-pricing`、`suede-ads` 或 `suede-content-strategy`。
- 从这些技能中，将基于当前来源的竞争对手研究路由回 `suede-competitor-profiling`。
