# Figma → HyperFrames

将用户的 Figma 作品导入合成项目。**按能力拆分**（设计规范 §2）：

| 阶段 | 内容                | 传输方式                  | 使用界面                      |
| ----- | ------------------- | ------------------------- | ----------------------------- |
| 1     | 静态资源            | REST                      | `hyperframes figma asset`     |
| 2     | 品牌令牌/样式       | REST                      | `hyperframes figma tokens`    |
| 3     | 组件 → HTML         | REST                      | `hyperframes figma component` |
| 4     | 动效 → GSAP         | 可用时使用连接器          | 使用其动效上下文              |
| 5     | 着色器              | 连接器/手动导出           | 使用连接器或原生导出          |

凡是可以使用 REST 的地方都使用 REST（适合大规模、无头方式运行）。兼容的 Figma 连接器对于动效和着色器数据而言是可选的；如果没有连接器，请求用户提供原生导出。所有路径都会将资源冻结到本地，以确保渲染结果具有确定性。故事板重建会将阶段 1 的资源导出（REST）与智能体驱动的时间线组装结合起来——不需要连接器。现有的冻结资源、清单记录和绑定不受路由变更影响——这种拆分只会改变下一次导入所使用的凭据。

## 身份验证——两种凭据，限定作用域

**预检——在首次调用 CLI 之前，检查令牌是否存在**：Shell 环境（`[ -n "$FIGMA_TOKEN" ]`）**或**项目 `.env`（CLI 会自动加载它——`.env` 中存在相应条目即视为已配置）。如果两者都没有，请勿为了获取错误信息而运行命令——应先引导用户完成一次性设置，然后停止并等待：

1. figma.com/settings → **Security** → **Personal access tokens** → Generate new token。
2. 作用域——此集成只需要只读权限（它绝不会写入 Figma）：**File content: Read-only** + **File metadata: Read-only**。如果你要在非 Enterprise 方案中运行 `tokens`，还需添加 **Library content: Read-only**——已发布样式的回退机制会访问 `/v1/files/:key/styles`，没有此权限将返回 403（旧版设置说明遗漏了这一作用域）。如需使用品牌变量，可选择添加 **Variables: Read-only**——仅限 Enterprise；如果没有此权限，`tokens` 会自动降级为使用已发布样式（这是预期行为，并非错误——应向用户说明）。现在，403 会明确指出缺失的具体作用域；429 会自动重试（按分钟限流，并遵循 `Retry-After`）。
3. 请用户在其 Shell 配置文件或项目 `.env` 中设置 `FIGMA_TOKEN`；绝不要让他们将令牌粘贴到对话中。

在引导用户完成初始设置时，还应一并简要说明预期行为：每次导入都会保存为**记录了来源信息的本地冻结文件**——渲染时绝不会调用 Figma；重新运行命令只会重新导入 Figma 中发生变化的内容；一个令牌即可用于导入资源、品牌令牌和组件，并适用于其 Figma 账户有权查看的所有文件。

- **阶段 4–5（动效/着色器）：** 需要兼容的 Figma 连接器，其授权与令牌相互独立。如果连接器不可用或未经身份验证，请用户连接该连接器或提供原生导出文件，然后停止。
- 明确说明失败阶段需要哪一种凭据——绝不要将这种凭据分离描述为功能损坏。
- 流程中途出现 `BAD_TOKEN` (401) → 令牌已过期/被撤销；重新生成。`FORBIDDEN` (403) → 消息会指出确切缺少的权限范围（例如，样式回退需要 `library_content:read`）——添加该权限，否则说明此账户无法看到该文件。`REQUIRES_ENTERPRISE`（变量请求返回 403）→ 这不是失败：样式回退已经运行。`RATE_LIMITED` (429) → 客户端已经使用退避策略进行了重试（这适用于每一次读取——资源、令牌、样式、节点树、版本——重试位于共享请求路径中；会遵循 `Retry-After`，最长限制为 60 秒）；如果仍然出现，请等待一分钟，或减少每次调用导入的节点数量。

**速率限制注意事项（规范 §2.1）：** 连接器配额因 Figma 套餐而异——批量请求父级框架，除非用户要求，否则跳过验证截图，并缓存原始响应，确保重新派生结果时不再发起第二次调用。REST 按分钟限流（每分钟 10 次以上，各端点使用独立配额桶）——足以应对大批量操作，遇到 429 时执行退避。

## 路由

使用 `parseFigmaRef` 解析用户的 Figma 链接（URL、`fileKey:nodeId`、单独的 `fileKey`）。然后根据意图进行路由：

- “使用这个图层/徽标/图像” → **资源**（CLI）
- “提取我的品牌/颜色/令牌” → **令牌**（CLI）
- “根据这个框架构建场景” → **组件**（CLI）
- “导入这个动画/动效” → **动效**（连接器可用时使用，见下文）
- 故事板分区/由场景帧组成的胶片条 → **故事板**（见下文）
- 着色器填充/效果 → **着色器**（见下文）

**向用户讲述每一个步骤**——在每条命令执行前，说明即将从 Figma 提取什么；执行后，说明产物保存到了哪里（冻结路径/伴随文件/组件目录）、合成内容发生了什么变化，以及紧接着要执行的操作（预览、添加输出的变量、重新导入以关联绑定）。绝不要让用户不得不追问“成功了吗？”或“接下来做什么？”。

## 资源（阶段 1 — CLI）

```bash
hyperframes figma asset '<url-or-fileKey:nodeId>' [more refs…] [--format svg|png|jpg|pdf] [--scale 2] [--description "..."] [--entity "..."]
```

通过 REST 渲染、清理 SVG、冻结至 `.media/images/` 下、将来源信息追加到清单、重新生成 `.media/index.md`（共享的媒体使用清单），并输出一个 `<img>` 片段。对于每个 `fileKey:nodeId:format:scale:version` 都具有幂等性。矢量图/徽标优先使用 SVG（可缩放、可制作动画），需要保证光栅图像保真度时，使用带 `--scale 2` 的 PNG。**始终传入 `--description "<what it is>"`**（它会成为索引行和 `<img alt>`）；对于具名品牌标志，还应添加 `--entity "<name>"`，以便媒体使用功能的 `resolve --entity` 稍后能够找到它们（实体命中会跨图像/图标进行匹配）。

**在一次请求中批量处理多个节点**——传入同一文件中的多个引用（以空格分隔或用逗号连接）：`hyperframes figma asset 'KEY:1-2' 'KEY:3-4' 'KEY:5-6'`。所有节点都会在一次 `/v1/images` 调用中完成渲染，这是 Figma 针对每分钟速率限制提供的解决方案——提取整个框架中的资源时，应优先采用这种方式，而不是执行 N 条独立命令。`--description`/`--entity` 会应用于批次中的每个节点，因此应将用途相同的节点放在同一批次中。无论如何，遇到 429 时也会使用退避策略自动重试。

## 令牌（阶段 2 — CLI）

```bash
hyperframes figma tokens <fileKey>
```

将变量导入为 composition 品牌变量条目，同时生成 `figma-tokens.json` 辅助文件和绑定索引记录（`.media/figma-bindings.jsonl`）。上游仅向 Enterprise 方案开放变量功能：在其他方案中，该命令会降级为已发布的样式元数据（值会在组件导入时解析）。请将输出的条目添加到 composition 的 `data-composition-variables` 中。

如果同时需要令牌和组件，**请先导入令牌，再导入组件**——这样组件颜色才能链接到品牌变量，而不是将重复值直接固化进去。

**非 Enterprise 变量路径（已实地验证）：** REST 变量仅向 Enterprise 方案开放，但兼容的连接器可能会提供变量定义。当 `tokens` 报告 `REQUIRES_ENTERPRISE` 且连接器可用时，获取一次父场景的变量，将原始响应缓存到 `.media/figma-cache/`，并用它构建绑定索引。REST 节点树中的 `boundVariables` 提供每个属性对应的 `VariableID`；按节点和属性将其联接，然后写入 `.media/figma-bindings.jsonl` 行（`{kind:"binding", figmaId, sourceFileKey, compositionVariableId: "figma:<name>", version}`）以及 composition 变量条目。所有下游功能（组件 `var()` 解析、刷新、运行时 CSS 变量）均由已交付的机制处理。请为用户标注：“通过 Figma 连接器获取令牌——Enterprise 方案可直接通过 `hyperframes figma tokens` 获取这些令牌。”

运行时会将每个已声明的 composition 变量定义为 CSS 自定义属性（位于文档根节点和子 composition 宿主节点上），因此当变量默认值发生变化时，导入的 `var(--slug, literal)` 会自动应用新的配色——只需更新 `data-composition-variables` 中的一个值，即可为每个已导入的组件重新塑造品牌风格，无需重新导入任何内容。`hyperframes render --variables '<json>'` 可在渲染时覆盖这些变量。

## 组件（阶段 3 — CLI）

```bash
hyperframes figma component '<url-or-fileKey:nodeId>'
```

将节点树转换为采用精确 figma 几何结构的可编辑 HTML，并打包为 `compositions/components/<name>/` 下的注册表项目。矢量图形/布尔运算会通过阶段 1 的导出自动栅格化。绑定处理流程（规范 §7.1，仅限精确 ID——绝不按值匹配）：

- **静态保真度自检（主视觉内容必须执行）**：导入后，渲染该片段并与 figma 自身的像素进行比较——`figma asset <same node> --format png` 是基准真值。文本是已知的偏差维度：如果 figma 文本框的高度小于其行高，则它采用了垂直裁剪边界（映射器会为此输出 `text-box-trim`；在未使用它的情况下，实测 70px 字体的偏差约为 6px）。如果比较结果显示存在映射器未处理的偏差，请将其报告出来——不要在不说明的情况下手动微调片段。
- 填充绑定到**已导入的**令牌 → `var(--slug, #literal)`——品牌刷新会自动传播。
- 绑定到**未知的**令牌 → 字面值 + `data-figma-unresolved` 标记。命令会提示这一情况；请向用户建议：对源文件（或库文件）运行 `tokens`，然后重新导入组件以建立链接。对于每个未知库，只询问**一次**它对应哪个文件——绝不猜测，也绝不按十六进制颜色值匹配。

## 动效（阶段 4 — 连接器辅助）

**使用信标：**连接器辅助阶段没有 CLI 接触点，因此请在开始和结束时触发技能信标（匿名、经用户同意、永不导致失败）：开始时运行 `npx hyperframes events --skill=figma-motion`，完成时运行 `npx hyperframes events --skill=figma-motion --event=skill_completed --outcome=success|error`。着色器（`figma-shaders`）和故事板（`figma-storyboard`）同样如此。

不存在对应的 REST 方式。当有兼容的连接器可用时，使用它并将其输出交给 `@hyperframes/core/figma` 中的纯辅助函数；否则，请用户提供原生导出：

1. 通过一次递归请求获取父级画框的动效上下文，而不是为每个元素分别发起请求。将原始 JSON 保存在项目旁边（`.media/figma-cache/`），这样重新转换就无需额外开销。
2. 使用 `@hyperframes/core/figma` 中的 `motionContextToDocs(rawResponse, { selectorFor, repeat })` 将其规范化为 `MotionDoc` — **绝不要手动转录关键帧数值**。该辅助函数以程序化方式编码了经过实际验证的解码规则：它会解析 motion.dev 代码片段（这是可靠的编码方式 — CSS 代码片段会拉伸时长，并且可能与之不一致，因此会被忽略）、移除循环回绕的尾部关键帧（时间约为 ≈0.9999→1 的亚毫秒片段是循环的瞬时重置，而不是创作出的动效 — 回绕通过 `repeat` 重启实现），并原样保留贝塞尔缓动。`selectorFor` 必须返回阶段 3 组件导入中的 ID — 不要根据节点名称派生选择器。
   2b. **在宣布完成前对照基准真值进行验证 — 强制要求**：通过可用连接器导出该组的根画框，并运行 `node skills/figma/scripts/verify-motion.mjs --reference <export.mp4> --render <render.mp4> --crop WxH+X+Y` — 它会比较动效能量差异（静态导入保真度的影响会相互抵消），并在最小动效 PSNR 低于 15dB 时判定失败（校准结果：忠实还原 ≈ 20+，存在偏差 ≈ 5）。应根据渲染结果中卡片的实际边缘测量 `--crop`，不要猜测。失败意味着应重新检查转换，而不是调整阈值。
3. `motionToGsap(doc)` → `emitTimelineScript(spec)` → 在 GSAP + CustomEase CDN 标签之后注入为 `<script>`。时间线应处于暂停状态、具有有限时长，并使用字面量键注册到 `window.__timelines`。
4. 无法转换的轨道（着色器驱动、不支持的属性、复杂蒙版）→ 通过连接器导出并固化为 MP4，然后将其嵌入为 `<video class="clip">`。例外：着色器驱动的轨道 — Figma 的导出路径会将着色器扁平化为基础颜色（参见下方的“着色器”），因此在此处烘焙会悄无声息地丢失着色器；请改为让用户提供 Figma 原生导出。始终说明使用了哪条路径以及原因。映射集合之外的命名缓动会回退为线性缓动 — 映射表位于 `motionEase.ts` 中；发生回退时应告知用户。
5. 在宣布完成前运行 `npx hyperframes check`。

## 着色器（阶段 5 — 主要为手动操作）

Figma 的连接器渲染路径不会执行着色器（它们会被扁平化为基础颜色），并且只有**发布到库中**的样式才能访问着色器源代码（需要付费的 Full 席位）。默认路径：请用户在 Figma 中原生导出着色器画框（PNG 或 Motion MP4），然后将其作为阶段 1 资产/剪辑导入。不要尝试通过连接器对着色器进行像素捕获 — 它会悄无声息地产生错误结果。

## 故事板（场景帧的一个 SECTION → 动画）

**首要原则：故事板帧是关键帧，而不是幻灯片。** 包含同一元素的两个帧描述的是该元素随时间变化的状态——应在这些状态之间对该元素进行动画处理；绝不能把这些帧作为一系列静止画面播放。连续四帧中绘制在逐渐降低的 y 位置上的徽标，是同一个元素通过四个关键帧向上移动。将故事板帧依次连续播放是典型的失败做法；你的任务是重建这些帧所隐含的元素时间线。

故事板文件遵循一种可以机械解析的语法——不要凭肉眼判断，要进行解码：

1. **场景单元**：在 SECTION 内部，每个帧大小的节点都是一个场景——既包括命名的 FRAME，_也包括_ 独立的全帧 RECTANGLE（设计师会将静止画面直接粘贴到该区域中）。应按尺寸筛选（≈ 合成画面的宽高比，例如 >1400×900），而不是按节点类型或名称筛选。
2. **顺序 = x 位置**（如果条带发生换行，则按行优先）。根据 `absoluteBoundingBox.x` 对场景排序。
3. **对相邻帧做差异比较，将其组织成元素链**——动画就存在于这里。匹配连续帧中的子节点：首先按**名称**匹配（名称相同 = 同一个元素 → 在不同状态之间对其相对 x/y/w/h 进行补间），然后按**几何相似性**匹配（尺寸相近 + 中心点接近 = 像素内容发生变化的同一个逻辑元素 → 在对几何属性进行补间的同时，原位交叉淡化两次导出结果；这适用于文本逐字输入和形态变换状态）。未匹配的子节点在其所属场景的节拍点进入或退出。帧背景填充应作为颜色轨道进行补间。每条元素链只导出一个素材（仅当像素确实不同时，才为每种状态分别导出）——绝不能为每一帧导出一个静止画面。
4. **静止画面是后备方案，而不是默认方案**——仅用于无法拆分的帧（没有共享元素的扁平化全帧截图）；这类帧采用下文所述的动态分镜处理方式。
5. **导演注释**：条带下方的 TEXT 节点用于描述运动意图，并与其 x 范围所重叠的场景配对。它们描述的是_如何_制作动画——并不是要显示在画面上的文案。
6. **批量导出**（元素或静止画面）：`GET /v1/images` 接受以逗号分隔的 id，但大型场景帧在 id 数量超过约 12 个时会触发 "Render timeout"——每次调用应分块处理约 4 个，并设置重试。（每个场景调用一次会浪费速率配额；通过单素材路径处理 26 个场景大约需要 52 次调用。）
7. **注释动词 → 转场**（以下为起始词汇表，可在遇到新情况时扩展）：

| 注释内容                        | 处理方式                                                          |
| ------------------------------- | ----------------------------------------------------------------- |
| 爆炸 / 爆发                     | 进入时缩放约 1.5→1 + 淡入，`power3.out`                            |
| 滑入 / 滑向…… / 滚动           | 从对应边缘沿指定方向滑入                                          |
| 变形 / 显现                     | 交叉淡化——如果运动发生在单个场景内部，则使用第 3 阶段导入         |
| 循环展示 / 逐个展示             | 延长停留时间——如果各项在场景内部进行动画，则使用第 3 阶段导入     |
| （无注释）                      | 交叉淡化 + 缓慢的 Ken Burns 漂移动画                              |

8. **静帧与组件的路由选择**：描述场景_之间_运动的注释 → 在静帧上添加转场（见上文）。描述场景_内部_运动的注释（“文本行依次显现”“胶囊元素以动画方式进入”）→ 该帧应进行 Phase-3 组件导入（真实元素），并按照注释制作动画，而不是使用扁平 PNG。先使用静帧完成动态分镜，再升级注释中特别指出的场景。
9. 使用一个 `main` 时间线对所有内容进行编排（按绝对时间设置每个场景的 opacity/x/y）——制作动态分镜不需要为每个场景创建子合成。
10. **升级处理——当各帧描绘的是同一个产品 UI 时 → 重建应用，而不是使用元素链。** 当每一帧都是同一个应用界面的连续状态（注册流程、设置面板、播放器）时，元素链无法充分呈现效果。将 UI 重建为实时 DOM——对会改变状态的部分进行 Phase-3 组件导入，对静态界面框架使用真实导出的像素（**用代码实现会改变状态的部分，冻结不会改变的部分**）——并将每一帧的差异视为一个**要执行的交互**，而不是一个要应用的补间动画：光标进入、点击控件、状态作出响应，界面像真实导航一样推入/滑动。最终效果应像是一段正常运行的应用的连续屏幕录制。这是基本准则在 UI 流程中的彻底贯彻；静帧/元素链处理方式适用于并非同一个连贯应用的故事板。
