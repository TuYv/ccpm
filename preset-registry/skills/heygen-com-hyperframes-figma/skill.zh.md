# Figma → HyperFrames

将用户的 Figma 作品导入合成项目。**按能力拆分**（设计规范 §2）：

| 阶段 | 内容                | 传输方式                  | 接口                          |
| ---- | ------------------- | ------------------------- | ----------------------------- |
| 1    | 静态资源            | REST                      | `hyperframes figma asset`     |
| 2    | 品牌令牌/样式       | REST                      | `hyperframes figma tokens`    |
| 3    | 组件 → HTML         | REST                      | `hyperframes figma component` |
| 4    | 动效 → GSAP         | 连接器（可用时）          | 使用其动效上下文              |
| 5    | 着色器              | 连接器 / 手动导出         | 使用连接器或原生导出          |

凡是 REST 能够胜任的场景都会使用 REST（适合大规模使用，且支持无头模式）。兼容的 Figma 连接器对于动效和着色器数据是可选的；如果没有连接器，则要求用户提供原生导出。所有路径都会在本地冻结资源，以确保渲染结果具有确定性。故事板重建会将阶段 1 的资源导出（REST）与由智能体驱动的时间线组装结合起来——无需连接器。现有的冻结资源、清单记录和绑定不受路由变更影响——这种拆分只会改变下一次导入所使用的凭据。

## 身份验证——两个凭据，作用域明确

**预检——首次调用 CLI 之前，请检查令牌是否存在**：shell 环境变量（`[ -n "$FIGMA_TOKEN" ]`）**或**项目 `.env`（CLI 会自动加载它——`.env` 中存在相应条目即视为已配置）。如果两者都不存在，请勿为了获取错误信息而运行命令——应先引导用户完成一次性设置，然后停止并等待：

1. figma.com/settings → **Security** → **Personal access tokens** → Generate new token。
2. 作用域——此集成只需要只读权限（它绝不会写入 Figma）：**File content: Read-only** + **File metadata: Read-only**。如果要在非 Enterprise 套餐上运行 `tokens`，还需添加 **Library content: Read-only**——已发布样式的回退机制会访问 `/v1/files/:key/styles`，如果没有此权限，便会返回 403（旧版设置说明遗漏了此作用域）。还可以选择为品牌变量添加 **Variables: Read-only**——仅限 Enterprise；如果没有此权限，`tokens` 会自动降级为使用已发布样式（这是预期行为，并非错误——应明确告知用户）。现在，403 会指出具体缺少的作用域；429 会自动重试（每分钟限制，并遵循 `Retry-After`）。
3. 请用户在其 shell 配置文件或项目 `.env` 中设置 `FIGMA_TOKEN`；绝不要让用户将令牌粘贴到对话中。

在引导设置时，还要简洁地说明预期行为：每次导入都会生成一个**记录了来源信息的本地冻结文件**——渲染时绝不会调用 Figma；重新运行命令只会重新导入 Figma 中发生变化的内容；并且一个令牌即可用于其 Figma 账户有权查看的所有文件中的资源、品牌令牌和组件。

- **阶段 4–5（动效/着色器）：** 需要兼容的 Figma 连接器，其授权与令牌相互独立。如果连接器不可用或未经身份验证，请让用户连接它或提供原生导出，然后停止。
- 明确说明失败的阶段需要哪一种凭据——绝不要将这种分离呈现为系统故障。
- 流程中途出现 `BAD_TOKEN` (401) → 令牌已过期/被撤销；重新生成。`FORBIDDEN` (403) → 消息会指出确切缺少的作用域（例如，样式回退需要 `library_content:read`）——添加该作用域，否则说明该账户无法查看此文件。`REQUIRES_ENTERPRISE`（变量请求返回 403）→ 并非失败：样式回退已经运行。`RATE_LIMITED` (429) → 客户端已经通过退避机制进行了重试（这适用于每一次读取——资产、令牌、样式、节点树、版本——重试逻辑位于共享请求路径中；会遵循 `Retry-After`，上限为 60 秒）；如果仍然出现此错误，请等待一分钟，或减少每次调用导入的节点数量。

**速率限制意识（规范 §2.1）：** 连接器配额因 Figma 套餐而异——批量请求父级帧，除非用户要求，否则跳过验证截图，并缓存原始响应，确保重新推导绝不会产生第二次调用。REST 限制按分钟计算（每分钟 10 次以上，按端点分别设置配额桶）——足以支持大批量操作，遇到 429 时进行退避。

## 路由

使用 `parseFigmaRef` 解析用户的 Figma 链接（URL、`fileKey:nodeId`、纯 `fileKey`）。然后根据意图进行路由：

- “使用这个图层/徽标/图像” → **资产**（CLI）
- “拉取我的品牌/颜色/令牌” → **令牌**（CLI）
- “基于这个帧构建场景” → **组件**（CLI）
- “导入这个动画/动效” → **动效**（连接器可用时使用，见下文）
- 故事板分区/场景帧胶片条 → **故事板**（见下文）
- 着色器填充/效果 → **着色器**（见下文）

**向用户讲述每一个步骤**——在执行每条命令前，说明即将从 Figma 拉取什么；执行后，说明产物保存到了哪里（冻结路径/伴随文件/组件目录）、合成中发生了哪些变化，以及下一步要立即执行的操作（预览、添加打印出的变量、重新导入以链接绑定）。绝不能让用户不得不询问“成功了吗？”或“现在该做什么？”。

## 资产（阶段 1 — CLI）

```bash
hyperframes figma asset '<url-or-fileKey:nodeId>' [more refs…] [--format svg|png|jpg|pdf] [--scale 2] [--description "..."] [--entity "..."]
```

通过 REST 渲染，清理 SVG，冻结到 `.media/images/` 下，将来源信息追加到清单中，重新生成 `.media/index.md`（共享媒体使用清单），并输出一个 `<img>` 代码片段。对于每个 `fileKey:nodeId:format:scale:version` 都具有幂等性。对于矢量图/徽标，优先使用 SVG（可缩放、可制作动画）；对于需要保持光栅图像保真度的情况，使用 PNG `--scale 2`。**始终传入 `--description "<what it is>"`**（它会成为索引行和 `<img alt>`）；对于命名的品牌标识，还要添加 `--entity "<name>"`，以便媒体使用的 `resolve --entity` 稍后能够找到它们（实体命中会跨图像/图标进行匹配）。

**在一次请求中批量处理多个节点**——传入同一文件中的多个引用（以空格分隔或用逗号连接）：`hyperframes figma asset 'KEY:1-2' 'KEY:3-4' 'KEY:5-6'`。所有节点都会在一次 `/v1/images` 调用中完成渲染，这是 Figma 自身针对每分钟速率限制提供的解决方案——当拉取整个帧所需的资产时，优先使用这种方式，而不是执行 N 条单独的命令。`--description`/`--entity` 会应用于批次中的每个节点，因此应将用途相同的节点批量处理。无论如何，遇到 429 时也会通过退避机制自动重试。

## 令牌（阶段 2 — CLI）

```bash
hyperframes figma tokens <fileKey>
```

将变量导入为合成中的品牌变量条目，同时生成 `figma-tokens.json` 辅助文件和绑定索引记录（`.media/figma-bindings.jsonl`）。上游仅企业版支持变量：在其他套餐中，该命令会降级为已发布的样式元数据（其值在组件导入时解析）。将输出的条目添加到合成的 `data-composition-variables` 中。

如果同时需要令牌和组件，**请先导入令牌，再导入组件**——这样组件颜色才能关联到品牌变量，而不是固化为重复值。

**非企业版变量路径（已通过实际测试）：** REST 变量仅企业版可用，但兼容的连接器可能会提供变量定义。当 `tokens` 报告 `REQUIRES_ENTERPRISE` 且连接器可用时，获取一次父场景的变量，将原始响应缓存到 `.media/figma-cache/`，并使用它构建绑定索引。REST 节点树的 `boundVariables` 提供各属性对应的 `VariableID`；按节点和属性将它们关联起来，然后写入 `.media/figma-bindings.jsonl` 行（`{kind:"binding", figmaId, sourceFileKey, compositionVariableId: "figma:<name>", version}`）以及合成变量条目。所有下游功能（组件 `var()` 解析、刷新、运行时 CSS 变量）均由已发布的机制处理。请向用户标明：“令牌通过 Figma 连接器获取——企业版套餐可直接通过 `hyperframes figma tokens` 获取。”

运行时会将每个已声明的合成变量定义为 CSS 自定义属性（位于文档根节点和子合成宿主上），因此，当变量默认值发生变化时，导入的 `var(--slug, literal)` 会随之更新重新着色——只需更新 `data-composition-variables` 中的一个值，即可为所有已导入组件更换品牌样式，而无须重新导入任何内容。`hyperframes render --variables '<json>'` 可在渲染时覆盖这些变量。

## 组件（阶段 3 — CLI）

```bash
hyperframes figma component '<url-or-fileKey:nodeId>'
```

节点树 → 按照 Figma 的精确几何结构生成可编辑 HTML，并将其打包为 `compositions/components/<name>/` 下的注册表项。矢量和布尔运算会通过阶段 1 的导出自动栅格化。绑定过程（规范 §7.1，仅限精确 ID——绝不按值匹配）：

- **静态保真度自检（首屏核心内容必须执行）**：导入后，渲染片段，并将其与 Figma 自身的像素进行比较——`figma asset <same node> --format png` 是基准真值。文本是已知的偏差来源：如果 Figma 文本框的高度小于其行高，则其边界经过了垂直裁剪（映射器会为这类文本框生成 `text-box-trim`；在未使用该属性时，实测 70px 字体的偏差约为 6px）。如果比较结果显示映射器未覆盖的偏差，请报告该问题——不要在不作说明的情况下手动微调片段。
- 填充绑定到**已导入的**令牌 → `var(--slug, #literal)`——品牌刷新会自动传播。
- 绑定到**未知的**令牌 → 字面值 + `data-figma-unresolved` 标记。命令会告知你；请向用户建议：对源文件（或库文件）运行 `tokens`，然后重新导入组件以建立关联。对于每个未知库，只询问**一次**它对应哪个文件——绝不猜测，也绝不按十六进制颜色值匹配。

## 动效（阶段 4 — 连接器辅助）

**使用信标：**连接器辅助阶段没有 CLI 接触点，因此请在开始和结束时触发技能信标（匿名、需用户同意、永不导致失败）：开始时运行 `npx hyperframes events --skill=figma-motion`，完成时运行 `npx hyperframes events --skill=figma-motion --event=skill_completed --outcome=success|error`。着色器（`figma-shaders`）和故事板（`figma-storyboard`）也同样如此。

不存在对应的 REST 方式。如果有兼容的连接器可用，请使用它，并将其输出传给 `@hyperframes/core/figma` 中的纯辅助函数；否则，请让用户提供原生导出：

1. 通过一次递归请求获取父级画框的动效上下文，而不是对每个元素分别发起请求。将原始 JSON 保存在项目旁边（`.media/figma-cache/`），这样重新转换无需额外成本。
2. 使用 `@hyperframes/core/figma` 中的 `motionContextToDocs(rawResponse, { selectorFor, repeat })` 将其规范化为 `MotionDoc` — **绝不要手动转录关键帧数值**。该辅助函数以机械化方式实现经过实战检验的解码规则：它解析 motion.dev 片段（这是可靠的编码方式 — CSS 片段会拉长持续时间，并且可能彼此不一致，因此会被忽略）、移除循环回绕的尾部关键帧（时间 ≈0.9999→1 处的亚毫秒片段是循环的瞬时重置，而不是创作出的动效 — 回绕通过 `repeat` 重新启动来实现），并原样保留贝塞尔缓动。`selectorFor` 必须返回阶段 3 组件导入中的 id — 不要根据节点名称派生选择器。
   2b. **在宣布完成之前对照真实基准进行验证 — 强制要求**：通过可用的连接器导出该组的根画框，然后运行 `node skills/figma/scripts/verify-motion.mjs --reference <export.mp4> --render <render.mp4> --crop WxH+X+Y` — 它会比较动效能量差异（静态导入保真度的影响会相互抵消），并在最低动效 PSNR 低于 15dB 时失败（校准值：忠实还原 ≈ 20+，存在偏差 ≈ 5）。请根据渲染结果中卡片的实际边缘测量 `--crop`，不要猜测。FAIL 意味着应重新检查转换，而不是调整阈值。
3. `motionToGsap(doc)` → `emitTimelineScript(spec)` → 在 GSAP + CustomEase CDN 标签之后注入为 `<script>`。时间线应处于暂停状态、次数有限，并使用字面量键注册到 `window.__timelines`。
4. 无法转换的轨道（由着色器驱动、不受支持的属性、复杂蒙版）→ 通过连接器导出，将 MP4 固化，然后以 `<video class="clip">` 嵌入。例外：由着色器驱动的轨道 — Figma 的导出路径会将着色器扁平化为基础颜色（参见下方的“着色器”），因此在该路径中进行烘焙会悄无声息地丢失着色器；请改为让用户提供 Figma 原生导出。始终说明使用了哪种路径以及原因。映射集合之外的命名缓动会回退为线性缓动 — 映射表位于 `motionEase.ts` 中；触发回退时，请告知用户。
5. 在宣布完成之前运行 `npx hyperframes check`。

## 着色器（阶段 5 — 主要为手动操作）

Figma 的连接器渲染路径不会执行着色器（它们会被扁平化为基础颜色），并且只有**已发布到库中**的样式才能访问着色器源代码（需要付费的 Full 席位）。默认路径：让用户在 Figma 中原生导出着色器画框（PNG 或 Motion MP4），然后将其作为阶段 1 资产／剪辑导入。不要尝试通过连接器对着色器进行像素捕获 — 这会悄无声息地产生错误结果。

## 故事板（由场景帧组成的 SECTION → 动画）

**首要原则：故事板帧是关键帧，而不是幻灯片。** 包含同一元素的两个帧描述了该元素随时间变化的状态——应在这些状态之间对该元素进行动画处理；绝不能把这些帧作为一系列静态图依次播放。连续四个帧中绘制在逐渐降低的 y 位置上的徽标，是同一个元素经过四个关键帧向上升起。将故事板帧首尾相接地播放是错误做法；重建它们所隐含的元素时间线才是任务所在。

故事板文件遵循一种可以机械解析的语法——不要凭肉眼判断，要进行解码：

1. **场景单元**：在 SECTION 内，每个帧大小的节点都是一个场景——既包括命名的 FRAME，也包括独立的全帧 RECTANGLE（设计师会将静态图直接粘贴到该分区中）。应按尺寸筛选（≈ 合成画面的宽高比，例如 >1400×900），而不是按节点类型或名称筛选。
2. **顺序 = x 位置**（如果条带发生换行，则按行优先）。按 `absoluteBoundingBox.x` 对场景排序。
3. **对相邻帧进行差异比较，将其串联为元素链**——动画就存在于这里。匹配连续帧中的子元素：首先按**名称**匹配（名称相同 = 同一个元素 → 在不同状态之间对其相对 x/y/w/h 进行补间），然后按**几何相似性**匹配（尺寸相近 + 中心点邻近 = 像素发生变化的同一个逻辑元素 → 在对几何属性进行补间的同时，在原位置交叉淡化两份导出内容；这可以处理打字文本的渐进过程和变形状态）。未匹配的子元素在其所属场景的节拍点进入或退出。帧的背景填充作为颜色轨道进行补间。每条元素链只导出一个素材（仅当像素确实不同时，才为每种状态分别导出一个）——绝不能为每一帧导出一张静态图。
4. **静态图是后备方案，而不是默认方案**——仅用于无法拆解的帧（没有共享元素的扁平化全帧截图）；这些帧采用下文所述的动态分镜处理方式。
5. **导演注释**：条带下方的 TEXT 节点用于描述运动意图，并与其 x 范围所重叠的场景配对。它们描述的是_如何_制作动画——并非屏幕上要显示的文案。
6. **批量导出**（元素或静态图）：`GET /v1/images` 接受以逗号分隔的 ids，但大型场景帧在超过约 12 个 ids 时会遇到 "Render timeout"——每次调用分成约 4 个一组，并加入重试机制。（每个场景调用一次会浪费速率配额；通过单素材路径处理 26 个场景约需 52 次调用。）
7. **注释动词 → 转场效果**（初始词汇表，遇到新表达时继续扩展）：

| 注释内容                        | 处理方式                                                          |
| ------------------------------- | ----------------------------------------------------------------- |
| EXPLOSION / BURST               | 进入时缩放约 1.5→1 + 淡入，`power3.out`                           |
| SLIDES / SLIDE TO THE… / SCROLL | 从对应边缘沿指定方向滑入                                          |
| MORPH / REVEALS                 | 交叉淡化——或者，如果运动发生在单个场景内部，则使用 Phase-3 import |
| CYCLE THROUGH / EACH ONE        | 延长停留——或者，如果各项在场景内部运动，则使用 Phase-3 import     |
| （无注释）                      | 交叉淡化 + 缓慢的 Ken-Burns 漂移                                  |

8. **静帧与组件的路由选择**：描述场景_之间_运动的注释 → 在静帧上添加转场（见上文）。描述场景_内部_运动的注释（“文本行依次显现”“胶囊形元素以动画方式进入”）→ 该帧应在第 3 阶段导入组件（真实元素），并按注释为其添加动画，而不是使用扁平 PNG。先使用静帧完成动态分镜，再升级注释中特别指出的场景。
9. 使用一条 `main` 时间线编排所有内容（按绝对时间设置每个场景的 opacity/x/y）——动态分镜不需要为每个场景创建子合成。
10. **升级处理——当各帧描绘的是同一个产品 UI 时 → 重建应用，而不是使用元素链。** 当每一帧都是同一个应用界面在连续状态下的呈现（注册流程、设置面板、播放器）时，元素链无法充分表现其效果。应将 UI 重建为实时 DOM——对会改变状态的部分执行第 3 阶段组件导入，对静态界面框架使用真实导出的像素（**用代码实现会改变状态的部分，冻结不会改变的部分**）——并将每一帧的差异视为一次**要执行的交互**，而不是要应用的补间动画：光标移入、点击控件、状态作出响应，页面像真实导航一样推入/滑动。最终效果应像是一段连贯的、实际可用应用的屏幕录制。这是 UI 流程中基本准则的最终体现；静帧/元素链处理方式适用于并非同一个连贯应用的故事板。

## 确定性

绝不要在合成中留下 Figma URL——必须先冻结。绝不要输出 `repeat: -1`。时间线应处于暂停状态、时长有限，并使用字面量 `window.__timelines` 键。所有 Figma I/O 都应在导入时完成；渲染时只能访问本地文件。
