# Growth Signal 图表

以 Growth Signal 的固定风格，创建有用、有来源依据的 AI、商业和营销帖子。匹配所请求的阶段：候选研究、设计探索、单篇帖子或轮播图。设计修订不要求重新开始研究流程。

## 仓库集成

在完整的 AI Marketing Skills checkout 中运行时，如果允许网络访问，请使用现有的 `telemetry/version_check.py` 执行非阻塞式更新检查。运行结束后，使用 `telemetry/telemetry_log.py`，记录 skill name `growth-signal-charts`、实际耗时、实际成功状态以及仓库的 `VERSION`。遵循现有的明确遥测同意机制；绝不要代表用户启用远程报告。不要记录帖子文本、分析数据、标识符、路径、来源或凭据。独立副本跳过不可用的仓库辅助工具，不得因此阻塞任务。

## 已批准的方向

默认风格为 **Field Manual / Desk Edition**。“Engineering edition”指的是这种实用的技术手册方向。**Growth Signal** 仍然是公开系列名称；edition 名称用于描述供审核的视觉处理方式。

设计前，阅读 [Desk Edition style guide](references/desk-edition-style.md)。使用出版方的视觉识别。用户提供的参考可以用于调整布局；本公开 skill 不包含任何私有参考图像或分析数据导出文件。

- 以白色为主。使用石墨色文字、小型开放环标记、纤细的橙色索引轨道、醒目的窄体标题和克制的技术标签。来源文本必须保持清晰易读。
- 基础调色板：白色 `#FFFFFF`、石墨色 `#19171B`、橙色 `#F05B24`；紫罗兰色 `#6336C7` 可作为小面积点缀。出版方可以尝试不同调色板。在选定变化之前，默认保持已批准的调色板。
- 插图应小巧且切题。报告、数据连接器或成本账本可以解释软件工作。装饰性的螺栓和机械装置本身无法解释软件。
- 在数据和文案周围留出空间。避免大型元数据表格、重复印章、帖子中的调色板色板、整页网格以及多个相互竞争的强调信息。
- Anime 不属于默认风格。除非用户提出要求，否则不要向该系列添加 anime 角色或 manga 风格。
- 保留已批准的设计。将新风格标记为实验；不要因为生成了新图像就悄悄替换默认风格。

适合发布的实现需要独立的幻灯片文件和数值准确的图形。风格指南是布局规范，不是任何数值声明的证据。

## 研究与候选选择

对于候选选择、绩效评审或自动化设计，请阅读 [selection and performance](references/selection-and-performance.md)。从出版方的原始主张、示例和运营经验开始。将已发布的帖子 ID 与实测表现进行匹配，然后使用外部数据支持或质疑该论点。相关的成功主题可以作为新图表的假设；它并不能证明新统计数据会取得良好表现。

当需要近期外部调研时，如已提供且可运行，请使用已安装的 **last30days** 技能。应解析其当前所在位置，而不是假定脚本路径。若运行器不可用，请使用带标签的网页调研替代方案。不要声称该机器人曾运行，也不要让这阻止对发布者自身内容的获授权工作。已保存的技能不会安装运行器，也不会创建自动化。

将图表数值追溯至原始发布物或有文档记录的第一方数据。核查主张或撰写文案时，请阅读[编辑与证据指南](references/editorial-and-evidence.md)。将来源保真度和读者理解度作为要求；按原创洞见、已衡量的受众兴趣、买家相关性和新鲜度对符合条件的创意排序。当主题与买家有自然联系时，使用发布者选定的业务或产品。明确区分触达实验，不要强行将每个主题都推销为产品。

在呈现预览之前，展示这些创意及其原始来源、已衡量的信号、图表证据，以及尝试或暂缓的理由。若涵盖这些平台，请为每个选定创意分别撰写 Instagram、X 和 LinkedIn 文案。即使设计看起来精美，也应拒绝薄弱候选项。一批有用的内容可以不包含任何图表。

以下已批准的规则以及选择参考资料中的规则为默认规则。在被要求时，或存在需要该审查的重大冲突时，使用 **grill-me-overview**；若不可用，则对未解决的决策进行简短的直接审查；不要让用户为每一批内容重复已经确定的选择。将已接受的变更转化为持久规则。自行赋予的设计评分不是播放量或潜在客户的证据。

## 让故事易于理解

默认制作范围：**聚焦包含图表的幻灯片；其他一切都是噪声。** 默认交付中的每一张幻灯片都必须包含有意义且注明来源的数值图表。将解读放在文案中。除非用户在后续请求中明确要求，否则省略工作流幻灯片、截图、空白工作表、创作者简报、建议卡片和结尾 CTA 幻灯片。不要将这些做成装饰性图表来规避此规则。

在设计前定义图表的主题和发现。轮播图可以串联 **发现 → 相关发现**，但每张幻灯片都必须证明其存在的价值。一张有力的图表可以作为独立帖子；不要为了达到预设长度而添加幻灯片。更多主题需要更多有用证据，而不是填充内容。

- 明确决定交付物是独立帖子、一个轮播图，还是替代概念板。
- 将轮播页面编号为“第 1 张，共 N 张”等。不要为连续幻灯片使用单独的期号。
- 每张幻灯片即使单独观看，也应标明其主题。后一张幻灯片可以依赖前面的证据，但不应要求读者理解前文才能明白建议所涉及的内容。
- 说明工具、任务或工作流。将“构建、集成、维护、审查”替换为具体行动，例如“当数据连接中断时，由谁修复？”
- 避免“演示不是成本”或“惊艳之后的工作”之类的空洞口号。说明读者应检查或采取什么行动。
- 标注拟议的清单、假设示例或编辑图示。不要暗示被引用的研究提供了这些建议。

## 根据问题选择视觉形式

| 证据或目的 | 适合的处理方式 |
| --- | --- |
| 一个有意义的百分比 | 大号统计数据强调或精确占比图 |
| 跨类别比较大小 | 使用共同尺度的条形图或点图 |
| 可比较组在两个时间点的数据 | 斜率图 |
| 跨多个日期的测量序列 | 折线图 |
| 汇总到总数的组成部分 | 瀑布图，仅在算术关系成立时使用 |
| 依赖关系、步骤或选择 | 超出当前仅限图表的范围；只有在明确要求时才使用图示 |

在不同帖子之间变换数据图表形式。保持图形标记、字体层级、克制的视觉风格和来源位置一致。让绘图区占据幻灯片的主导地位。

每个小型数据图表都必须在其**左下角**标注引用，包括一张幻灯片上包含多个图表的情况。在图形中使用发布者、简短标题和日期；在来源台账/图注中保留完整 URL 和方法说明。加入解读该数字所需的单位和总体范围。不同研究可能需要分别标注引用和限定条件。

## 构建和审阅

对于新的栅格概念艺术和对栅格画板的编辑，使用可用的图像生成工作流。提供确切文案，以及经过检查并获用户认可的参考图（如有）。保留与输出结果一同使用的提示词。对于最终数值图表，使用确定性的图表/矢量布局；图像生成的比例不能作为准确性的依据。不要通过基于代码的变通方法修改栅格插图。

概念画板可以展示相邻幻灯片以供审阅。最终轮播图必须同时包含**每张幻灯片一个 PNG 文件**以及**每个轮播图一个按顺序排列的 PDF 文件**。如果未指定尺寸，默认使用 1080 × 1350 作为竖版工作尺寸。确认 PNG 和 PDF 页面具有相同的幻灯片顺序和外观。可编辑/原生图表资源可以作为额外文件提供；但不能替代 PNG 和 PDF 导出文件。

检查阅读顺序、独立呈现的主题、来源位置、裁切情况和手机尺寸下的可读性。核实实际数值、坐标轴范围、单位、几何关系和计算结果；不要相信图像生成器生成的条形长度或单元格数量。检查图示是否暗示经过测量的因果关系或捏造的结果。

交付所请求的产物、适用的来源台账/图注，以及一条明确的建议。在工作区中保存最终项目资源。此技能用于准备本地草稿；不意味着拥有发布、发送、安排发布、安装付费研究工具或消耗外部研究配额的权限。
