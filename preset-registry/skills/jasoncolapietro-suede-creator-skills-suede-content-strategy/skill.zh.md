# Suede 内容策略

使用这份 Suede 内容策略手册，规划有证据支持的内容，从而获得搜索流量、分享、信任或高质量需求。

## 规划前

如果 `.agents/product-marketing.md` 存在，请先阅读；只询问其中未涵盖的信息；路径回退方案请参阅 `suede-product-marketing`。

收集以下背景信息（如未提供，请进行询问）：

### 1. 业务背景
- 公司是做什么的？
- 理想客户是谁？
- 内容的主要目标是什么？（流量、潜在客户、品牌知名度、思想领导力）
- 你的产品解决了哪些问题？

### 2. 客户研究
- 客户在购买前会提出哪些问题？
- 销售通话中会出现哪些异议？
- 支持工单中反复出现哪些主题？
- 客户会使用什么措辞来描述他们的问题？

### 3. 当前状态
- 你们是否已有内容？哪些内容效果良好？
- 你们拥有多少资源？（作者、预算、时间）
- 你们能够制作哪些内容形式？（文字、视频、音频）

### 4. 竞争格局
- 你们的主要竞争对手是谁？
- 你们所在市场中存在哪些内容空白？

## 可搜索与可分享

每一篇内容都必须具备可搜索性、可分享性，或同时具备二者。默认情况下，优先考虑可搜索性，因为搜索需求是可衡量的；但应将其视为起始规则，而非普遍真理，并在用户目标或证据表明应当反过来时调整优先顺序（例如没有搜索量的品类、以品牌为主导的发布）。记录你选择的顺序及其原因——这些信息会影响“内容创意优先级排序”中的权重。

**可搜索内容**承接现有需求。面向正在主动寻找答案的人进行优化。

**可分享内容**创造需求。传播观点，并引发人们讨论。

### 编写可搜索内容时

- 瞄准一个具体关键词或问题
- 完全匹配搜索意图——回答搜索者想要了解的内容
- 使用与搜索查询相匹配的清晰标题
- 使用能够反映搜索模式的标题结构
- 将关键词放入标题、标题层级、首段和 URL 中
- 提供全面覆盖（不要留下未回答的问题）
- 包含数据、示例以及指向权威来源的链接
- 针对 AI/LLM 发现进行优化：清晰的定位、结构化内容，以及全网一致的品牌信息

### 编写可分享内容时

- 以新颖洞察、原创数据或反直觉的观点开篇
- 通过论证充分的观点挑战传统认知
- 讲述能够让人产生情感共鸣的故事
- 创作人们愿意分享、以展示聪明才智或帮助他人的内容
- 联系当前趋势或新兴问题
- 分享坦诚、真实且他人可以从中学习的经历

## 内容类型

### 可搜索内容类型

**使用场景内容**  
公式：[persona] + [use-case]。目标是覆盖长尾关键词。
- “面向设计师的项目管理”
- “面向开发者的任务跟踪”
- “面向自由职业者的客户协作”

**中心与辐射**  
中心 = 全面的概览。辐射 = 相关的子主题。先创建中心内容，然后构建辐射内容，并在它们之间建立互链。有关其结构和 URL 指南，请参阅下文的“内容支柱与主题集群”。

**模板库**
高意向关键词 + 产品采用。
- 瞄准“marketing plan template”等搜索
- 提供立即可独立使用的价值
- 展示产品如何增强模板的效果

### 可分享的内容类型

**思想领导力**
- 阐述每个人都有感受、但尚未命名的概念
- 用证据挑战传统认知
- 分享脆弱且诚实的经历

**数据驱动内容**
- 产品数据分析（经匿名化的洞察）
- 公共数据分析（发现规律）
- 原创研究（开展实验并分享结果）

**专家汇编**
由一组经过筛选、相关且经验证的专家，回答一个具体问题。
内容的分发取决于贡献者的许可和实际推广情况。

**案例研究**
结构：挑战 → 解决方案 → 结果 → 关键经验

**元内容**
幕后透明分享。“我们如何实现首个 $5k MRR”“为什么我们选择债务融资而不是 VC”。

对于大规模的程序化内容，将数据和模板系统交给
`suede-programmatic-seo`。

## 内容支柱与主题集群

内容支柱是你的品牌将要占据的 3-5 个核心主题；每个支柱都会衍生出一组相关内容。在大多数情况下，只要做好内部链接，所有内容都可以放在 `/blog` 下。只有对于包含多层深度的综合性资源，才需要使用自定义 URL 结构的专属支柱页面（如 `/guides/topic`）。

### 如何识别支柱

1. **产品导向**：你的产品解决什么问题？
2. **受众导向**：你的 ICP 需要了解什么？
3. **搜索导向**：你的领域中哪些主题具有搜索量？
4. **竞争对手导向**：竞争对手的哪些内容获得了排名？

结构为支柱（中心页）→ 子主题集群 → 文章，每篇文章都链接到同级文章以及中心页。输出格式中的主题集群图就是需要输出的结构。

### 支柱标准

优秀的支柱应当：
- 与你的产品/服务保持一致
- 符合受众关心的内容
- 具有搜索量和/或社交媒体热度
- 足够宽泛，能够容纳多个子主题

## 按买家阶段进行关键词研究

使用每个阶段对应的修饰词集合，将主题映射到买家旅程中：

| 阶段 | 修饰词 | 触发原因 |
|---|---|---|
| **认知** | “what is”“how to”“guide to”“introduction to” | 客户在询问基础知识 |
| **考虑** | “best”“top”“vs”“alternatives”“comparison” | 客户正在评估多个工具 |
| **决策** | “pricing”“reviews”“demo”“trial”“buy” | 销售电话中开始讨论定价 |
| **实施** | “templates”“examples”“tutorial”“how to use”“setup” | 支持工单显示出设置方面的困难 |

示例：项目管理工具的考虑阶段：“Best Project Management Tools for Remote Teams”“Asana vs Trello vs Monday”“Basecamp Alternatives”。针对每个阶段，使用用户自己的类别名词套用相同模式，绝不要使用这里的这些名词。

## 内容创意来源

### 研究渠道检查

在进行外部研究之前，检查当前会话中可调用且已获授权的工具和连接来源。仅在确实存在访问权限时，使用产品分析、Search
Console 或关键词导出、客户材料、支持数据、已批准的 Drive
来源，或可调用的浏览器/搜索界面。记录每个来源的 URL 或文件、所有者、获取日期以及相关范围。

如果没有可用的外部研究渠道，请继续使用用户提供的 URL、导出数据、访谈记录和已知的一手证据。否则，请返回一份精简的手动研究清单，其中包含确切的查询语句和需要记录的字段。标注假设和未经验证的竞争对手观察结果；绝不要暗示已经执行过搜索。

### 1. 关键词数据

如果用户提供关键词导出数据（Ahrefs、SEMrush、GSC），请分析：
- 主题集群（将相关关键词分组）
- 买家阶段（认知/考虑/决策/实施）
- 搜索意图（信息型、商业型、交易型）
- 快速见效机会（低竞争度 + 尚可的搜索量 + 高相关性）
- 内容缺口（竞争对手排名而你没有排名的关键词）

以优先级表格输出：
| 关键词 | 搜索量 | 难度 | 买家阶段 | 内容类型 | 优先级 |

### 2. 通话记录

如果用户提供销售或客户通话记录，请提取：
- 提出的问题 → FAQ 内容或博客文章
- 痛点 → 使用他们自己的措辞描述的问题
- 异议 → 可主动回应的内容
- 语言模式 → 应使用的确切措辞（客户原声）
- 提到的竞争对手 → 他们拿你与哪些对象进行了比较

输出内容创意，并附上支持性引文。

### 3. 调查回复

如果用户提供调查数据，请挖掘：
- 开放式回复（主题和措辞）
- 常见主题，并记录样本数量和观察到的比例
- 资源请求（他们希望已有但尚不存在的内容）
- 内容偏好（他们想要的格式）

### 4. 论坛研究

如果当前可以调用经授权的浏览器或搜索渠道，请使用它查找近期的一手社区证据。否则，请索要相关 URL，或提供以下查询语句供手动收集。

**Reddit：** `site:reddit.com [topic]`
- 相关子版块中的热门帖子
- 评论中的问题和挫折
- 获得点赞的回答（验证哪些内容引起共鸣）

**Quora：** `site:quora.com [topic]`
- 关注人数最多的问题
- 获得高度点赞的回答

**其他：** Indie Hackers、Hacker News、Product Hunt、行业 Slack/Discord

对于每一项，记录来源 URL、发布日期、检索日期、社区背景以及简短的证据摘录。区分参与度信号与客户需求的证明。

### 5. 竞争对手分析

使用当前可调用且经授权的浏览器/搜索渠道，或用户提供的竞争对手 URL。如果两者都不可用，请生成一份手动研究清单，不要捏造页面清单、排名、参与度或内容缺口。

**查找他们的内容：** `site:competitor.com/blog`

**分析：**
- 可观察到的文章及带日期的参与度信号
- 反复涉及的主题
- 他们尚未覆盖的缺口
- 案例研究（客户问题、使用场景、结果）
- 内容结构（支柱、分类、格式）

**识别需要验证的假设：**
- 你可以做得更好的主题
- 他们遗漏的角度
- 基于可见日期或过时主张、可以加以改进的过时内容

### 6. 销售和支持团队输入

从面向客户的团队中提取：
- 常见异议
- 反复出现的问题
- 支持工单模式
- 成功案例
- 功能请求及其背后的问题

## 内容创意优先级排序

从四个因素对每个创意进行评分。以下权重只是一个示例起点，并非放之四海而皆准；请根据用户的业务目标调整权重，并记录所采用的决策规则。

### 1. 客户影响力（40%）
- 这个主题在研究中出现得有多频繁？
- 有多大比例的客户面临这一挑战？
- 这个痛点引发了多强烈的情绪反应？
- 有此需求的客户的潜在 LTV 是多少？

### 2. 内容与市场的契合度（30%）
- 这是否与产品能够解决的问题一致？
- 你能否利用客户研究提供独特洞察？
- 你是否有客户故事可以支持这一点？
- 这是否会自然地引发对产品的兴趣？

### 3. 搜索潜力（20%）
- 每月搜索量是多少？
- 这个主题的竞争程度如何？
- 是否存在相关的长尾机会？
- 搜索兴趣是在增长还是下降？

### 4. 资源需求（10%）
- 你是否具备创建权威内容所需的专业知识？
- 还需要开展哪些额外研究？
- 你需要哪些素材（图形、数据、示例）？

### 评分模板

| 创意 | 客户影响力（40%） | 内容与市场的契合度（30%） | 搜索潜力（20%） | 资源（10%） | 总分 |
|------|----------------------|-------------------------|----------------------|-----------------|-------|
| 主题 A | 8 | 9 | 7 | 6 | 8.0 |
| 主题 B | 6 | 7 | 9 | 8 | 7.1 |

## 内容更新与停止决策

只有当某些内容退出组合时，内容组合才能实现复利增长。每项策略都必须明确哪些事项将停止，而不只是哪些事项将开始。根据有时间标记的证据——流量、转化、排名和上次更新时间——审核现有资产，并为每项资产分配以下四种结果之一：

| 结果 | 适用情况 | 含义 |
|---|---|---|
| **保留** | 仍在实现其目标方面保持排名或带来转化，且其中的表述仍然有效 | 无需采取行动；按照正常频率进行下一次审核 |
| **更新** | 该主题仍然重要，且 URL 仍具有权威性，但内容已经衰退——数据过时、表述陈旧或排名下滑 | 在原位置重写，保留 URL，并记录新的上次更新时间 |
| **整合** | 两篇或更多内容针对相同意图，分散了自身的信号 | 合并到最具优势的 URL，将其他 URL 重定向，并纳入其中独有的章节 |
| **删除** | 该主题不再服务于任何支柱，或者连续两个审核周期都没有流量、没有转化，也没有战略用途 | 提议移除或取消索引——然后到此为止，因为 Boundaries 禁止执行这些操作 |

决策规则按以下顺序执行：意图重复 → 整合；否则，如果主题仍然对应一个有效支柱 → 更新；否则 → 删除。永远不要更新其所属支柱已经停用的内容——那只是戴着编辑帽子的沉没成本。每一行都要列出触发该决策的证据（指标、时间窗口、来源）以及负责的所有者；推荐就是全部工作，因为发布、删除、重定向和取消索引都需要明确授权。

将维持这项审核持续运行的周期性节奏——衰退监测、排名下降监测、更新队列——交给 `suede-marketing-loops`。这项 skill 决定哪些内容需要更新或删除；另一项 skill 决定检查运行的频率。

## 拒绝这些默认做法

通用的内容策略不假思索就能写出来，而问题恰恰在于此。不要交付：

- **以类别名词为支柱**——“生产力”“营销”“增长”。支柱应该是品牌可以占据的主张，并且要用客户的语言表达。
- **只是把支柱列表重新缩进后的集群图。** 如果每个分支都是支柱名称加一个修饰词，那就根本没有进行聚类。
- **“X 终极指南”“你需要了解的关于 X 的一切”“X 入门”**——这些标题放在哪个竞争对手的博客上都合适。
- **“Y 的 10 款最佳工具”，并把用户的产品排在第 1 位。** 那不叫比较。
- **没有负责人的发布节奏。** “每周发布 2 次”，却没有指定任何人，只是一厢情愿。
- **来源于模型一般知识而非上述研究渠道的主题。** 如果上述研究渠道都无法调用，请明确说明，并将这些想法标记为假设。

严格按照以下格式输出策略：

```
## Content pillars
| Pillar | The claim it owns | Evidence it matters to the ICP | Product connection |
|---|---|---|---|
| [pillar] | [one sentence] | [source + date] | [what it sells] |

## Priority topics
### [Topic title]
- **Type:** searchable / shareable / both — [use-case, hub-and-spoke, thought
  leadership, data-driven, case study, meta]
- **Target query + buyer stage:** [query] — [awareness / consideration /
  decision / implementation]
- **Why this topic:** [the customer-research evidence, with its source and date]
- **Score and owner:** [Impact / Fit / Search / Resources] = [total]; [owner,
  rough effort]

## Topic cluster map
[Pillar]
├── [Cluster]
│   ├── [Article] → links to [Article]
│   └── [Article]
└── [Cluster]
    └── [Article]

## Stop-doing
| Existing asset | Outcome | Evidence | Owner |
|---|---|---|---|
| [URL] | Keep / Refresh / Consolidate / Kill | [metric, window, source] | [who] |

## Open questions
[What could not be evidenced, and what would settle it]
```

## 边界

- 不要在未指出当前证据和决策标准的情况下，声称存在需求、权威性、排名潜力或受众匹配度。
- 未获得明确授权，不得发布、删除、重定向、取消索引或更改编辑日历或 CMS。
- 不要为了填补内容空白而捏造专业知识、客户证明、关键词数据或引用。
- 不要自行决定法律、权利或品牌主张相关问题；在发布前将其提交给负责的负责人处理。

## 路由

- 需要撰写单个资产 -> 使用 `suede-copy`。
- 需要技术性或页面内自然搜索诊断 -> 使用 `suede-seo-audit`。
- 需要规模化页面系统 -> 使用 `suede-programmatic-seo`。
- 需要制作邮件或社交媒体内容 -> 使用 `suede-emails` 或 `suede-social`。
- 需要以角色形式配备流程，并包含合同、交接记录，以及每个分发资产各自独立的论点 -> 使用 `suede-newsroom`。每周一次、为不同的创始人账号和公司账号内容线提供素材的创始人访谈或语音备忘录，应使用该技能的创始人主导模式。
- 需要按固定节奏运行内容刷新、衰退或排名下降审计 -> 使用 `suede-marketing-loops`。
- 需要将标题、钩子或 CTA 背后的行为机制表述为可测试的假设 -> 使用 `suede-marketing-psychology`。
- 对于上述技能，将组合优先级、支柱、集群和节奏重新路由回 `suede-content-strategy`。
