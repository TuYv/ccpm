# Suede 内容策略

使用此 Suede 内容策略手册来规划有证据支撑的内容，以赢得搜索流量、分享、信任或高质量需求。

## 规划前

如果 `.agents/product-marketing.md` 存在，请先阅读它，并且只询问其中未涵盖的内容；有关路径回退，请参阅 `suede-product-marketing`。

收集以下背景信息（如未提供则询问）：

### 1. 业务背景
- 公司是做什么的？
- 理想客户是谁？
- 内容的主要目标是什么？（流量、潜在客户、品牌知名度、思想领导力）
- 你的产品解决哪些问题？

### 2. 客户研究
- 客户购买前会问哪些问题？
- 销售电话中会出现哪些异议？
- 支持工单中反复出现哪些主题？
- 客户使用什么语言来描述他们的问题？

### 3. 当前状态
- 你是否有现有内容？哪些内容有效？
- 你拥有哪些资源？（写作者、预算、时间）
- 你可以产出哪些内容形式？（文字、视频、音频）

### 4. 竞争格局
- 你的主要竞争对手是谁？
- 你的市场中存在哪些内容缺口？

## 可搜索与可分享

每篇内容都必须具备可搜索性、可分享性，或两者兼具。可搜索性默认是首要优先级，因为搜索需求可衡量；将此视为起始规则，而非普遍真理，并在用户目标或证据表明应当反转时进行反转（例如没有搜索量的品类、品牌主导的发布）。记录你选择的顺序及原因——这将影响“内容创意优先级排序”中的权重。

**可搜索内容** 捕获现有需求。针对正在主动寻找答案的人进行优化。

**可分享内容** 创造需求。传播观点并引发讨论。

### 撰写可搜索内容时

- 锁定特定关键词或问题
- 精确匹配搜索意图——回答搜索者想知道的内容
- 使用与搜索查询相匹配的清晰标题
- 使用反映搜索模式的标题结构
- 在标题、标题层级、第一段、URL 中放置关键词
- 提供全面覆盖（不要留下未解答的问题）
- 包含数据、示例以及权威来源链接
- 为 AI/LLM 发现进行优化：清晰定位、结构化内容、全网一致的品牌形象

### 撰写可分享内容时

- 以新颖洞察、原创数据或反直觉观点开篇
- 以论证充分的观点挑战传统认知
- 讲述能让人产生情感共鸣的故事
- 创作人们愿意分享、以显得聪明或帮助他人的内容
- 关联当前趋势或新兴问题
- 分享他人可以从中学习的脆弱而真诚的经历

## 内容类型

### 可搜索内容类型

**使用场景内容**
公式：[persona] + [use-case]。面向长尾关键词。
- “面向设计师的项目管理”
- “面向开发者的任务跟踪”
- “面向自由职业者的客户协作”

**中心页与辐射页**
中心页 = 全面概述。辐射页 = 相关子主题。先创建中心页，再构建辐射页，并在它们之间进行内部链接。有关结构和 URL 指导，请参阅下方的“内容支柱与主题集群”。

**模板库**
高意向关键词 + 产品采用。
- 以“marketing plan template”等搜索为目标
- 提供即时的独立价值
- 展示产品如何增强模板的效果

### 可分享的内容类型

**思想领导力**
- 阐述每个人都能感受到、但尚未命名的概念
- 用证据挑战传统观念
- 分享脆弱而诚实的经历

**数据驱动型内容**
- 产品数据分析（匿名化洞察）
- 公共数据分析（发现模式）
- 原创研究（开展实验并分享结果）

**专家汇总**
邀请一组经过筛选且已验证的相关专家，回答一个具体问题。
分发效果取决于贡献者的许可和实际推广情况。

**案例研究**
结构：挑战 → 解决方案 → 结果 → 关键经验

**元内容**
幕后透明内容。“我们如何实现首个 $5k MRR”，“为什么我们选择负债融资而不是 VC”。

对于大规模程序化内容，将数据和模板系统交给
`suede-programmatic-seo`。

## 内容支柱与主题集群

内容支柱是你的品牌将重点占据的 3-5 个核心主题；每个支柱都会衍生出一个相关内容集群。大多数情况下，只要做好内部链接，所有内容都可以放在 `/blog` 下。只有具备多层深度的综合性资源，才需要使用带有自定义 URL 结构的独立支柱页面（例如 `/guides/topic`）。

### 如何识别支柱

1. **产品导向**：你的产品解决了哪些问题？
2. **受众导向**：你的 ICP 需要了解什么？
3. **搜索导向**：你的领域中哪些主题具有搜索量？
4. **竞争对手导向**：竞争对手在什么内容上获得了排名？

结构为支柱（中心页）→ 子主题集群 → 文章；每篇文章都应链接到同级文章以及上级中心页。Output Format 中的 Topic cluster map 就是需要输出的结构。

### 支柱标准

优秀的支柱应当：
- 与你的产品/服务保持一致
- 符合受众关心的内容
- 具有搜索量和/或社交媒体关注度
- 足够宽泛，能够容纳许多子主题

## 按买家阶段进行关键词研究

使用每个阶段对应的修饰词集合，将主题映射到买家旅程中：

| 阶段 | 修饰词 | 触发因素 |
|---|---|---|
| **认知** | "what is," "how to," "guide to," "introduction to" | 客户询问基础知识 |
| **考虑** | "best," "top," "vs," "alternatives," "comparison" | 客户正在评估多个工具 |
| **决策** | "pricing," "reviews," "demo," "trial," "buy" | 销售电话中开始讨论价格 |
| **实施** | "templates," "examples," "tutorial," "how to use," "setup" | 支持工单显示出设置方面的困难 |

以项目管理工具的 Consideration 阶段为例：“Best Project Management Tools for Remote Teams”、“Asana vs Trello vs Monday”、“Basecamp Alternatives”。针对每个阶段应用相同模式，使用用户自己的类别名词，绝不要使用这些示例中的词语。

## 内容创意来源

### 研究面检查

在进行外部研究之前，检查当前会话中可调用且已获授权的工具和已连接来源。仅在确实拥有访问权限时，使用产品分析、Search
Console 或关键词导出、客户资料、支持数据、获批准的 Drive
来源，或可调用的浏览器/搜索界面。
记录每个来源的 URL 或文件、所有者、检索日期以及相关范围。

如果没有可用的外部研究渠道，请继续使用用户提供的 URL、导出文件、转录内容和已知的一手证据。否则，请返回一份简明的手动研究清单，其中包含确切的查询语句和需要记录的字段。为假设和未经验证的竞争对手观察结果添加标签；绝不要暗示已经执行过搜索。

### 1. 关键词数据

如果用户提供了关键词导出数据（Ahrefs、SEMrush、GSC），请分析：
- 主题集群（将相关关键词分组）
- 买家阶段（认知/考虑/决策/实施）
- 搜索意图（信息型、商业型、交易型）
- 快速获胜机会（竞争度低 + 搜索量尚可 + 相关性高）
- 内容差距（竞争对手排名而你没有排名的关键词）

以优先级表格输出：
| 关键词 | 搜索量 | 难度 | 买家阶段 | 内容类型 | 优先级 |

### 2. 通话转录内容

如果用户提供了销售或客户通话转录内容，请提取：
- 提出的问题 → FAQ 内容或博客文章
- 痛点 → 使用客户自己的措辞描述问题
- 异议 → 需要主动回应的内容
- 语言模式 → 应使用的确切措辞（客户之声）
- 提及的竞争对手 → 他们将你与谁进行了比较

输出内容创意，并附上支持性引述。

### 3. 调查回复

如果用户提供了调查数据，请挖掘：
- 开放式回复（主题和措辞）
- 常见主题，并记录样本数量和观察到的比例
- 资源需求（他们希望已有但尚不存在的内容）
- 内容偏好（他们希望采用的格式）

### 4. 论坛研究

如果当前可以调用经授权的浏览器或搜索渠道，请使用它来查找近期的一手社区证据。否则，请请求相关 URL，或提供以下查询语句供手动收集。

**Reddit：** `site:reddit.com [topic]`
- 相关子版块中的热门帖子
- 评论中的问题和不满
- 获得赞同的回答（验证哪些内容引发共鸣）

**Quora：** `site:quora.com [topic]`
- 关注人数最多的问题
- 获得高度赞同的回答

**其他：** Indie Hackers、Hacker News、Product Hunt、行业 Slack/Discord

对于每一项，请记录来源 URL、发布日期、检索日期、社区背景以及简短的证据摘录。区分互动信号与客户需求的证明。

### 5. 竞争对手分析

使用当前可以调用且获得授权的浏览器/搜索渠道，或使用用户提供的竞争对手 URL。如果两者都不可用，请生成手动研究检查清单，不要编造页面清单、排名、互动数据或差距。

**查找他们的内容：** `site:competitor.com/blog`

**分析：**
- 可观察到的文章及带日期的互动信号
- 反复涉及的主题
- 他们尚未覆盖的差距
- 案例研究（客户问题、使用场景、结果）
- 内容结构（支柱、分类、格式）

**确定需要验证的假设：**
- 你可以做得更好的主题
- 他们遗漏的角度
- 基于可见日期或过时说法、可以改进的过时内容

### 6. 销售与支持输入

从面向客户的团队中提取：
- 常见异议
- 重复出现的问题
- 支持工单模式
- 成功案例
- 功能请求及其背后的问题

## 内容创意优先级排序

从四个因素对每个创意进行评分。以下权重只是一个说明性的起点，
并非普遍真理；应根据用户的业务目标进行调整，并记录所选的决策规则。

### 1. 客户影响（40%）
- 该主题在研究中出现的频率有多高？
- 有多少比例的客户面临这一挑战？
- 这个痛点引发的情绪有多强烈？
- 有这种需求的客户，其潜在 LTV 是多少？

### 2. 内容-市场匹配度（30%）
- 这是否与您的产品所解决的问题一致？
- 您能否从客户研究中提供独特见解？
- 您是否有客户案例来支持这一点？
- 这是否会自然引导至对产品的兴趣？

### 3. 搜索潜力（20%）
- 每月搜索量是多少？
- 该主题的竞争程度如何？
- 是否存在相关的长尾机会？
- 搜索兴趣是在增长还是下降？

### 4. 资源要求（10%）
- 您是否具备创建权威内容所需的专业知识？
- 还需要进行哪些额外研究？
- 您将需要哪些资产（图形、数据、示例）？

### 评分模板

| 创意 | 客户影响（40%） | 内容-市场匹配度（30%） | 搜索潜力（20%） | 资源（10%） | 总分 |
|------|----------------------|-------------------------|----------------------|-----------------|-------|
| 主题 A | 8 | 9 | 7 | 6 | 8.0 |
| 主题 B | 6 | 7 | 9 | 8 | 7.1 |

## 更新与停止执行决策

只有当某些内容退出时，内容组合才能产生复利。每项策略都必须明确哪些要停止，而不只是哪些要开始。根据有时效性的证据——流量、转化、排名和最后更新时间——审查现有资产，并为每项内容指定以下四种结果之一：

| 结果 | 适用情况 | 含义 |
|---|---|---|
| **保留** | 仍在围绕其目标获得排名或产生转化，且相关主张仍然有效 | 无需操作；在正常节奏下进行下一次审查 |
| **更新** | 该主题仍然重要，且 URL 仍具权威性，但内容已经衰退——数据过时、主张陈旧，或排名下滑 | 原地重写，保留 URL，并记录新的最后更新时间 |
| **合并** | 两篇或更多内容针对相同意图，分散了彼此的信号 | 合并至最强的 URL，重定向其他 URL，并纳入其中独有的部分 |
| **删除** | 该主题不再服务于某个支柱，或连续两个审查周期均无流量、无转化、无战略用途 | 建议移除或取消索引——并到此为止，因为 Boundaries 禁止执行此操作 |

按顺序执行的决策规则：意图重复 → 合并；否则，主题仍映射到活跃支柱 → 更新；否则 → 删除。绝不要更新其支柱已被淘汰的内容——那只是戴着编辑帽的沉没成本。每一行都要注明触发该决定的证据（指标、周期、来源）以及负责的所有者；建议本身就是全部工作，因为发布、删除、重定向和取消索引都需要明确授权。

将维持此审查持续运行的循环节奏——衰退监控、排名下滑监控、更新队列——交给 `suede-marketing-loops`。此技能决定哪些内容需要更新或删除；那个技能决定检查的运行频率。

## 拒绝这些默认做法

通用的内容策略几乎会自行形成，而这恰恰是问题所在。不要交付：

- **以品类名词作为支柱** ——“Productivity”“Marketing”“Growth”。支柱应是一项品牌能够占据的主张，并且要用客户的语言表达。
- **只是将支柱列表重新缩进的集群图。** 如果每个分支都是支柱名称加上一个修饰词，那就根本没有进行聚类。
- **“The Ultimate Guide to X”“Everything You Need to Know About X”“X 101”** ——任何竞争对手博客上都可能出现的标题。
- **“10 Best Tools for Y”，且用户的产品排在第 #1 位。** 这不是对比。
- **没有负责人的发布节奏。** “Publish 2x/week”但没有指定任何人，只是一个愿望。
- **源自模型通用知识的话题**，而非上述研究渠道。如果没有任何渠道可调用，请明确说明，并将这些想法标记为假设。

## 输出格式

严格按照以下结构输出策略：

```
## Content pillars
| Pillar | The claim it owns | Evidence it matters to the ICP | Product connection |
|---|---|---|---|
| [pillar] | [one sentence] | [source + date] | [what it sells] |

## Priority topics
### [Topic title]
- **Type:** searchable / shareable / both — [use-case, hub-and-spoke, thought
  leadership, data-driven, case study, meta]
- **Target query + buyer stage:** [query] — [awareness / consideration /
  decision / implementation]
- **Why this topic:** [the customer-research evidence, with its source and date]
- **Score and owner:** [Impact / Fit / Search / Resources] = [total]; [owner,
  rough effort]

## Topic cluster map
[Pillar]
├── [Cluster]
│   ├── [Article] → links to [Article]
│   └── [Article]
└── [Cluster]
    └── [Article]

## Stop-doing
| Existing asset | Outcome | Evidence | Owner |
|---|---|---|---|
| [URL] | Keep / Refresh / Consolidate / Kill | [metric, window, source] | [who] |

## Open questions
[What could not be evidenced, and what would settle it]
```

## 边界

- 未说明当前证据和决策标准时，不要声称存在需求、权威性、排名潜力或受众契合度。
- 未获得明确授权时，不要发布、删除、重定向、取消索引，或更改编辑日历或 CMS。
- 不要编造专业能力、客户证明、关键词数据或引用来填补内容空白。
- 不要决定法律、权利或品牌主张相关的问题；发布前请将其标记给负责的所有者。

## 路由

- 需要撰写单个内容资产 -> 使用 `suede-copy`。
- 需要技术性或页面内自然搜索诊断 -> 使用 `suede-seo-audit`。
- 需要规模化页面系统 -> 使用 `suede-programmatic-seo`。
- 需要电子邮件或社交媒体内容制作 -> 使用 `suede-emails` 或 `suede-social`。
- 需要按固定节奏运行刷新、衰减或排名下滑审计 -> 使用 `suede-marketing-loops`。
- 需要阐明标题、钩子或 CTA 背后的行为机制，并将其表述为可测试的假设 -> 使用 `suede-marketing-psychology`。
- 从这些技能中，将内容组合优先级、支柱、集群和节奏路由回 `suede-content-strategy`。
