# Suede 内容策略

使用这份 Suede 内容策略手册，规划有证据支持的内容，以赢得搜索流量、分享、信任或高质量需求。

## 规划前

如果 `.agents/product-marketing.md` 存在，请先阅读；只询问其中未涵盖的信息；路径回退方案请参见 `suede-product-marketing`。

收集以下背景信息（如果未提供，请询问）：

### 1. 业务背景
- 公司做什么？
- 理想客户是谁？
- 内容的主要目标是什么？（流量、潜在客户、品牌知名度、思想领导力）
- 产品解决了哪些问题？

### 2. 客户研究
- 客户在购买前会提出哪些问题？
- 销售电话中会出现哪些异议？
- 支持工单中反复出现哪些主题？
- 客户会使用什么措辞来描述他们的问题？

### 3. 当前状态
- 是否已有现成内容？哪些内容表现良好？
- 你有哪些资源？（作者、预算、时间）
- 你可以制作哪些内容形式？（文字、视频、音频）

### 4. 竞争格局
- 主要竞争对手是谁？
- 市场中存在哪些内容空白？

## 可搜索内容与可分享内容

每一篇内容都必须具备可搜索性、可分享性，或同时具备二者。可搜索性默认应作为首要优先级，因为搜索需求是可衡量的；但要把这当作起始规则，而不是普遍真理，并在用户目标或证据表明应当反过来时调整顺序（例如没有搜索量的品类，或以品牌为主导的发布）。记录你选择该顺序的原因——它会影响“内容创意优先级排序”中的权重。

**可搜索内容**承接现有需求。面向正在主动寻找答案的人进行优化。

**可分享内容**创造需求。传播观点，并引发人们讨论。

### 编写可搜索内容时

- 瞄准一个具体关键词或问题
- 完全匹配搜索意图——回答搜索者想要了解的内容
- 使用与搜索查询相匹配的清晰标题
- 使用反映搜索模式的标题结构
- 将关键词放入标题、各级标题、第一段和 URL 中
- 提供全面覆盖（不要留下未解答的问题）
- 包含数据、示例以及指向权威来源的链接
- 针对 AI/LLM 发现进行优化：清晰的定位、结构化内容，以及在整个网络上保持品牌一致性

### 编写可分享内容时

- 以新颖洞察、原创数据或反直觉的观点开篇
- 用有充分论证的观点挑战传统认知
- 讲述能让人产生情感共鸣的故事
- 创作人们愿意分享、以展示自身智慧或帮助他人的内容
- 联系当前趋势或新兴问题
- 分享他人可以从中学习的真实、坦诚经历，包括脆弱的一面

## 内容类型

### 可搜索内容类型

**使用场景内容**  
公式：[persona] + [use-case]。瞄准长尾关键词。
- “面向设计师的项目管理”
- “面向开发者的任务跟踪”
- “面向自由职业者的客户协作”

**中心与辐射**  
中心 = 全面的概览。辐射 = 相关子主题。先创建中心内容，然后构建辐射内容，并在它们之间建立互链。有关其结构和 URL 指导，请参见下文的“内容支柱与主题集群”。

**模板库**
高意向关键词 + 产品采用。
- 瞄准“marketing plan template”之类的搜索
- 提供即时的独立价值
- 展示产品如何增强模板的效果

### 可分享的内容类型

**思想领导力**
- 阐明每个人都有感受、但尚未为其命名的概念
- 用证据挑战传统认知
- 分享脆弱、诚实的经历

**数据驱动型内容**
- 产品数据分析（经过匿名化的洞察）
- 公开数据分析（发现规律）
- 原创研究（开展实验并分享结果）

**专家汇编**
邀请一组经过筛选、相关且经过验证的专家回答一个特定问题。
传播效果取决于贡献者的许可和实际推广情况。

**案例研究**
结构：挑战 → 解决方案 → 结果 → 关键经验

**元内容**
幕后透明分享。“我们如何实现首个 $5k MRR”，“为什么我们选择债务融资而不是 VC”。

对于大规模的程序化内容，将数据和模板系统交由
`suede-programmatic-seo` 处理。

## 内容支柱与主题集群

内容支柱是你的品牌将要占据的 3-5 个核心主题；每个支柱都会衍生出一组相关内容。在大多数情况下，只要做好内部链接，所有内容都可以放在 `/blog` 下。只有对于包含多层深度的综合性资源，才需要采用自定义 URL 结构的专门支柱页面（例如 `/guides/topic`）。

### 如何识别内容支柱

1. **以产品为导向**：你的产品解决什么问题？
2. **以受众为导向**：你的 ICP 需要了解什么？
3. **以搜索为导向**：你的领域中哪些主题具有搜索量？
4. **以竞争对手为导向**：竞争对手正在为哪些关键词排名？

结构为支柱（中心页）→ 子主题集群 → 文章，每篇文章都链接到其同级文章以及中心页。Output Format 中的 Topic cluster map 就是要输出的结构。

### 内容支柱标准

优秀的内容支柱应当：
- 与你的产品/服务保持一致
- 符合受众关心的内容
- 具有搜索量和/或社交媒体关注度
- 足够宽泛，能够涵盖许多子主题

## 按买家阶段进行关键词研究

使用每个阶段对应的修饰词集合，将主题映射到买家旅程：

| 阶段 | 修饰词 | 触发因素 |
|---|---|---|
| **认知** | “what is”、“how to”、“guide to”、“introduction to” | 客户在询问基础信息 |
| **考虑** | “best”、“top”、“vs”、“alternatives”、“comparison” | 客户正在评估多个工具 |
| **决策** | “pricing”、“reviews”、“demo”、“trial”、“buy” | 销售通话中开始讨论定价 |
| **实施** | “templates”、“examples”、“tutorial”、“how to use”、“setup” | 支持工单显示出设置方面的困难 |

以项目管理工具的考虑阶段为例：“Best Project Management Tools for Remote Teams”、“Asana vs Trello vs Monday”、“Basecamp Alternatives”。针对每个阶段应用相同的模式，使用用户自己的类别名词，绝不要使用这里的这些名词。

## 内容创意来源

### 研究面检查

在进行外部研究之前，检查当前会话中可调用且已获授权的工具和已连接来源。仅在实际存在访问权限时，使用产品分析、Search
Console 或关键词导出、客户材料、支持数据、获批准的 Drive
来源，或可调用的浏览器/搜索界面。记录每个来源的 URL 或文件、所有者、检索日期以及相关范围。

如果没有可用的外部研究渠道，请继续使用用户提供的 URL、导出数据、转录文本和已知的一手证据。否则，返回一份精简的手动研究清单，其中包含准确的查询语句和需要记录的字段。标注假设和未经验证的竞争对手观察结果；绝不要暗示已经执行过搜索。

### 1. 关键词数据

如果用户提供了关键词导出数据（Ahrefs、SEMrush、GSC），请分析：
- 主题集群（将相关关键词分组）
- 买家阶段（认知/考虑/决策/实施）
- 搜索意图（信息型、商业型、交易型）
- 快速见效机会（低竞争度 + 适当搜索量 + 高相关性）
- 内容缺口（竞争对手排名而你没有排名的关键词）

以优先级表格输出：
| 关键词 | 搜索量 | 难度 | 买家阶段 | 内容类型 | 优先级 |

### 2. 通话转录

如果用户提供了销售或客户通话转录，请提取：
- 提出的问题 → FAQ 内容或博客文章
- 痛点 → 用他们自己的话描述的问题
- 异议 → 用于主动回应的内容
- 语言模式 → 要使用的确切措辞（客户原声）
- 提及的竞争对手 → 他们拿你与谁进行了比较

输出内容创意，并附上支持性引述。

### 3. 调查回复

如果用户提供了调查数据，请挖掘：
- 开放式回复（主题和语言）
- 常见主题，并记录样本数量和观察到的比例
- 资源需求（他们希望现有何种资源）
- 内容偏好（他们想要的格式）

### 4. 论坛研究

如果当前可以调用已授权的浏览器或搜索渠道，请使用它来查找近期的一手社区证据。否则，请索要相关 URL，或提供以下查询语句供手动收集。

**Reddit：** `site:reddit.com [topic]`
- 相关子版块中的热门帖子
- 评论中的问题和挫折
- 获得点赞的回答（验证哪些内容引发共鸣）

**Quora：** `site:quora.com [topic]`
- 关注者最多的问题
- 获得大量点赞的回答

**其他：** Indie Hackers、Hacker News、Product Hunt、行业 Slack/Discord

对于每个项目，记录来源 URL、发布日期、检索日期、社区背景以及简短的证据摘录。区分互动信号与客户需求的证明。

### 5. 竞争对手分析

使用当前可调用且已获授权的浏览器/搜索渠道，或使用用户提供的竞争对手 URL。如果两者都不可用，则生成一份手动研究清单，不要虚构页面清单、排名、互动数据或内容缺口。

**查找其内容：** `site:competitor.com/blog`

**分析：**
- 可观察到的文章和带日期的互动信号
- 反复覆盖的主题
- 他们尚未覆盖的缺口
- 案例研究（客户问题、使用场景、结果）
- 内容结构（支柱、类别、格式）

**确定需要验证的假设：**
- 你可以做得更好的主题
- 他们遗漏的角度
- 可以改进的过时内容，依据是可见日期或陈旧的论断

### 6. 销售和支持输入

从面向客户的团队中提取：
- 常见异议
- 重复出现的问题
- 支持工单模式
- 成功案例
- 功能请求及其背后的问题

## 内容创意优先级排序

从四个因素对每个创意进行评分。以下权重只是一个示例性的起点，并非适用于所有情况的普遍真理；请根据用户的业务目标进行调整，并记录所采用的决策规则。

### 1. 客户影响力（40%）
- 这个主题在研究中出现的频率有多高？
- 有多大比例的客户面临这一挑战？
- 这个痛点引发的情绪有多强烈？
- 有此需求的客户的潜在 LTV 是多少？

### 2. 内容-市场契合度（30%）
- 这是否与产品所解决的问题一致？
- 能否利用客户研究提供独特的洞察？
- 是否有客户案例可以支持这一点？
- 这是否会自然地引发用户对产品的兴趣？

### 3. 搜索潜力（20%）
- 每月搜索量是多少？
- 这个主题的竞争程度如何？
- 是否存在相关的长尾机会？
- 搜索兴趣是在增长还是下降？

### 4. 资源需求（10%）
- 是否具备创建权威内容所需的专业知识？
- 还需要进行哪些额外研究？
- 需要哪些素材（图形、数据、示例）？

### 评分模板

| 创意 | 客户影响力（40%） | 内容-市场契合度（30%） | 搜索潜力（20%） | 资源（10%） | 总分 |
|------|------------------|----------------------|----------------|------------|------|
| 主题 A | 8 | 9 | 7 | 6 | 8.0 |
| 主题 B | 6 | 7 | 9 | 8 | 7.1 |

## 更新与停止执行决策

只有当某些内容退出组合时，组合才能实现复利增长。每项策略都必须明确哪些事情将停止，而不仅仅是哪些事情将开始。根据有时间标记的证据——流量、转化、排名和上次更新时间——审查现有资产，并为每项资产分配以下四种结果之一：

| 结果 | 适用情况 | 含义 |
|---|---|---|
| **保留** | 仍然按照目标获得排名或转化，且其中的论断仍然是最新的 | 不采取行动；按照正常周期进行下一次审查 |
| **更新** | 主题仍然重要，URL 仍然具有权威性，但内容已经衰退——数据过时、论断陈旧或排名下滑 | 在原位置重写，保留 URL，并记录新的上次更新时间 |
| **合并** | 两篇或更多内容针对相同的搜索意图，分散了各自的信号 | 合并到最强的 URL，将其他 URL 重定向，并纳入其中独有的部分 |
| **删除** | 该主题不再服务于任何支柱，或者连续两个审查周期都没有流量、没有转化，也没有战略用途 | 提议移除或取消索引——并止步于此，因为 Boundaries 禁止执行该操作 |

决策规则依次为：意图重复 → 合并；否则，如果主题仍然对应某个有效支柱 → 更新；否则 → 删除。绝不要更新所属支柱已被弃用的内容——那只是披着编辑外衣的沉没成本。每一行都要写明触发该决策的证据（指标、时间窗口、来源）以及负责的所有者；提出建议就是全部工作，因为发布、删除、重定向和取消索引都需要明确授权。

将维持这项审计运行的定期节奏——衰退监测、排名下降监测、更新队列——交给 `suede-marketing-loops`。此技能决定哪些内容需要更新或删除；该技能决定检查运行的频率。

## 摒弃这些默认做法

通用的内容策略几乎可以自行生成，而问题恰恰在于此。不要交付以下内容：

- **使用类别名词作为支柱**——“生产力”“营销”“增长”。支柱应该是品牌能够占据的主张，并且要用客户自己的话来表达。
- **只是把支柱列表重新缩进后的集群图。** 如果每个分支都是支柱名称加一个修饰词，那就说明根本没有完成聚类。
- **“X 终极指南”“你需要了解的关于 X 的一切”“X 入门”**——这些标题放在任何竞争对手的博客上都成立。
- **“Y 的 10 款最佳工具”，并把自家产品排在第 1 位。** 那不叫比较。
- **没有负责人的发布节奏。** “每周发布 2 次”，却没有指定任何人，只是一厢情愿。
- **来自模型通用知识的选题**，而不是来自上述研究渠道。如果没有任何渠道可调用，就明确说明，并将这些想法标记为假设。

严格按照以下结构输出策略：

```
## Content pillars
| Pillar | The claim it owns | Evidence it matters to the ICP | Product connection |
|---|---|---|---|
| [pillar] | [one sentence] | [source + date] | [what it sells] |

## Priority topics
### [Topic title]
- **Type:** searchable / shareable / both — [use-case, hub-and-spoke, thought
  leadership, data-driven, case study, meta]
- **Target query + buyer stage:** [query] — [awareness / consideration /
  decision / implementation]
- **Why this topic:** [the customer-research evidence, with its source and date]
- **Score and owner:** [Impact / Fit / Search / Resources] = [total]; [owner,
  rough effort]

## Topic cluster map
[Pillar]
├── [Cluster]
│   ├── [Article] → links to [Article]
│   └── [Article]
└── [Cluster]
    └── [Article]

## Stop-doing
| Existing asset | Outcome | Evidence | Owner |
|---|---|---|---|
| [URL] | Keep / Refresh / Consolidate / Kill | [metric, window, source] | [who] |

## Open questions
[What could not be evidenced, and what would settle it]
```

## 边界

- 如果不指出当前证据和决策标准，不得声称存在需求、权威性、排名潜力或受众匹配度。
- 未经明确授权，不得发布、删除、重定向、取消索引，也不得更改编辑日历或 CMS。
- 不得为了填补内容空白而捏造专业能力、客户证明、关键词数据或引文。
- 不得自行决定法律、权利或品牌声明相关问题；发布前应将其标记出来，交由负责的负责人处理。

## 路由

- 需要撰写单个资产 → 使用 `suede-copy`。
- 需要进行技术诊断或页面有机搜索诊断 → 使用 `suede-seo-audit`。
- 需要构建规模化页面系统 → 使用 `suede-programmatic-seo`。
- 需要制作电子邮件或社交媒体内容 → 使用 `suede-emails` 或 `suede-social`。
- 需要将流程配置为带有角色、合同、交接记录，并且每个分发资产都具备一个独立论点的团队 → 使用 `suede-newsroom`。
- 需要按固定节奏运行内容刷新、衰退或排名下降审计 → 使用 `suede-marketing-loops`。
- 需要将标题、钩子或 CTA 背后的行为机制表述为可测试的假设 → 使用 `suede-marketing-psychology`。
- 从这些技能中，将组合优先级、支柱、集群和发布节奏重新路由回 `suede-content-strategy`。
