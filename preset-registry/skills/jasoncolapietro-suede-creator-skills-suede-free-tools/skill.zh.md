# Suede 免费工具增长策略

当一个真正有用的工具能够带来高质量的发现机会，并自然地将用户引导至付费产品时，Suede 会将工程能力用作营销手段。选择、评分并限定范围，打造一个最小且可维护的计算器、评分器、生成器或实用工具，使其输出能够赢得关注，而不只是获取关注。

## 初步评估

**先检查产品营销背景：**
如果 `.agents/product-marketing.md` 存在（或者在较早的设置中存在 `.claude/product-marketing.md`，或旧版文件名 `product-marketing-context.md`），请先阅读，再提出问题。使用其中的背景信息，只询问该信息尚未涵盖或与此任务具体相关的内容。

在设计工具策略之前，需要了解：

1. **业务背景** - 核心产品是什么？目标受众是谁？他们面临哪些问题？

2. **目标** - 线索生成？SEO/流量？品牌知名度？产品教育？每条线索的价值是多少（该来源的 LTV 和成交率）？

3. **资源** - 是否具备构建工具的技术能力？是否有持续维护的带宽？用于推广的预算是多少？时间安排如何？

4. **现有行为** - 受众目前使用哪些工具或手动替代方案？现在如何生成线索？

## 核心原则

### 1. 解决真实问题
- 工具必须提供真正的价值
- 解决受众实际存在的问题
- 即使不使用你的主产品，也应当有用

### 2. 与核心产品相邻
- 与你销售的产品相关
- 能够自然地从工具引导至产品
- 帮助用户了解你所解决的问题

### 3. 简单且聚焦
- 专注做好一件事
- 使用门槛低
- 立即提供价值

### 4. 值得投入
- 线索价值 × 预期线索数 > 构建成本 + 维护成本

在做出是否推进的判断之前，先填写全部四项，并展示计算过程：
- **线索价值** = 客户 LTV × 该线索来源的成交率，数据来自需求收集表中的数字。
- **预期线索数** = SEO 目标关键词的月搜索量 × 明确说明的访问到使用转化率 × 明确说明的使用到留资转化率。
- **构建成本** = 下方 MVP 范围所需的工程师天数。
- **维护成本** = 每季度用于保持数据、依赖项和托管环境最新所需的工程师天数。

说明你假设的每个转化率，以及这些假设的来源。如果某一项无法找到来源，
请指出具体是哪一项，并将是否推进的结论标记为未解决，而不是自行填入数值。

| 类型 | 示例 | 最适合的场景 |

## 构思框架

### 从痛点入手

1. **你的受众会在 Google 上搜索哪些问题？** - 搜索查询研究、常见问题

2. **哪些手动流程很繁琐？** - 电子表格任务、重复性计算

3. **购买你的产品前，他们需要什么？** - 评估、规划、比较

4. **他们希望拥有但目前缺少哪些信息？** - 难以轻松获取的数据、基准数据

### 验证想法

- **搜索需求**：是否存在搜索量？竞争有多激烈？
- **独特性**：现有哪些方案？如何做到好 10 倍？
- **潜在客户质量**：这个受众是否与买家匹配？
- **构建可行性**：复杂程度如何？能否确定 MVP 的范围？

## 潜在客户获取策略

### 门槛设置选项

| 方式 | 优点 | 缺点 |
|----------|------|------|
| 完全设置门槛 | 最大化获取量 | 使用量较低 |
| 部分设置门槛 | 兼顾两者 | 常见模式 |
| 不设置门槛 + 可选 | 最大化触达范围 | 获取量较低 |
| 完全不设置门槛 | 纯 SEO/品牌建设 | 没有直接潜在客户 |

### 潜在客户获取最佳实践
- 价值交换清晰：“获取完整报告”
- 尽量减少阻力：只需填写电子邮件
- 展示他们将获得的内容预览
- 可选：通过提出一个资格筛选问题进行细分

门槛设置本身的权衡——每个字段的转化成本以及如何阐述这种交换——由
`suede-lead-magnets` 负责。决定需要用户提供哪些信息时，请使用其中的门槛设置表；上面的表格仅涵盖工具在哪个位置设置门槛。

## SEO 注意事项

### 关键词策略
**工具落地页**：“[事物] calculator”、“[事物] generator”、“free [工具类型]”

**辅助内容**：“How to [使用场景]”、“What is [概念]”

### 链接建设
免费工具能够吸引链接，因为它们：
- 真正有用（人们会引用它们）
- 独特（不能随便链接到任何页面）
- 易于分享（能够通过社交传播扩大影响）

## 构建还是购买

### 定制构建
适用情况：独特概念、品牌核心、高战略价值、拥有开发能力

### 使用无代码工具
选项：Outgrow、Involve.me、Typeform、Tally、Bubble、Webflow
适用情况：需要快速上市、开发资源有限、测试概念

### 嵌入现有工具
适用情况：已有优质方案、可用白标、并非核心差异化因素

## MVP 范围

### 最小可行工具
1. 仅实现核心功能——专注做好一件事，并且可靠运行
2. 必要的 UX——输入清晰、输出直观、适配移动设备
3. 基本的潜在客户获取——收集电子邮件，并将潜在客户发送到有用的位置

### 初期应跳过的内容
创建账户、保存结果、高级功能、完美设计、覆盖每一种边缘情况

## 输出格式

严格返回以下部分：

### 1. 推荐工具
工具名称，以及它为用户完成的工作的一句话描述。

### 2. 评分卡
填写完整的表格，为每个因素给出分数、总分和结论等级。对于三个有锚定标准的因素，说明该分数背后的证据。

### 3. MVP 范围
明确列出两个清单：**包含**（v1 要做什么）和 **不包含**（有意推迟什么）。任何项目都不能同时出现在两个清单中。

### 4. 门控决策
选择“门控选项”中的一个选项，并用一句话说明所接受的权衡。

### 5. SEO 目标
工具页面的单一目标查询词，以及配套内容的查询词。

### 6. 数据采集交接
工具必须发出的两到三个使用事件（use、complete、capture），以便 `suede-analytics` 读取漏斗数据。此技能本身不定义指标计划。

## 边界

- 没有证据和注明日期的假设时，不要声称存在搜索需求、潜在客户数量、链接潜力或构建可行性。
- 除非用户授权实施，否则不要构建、部署、发布、收集潜在客户或连接生产数据。
- 不要虚构工具输出，也不要将计算器伪装成专业、法律、医疗或财务建议。
- 不要替用户决定定价、数据保留或同意政策。

## 路由

- 可下载资产使用 `suede-lead-magnets`，公共转化页面使用 `suede-site-alchemy`。
- 搜索验证使用 `suede-seo-audit`，使用情况衡量使用 `suede-analytics`。
- 捕获后的生命周期序列使用 `suede-emails`。
- 工具页面周边的配套内容使用 `suede-content-strategy`。
- 工具分发和发布推广使用 `suede-ads` 和 `suede-social`。
- 工具页面或其门控流程的测试设计与评估使用 `suede-ab-testing`。
