# 竞争情报

系统化地跟踪竞争对手。不要沉迷其中——情报应当推动真正的决策。充分了解竞争对手，以便战胜他们。不要让他们左右你的议程。

## 关键词

竞争情报、竞争对手分析、竞争作战卡、赢单/输单分析、竞争定位、竞争动态跟踪、市场情报、竞争对手研究、SWOT、竞争格局图、功能差距分析、竞争战略、市场份额、竞争优势、护城河、转换成本

---

## 首先澄清

生成内容之前，请确认以下输入。如果其中任何一项未知或含糊，请提问——不要自行假设：

- [ ] **需要哪种输出**（竞争作战卡、定位图、赢单/输单分析或董事会摘要）——每种输出都有不同的模板和数据要求
- [ ] **要分析哪些竞争对手及其层级**（直接、相邻、未来）——这决定跟踪强度，以及哪些竞争对手会出现在产出物中
- [ ] **你的 ICP 以及你解决的问题**——这决定威胁分类矩阵，以及如何区分真正的竞争对手与干扰项
- [ ] **你真正的差异化优势及其证据点**——如果没有具体、有证据支撑的优势，“我们为何获胜”和“关键制胜问题”部分将毫无价值

停止规则：只询问对输出影响最大的 2-3 个问题。如果用户说“直接起草”，则继续，并在产出物顶部列出你的假设。

## 五层情报系统

### 第 1 层：识别竞争对手

#### 威胁分类矩阵

| | 相同 ICP | 不同 ICP |
|---|---|---|
| **相同问题** | 直接威胁（第 1 层级） | 相邻观察对象（第 2 层级） |
| **不同问题** | 替代风险（第 2 层级） | 仅监测（第 3 层级） |

#### 竞争对手层级

| 层级 | 定义 | 跟踪强度 | 示例 |
|------|-----------|-------------------|---------|
| 1：直接 | 相同 ICP、相同问题、价格相近 | 每月深度跟踪 | 你最主要的 3 个具名竞争对手 |
| 2：相邻 | 争夺相同预算，但采用不同的解决方案路径 | 每季度审查 | 自建方案、相邻产品 |
| 3：未来 | 相邻领域中资金充足的企业，或产品路线图存在重叠的现有巨头 | 每半年扫描 | 获得融资的初创企业、大型科技公司的功能 |

### 第 2 层：跟踪维度

| 维度 | 信息来源 | 频率 | 优先级 |
|-----------|---------|---------|----------|
| 产品动态 | 更新日志、G2、Capterra、Twitter、LinkedIn | 每月 | 高 |
| 定价变化 | 定价页面、销售情报、客户反馈 | 事件触发 | 高 |
| 融资 | Crunchbase、TechCrunch、LinkedIn | 事件触发 | 中 |
| 招聘信号 | LinkedIn 职位发布、Indeed、Glassdoor | 每月 | 中 |
| 合作伙伴关系 | 新闻稿、联合营销、集成 | 事件触发 | 中 |
| 客户赢单/流失 | 案例研究、评论网站、LinkedIn | 每月 | 高 |
| 竞争对手的客户流失 | G2 评论、论坛、你自己的入站线索 | 持续 | 高 |
| 信息传达变化 | 主页、广告、会议演讲 | 每季度 | 中 |

### 第 3 层：分析框架

#### 针对每个竞争对手的 SWOT 分析

| 要素 | 关键问题 |
|---------|-------------|
| 优势 | 他们在哪些方面持续获胜？客户称赞什么？ |
| 劣势 | 他们在哪些方面失利？评论中抱怨什么？ |
| 机会 | 他们可以采取什么行动，从而对你构成更大威胁？ |
| 威胁 | 哪些风险会威胁他们的生存？什么因素可能使他们变得无关紧要？ |

#### 功能差距分析模板

| 功能/能力 | 你方 | 竞争对手 A | 竞争对手 B | 状态 |
|-------------------|-----|-------------|-------------|--------|
| 核心功能 1 | [check] | [check] | [x] | 你方的优势 |
| 核心功能 2 | [x] | [check] | [check] | 差距——是否已列入路线图？ |
| 功能 3 | [check] | [x] | [x] | 护城河（你方独有） |
| 功能 4 | [x] | [x] | [check] | 仅竞争对手 B 具备 |
| 功能 5 | [check] | [check] | [check] | 基本必备能力 |

#### 竞争定位图

选择两个能够体现你方差异化的坐标轴：

| 常见坐标轴组合 | 适用场景 |
|------------------|------------|
| 价格与功能深度 | 当你方以性价比竞争时 |
| 企业级就绪度与中小企业就绪度 | 当你方服务于不同的细分市场时 |
| 易于实施与可配置性 | 当实施速度是你方优势时 |
| 垂直领域专用与通用型 | 当你方专注于特定领域时 |

### 第 4 层：输出格式

#### 竞争作战卡模板（销售使用）

```
BATTLECARD: [Competitor Name]
Last Updated: [Date]

OVERVIEW
  Company: [name, founded, HQ, funding, size]
  Product: [1-sentence description]
  ICP overlap: [High/Medium/Low]
  Threat level: [High/Medium/Low]

WHY WE WIN
  1. [Advantage 1 with proof point]
  2. [Advantage 2 with proof point]
  3. [Advantage 3 with proof point]

WHERE THEY WIN
  1. [Their advantage -- be honest]
  2. [Their advantage]

LANDMINES (what they say about us)
  - "[Their claim]" --> Counter: "[Your response with evidence]"
  - "[Their claim]" --> Counter: "[Your response with evidence]"

KILLER QUESTIONS (ask the prospect)
  1. "[Question that exposes competitor weakness]"
  2. "[Question that highlights your strength]"
  3. "[Question that validates your differentiation]"

RECENT MOVES
  - [Date]: [What they did, what it means]

CUSTOMER REFERENCES (ask for these)
  - [Customer name, use case, result]
```

#### 董事会竞争态势摘要（每月）

```
COMPETITIVE INTELLIGENCE SUMMARY -- [Month]

MARKET MOVEMENTS
  [Competitor A]: [What happened, significance]
  [Competitor B]: [What happened, significance]

WIN/LOSS SNAPSHOT
  Win rate vs [Comp A]: [X]% (trend: [up/down/stable])
  Win rate vs [Comp B]: [X]% (trend: [up/down/stable])
  Top win reason: [reason]
  Top loss reason: [reason]

RECOMMENDED RESPONSE
  [1 specific action with owner and timeline]

RISK WATCH
  [Specific risk with probability and impact]
```

### 第 5 层：竞争情报节奏

| 频率 | 活动 | 输出 |
|---------|----------|--------|
| 每月（定期） | 审查一级竞争对手，更新竞争作战卡 | 更新后的竞争作战卡 + 管理层摘要 |
| 事件触发 | 竞争对手融资、发布新功能或调整定价 | 48 小时内完成影响评估 |
| 每季度 | 全面审查竞争格局，更新定位图 | 可供董事会使用的竞争态势幻灯片 |
| 每年 | 添加或移除跟踪的竞争对手，更新威胁评估 | 更新后的竞争战略 |

## 赢单/丢单分析

### 何时开展

| 事件 | 是否访谈？ | 执行者 |
|-------|-----------|-------------|
| 丢失 ACV 超过 $50K 的交易 | 始终进行 | 非客户经理人员（客户成功、产品或外部人员） |
| 合作超过 6 个月后客户流失 | 始终进行 | 客户成功或产品团队 |
| 竞争性赢单 | 选择性进行 | 产品或市场营销团队 |
| 因“未做决定”而丢单 | 抽样进行 | 市场营销或产品团队 |

### 访谈流程

| 顺序 | 问题 | 你能了解到什么 |
|-------|----------|---------------|
| 1 | “请详细介绍一下你们的评估流程” | 他们如何采购、有哪些人参与 |
| 2 | “你们还考虑了哪些其他产品？” | 从他们的视角看竞争产品范围 |
| 3 | “你们做出决策时最重要的 3 项标准是什么？” | 决策驱动因素（可能与 AE 汇报的不同） |
| 4 | “[our product] 哪些方面未达到预期？” | 具体差距，而不是模糊的“他们更好” |
| 5 | “最终的决定性因素是什么？” | 促使他们做出决定的那一个因素 |
| 6 | “什么情况会改变你们的决定？” | 反事实情景 -- 最具可操作性的情报 |

### 汇总分析

| 指标 | 频率 | 输出 |
|--------|---------|--------|
| 赢单原因（按出现频率排序） | 每月 | 前 5 项及趋势 |
| 丢单原因（按出现频率排序） | 每月 | 前 5 项及趋势 |
| 竞争对手赢单率（按竞争对手、细分市场划分） | 每月 | 竞争记分板 |
| 赢单率随时间的变化趋势 | 每季度 | 面向董事会的趋势线 |

## 平衡之道：情报与过度关注

### 过度跟踪的信号

| 信号 | 风险 |
|--------|------|
| 路线图由“他们发布了 X”驱动 | 被动应对，而非战略驱动 |
| 竞争对手融资时团队士气下降 | 情绪化，而非分析性 |
| 为匹配功能清单而发布功能 | 为竞争对手构建产品，而非为客户 |
| 定价总是从“嗯，他们收取 X”开始 | 以成本为锚，而非以价值为锚 |

### 跟踪不足的信号

| 信号 | 风险 |
|--------|------|
| AE 在通话中措手不及 | 因准备不足而丢单 |
| 潜在客户比你的团队了解得更多 | 销售中的可信度差距 |
| 错过竞争对手的重大产品发布 | 原本可以主动应对，却只能被动响应 |
| 定位超过 12 个月未发生变化 | 市场已经变化，而你没有 |

### 正确的姿态

- 对竞争对手的了解应足以战胜他们
- 不要让他们决定你的议程
- 路线图由客户问题驱动，并参考竞争差距
- 定价以你的价值为锚，而不是以他们的价格为锚

## 危险信号

| 信号 | 影响 | 行动 |
|--------|------------|--------|
| 核心细分市场中的竞争对手赢单率 > 50% | 根本性的定位问题 | 开展战略审查，而不是制作更多竞争作战卡 |
| 5+ 个交易中出现相同异议 | 真实存在的功能差距，而非认知偏差 | 作为产品路线图的输入 |
| 竞争对手在你的领域招聘了 10+ 名工程师 | 即将进行重大产品投资 | 加快你的路线图进度或实现差异化 |
| 竞争对手融资 > $20M，并以你的 ICP 为目标 | 未来 12 个月的竞争强度将加剧 | 强化护城河，锁定客户 |
| 潜在客户评估你只是为了证明选择竞争对手的合理性 | 你只是那个“用于勾选的选项” | 改变市场认知或更换细分市场 |
| 未开展任何赢单/丢单访谈 | 无法从结果中学到任何东西 | 立即实施赢单/丢单分析计划 |

## 工具参考

### 1. market_landscape_mapper.py

跨可配置维度绘制竞争格局，按层级对竞争对手进行分类，绘制市场定位图，并识别市场空白机会。

```bash
python scripts/market_landscape_mapper.py --input competitors.json --json
python scripts/market_landscape_mapper.py --input competitors.json
```

| 标志 | 类型 | 说明 |
|------|------|-------------|
| `--input` | 必需 | 包含竞争对手数据（name、tier、dimensions、scores）的 JSON 文件路径 |
| `--json` | 可选 | 以 JSON 格式而非人类可读文本输出 |

### 2. competitor_tracker.py

跟踪竞争对手在 8 个维度（产品、定价、融资、招聘、合作伙伴关系、客户、传播信息、市场份额）上的动态变化。检测重大变化并生成警报。

```bash
python scripts/competitor_tracker.py --input tracking_data.json --json
python scripts/competitor_tracker.py --input tracking_data.json
```

| 标志 | 类型 | 说明 |
|------|------|-------------|
| `--input` | 必需 | 包含一段时间内竞争对手跟踪条目的 JSON 文件路径 |
| `--json` | 可选 | 以 JSON 格式而非人类可读文本输出 |

### 3. swot_analyzer.py

执行结构化 SWOT 分析，包括加权评分、交叉影响评估（SO/WO/ST/WT 战略）和战略优先级建议。

```bash
python scripts/swot_analyzer.py --input swot_data.json --json
python scripts/swot_analyzer.py --input swot_data.json
```

| 标志 | 类型 | 说明 |
|------|------|-------------|
| `--input` | 必需 | 包含 strengths、weaknesses、opportunities、threats（每项均包含 description、impact 1-10、confidence 1-10）的 JSON 文件路径 |
| `--json` | 可选 | 以 JSON 格式而非人类可读文本输出 |

## 故障排查

| 问题 | 可能原因 | 解决方案 |
|---------|-------------|------------|
| 竞争作战卡在创建后数周内便已过时 | 未针对竞争对手动态设置触发式更新流程 | 实施由监控警报触发、事件驱动的竞争作战卡更新机制；为每个 Tier 1 竞争对手指定一名竞争作战卡负责人 |
| 未开展赢单/输单访谈 | AEs 不愿参与或没有明确的负责人 | 指定非 AE 人员（CS、产品团队或外部人员）开展访谈；将赢单/输单分析设为必需流程，而非可选项 |
| 竞争情报停留在 Slack 中，未传递给销售团队 | 缺少单一事实来源或固定的分发节奏 | 将情报集中到与 CRM 关联的竞争作战卡中；在 CRO 负责下设定每月分发节奏 |
| 功能差距分析未影响路线图 | 产品团队未使用竞争数据 | 将 CPO 纳入季度市场格局评审；将差距分析与路线图规划周期挂钩 |
| 竞争对手层级分类从未更新 | 未对竞争格局进行年度评审 | 安排年度层级重新评估；根据 ICP 重合度和融资变化增减竞争对手 |
| 团队对竞争对手的每个动态都反应过度 | 缺少评估威胁重要性的框架 | 使用威胁分类矩阵过滤有效信号与噪声；仅上报 Tier 1 竞争对手的变化 |
| 情报收集缺乏一致性 | 未针对各个跟踪维度指定负责人或节奏 | 根据情报分工表指定各维度负责人；尽可能实现监控自动化 |

## 成功标准

- 在 Tier 1 竞争对手出现重大动态后的 48 小时内更新竞争作战卡
- 针对排名前三的竞争对手，赢单率逐季度保持稳定或有所提升
- 对 ACV 超过 $50K 的输单交易开展赢单/输单访谈，覆盖率达到 90% 以上
- 销售团队无需参考资料，即可阐明相较于每个 Tier 1 竞争对手的三大差异化优势
- 竞争情报每季度至少影响 2 项路线图决策
- 从竞争对手事件发生到内部获知的时间不超过 72 小时
- 每年至少根据市场格局分析更新一次定位

## 范围与限制

**范围内：** 竞争对手识别与层级分类；跨产品、定价、融资、招聘、合作伙伴关系、客户、信息传递和市场份额 8 个维度的跟踪；针对每个竞争对手的 SWOT 分析；功能差距分析；竞争作战卡的创建与分发；赢单/输单分析；竞争定位图；董事会层面的竞争态势摘要；以及通过 Python 工具绘制市场格局图。

**范围外：** 实时竞争对手监控（工具分析特定时间点的数据导出）、来自竞争对手内部数据的定价情报、客户层面的交易指导（工具会标记模式，但不会规定销售策略）、市场调研问卷或一手研究，以及超出公开数据范围的竞争对手财务建模。

**限制：** SWOT 和市场格局分析取决于输入数据的质量与时效性。超过 6 个月的竞争情报应仅作为方向性参考。赢单/输单分析每季度至少需要开展 10 次访谈，才能具备统计显著性。市场定位图具有主观性，应使用客户认知数据进行验证。

## 集成点

- **cro-advisor** -- 竞争作战卡直接用于销售赋能；赢单/输单数据为销售管道策略和配额设定提供依据
- **cpo-advisor** -- 功能差距分析会影响产品路线图的优先级排序和产品组合投资决策
- **cmo-advisor** -- 竞争定位为信息传达、内容策略和营销活动差异化提供依据
- **ceo-advisor** -- 董事会层面的竞争态势摘要为战略方向和并购评估提供依据
- **board-deck-builder** -- 每月竞争格局幻灯片会纳入季度董事会演示文稿
- **sales-success/** -- 竞争作战卡和制胜问题帮助销售团队开展竞争性销售
