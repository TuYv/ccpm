# 品牌指南

按照 Sentry 的品牌指南撰写面向用户的文案。

## 语气选择

根据具体情境选择合适的语气：

| 使用直白表达 | 使用 Sentry 风格 |
|------------------|------------------|
| 产品 UI（按钮、标签、表单） | 404 页面 |
| 文档 | 空状态 |
| 错误消息 | 新手引导流程 |
| 设置页面 | 加载状态 |
| 事务性电子邮件 | “新功能”公告 |
| 帮助文本 | 营销文案 |

除非特定情境明确需要个性化表达，否则**默认使用直白表达**。

## 直白表达（默认）

直白表达清晰、直接且实用。大多数 UI 元素都应使用这种表达方式。

### 规则

1. **简洁** - 用最少的文字表达清楚
2. **直接** - 告诉用户要做什么，而不是能做什么
3. **使用主动语态** - 使用“保存更改”，而不是“更改将被保存”
4. **避免术语** - 使用用户能够理解的简单词语
5. **具体明确** - 使用“发现 3 个错误”，而不是“发现一些错误”

### 示例

| 不要写 | 应写 |
|------------|-------|
| “点击此处保存更改” | “保存” |
| “你可以按日期筛选结果” | “按日期筛选” |
| “发生了错误” | “出了点问题” |
| “请输入有效的电子邮件地址” | “输入有效的电子邮件” |
| “确定要删除吗？” | “删除此项目？” |

## Sentry 风格

Sentry 风格会在适当的时机增添个性。它富有同理心、自知之明，偶尔还会带点挖苦意味。

### 原则

1. **有同理心的调侃** - 将不满指向处境，绝不针对用户
2. **自知之明** - 承认软件世界中的荒诞之处
3. **有趣但实用** - 个性化表达应该强化含义，而不是模糊含义
4. **恰到好处的时机** - 仅在用户有时间欣赏时使用

### 示例

**404 页面：**
> “此页面不存在。也许它从未存在过。也许它只是一场梦。无论如何，让我们带你回到正轨。”

**空状态：**
> “暂时没有错误。趁这片刻安宁还在，好好享受吧。”

**新手引导：**
> “让我们获取你的第一个错误。别担心，它没有听起来那么可怕。”

**加载状态：**
> “正在处理数据……”
> “正在获取你的数据……”

### 不应使用 Sentry 风格的情境

- 错误消息（用户正感到沮丧）
- 设置页面（用户需要专注）
- 文档（用户需要获取信息）
- 账单/付款流程（用户需要信任感）

## 通用规则

### 拼写和语法

- 使用**美式英语**拼写（使用 color，而不是 colour）
- 标题和页面标题使用**标题式大小写**
- 正文、按钮和标签使用**句首字母大写**

### 标点符号

- UI 文本中**不使用感叹号**（庆祝性场景除外）
- 简短的 UI 标签或按钮文本中**不使用句号**
- 完整句子和帮助文本中**使用句号**
- 除缩写词（API、SDK、URL）外，**不使用全大写**

### 用词选择

| 避免 | 首选 |
|-------|--------|
| 请 | （省略） |
| 抱歉 | （具体说明问题） |
| 发生错误 | 出了点问题 |
| 无效 | （说明具体问题） |
| 成功！ | （说明发生了什么） |
| 糟糕 | （具体说明问题） |

## 破折号用法

| 类型 | 用途 | 示例 |
|------|-----|---------|
| 连字符 (-) | 复合词、范围 | "实时（real-time）"、"1-10" |
| 短破折号 (--) | 范围、关系 | "2023--2024"、"父级--子级" |
| 长破折号 (---) | 插入、强调 | "错误---即使是很小的错误---也很重要" |

在大多数 UI 场景中，使用连字符。短破折号仅用于日期范围，长破折号仅用于较长的文本。

## UI 元素指南

### 按钮

- 使用动作动词："保存"、"删除"、"创建"
- 表述要具体：使用"创建项目"，而不只是"创建"
- 尽可能不超过 2-3 个词
- 不使用句号或感叹号

### 错误消息

1. 说明发生了什么
2. 说明原因（如果有帮助）
3. 说明下一步该怎么做

**推荐：** "无法保存更改。请检查网络连接，然后重试。"
**不推荐：** "错误：保存失败。"

### 空状态

1. 说明这里通常会显示什么
2. 提供一个明确的操作来填充该状态
3. 此处适合使用 Sentry Voice

**推荐：** "还没有项目。创建你的第一个项目，开始跟踪错误。"

### 确认对话框

- 在标题中明确说明操作
- 如果操作具有破坏性，请说明后果
- 使用具体的按钮标签（使用"删除项目"，而不是"确定"）

### 工具提示和帮助文本

- 控制在 2 句话以内
- 解释"为什么"，而不只是"是什么"
- 对于复杂主题，链接到文档

## 反面模式

避免以下常见错误：

- **机器人式表达：** "项目已成功删除" -> "已删除"
- **被动语态：** "更改已被保存" -> "更改已保存"
- **不必要的词语：** "为了能够" -> "为了"
- **模糊措辞：** "这可能会导致……" -> "这将导致……"
- **双重否定：** "并非不像……" -> "类似于……"
- **UI 中的营销式表达：** "为你的工作流注入超强动力" -> "加快你的工作流"
