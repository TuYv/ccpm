# 设计

将设计思维应用于形式、功能和适配性问题——发现人们真正的需求，积极利用约束，通过迭代塑造方案，并删减至本质。判断需要开展哪种设计工作，并应用正确的工具。

## 哪种工具适用

| 你需要…… | 工具 |
|---|---|
| 透过人们所说的想要，发现其真正需求 | user-needs |
| 区分硬性限制与柔性偏好，并理解它们所界定的解决方案空间 | design-constraints |
| 在制作与学习之间构建反馈循环 | iteration |
| 移除不必要的部分，找到本质形式 | simplicity |

## 路由决策

**问题界定检查：** 在进行路由之前，确认设计情境和核心问题。用一句话说明你识别出的内容——正在设计的对象及其需要解决的问题——然后使用 `AskUserQuestion`：
- **问题：**“我是这样理解的：[用一句话界定设计情境和核心问题]。对吗？”
- **标题：**“问题界定”
- **选项：**
  - **是——继续**——问题界定正确
  - **调整**——有一个要素不准确；用户会先纠正它，然后你再继续
  - **重新界定**——实际情境与当前理解不同；采纳修正后再继续

- **不知道用户真正需要什么，或者表述出的需求像是某种替代性诉求** → user-needs
- **已有一系列约束条件，需要理解它们留下了怎样的设计空间** → design-constraints
- **已有方向，但需要通过多个周期进行测试和改进** → iteration
- **已有方案，但感觉臃肿、杂乱或过度设计** → simplicity
- **不明确** → 先使用 user-needs；大多数设计失败都始于解决了错误的问题

## 确认方向

判断适用的工具后，使用 `AskUserQuestion` 工具确认方向。动态构建问题，并在其中包含你的判断：

- **问题：**“我的判断是：**[判断出的工具]**——[用一句话说明它为何适用]。你想如何继续？”
- **标题：**“方向”
- **选项：**
  - **是，运行该工具**——使用已经提供的上下文，立即执行判断出的技能
  - **显示所有选项**——列出该类别中的所有技能，并为每个技能提供一句话说明
  - **快速版本**——如果当前情境存在轻量级替代方案，则运行该方案
  - **重新判断**——重新审视情境描述，得出不同的判断

根据用户的选择继续。

## 用户需求

*透过人们所说的想要，发现其真正需求。*

人们表述的是解决方案，而不是需求。“我想要一匹更快的马”是解决方案；其底层需求是更快地出行。此技能使用待办任务框架和潜在需求映射，将真实需求与表述出的想要区分开来。它会揭示功能性任务（他们试图完成什么）、情感性任务（他们希望有何种感受）和社会性任务（他们希望别人如何看待自己）。输出结果是一套设计真正可以据此解决问题的需求层级。

**输出：** 表层诉求与真实需求、待完成任务映射（功能性/情感性/社会性）、用户尚未明确表达的潜在需求，以及以需求而非解决方案表述的设计目标。

## 设计约束

*有效利用约束——通过梳理硬性限制和软性偏好，理解真正的解决方案空间。*

约束并非设计的敌人，而是对问题的界定。每一项设计都存在于一系列限制之中——技术、物理、经济、监管和时间限制。此技能区分硬性约束（确实固定不变）与软性偏好（可协商），梳理它们之间的相互作用，并识别最严格的约束如何聚焦设计空间。最严格的真实约束往往会直接指向解决方案。

**输出：** 约束图谱（按领域划分硬性约束与软性约束）、约束之间的相互作用、它们共同界定的解决方案空间，以及该空间内富有成效的设计区域。

## 迭代

*构建制作与学习之间的反馈循环。*

优秀的设计无法从一开始就被完整规划出来——它是在一轮轮制作和测试中逐步发现的。此技能构建迭代循环：要制作什么原型、采用何种保真度、要回答什么问题，以及如何解读每次测试所传递的信号。它将收敛性测试（这是否可行？）与发散性测试（应选择哪个方向？）区分开来，并明确何时已积累足够的认知，可以开始收窄范围。Dieter Rams 的十项原则和 Don Norman 的日常事物设计理念，都源自这种制作与观察的严谨循环。

**输出：** 当前设计假设、原型规格（保真度、形式、要制作的内容）、测试设计（问题、方法、测试对象）、用于决定收敛或转向的标准，以及下一轮循环。

## 简洁性

*找到恰好满足需求的形式——不多不少。*

Rams 的原则：优秀的设计应尽可能少地设计。目标并非为了极简而极简，而是适切性——形式完整服务于功能，不留冗余。此技能采用系统化减法：识别每个元素、检验每个元素承担的任务，并移除非承重元素。判断标准不是“这能否被移除？”，而是“移除它是否会破坏功能？”Edward Tufte 的数据墨水比将这一逻辑应用于信息设计；同样的原则也适用于每一件设计产物。

**输出：** 元素清单、每个元素承担的任务、在不损失功能的情况下可以移除的内容、真正承担关键作用的内容，以及简化后的形式与相应理由。
