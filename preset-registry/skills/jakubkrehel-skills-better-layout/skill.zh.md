# 布局

在读到任何文字之前，位置、间距和对齐就已经传达了层级。此技能用于构建这种结构并进行压力测试：调整尺寸、翻译内容、为 RTL 镜像布局。

在项目的样式系统中编写每一项修复。以下数值适用于没有既定密度系统的界面，作为起点；适用时，请按原样使用，不要替换成看起来熟悉的数值。对于仍能通过压力测试的刻意平台框架、紧凑型专业工具和项目令牌，应予以保留。

点击区域和焦点行为属于 `better-accessibility`。圆角、阴影和动画属于 `better-ui`。行长和文本间距属于 `better-typography`。

## 使用间距分组，而不是线条

优先用空间分组，其次使用背景形状，分隔线最后使用，且仅在单靠空间无法承载结构时使用。组与组之间的间距必须至少是组内间距的 2 倍（组内 `8px`，组间 `16px`+），否则分组会显得像噪声。对齐边缘和重要性排序参见 [grouping-and-alignment.md](grouping-and-alignment.md)。

## 保持控件与内容的区别

为每个交互元素提供背景形状、边框或一致的放置区域。若一个控件的样式与其旁边的静态文本相同，它就不会被识别为控件。

## 对齐到共享边缘

选择对齐边缘并始终保持一致；每一条游离边缘都会显得像噪声。每增加一级从属关系，就使用一个项目间距步长，其中 `16px` 是一个有用的默认值。

对依赖方向的布局使用逻辑属性：`padding-inline-start`、`margin-inline-end`。仅将物理的左和右保留给真正的物理几何关系。

## 按重要性排序

最重要的内容应靠近顶部和起始边缘。阅读顺序从上到下、从起始到末尾流动。应以起始和末尾思考，而不是左和右。

## 提示隐藏内容

渐进披露需要可见的提示。使用项目既有的提示方式，或让下一项在滚动边缘外露出 `16–32px`，或显示一个披露控件。没有任何提示而被隐藏的内容，等同于不存在。

## 目标之间留出呼吸空间

在没有既定密度系统时，相邻带边框或填充的控件之间从 `12px` 开始，围绕无边框的纯文本和纯图标控件使用 `24px`。紧凑布局可以使用更小的间距，前提是 `better-accessibility` 的点击区域不重叠，且控件仍然清晰可辨。布局边距和断点方案参见 [spacing-and-adaptivity.md](spacing-and-adaptivity.md)。

## 按钮与边缘保持内缩

在内容布局中，让全宽按钮保持在布局边距之内，并使用可见的圆角；在移动端，行内方向的起始内边距接近 `16px`。当边到边操作遵循既定平台框架、考虑安全区域，并且仍能与系统 UI 区分开时，它们是可行的。

## 内容可出血，控件应悬浮

背景和媒体延伸至视口边缘。控件和文本保持在布局边距及安全区域（`env(safe-area-inset-*)`）之内。粘性框架应悬浮在内容层之上，而不是遮挡内容。

## 保持结构，直到它不再适用

断点应由内容决定，而不是由设备预设决定。只要扩展布局确实仍能容纳，就保持它，并尽可能晚地折叠。优先使用容器查询进行组件级适配，并首先测试最小和最大的尺寸。

## 为增长和裁剪做好规划

翻译后的字符串会变长，而短字符串的相对增长更明显，因此单词按钮标签是屏幕上风险最高的元素。不要为文本容器设置固定宽度或高度，并允许行换行。使用伪本地化和一个有代表性的区域设置进行测试，而不是预留一个百分比。

绝不要将关键操作放在调整尺寸或滚动时会被裁剪的位置。应将其保留在正常文档流中，或放在适合产品的稳定固定界面区域中。

## 完成之前

| 错误 | 修复方式 |
| --- | --- |
| 本地化布局中使用 `margin-left` / `padding-right` | 使用 `margin-inline-start` / `padding-inline-end` |
| 内容布局中的按钮紧贴视口边缘 | 在项目边距内设置内嵌距离；保留有意设计的平台固定界面区域 |
| 因为 768/1024 是默认值而在这些位置设置断点 | 在内容实际无法继续容纳的位置断点 |
| 固定宽度的文本容器按一种语言尺寸设定 | 使用 `max-width` 和换行；测试伪本地化 |
| 主要操作位于面板中容易被裁剪的底部 | 使用粘性定位，或带有安全区域内边距的稳定固定界面区域 |

## 报告

**严重程度。** `HIGH` 会在受支持的视口中阻塞内容或操作。`MEDIUM` 会损害层级、阅读顺序或适应性。`LOW` 是孤立的对齐或间距优化问题。

**验证。** 没有浏览器时：使用逻辑属性替代物理属性，针对受支持视口列表检查容器查询和媒体查询，以及检查 DOM 顺序是否符合预期阅读顺序。有浏览器时：检查每个受支持的宽度、200% 缩放和 RTL 镜像。将每一项无法运行的检查报告为 `Not verified`。

**格式。** 按其违反的原则对发现项分组，按严重程度排序，每个根本原因一行，列出其出现的所有位置：

| 严重程度 | 位置 | 修改前 | 修改后 | 原因 |
| --- | --- | --- | --- | --- |

`Location` 为 `path/to/file:line`。`Why` 应说明原则及其对用户的影响。

当仍存在任何 `HIGH` 时，以 `Block` 结束；否则以 `Approve` 结束，并将其余待完成工作保留在表格中。绝不要 `Approve` 未检查的覆盖范围。没有内容可报告时，说明“没有可操作的布局发现项”，并报告验证情况。
