# 机会评估器

**目标：** 在承诺实施之前评估产品机会。从可观察的需求和可触达的获客路径出发，尽早淘汰较弱的候选方案，并推荐一个低成本的验证步骤，同时避免捏造看似精确的市场数据。

**执行契约：** 按顺序排列的复选框即完成定义。在内部将每一项跟踪为 `PENDING`、有具体证据支持的 `PROVEN`、有证据表明其条件不存在的 `CLEARED`，或存在证据缺口的 `UNPROVEN`；阅读、委派或工具故障不能作为证明。完成每个部分后重新核对各项。返回结果前，解决所有 `PENDING` 项，并且只统计 `PROVEN` 和 `CLEARED`；对每个证据缺口应用此技能的判定和批准规则。
保留用户意图、范围和现有授权。继续执行已获授权的工作；只有在存在会产生重大影响且尚未解决的选择，或需要外部批准时才提问。根据实质性风险调整分析深度，不得暗中跳过检查。保留依赖关系和安全顺序；除此之外，为每项义务选择适当的验证方法。

## 工具路由

| 需求 | 首选工具 | 使用时机 | 后备方案 |
|---|---|---|---|
| 产品和约束 | 用户上下文，以及现有的产品、分析、客户和战略文档 | 确定受众、资产、渠道、经济性和非目标 | 说明假设，并且只询问会对意图产生重大影响的缺失信息 |
| 当前需求和获客 | Web 研究、趋势或市场平台数据、社区、评论、广告、目录和一手客户证据 | 针对所有会影响淘汰或推荐决策的外部市场主张 | 将该信号标记为不可用；绝不根据搜索结果数量推断数值 |
| 竞争和定价 | 竞争对手产品页面、定价、发布历史、分发渠道、评论，以及相关情况下的公开申报文件 | 确定替代方案、付费意愿信号和可信的差异化优势 | 使用定性证据，并明确说明置信度 |
| 可行性和验证成本 | 现有能力、公共 API、法规、平台规则和当前官方文档 | 比较成本最低且可信的实验以及主要阻碍因素 | 标明估算值，并指出仍需获取的证据 |

评估应保持只读。不要创建项目文件、路线图、Epic、Story、实施计划、营销活动、商品条目、广告或客户外联内容。

## 证据类别

| 类别 | 含义 |
|---|---|
| `MEASURED` | 具有已知方法和日期的直接分析数据、交易、实验或经检测记录的观察结果 |
| `REPORTED` | 一手来源报告了某个数值或行为，但无法独立获取其底层测量数据 |
| `ESTIMATED` | 基于明确输入和假设而建立的模型 |
| `INFERRED` | 根据可观察的代理指标得出的定性结论 |
| `UNKNOWN` | 证据不可用、已过时、不可比较，或过于薄弱，无法支持决策 |

不要将 `REPORTED`、`ESTIMATED` 或 `INFERRED` 证据转化为实测的市场规模、搜索量、转化率、收入或付费意愿主张。为每个外部来源注明日期，并在事件发生日期与发布日期不同时对二者加以区分。
将创作者主张、预期体验、品味和信念视为所有者偏好及战略契合度的输入，绝不能将其视为需求、获客或付费意愿的证据。

## 检查清单

### 1. 界定决策

- [ ] 明确现有产品或能力、目标用户、创建者论点、预期体验、决策时间范围、可用资产、地理或监管范围、约束条件，以及明确的非目标。
- [ ] 接受用户提供的候选方案，或根据产品背景和当前信号生成一组范围受限、具有实质差异的机会；不要创建同一想法的表面变体。
- [ ] 定义哪些条件足以支持进一步验证：可识别的用户和问题、可观察的需求、可触达的渠道、可信的价值交换、差异化切入点，以及成本可控的实验。
- [ ] 将新方向的探索与已承诺工作的优先级排序或实施规划区分开来。
- [ ] 记录可能逆转推荐结论的假设，将可研究的事实与负责人偏好区分开来；只有当不同理解会实质性改变候选方案或实验时，才提出一个简洁的问题。

### 2. 为每个候选方案收集一组证据

- [ ] 确定谁正在经历该问题、他们目前如何解决、什么会触发主动搜索或购买，以及有哪些证据表明痛点是反复出现的或代价高昂的。
- [ ] 找到可触达的获客渠道及其机制：查询、市场类别、集成生态、社区、合作伙伴、外展受众，或其他可观察的路径。
- [ ] 调查直接竞争对手、替代方案、无行动行为、定价、定位、分发方式、评论中的抱怨，以及持续投入或放弃的证据。
- [ ] 研究经济信号，但不要臆造单位经济学：价格锚点、预算负责人、购买频率、转换成本、交付成本、平台费用和支持负担。
- [ ] 确定会影响验证实验成本的实施、数据、依赖、监管、信任、分发和运营障碍。
- [ ] 记录来源/日期、证据类别、范围、置信度、矛盾之处和决策影响。将重复使用的统计数据和联合发布的报告追溯至其原始来源；相关联的副本算作一个信号，而不是相互独立的佐证。
- [ ] 一旦证据足以淘汰某个候选方案，或更多来源无法改变其状态，就停止对该候选方案的研究。

### 3. 应用证据优先的淘汰机制

- [ ] 当证据与必要的可行性条件相矛盾，或表明在既定约束下不存在可行的验证路径时，淘汰候选方案。仅仅缺少公开数据时，根据下面的规则将候选方案暂缓为 `UNKNOWN`。
- [ ] 将竞争对手的存在视为需求和约束条件的线索；验证使用或购买信号，而不是假设有一个列表就证明存在需求。必须针对替代方案和无行动行为提出具体的切入点。
- [ ] 不要使用关于搜索量、竞争对手数量、ARPU、市场规模或 MVP 周期的通用阈值。
- [ ] 对于公开数据薄弱的候选方案，将其保留为 `UNKNOWN`，而不是在廉价的主要实验可以解决不确定性的情况下将其标记为无效。
- [ ] 为每个被淘汰的候选方案记录决定性证据和证伪条件，使拒绝结论可以复现。
- [ ] 只有在外部可行性得到确认后，才询问负责人是否愿意且有能力去服务该受众、运营该渠道和运营模式，并投入验证工作；不要推断其个人兴趣。

### 4. 比较幸存候选并选择下一项实验

- [ ] 比较幸存候选的证据强度、问题严重程度、渠道可触达性、差异化、经济性、验证成本、与创作者理念及预期体验的战略契合度，以及可逆性；不要将它们压缩成虚假的综合评分。
- [ ] 保留有意义的分歧和敏感性：展示哪项假设发生变化会使另一候选变得更优。
- [ ] 仅当某个候选针对既定目标的证据明显更强时，才选择一个主要推荐；否则返回 `INCONCLUSIVE`。
- [ ] 定义成本最低且可信的验证实验，通过观察到的行为，而不仅是口头表达的购买意向，来测试最薄弱的决定性假设。
- [ ] 指定实验受众、渠道、报价或原型、成功和失败证据、预算或时间边界、安全约束以及停止规则，但不要假装已经知道结果。
- [ ] 优先采用可逆测试，例如在适当披露的前提下进行人工交付、原型使用、定价或预购意向测试、渠道响应或集成需求测试，然后再决定是否投入实施。

### 5. 验证并报告

- [ ] 使用收集到的一手来源证据核对具有重要影响的外部声明；仅刷新过时、相互矛盾或对决策至关重要但缺乏支持的声明，并明确标注较弱的证据。
- [ ] 在最终结果中区分事实、估算、推断、负责人偏好和未解决的未知事项。
- [ ] 仅当候选具备可信的需求信号、可触达的渠道、差异化路径、合理的价值交换以及可执行的验证实验时，使用 `RECOMMEND <candidate>`。
- [ ] 当证据无法区分领先候选，或在做出选择前需要进行低成本实验时，使用 `INCONCLUSIVE`。
- [ ] 当决策缺少产品背景、候选范围、合法的研究访问权限或安全的验证边界时，使用 `BLOCKED`。
- [ ] 根据证据核对推荐、淘汰和暂缓的候选；报告拟议的下一项实验，但不要创建文件或执行实验。

## 自检

- [ ] **返回前进行核对。** 检查逐项证据、需求覆盖情况、矛盾、范围、结论以及适用的清理工作。修正报告或已授权的工件。复用有效证据；不要自动重新扫描仓库或重新运行已成功的命令。仅针对相关变更、失败或未解决的证据重复检查。披露剩余缺口。

## 输出约定

使用用户的语言，按照以下顺序报告；保留全部五个字段，并且每项事实只陈述一次。结果较小时，每个字段可以使用一行；省略空表格，不要复制链接工件：

1. **结果：** Skill 专属结论及有证据支持的结果。
2. **范围：** 已审查/变更的范围、排除项、基线和重要假设。
3. **证据：** 以下 Skill 专属字段；区分事实、推断和未经验证的声明。链接工件；必要时使用表格。
4. **验证：** 检查/结果、不可用的证据，以及适用的清理工作/外部状态。
5. **完成情况：** `Checklist: X/Y complete`；`Incomplete: None` 或每个 `UNPROVEN` 项的原因、对结果的影响以及确切的下一步行动；剩余风险和所需决策。

**技能专属证据：** 将产品、受众、候选方案、约束条件和创作者论点与市场证据分开。比较需求、渠道、替代方案/切入点、经济性、验证成本、来源/日期/类别和置信度。对于已淘汰或延期的候选方案，给出决定性证据或明确未知项，以及证伪/解决条件。说明建议或得出“无法确定”结论的理由，并提出实验契约、预算、停止规则和能够改变决策的证据；不要执行外联或实验。
