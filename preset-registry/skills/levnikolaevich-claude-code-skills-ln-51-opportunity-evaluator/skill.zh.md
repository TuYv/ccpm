# 机会评估器

**目标：** 在承诺实施之前评估产品机会。从可观察到的需求和可触达的获客路径出发，尽早淘汰薄弱候选项，并推荐一个低成本的验证步骤，避免制造虚假的市场精确度。

**执行约定：** 将下方按顺序排列的复选框工作流视为此技能的完成定义。按顺序完成每一项，并且只有在相应操作及所需证据均已完成时，才将其标记为完成。`N/A`、已跳过、不可用或已委派的项目仍视为未完成。
在返回结果之前，将此技能的裁决、决策和批准规则应用于每个未完成项，并在开头添加 **检查清单：已完成 X/Y 项**<br>**未完成：无 | 章节/项目 — 原因；对结果的影响；确切的下一步操作**；列出每个未完成项。

## 工具选择

| 需求 | 首选工具 | 使用时机 | 后备方案 |
|---|---|---|---|
| 产品和约束 | 用户上下文，以及现有的产品、分析、客户和战略文档 | 确定受众、资产、渠道、经济性和非目标 | 陈述假设，并且只询问会产生实质影响的缺失意图 |
| 当前需求和获客 | Web 调研、趋势或市场平台数据、社区、评论、广告、目录和一手客户证据 | 对影响淘汰或推荐的每个外部市场主张进行评估时 | 将该信号标记为不可用；绝不根据搜索结果数量推断数值 |
| 竞争和定价 | 竞争对手的产品页面、定价、发布历史、分销渠道、评论，以及相关情况下的公开申报文件 | 确定替代方案、付费意愿信号和可信的差异化 | 使用定性证据，并明确标注置信度 |
| 可行性和验证成本 | 现有能力、公共 API、法规、平台规则和当前官方文档 | 比较成本最低且可信的实验和主要阻碍因素 | 标注估算，并说明仍需哪些证据 |

评估过程应保持只读。不要创建项目文件、路线图、史诗、用户故事、实施计划、营销活动、商品条目、广告或客户外联内容。

## 证据类别

| 类别 | 含义 |
|---|---|
| `MEASURED` | 通过方法和日期已知的直接分析、交易、实验或仪器化观察获得 |
| `REPORTED` | 一手来源报告了某个数值或行为，但无法独立获取其底层测量数据 |
| `ESTIMATED` | 基于明确输入和假设而提出的模型 |
| `INFERRED` | 根据可观察的代理指标得出的定性结论 |
| `UNKNOWN` | 证据不可用、已过时、不可比较或过于薄弱，无法支持决策 |

不要将 `REPORTED`、`ESTIMATED` 或 `INFERRED` 证据转化为实测的市场规模、搜索量、转化率、收入或付费意愿主张。为每个外部来源标注日期，并在事件日期与发布日期不同时加以区分。
将创作者的论点、预期体验、品味和信念视为所有者偏好及战略契合度输入，绝不能视为需求、获客或付费意愿证据。

## 检查清单

### 1. 明确决策框架

- [ ] 明确现有产品或能力、目标用户、创作者的核心判断、预期体验、决策周期、可用资产、地域或监管范围、约束条件，以及明确的非目标。
- [ ] 接受用户提供的候选方向，或根据产品背景和当前信号生成一组数量有限且存在实质差异的机会；不要为同一个想法创建仅有表面差异的变体。
- [ ] 定义值得进一步验证的条件：可识别的用户和问题、可观察的需求、可触达的渠道、可信的价值交换、差异化切入点，以及成本可承受的实验。
- [ ] 将新方向的探索与已承诺工作的优先级排序或实施规划区分开来。
- [ ] 记录可能推翻建议的假设，将可研究的事实与负责人偏好区分开；只有当不同解读会实质性改变候选方向或实验时，才提出一个简洁的问题。

### 2. 为每个候选方向收集一套证据

- [ ] 确定谁会遇到该问题、他们目前如何解决、什么会触发主动搜索或购买，以及哪些证据表明该痛点会反复出现或代价高昂。
- [ ] 找到可触达的获客渠道及其机制：查询、市场分类、集成生态系统、社区、合作伙伴、外联目标受众，或其他可观察的路径。
- [ ] 调查直接竞争对手、替代方案、维持现状的行为、定价、定位、分发方式、评论中的投诉，以及持续投入或放弃的证据。
- [ ] 在不虚构单位经济效益的前提下考察经济信号：价格锚点、预算负责人、购买频率、切换成本、交付成本、平台费用和支持负担。
- [ ] 识别会影响验证实验成本的实施、数据、依赖项、监管、信任、分发和运营阻碍。
- [ ] 记录来源、日期、证据类别、范围、置信度、矛盾之处，以及每个信号能够改变的候选方向决策。
- [ ] 一旦证据足以淘汰某个候选方向，或新增来源无法改变其状态，就停止对该候选方向的研究。

### 3. 采用证据优先的淘汰方法

- [ ] 如果无法确定具体的用户问题、可观察的需求信号、可触达的渠道、可信的价值交换或可行的验证路径，则淘汰该候选方向。
- [ ] 将竞争视为需求和约束的证据，而不是自动否决的理由；针对替代方案和维持现状的选择，必须具备具体的差异化切入点。
- [ ] 不要对搜索量、竞争对手数量、ARPU、市场规模或 MVP 周期采用统一阈值。
- [ ] 对于公开数据薄弱的候选方向，如果可以通过低成本的一手实验消除不确定性，则将其保留为 `UNKNOWN`，而不是将其标记为无效。
- [ ] 为每个被淘汰的候选方向记录决定性证据和证伪条件，确保淘汰结论可以复现。
- [ ] 只有在确认外部可行性之后，才评估负责人是否愿意且有能力面向该受众、使用该渠道、采用该运营模式并投入验证工作；不要推断其个人兴趣。

### 4. 比较入围候选方案并选择下一项实验

- [ ] 比较入围候选方案的证据强度、问题严重程度、渠道可触达性、差异化、经济性、验证成本、与创作者理念及预期体验的战略契合度，以及可逆性，但不要将这些因素合并成虚假的综合评分。
- [ ] 保留有意义的分歧和敏感性：说明哪项假设会使另一个候选方案变得更可取。
- [ ] 仅当某个候选方案针对既定目标的证据明显更强时，才选择一个主要推荐方案；否则返回 `INCONCLUSIVE`。
- [ ] 定义成本最低且可信的验证实验，通过观察到的行为，而非仅凭口头表达的购买意愿，检验最薄弱的决定性假设。
- [ ] 明确实验受众、渠道、产品方案或原型、成功与失败的证据、预算或时间边界、安全约束和停止规则，但不要假装知道实验结果。
- [ ] 在承诺实施之前，优先采用可逆的测试，例如人工服务交付、原型使用、在适当披露的前提下测试定价或预购意向、渠道响应或集成需求。

### 5. 验证并报告

- [ ] 根据当前的一手来源重新核查每一项会产生重大影响的外部主张，否则标注其较弱的证据类别和局限性。
- [ ] 在最终结果中区分事实、估算、推断、所有者偏好和尚未解决的未知因素。
- [ ] 仅当候选方案具备可信的需求信号、可触达的渠道、差异化路径、合理的价值交换和可执行的验证实验时，才使用 `RECOMMEND <candidate>`。
- [ ] 当证据无法区分领先的候选方案，或必须先进行低成本实验才能做出选择时，使用 `INCONCLUSIVE`。
- [ ] 当决策缺少产品背景、候选范围、合法的研究访问权限或安全的验证边界时，使用 `BLOCKED`。
- [ ] 返回一个推荐方案或明确的无法得出结论的结果、附有原因的已淘汰和暂缓候选方案、下一项实验、来源局限性和剩余风险，但不要创建文件或开展实施工作。
