# 机会评估器

**目标：** 在承诺实施之前评估产品机会。从可观察的需求和可触达的获客路径出发，尽早淘汰薄弱候选项，并推荐一个低成本验证步骤，避免人为制造市场精确度。

**执行契约：** 将下方按顺序排列的复选框工作流视为本技能的完成定义。将每个复选框标记为 `PENDING`，然后根据具体证据将其解决为 `PROVEN`，根据证明其条件触发器不存在的证据将其解决为 `CLEARED`，或标记为 `UNPROVEN`；阅读、提及、委派、跳过或工具故障都不算证明。
返回之前，解决每个 `PENDING`，仅将 `PROVEN` 和 `CLEARED` 项计为已完成，根据本技能的判定、决策和批准规则处理每个 `UNPROVEN` 项，并在开头添加 **检查清单：X/Y 已完成**<br>**未完成：无 | section/item — 原因；对结果的影响；确切的下一步行动**；列出每个 `UNPROVEN` 项。

## 工具路由

| 需求 | 首选工具 | 使用时机 | 备用方案 |
|---|---|---|---|
| 产品与约束 | 用户上下文以及现有的产品、分析、客户和战略文档 | 确定受众、资产、渠道、经济性和非目标 | 说明假设，并仅请求缺失且会产生重大影响的意图 |
| 当前需求与获客 | 网络研究、趋势或市场数据、社区、评论、广告、目录以及一手客户证据 | 任何会影响淘汰或推荐的外部市场主张 | 将该信号标记为不可用；绝不要根据搜索结果数量推断数值 |
| 竞争与定价 | 竞争对手产品页面、定价、发布历史、分发渠道、评论，以及相关情况下的公开申报文件 | 确定替代方案、付费意愿信号和可信的差异化优势 | 使用定性证据并明确说明置信度 |
| 可行性与验证成本 | 现有能力、公共 API、法规、平台规则和当前官方文档 | 比较成本最低的可信实验和主要阻碍 | 标注估算值，并说明仍需获取的证据 |

保持评估为只读。不要创建项目文件、路线图、Epic、Story、实施计划、活动、列表、广告或客户触达。

## 证据类别

| 类别 | 含义 |
|---|---|
| `MEASURED` | 直接分析数据、交易、实验或已埋点的观察结果，且已知方法和日期 |
| `REPORTED` | 一手来源报告了某个数值或行为，但底层测量无法独立获得 |
| `ESTIMATED` | 基于明确输入和假设所建立的模型得出的陈述性结果 |
| `INFERRED` | 根据可观察代理指标得出的定性结论 |
| `UNKNOWN` | 证据不可用、已过时、不可比较，或过于薄弱，无法支持决策 |

不要将 `REPORTED`、`ESTIMATED` 或 `INFERRED` 证据转化为经过测量的市场规模、搜索量、转化率、收入或付费意愿主张。为每个外部来源标注日期，并在事件日期与发布日期不同时加以区分。
将创作者的论点、预期体验、品味和信念视为所有者偏好与战略契合度输入，绝不要将其视为需求、获客或付费意愿证据。

## 检查清单

### 1. 明确决策

- [ ] 明确现有产品或能力、目标用户、创作者论点、预期体验、决策时间范围、可用资产、地域或监管范围、约束条件以及明确的非目标。
- [ ] 接受用户提供的候选方案，或根据产品背景和当前信号生成一组边界明确且具有实质差异的机会；不要创建同一想法的表面变体。
- [ ] 明确哪些条件足以支持开展更深入的验证：可识别的用户和问题、可观察的需求、可触达的渠道、可信的价值交换、差异化切入点，以及负担得起的实验。
- [ ] 将新方向的探索与已承诺工作的优先级排序或实施规划区分开来。
- [ ] 记录可能推翻建议的假设，将可研究的事实与负责人偏好区分开来；只有当不同解读会实质性改变候选方案或实验时，才提出一个简洁的问题。

### 2. 为每个候选方案收集一组证据

- [ ] 确定谁正在经历该问题、他们目前如何解决、什么会触发主动搜索或购买，以及哪些证据表明该痛点是反复出现的或代价高昂的。
- [ ] 找到一个可触达的获客渠道及其机制：查询、市场类别、集成生态、社区、合作伙伴、外向营销受众，或其他可观察的路径。
- [ ] 调查直接竞争对手、替代方案、无所作为的行为、定价、定位、分销、评价中的抱怨，以及持续投入或放弃的证据。
- [ ] 在不臆造单位经济效益的前提下，考察经济信号：价格锚点、预算负责人、购买频率、转换成本、交付成本、平台费用以及支持负担。
- [ ] 识别会影响验证实验成本的实施、数据、依赖、监管、信任、分销和运营障碍。
- [ ] 记录来源、日期、证据类别、范围、置信度、矛盾之处，以及每个信号可能改变的候选决策。
- [ ] 一旦证据足以淘汰某个候选方案，或更多来源无法改变其状态，就停止对该候选方案的研究。

### 3. 应用证据优先的淘汰机制

- [ ] 当无法确立具体的用户问题、可观察的需求信号、可触达的渠道、可信的价值交换或可行的验证路径时，淘汰该候选方案。
- [ ] 将竞争视为需求和约束的证据，而不是自动否决的理由；必须针对替代方案和无所作为的选项提出具体的切入点。
- [ ] 不要使用关于搜索量、竞争对手数量、ARPU、市场规模或 MVP 周期的通用阈值。
- [ ] 对于公开数据薄弱的候选方案，如果低成本的初步实验可以解决不确定性，则将其保留为 `UNKNOWN`，而不是将其标记为无效。
- [ ] 为每个被淘汰的候选方案记录决定性证据和证伪条件，使拒绝过程可复现。
- [ ] 只有在外部可行性得到确认后，才询问负责人是否愿意且有能力去触达该受众、渠道和运营模式，并投入验证工作；不要推断其个人兴趣。

### 4. 比较幸存候选并选择下一项实验

- [ ] 根据证据强度、问题严重程度、渠道可触达性、差异化程度、经济性、验证成本、与创作者论点及预期体验的战略契合度，以及可逆性比较幸存候选，但不要将它们压缩成虚假的综合评分。
- [ ] 保留有意义的分歧和敏感性：说明哪项假设发生变化时，另一个候选会变得更可取。
- [ ] 仅当某个候选针对既定目标的证据明显更强时，才选择一个主要推荐；否则返回 `INCONCLUSIVE`。
- [ ] 定义成本最低且可信的验证实验，通过观察行为而不仅是陈述的购买意向，来测试最薄弱的决定性假设。
- [ ] 明确实验受众、渠道、产品方案或原型、成功与失败的证据、预算或时间边界、安全约束以及停止规则，不要假装知道结果。
- [ ] 在承诺实施之前，优先采用可逆测试，例如人工代交付、原型使用、在适当披露前提下测试定价或预购意向、渠道响应，或集成需求。

### 5. 验证并报告

- [ ] 针对每一项会影响决策的外部声明，重新通过当前的一手来源进行核查；否则标注较弱的证据类别及其局限性。
- [ ] 在最终结果中区分事实、估算、推断、所有者偏好和未解决的未知事项。
- [ ] 仅当候选具备可信的需求信号、可触达的渠道、可行的差异化路径、合理的价值交换以及可执行的验证实验时，才使用 `RECOMMEND <candidate>`。
- [ ] 当证据无法区分领先候选，或在做出选择前需要开展低成本实验时，使用 `INCONCLUSIVE`。
- [ ] 当决策缺少产品背景、候选范围、合法的研究访问权限或安全的验证边界时，使用 `BLOCKED`。
- [ ] 返回一项推荐或明确的无法下结论结果、说明原因的已淘汰和延期候选、下一项实验、来源局限性及剩余风险，不要创建文件或开展实施工作。
