# 董事会材料构建器

构建能够讲述故事，而不只是展示数据的董事会材料。每个部分都应有负责人、叙事主线和一个“那又怎样”的结论。董事会每季度会审阅 10 多份材料——你的材料需要有一条贯穿始终的主线。

## 关键词

董事会材料、投资者更新、董事会会议、董事会资料包、投资者关系、季度回顾、董事会演示文稿、融资材料、投资者材料、董事会叙事、QBR、季度业务回顾、董事会报告、指标仪表板、坏消息传达、差异解释

---

## 首先澄清

生成内容之前，请确认以下输入。如果有任何一项未知或含糊，请提问——不要自行假设：

- [ ] **材料类型和受众**（季度董事会、月度更新、融资、紧急事项）——决定幻灯片数量、结构以及应包含哪些部分
- [ ] **本期的核心信息**（超出计划／未达计划／需要决策）——决定开场框架，以及是否需要采用 SOUF 坏消息结构
- [ ] **董事会实际跟踪哪些指标**（以及相应目标）——指标仪表板应只显示这些指标，并根据目标展示 RAG 状态
- [ ] **需要董事会作出的具体决定或提出的具体请求**——请求部分是价值最高的一页，必须具体明确，并指定负责人

停止规则：只询问对输出影响最大的 2-3 项。如果用户说“直接起草即可”，则继续，并在交付物顶部列出你的假设。

## 材料类型和结构

### 材料类型选择

| 类型 | 适用场景 | 幻灯片数量 | 提前发送时间 | 关键部分 |
|------|------|-------------|-----------------|-------------|
| 季度董事会材料 | 常规董事会会议 | 20-30 页 | 提前 48 小时 | 下文所述的完整材料 |
| 月度更新 | 早期阶段董事会 | 8-12 页 | 提前 24 小时 | 指标 + 风险 |
| 融资材料 | 正在进行融资 | 12-15 页 | 会议期间 | 愿景 + 进展 |
| 紧急／临时材料 | 危机或重大决策 | 5-8 页 | 视情况而定 | 现状 + 选项 |

## 标准董事会材料（按部分说明）

### 第 1 部分：执行摘要（CEO）

三句话。不多，也不少。

| 句子 | 目的 | 示例 |
|----------|---------|---------|
| 1 | 业务现状 | “我们第三季度结束时的 ARR 为 $2.4M，环比增长 22%” |
| 2 | 本期最重大的进展 | “签署了我们金额最大的企业合同（$180K ACV）” |
| 3 | 前瞻性优先事项 | “第四季度优先事项：完成 A 轮融资，并使 ARR 达到 $2.8M” |

**反模式**：“我们本季度表现良好，各方面都取得了大量进展。”
**失败原因**：没有传达任何实质信息。董事会没有获得任何信息。浪费时间。

### 第 2 部分：关键指标仪表板（COO）

最多 6-8 项指标。每项指标都需要有目标和状态。

| 指标 | 本期 | 上期 | 目标 | 状态 | 趋势 |
|--------|-------------|-------------|--------|--------|-------|
| ARR | $2.4M | $1.97M | $2.3M | [G] | 上升 |
| MoM Growth | 8.1% | 7.2% | 7.5% | [G] | 上升 |
| Burn Multiple | 1.8x | 2.1x | < 2x | [G] | 改善 |
| NRR | 112% | 108% | > 110% | [G] | 上升 |
| CAC Payback | 11 个月 | 14 个月 | < 12 个月 | [G] | 改善 |
| Headcount | 24 | 21 | 25 | [Y] | 低于计划 |

**规则**：只展示董事会实际跟踪的指标。询问他们关心什么。删除他们已经明确表示不关心的所有内容。

### 第 3 节：财务更新（CFO）

| 组成部分 | 包含内容 | 格式 |
|-----------|---------|--------|
| 损益汇总 | 收入、销货成本、毛利率、运营费用、净现金消耗 | 包含差异列的表格 |
| 现金状况 | 当前余额 + 可维持月数 | 单个数字，加粗 |
| 现金消耗倍数趋势 | 3 个季度的趋势 | 折线图 |
| 与计划的差异 | 每个项目与预算的对比 | 表格，每项附一句解释 |
| 预测更新 | 下一季度预测 | 保守、基准、乐观 |

**规则**：每项差异都需要用一句话解释。只说“收入低于目标”而不作解释是不可接受的。

### 第 4 节：收入和销售管道（CRO）

| 组成部分 | 包含内容 | 格式 |
|-----------|---------|--------|
| ARR 瀑布图 | 期初 -> 新增 -> 扩展 -> 收缩 -> 流失 -> 期末 | 瀑布图 |
| NRR 和客户流失率 | 当前值 + 4 个季度的趋势 | 表格 + 趋势线 |
| 各阶段销售管道 | 金额，而不只是数量 | 漏斗可视化 |
| 预测 | 下一季度预测及置信水平 | “高置信度为 $2.6M，乐观情况下可达 $2.9M” |
| 前 3 大交易 | 名称、金额、成交日期、风险 | 表格 |

**规则**：预测必须包含置信水平。“我们预计为 $2.8M”这种表述说服力不足。

### 第 5 节：产品更新（CPO）

| 组成部分 | 包含内容 | 格式 |
|-----------|---------|--------|
| 本季度已交付 | 3-5 项内容及其对用户的影响 | 项目符号列表 |
| 下一季度将交付 | 3-5 项内容及目标日期 | 项目符号列表 |
| PMF 信号 | NPS 趋势、DAU/MAU、功能采用率 | 指标表格 |
| 关键认知 | 从客户研究中获得的一项洞察 | 叙述性段落 |

**规则**：不要罗列功能。只列出有证据证明对用户产生影响的功能。

### 第 6 节：增长与营销（CMO）

| 组成部分 | 包含内容 |
|-----------|---------|
| 各渠道 CAC | 包含效率趋势的表格 |
| 销售管道贡献 | 各渠道贡献的金额 |
| 有效举措 | 有数据支持的具体渠道/营销活动 |
| 正在削减的举措 | 表现不佳的渠道 |
| 正在测试的举措 | 带有假设的新实验 |

### 第 7 节：工程与技术（CTO）

| 组成部分 | 包含内容 |
|-----------|---------|
| 交付速度 | 4 个季度的趋势 |
| 技术债务占比 | 当前值 + 解决计划 |
| 基础设施 | 正常运行时间、事故、成本趋势 |
| 安全态势 | 除非存在重大问题，否则仅用一行说明 |

**规则**：除非存在重大问题，否则应保持简短。董事会不需要了解冲刺细节。

### 第 8 节：团队与人员（CHRO）

| 组成部分 | 包含内容 |
|-----------|---------|
| 员工人数 | 实际值与计划值对比 |
| 招聘 | 已发出的录用通知、候选人管道、招聘周期趋势 |
| 人员流失 | 遗憾流失与非遗憾流失 |
| 员工敬业度 | 最新调查得分及趋势 |
| 重要事项 | 关键入职人员、关键离职人员、关键空缺职位 |

### 第 9 节：风险与安全（CISO）

| 组成部分 | 包含内容 |
|-----------|---------|
| 安全态势 | 关键控制措施的状态 |
| 合规 | 正在进行的认证、截止日期 |
| 事故 | 本季度（如有）：影响、解决情况、预防措施 |
| 前 3 大风险 | 风险描述 + 缓解状态 |

### 第 10 节：战略展望（CEO）

| 组成部分 | 应包含的内容 |
|-----------|---------|
| 下一季度优先事项 | 3-5 项，按重要性排序 |
| 需要董事会做出的决定 | 具体的表决或批准事项 |
| 请求事项 | 具体且可执行的请求 |

**规则**：“请求事项”部分最为重要。“我们希望获得 3 次与 B 轮公司 CFO 的热情引荐”要优于“如能提供任何帮助，我们将不胜感激”。

### 第 11 节：附录

应包含以下内容，但除非被问及，否则不要展示：
- 详细的财务模型
- 完整的销售管线数据
- 同期群留存图表
- 客户案例研究
- 详细的人员编制明细

## 叙事框架

### 四幕式结构

每份董事会演示文稿都应遵循以下主线：

```
Act 1: WHERE WE SAID WE'D BE
  Last quarter's targets and commitments

Act 2: WHERE WE ACTUALLY ARE
  Honest assessment -- good and bad

Act 3: WHY THE GAP EXISTS
  One cause per variance. Not excuses -- explanations.

Act 4: WHAT WE'RE DOING ABOUT IT
  Specific, dated, owned actions
```

这一结构既适用于好消息，也适用于坏消息。它之所以可信，是因为它正视现实。

### 开场框架

董事会应在第 3 张幻灯片之前了解关键信息，而不是等到第 30 张。

| 好的开场 | 不好的开场 |
|-------------|-------------|
| “我们的 ARR 超出目标 8%，NRR 达到 112%” | “让我带大家回顾一下我们这个季度的情况……” |
| “我们的营收比目标少了 $300K。以下是原因和解决方案。” | “首先，介绍一些市场状况的背景……” |
| “我们需要董事会就这项收购机会进行表决” | “在进入主要议题之前，先介绍一些最新情况……” |

## 传达坏消息

### SOUF 框架

| 步骤 | 内容 | 示例 |
|------|------|---------|
| **S**tate（陈述） | 直截了当地陈述事实 | “我们未达到 Q3 ARR 目标，差额为 $300K（差距 12%）” |
| **O**wn（担责） | 承担原因责任 | “主要原因：企业销售周期比模型预测的更长” |
| **U**nderstand（理解） | 表明你已理解问题 | “分析了 8 笔停滞的交易；共同模式是采购流程延迟” |
| **F**ix（解决） | 提出解决方案 | “三项调整：[具体且有日期的事项]，修订后的 Q4 目标：$2.6M” |

### 传达坏消息的反模式

| 反模式 | 失败原因 | 更好的做法 |
|-------------|-------------|-----------------|
| 先讲好消息以缓和坏消息 | 董事会会注意到这种包装方式并产生不信任 | 从最重要的事情讲起 |
| 将“市场状况”作为原因 | 那只是背景，不是原因 | 指明具体且可控的原因 |
| 没有数据支撑的解决方案 | 董事会不会相信缺乏依据的解决方案 | 展示解决方案背后的分析 |
| 修订预测却不说明假设 | 看起来像是在猜测 | 展示自下而上的推导过程 |

## 董事会演示文稿的常见错误

| 错误 | 解决方法 |
|---------|-----|
| 幻灯片过多（> 25） | 坚决删减。如果你无法解释清楚，说明这张幻灯片有问题。 |
| 指标没有目标 | 每个指标都需要有目标和状态指示器 |
| 缺乏叙事 | 只有数据而没有故事，会迫使董事会自行得出结论 |
| 掩盖坏消息 | 先讲坏消息，承担责任并解决问题 |
| 请求含糊不清 | 只提出具体、可执行且已指定负责人的请求 |
| 没有解释差异 | 每一项与目标之间的差距都需要用一句话说明原因 |
| 附录内容陈旧 | 附录只有保持最新才有用 |
| 为阅读而设计，而非为会议室展示而设计 | 演示文稿是用来讲解的——必须适合口头表达 |
| 格式不一致 | 使用同一个模板、同一套配色方案和同一种字体 |
| 每张幻灯片文字过多 | 每张幻灯片最多 6 行。详细信息放在演讲者备注中。 |

## 演示文稿制作工作流

```
T-14 days: CEO sets agenda, identifies key messages
T-10 days: Section owners begin drafting their sections
T-7 days:  First drafts due. CEO reviews for narrative alignment.
T-5 days:  Second drafts. CFO validates all numbers.
T-3 days:  Final deck assembly. Narrative check.
T-2 days:  Send to board. Include cover note with 3 key takeaways.
T-0:       Meeting. CEO presents. Section owners available for questions.
```

## 危险信号

- 在会议前一晚才完成演示文稿——没有时间进行审核或统一叙事
- 演示文稿中的数字与财务模型不一致——严重损害可信度
- 没有请求事项部分——浪费董事会会议时间
- 连续 4 个以上季度使用相同的演示文稿格式且未做迭代——未积极响应反馈
- 董事会成员对信息感到意外——他们绝不应在会议上才得知坏消息
- 超过 30 张幻灯片——到第 20 张之后注意力就会流失
- 未跟进上次会议的行动事项——存在问责缺口

## 故障排除

| 问题 | 可能原因 | 解决方法 |
|---------|-------------|-----|
| 董事会成员提出演示文稿中已经回答过的基础问题 | 演示文稿发送得不够提前，或内容无法独立理解 | 至少提前 48 小时发送，并附上包含 3 个要点的说明；确保演示文稿无需讲解也能独立阅读 |
| 各部分的财务数字不一致 | 缺少 CFO 交叉验证步骤 | 增加 T-5 天的 CFO 验证检查点；所有指标采用单一事实来源 |
| 会议在前几个部分耗时过长 | 演示幻灯片细节过多，且未设定时间限制 | 强制每张幻灯片最多 6 行；使用演讲者备注补充详细内容；指定计时人员 |
| 董事会成员对坏消息感到意外 | 未在一对一预沟通电话中提前说明相关信息 | CEO 在会议前向每位董事会成员简要说明重大问题 |
| 请求事项部分没有产生后续行动 | 请求含糊不清（“任何帮助都非常感谢”） | 请求应具体、明确到人且可执行（“向 B 轮融资公司的 CFO 提供 3 次暖介绍”） |
| 连续 4 个以上季度使用相同的演示文稿格式，且没有改进 | 缺少会后反馈闭环 | 在会议结束时评估演示文稿的有效性；每季度迭代一个部分 |
| 附录从未被引用 | 附录内容陈旧，或与当前议程无关 | 每次会议前更新附录；删除连续 2 个以上季度无人问及的数据 |

## 成功标准

- 在 80% 以上的会议中，董事会成员反馈已提前阅读演示文稿（根据会前收到的问题衡量）
- 会议在分配的时间内结束，且 70% 以上的时间用于战略讨论，而非状态更新
- 每次董事会会议至少产生 2 项已记录的决策，并明确负责人和截止日期
- 坏消息绝不会在会议上突然出现——所有重大问题均通过一对一预沟通电话提前说明
- 董事会 NPS（非正式季度检查）的会议实用性评分达到 8+/10
- 在 T-2 天前完成演示文稿汇编，且 90% 以上的季度不会出现最后一刻手忙脚乱的情况
- 上次会议行动项的完成率达到 80% 以上，并在下次会议上汇报

## 范围与限制

**范围内**：董事会演示文稿结构、章节模板、叙事框架、坏消息传达、指标仪表板、演示文稿汇编工作流、董事会准备检查清单、质量验证。

**范围之外**：实际财务数据收集、幻灯片设计/视觉格式设置、董事会成员关系管理、法律治理要求、委托书准备、监管申报。

**局限性**：此技能提供结构和流程，但无法取代编写董事会叙事所需的判断力。演示文稿结构验证器检查的是完整性，而非内容质量。指标仪表盘工具会根据所提供的数据计算 RAG 状态，但不会获取实时指标。
