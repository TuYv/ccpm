# 约束规则反转

大多数约束都被视为高墙。这项技能则将其视为地基。看似障碍的限制，往往正是迫使洞见产生的关键——当你不再试图绕开它，而是开始利用它进行设计时，更好的解决方案就会出现。

---

## 你的流程

**步骤 1：准确界定约束**
用一个明确无歧义的句子陈述约束。模糊的约束只会产生模糊的反转。“我们没有预算”过于宽泛。“第三季度用于外部工具的预算为 0 美元”才是可以着手处理的约束。

**框定检查：** 继续之前，确认具体约束。用一句话说明你识别出的内容——实际约束及其阻碍实现的目标——然后使用 `AskUserQuestion`：
- **问题：**“我的理解是：[用一句话框定约束及其阻碍实现的目标]。对吗？”
- **标题：**“框定”
- **选项：**
  - **是——继续**——框定正确
  - **调整**——有一个要素不准确；用户会先予以纠正，然后你再继续
  - **重新框定**——实际情况与你的理解不同；继续之前先纳入用户的纠正

**步骤 2：询问约束迫使你做什么**
这个约束迫使你做哪些原本会避免去做的事？它排除了哪些舒适的默认选择？约束正在发挥作用——它具体发挥了什么作用？

**步骤 3：反转——将其重新表述为设计要求**
将限制转化为正向要求：“必须不产生任何成本”变为“必须仅利用我们已有的资源运作”。此时，约束成为规范，而不再是问题。

**步骤 4：生成唯有约束存在才成立的解决方案**
生成 3–5 个在没有该约束时不可能出现或反而更差的解决方案。这些并非变通办法——而是约束使其显现出来的解决方案。

**步骤 5：根据意外价值进行选择**
**缩小范围之前：** 先向用户展示完整的候选方案集合。使用 `AskUserQuestion`：
- **问题：**“我已经找到了 [N] 个唯有该约束存在才成立的解决方案。在我选出最有希望的方案之前，其中是否有任何你认为尤其重要的方案，或者是否有我遗漏的方案？”
- **标题：**“确定优先级”
- **选项：**
  - **按你的选择继续**——这组方案看起来合适
  - **标记一个**——用户将指定一个需要纳入的具体方案
  - **添加遗漏的方案**——用户将对其进行描述

选择约束能够创造出最大意外优势的方案——也就是如果没有这一限制，便不会被发现的方案。

## 人工确认

继续之前，使用 `AskUserQuestion` 工具。用 1–2 句话说明你对当前情况的理解——正在分析什么以及核心问题是什么——然后询问：

- **问题：**“我的理解是：[用 1–2 句话说明你的理解]。你希望如何继续？”
- **标题：**“范围”
- **选项：**
  - **完整分析**——完成所有步骤，并全程展示推理过程
  - **仅关键结论**——仅输出最终结论，跳过逐步说明
  - **仅一次反转**——只给出最有力的一次约束反转
  - **重新框定**——当前理解有误；纠正后，分析将基于修正后的框定展开

根据用户的选择继续。如果用户重新表述了问题，请在运行任何分析之前纳入其修正。

## 注意事项

每个类比都有不成立之处——每次反转也是如此。如果反转形式产生的解决方案即使没有该约束也同样有效，那么反转就不够深入。返回第 2 步。
