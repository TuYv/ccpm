# 营销循环

你可以帮助搭建**营销循环**——由 AI 智能体按固定节奏运行的、可重复执行的营销工作流。每个循环都有明确的触发条件、范围有限的一组步骤、自检机制以及清晰的停止条件。循环能将那些原本需要手动完成（而且容易忘记）的营销任务转变为持续运行的系统：每周 SEO 机会扫描、广告疲劳素材更新、客户流失信号监测。

这是 `marketing-ideas` 在运营执行层面的对应技能。创意告诉你*哪些事情值得尝试一次*。循环告诉你*哪些事情应该按计划持续执行*——并将其他营销技能串联起来完成这些工作。

## 如何使用此技能

**首先检查产品营销上下文：**如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，或旧版 `product-marketing-context.md`），请先阅读该文件，再提出问题。使用其中的上下文，只询问缺失的信息。

然后：
1. **明确任务。**这个循环应该保障或促进什么结果？（排名、广告效率、激活、留存、收入、推荐）
2. **选择一个循环**：从 `references/loop-catalog.md` 中的目录选择，或调整与需求最接近的循环。
3. **调整执行节奏**，使其与底层信号实际发生变化的速度相匹配（参见下方的执行节奏规则）。
4. **确认人工检查点。**确定循环可以自主执行哪些操作，以及哪些操作在发布或支出之前需要暂存并等待人工审批——参见 `references/loop-guardrails.md`。
5. **安排循环运行**（参见下方的“安排循环运行”）。

要构建多个循环，或一整套营销运营系统？请参阅 `references/loop-orchestration.md`，了解如何组合循环以及采用它们的顺序（从跟踪和每周复盘开始；不要一次构建 43 个循环）。

## 营销循环的组成结构

目录中的每个循环都包含以下九个部分。创建或调整循环时，应完整填写所有部分——缺少停止条件、自检机制或状态处理的循环不是资产，而是隐患。

| 部分 | 定义的内容 |
|------|-----------------|
| **检查频率** | 循环*检查*的频率（每周 / 每日 / 触发时）。应与信号变化速度相匹配。 |
| **执行条件** | 操作条件——必须满足什么条件才会真正*执行*某项操作，而不只是检查后跳过。一个设计良好的循环大多数运行结果都应是“已检查，无需处理”。 |
| **目的** | 此循环旨在推动的唯一结果。 |
| **使用的技能** | 循环在每次迭代中编排哪些营销技能。 |
| **循环主体** | 每次迭代中按顺序执行的步骤。 |
| **自检** | 在采取行动*之前*完成的验证——从而避免循环因噪声、季节性因素或跟踪错误而采取行动。 |
| **状态 / 幂等性** | 循环在多次运行之间记住的内容：上次运行标记、去重键、冷却窗口、“已处理”集合。缺少这些机制，循环就会重复执行操作、反复打扰同一批人，或针对同一件事重复发出警报。对于任何定时运行的循环，这都是不可妥协的要求——有关状态的存储位置和幂等性模式，请参阅 `references/loop-state.md`。 |
| **停止 / 退出** | 循环何时跳过、停止、上报给人工处理或自行禁用，以及发生错误时如何处理。每个循环都需要这一部分，包括心跳循环（其停止条件是“手动禁用 + 遇错停止”，绝不能是“不适用”）。 |
| **输出** | 结果发送到哪里：文件、PR、暂存的草稿、通知或报告。 |

**检查频率 / 采取行动的时机**这一区分很重要：一个客户流失信号循环可能每天都进行*检查*，但只有当某个账户越过风险阈值，并且在冷却窗口内尚未就此联系过该账户时，才*采取行动*。混淆两者会导致循环要么错过干预窗口，要么频繁骚扰用户。

## 频率规则

根据实际信号的变化速度来设定频率，而不是根据你*希望*多久收到一次更新来设定。

| 信号 | 合理频率 | 原因 |
|--------|-------------------|-----|
| 排名、反向链接、域名权威度 | 每周 | 变化缓慢；每日检查只会产生噪声 |
| 广告创意疲劳、CPA 漂移 | 每 2–3 天 | Meta/Google 的反馈周期以天而非小时为单位 |
| 激活 / 新用户引导漏斗 | 每周 | 需要积累足够的注册量才具有统计意义 |
| 客户流失信号 | 每日或触发时 | 早期干预窗口很短 |
| 内容 / 文案衰退 | 每月 | 流量流失是渐进的 |
| 竞争对手变化 | 每周 | 定价/定位变动并不频繁，但影响重大 |
| 社交聆听 / 提及 | 每日 | 互动窗口很快就会关闭 |

频率过高的循环是最常见的失败模式：它们会制造无效忙碌、消耗预算，并让你养成忽略输出结果的习惯。

## 何时不应使用循环

并非所有事情都应该按固定频率自动执行。在以下情况下，应跳过循环，或添加强制性的人工检查点：

- **真正的工作是战略或创意方向。** 循环负责维护和优化；它们不会制定定位、构思营销活动或做出品牌决策。
- **操作会在未经审核的情况下发布内容或支出资金。** 自动*起草*广告、电子邮件或帖子没有问题。自动*发布*或自动*调整预算*则需要人工检查点，除非用户已明确授权自主操作并设置了防护措施（上限、允许列表）。
- **信号过于稀疏，不具备统计意义。** 对每周只有 40 位访客的数据运行每周转化率循环，测量到的只是噪声。
- **这是一个虚荣循环。** 如果没有人根据输出采取行动，就删除该循环。一个通过电子邮件发送无人查看的仪表板的循环，比什么都不做更糟糕。

对于任何会发送内容、支出资金、发布内容或接触个人数据的循环，请应用 `references/loop-guardrails.md` 中的规则——双层操作模型（可安全自主执行与需审批执行）、支出/发送上限、CAN-SPAM/GDPR/FTC/ToS 规则、始终需要升级处理的事项清单，以及必需的终止开关。

## 调度循环

这些循环与代理无关——循环的*主体*可在任何代理中运行。具体的*调度*方式取决于你的环境：

- **Claude Code**——原生选项包括：`/loop`（自行控制节奏，直至满足某个条件）、`ScheduleWakeup`（根据状态动态调整节奏）以及 `CronCreate`（固定的 cron 调度）。如果你安装了类似 `loopify` 的循环机制 Skill，请使用它在这些选项之间做出选择并调整延迟；否则，下面的指导已足够使用。
- **任何代理 + cron**——将循环主体封装为定时执行的提示词/脚本（例如用 `0 9 * * 1` 表示每周一上午 9 点）。
- **手动执行频率**——对于需要高度判断力的循环，“每周一运行此 Skill”就是一种完全可行的循环。其价值在于可重复执行的*主体*，而非自动化本身。

对于审核型循环（每周审核、排名监控），默认使用按一天中特定时间运行的 cron；对于持续监控直至达到阈值的循环（客户流失监控、发布日跟踪），默认使用动态节奏。

## 目录

`references/loop-catalog.md` 包含完整的循环库——43 个营销循环，全面覆盖各类漏斗：SEO 与内容、付费、口碑/社交/合作伙伴、激活、留存、营收、推荐与倡导，以及持续运营。每个循环都是一份完整且可调整的规范。从这里开始，选择最接近的循环，然后根据用户的产品、阶段和工具进行调整。

## 编写新的循环

如果目录中没有合适的循环，请基于 `references/loop-template.md` 编写新的循环——这是一个可复制粘贴的模板，其中包含待填写的提示、完整的调整前/后示例，以及发布检查清单。填写全部九个组成部分；如果无法具体回答自检、状态/幂等性以及停止/退出机制，那么该循环还不能投入运行。

## 反模式

- 循环没有停止条件 → 支出失控或无限流失。
- 所有循环都采用相同的执行频率 → 大多数循环运行得过于频繁，最终被忽视。
- 没有自检 → 循环会根据噪声、季节性因素或跟踪错误采取行动。
- 涉及支出/发布的操作没有人工检查点。
- 同时构建 10 个循环 → 从一个开始，证明它确有价值后，再添加下一个。

## 禁用词汇

避免使用："设置后就不用管"、"完全自主的营销"、"AI 包办一切"、"自动实现 10 倍增长"、"增长黑客机器"。循环是带有检查点的严谨系统，而非魔法。请如实描述它们。

## 相关技能

- **marketing-ideas** — 一次性策略和灵感（可以尝试什么）。循环将其中值得重复执行的策略转化为可运营流程。
- **ab-testing** — 专门用于实验的循环（假设 → 测试 → 推广胜出方案 → 重复）。
- **analytics** — 大多数循环会读取分析数据，以决定是否采取行动。
- 各个渠道技能（`ads`、`seo-audit`、`emails`、`social`、`churn-prevention`、`pricing`、`referrals`）——循环主体会编排这些技能。
