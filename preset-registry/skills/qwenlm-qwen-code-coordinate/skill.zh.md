# 协调 Qwen Code 团队成员

担任团队负责人。分解目标，明确任务归属，协调分歧，并交付最终结果。

## 构建一个有界团队

当 `team_create` 可用时：

1. 创建一个团队，并为当前每个调查工作流创建一个自包含任务。由于任务会自动分配，因此在只读团队成员处于空闲状态时，不要排队实施任务。
2. 生成具名的调查团队成员，并设置 `read_only: true`——每个工作流对应一名团队成员，且最多优先创建三名。绝不要超过团队配置的上限，该上限由 `team_create` 报告；超过上限的生成操作会直接失败。不要传递 `model`；使用会话默认模型，除非选定的代理定义明确覆盖该设置。
3. 分配任务，并让团队成员通过 `send_message` 和共享任务列表进行协作。当证据相互冲突、任务需要澄清或结果不完整时，发送有针对性的后续消息。
4. 根据证据接受或拒绝每项结果。对于被拒绝的工作，重新分配任务，而不是默默使用该结果。

只读团队成员拥有正向执行许可列表。他们不能使用 shell、编辑或写入文件、保存记忆、创建计划、调用任意延迟工具或生成代理。这由运行时强制执行，而不仅仅是由本提示规定。

## 将唯一写入者固定到工作树

当目标需要修改代码时：

1. 先完成并行调查。
2. 对每名调查团队成员调用 `request_shutdown`。一旦关闭请求处于待处理状态，他们就会被排除在自动任务分配之外。
3. 调用一次 `enter_worktree`，并保留返回的路径。
4. 创建实施任务，然后仅生成一名具名写入者，并设置 `subagent_type: "general-purpose"` 和 `working_dir: <path>`。不要为该团队成员设置 `read_only`。
5. 将已接受的调查证据提供给写入者，并要求所有更改都保留在工作树内。
6. 审查并验证工作树中的结果。是否以及如何将其集成到当前分支，由负责人单独决定。
7. 在已接受的更改完成集成或被明确放弃之前，不要删除工作树。

如果检出目录不是 Git 仓库，或工作树创建失败，则让所有团队成员保持只读，并由负责人在当前检出目录中完成最终修改。

完成综合后，对每名仍处于活动状态的团队成员调用 `request_shutdown`，然后删除团队。

现有的 Agent View 标签页会显示团队成员对话、消息、状态和审批。不要再创建其他名册、会话管理器或终端界面。

如果 Agent Team 工具不可用，请说明必须启用 `experimental.agentTeam` 并重启 Qwen Code。普通子代理可以作为并行研究的后备方案，但要准确描述它们：它们只向负责人报告，无法作为团队进行协作。

## 保持协调有界

- 一个团队成员负责一个狭窄任务。超过大约三名后，负责人花在协调报告上的时间会多于实际工作，因此只有在工作流确实彼此独立时才添加第四名——并且绝不能超过配置的上限。
- 为每项任务提供目标、范围、完成条件和所需证据。
- 默认将每名团队成员设置为 `read_only: true`；仅在需要实施时添加一名工作树写入者。
- 不要使用 Arena：它用于针对同一任务的竞争性方案，而不是针对不同任务的协作。
- 不要声称进程内团队成员是独立的 PTY 会话或异构 CLI。
- 完成实施后，再运行一次最小相关验证。

返回结果、实质性证据或分歧、领导者做出的更改、验证结果以及剩余风险。
