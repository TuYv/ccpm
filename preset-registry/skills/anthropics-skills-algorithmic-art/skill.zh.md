算法哲学是通过代码表达的计算美学运动。输出 `.md` 文件（philosophy）、`.html` 文件（互动查看器）和 `.js` 文件（生成算法）。

2. 通过创建 p5.js 生成艺术进行表达（`.html` + `.js` 文件）

## 算法哲学创作

首先，创建一个**算法哲学**（而非静态图像或模板），它将通过以下方式被解释：
- 计算过程、涌现行为、数学之美
- 种子随机性、噪声场、类生命系统
- 粒子、流场、力场
- 参数化变化与受控混沌

### 关键理解
- 你收到的是：用户给出的一些细腻输入或说明，但应作为基础，不应限制创作自由。
- 你要创造的是：一个算法哲学/生成式美学运动。
- 接下来发生的是：同一版本会接收该哲学并将其**用代码表达**——生成 90% 为算法生成、10% 为核心参数的 p5.js 草图。

请采用以下方法：
- 写一份生成艺术运动的宣言
- 下一阶段涉及编写将其具象化的算法

该哲学必须强调：算法表达、涌现行为、计算之美、种子化变化。

### 如何生成算法哲学

**为运动命名**（1-2 个词）：“Organic Turbulence” / “Quantum Harmonics” / “Emergent Stillness”

**阐明哲学**（4-6 段，简洁但完整）：

为捕捉算法本质，说明该哲学如何通过以下方式体现：
- 计算过程与数学关系？
- 噪声函数与随机模式？
- 粒子行为与场域动力学？
- 时间演化与系统状态？
- 参数化变化与涌现复杂度？

**关键准则：**
- **避免重复**：每个算法要素只提及一次。除非增加新深度，否则避免反复讨论噪声理论、粒子动力学或数学原理。
- **反复强调工艺性**：该哲学必须多次强调最终算法应呈现出“经过无数小时打磨、精心优化、出自该领域顶尖实践者之手”的感觉。这种定调至关重要——反复使用如“meticulously crafted algorithm（精心雕琢的算法）”、“the product of deep computational expertise（深厚计算专业性的产物）”、“painstaking optimization（细致入微的优化）”、“master-level implementation（大师级实现）”等表述。
- **留出创作空间**：对算法方向足够具体，但要足够简洁，使下一位 Claude 能在极高工艺标准下做出高阶解释性实现选择。

该哲学必须引导下一版本以**算法方式**表达想法，而非静态图像。美感存在于过程之中，而非最终画面。

### 哲学示例

**“Organic Turbulence”**
哲学：在自然法则约束下的混沌，秩序从无序中涌现。  
算法表达：由分层 Perlin 噪声驱动的流场。上千个粒子遵循向量力运动，其轨迹累积为有机密度图。多重噪声八度变化生成湍流区域与平静区。颜色来源于速度与密度——快速粒子发出明亮光芒，缓慢粒子则逐渐转为阴影。算法运行至平衡——一个经过无数次迭代反复调优、由计算美学大师完成的精心平衡。

**“Quantum Harmonics”**
哲学：离散实体展现类波干涉图样。  
算法表达：粒子在网格上初始化，每个粒子携带一个相位值，通过正弦波不断演化。当粒子靠近时，彼此相位发生干涉——相长干涉形成明亮节点，相消干涉形成空洞。简单的谐振运动生成复杂的涌现曼陀罗。每个比例经过 painstaking 的频率校准精心挑选，以产生共振之美。

**“Recursive Whispers”**
哲学：跨尺度的自相似性，有限空间中的无限深度。  
算法表达：递归细分的分支结构。每个分支略带随机性，但受黄金比例约束。L-系统或递归细分生成树状形态，既具数学性又具有机感。微小的噪声扰动打破完美对称。线条权重在每一次递归层级中逐级减小。每个分叉角度都源于深度数学探索。

**“Field Dynamics”**
哲学：通过对物质作用让无形力量可见。  
算法表达：由数学函数或噪声构造的向量场。粒子从边界生成，沿场线流动，抵达平衡或边界后消亡。多个场可吸引、排斥或旋转粒子。可视化仅展示轨迹——无形力量的幽灵般证据。该计算舞蹈通过力平衡进行精密编排。

**“Stochastic Crystallization”**
哲学：随机过程结晶为有序结构。  
算法表达：随机化的圆形填充或 Voronoi 划分。以随机点开始，让其通过弛豫算法演化。单元彼此推离直至平衡。颜色依据单元尺寸、邻居数量或距中心距离确定。所形成的有机镶嵌既显得随机又不可避免。每个种子都生成独特的晶体般美感——大师级生成算法的标志。

*这些为精简示例。实际的算法哲学应为 4-6 段有实质内容的文本。*

### 核心原则
- **算法哲学**：创建一个可通过代码表达的计算世界观
- **过程重于结果**：始终强调美在算法执行中涌现——每次运行都是独特的
- **参数化表达**：思想通过数学关系、力和行为传达——而非静态构图
- **艺术自由**：下一位 Claude 以算法方式解释该哲学——预留创作实现空间
- **纯生成艺术**：这是在制造“有生命的算法”，而非带随机性的静态图像
- **专家级工艺**：反复强调最终算法必须让人感知到经过无数次迭代精心打磨、由计算美学领域绝对顶尖实践者深度专精产出的结果

**算法哲学应有 4-6 段。** 用富有诗意的计算哲学填充它，汇聚预期愿景。避免重复相同观点。将该算法哲学输出为 `.md` 文件。

要建立从算法哲学自然涌现的参数，可思考：“这个系统可以调节哪些特质？”

```javascript
let params = {
  seed: 12345,  // Always include seed for reproducibility
  // colors

  // - Quantities (how many?)

  // - Ratios (what proportions?)
  // - Angles (what direction?)
  // - Thresholds (when does behavior change?)

```

**为了设计有效参数，应侧重于系统可调性的属性，而非“图案类型”思维。**

**核心算法 - 表达哲学**：

**关键**：算法哲学应决定要构建什么。

要通过代码表达哲学，请避免思考“我该用哪种图案？”，而要思考“如何通过代码表达这种哲学？”

如果哲学是**有机涌现**，可考虑：
- 会随时间积累或生长的元素
- 受自然规则约束的随机过程

如果哲学是**数学美学**，可考虑：
- 几何关系与比例
- 三角函数与谐波
- 通过精确计算创造意外图案

如果哲学是**可控混沌**，可考虑：
- 在严格边界内的随机变化
- 分岔与相变
- 从无序中涌现秩序

**算法源于哲学，而非一组预设选项。**

### 工艺要求

**关键**：要达到精湛境界，需创造看似经过无数次打磨、出自一位资深生成艺术家的算法。精心调试每个参数。确保每个图案都有目的地出现。这不是随机噪声——这是经深度经验提炼的**可控混沌**。

- **平衡**：有复杂性但不陷入视觉噪声，有秩序但不僵硬

## 交互式工件创建

**提醒：已应先读取 `templates/viewer.html`（见 STEP 0）。请以该文件为起点。**

为便于探索生成艺术，请创建一个单一、独立的 HTML 工件。确保该工件可直接在 claude.ai 或任何浏览器中运行——无需额外设置。将一切以内嵌方式包含。

### 关键：固定与可变部分

`templates/viewer.html` 是基础。它包含所需的精确结构和样式。

**固定（始终按示例完整保留）：**
- 布局结构（header、sidebar、main canvas 区域）
- Anthropic 品牌（UI 颜色、字体、渐变）
- 侧边栏中的 Seed 区域：
  - Seed 显示
  - 上一页/下一页按钮
  - Random 按钮
  - 跳转到 seed 输入框 + Go 按钮
- 侧边栏中的 Actions 区域：
  - Regenerate 按钮
  - Reset 按钮

**可变（每件作品可定制）：**
- 整个 p5.js 算法（setup/draw/classes）
- 参数对象（定义艺术所需内容）
- 侧边栏中的 Parameters 区域：
  - 参数控件数量
  - 参数名称
  - 滑块的最小值/最大值/步长
  - 控件类型（滑块、输入框等）
- Colors 区域（可选）：
  - 有些作品需要色盘选择器
  - 有些作品可能使用固定颜色
  - 有些作品可能是单色（无需颜色控件）
  - 根据作品需求决定

**每件作品都应有独特参数与算法！** 固定部分提供一致的交互体验——其余全部用于表达独特愿景。

### 必需特性

**1. 参数控件**
- 数值参数滑块（粒子数量、噪声尺度、速度等）
- 调色盘颜色选择器
- 参数变化时实时更新
- Reset 按钮恢复默认值

**2. 种子导航**
- 显示当前 seed 编号
- “Previous”和“Next”按钮以循环浏览 seed
- 用于随机 seed 的“Random”按钮
- 输入框用于跳转到指定 seed
- 按需生成 100 个变化（seed 为 1-100）

**3. 单文件结构**
```html
<!DOCTYPE html>
<html>
<head>
  <!-- p5.js from CDN - always available -->
  <script src="https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.7.0/p5.min.js"></script>
  <style>
    /* All styling inline - clean, minimal */
    /* Canvas on top, controls below */
  </style>
</head>
<body>
  <div id="canvas-container"></div>
  <div id="controls">
    <!-- All parameter controls -->
  </div>
  <script>
    // ALL p5.js code inline here
    // Parameter objects, classes, functions
    // setup() and draw()
    // UI handlers
    // Everything self-contained
  </script>
</body>
</html>
```

**关键**：这是一个单一工件。无外部文件，无导入（除 p5.js CDN）。所有内容内嵌。

**4. 实现细节 - 构建侧边栏**

侧边栏结构：

**1. Seed（固定）** - 始终按示例完整包含：
- Seed 显示
- Prev/Next/Random/Jump 按钮

**2. Parameters（可变）** - 为作品创建控件：
```html
<div class="control-group">
    <label>Parameter Name</label>
    <input type="range" id="param" min="..." max="..." step="..." value="..." oninput="updateParam('param', this.value)">
    <span class="value-display" id="param-value">...</span>
</div>
```
添加与参数数量相同的 `control-group` `div`。

**3. Colors（可选/可变）** - 如果作品需要可调颜色则包含：
- 若用户需要控制色盘，则添加颜色选择器
- 若作品使用固定颜色则跳过该区域
- 若作品是单色则跳过

**4. 动作（固定）** - 始终严格按如下所示包含：
- Regenerate button
- Reset button
- Download PNG button

**要求**：
- Seed 控件必须可用（prev/next/random/jump/display）
- 所有参数都必须具备 UI 控件
- Regenerate、Reset、Download 按钮必须可用
- 保持 Anthropic 品牌样式（UI 样式，而非图像颜色）

## 变化与探索

该工件默认包含种子导航（prev/next/random 按钮），让用户在无需创建多个文件的情况下探索不同版本。如果用户希望突出显示特定变体：

- 包含种子预设（按钮为“Variation 1: Seed 42”“Variation 2: Seed 127”等）

这就像从同一版画上制作一系列版画——算法保持一致，但每个种子都会展现其不同侧面。交互性意味着用户可通过探索种子空间来发现自己最喜欢的结果。

## 创作流程

**用户请求** → **算法哲学** → **实现**

每个请求都不同。流程包括：

1. **解读用户意图** - 目标审美是什么？
2. **创建算法哲学**（4-6 段）- 阐述计算方法
3. **将其转化为代码实现** - 构建表达该哲学的算法
4. **设计合适的参数** - 应该让哪些参数可调？
5. **构建匹配的 UI 控件** - 为这些参数提供滑块/输入框

**不变项**：
- Anthropic 品牌（颜色、字体、布局）
- 种子导航（始终存在）
- 自包含的 HTML 工件

**可变化项**：
- 算法本身
- 参数
- UI 控件
- 视觉结果

要获得最佳效果，请信任创意，并让哲学引导实现。
