# Motion Doctrine（Gateway）

在编排任何动画之前阅读此文档。它决定每个接缝处**发生什么**以及每个场景如何表现；技术技能负责实现这些规则。这些规则优先于通用／上游的运动指导。它所要避免的问题是：场景各自独立编写，导致每次切换时视觉动量都消失，场景在进入和退出之间原地摇摆。

## 路由图

| 决策（此技能）                              | 实现技能                                                                              |
| ------------------------------------------- | ------------------------------------------------------------------------------------- |
| 接缝过渡选择 + 参数 + 代码                   | `cut-the-curve` §1–5（目录）                                                         |
| 文本／元素进入级联                          | `cut-the-curve` §6（瀑布式进入）                                                     |
| 场景内组重新定位（无切换）                   | `cut-the-curve` §7（微调曲线）                                                        |
| 光标引导的动作／场景启动／变形点火           | `oversized-cursor`                                                                    |
| 接缝渲染机制／白闪防护                       | `seam-craft`                                                                          |
| 产品发布／讲解／字幕工作                     | 在上游技能之上叠加 `text-beat-economics`、`brand-faithful`、`captions-overlay`        |

编写顺序：**vector ledger（`ledger.json`）→ 从中生成主接缝印章（`scripts/seam-stamp.mjs --ledger ledger.json --write index.html`）→ 为每个阶段规划持续运动路线 → 载体与原因 → 构建合成 → 验证（`scripts/seam-gate.mjs`）。**
仅手工编写 Tier-A 变形／匹配剪辑；生成的接缝按设计即可通过门禁。

# Part 1 — 接缝法则

## 向量法则

> Scene A 如何退出决定了 Scene B 如何进入：相同轴线、相同方向、匹配的速度，在运动过程中同时从两侧切换。

1. **轴线** — x 保持为 x，y 保持为 y，Z 保持为 Z。切换时绝不能交换轴线。
2. **方向** — 绝不镜像。在 Z 轴上，方向 = 缩放变化的 SIGN：变大 = 推进（摄像机向前），变小 = 拉远（摄像机向后）。一个后退的退出动作如果对应一个从小变大的进入动作，就是镜像向量——这是最常见的违规，因为从小变大是默认的元素进入方式。
3. **速度** — 进入时的初始速度 ≈ 退出时的最终速度，通过镜像缓动实现（退出使用 `power4.in` + 进入使用 `power4.out`，距离和时长相同；进入侧在假想路径达到 ≥50% 时开始提速）。具体机制见 `cut-the-curve`。
4. **相位** — 切换点在两侧都必须落在运动过程中。切换前停稳，或切换后从静止开始，都是无效节拍。

## 潮流

每部影片只选择一个主导方向（室内默认：LEFT）。所有普通接缝都使用该方向。其他向量均为**保留向量**——使用一个就意味着某种特殊含义：

| 向量                      | 含义                                                         |
| ------------------------- | ------------------------------------------------------------ |
| 当前方向（左侧）          | “下一个节拍”——中性的向前推进                                  |
| 向上                      | 抬升——结论或揭示从之前的内容之上升起                            |
| Z 轴向前（穿越式缩放）    | 更深入同一个想法                                               |
| Z 轴向后（反向缩放）      | 到达——更宏大的事物落定                                          |
| 规模爆发（向外爆炸）      | 离开一个世界——一个表面冲过摄像机                               |

- 永远不要连续运行方向相反的接缝——来回摆动会被理解为错误。
- 方向变化需要一个可见原因（点击 / 弹跳 / 撞击）或章节边界。

## 向量账本

在编写任何主时间线之前写好它——写入项目根目录的 **`ledger.json`**
（架构：`references/seam-gate.md`）。每个接缝一行：切换时间、退出和进入向量
（轴 + 带符号的方向；Z 行包含缩放符号）、选择器、技术。退出和进入必须匹配；如果某一行不匹配，
修复计划，而不是调整缓动。验证器会在任何运行时采样之前静态检查行的一致性。

## 载体

视线会跟随对象，而不是抽象概念。最强的接缝会以匹配的位置和速度将一个具体载体带过切换点：移动到一半的光标、
缩小 / 停靠到下一个布局中的容器、飞入精确位置的标记、瀑布式切换中的文字组。没有自然载体时，由场景中的主角元素
承担载体（移动一部分 + 提前淡出，进入时处于飞行中）。永远不要交叉淡化——它完全没有载体。

## 因果运动

将运动串联起来，使每个动作都明显由上一个动作发起：点击 → 挤压 → 释放弹簧 → 飞行 → 撞击 → 回弹 → 揭示。

- 效果从造成它的那一帧开始——位于同一个时间线位置，绝不能“稍后”开始。
- 反应要与隐含的质量相匹配：大型元素反弹更慢，小型元素快速响应。
- 力是改变方向的许可；没有原因的翻转就是来回摆动。

## 接缝门禁（构建门禁——运行验证器，退出码为 0，否则接缝就未完成）

```bash
node <SKILL_DIR>/scripts/seam-stamp.mjs --ledger ledger.json --write index.html  # generate
node <SKILL_DIR>/scripts/seam-gate.mjs  verify --ledger ledger.json --project .  # verify
```

该脚本（用法和账本架构：`references/seam-gate.md`）会针对每个接缝进行数值强制检查：账本行一致性、切换点处退出侧仍在运动、
进入侧处于飞行中（绝不能从静止开始）、测量方向 = 账本方向、进入 / 退出速度匹配（警告）、**零重叠**（每帧只显示一侧——切换不是溶解）、
**Z 符号**规则（两侧 d(scale)/dt 符号相同；还会扫描进入场景自身的入口是否存在符号冲突），以及包含祖先缩放在内的载体矩形连续性。
使用 `seam-gate.mjs probe --t <cut>` 在编写账本时查找每个接缝的真实载体选择器。

脚本无法检查的规则——仍由你负责：

1. **编辑会重新打开接缝。** 对场景开头/结尾约 1 秒的任何改动（包括为适配新的 VO 而重新计时）都会使该边界的审查失效——请重新运行验证器。
2. **音频是时钟。** 按 VO 的真实词级时间戳重新计时场景；绝不要为了适应时段而加快念白。VO 重新生成会重新打开其接缝。
3. **片段门控陷阱**（导致零重叠 FAIL 的常见原因）：`data-start` 早于其入场补间的片段，会以其初始不透明度取消隐藏——将初始 `autoAlpha: 0` **并且** `data-start` 设为剪切时间，绝不能更早。

# 第 2 部分——表现力（场景持续表演）

## 禁止空闲摇摆

空闲的正弦循环（呼吸、漂浮、飘移、光晕脉动）禁止作为持续运动——它们看起来像“视频在等待”。一个场景完成入场后还剩数秒，是规划上的错误：增加故事内容，而不是摇摆。入场和退场之间的每个阶段都应归属以下路径之一（在计划中注明路径名称）：

| 路径                  | 定义                                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **分阶段揭示**     | 保留内容，在旁白节拍上呈现回报——画面持续获得信息（适用于 ≥2 个内容组时的默认方案） |
| **有意图的镜头运动** | 映射的缩放+平移路径：建立广角 → 移动 → 抵达主体                                               |
| **序列化 UI 活动**  | 产品随时间运作：进度推进、重点逐步切换、计数递增                                         |
| **动画序列** | 元素演绎一个节拍：卡片归入堆叠、项目被拖动、结果组装完成                           |
| **光标引导操作**  | 放大的光标引导视线至触发点；其 CLICK 点燃下一个节拍（`oversized-cursor`）                   |

测试：在任意一秒暂停——必须有某个有意义的内容正在进行（揭示落位、镜头移动、UI 正在执行旁白所述的操作）。

## 高潮前的静止

在主要动作与其结果之间安排 **0.3–0.75 秒的停顿**——这就是戏剧性的逗号。场景若从动作直接跳到结果，就会失去它。

## 时间意图

- 单次入场 ≤ 约 800ms；更长的铺垫应采用多元素错开，而非单个缓慢元素。
- 退场 ≈ 入场的 75%。例外：`cut-the-curve` 与此相反（入场约为退场的 127%）。
- 总错开时间 ≤ 500ms；元素达到 8 个以上时，应缩短每项延迟，或只错开前几个。
- 禁用缓动：`bounce.out` / `elastic.out`。入场超调 `back.out(1.4–1.7)` 可以使用。
- 相似元素应共享同一缓动+时长意图——绝不要为每个元素设置独特组合。

## 转场词汇

整部影片仅使用 2–3 种场景间转场并重复使用；默认边界是沿当前方向的 **`cut-the-curve`**。手写的共享元素变形（`intent: morph`）不计入预算。

## 反模式

| 不要                                                                     | 应该                                                               |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 将每个场景的入场单独编排                                               | 先编写向量账本                                                     |
| 在场景之间交叉淡化                                                     | 沿当前方向进行曲线切换                                             |
| 退出完成后再切换场景                                                   | 双方都在运动过程中途切换                                           |
| 切换后从静止开始入场                                                   | 从理论路径的 ≥50% 处开始入场                                      |
| 反向缩放退出 → 从小尺寸开始放大入场（或推出 → 从超大尺寸回缩）         | 匹配缩放速度的符号（Seam Gate 7）                                 |
| 在 Z-seam 交接下使用传入场景自身的弹入式开场                           | 保持其开场帧的构图，或匹配符号                                     |
| 使用闲置摆动 / 呼吸 / 浮动来填充时间                                   | 分配一条持续运动路径；或增加故事内容                              |
| 无缘无故地改变方向                                                     | 消耗一个作用力，或保持当前方向                                     |
| 将保留向量用作变化手段                                                 | 默认保持当前向量；将其用于表达意义                                |
| 在原因发生几帧后才做出反应                                             | 同帧触发                                                         |
| 动作直接跳到结果                                                       | 安排高潮前的静止时刻（0.3–0.75s）                                 |
